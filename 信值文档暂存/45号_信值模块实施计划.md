## 一、设计理念与核心命题

### 1.1 一个核心命题

> 现行信用体系(征信分/平台分)的三大窄域: **只罚不修**(违约记录 5 年覆盖, 无修复通道)、
> **只看金融**(忽略伦理与贡献维度)、**只归机构**(个人无自证渠道)。
> 信值模块的答案: **法治 50% + 伦理 30% + 贡献 20% 的三层可解释度量 +
> 即时修复引擎 + 行为资产化的价值锚定**。

### 1.2 三大理念落法(本仓惯例)

## 三、P0:角色档案与三层评分内核

### 3.1 双角色差异化计算矩阵

| 层级 | 权重(宪法级) | 个人角色维度 | 企业/机构角色维度 |
|------|------|------------|------------------|
| **L1 法治合规** | **50%** | 法院执行/行政处罚/纳税记录/合同履约判决 | 工商税务环保合规/知识产权资质/劳动用工安全/**企业无形资产确权** |
| **L2 社会伦理** | **30%** | 平台信用分(授权)/社区评价/网络言行/自愿提交证据 | ESG 评级/供应链责任/消费者投诉舆情/行业自律 |
| **L3 社会贡献** | **20%** | 志愿服务/公益捐赠/见义勇为/低碳行为 | 技术开源/标准制定/就业带动/应急响应 |

**双层输出**(关键设计——度量与资产分离, 防"分数即金钱"异化):

- **信值分 TrustScore** ∈ [0, 100]: 度量层, 三层加权
  `Score = 0.5×S_L1 + 0.3×S_L2 + 0.2×S_L3`
- **信值余额 TV**: 资产层, 由**验证通过的正向行为**按准备金规则发行(P3 详述);
  L1 合格是发行门槛(熔断时冻结), **合规是义务不是资产**——守法不产信值,
  只有 L3 贡献与 L2 高分正向行为构成发行准备金

### 3.2 第28档案 TrustValueScorer

```python
# services/trust_scoring_service.py
class TrustValueScorer:
    """第28档案: 信值三层评分(宪法权重 + 软因子可学习)

    因子按层分组(L1×3 + L2×3 + L3×3, 每层因子归一后×宪法权重):
        L1(50%): legal_record    司法合规度(执行/判决/处罚)
                 regulatory      行政监管(税务/资质/用工)
                 asset_integrity 无形资产确权(企业)/履约(个人)
        L2(30%): platform_conduct  平台言行与评价(授权)
                 community_standing 社区/舆情口碑
                 ethics_evidence    自愿提交的伦理行为证据
        L3(20%): contribution_net  净贡献(因果效应剔自然增长)
                 impact_radius     影响力辐射半径×持续时长
                 longtail_good     长尾正向(微小但高频)

    硬约束(区别于 26/27 档案):
        - 层间权重 0.5/0.3/0.2 为宪法常量, Hedge 学习只调
          层内因子相对权重, 层间结构永不动摇(护栏 guardrail)
        - L1 熔断: legal_record < 30 时信值分直接锁 critical 档,
          L2/L3 得分不参与(硬约束引擎, 上层不可覆盖)
    """
    CONSTITUTION = {"L1": 0.5, "L2": 0.3, "L3": 0.2}
    WEIGHTS = {  # 层内因子权重(Hedge 可调, 学习域仅限层内)
        "legal_record": 0.20, "regulatory": 0.17, "asset_integrity": 0.13,
        "platform_conduct": 0.12, "community_standing": 0.10, "ethics_evidence": 0.08,
        "contribution_net": 0.09, "impact_radius": 0.07, "longtail_good": 0.04,
    }
```

## 五、P2:即时修复引擎("放下屠刀, 立地成佛"算法)

### 5.1 工程化转译

> 佛学理念 → 工程语义: **"立地成佛" ≠ 瞬间清零, 而是
> 违规确认的那一刻, 修复通道即时开启 + 高效激励窗口打开。**
> 系统给改过者一条清晰、可执行、有希望的路径, 而非机械惩罚。

### 5.2 修复值数学模型

```
修复值 ΔV_repair = α × Σ(β_i × V_i × γ(t_i)) × AI验真分

    α  修复上限系数(熔断分级决定):
        general  α = 1.0   一般违规, 全额修复通道
        severe   α ≤ 0.3   严重违法, 天花板修复(防"有钱洗白")
        criminal α = 0     刑事犯罪, 永久熔断
    β_i 行为关联度权重(针对性修复 > 通用修复):
        如: 酒驾→交通安全宣讲 β=1.5; 泛泛捐款 β=0.3
    γ(t) 时效衰减: γ(t) = e^(-λt), λ=0.1
        → 24h 内修复效率 ≈ 30 天后的 18~20 倍(高效激励窗口)
    V_i 修复行为自身验证价值(AI 多模态打分)
    AI验真分: 证据真实性+有效性双重打分, 低于阈值不计入
```

```python
# services/trust_repair_service.py
@dataclass
class RepairEngine:
    LAMBDA = 0.1   # 时效衰减系数

    def repair_gain(self, violation, repairs: list) -> float:
        """修复值计算(即时性: 违规确认即开通道, 无等待期)"""
        alpha = FUSE_ALPHA[violation.fusedLevel]      # {general:1.0, severe:0.3, criminal:0}
        total = sum(r.beta * r.value * math.exp(
            -self.LAMBDA * r.days_since) for r in repairs)
        return alpha * total * min(repairs_avg_authenticity, 1.0)
```

### 5.3 修复的三重校验(防洗白)

1. **上限保护**: 修复后 L1 得分不超过 `min(修复值, 违规扣分×α)`——
   永远追不回的部分就是"代价"(修复天花板)
2. **针对性加权**: β 系数由违规类型×修复行为的**语义关联度**决定
   (LLM 归类 + 规则映射表, mock 态确定性规则)
3. **验真前置**: 修复证据走 P1 验真管线, 表演式修复(摆拍/代打卡)
   被多模态鉴别拦截

### 5.4 修复事件与留痕

表 `trust45_repairs`: `{repairId, trustId, violationEventId, repairs[{beta,
value, evidenceRef, verified}], gain, before/afterScore, ts}`——
全链留痕, 归因报告可回放。

**端点(4)**: `POST /trust/repairs`(提交修复证据包)/
`GET /trust/repairs/{trustId}/plan`(**修复建议路径**——针对当前熔断/
扣分项, 给出 β 加权最优的修复行为清单)/`GET /trust/repairs/{id}`
(修复明细)/`POST /trust/repairs/{id}/verify`(触发验真)

**测试与验收**: 专项预计 30 项(α/β/γ 数学断言/天花板保护/即时开启/
λ 衰减曲线数值验证 24h vs 30d≈20 倍/针对性 β 映射) + 实机 8 项
(违规→修复计划→存证→验真→分数回升全链 E2E)。

## 六、P3:信值资产与价值兑换系统(1 TV = 1 元)

### 6.1 双通缩发行模型(防通胀核心)

```
发行锚定(准备金制):
    每 +1 TV 发行 ← 必须有对应 L3 净贡献 / L2 高分正向行为的
    可验证资产作准备金(AI 验真通过 + 因果效应剔水分后)
    L1 合格是发行门槛(熔断态冻结发行), 但合规本身不产 TV
        ——守法是义务, 不是资产(设计立场)

兑换销毁(非转移):
    1 TV 兑换 1 元货品/服务 → TV 实时销毁 + 对应行为资产标记"已消耗"
    → 通货紧缩型价值系统: 越兑换越稀缺, 行为资产池越纯净
```

### 6.2 信用分↔信值转换(单向防套利)

```
本站信用分 → 信值 TV: 允许(动态汇率, 缺省 100 信用分 = 1 TV,
    汇率由信值准备金池/信用分总量比动态调整, 周度重算)
    转换后信用分同步扣减(等量销毁)
信值 TV → 本站信用分: 禁止(单向, 防套利循环)
```

### 6.3 防挤兑四件套

| 机制 | 规则 |
|------|------|
| 单日兑换上限 | 个人 ≤500 TV/日, 机构 ≤5000 TV/日(可配置) |
| 单月兑换上限 | 个人 ≤5000 TV/月, 机构 ≤50000 TV/月 |
| 商户保证金 | 合作商户缴纳保证金或智能合约托管(兑换货品履约担保) |
| 熔断联动 | L1 熔断态资产冻结(不可兑换/不可转入, 修复解锁) |

### 6.4 账本设计

表 `trust45_ledger`(复式记账, 流水不可篡改):
`{ledgerId, trustId, direction: issue|burn|transfer_in|freeze,
amount, reserveRef(准备金资产引用), counterpart, memo, balanceAfter, ts}`

**端点(5)**: `GET /trust/balance`(余额+冻结额+发行准备金明细)/
`POST /trust/redeem`(兑换申请→商户核销)/`POST /trust/redeem/{id}/confirm`
(商户确认发货→TV 销毁)/`POST /trust/convert`(信用分→TV 单向转换)/
`GET /trust/ledger`(账本流水)

**测试与验收**: 专项预计 28 项(准备金约束发行/销毁原子性/单向转换/
汇率动态/防挤兑上限/熔断冻结) + 实机 8 项(发行→兑换→销毁→
信用分转入→上限拦截 E2E)。

## 七、P4:自进化闭环与可解释性

### 7.1 自我优化闭环(42/43/44号裁决回流范式平移)

```
用户申诉(信值变动异议)
    → 人工复核(裁决: 计算正确 / 计算错误)
    → 真值回流: collect(已裁决未回流事件 → 第28档案 Hedge 反馈)
                run(触发一轮乘性更新 + 护栏)
                status(档案/权重/漂移视图)
    → 层内因子权重调优(层间 50/30/20 宪法护栏永不动)
```

外部注入通道: 新法规出台/重大社会事件 → 人工编写**伦理补丁**
(因子新增/删除/β 映射更新) → 版本留痕 → 注入(45号 v7.9 经验回放同款)。

### 7.2 可解释性强制(归因报告)

每次信值分/TV 变动必须附带人类可读归因(**禁止黑箱**):

```
【信值变动归因】
角色: 个人 #1024 | 层级: L2 社会伦理(权重 30%)
行为: 平台"某商城"授权信用分 785→812(探针通道)
依据: 因子 platform_conduct +2.1 分
变动: 信值分 71.3 → 72.0(+0.7)
说明: 授权数据源经跨源交叉验证(置信度 0.92)
申诉: 如有异议, 7 日内提交 /trust/appeals
```

LLM 三态: mock(代码模板生成, 数字来自计算层——**LLM 幻觉不进入数据**,
42号发票摘要同口径)/real(润色归因文案)。

### 7.3 申诉与人工复核

## 九、合规与伦理红线(宪法层, 不可逾越)

| # | 红线 | 工程落法 |
|---|------|---------|
| 1 | **严禁信用货币化异化**: TV 可兑货品/服务, **不得兑现金/不得作贷款审批依据/不得二级市场交易** | 兑换端点白名单(商户+货品类目); 账本 direction 枚举锁死; 转账类 API 永不开放 |
| 2 | **数据最小必要**: 雷达仅采集与信值计算直接相关的公开数据; 私有数据必须授权; **生物特征/医疗健康等敏感信息绝对禁止入模** | 采集白名单 schema 校验; 敏感字段黑名单(入库前硬拦截); 证件明文不落盘(摘要) |
| 3 | **算法备案与安全评估**: 上线前完成算法备案/安全评估/伦理审查 | P1 合规试点里程碑(见 §十一); 备案材料清单外部待办 |
| 4 | **可解释性强制**: 每次变动附带人类可读归因, 禁止黑箱 | P4 归因报告(变动无归因即拒绝落库——DB 层约束) |
| 5 | **修复上限保护**: L1 严重违法设修复天花板, 防"有钱/有资源洗白" | α 系数硬编码 + severe 档 0.3 天花板; 修复值超天花板即拒绝 |

**独立监督委员会**(建议项目启动即成立): 法律/伦理/社会学/技术专家,
对模型上线与重大更新持**一票否决权**——公信力是生命线, 技术只是工具。

## 十、与既有模块的一致性声明

- **零不可逆变更**: `TRUST_VALUE_MODE=off` 默认(模块静默/看板空载);
  既有路由文件零改动
- **fail-open 铁律**: 信值计算基础设施异常 → 展示上次快照 + 留痕

  (非 AI 判断); 处置型动作(封禁)仍归 43号
- **范式复用清单**: 双模式仓储(38-44号)/评分器+Hedge 档案(ai_learning,
  第28档案 batch=12)/LLM 三态(41/42号)/事件裁决真值回流(42/43/44号)/
  Key 双头鉴权+双限(44号 P1/P2)/幂等键(41号)/看板按需加载(43号)
- **编号衔接**: 第28档案 TrustValueScorer(第27档案 ApiHealthScorer 顺延)
