| 动态定价(α抵扣系数/成本保护/价差≤20%) | **60号支付定价引擎完全同构**(信任×贡献×活动三因子, 总折扣≤30%上限) + 47号 P3 层级乘性(restricted×0.5/watched×0.8/trusted×1.1=信值溢价γ) | ~90% |

## 二、四层架构(全部为编排层)

```
【感知层·信值账户聚合】68号 xinzhi_radar_service(新)
    用户信值五维 = 聚合 47号tier(诚信基础) × 67号信任指数(互助)
    × 44号评分(专业) × 登录/订单流水(活跃) × 62号估值斜率(成长)
    → 分段Sigmoid归一化(文档公式) → 硬熔断(任一维<40→总分≤59)
    → 软奖励(连续6月无违规+互助TOP10%→+5) → 负面半衰期90天
    ★ 零新建计算:五维数据源全部是既有模块的只读聚合
        ▼
【决策层·臻选货架引擎】68号 xinzhi_prime_service(新)
    商品三维评分 = 信值契合度(品类×场景×用户tier知识映射表)
    × 体验确定性(硬闸<0.6: 37号商家评级+64号五防+P6e价值观词表)
    × 转化潜力(同类商品历史漏斗, 冷启动0.5)
    → 商品四级: L1臻选位(≥75) / L2优选(≥50) / L3普通 / L4风险
    ★ 引擎范式复用 40号P7b(同构), 数据域从"事件"换为"商品"
        ▼
【体验层·透明定价与导购】
    展示价 = 60号三因子定价(信任×贡献×活动, ≤30%)
    + 47号P3层级乘性(γ信值溢价: trusted×1.1) − 成本价保护
    → 详情页强制公示: 原价-信值抵扣-会员折扣=实付(文档要求)
    导购 = 48号小竹新增"臻选导购人格"(SOP五步法话术库:
    意图锚定→信值佐证→透明解释→履约跟进→价值沉淀)
    ★ 数字永远来自查询层, 小竹仅组织语言(LLM禁数字铁律不变)
        ▼
【治理层·信值宪法】(零新增, 复用既有)
    反作弊 = 43号UEBA + P2a质量门 + 64号五防 → 四级处置
    (L1标记/L2限制观察/L3人工复核/L4自动——L3-L4经46号)
    反馈闭环 = 标签路由(复用67号评价/44号回流范式) → 模型迭代
    杀熟检测 = 64号 PRICE-MANIP 扩展(同SKU用户间价差>20%→46号)
```

## 三、核心交付明细

### P0 信值账户聚合层
- **xinzhi_radar_service**(新): 五维聚合计算(分段Sigmoid+熔断+奖励+衰减)——
  权重配置化入 redis(诚信30/互助25/专业20/活跃15/成长10, 后台可调),
  新用户 30 天冷启动保护(活跃15→25, 诚信30→20), 全计算审计留痕
- **信值账户页**(taro-app): 五维雷达图可视化+每维"影响因素TOP3"
  (文档要求: "诚信度↓: 因上周1笔订单超时"式归因)
- 端点: GET /api/xinzhi/radar(五维+总分+归因) / GET /api/xinzhi/history(90日曲线)

### P1 臻选货架引擎
- **xinzhi_prime_service**(新): 商品三维评分批次执行(P7b 范式移植)
- 商品 L1-L4 回写+信值加权排序(基础分=相关性×转化, 最终分=基础×
  (1+α×信值调节), α运营配置——文档公式)
- **臻选首页频道**(taro-app): L1臻选位+品类导航+信值专享价标签
- 端点: POST /api/xinzhi/products/score / GET /api/xinzhi/prime(L1货架) /
  GET /api/xinzhi/products/{id}/score(三维分明细+解释)

### P2 透明定价与导购
- 价格构成拆解卡(原价-信值抵扣-折扣=实付, 详情页强制)
- 小竹臻选导购人格(SOP五步法, 复用 53号脚本/59号编排基础设施)
- 反馈闭环: 👍/👎微交互+标签路由(L1安抚/L2工单/L3紧急15分钟)
  ——复用 67号评价+44号回流幂等范式
- 端点: GET /api/xinzhi/price/{sku}(构成拆解) / POST /api/xinzhi/feedback /
  GET /api/xinzhi/feedback/{id}(进度透明)

### P3 互助购物生态(差异化核心)
- **邻里臻选频道**: 同小区/同城高信值用户购买聚合展示(复用 67号LBS+
  P6f-3 零个体数据红线——仅聚合口径, 平台×品类×漏斗)
- **互助求购**: 需求发布→认证商家/邻里响应(67号叫帮三单上限/
  紧急→距离→新单排序直接复用)
- **碳积分联动**: 互助购物获碳积分(67号口径: 公益单100%/接力均摊)
- 端点: GET /api/xinzhi/neighbor(邻里臻选) / POST /api/xinzhi/groupbuy
  (邻里求购) + 67号既有 29 端点零改动

### P4 商家信值体系
- 37号同盟扩展: 商家信值认证"4+2"(主体/履约/服务/后台四必查+
  生态贡献/外部背书两加分)——复用 38号审核工作台范式
- **商家预演沙盘**(P7c 范式移植): 申报配置→模拟1000单履约→
  信值轨迹预测→《启航报告》(TOP3风险+成长路线图)
- 动态评级 S-A-B-C-D(升降级留痕, 处罚经 46号)
- 端点: POST /api/xinzhi/merchant/apply / POST /api/xinzhi/merchant/simulate
  (预演沙盘) / GET /api/xinzhi/merchant/{id}/level

### P5 灰度上线与白皮书
- 三态灰度: XINZHI_MODE=off(默认零影响)/shadow(观察留痕)/
  assist(辅助生效)——项目既有范式
- A/B 护栏: 退款率/客诉进线/卸载率任一恶化>3%自动暂停(文档口径)
- 年度信值白皮书(复用 40号 P6f-3 四章节框架+67号白皮书范式)
- Docker 实机验证 + zxjiu.com 生产部署 + 收官三册(运行报告/
  用户指南/交付总结——MD/HTML/PDF 四件套)

## 八、关键设计决策备忘

1. **编排优先于新建**:凡既有模块有的能力, 68号只做只读聚合+展示,
   绝不复制计算逻辑(防止双源真相)——五维雷达的数据主权留在 47/44/67号
2. **同构复用判定**:P7b"契合×安全硬闸×转化"与文档"三维匹配"逐项
   同构, 故商品评分引擎直接移植范式, 仅数据域适配(事件→商品)
3. **小竹导购的 LLM 边界**:话术组织允许 LLM(语言层), 数字/评分/
   排序/定价永远查询层直出(判定层)——延续全站"LLM 禁判定链"铁律
4. **邻里频道合规**:复用 P6f-3 白皮书的 PII 双层防线+零个体数据口径,
   聚合粒度=平台×品类×漏斗, 个体购买永不暴露
5. **预演沙盘双用途**:商家入驻预演(P4)复用 P7c 合规预演沙盘的
   "模拟→预警→建议书"三段式, 参数域从创作合规换为履约能力
6. **默认零影响**:XINZHI_MODE=off 时既有 67 模块零改动——灰度铁律
   (购物台是新增前台, 不触碰任何既有链路的一行代码)
