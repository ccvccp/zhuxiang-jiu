# 47号·验真风控管理端运维手册

> 配套：[47号_L2L3信值验真风控模块实施计划.md](47号_L2L3信值验真风控模块实施计划.md) · [47号_完整交付总结文档.md](47号_完整交付总结文档.md)
> 定位：信值验真风控的**人工值守与裁决**工作台——角色风险画像判读、团伙嫌疑复核、画像误判申诉处置、通道收窄灰度切换。
> 前置依赖：45号信值模块（存证/验真/评分）已运行；46号治理中枢（公平性桥接可选）。

## 一、入口与权限

| 项 | 说明 |
|----|------|
| 访问角色 | `X-Role: admin`（风控/治理岗；复核申诉入口对角色开放） |
| 基址 | `http://<host>:8000`（实机 `http://127.0.0.2:8000`） |
| 看板面板 | 打开 `trust-risk-dashboard.html`（文件直开，配后端地址后保存） |
| 数据源 | `GET /api/trust/risk/dashboard`（五区块一次拉取，手动刷新） |
| 刷新建议 | 画像视图按需；命中统计日看；团伙视图周看；先验状态随开关变更即看 |

**一句话红线**（面板常驻，操作前必读）：**画像不处罚**——嫌疑仅标记、通道只收窄（且须显式开关）；任何信值扣减仍走 45号既有事件流；L1 法治数据官方背书永不折损。

## 二、看板五区块判读（dashboard）

`GET /api/trust/risk/dashboard`（或面板①-⑤区块）：

| 区块 | 字段 | 判读要点 |
|------|------|---------|
| ① 风险排行 | `byTier` | trusted/standard/watched/restricted 四档分布。watched+restricted 占比 >20% → 检查近期是否有批量攻击或阈值偏严 |
| | `watchlist` | 只含 watched/restricted，按 riskEMA 降序（最险在前）。每行带命中明细芯片，是每日巡检主入口 |
| ② 命中统计 | `totals` | 七类命中累计（降序）。`semantic_reuse`/`value_anomaly` 高 → 刷分活跃；`collusive_suspect` 高 → 跑协同扫描复核 |
| | `affectedProfiles` | 每类信号波及的档案数（totals 高但 affected 低 = 少数惯犯；两者同高 = 批量行为） |
| ③ 嫌疑视图 | `totals.suspects` | 当前团伙嫌疑档案数；`mutualPairs` 互证对数 |
| | `suspects[].marked` | 已标记=画像已沉淀（scan 已跑）；未标记=视图识别但还没扫描沉淀 |
| ④ 复核队列 | `pendingCount` | 待复核申诉数（>0 需处理，见 §六） |
| | `recent` | 近期已决申诉（calibrated/rejected）留痕 |
| ⑤ 回流状态 | `enabled` | **RISK_PRIOR_MODE 开关态**（ON=画像回流通道生效，OFF=纯沉淀观察，见 §七） |
| | `tierGates` | 四档乘数表：restricted ×0.5 / watched ×0.8 / trusted ×1.1（standard ×1.0） |

单区块异常时显示 `error` 字段但看板整体仍可用（fail-soft 分区——单区块数据源故障不阻断其余区块）。

## 三、七类命中信号速查

| 信号 | 含义 | 来源 | 触发条件 |
|------|------|------|---------|
| `hypocrisy` | L2 伪善预警 | 45号 P6 守门 | 跨平台一致性 <0.3 的正向事件 |
| `self_promotion` | L3 作秀降权 | 45号 P6 守门 | 宣传占比 >0.7 |
| `recurrence` | 再犯风险 | 45号 P6 修复路径 | 第 5 次及以上违规后修复 |
| `behavior_burst` | 行为突增 | 45号 P7 v2 验真 | 突增比 >5（近 7 天/日均基线） |
| `semantic_reuse` | 证据复用嫌疑 | **47号 P1** | 同角色 3-gram 相似度 >0.8（改字重放） |
| `value_anomaly` | 价值分布异常 | **47号 P1/P2** | 小额高频 或 价值-证据错配 或（P2 起间接）团伙折损 |
| `collusive_suspect` | 团伙嫌疑 | **47号 P2** | 互证对 ≥3 或 跨角色指纹共享 ≥2 次 |

**画像分层与 EMA 收敛对照**（α=0.2，连续命中）：

| 命中次数 | riskEMA | trustLevel | 分层 |
|---------|---------|-----------|------|
| 1 | 0.2000 | 0.8000 | trusted |
| 4 | 0.5904 | 0.4096 | watched |
| 7 | 0.7903 | 0.2097 | restricted |

> EMA 天然抗单次噪声：一次异常事件只推 0.2；零风险事件会逐次稀释（×0.8 衰减）——画像自愈不需要人工干预。

## 四、日常巡检操作

### 4.1 角色级检测（建议按需/日度）

```bash
POST /api/trust/risk/{trustId}/scan        # X-Role: admin
```

- 触发一轮该角色的价值分布检测（小额高频），命中沉淀画像
- **幂等**：与最近一次扫描结果一致时不重复计数；新存证进入则增量重判
- 返回 `valueAnomaly`（判定详情）+ `semanticBucketSize`（指纹桶容量）

### 4.2 协同扫描（建议周度）

```bash
POST /api/trust/risk/collusion/scan        # X-Role: admin
GET  /api/trust/risk/collusion             # 团伙视图（纯读，零写入）
```

- 扫描近 90 日存证：互证对（`trust:{id}` 双向引用 ≥3 回合）+ 跨角色指纹共享（≥2 次）→ 双方 `collusive_suspect` 沉淀
- **幂等**：已标记角色跳过（返回 `marked`/`skipped` 两个列表）
- 视图含完整证据链：`mutualPairs[].timeline`（互证时间线，每条含 eventId/ts/depositor/referenced）与 `sharedFingerprints`（exact/semantic + 相似度）——**复核团伙嫌疑以证据链为准，不以计数为准**

### 4.3 公平性桥接（建议月度，配合 46号审计）

```bash
POST /api/trust/risk/dashboard/fairness-bridge    # X-Role: admin
POST /api/ai-gov/fairness/audit  {"scorerId": "trust_value"}
```

- 画像 tier → `risk_{tier}` 分组按信值分均值上报 46号公平性采样（每组 n≥5 才参与）
- 用途：**风控自身的公平性审计**——验证通道收窄是否在群体间造成系统性偏差（防守门误伤）
- 46号审计报告 `groups` 含 `risk_*` 维度后判读：flagged 仅标记不下结论，均值差异比 >20% 需人工复核阈值

## 五、画像查询与判读

### 5.1 单档案画像

```bash
GET /api/trust/risk/{trustId}              # X-Role: admin
```

| 字段 | 判读 |
|------|------|
| `riskEMA` / `trustLevel` | 风险指数与信任度（校准后为覆盖值） |
| `trustLevelComputed` | 计算值（与 trustLevel 不同 = 存在人工校准） |
| `tier` | 四档标签（仅标签不处罚） |
| `hitCounts` | 七类命中计数——判读画像成因的主依据 |
| `riskHistory` | 近 20 条风险事件快照（source/risk/signals/detail） |
| `reviewRequests` / `pendingReview` | 复核申诉队列（见 §六） |
| `calibrated` / `calibrateNote` | 人工校准状态与理由 |

### 5.2 全档案排行

```bash
GET /api/trust/risk                        # X-Role: admin
```

风险降序 + `byTier` 分层统计——快速定位最需关注的档案。

### 5.3 判读口径速查

| 场景 | 判读 | 动作方向 |
|------|------|---------|
| `semantic_reuse` 高 + 单一档案 | 改字重放惯犯 | 确认证据链（P1 折损已自动生效）；惯犯走复核维持 |
| `value_anomaly` 高 + 多档案 | 小额高频刷分模式 | 确认基线合理性；批量误伤走校准 |
| `collusive_suspect` + 互证时间线密集 | 团伙互证 | 证据链复核（见 4.2）；确系正常互助 → 校准 |
| `hypocrisy` 集中 + 新档案 | P6 守门跨平台不一致 | 属 45号域，按其守门口径处置 |
| riskEMA 高但 hitCounts 全零 | 校准覆盖历史遗留 | 核对 calibrateNote，必要时清除校准 |

## 六、复核申诉处置（角色误判自救通道）

### 6.1 流程

角色对画像误判提交申诉（`POST /api/trust/risk/{trustId}/review-request`，开放端点，8-500 字符理由，同一档案同时只挂一条）→ 进入待复核队列：

```bash
GET  /api/trust/risk/{trustId}                       # 看 reviewRequests 队列
POST /api/trust/risk/{trustId}/reviews/{reviewId}/decide    # X-Role: admin
{"approve": true,  "trustLevel": 0.8, "note": "复核确认: 互证系正常互助"}
{"approve": false, "note": "证据链充分, 维持原判"}
```

### 6.2 裁决效果

| 裁决 | 复核状态 | 联动动作 |
|------|---------|---------|
| `approve: true` + trustLevel | calibrated | **复核即校准**：画像 trustLevel 覆盖为目标值（留痕双向：review 记录 + calibrateNote）→ 通道立即按新档位恢复 |
| `approve: false` | rejected | 维持原判，画像不动（风险指数照常自然衰减） |

已处理复核重复操作返回 409；复核记录不存在返回 404；approve 必须携带目标 trustLevel。

### 6.3 判定口径速查

| 场景 | 判定 | 依据 |
|------|------|------|
| 申诉"互证系业务互助" + 互证对恰 3 回合 + 证据各自独立 | 误报 | 正常合作也会互证，看**证据是否各自独立**（共享指纹=0）→ approve + 校准 0.6-0.8 |
| 申诉含糊 + 共享指纹 ≥2 + 时间线同分钟级 | 维持 | 共享证据文本是团伙铁证 |
| 申诉"高频申报系业务旺季" + value_anomaly 单一信号 | 视基线 | 群体确实旺季 → approve；仅该角色"旺季"→ 维持 |
| restricted 档申诉 + 七类命中分散 | 维持 | 多维度独立命中非误判 |

## 七、先验回流开关（RISK_PRIOR_MODE 灰度切换）

### 7.1 开关语义

| 态 | 语义 | 影响 |
|----|------|------|
| `off`（默认） | 画像只沉淀观察 | 存证 delta 无任何折损；v2 验真不带先验——**零影响态** |
| `on` | 画像回流通道生效 | ① v2 验真起点折扣：融合分 = trustLevel×0.3 + 组件分×0.7；② L2/L3 正向 delta 层级乘性：restricted ×0.5 / watched ×0.8 / trusted ×1.1 |

**安全设计**（切换前须知）：
- 只作用 L2/L3 自愿申报（L1 法治数据官方背书永不折损）
- 负向/零 delta 永不折损
- 入口守门（P1 语义/价值）×画像守门**叠乘封底 ×0.4**——总折损不超 60%
- 折扣是乘性不是禁入：restricted 角色 + 满分证据仍可过验真（0.79>0.7）——**通道永不开死，靠证据质量可爬回**
- trusted ×1.1 与 45号自愿披露激励 ×1.05 叠乘**封顶 ×1.15**

### 7.2 启用操作（运维决策）

```bash
# 1. 容器环境变量（compose 已预置默认 off）
#    docker-compose.yml: RISK_PRIOR_MODE=${RISK_PRIOR_MODE:-off}
RISK_PRIOR_MODE=on docker compose -p zhuxiang-jiu up -d backend

# 2. 验证开关生效
curl -H "X-Role: admin" http://127.0.0.2:8000/api/trust/risk/dashboard | jq .priorMode
# → true；看板⑤区块 enabled=ON

# 3. 抽样验证通道语义
#    restricted 档存证 delta 应为基准 ×0.5（回包 riskPriorGate.combinedMultiplier=0.5）
```

**启用前检查单**：
- [ ] 画像已运行 ≥2 周（riskEMA 有收敛样本）
- [ ] 复核申诉队列 pendingCount=0（积压先清）
- [ ] 已跑 ≥1 轮公平性桥接且 46号审计无 flagged（无群体偏差）
- [ ] watchlist 逐档复核（restricted 档确认非误伤——参考 §6.3 口径）

**关闭操作**（一键回退）：同命令改 `RISK_PRIOR_MODE=off` 重建容器即可——画像数据不丢，仅通道干预停用。

## 八、人工校准操作

```bash
POST /api/trust/risk/{trustId}/calibrate
{"trustLevel": 0.8, "note": "复核确认: 高频申报系业务旺季"}     # X-Role: admin

POST /api/trust/risk/{trustId}/calibrate/clear
{"note": "复核期满, 恢复自动计算"}                              # X-Role: admin
```

| 规则 | 说明 |
|------|------|
| 目标值域 | trustLevel ∈ [0,1]（0.8+/0.5+/0.3-/其余 → trusted/standard/restricted/watched） |
| 理由必填 | 1-300 字符（审计留痕） |
| 抗冲刷 | 后续风险事件回流**不冲掉**校准覆盖 |
| 可反复修正 | 零不可逆——再次 calibrate 覆盖，clear 回到计算值 |
| 与复核关系 | 复核 approve 即校准（同一入口两种触发）；直接 calibrate 用于运营主动处置 |

**使用建议**：校准是**例外通道**而非日常工具——批量校准前先跑公平性桥接确认不是系统性误伤（真系统性问题应调阈值，而非逐档校准）。

## 九、故障排查

### 9.1 fail-soft 行为对照（均为设计内行为，非故障）

| 现象 | 原因 | 处置 |
|------|------|------|
| 存证/评分正常但画像无沉淀 | 画像存储瞬断（fail-soft 放行主流程） | 查 backend 日志 `trust47_*_skip`；存储恢复后新事件自动恢复沉淀（历史不补） |
| 看板某区块显示 error | 该区块数据源异常（fail-soft 分区） | 其余区块照常用；按 error 字段定位（collusion→协同扫描数据源） |
| scan/collusion 结果与预期不符 | 上轮验收/测试残留数据 | 容器内清理 `zhuxiang:trust47:*`（画像）；注意互证对分析还读 `trust45:trust45_events:*`（存证留痕） |

### 9.2 常见问题

| 问题 | 排查 |
|------|------|
| 改字证据未被 semantic_reuse 命中 | 3-gram 相似度 >0.8 需证据 ≥29 字符（短文本改字相似度自然低——阈值保守防误判，属设计） |
| 同一角色重复 scan 计数不涨 | scan 幂等设计（与最近一次留痕一致跳过）——不是丢数据 |
| collusion scan 返回 marked=[] | 幂等：上轮已标记（看 skipped 列表）；或互证对 <3/共享 <2（未达阈值） |
| 公平性桥接返回"无有效分组" | 每 tier 组画像 <5（46号 MIN_GROUP_SAMPLES 口径）——先积累画像再桥接 |
| 开关 on 后 delta 未折损 | 检查三点：①L1 层不折损（设计）②delta ≤0 不折损（设计）③riskPriorGate 字段是否为 null（画像读取 fail-soft 时静默放行） |
| 桥接/审计 404 | 46号 registry 未入册——先 `POST /api/ai-gov/registry/sync` |

### 9.3 数据清理（慎用，仅验收/测试环境）

```bash
# 容器内 redis-cli
docker exec zhuxiang-jiu-redis-1 redis-cli --scan --pattern "zhuxiang:trust47:*"     # 画像
docker exec zhuxiang-jiu-redis-1 redis-cli --scan --pattern "zhuxiang:trust45:trust45_events:*"  # 存证留痕
# 注意事件键是 trust45:trust45_events:{id} 双重前缀, seq 在 trust45:events:seq
```

生产环境**禁止**清理：画像是累积视图，清空 = 风控记忆归零。

## 十、运维节奏与红线速查

### 10.1 节奏表

| 频率 | 操作 | 端点 |
|------|------|------|
| 日 | 看 watchlist + 命中统计 | GET /risk/dashboard |
| 日 | 处置待复核申诉 | 见 §六 |
| 按需 | 角色级检测（重点档案） | POST /risk/{id}/scan |
| 周 | 协同扫描 + 团伙证据链复核 | POST /risk/collusion/scan → GET /risk/collusion |
| 月 | 公平性桥接 + 46号审计 | POST /risk/dashboard/fairness-bridge |
| 观察期后 | 评估开启 RISK_PRIOR_MODE | 见 §七检查单 |

### 10.2 红线速查（操作不可逾越）

1. **画像不处罚**——任何操作不直接扣信值分；处罚走 45号既有事件流
2. **L1 不折损**——法治数据官方背书，风控永不作用
3. **负向不折损**——只影响正向入分通道
4. **团伙必人工**——collusive_suspect 仅标记，处罚必须复核证据链后经人工决定
5. **默认零影响**——RISK_PRIOR_MODE 不开则全链纯观察；开启是显式运维决策

---

*47号运维口径（2026-09-04）：风控的日常是"看与核"，不是"罚与禁"——
画像自动累积、通道自动收窄、申诉有正门、误判有出口；管理员
的职责是守住证据链的裁决质量， 而非追逐每一个风险数字。*
