# 50号·小竹语音信值积分引擎实施计划

> 前序: [48号_小竹智能语音中枢实施计划.md](48号_小竹智能语音中枢实施计划.md)(P0-P4 收官) · [49号_小竹可信函数调用深化实施计划.md](49号_小竹可信函数调用深化实施计划.md)(P0-P4 收官)
> 输入: 《语音交互信值积分规则细则 v2.0》(用户提供——已对齐 L1-L3 三层信值架构)
> 定位: 语音交互不仅是功能入口, 更是高置信度行为信号采集源——把"用户说话"确权为"可信行为的数字刻度"

---

## 一、模块定位与全站统筹视图

50号 = 语音行为 → 信值积分的确权引擎。它不新建语音功能, 而是给 48/49号已交付的语音中枢装上"计分仪表盘", 并以正确的轨道接入 45号三层信值:

| 既有模块 | 在本方案中的角色 | 集成方式 |
|---------|----------------|---------|
| 48号 语音中枢 | 行为信号源(轮次/意图/共创/失败挖掘) | turn 后置钩子(服务层, fail-soft) + 共创桥接 |
| 49号 可信函数调用 | 真实性信号源(consent 双因子/预算/声纹代理/ref) | 信号复用 + 预算事件监听 |
| 45号 信值模块 | 信值落点(L2/L3 经 deposit 验真; UEBA 守门全继承) | submit_deposit + submit_repair 既有通道 |
| 47号 画像/指纹 | 反作弊复用(3-gram 语义指纹/时序规律) | import 复用(不改动其档案) |
| 46号 AI 治理 | 公平性审计(L3 天花板/新用户上浮的分布核验) | submit_samples 显式上报 |

**三轨架构(核心裁定, 详见 §三)**: 语音积分本体在 voice50 独立台账(防刷封顶/衰减/对冲全在台账层消化); L2/L3 经 T+1 反作弊清洗后聚合走 45号 deposit 验真入信值; L1 真实性信号实时作用风控域(不污染 45号法治因子)。

## 三、红线冲突辨析(五处——裁定与转化)

### 1. 反语音霸权 vs "90 天无语音月衰减 5%"

48号铁律: **不用语音不扣分**。v2.0 §七衰减直接违反(不用语音=信值缩水)。

**裁定**: 衰减对象**只能是 voice50 激励池**(语音行为挣得的贡献余额——"保鲜"而非"惩罚"), **绝不触碰已入账的核心信值分**; 保底 30% 语义即"历史贡献的底薪不没收"。核心信值一旦经 45号验真入账, 永不因"不用语音"回退。看板口径注明: 池是"语音贡献余额", 不是信值分。

### 2. 积分入信值通道 vs 45号九因子封闭注册表

45号 record_event 校验因子 ∈ 九因子(L1×3/L2×3/L3×3), **不可新增因子**; 且 48号既有红线"积分入信值走 45号 deposit 验真"。v2.0 的"L1 积分即时到账"若直写 45号 L1, 会把"声纹登录"灌进 legal_record/regulatory/asset_integrity——**法治域因子被交互域信号污染**。

**裁定(三轨)**:
- **L2/L3 轨(T+1)**: 结算批聚合当日语音积分 → `submit_deposit(layer, factor, ...)` 走验真管线入 ethics_evidence(L2)/contribution_net·longtail_good(L3)——语义正确且继承全部验真/守门/因果净贡献数学;
- **L1 轨(实时)**: 真实性信号实时入 voice50 台账+暴露风控状态(供 47号画像/守门消费), **不入 45号 L1**; v2.0"用于风控决策"由风控域承接而非法治分承接;
- **台账轨(本体)**: 全部 14 行为积分先入 voice50 独立台账, 防刷封顶在台账层消化后才具备桥接资格。

### 3. 声纹代理不作凭证 vs 声纹验证 ×1.5 加成

49号 P1 明示声纹为确定性哈希代理(**不作身份凭证**)。若 proxy 态直接给 ×1.5 并桥接入信值, 等于用弱信号换真信值。

**裁定**: 双态交付——`voiceprintMode=proxy`(默认)时加成照常计算但**只入台账**且审计标注; `real`(国标 SDK 集成后翻转, 外部待办)才允许带加成的积分进入 T+1 桥接轨道。活体检测同口径(mock 声谱特征确定性模拟, 供反作弊管线联调)。

### 4. 反语音霸权(再裁定) vs "累计扣分>20 触发语音功能降级"

**裁定**: 降级只冻结**积分获取**(voice50 标记 frozen, 恢复需人工复核), **绝不阻断语音入口本身**——语音是可选入口红线一字不改。同理反作弊"账号临时锁定"处置也只作用积分域+上报, 登录/语音通道走既有安全模块口径。

### 5. 预算均等 vs 群体系数(残障 ×1.2 / 儿童 L3 ×0.8)

49号铁律: 预算只按用户自主偏好分级。群体系数作用的是**积分折算**, 不是预算分级——预算红线不破。但群体乘数须经 46号公平性采样上报核验(分布无歧视放大), 且群体认定默认 self-declared+认证待办(外部), mock 期由 group_profile 显式配置驱动测试。

## 四、架构设计

```
48号 turn 流 ──后置钩子(fail-soft, VOICE50_MODE=off 默认)──▶ voice50 事件管道
                                                                │
              ┌─────────────────[反作弊闸门(实时层)]─────────────┤
              │  TTS 活体模拟 / 诱导套取 NLU / 预算 429 监听       │
              ▼                                                  ▼
      [规则引擎: 行为注册表 × 系数]                        voice50_events(原始事件)
       声纹×(1.5|0.3) · 质量×(1.2|0.5) · 群体系数              │
       日限 · 防刷封顶(基线×3, 超限×0.1)                        │
              │                                                  │
              ▼                                                  ▼
      L1 实时轨(台账+风控状态) ◀──────────────┐          L2/L3 待结算队列(pending)
      · 供 47号画像/守门消费(只读桥)           │                  │
      · 扣分>20 → frozen(积分域)              │        [T+1 结算 job / 手动补偿]
                                             │                  │
                                             │      反作弊清洗(脚本化 3-gram/共用聚类)
                                             │                  │
                                             ▼                  ▼
      45号 submit_repair(修复对冲≤50%) ◀── voice50_ledger(激励池: 衰减/抵扣/余额)
                                             │                  │
                                             │                  ▼
                                             │      45号 submit_deposit(验真→入账)
                                             │      L2→ethics_evidence
                                             │      L3→contribution_net/longtail_good
                                             ▼
                                    explainability_ref(exp-voice50-*)
                                    会员/管理端归因查询
```

**四组件**:
1. **行为注册表**(voice50_rules, 热更新): 14 行为×{layer, 基础分, 加成链, 扣分项, 日限, 目标因子}——启动自检对齐 45号九因子映射;
2. **规则引擎**(确定性数学): 系数链 `final = base × voiceprint × quality × group`, 日限截断, 封顶 `min(earned, 3×baseline)+溢出×0.1`——数字全部来自计算层(LLM 只做语义分类: 礼貌/意图类别);
3. **结算器**(T+1): 批次扫描 pending→清洗→聚合→deposit 申报(证据=批次明细 ref 串联, voluntary=True 激励位)→入账回写;
4. **激励池**(voice50_ledger): 余额/已抵扣/衰减史; 对冲走 45号 submit_repair(kind=voice_pool_offset, value=池内划扣)——α/β/γ 修复数学全继承。

**质量系数口径(确定性)**: 规则轨 pattern 精确命中=0.95 / 近似命中=0.7 / 兜底=不计; LLM 轨(开时)取模型置信度。≥0.8 计有效积分(对齐 v2.0 §一-2)。

## 七、分期计划(P0-P5 六期)

### P0 引擎骨架与规则注册表

- voice50_rules 行为注册表(14 行为全量+九因子映射声明)+启动自检(对齐 45号 LAYER_OF)
- 事件管道: 48号 turn 后置钩子(fail-soft; VOICE50_MODE=off 默认零影响)
- L1 实时轨(台账入账+防刷封顶数学)+explainability_ref 绑定(exp-voice50-* 范式)
- 端点: GET voice-score/my(会员)+GET rules/PUT rules/{behavior}(admin 热更新留痕)
- 第 17 语音指令"我的语音积分"(48号 指令集纯增量)

**测试**: 专项约 35 项(注册表自检/钩子零影响/封顶数学/ref/查询/热更新留痕)

### P1 L1 四行为与声纹双态

- 四行为全量(登录/确认/环境/反欺诈)——49号 consent·预算·会话信号复用
- 声纹验证器双态(proxy/real)——proxy 加成只入台账+审计标注
- L1 降级(扣分>20 → 台账 frozen, 人工复核恢复端点)

**测试**: 专项约 30 项(系数数学×1.5·0.3·0.5·1.3/日限/扣分项/降级与恢复/双态审计)

### P2 L2 五行为与 T+1 结算

- 五行为全量(意图/授权/反馈/礼貌/跨文化)——48号 共创+49号 预算偏好桥接
- 交互质量系数(置信度确定性映射+连贯性)
- voice50_settlement 结算账本(批次/清洗/聚合/deposit 申报/入账回写)+结算 job+POST settle 手动补偿端点

**测试**: 专项约 35 项(五行为数学/质量系数/批次幂等/清洗拒绝原因/deposit 证据串/入账对账)

### P3 L3 五行为与公平天花板

- 四行为全量(语料/佐证/问答/伴侣)+联邦梯度预留接口(预算前置校验)
- 佐证 per-claim 走 45号验真(采信 ×2)
- 动态天花板+新用户首月上浮 50%+46号公平性采样上报(语音积分分布 group 标签)

**测试**: 专项约 30 项(天花板数学/上浮/验真桥接/伴侣月度/公平性上报)

### P4 反作弊五模式与处置申诉
