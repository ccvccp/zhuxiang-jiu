> 环境生产: 47.236.61.117(zxjiu.com) + 本地开发

## 一、背景与目标

45号 P0-P7 已全线交付(465 专项断言, 34 端点生产运行), 但对比全站
四大模型(68号信值/71号支付/73号会员/74号NexusFlow)缺**三态灰度模式层**
——决策无开关、无护栏、无运行时切档。本次升级补齐该层, 使 45号具备:

- 决策可控(off 关闭 / shadow 观察 / assist 生产)
- 业务护栏(三指标恶化自动暂停)
- 运行时切档(免容器重建, 人工留痕)
- 全站统一转段 SOP 与回滚口径

## 二、三态与读取链

`TRUST45_MODE`(编号惯例, 避开已有 TRUST_RADAR_MODE):

| 态 | 行为 |
|---|---|
| off(默认) | 17 决策端点 409(决策面关闭); 观测/纠错面不受影响 |
| shadow | 决策放行 + 响应留痕标记 `trust45Mode` 字段 |
| assist | 决策生效(生产档) |

读取链(优先级): **护栏暂停 > 运行时 override > 环境变量 > 默认 off**。

## 三、端点分类(34 → 38)

| 面 | 数量 | 端点 |
|---|---|---|
| 决策面(门控) | 17 | roles 建档/score/events、radar/scan、probes、deposits、repairs、repairs/verify、redeem、redeem/confirm、convert、merchant/deposit、patches、open/redeem/confirm、open/deposits、open/convert、learning/run |
| 纠错/回流豁免 | 5 | appeals 提交/队列/decide、learning/collect、attribution(宪法口径: 观测与纠错永不关停) |
| 观测面 | 12 | roles 视图/probes/deposits/status/repairs plan/detail/balance/ledger/learning-status/patches/open-query/open-audit/dashboard |
| 控制面(新增) | 4 | GET /mode、POST /mode/override、POST /mode/guard、POST /mode/resume |

实现: `routes/trust_value_routes.py` 逐端点 `_gate()` 门控 + `_mark()`
标记(纯增量, 既有端点语义零变化); `services/trust45_mode_service.py`
(蓝本: 68号 xinzhi_mode_service); `repositories/trust_value_repository.py`
新增 `trust45_grayscale` 单例状态表(load/save 双模式)。

## 四、护栏三指标(45号语义)

| 指标 | 基线 | 代理语义 |
|---|---|---|
| appealOverturnRate 申诉翻转率 | 0.05 | 裁决 overturned 占比——误判代理 |
| circuitRate 熔断触发率 | 0.02 | L1 熔断档案占比——误杀代理 |
| redeemRejectRate 兑换拒绝率 | 0.05 | 防挤兑四件套拦截占比 |

恶化判定: (cur-base)/base > **3%** 自动暂停(基线 0 时 cur>0 即恶化);
paused 留痕 pausedReason/breachTrail(≤50); 恢复须人工 resume(决策留痕)。
护栏是保护机制(功能开关非处罚), 可自动; 全确定性(阈值比较, LLM 禁入)。

## 五、控制面 API

| 端点 | 鉴权 | 说明 |
|---|---|---|
| GET /api/trust/mode | 无 | 灰度总览(模式/读取链/护栏/红线公示) |
| POST /api/trust/mode/override?mode= | X-Member-Id | 运行时切档(空串清除回落 env) |
| POST /api/trust/mode/guard | X-Member-Id | 护栏检查(baseline 可选覆盖) |
| POST /api/trust/mode/resume?note= | X-Member-Id | 人工恢复(决策留痕) |

## 九、上线实测修复(P0, 2026-09-15 22:22)

生产三层自验发现**灰度态序列化 P0 缺陷**(本地内存模式不可见,
仅 Redis 模式暴露):

- 症状: 首次请求 mode 正常(assist/env), 第二次起决策面全 409
  `guard_pause`——Redis 读回字符串 `"0"` 在 Python 为真值,
  `paused` 未注册 bool 清单致永久误判暂停
- 伴生: `metrics`/`breachTrail` JSON 列表未反序列化,
  `list("[]")` 拆成 2 字符 → checkCount/breachCount 虚报 2
- 修复: `trust_value_repository.py` 序列化清单补注册
  (`_BOOL_FIELDS` + `paused`; `_deserialize` + metrics/breachTrail
  JSON 分支)——对齐 68号 xinzhi_repository 清单口径
- 回归: `test_trust45_mode.py` 新增 5 条序列化往返回归断言
  (53/53 全绿); 存量 p0~p7 全量回归 423 断言全绿; ruff 全绿
- 部署: 提交 `c3361a6` 已推送, 生产容器重建完成
- 生产复验: mode=assist/env, 建档 200+assist 标记, 档案/余额/
