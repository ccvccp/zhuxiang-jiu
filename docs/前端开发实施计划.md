## 三、每任务统一工作流（对齐项目工程纪律）

```
实现(按规格书绑定表) → 语法校验(node --check / esprima)
  → 浏览器端到端(mock+live 双态各一轮, 回落路径必须演练)
  → 六查清单(规格书 §5: 模板/令牌/组件/绑定/状态/鉴权)
  → 回归(同批既有页 + 换肤路径若涉色)
  → 提交(单任务单提交, 信息注明任务号)
```

**提交粒度**：T1.x 每页一提交；T3.1 独立提交；批次二每页一提交。

## 四、风险与前置核对

| 风险 | 影响任务 | 前置动作 |

| `/api/product/{id}` 的 id 形态与 data.js SKU 键不一致 | T1.2 | 实施前 curl 一条真实 id（如 ZX42-2026B01 形态核对），确定 URL 参数方案 |
