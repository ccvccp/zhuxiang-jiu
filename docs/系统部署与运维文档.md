## 1. 系统概述

### 1.1 架构

```
┌─────────────────────────────────────────────────┐
│                  Docker Compose                 │
│  ┌───────────────────────┐  ┌────────────────┐  │
│  │   backend (FastAPI)   │  │  redis:7-alpine│  │
│  │   Uvicorn :8000       │←→│  :6379         │  │
│  │   4 层架构            │  │  AOF 持久化    │  │

         ↑ 端口映射 8000:8000 / 6379:6379
```

## 2. 环境要求与前置准备

### 2.1 硬件要求

| 资源 | 最低要求 | 推荐配置 |
|------|---------|---------|
| 物理内存 | 8 GB | 16 GB |
| CPU | 2 核 | 4 核+ |

### 2.2 软件要求

| 软件 | 版本 | 用途 |
|------|------|------|
| Windows 10/11 | 21H2+ | 宿主系统 |
| WSL2 | 最新内核 | Docker 后端 |
| Docker Desktop | 4.30+ | 容器引擎 |
| PowerShell | 5.1+ / 7+ | 脚本执行 |

### 2.3 WSL2 配置(.wslconfig)

**文件位置**:`C:\Users\<用户名>\.wslconfig`

**编码要求**:**UTF-8 with BOM**(PowerShell 5.1 兼容性要求)

**推荐配置**:
```ini
[wsl2]
memory=8GB
processors=4
swap=4GB
localhostForwarding=true
defaultUser=<你的用户名>
pageReporting=false
sparseVhd=true
```

**验证配置生效**:
```powershell
# 重启 WSL 使配置生效
wsl --shutdown
# 重启 Docker Desktop(开始菜单点击),等待托盘图标变绿

# 验证(应显示约 8.0Gi)
wsl -d docker-desktop free -h

# 验证 Docker 引擎(应显示约 8.59GB)
docker info --format "Total Memory: {{.MemTotal}}; CPUs: {{.NCPU}}"
```

> ⚠️ **注意**:`.wslconfig` 必须使用 **UTF-8 BOM + CRLF** 行尾。LF 行尾会导致 WSL 解析失败,配置不生效。

## 3. 部署指南

### 3.1 首次部署

```powershell
# 1. 启动 Docker Desktop(开始菜单),等待托盘图标变绿
# 2. 进入项目目录
cd d:\网站架构设计

# 3. 构建并启动(首次需构建镜像)
docker compose -p website-arch up -d --build backend

# 4. 等待健康检查通过(约 30-80 秒)
docker compose -p website-arch ps
# 期望:backend 显示 Up (healthy)

# 5. 验证 API
curl http://localhost:8000/api/decision/health
# 期望:{"status":"healthy",...}
```

### 3.2 项目名说明

由于项目路径包含中文(`d:\网站架构设计`),Docker Compose 无法自动推断项目名,必须显式指定 `-p website-arch`:

```powershell
# 所有 docker compose 命令都需要 -p 参数
docker compose -p website-arch up -d backend      # 启动
docker compose -p website-arch ps                 # 查看状态
docker compose -p website-arch logs backend       # 查看日志
docker compose -p website-arch down               # 停止
```

### 3.3 镜像重建

当修改源码或依赖后,需要重新构建镜像:

```powershell
cd d:\网站架构设计
docker compose -p website-arch build --no-cache backend
docker compose -p website-arch up -d backend
```

### 3.4 使用启动脚本

项目提供 `scripts/docker-start.ps1` 脚本(支持 7 种模式):

```powershell
# 默认:构建 + 启动 + 查看日志
.\scripts\docker-start.ps1

# 仅构建
.\scripts\docker-start.ps1 -Action build

# 仅启动(不重新构建)
.\scripts\docker-start.ps1 -Action up

# 查看日志
.\scripts\docker-start.ps1 -Action logs

# 查看状态
.\scripts\docker-start.ps1 -Action status

# 重启服务
.\scripts\docker-start.ps1 -Action restart

# 停止并清理
.\scripts\docker-start.ps1 -Action down

# 验证健康检查
.\scripts\docker-start.ps1 -Action verify
```

容器启动后,健康检查遵循以下时序:

| 时间点 | 状态 | 说明 |
|--------|------|------|
| 0-30s | `Up (health: starting)` | 启动期,不算失败 |
| 30-40s | `Up (health: starting)` | 首次检查 |
| 30-80s | `Up (healthy)` | 检查通过 |

配置参数:
- `start_period: 30s` - 启动期
- `interval: 10s` - 检查间隔
- `timeout: 5s` - 超时
- `retries: 5` - 重试次数

## 5. 配置说明

### 5.1 docker-compose.yml 关键配置

```yaml
services:
  backend:
    build: ./zhuxiang-jiu/backend
    ports:
      - "8000:8000"
    environment:
      - REDIS_URL=redis://redis:6379/0    # Redis 连接(服务名)
      - LOCK_MODE=redis                   # 锁模式:asyncio|redis
      - STORE_MODE=redis                 # 存储模式:asyncio|redis
      - PORT=8000
      - HOST=0.0.0.0
    depends_on:
      redis:
        condition: service_healthy        # 等 Redis 健康后启动
    mem_limit: 1g                         # 内存硬上限
    memswap_limit: 2g                     # 内存+swap 上限
    mem_reservation: 512m                 # 软预留
    command: >                            # 启动命令(seed + uvicorn)
      sh -c "cd /app &&
             python scripts/seed_redis.py || echo '[WARN] seed failed...';
             cd /app &&
             exec uvicorn main:app --host 0.0.0.0 --port 8000 --workers 1 --no-access-log"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/api/decision/health"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis-data:/data                  # 数据持久化卷
    command: redis-server --appendonly yes  # AOF 持久化
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 5
      start_period: 3s
```

### 5.2 环境变量说明

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `REDIS_URL` | `redis://redis:6379/0` | Redis 连接字符串 |
| `LOCK_MODE` | `redis` | 锁模式:`asyncio`(单进程)/ `redis`(多进程) |
| `STORE_MODE` | `redis` | 存储模式:`asyncio`(内存)/ `redis`(持久化) |
| `PORT` | `8000` | 服务端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `CORS_ORIGINS` | localhost:8080,3000 | CORS 白名单(逗号分隔) |
| `LOG_LEVEL` | `INFO` | 日志级别 |
| `PYTHONPATH` | `/app` | Python 模块搜索路径 |

### 5.3 锁与存储模式

| 模式组合 | LOCK_MODE | STORE_MODE | 适用场景 |
|---------|-----------|------------|---------|
| 单进程内存 | `asyncio` | `asyncio` | 单元测试、本地开发 |
| 多进程持久化 | `redis` | `redis` | **生产环境**(默认) |

> ⚠️ 生产环境必须使用 `redis` 模式,确保跨进程并发安全和数据持久化。

### 5.4 Redis Key 规范

| 实体 | Key 格式 | 类型 |
|------|---------|------|
| 代理商 | `zhuxiang:agent:{id}` | Hash |
| 库存 | `zhuxiang:inventory:{productId}` | Hash |
| 仓储库位 | `zhuxiang:warehouse:slots` | Hash |
| 入库日志 | `zhuxiang:warehouse:inbound_log` | List |
| 出库日志 | `zhuxiang:warehouse:outbound_log` | List |
| 订单 | `zhuxiang:orders` | List |
| 区域认领 | `zhuxiang:shipping_claims` | Hash |
| 分布式锁 | `lock:{original_key}` | - |

## 8. 排障指南

### 8.1 常见问题速查

| 症状 | 可能原因 | 解决方案 |
|------|---------|---------|
| 容器 `Exited (137)` | OOMKilled(内存不足) | 检查 `.wslconfig` 内存配置 |
| 容器 `Exited (1)` | 应用启动失败 | 查看 `docker logs` |
| `unhealthy` 状态 | 健康检查失败 | 检查 Uvicorn 是否启动 |
| `project name must not be empty` | 中文路径 | 添加 `-p website-arch` |
| `failed to connect to docker API` | Docker 引擎未启动 | 启动 Docker Desktop |
| `ModuleNotFoundError: No module named 'core'` | 镜像构建问题 | `build --no-cache` 重建 |
| 容器反复重启 | 配置错误或依赖缺失 | 查看日志定位 |

### 8.2 诊断命令

```powershell
# 1. 检查 Docker 引擎
docker info --format "Server Version: {{.ServerVersion}}"

# 2. 检查 WSL2 内存(应约 8.0Gi)
wsl -d docker-desktop free -h

# 3. 检查容器状态
docker compose -p website-arch ps -a

# 4. 查看后端日志
docker compose -p website-arch logs --tail 100 backend

# 5. 检查端口占用
netstat -ano | findstr :8000

# 6. 进入容器调试
docker compose -p website-arch exec backend sh

# 7. 检查容器内文件
docker compose -p website-arch exec backend ls -la /app/
docker compose -p website-arch exec backend ls -la /app/core/

# 8. 测试容器内网络
docker compose -p website-arch exec backend curl -f http://localhost:8000/api/decision/health
```

### 8.3 OOMKilled 排障

**症状**:容器 `Exited (137)` 或 `OOMKilled`

**诊断**:
```powershell
# 检查容器退出原因
docker inspect --format '{{.State.ExitCode}} - {{.State.OOMKilled}}' <容器名>

# 检查 WSL2 内存
wsl -d docker-desktop free -h
# 期望:total 约 8.0Gi
```

**解决**:
1. 确认 `.wslconfig` 配置正确(UTF-8 BOM + CRLF)
2. 执行 `wsl --shutdown` 重启 WSL2
3. 重启 Docker Desktop

### 8.4 Docker 引擎无法启动

**症状**:`failed to connect to docker API`

**解决步骤**:
```powershell
# 1. 更新 WSL2 内核
wsl --update

# 2. 启动 Docker 服务(管理员 PowerShell)
Start-Service com.docker.service

# 3. 启动 Docker Desktop(开始菜单)

# 4. 等待托盘图标变绿(30-60 秒)

# 5. 验证
docker info --format "Server Version: {{.ServerVersion}}"
```

### 8.5 镜像构建失败

**症状**:`docker compose build` 失败

**诊断**:
```powershell
# 使用诊断脚本
.\scripts\build-diagnose.ps1

# 手动检查
docker compose -p website-arch build --no-cache backend 2>&1 | Select-String "ERROR|FAIL|error"
```

**常见原因**:
- `pip install` 失败 → 检查网络代理
- `COPY` 失败 → 检查文件路径和 `.dockerignore`
- `test -f` 失败 → `__init__.py` 缺失

### 8.6 .wslconfig 配置不生效

**验证文件格式**:
```powershell
# 检查编码(应有 UTF-8 BOM)
$bytes = [System.IO.File]::ReadAllBytes('C:\Users\<用户名>\.wslconfig')
# 前 3 字节应为:EF BB BF

# 检查行尾(应为 CRLF)
$content = Get-Content 'C:\Users\<用户名>\.wslconfig' -Raw
([regex]::Matches($content, "`r`n")).Count  # 应 > 0
```

**修复方法**:参考 `.wslconfig.bak` 备份,确保 UTF-8 BOM + CRLF 格式。

```powershell

# === 停止 ===
docker compose -p website-arch down                     # 停止(保留数据)
docker compose -p website-arch down -v                 # 停止+删数据卷

# === 重启 ===
docker compose -p website-arch restart backend          # 重启后端

# === 重建 ===
docker compose -p website-arch build --no-cache backend # 重新构建镜像
```
