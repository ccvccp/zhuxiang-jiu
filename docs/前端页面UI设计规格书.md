> **重制版说明（2026-10-17）**：原版为四批次前端治理的设计基准（含 §1 页面规格/§4 绑定表/§5 六查清单），在 10-17 IDE 误撤销事故中丢失，本文依据 T1-T4 批次实施记录与《前端开发实施计划.md》《前端页面与接口映射UI设计文档.md》（两份均已恢复）重制**治理规范部分**；逐页绑定表请以映射文档为准（原文绑定表未随本文恢复）。四批次已全部完成，本文为存量规范基准+后续新页验收依据。

## 一、设计令牌体系（T3.1 治理后基准）

### 1.1 基础令牌（css/style.css `:root`）

主题色系、`--color-white/muted/text-faint/text-mid/text-light/ok/ok-deep/ok-bg/danger-bg/info/warn/gray-light/border-gray` 等 12+ 语义令牌（T3.1 增补，值=原内联高频色一一映射，零视觉变化令牌化 992 处/55 文件）。

### 1.2 令牌使用铁律

- 新代码**禁止硬编码色**——一律 `var(--token)`；未引 style.css 的独立页用 `var(--token, 原值)` fallback 双轨。
- 白名单四类（[T3硬编码色白名单.md](T3硬编码色白名单.md)）：JS canvas fillStyle（247 处）/渐变邻域（204 处）/低频一次性（1160 处）/品牌装饰豁免。
- **换肤铁律**：site-theme 换肤路径永不关停；换肤路径前端覆盖为待建项（登记）。

## 二、组件规范

### 2.1 badge 六语义（T3.2 定案）

| 语义 | 类名/令牌 | 用途 |
|---|---|---|
| green | badge.ok→green | 成功/通过 |
| red | badge.fail→red | 失败/拒绝 |
| weak | 灰 #f4f4f4 | 弱化态（非黄灯） |
| yellow | 警示黄灯 | 第六语义（收编为规范） |
| blue/gold/purple/orange/manual | 扩展分类 | 业务标签非状态灯（白名单） |

### 2.2 空态标准（T3.3）

`.empty-state` 全站标准（居中灰字+场景文案）；各 dashboard `.dash-empty` 沿用；空态必须诚实提示（非假数据）。409 提示范本：payport-dashboard「容器需 PAY71_MODE=shadow/assist」。

### 2.3 stat 卡初值（T3.4）

初值统一 `--`（勿用 0 或"加载中…"）；刷新范式：30s setInterval 或手动刷新按钮（观测页豁免范式）。

### 2.4 观测页失败回落（T2 基准）

接口失败回落现静态文案：`观测面暂不可达 · 点击「手动刷新」重试`；TBODY 自动 colspan；保留 errBar 具体错误信息；不编造数据。

## 三、可访问性与响应式基准（T4 定案）

- **对比度**：正文 13.97:1 / 辅助 5.33:1 / 主色 4.86:1 / 按钮白字 4.86:1 全达标；辅助文字 ≥4.5:1（`--color-muted: #8a8a8a` 达弱化态 3.16:1）。
- **金色 #c9a961**：仅用于大号价格数字/数据系列/金按钮边框强调；12px 金字禁用（改 text-light）；挑战者图表金色 15 处为数据可视化语境豁免；`.btn.gold` 白字品牌装饰豁免。
- **窄屏**：单列堆叠；挂件面板 `width:360px; max-width:calc(100vw-40px)`（375px 视口 335px，等效 min(380px, 92vw)）；产品卡 grid auto-fill。
- **键盘**：按钮一律原生 button/a；弹窗 Esc 可关；div[onclick] 34 处登记已知项（dashboard 测试页为主）。
- **挂件时序**：探测失败隐藏多模态键时延 ≤1s（probeHub 800ms Promise.race 竞速，实测 49ms）。

## 四、live 化双模式规范（T1 基准）

- **双轨渲染**：页面先渲染静态（不白屏）→ 异步拉取成功重渲染 → **失败静默回落静态**（回落铁律）。
- **版式同构红线**：mock/live 同容器结构同版式；验证法=168 元素 computed 色快照对比 0 差异。
- **契约实测先行**：接入前 curl 实测响应字段，再按绑定表落 DOM。
- **全字段 escapeHtml** 后入 DOM；10s AbortController 超时。
- 鉴权范式：`Authorization: Bearer {accessToken}` + `X-Member-Id` 双头（compat 中间件剥离裸兼容头）。

## 五、六查清单（每任务验收）

1. **模板**：页面结构与规格书 §1 一致（版式同构）
2. **令牌**：零新增硬编码色（grep 复核+白名单核对）
3. **组件**：badge 六语义/空态标准/stat 初值按 §二
4. **绑定**：接口绑定与映射文档绑定表一致（字段名以实测为准）
5. **状态**：mock/live/失败回落三态齐备（route abort 演练）
6. **鉴权**：公开/登录/admin 边界与中间件白名单一致

## 六、验证工作流

```
实现 → 语法校验(node --check / esprima)
  → Playwright e2e(mock+live 双态各一轮, 回落路径必须演练)
  → 六查清单 → 回归(同批既有页+换肤路径若涉色) → 提交(单任务单提交)
```

联调环境：本地反代静态服务器（http.server 子类，静态根+/api→后端端口）实现前端同源；失败态用 `page.route("**/api/**", abort)` 模拟。
