## 二、匹配逻辑四层解剖（本批实证）

### 第 1 层：persist 归一（_resolve_drama，入库瞬间）
- **dedup_key 双键**：itemId 优先 / 剧名|平台兜底；
- 本批两种走向：①9 主剧+2 推荐位 → 无同名行 → 新建（dedup_key=itemId）；②我李长生/重回1988 → **按剧名匹配到既有 multi 行合并**（不建新行、不换 itemId——multi 行身份保持，ep 由契约刷新）；
- 同剧双码 9 部（与批 1 重复）在更上游的**契约层 series_id 合并**已被去重，未到 persist。

### 第 2 层：L1 精确匹配（matcher，同名快照 ↔ 主行）
本批 L1 补链=2，正是两处「跨源激活」：
- 《装穷参加同学会》djgc 悬空快照 → 新行 #314；
- 《这一次，女婿他绝不低头》duanjubaike 悬空快照 → 新行 #310；
- 我李长生/重回1988 的 hongguo 快照在 persist 时已直接挂行，无需 matcher——**L2 跨源建行=0 属正常**（新行均单源起步，第二源出现才触发 L2，如末世选择第二季的 djgc×sdc_ai 案例）。

### 第 3 层：L3 fuzzy 复核拦截（季数/改名保护）
《谁说没灵根不能修仙的？之无灵证道》（无季数版，78 集）vs djgc 的「第 40 季 / 41 季 / 42 季」三快照：
- contain 1.00（子串全含）与 fuzzy 0.88 均**入复核队列不自动链**——季数差异是 IP 续季不是同一部剧；
- 该 IP 已更新至 42 季（池内最长续季纪录：对比聚宝仙盆 S13/万妖图录传 S13），本批入池的是系列起点——**L3 拦截避免把 40 季的 djgc 热度错记在第一季头上**。

### 第 4 层：contentType 分轨（新增维度，匹配佐证备役）
本批新快照首次实测 `raw_json.contract.contentType` 双态落地（谁说没灵根=manju / 这一次女婿=duanju）——当前不参与匹配判定，但为未来提供分轨佐证：同一 IP 的漫剧续季 vs 真人短剧翻拍可借 contentType 区分，避免跨形态误链。

## 四、启示

1. **三通道各司其职的实证**：分享链投喂（主剧+itemId 指纹）+ 推荐位轮换（2 部计划外新剧零成本捕获）+ 聚合榜悬空快照（被新入池剧激活，L1 双向受益）——批3 一轮把三条发现链路全部走到；
2. **merged 路径保 multi 行身份**：L2 建行的 multi 行不被 hongguo 契约覆盖为 hongguo（itemId 不夺占），ep 等事实字段可被更强数据源刷新——归一键设计在多源汇聚下的稳健性得到验证；
3. **L3 季数拦截对长寿 IP 尤其关键**：42 季 IP 的各季热度若被 contain 1.00 误链，热度归因将错乱一个数量级；
4. **PUGC 行标记池边界**：《哪吒传奇3》-7（ep=0、无 itemId）如实入库——share 池的判定标准是「红果分发的内容」而非「系列短剧」，边界样本留档比丢弃更有观测价值。

### 6.6 方法论警示：matcher 回填抹平历史期 linked 演化

matcher/persist 补链会**回写历史期悬空快照的 drama_id**（10-15 期已被刷到 linked 39，与 10-16 期一致）——事后从 DB 做两期 linked 集合差**无法还原 +21 的逐部时间线**。D+N 互链转化研究须以**入池时点的运行日志**为准；DB 快照只反映「当前累计稳态」。本节 6.2 的构成拆解即基于稳态+批4 23 链全对照反推。
