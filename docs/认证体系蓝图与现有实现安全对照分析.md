## 一、总览：超出蓝图的部分（现有优势）

| 蓝图要求 | 现有实现 | 判定 |
|---|---|---|
| 修改密码后强制下线 | `auth_service.py:936-939` 改密**级联吊销该会员全部已签发令牌**（全设备）+ 签发新令牌对 | ✓ 超出（蓝图仅"清除 Session"） |
| refresh token 防重放 | jti 黑名单（Redis/内存双模式）+ refresh 轮换即吊销旧 jti（`auth_service.py:821`）+ access/refresh 类型隔离 | ✓ 等价偏优（蓝图为"存哈希+usedAt 标记"） |
| 密码哈希存储 | PBKDF2-HMAC-SHA256 **120,000 轮 + 每用户独立盐** + 恒时比较（`core/auth.py:37,55-79`）；旧固定盐 SHA256 登录即透明升级 | ✓ 达标（蓝图推 bcrypt/Argon2，PBKDF2-120k 为 OASIS/OWASP 认可等价方案） |
| 操作日志审计 | `_record_auth_event` 登录失败留痕 + 43 号撞库计数 | ✓ 有 |
| 短信验证码通道 | 60s 频控/日 10 条/3 次作废/TTL 5min | ✓ 超出蓝图粒度 |
| 2FA/管理员侧 | TOTP + IP 白名单 + 异地告警 + 5 次锁 30min + 首登强制改密 | ✓ 蓝图未涉及（管理员体系独有） |

## 三、蓝图采信分级

- **采信（规范层）**：密码强度三字符类/密码历史 3-5 次/防暴力限流阈值/传输加密要求/操作日志字段——全部与 G1-G4 修复对齐；
- **不采信（代码层）**：Node.js Express + bcryptjs + Sequelize 全套代码（技术栈不符）；Vue3 前端组件（项目前端另行规划）；其 JWT 双令牌设计与我们等价但实现路径不同，仅作交叉参考；
- **蓝图自身缺陷提示**：其密码修改接口把 `new_password` 明文放请求体（仅靠 HTTPS 兜底）、`confirm_password` 后端冗余字段、mockDB 直返成功——**参考其规范时忽略其代码细节**。
