## 一、系统概述

竹香酒商城（zxjiu.com）是一个**AI 深度融合的酒类电商+内容+短剧聚合平台**，当前态核心数字：

| 维度 | 数据 | 出处 |
|---|---|---|
| 后端路由 | 37+ 路由文件、505→2581 端点（v8.0 基线 505，此后模块持续扩展至 2581） | v8.0 核对基线+近期模块 |
| 测试基线 | 1610 条测试断言场景（多批次单元测试报告累计） | 各批次测试报告 |
| 短剧数据业务 | 352 部剧相关业务（85号短剧池，主表 327 部+跨池联动） | 85号持久化层 |
| 前端页面 | 47 页面（C 端 15 页全 live 化+治理观测看板+admin 后台） | 前端四批次 |
| 生产数据 | Redis 122,973 键（zhuxiang: 前缀全量） | 国内 ECS 实测 |
| 生产部署 | 国内 ECS 8.147.66.237 单栈（2026-10-17 海外机停用收敛） | 海外迁移记录 |

## 二、架构分层（六层架构）

```
┌─ 前端展示层  47 页静态 SPA(原生 HTML/CSS/JS, 无框架) + Taro 小程序(H5)
│              mock/live 双模式渲染 + env-adapter 切换 + 失败回落铁律
├─ 接入层      nginx(/api→127.0.0.1:8000, /r/ 短链302, UA封禁) + JWT 全局中间件
├─ 路由层      FastAPI 路由文件(37+)  REST + WebSocket(QR/实时通道)
├─ 服务层      services/*_service.py(模块业务) + Agent 编排(agent75/竹韵)
├─ 数据层      repositories/*_repository.py 双模式 Repository(内存/Redis 自动跟随 STORE_MODE)
└─ 存储层      Redis(生产 122K 键, zhuxiang: 前缀) / MySQL(drama85 短剧库) / 内存模式(测试)
```

**双模式存储/双模式 Repository**：所有 Repository 内存/Redis 双轨实现，`STORE_MODE` 切换零迁移——测试零依赖、生产即插即用。

## 四、模块体系（编号制）

模块按编号管理（1-85号+），重点模块：

- **认证域**：auth（会员 JWT 双令牌 2h/7d）+ admin（后台独立会话 X-Admin-Token+2FA TOTP+IP 白名单+失败锁定）+ entry（39号统一登录入口：扫码/WebAuthn/生物核验/OAuth 三方）
- **交易域**：product/order/cart/checkout/payment（微信 APIv3/支付宝 RSA2 回调验签）/logistics（轨迹回调+智能路由 P1-17）
- **AI 域**：35号 AI 智能中枢（编排中枢/训练治理/媒体用量审批）、知识库（RAG 问答/倒排索引/Embedding 语义/Rerank/多模态视觉/视频抽帧 ASR）、chat（AI 客服三态灰度 off/shadow/assist+竹韵人格层）
- **风控信用域**：竹信分（等级规则引擎/季度结算/先享后付三审）、信值体系（45/47/50/62/64/68号，一底座五权）、trust-risk/ai-governance
- **内容营销域**：站内社区（先审后显）、活动中心、promo-radar/promo-studio（AI 评分三审）、blogger、引流（attract72 四级灰度 off/observe/assist/full）
- **短剧域**（85号）：批量投喂（百度/红果/DataEye 等 11 源）→ 五层预检 → 持久化四表 → 跨源合并 → contentType 契约分轨
- **观测域**：zyh（75号竹韵智衡）/synapse（76号织智）/zjian（77号竹鉴）三观测面 + 各模块 dashboard

## 五、核心子系统

### 5.1 认证与鉴权（三套体系安全对照）

- **全局 JWT 中间件**（auth_middleware）：公开路径白名单（PUBLIC_EXACT+GET 前缀+正则）→ Bearer 校验注入身份头（剥离伪造 X-Role/X-Member-Id）→ AUTH_MODE compat/strict 双态
- **后台会话**：X-Admin-Token 独立会话（30min 超时），mustChangePassword 强制改密，PBKDF2 密码（P1-21）
- **入口面**（39号）：五通道（密码/短信/扫码/生物/OAuth）+ 风险评分 guard（challenge/BLOCK 分级）

### 5.2 AI 知识与对话链

- **RAG 链**：rag_answer（60s 结果缓存，key=question|provider|category|persona）→ 检索（倒排+语义）→ 幻觉治理 system（"仅依据编号资料回答"）→ LLM 合成
- **chat 三态灰度**：CHAT_LLM_MODE off（rule 轨默认）/shadow（LLM 留痕不呈现，shadowLlm 字段 admin 审计）/assist（LLM 呈现失败回退）
- **竹韵 V0.5 人格层**（2026-10-17）：zhuyun_persona（基座+三场景 night/gift/complaint+care_gate 关怀护栏先于一切轨道）→ persona_system 注入 LLM 轨 system 前缀；挂件 ai-hub-widget 挂载 index/service
- **评分器体系**：14+ 评分器（AI Scoring）+ RAG 检索增强+经验回放+长期记忆三大机制（v7.9）

### 5.3 DPO × SelfPlay 进化闭环（P4-10，2026-10-16）

- DPO 五源偏好对归集（数据面 dpo_pairs）+ SelfPlay 六类红蓝对抗面 + 串联闭环（生产采数调度）
- 82号进化开闸灰度机制 + MCP 只读工具面 + agent75 四角色拓扑/跨会话记忆/多步熔断

### 5.4 85号短剧数据平台

- 四层架构：投喂层（批量链解析）→ 预检层（五层检测/三态判定/农场指纹）→ 持久层（MySQL drama85 四表，dedup_key 幂等）→ 合并层（两级匹配/跨源建行互链/复核队列 0.4%）
- APScheduler 四任务日调度（Day7 验收 8/9 指标达标）

## 六、数据架构

- **键空间**：Redis 全量 `zhuxiang:` 前缀（radar 42K/blogger 20K/promo 10K/knowledge 8K 等模块留痕为大头）；admin 会话锁、chat 会话锁、模式状态键（chat:mode:state）
- **85号库**：MySQL 容器四表（主表 327 部/快照 600+/跨源行），contentType 快照层双态

- **缓存**：rag_answer 60s 结果缓存（persona 维度隔离）；nginx 静态 30d immutable + v 号归一（v=20261017）

### 8.2 部署通道

- **前端**：本地打包 tgz → OSS（zxjiu-videos/deploy/）→ 云助手五步（备份→下载→解压→v 号归一 UTF8 无 BOM→验证）

- **铁律**：云助手 PowerShell 脚本必须 UTF-8 带 BOM（无 BOM 被远端 PS5 按 GBK 解析中文错乱）+ 本地 Parser::ParseFile 预校验
- **回滚**：每部署先 tar 备份被覆盖文件集（C:\tmp8147\）

## 九、安全体系

- **传输**：443 certbot（letsencrypt）；nginx UA 封禁（PetalBot|Scrapy|SERanking→403）
- **认证**：JWT 双令牌+refresh；admin PBKDF2+TOTP 2FA+IP 白名单+异地登录告警+失败锁定（5 次 15min）
- **防越权**：中间件剥离伪造身份头（X-Role/X-Member-Id 无 token 即剥）；admin 写操作须会话 token
- **内容安全**：先审后显（社区）、AI 评分三审（promo）、酒类年龄门（ageConfirmed≥18）
- **理性饮酒护栏**：竹韵 care_gate 关怀闸（借酒消愁类绝不推酒+心理援助热线）
- **数据合规**：人脸图永不落库（vision 判照仅存报告）；IP 城市级粒度不落库

## 十、工程纪律

1. **单任务单提交**，信息注明任务号；批次文件集不相交可并行
2. **pre-commit 钩子**：JS 括号状态机静态检查+语音链路故障回归三件套（awk 正则字面量识别增强版）
3. **文档-代码同步核对**：check-doc-code-sync.py 机检（31 模块/37 路由文件/505 端点基线）+ 人工核对清单
4. **回落铁律**：页面先渲染静态再异步替换，失败静默回落（live 化全程版式零变化，168 元素快照 0 差异验证法）
5. **契约实测先行**：接口接入前 curl 实测响应字段（响应字段名先实测再写 UI）
6. **验证方法论**：pytest 单测+Playwright(msedge) e2e 双态（mock/live 各一轮+route abort 失败演练）；本地反代静态服务器（http.server 子类 /api→后端）同源联调
7. **降级有兜底**：LLM off/异常降级、探测超时竞速（probeHub 800ms）、fail-soft 不阻断主流程
