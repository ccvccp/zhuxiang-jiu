### 2.2 P1 — 并发/Mutex 边界 (15 用例)

> 目标：验证 FIFO 锁在极端并发下的正确性

| 用例 ID | 描述 | 测试内容 | 预期 |
|---------|------|----------|------|
| MC1 | 1000 并发 deduct | 库存 1000，1000 次 deduct | 库存=0, 无超卖 |
| MC2 | 1000 并发 restock | 库存 0，1000 次 restock | 库存=1000 |
| MC3 | 1000+1000 混合 | 1000 deduct + 1000 restock | 库存=初始值 |
| MC4 | 锁重入测试 | 同一 key 连续 acquire 2 次 | 第2次等待, 不死锁 |
| MC5 | 锁释放后重获 | acquire → release → acquire | 立即获取, 无残留 |
| MC6 | 空锁 key | `acquire("")` | 正常加锁/释放 |
| MC7 | 超长锁 key | `acquire("stock:" + "x"×1000)` | 正常加锁/释放 |
| MC8 | 100 个不同 key 并发 | 100 个 productId 各 deduct | 全部串行, 无交叉 |
| MC9 | 极速 acquire/release | 1ms 内 100 次 acquire+release | 全部串行 |
| MC10 | 内存泄漏检测 | 10000 次 acquire+release 后内存 | 队列清空, 无泄漏 |
| MC11 | 库存=1 竞争 | 库存 1, 100 并发 deduct | 仅 1 个成功, 99 回滚 |
| MC12 | 库存=0 边界 | 库存 0, 100 并发 deduct | 全部回滚, 库存不变 |
| MC13 | restock 到负数 | 库存 -5, restock 10 | 库存=5 |
| MC14 | 并发 deduct+cancel | 50 deduct + 50 cancel | 库存正确, 无脏数据 |
| MC15 | 跨模块锁竞争 | inventory + checkout 同时操作 | 各自锁独立, 无阻塞 |
