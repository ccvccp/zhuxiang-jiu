# 语音系统风险复查(qwen3-max)

### 1. 【风险预判】遗留项按 **概率 × 影响** 排序（高 → 低）

| 排名 | 遗留项 | 理由 |
|------|--------|------|
| **1** | **3. 面板哑流自愈(v84)未经真机复验** | **高概率 + 高影响**：v84 引入“近零能量 3s → 硬重置 30s 退避”逻辑，但依赖音频能量检测。真机环境存在麦克风静默、弱信号、背景白噪等场景，极易触发“哑流”。若自愈失败，用户将遭遇**完全无响应**（TTS/ASR 双断），直接影响核心可用性。且当前容器无流量验证，暴露风险极高。 |
| **2** | **6. 面板 REST 轨空轮二打(弱音频轮)未做** | **高概率 + 中高影响**：用户常在面板打开后补说“再便宜点”“有红色吗”等弱语音指令。若系统未处理空轮或弱音频轮（如 ASR 返回 tiny/empty 但上下文应续接），会导致**意图断裂、状态错乱**。该路径在回归测试中易被忽略（依赖特定交互节奏），真机高频发生。 |
| **3** | **2. 打断 SLA 基线未收(cut_after_ms)** | **中高概率 + 中影响**：文档要求 <200ms，但受百炼 partial 回流约束。若实际打断延迟 >500ms，用户感知明显卡顿。虽 v82 已埋点，但无实测数据支撑，**可能掩盖体验劣化**，尤其在高负载或弱网下。 |
| **4** | **5. LLM 轨拼接污染根因未深究** | **中概率 + 中影响**：v83 已用 pattern 拦截虚假执行，但“竹海至尊您好”类污染说明 prompt 注入逻辑存在边界漏洞。若污染扩散至 action 参数（如商品ID拼错），可能导致**错误执行**。但当前兜底有效，影响可控。 |
| **5** | **1. 影子状态机 ILLEGAL 频率未知** | **低概率 + 高影响（潜在）**：SM 五态+7转换点设计严谨，ILLEGAL 应罕见。但若存在未覆盖的并发/异常退出路径（如 ws closure 与 PROCESSING 看门狗竞态），可能引发**状态锁死**。需数据验证，但当前零流量下难暴露。 |
| **6** | **4. 跨会话会员偏好记忆未实现** | **低概率 + 低影响（当前）**：仅限会话内记忆，跨 session 需 repo 查询。真机复测通常单会话，**短期内不影响功能正确性**，属体验优化债。 |

### 2. 【复测优先级】最小话术集（10 条内）

| 话术 | 目标遗留项 | 设计意图 |
|------|------------|--------|
| 1. （面板打开后静默 5 秒，轻声说）“有货吗？” | **3, 6** | 触发哑流检测 + 弱音频轮处理 |
| 2. （面板打开后快速说）“不要这个，换红色的” | **6** | 验证空轮后弱指令能否续接 REST 轨 |
| 3. （播放 TTS 中）“停！查 iPhone” | **2** | 测量真实打断延迟（cut_after_ms） |
| 4. “帮我找一款 42 度的酒” | **（回归验证）** | 确保 v86 修复后 42 度指令正常（防回归） |
| 5. “刚才那款能便宜点吗？”（面板关闭后立即说） | **4, 6** | 测试跨轮记忆边界 + 弱音频意图衔接 |
| 6. （连续快速问）“有茅台吗？…不要，要五粮液…算了，还是茅台” | **2, 5** | 高频打断 + LLM 上下文拼接压力测试 |
| 7. （后台切回前台，面板已开）“加购” | **3, 6** | 验证 visibilitychange 后哑流自愈 + 弱指令 |
| 8. “会员价多少？”（非会员身份） | **（v80/v81 边界）** | 验证 member 窗白名单是否误触发 |
| 9. （TTS 播放末尾 0.5s）“等等，先别下单” | **2** | 极限打断场景，逼近 200ms SLA |
| 10. “推荐个高端白酒” → （面板出后）“指名要飞天茅台” | **5, 6** | LLM 推荐 → 指名切换，检验上下文污染与空轮 |

> 注：话术 1、2、7 覆盖 **v84 哑流自愈**与**空轮二打**；话术 3、6、9 聚焦**打断 SLA**；话术 10 探测**LLM 拼接污染**。

### 3. 【潜伏 bug 扫描】“单路径验证盲区”（类 42 度 bug）

基于修复史中 **“分支漏赋值”**（v86: ina 命中分支漏赋值导致 UnboundLocalError）和 **“边界条件未覆盖”** 模式，指出以下高危盲区：

1. **指名+预算复合指令的 LLM 轨分支**（v80/v81）  
   - 场景：“**要飞天茅台，预算 2000 内**”  
   - 风险：v80 的“指名直入”与 v81 的“预算过滤”可能存在**分支互斥或参数覆盖**。若 LLM 分类时仅走指名路径而忽略预算，或反之，则导致**价格超限仍推荐**。类似 v86 的“单路径命中即跳过其他赋值”。

2. **member 窗边界 5 分钟整**（v80）  
   - 场景：用户在 **member 窗口开启第 300 秒整** 说“会员价”  
   - 风险：窗口有效期判断若用 `>=` vs `>` 或时间戳取整误差，可能导致**临界点身份误判**（应失效却生效，或反之）。此类边界在脚本中常被忽略（只测 299s/301s）。

3. **44 度跨款边界**（v86 类比延伸）  
   - 场景：“**44 度的国窖**”（非热门 SKU）  
   - 风险：v86 修复了 42 度因 ina 分支漏赋值而静默失败，但**其他度数（如 44/52）可能复用相同解析逻辑**，若未全量覆盖度数枚举，同样存在**UnboundLocalError 或静默丢弃**风险。

> 建议补入专项脚本：覆盖 **复合条件边界**、**时间临界点**、**非主流参数枚举**。

### 4. 【架构债】影子状态机收紧为硬守卫需处理的 ILLEGAL 路径

若将影子状态机（v82）从“留痕观察”升级为“硬守卫”（即 ILLEGAL 转换直接阻断流程），需重点处理以下 **非法转换路径**：

- **PROCESSING → IDLE（无 closure 触发）**  
  当前依赖 15s 看门狗超时退出 PROCESSING。若网络闪断导致 ws 未发 close，但 ASR/TTS 流已终止，状态机可能滞留。硬守卫需明确：**超时必须强制转 TERMINATED**，而非允许跳 IDLE。

- **WAIT_TTS → LISTENING（未收到 TTS_END）**  
  若 TTS 流异常中断（如 stream_failed），但前端未上报结束事件，状态机可能卡在 WAIT_TTS。硬守卫需增加：**TTS 异常时强制转 PROCESSING 或 TERMINATED**，禁止直接跳 LISTENING。

- **LISTENING → LISTENING（重复唤醒）**  
  用户连续说“你好小X”两次，可能触发两次 wakeword_in_final。当前允许 LISTENING 自循环，但若伴随 ctx 冲突（如 session 未 clean），可能污染意图。硬守卫应**拦截第二次唤醒直至首轮结束**。

- **TERMINATED → 任意态（会话已关但消息迟到）**  
  ws 关闭后，若 ASR/TTS 回包因网络延迟到达（err_after_close），当前可能尝试更新状态。硬守卫必须**丢弃所有 TERMINATED 后的消息**，杜绝状态回跳。

> 核心原则：**所有转换必须有明确前置条件与后置清理**，否则硬守卫将导致合法流程被误杀。建议先通过 points 埋点收集 1 周 ILLEGAL 日志，再制定转换白名单。
