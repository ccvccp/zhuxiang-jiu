- 文案与品牌绑定（温一壶竹香酒/在家小酌/冰镇竹香）——关怀即种草的运营导向

## 三、验证中发现并修复的问题

### 3.1 生产级 Bug：问候时段/节日判定 UTC 错位 8 小时（已修复）

**现象**：矩阵脚本实测本地时间早 7:13，`build_greeting` 输出「夜深了」（period=night）。

**根因**：`build_greeting` 用 `ts()`（`core/helpers.ts` 返回 `datetime.now(UTC).isoformat()`）切小时与日期——对中国用户（UTC+8）全部错位：

| 北京时间 | 修复前输出 | 应输出 |
|---|---|---|
| 早 7:00 | 夜深了 | 早上好 |
| 中午 12:00 | 夜深了 | 中午好 |
| 下午 15:00 | 早上好 | 下午好 |
| 晚 20:00 | 中午好 | 晚上好 |

节日判定同样受影响：北京时间节日凌晨 0-8 点按 UTC 仍是前一天，HOLIDAYS 表漏判（如国庆凌晨访问不出现「国庆节快乐」）。

**修复**（scene_service.py `build_greeting`）：改用 `datetime.now(UTC) + timedelta(hours=8)` 北京时间固定偏移——中国无夏令时，固定 +8 永远正确；不引入 `zoneinfo` 避免 Windows 本地测试的 tzdata 依赖。

**验证**：本地 34/34 → 生产部署 → 实调 `GET /api/scene/context?city_code=370900`，北京时间 7:40 正确输出 `「早上好，欢迎来自山东省泰安市的朋友！」`（period=morning，背景 foggy）。

**沉淀铁律**：`ts()` 是 UTC——所有用户侧时间语义（时段/日期/文案判定）必须转北京时间后再使用。

### 3.2 高温测试用例时段敏感脆弱断言（已修复）

原断言 `background == "sunny"` 在夜间时段跑测试必失败（晴+夜 → 背景 `night` 是正确设计），改为 `in ("sunny", "night")`。与此前 cooldown 测试 UTC 日期差属同类时间敏感问题。

### 3.3 严寒文案无专项用例（已补充）

雪天用例（-2°C）走雪分支，严寒分支（≤0°C 无雪雨）原无直接覆盖，补充专项用例后四类提示全部有实证。
