# 55号·二维码AI智能管理模块实施计划

> 定位：全站智能应用的**统一交互总线**——"意图即码、码即服务、全域贯通"
> 范式：Value-UEBA 体系下「大模型大脑 × 二维码手脚 × 信值血液」的工程化落地
> 版本：v1.0（2026-09-06）

---

## 〇、参照方案的本站化优化升级说明

参照方案（用户输入）的四大理念全量继承，工程落地做五项**本站化升级**：

| 参照方案要点 | 本站化升级（落地口径） |
|---|---|
| LLM 意图理解引擎 | **规则轨优先+LLM 澄清三态**（48号/44号范式）：LLM 不进路由决策链——意图→服务映射走**封闭白名单注册表**（杜绝幻觉链接的铁律工程化）；LLM 仅在模糊意图时做澄清问句生成与参数补全（mock 确定性模板/real 润色，失败回退） |
| 全站资源知识图谱 | 51号本体是**封闭注册表（9实体零改动红线）**——55号自建轻量**服务资源注册表 SERVICE_REGISTRY**（serviceId→route→模板→敏感度→隐私成本），并可选读取 51号做语义 grounding 增强（只读） |
| SM4/SM2 加密签名 | 标准库无国密依赖——落地为**HMAC-SHA256 签名载荷**（`payload|sig|exp|nonce`，防篡改+防重放+时效三合一）；SM2/SM4/TEE 国密化列为外部待办 |
| 隐私预算 & 风控校验 | 直接复用 **49号 check_and_spend**（敏感度分级 L0-L3 成本对齐 51号口径）——超预算降级公开版页面 |
| 意图满足率等度量 | 六指标管道（52号范式）+ **第30档案学习闭环**（44号 Hedge——qr_orchestration 八因子） |

**核心原则（继承+强化）**：AI 生成不是目的，精准匹配需求并安全交付才是目的。大模型是大脑、二维码是手脚、信值体系是血液——**码是 invisible bridge**。

## 一、模块定位与架构

```
用户自然语言("我要办老年优待证")
        │
        ▼
① 意图理解引擎(规则轨优先——48号范式)
        │ 清晰命中                │ 模糊/缺失
        ▼                        ▼
② 服务资源注册表           ③ LLM 澄清问句生成
   (SERVICE_REGISTRY          (mock/real 三态)
    封闭白名单)                    │ 用户补答
        │                        ▼
        ▼                   回①重解析
④ 动态码生成器(参数化模板+签名载荷
   HMAC+exp+nonce+无障碍样式)
        │
        ▼
⑤ 隐私预算校验(49号 check_and_spend)
   ├─ 通过 → 渲染个性化落地页
   └─ 超预算 → 降级公开版页面(千面千码)
        │
        ▼
⑥ 扫码核销(验签+防重放+跨端续接)
        │
        ▼
⑦ 全链追踪(生成→扫码→完成→信值结算)
   └→ 决策回流 → 第30档案 Hedge 学习(44号复用)
                  → 漂移监控(46号三检测器)
                  → 治理红线(冻结/审批/回滚)
```

**双模型铁律（54号范式平移）**：意图→服务映射的**规则置信分**（55号 qr_orchestration 第30档案）与 48号既有意图轨**并行不替换**——55号仅对"生码决策"打分回流，不侵入小竹中枢。

## 二、服务资源注册表（SERVICE_REGISTRY——封闭白名单）

51号本体零改动红线下的轻量替代。每条服务资源含八字段：

```python
SERVICE_REGISTRY = {
    "elderly_card": {
        "label": "老年优待证办理", "route": "/api/hub/panel",
        "template": "service_apply",        # 参数化模板
        "sensitivity": "L1",                # 对齐 51号敏感度分级
        "privacyCost": 0.005,                # 对齐 51号 SENSITIVITY_TIERS
        "params": ["region", "holder"],     # 允许注入的参数白名单
        "audience": ["elderly", "general"],
        "riskLevel": "low",
    },
    ...
}
```

- **首批 12 项高频服务**（模板库四类：办事 apply/查询 query/下载 download/反馈 feedback）
- **启动自检**（52号 registry 范式）：route 前缀合法/敏感度成本对齐/参数白名单非空/幂等 serviceId——RuntimeError 宪法级
- **第三方生态接入**：`status=pending` 状态——需 46号 变更审批总线通过方可激活（合规审核工程化）

## 三、动态码生成与核销

### 3.1 签名载荷结构（防篡改+防重放+时效三合一）

```
ZXBJ-QR55:{serviceId}:{b64(payload)}.{sig}.{exp}.{nonce}
  payload: 模板参数(白名单内)+会员 digest(非明文)
  sig:     HMAC-SHA256(secret, serviceId|payload|exp|nonce)
  exp:     有效期时间戳(默认 300s, 模板可配)
  nonce:   一次性随机数(扫码核销即失效——防重放)
```

### 3.2 千面千码（自适应落地）

扫码时按扫码者画像适配：信值等级（45号）→ 展示深度；无障碍模式（老年/视障）→ 高对比样式+语音触发标记；隐私预算余量（49号）→ 超预算降级公开版。

### 3.3 防伪与拨测

- 验签失败 → 立即阻断+`tamper` 事件留痕（上报风控）+受影响用户信值补偿事件
- 生成后自动化拨测（P4）：白名单 route 可达性验证——失败重试/转人工，**生成失败不计预算**（参照方案铁律）

## 四、数据模型（4 表，前缀 qr55）

| 表 | 主键 | 用途 |
|----|------|------|
| qr55_codes | codeId | 码实例（载荷/服务/生成者/状态 active-redeemed-expired-tampered） |
| qr55_events | eventId | 全链事件（generate/scan/redeem/expire/tamper——闭环追踪） |
| qr55_feedback | feedbackId | 决策回流标注（eventId 关联+reward） |
| qr55_model_events | modelEventId | 模型生命周期事件（学习/晋升/回滚/漂移） |

复用 44号：ai_learning_profiles（第30档案）+ ai_learning_feedback（跨模块反馈池）。

## 五、第30档案：qr_orchestration 八因子信任分

| 因子 | 权重 | 口径 |
|------|------|------|
| intent_confidence | 0.15 | 意图解析置信度（规则轨） |
| service_match | 0.15 | 服务匹配度（精确/模糊/澄清次数） |
| template_fit | 0.10 | 模板适配度（参数完整率） |
| budget_sufficiency | 0.15 | 隐私预算余量（49号） |
| member_trust | 0.15 | 会员信值等级（45号） |
| expiry_freshness | 0.10 | 有效期新鲜度（生成→扫码时距） |
| accessibility_need | 0.10 | 无障碍需求命中（千面适配） |
| risk_posture | 0.10 | 风险态势（46号冻结/风控标记） |

输出 0-100 信任分 → 三级生码策略（`direct` 直接生成 / `confirm` 参数确认 / `clarify` 澄清对话）——对齐参照方案"模糊/缺失→澄清"。

## 六、决策回流管道（七类真值信号）

| 信号源 | reward | 语义 |
|--------|--------|------|
| 生码后扫码+服务完成 | +1.0 | 意图满足（生成正确） |
| 生码后扫码未完成（放弃） | +0.3 | 弱满足 |
| 澄清后命中（二次即中） | +0.8 | 澄清有效 |
| 澄清 ≥3 轮才命中/放弃 | -0.6 | 澄清低效 |
| 生码后过期未扫 | -0.4 | 生成过剩 |
| 验签失败（篡改） | -1.0 | 对抗样本 |
| 拨测失败重试成功 | -0.5 | 路由劣化 |

44号池双写+T+1 调度补标（54号 P1 范式全继承：幂等 eventId 1:1/延迟态转正/`_ts_utc` 时区统一）。

## 八、分期实施计划（P0-P5）

### P0 服务资源注册表+意图引擎+签名底座
- SERVICE_REGISTRY 12 项+启动自检（52号 registry 范式）
- 意图理解引擎（规则轨：关键词/同义词/参数抽取——48号范式）
- 签名载荷生成/验签（HMAC+exp+nonce）
- 第30档案注册（SCORER_REGISTRY batch14）
- 测试：专项约 22 断言
- QC：白名单封闭（未知 service 拒绝）；51号本体零改动

### P1 智能生码+扫码核销
- 动态码生成器（模板库+参数注入+千面适配）
- 隐私预算校验（49号 check_and_spend 织入）+超预算降级
- 扫码核销（验签+防重放+跨端续接标记）
- clarify 澄清（mock 确定性/real LLM 三态）
- 测试：专项约 26 断言
- QC：验签失败阻断+tamper 留痕；nonce 一次性

### P2 全链追踪+决策回流
- qr55_events 全链埋点（生成→扫码→完成→信值结算联动 45号）
- 七类信号真值标注+44号池双写+T+1 补标调度器
- 六指标管道（意图满足率/渗透率/预算健康度/拦截有效率/满意度/澄清效率）
- 测试：专项约 22 断言
- QC：幂等 eventId 1:1；回流不侵入业务链路

### P3 自主学习进化+升级回滚
- Hedge 学习轮次（44号 run_learning_cycle 复用）+护栏验证
- 手动晋升+版本回滚+滑动窗口回归检测→自动回滚+冻结（54号 P3 范式全继承）
- 测试：专项约 20 断言
- QC：权重演进单调收敛；晋升-回滚闭环

### P4 治理+安全+LLM 归因
- 46号三检测器接入+冻结守卫联动
- 拨测验证（route 可达性自动化）+篡改告警+信值补偿事件
- 无障碍模式+儿童简化模式（二次确认）
- LLM 归因报告（mock/real 三态——数字来自数据层）
- 测试：专项约 20 断言
- QC：冻结期间学习跳过；拨测失败不计预算

### P5 看板+红队+三件套收官
- 四区看板（码量/服务分布/回流漏斗/漂移+防御区）
- 红队：载荷伪造/重放/篡改/参数越权/白名单逃逸/预算绕过 六向量
- 宪法断言（44/46/48/51号零改动）+三件套文档
- 测试：专项约 24 断言
- QC：投毒防御（护栏+集中度）；全链零回归

**开关矩阵**：`QR55_MODE`（默认 off——off=生成面关闭：存量二维码链路零影响）；`QR55_LEARN_MODE`（学习调度，默认 off——双开关铁律）。

## 九、风险控制矩阵

| 风险 | 缓解 | 验证 |
|------|------|------|
| LLM 幻觉生成恶意链接 | 白名单注册表封闭+LLM 不进路由链 | P0 断言 |
| 码被替换/篡改 | HMAC 签名+nonce 防重放+exp 时效 | P1/P5 红队 |
| 过度采集扫码者信息 | 最小必要（参数白名单）+49号预算联动降级 | P1 断言 |
| 意图误配（码非所需） | 澄清对话+决策回流负修正 | P2 断言 |
| 生成过剩（过期未扫） | 过期信号负反馈+模板有效期收紧 | P2 断言 |
| 第三方接入合规 | pending 状态+46号审批总线激活 | P4 断言 |
| 权重投毒 | 护栏 [0.5,2.0]+标注源集中度检测 | P5 红队 |

## 十、一致性声明与外部待办

**零改动宪法**（每期断言验证）：44号学习中枢接口零改动（仅新增第30档案）；46号治理中枢零改动；48号小竹意图轨零改动（55号并行评分）；51号本体封闭注册表零改动（55号自建白名单）；49号隐私预算接口零改动（纯调用）。

**外部待办**：
1. 国密升级：HMAC-SHA256 → SM2 签名+SM4 载荷加密+TEE 解密（国标 SDK 接入后）
2. 统一扫码 SDK 前端组件（摄像头/相册/长按识别——前端工程独立排期）
3. 第三方生态首批接入方（合规审核流程演练）
4. LLM 澄清 real 轨实测（LLM_ENABLED=on+密钥注入后）

**结语**：码是 invisible bridge——当用户说出需求，服务便以最合适的方式抵达。55号让"人找码"进化为"码找人"，而信值与治理确保每一次抵达都值得托付。
