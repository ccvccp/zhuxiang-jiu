## 五、验收中发现并解决的问题(工程记录)

### 5.1 存量路由缺陷修复(检查期发现——本模块核心工程记录)

- **现象**: `GET /api/agreements/consents`、`GET /api/agreements/
  role-protocols`(及新增 mode 端点)返回 422 int_parsing
- **根因**: detail 路由 `GET /api/agreements/{agreement_id}`
  (int 路径参数)先注册——单段字面路径被其吞掉(FastAPI 路径
  参数验证 422 不再继续匹配); 57 项存量测试未覆盖此路径调用,
  生产 422 长期未被发现
- **修复**: detail 路由移至**全部单段字面路径(consents/
  role-protocols/mode 及控制面)之后**注册; 两段路径
  (stats/overview)不受影响
- **实证**: 修复后 consents/role-protocols/mode 全 200, 数字
  id 详情 404 正常; 生产实机复验 200
- **沉淀**: 同前缀下 int 路径参数路由与单段字面路径共存时,
  字面路径必须先注册; 存量测试未覆盖的字面路径调用是缺陷藏身处

### 5.2 仓储方法名(测试修正实录)

- 首版巡检造数用 `repo.create_agreement`——实际仓储为
  `save_agreement`(全字段含 id)+`next_agreement_id`

## 六、回滚与运维

- **回滚命令**:
  `sed -i 's/^AGREEMENT_MODE=.*/AGREEMENT_MODE=off/' /opt/zhuxiang/.env && docker compose up -d backend`
- **运行时切档**(免容器重建):
  `POST /api/agreements/mode/override {"mode":"shadow"}`
- **护栏暂停恢复**: `POST /api/agreements/mode/resume`(人工留痕)
- **巡检开关**: AGREEMENT_GUARD_AUTO=off 可关(默认 on——
  护栏是保护机制)
- **巡检间隔**: AGREEMENT_GUARD_INTERVAL(默认 3600s, 最小 60s)
- **off 态语义**: 决策 4 端点(条款创建/发布/版本/协议创建)409;
  **consent 用户同意权 + 观测面 6 GET 零影响**——off 态下
  用户签署条款与合规公示完全无碍
