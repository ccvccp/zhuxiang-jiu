# 43号·P6-1 情报源聚合与规模扩展 实施计划 v1.0

> 配套：[P6 总计划](43号P6_聚合规模化与就绪度实施计划.md) §二（本文为其 P6-1 部分的落地细化）
> 定位：把情报覆盖面从单源 firehol_level1（~2k 段）扩到**多源聚合**（level1+level2+cross，~180k 段）——冷启动防护面扩大约 90×。P5-6 已把**匹配查询**降到 O(log n)，本计划拆除**导入/读取/统计**侧的三道规模墙（按源替换语义 / 逐键 IO / stats 全量 list）。
> 调研结论（2026-09-03，逐行核实）：
> 1. **替换语义**：`import_netset(replace=True)` 调 `clear_threatintel()` 清**全部**段——聚合多源时导入 level2 会清掉 level1（数据丢失）；
> 2. **逐键写**：导入逐段 `await repo.save_threatintel(...)`（[threatintel_service.py L101-104]）——180k 段 = 180k 次 Redis round-trip，估算 15~20s+；
> 3. **逐键读**：`_list()`（[security_repository.py L165-179]）对每键 `await client.hgetall(key)`——区间构建（P5-6）与 stats 均走此路径，180k 段同样 15s+ 级；
> 4. **上限硬编码**：`MAX_IMPORT_CIDRS = 20000`（服务层模块常量）——聚合全量 ~180k 段直接被 parse 拒绝；
> 5. **stats 全量 list**：`stats()` 调 `list_threatintel()` 统计来源分布——180k 段时管理端单次调用卡顿 15s+ 级（最痛的墙：低频但必现）；
> 6. **feed 单源**：`feed_url()` 单 URL + `_AUTO_STATE_KEY = "threatintel:auto"` 单例状态——多源需 URL 列表解析与按源状态；
> 7. **clear 逐键 delete**：`clear_threatintel()` 逐段 `await client.delete(...)`——180k 段全清同样秒级~十秒级。

## 二、P6-1a：仓储层批量读写 + 按源清除

### ① pipeline 批量写

```python
async def save_many_threatintel(self, entries: list[tuple]) -> int:
    """批量写入情报段(pipeline, 每批 5000 防单命令过大)

    Args:
        entries: [(cidr, meta_dict), ...]
    Returns:
        写入条数
    """
    if is_redis_mode():
        client = await get_redis_client()
        for i in range(0, len(entries), 5000):
            batch = entries[i:i + 5000]
            pipe = client.pipeline(transaction=False)
            for cidr, meta in batch:
                pipe.hset(_k("security43", self.TABLE_POSTURE,
                             f"threatintel:{cidr}"),
                          mapping=self._serialize(meta))
            await pipe.execute()
            await asyncio.sleep(0)   # 让出事件循环(P4-2 范式)
        return len(entries)
    # 内存模式: 直写
    self._ensure_store()
    for cidr, meta in entries:
        self.store[self.TABLE_POSTURE][
            f"threatintel:{cidr}"] = meta
    return len(entries)
```

### ② pipeline 批量读（_list threatintel 路径专用优化）

```python
async def list_threatintel(self, limit=200000) -> list[dict]:
    """批量读取(pipeline hgetall, 每批 5000)——180k 段目标 <5s

    内存模式无变化。
    """
    if is_redis_mode():
        client = await get_redis_client()
        keys = [k for k in await client.keys(_k(
            "security43", self.TABLE_POSTURE, "*"))
            if not k.endswith(":seq")]
        # 过滤出 threatintel 段键 + scheduler/auto 单例排除
        ti_keys = [k for k in keys
                   if ":threatintel:" in k]
        result = []
        for i in range(0, len(ti_keys), 5000):
            pipe = client.pipeline(transaction=False)
            for k in ti_keys[i:i + 5000]:
                pipe.hgetall(k)
            for data in await pipe.execute():
                if data:
                    result.append(self._deserialize(data))
        return result[:limit]
    ...
```

> 注：threatintel 段键与 auto 状态/scheduler 统计共用 posture 表——键过滤 `":threatintel:"` 中缀天然排除单例键（既有 `actorKey` 前缀过滤保留双保险）。

### ③ 按源清除

```python
async def clear_threatintel(self,
                            source: str = None) -> int:
    """清空情报段

    source=None → 清全部(既有口径, 手动导入兼容)
    source="firehol_level2" → 仅清该源段(聚合按源替换)
    批量 delete 同样走 pipeline。
    """
```

### ④ 兼容与失效联动

- `save_many_threatintel` 末尾版本戳递增一次（而非逐段 save 的 N 次——P5-6 版本戳语义不变，次数收敛）
- 既有 `save_threatintel`/`get_threatintel` 单键方法保留（P5-6 命中回填依赖 `get_threatintel`）

## 七、关键风险与对策

| 风险 | 对策 |
|------|------|
| 180k 段导入阻塞事件循环 | pipeline 分批 5000 + 批间 `await asyncio.sleep(0)`（P4-2 范式）；实机门槛 60s 含此口径 |
| 计数器漂移（旁路删键） | total vs 区间缓存 segments 交叉校验触发兜底重建（一次性全量，完成后恢复毫秒级） |
| 按源替换 source 拼写错（清不掉旧段） | 同名 source 幂等刷新语义（clear(source) 后重导——拼写错误仅表现为"多了一份源"，stats 可见可清理）；手动端点 source 参数明示 |
| 单源毒源拖垮调度 | 每源独立 try + 失败计数（fail-soft 继承） |
| 多源 URL 可达性（外网） | 每源独立 fail-soft；实机用本地模拟源验证（P5-3 范式）；URL 可配镜像 |
| 提额后内存（180k 段 × ~3MB） | 实机内存增量断言（<50MB）；上限默认不变——提额为显式运维决策 |
| P5-6 区间缓存与按源替换联动 | 版本戳在批量写末尾递增（次数收敛语义不变）；专项含联动回归 |
