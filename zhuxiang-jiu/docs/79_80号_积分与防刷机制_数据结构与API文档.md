# 第一部分 数据结构设计

## 0. 存储形态说明

生产为 **Redis** 键值存储(单机), 测试为**进程内存 dict**(双模式同构,
`is_redis_mode()` 切换)。键命名统一 `{namespace}:{entity}:{id}`
(冒号分层); hash 存实体, set 存索引, list 存时序列表。下文按
"逻辑表"呈现, 每表标注 Redis 键型与索引。

## 1. 推广域(promotion:*)

### 1.1 codes —— 推广码表

| 字段 | 类型 | 说明 |
|---|---|---|
| code | string(PK) | 推广码, 格式 `ZXBJ-{6位大写字母数字}` |
| ownerMemberId | string | 归属会员 ID(Redis hash 值域为字符串) |
| channel | string | 领取渠道: wechat_miniprogram/douyin/kuaishou/xiaohongshu/bilibili/taobao/direct |
| status | string | active / revoked(撤销) |
| boundCount | int | 累计绑定人数(计数器) |
| createdAt / updatedAt | ISO8601 | 创建/更新时间 |

- 键: hash `promotion:codes:{code}`
- 索引: set `promotion:owner_codes:{ownerMemberId}` → [code...](按人查码)
- 序列: `promotion:codes:seq`(未用——码为随机生成)
- 领取幂等锁: `promotion:code:{memberId}:{channel}`

### 1.2 relations —— 绑定关系表(防刷核心)

| 字段 | 类型 | 说明 |
|---|---|---|
| inviteeMemberId | string(PK) | 被绑(新)会员 ID——**一人一绑**即此表主键约束 |
| inviterMemberId | string | 推荐人 ID |
| code | string | 绑定所用推广码 |
| channel | string | 来源渠道 |
| status | string | **valid**(计业绩)/ **invalid**(老会员绑定, 不计业绩; 管理端作废也置此值) |
| createdAt | ISO8601 | 绑定时间 |

- 键: hash `promotion:relations:{inviteeMemberId}`
- 索引: list `promotion:team:{inviterMemberId}` → [inviteeId...](推荐人的团队/业绩统计)
- 写入锁: `promotion:relation:{inviteeMemberId}`(一人一绑事务边界)
- 奖励锁: `promotion:reward:{memberId}`(钱包轨并发防重)
- **类型坑备忘**: Redis hash 值均为字符串, 与 int 会员 ID 比较须 `str(a)==str(b)` 归一(bind_relation/get_my_funnel 两处实证)

### 1.3 rewards —— 奖励记录表(钱包轨)

| 字段 | 类型 | 说明 |
|---|---|---|
| rewardId | int(PK) | 序列自增 `promotion:rewards:seq` |
| memberId | string | 受益会员 |
| rewardType | string | wallet(直推购物现金)/ wallet_l2(裂变)/ wine_qualify(领酒资格) |
| cycle | int | 第 N 轮 |
| amount | float | 金额(元) |
| status | string | issued / used |
| detail | string | 说明文案 |
| createdAt | ISO8601 | — |

- 键: hash `promotion:rewards:{rewardId}`
- 索引: set `promotion:member_rewards:{memberId}` → [rewardId...]

### 1.4 settings —— 参数配置表(单例)

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| enabled | bool(JSON) | true | 推广体系总开关 |
| level1Threshold / level1RewardAmount | int/float | 10 / 20.0 | 钱包直推奖 |
| level2SubPromoterCount / level2SubThreshold / level2RewardAmount | int/int/float | 6 / 5 / 15.0 | 钱包裂变奖 |
| wineMinPrice / eligibleProductIds | float/list | 200.0 / null | 领酒池 |
| pointsPerReferral | int | 300 | **79号**: 每引进 1 人推荐积分(0=关) |
| sharePointsPerAction | int | 20 | **80号**: 每次分享积分(0=关) |
| shareDailyLimit | int | 5 | **80号**: 分享计分日上限 |
| welcomeNewcomerPoints | int | 100 | **80号**: 被邀新人礼(0=关) |
| updatedAt / updatedBy | ISO8601/string | — | 审计 |

- 键: hash `promotion:settings`
- 序列化: bool/None/list 必须 JSON 化(redis-py 拒绝直传)
- **读合并**: `get_settings()` 以 DEFAULT_SETTINGS 为底、存量覆盖——新增字段对旧存量自动补默认

## 2. 积分域(points:*)—— 79/80号积分轨的承载表

### 2.1 accounts —— 积分账户表

| 字段 | 类型 | 说明 |
|---|---|---|
| userId | string(PK) | 会员 ID |
| totalPoints | int | 当前可用积分余额 |
| totalEarned | int | 累计获取 |

- 键: string(JSON) `points:account:{userId}`
- **写锁: `points:account:{userId}`**——与签到/抵扣/退款互斥(防并发覆盖吞分, P0 修复注释)

### 2.2 logs —— 积分流水表(79/80 号幂等与审计核心)

| 字段 | 类型 | 说明 |
|---|---|---|
| logId | int(PK) | 序列 `points:log:seq` |
| userId | string | 会员 |
| type | string | earn / deduct / refund / expire |
| **source** | string | 业务来源: **traffic79**(引进奖励)/ **share80**(分享)/ **welcome80**(新人礼)/ checkin / order 等 |
| points | int | 变动积分(earn 为正) |
| balance | int | 变动后余额快照 |
| **refId** | string | **幂等标记**(见下约定) |
| refDesc | string | 人读说明 |
| expireAt | ISO8601 | 过期时间(发放+24 个月) |
| status | string | available / expired |

- 键: string(JSON) `points:log:{logId}`
- 索引: list `points:logs_by_user:{userId}` → [logId...](时序)
- 查询: `list_logs(userId, source, limit)`——按 source 过滤是 79/80 各轨的统计入口

**refId 幂等标记约定(防重复发薪的根)**:

| source | refId 格式 | 防重范围 |
|---|---|---|
| traffic79 | `traffic79:{inviteeMemberId}` | 每个被引进人只发一次推荐分 |
| welcome80 | `welcome:{memberId}` | 每人一生一次新人礼 |
| share80 | `{UTC日期}:{itemType}:{itemId}` | 同内容当日只计一次; 当日计数即日限判断依据 |

### 2.3 辅助表(简)

- signins: hash `points:signins:{userId}`(field=日期, value=连续天数/积分/宝箱) + list `points:signin_list:{userId}`
- expire_batches: string `points:expire_batch:{batchId}` + list `points:expire_by_user:{userId}`

## 3. 归因域(attract:*)—— 防刷取证数据源

### 3.1 clicks —— 点击事件表

| 字段 | 说明 |
|---|---|
| clickId(PK) | 序列 `attract:click:seq` |
| code / codeType | 短码 / 码型(promotion/influencer/activity) |
| channel | UTM 优先, 无则按码型默认 |
| utmSource / utmMedium / utmCampaign | UTM 三参 |
| ip / userAgent / referer | **防刷取证三要素**(截断 200) |
| landingPath / abVersion | 落地页与 A/B 变体 |
| promoterId / influencerId | 码归属解析 |
| at | 点击时间 |

- 键: string(JSON) `attract:click:{clickId}`(注意 keys 扫描排除 `:seq`)

### 3.2 attributions —— 注册归因表

| 字段 | 说明 |
|---|---|
| clickId(PK) | 一次点击一生一次归并(重复归并 409) |
| code / channel / abVersion | 冗余快照 |
| promoterId / influencerId / memberId | 归属推荐人/博主/注册会员 |
| registeredAt | 注册时间 |
| leadId / bindStatus | traffic lead ID / promotion 绑定结果 |
| orderId / orderAmount / commission | 下单回写 |

- 键: string(JSON) `attract:attr:{clickId}`

## 4. growth80 无独立表(设计说明)

分享/新人礼**不建新存储**, 完全复用 points.logs 的 `source+refId` 承载——
理由: 积分流水即业务事实(单一事实源), 幂等/日限/统计全部可由流水推导,
避免双表一致性问题。日限计数 = 当日 refId 前缀匹配; 幂等 = refId 精确匹配。

## 5. 关系型迁移映射(前瞻, 当前不执行)

若未来迁 MySQL: codes→`promo_codes(code PK, owner_member_id IDX)` /
relations→`promo_relations(invitee_member_id PK UNIQUE, inviter_member_id IDX)` /
rewards→`promo_rewards(id PK, member_id IDX, reward_type, cycle)` /
accounts→`points_accounts(user_id PK, total_points, CHECK total_points>=0)` /
logs→`points_logs(id PK, user_id IDX, source IDX, ref_id, UNIQUE(user_id, source, ref_id) 幂等键)` /
clicks/attributions→`attract_clicks(id PK, code IDX)` / `attract_attributions(click_id PK UNIQUE)`。

# 第二部分 API 接口文档

## 0. 通用约定

- 基址: `https://zxjiu.com`(生产); 端口 8000(容器内)
- 鉴权: JWT `Authorization: Bearer <token>`; 会员身份 `X-Member-Id` 头; 管理身份 `X-Role: admin` 头
- 响应包络: `{"success": true, ...}`; 错误: `{"detail": "..."}`
- 错误码: 401 未登录 / 403 需管理员 / 404 资源不存在 / 409 业务拒绝(ValueError 口径) / 500 内部
- 积分发放类接口均为 fail-soft 辅助链: 不阻塞注册/绑定主流程

## 1. 会员端接口

### 1.1 分享事件上报(80号·计分)

```
POST /api/growth80/share
头: X-Member-Id: <UID>
体: {"itemType": "product", "itemId": "P100"}
  itemType: product / promo_code / content(≤20字符); itemId ≤40字符
```

响应(计分成功):
```json
{"success": true, "counted": true, "points": 20, "todayCount": 1}
```
响应(未计分——同内容当日已计/达日限):
```json
{"success": true, "counted": false, "reason": "今日该内容已计分", "todayCount": 1}
```
错误: 401 未登录; 409 `"分享积分活动未开启"`(参数为 0 时)。

### 1.2 今日分享情况

```
GET /api/growth80/share/today        头: X-Member-Id
→ {"success": true, "todayCount": 2, "dailyLimit": 5, "remaining": 3, "pointsPerAction": 20}
```

### 1.3 我的引流漏斗(79号)

```
GET /api/promotion/my/funnel        头: X-Member-Id
→ {"success": true,
   "codes": [{"code": "ZXBJ-KWIGKX", "channel": "douyin", "shareTip": "...",
              "clicks": 12, "registered": 3}],
   "totals": {"codes": 1, "clicks": 12, "registered": 3,
              "pointsEarned": 900, "conversionRate": 0.25}}
```
> registered 按"我的码集合"匹配归因表(生产 Redis promoterId 字符串类型坑规避)。

### 1.4 领取推广码

```
POST /api/promotion/code/claim      头: X-Member-Id
体: {"channel": "douyin"}
→ {"success": true, "code": "ZXBJ-XXXXXX", "channel": "douyin",
   "boundCount": 0, "shareTip": "抖音评论区/私信发送推广码 ...", "reclaimed": false}
```
- 同渠道幂等(reclaimed=true 返回原码); 409 渠道非法; 404 会员不存在。

### 1.5 我的推广码列表

```
GET /api/promotion/my/codes         头: X-Member-Id
→ {"success": true, "codes": [{code/channel/boundCount/shareTip}...]}
```

### 1.6 绑定推广码(新用户/注册归并内部也调此链)

```
POST /api/promotion/bind
体: {"code": "ZXBJ-XXXXXX", "inviteeMemberId": 123}
→ {"success": true, "counted": true, "inviterMemberId": 45,
   "code": "ZXBJ-XXXXXX", "countedNote": ""}
```
- counted=false: 被绑会员注册超 24h(老会员, 不计业绩不发分)
- 409: 码不存在/已失效/已绑过/自绑/成环

### 1.7 积分账户/流水查询

```
GET /api/points/account/{user_id}
→ {"success": true, "account": {"totalPoints": 400, "totalEarned": 400}}

GET /api/points/logs/{user_id}?source=share80     # source 可选: traffic79/welcome80/checkin...
→ {"success": true, "logs": [{"logId": 12, "source": "share80", "points": 20,
   "refId": "2026-10-01:product:P900", "refDesc": "内容分享奖励(product:P900, 80号)",
   "balance": 20, "expireAt": "2028-10-01T...", "status": "available"}]}
```

### 1.8 短码跳转(公开, 无鉴权)

```
GET /r/{code}?utm_source=douyin
→ 302 Location: /?clickId=1730&v72=trust_first&ch=douyin#/pages/login/index
```
- 点击先落库(attract clicks: IP/UA/referer 留痕)再跳转
- clickId 供注册请求 Referer 自动归并; ch 供前端渠道个性化欢迎
- 404 码不存在/已停用

## 2. 管理端接口(均需 X-Role: admin)

### 2.1 参数配置

```
GET /api/promotion/admin/settings
→ {"success": true, "settings": {...全部字段见第一部分 1.4...}}

PUT /api/promotion/admin/settings
体(只传要改的): {"sharePointsPerAction": 30, "shareDailyLimit": 3}
→ {"success": true, "settings": {...更新后全量...}}
```
- 409: 字段值非法(如负数: "分享计分(80号)须 ≥ 0(0=关闭)")
- 修改即时生效, 仅影响之后新事件

### 2.2 绑定关系审计

```
GET /api/promotion/admin/relations?inviterMemberId=45&status=valid&limit=200
→ {"success": true, "relations": [{inviteeMemberId, inviterMemberId, code,
   channel, status, createdAt}...]}
```

### 2.3 奖励记录

```
GET /api/promotion/admin/rewards?memberId=45&rewardType=wallet&status=issued
→ {"success": true, "rewards": [...]}
```

### 2.4 手动补发(客诉补偿)

```
POST /api/promotion/admin/rewards/grant
体: {"memberId": 123, "rewardType": "wallet", "amount": 20, "detail": "客诉补偿"}
```

### 2.5 撤销推广码 / 作废绑定关系

```
POST /api/promotion/admin/codes/{code}/revoke          # 撤销后不可再绑定
POST /api/promotion/admin/relations/{invitee_id}/invalidate   # 作废; 再调一次=恢复
```

### 2.6 领酒管理

```
GET  /api/promotion/admin/wine-claims?status=pending_shipped
POST /api/promotion/admin/wine-claims/{claim_id}/ship    # 发货流转
```

## 3. 错误语义速查(防刷相关)

| HTTP | detail 示例 | 对应闸门 |
|---|---|---|
| 409 | 今日已签到/今日该内容已计分 | 同源当日幂等 |
| 200+counted=false | 今日已达分享计分上限(5 次) | 分享日限 |
| 200+counted=false | 老会员绑定不计入推广业绩 | 24h 新人原则 |
| 409 | 会员 {id} 已绑定过推广码(一人仅可绑定一次) | 一人一绑 |
| 409 | 不能绑定自己的推广码 / 推广关系成环 | 自绑/防环 |
| 409 | 渠道非法: xxx, 可选: wechat_miniprogram, ... | 渠道白名单 |
| 409 | 该归因已回写订单 / 点击已归并至其他会员 | 归因幂等 |
