> 定位：**喝竹香酒，AI 送你回家**——买酒满额 AI 自动发放市内代驾券入券包，酒后一键叫代驾，AI 全自动完成"资格审查 → 券核销 → 智能派单 → 行程跟踪 → 本站支付 → 服务评分回流"全链路零人工。

## 二、六期核心交付

### P0：满额赠券引擎 + 司机资格 AI 审查
- **券引擎**（全站券体系第一块完整落地）：档位梯度（满500赠1/满1000赠2/满3000赠3，60元/张）、幂等（`RIDE{orderId}_{seq}`）、90天有效期、持有上限6张防囤积、惰性过期、订单退款冲正
- **司机审查**：L5 竹海SVIP 硬门槛 → 材料硬校验（驾龄≥3年/证件格式）→ 第22档案五因子评分（材料0.30/驾龄车型0.25/会员信用0.20/账户健康0.15/声明一致性0.10）→ 三档决策（≥70自动通过入池/50-70人工复核/<50拒绝）
- **订单支付钩子**：pay 成功满 500 自动赠券（best-effort 火后不管）、退款自动冲正
- 8 位种子司机（自营3/加盟3/直发2，泰安市区经纬度锚点）

### P1：智能派单引擎 + 行程状态机 + AI 结算
- **双层派单**（物流 smart_route_carrier 模式平移）：规则层（5km半径/评分≥4.0/非在忙硬过滤）+ 第23档案 AI 层（接驾距离0.30/服务评分0.25/接单可靠度0.20/轨道成本0.15/负载均衡0.10）
- **三轨溢出**：自营→加盟→平台直发兜底，永不拒单
- **行程状态机**：requested → dispatched → arriving → started → completed → settling → settled（分支 cancelled 免责窗口180s/no_driver）
- **AI 结算**：计价（起步35含5km+超程5元/km+超时1元/min+夜间20%）→ 券内本站支付、超出乘客补差 → 结算单（自营paid/加盟直发aggregated）→ 司机统计回写

### P2：平台直发三态回调 + 安全监控
- **tri-state 通道**：mock 确定性直发 / real fail-hard / mock_fallback 真实轨失败回退（回执标记来源）
- **回调四事件**：accepted/started/completed(触发AI结算+trace留痕)/cancelled(券退回)
- **安全三防线**：行前 POI 场景分类（非饮酒 POI 24h≥3次高频风控信号）/ 行中超时扫描（>3h预警，幂等）/ 行后里程异常（实际超预估2倍→风险事件+按实际计价）
- **风险面板**：三类事件聚合 + 管理端处置流

### P3：双向评价 AI 审评
- **双向**：乘客评司机（show/watch 回写评分、fold 不回写）+ 司机评乘客（留档观察）
- **第24档案**（37号 AllianceReviewScorer 范式平移）：极端情绪0.25/人身攻击0.25/广告刷评0.20/评价频率0.15/分值偏离0.15，词表代驾场景化（酒鬼/马路杀手/接私单）
- **增量口碑**：`new_rating = (rating×completedOrders + score)/(completedOrders+1)`——大基数稳定、新司机敏感
- fold 文本司机侧屏蔽、管理侧保留原文

## 三、实机验收（Docker 全量口径 82 项）

**执行**：`docker compose -p zhuxiang-jiu up -d --build backend` 重建镜像 → 宿主机 `python verify_ride_live.py`（基址 `http://127.0.0.2:8000` 直达容器）。

**脚本内置 Redis 前置准备**（落实 40号复盘行动清单"验收脚本应内置清理"）：清 `zhuxiang:ride:*` 全键、种子司机置 offline（派单确定性）、会员1 置 L5——**可重复执行**（第二次运行自动清理上次 29 个残留键）。

14 章节覆盖：连通鉴权 / 券引擎梯度 / **订单支付自动赠券 E2E**（真实下单→支付→券入包）/ 司机资格（非SVIP 409→L5 通过入池）/ 池管理 / 智能派单（唯一在线司机选中+在忙溢出）/ 行程全生命周期+AI结算 / 取消免责（券退回再用）/ 三轨溢出（超半径平台直发）/ 平台回调（completed 触发 aggregated 结算+trace 计价）/ 安全监控（中性 POI 第3次精确触发+风险处置）/ 双向评价（中评回写评分变化+恶意差评 fold 评分不变+fold 文本屏蔽）/ 无券 409 / 管理端全景。

**实机特有价值**：Redis 双模式序列化 round-trip（None/bool/int/float 类型还原）在真实容器验证通过——这是内存专项测试覆盖不到的路径。

## 五、设计原则沉淀

1. **物流模式平移**：派单引擎/状态机/回执/对账四件套从物流模块（送的是货）平移到代驾（送的是人），猎物换三轨运力
2. **券即全站基建**：41号券引擎是全站第一块完整券体系（发放/过期/核销/冲正），后续商品券可迁此骨架
3. **永不拒单**：三轨溢出兜底（自营→加盟→平台直发），`no_driver` 仅作极端留痕
4. **安全即底线**：POI/超时/里程三防线全 AI 自动，不阻断只留痕（酒后场景不能把乘客挡在门外）
5. **评价即口碑**：增量口碑公式让大基数司机评分稳定、新司机敏感——数学结构决定运营性质
6. **验收即清理**：实机脚本内置 Redis 前置清理，可重复执行（40号复盘行动清单落地）

## 六、P4 后续演进交付（日结对账 + 学习回流 + 前端看板）

原"后续演进方向"中三项已随 P4 落地：

- **日结对账单**：`ride_reconcile_service`（物流结算单模式平移）——本站结算单 vs 平台账单 vs 券核销**三方对平**；状态机 `pending → reconciling → confirmed → paid` + 差异分支 `diff → investigating → resolved → confirmed`；四类差异（金额不符/单据缺失/多余单据/券未核销，容差 ¥0.01）；单号 `RCN{YYYYMMDD}{track}`；6 个管理端点
- **Hedge 学习回流**：两个有真值的档案接线（第22 `driver_application_gate`：审查通过司机按后续服务评分回流 correct/reward；第23 `ride_dispatch`：settled+有评价行程按星级→期望动作回流 expectedAction）+ `ride_scheduler` 调度器（默认 `RIDE_LEARNING_AUTO=off`）+ 3 个 learning 端点；`DECISION_THRESHOLDS` 补三档案条目（含第24 `ride_review` 的回放评估能力）；`ride_review` 回流暂缓（无管理端人工标注真值源，编造假真值会污染权重）
- **前端看板**：`ai-ride-dashboard.html` + `js/ride-dashboard.js`（七区块：全景统计/券包/我的行程/司机池/风险面板/对账单/学习闭环，对齐 40号看板模式）

P4 过程修复的两个实机问题：①`RideReconcileService.list` 方法名遮蔽内置 `list` 导致类型注解崩溃（改名 `list_all`）；②Redis 模式 bool 字段读回 `"0"` 为 truthy 字符串致学习回流幂等误判（`_BOOL_FIELDS` 反序列化恢复）——均为只有实机链路才暴露的问题。

P4 专项 54 项（`test_ride_p4.py`）+ 实机验收扩至 **96 项**（新增第 15 章对账+学习回流，两次运行全绿验证可重复执行）。
