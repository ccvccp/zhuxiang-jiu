## 〇、现状基线与设计目标

### 现状(v1 已上线, 文档实录)

- 三轨积分: share80(20 分/日 5 次) / welcome80(100) / traffic79(300)——
  全部**即时发放**, 幂等靠 points.logs 的 source+refId 约定
- 防刷七闸: 同内容幂等 / 日限 / 24h 新人 / 一人一绑 / 防环自绑 /
  渠道白名单 / 发放幂等——全部**规则型, 事前拦截**

### v1 的三个已知敞口(P2 设计动因)

| 敞口 | 场景 | 现状后果 |
|---|---|---|
| O1 即时到账无观察期 | 刷单团伙注册一批"僵尸号" | 300+100 分已发出, 只能事后人工追回(无扣回端点) |
| O2 设备维度盲区 | 同一设备换手机号批量注册 | 一人一绑按"人"不按"设备", 每个僵尸号都计业绩 |
| O3 速率维度盲区 | 推荐人单日绑定量异常(如 50 人) | 无自动降闸, 只能靠人工审计发现 |

**v2 目标**: 积分侧补"延迟结算+阶梯", 防刷侧补"设备/速率"两维,
全部增量式落地——**不动 v1 已发数据的语义, 不动注册/绑定主链路**。

## 一、积分侧增强设计

### 1.1 延迟结算轨(Escrow)——引进积分冻结/活跃解冻

**规则**:
- traffic79(300 分)发放时置 **frozen** 状态(计入流水但不可用)
- 观察期 7 天, 解冻条件(满足其一): 被引进人登录 ≥3 次 / 产生首笔订单
- 期满未达标 → 积分**作废回收**(流水置 expired, 不发负数流水)
- welcome80(100)/share80(20) 保持即时(v2 仅对大额引进分做 Escrow)

**数据结构增量**(对齐 v1 文档风格):

```
points_escrows 表(新):
  escrowId   int PK        序列 points:escrow:seq
  userId     string        推荐人(受益人)
  source     string        固定 "traffic79"(v2 仅此轨)
  refId      string        沿用 traffic79:{inviteeMemberId}(幂等同源)
  points     int           冻结额度(300)
  unlockKey  string        "traffic79:{inviteeMemberId}:escrow"
  state      string        frozen / unlocked / forfeited
  deadline   ISO8601       发放+7天
  unlockedAt / reason      解冻/回收时间与依据
Redis: hash points:escrow:{escrowId}
索引: list points:escrow_by_user:{userId}; zset points:escrow_deadline(score=时间)
```

**points.accounts 增量**: `frozenPoints` 字段(冻结中额度, 展示用);
`points.logs` 增 state=frozen/unlocked 快照(向后兼容——旧流水无此字段视为 available)。

**解冻调度器**(挂 main.py startup, 74号调度器惯例):
- 每小时扫 `escrow_deadline` zset 到期项
- 查被引进人活跃计数(login_count/首单) → unlocked / forfeited
- 幂等: state 非 frozen 跳过; 锁 `points:escrow:{id}`

**熔断降级**(docx 采纳): 解冻率(7 天窗口 unlocked/(unlocked+forfeited))
< 90% 连续 3 天 → settings 新增 `referralEscrowEnabled` 自动置 false
(回落 v1 即时发放) + 站内信告警管理员——**一键回 v1 行为**。

### 1.2 阶梯奖励(月度)

**规则**(docx 运营建议落地, 数值 admin 可调):

| 档位 | 条件(自然月引进数) | 每人积分 |
|---|---|---|
| 基础 | < 50 | 300 |
| 精英 | ≥ 50 | 400 |
| 王者 | ≥ 200 | 500 |

**数据结构增量**: settings 加 `referralTierElite/TierKing/TierElitePts/TierKingPts`
(默认 50/200/400/500); 月度计数不建表——由 relations 按月聚合查询
(createdAt 前缀匹配, 量级内可承受; 超量再迁 monthly_stats 表)。

发放逻辑: _award_referral_points 先查当月已计数 → 取当前档位分值。
跨月清零天然由聚合口径解决。

## 二、防刷侧增强设计

### 2.1 设备指纹闸(复用 39号 hash_device_id)

**注册链挂接**: auth register 时(已有 fingerprint_of(UA) 调用点, P0 修复
注释 L216-225 处)同步写映射:

```
member_fingerprints 表(新):
  deviceId   string PK     39号 hash_device_id(UA/屏幕/语言/时区摘要)
  memberIds  list          该设备注册过的会员 ID
Redis: set member_fp:{deviceId} → [memberId...]
索引: string member_fp_last:{memberId} → deviceId(按人查设备)
```

**闸门规则**(bind_relation 计业绩判定内追加):
- invitee 的 deviceId 已关联 ≥3 个会员 → counted=False(reason=
  device_dup)——**不发分但允许绑定**(误杀成本 > 放行成本, 弱指纹仅作降权)
- 关联 ≥6 个 → 转 74号 IBMS 告警(critical, 人工处置)

### 2.2 速率异常检测(EMA 基线, 挂 74号巡检总线)

**设计**(EMA 黄金时段先例 + IBMS PATROL_ITEMS 注册表——增项即追加):

```
check_growth_abnormal(第 8 检查项):
  - 扫近 24h relations 新增, 按推荐人聚合
  - 与 7 天 EMA 基线比较: 单人日新增 > EMA×10 或 绝对值 > 50
    → WARN(单人行) / > 100 → FAIL(团伙嫌疑)
  - 状态: PASS/WARN/FAIL 三态入 IBMS 留痕(复用巡检总线+告警闭环)
```

**自动降闸**(docx"异常熔断"落地): FAIL 时自动执行
`shareDailyLimit` 临时下调为 1 + `referralEscrowEnabled` 强制 true
(强制观察期) + 管理员站内信——**只降不升**(恢复需人工)。

### 2.3 追回机制(补 v1 敞口 O1 的处置工具)

```
POST /api/promotion/admin/points/revoke
体: {"memberId": 123, "points": 400, "refId": "traffic79:456",
     "reason": "刷单追回(工单#T123)"}
语义: 写负数流水(type=deduct, source=admin_revoke, refId 同源),
      余额不足则扣至 0 并记欠口(不透支)
幂等: (userId, source, refId) 唯一——重复追回 409
权限: X-Role admin + 二次确认字段 confirm=true
```

## 三、实施路径(四步, 独立可回滚)

| 步 | 内容 | 依赖 | 回滚 |
|---|---|---|---|
| E1 | 追回端点(纯增量工具, 零风险先行) | — | 端点不调即无效果 |
| E2 | 设备指纹闸(注册挂接+降权判定) | 39号指纹(已有) | settings 加 deviceGateEnabled=false |
| E3 | Escrow 延迟结算(冻结/解冻/熔断) | — | referralEscrowEnabled=false 回 v1 即时 |
| E4 | 阶梯奖励 + IBMS check_growth_abnormal | IBMS 总线(已有) | 分值参数可调回 300 恒定 |

**上线顺序建议**: E1 → E2 → (观察 1 周) → E3 → E4。
每步独立单测(test_growth_v2_*.py)+ 灰度(settings 开关全部默认关,
按 74号 shadow 惯例先观察后放量)。

**触发器**: P1 运行 2 周且出现 O1-O3 任一实证(刷单/设备聚集/速率异常)
→ 启动对应步; 无实证则 E1(追回工具)仍建议先行——纯防御性零成本。

## 四、ROI 与边界

- **不做的**(维持 v1 裁定): 行为生物特征(鼠标轨迹/键击动力学——过度
  工程)、运营商网关一键登录、第三方 IP 信誉库(成本, 43号网关够用)
- **明确边界**: 设备指纹是弱特征(39号现有口径, UA 可变)——只降权不
  封号; Escrow 只冻 traffic79 大额轨; 所有新闸门 admin 可一键关
- **数据回报**: escrow 表天然形成"引进质量"数据集(解冻率/回收率/
  活跃特征)——为 P3 精准拉新模型(哪类会员带来的新客质量高)供料
