## 一、背景与问题

顺手赚钱模块(张贴广告物料打卡获利)的打卡照片凭证链路存在四项缺陷,
经 5 轮迭代修复全部闭环:

| # | 缺陷 | 影响 |
|---|------|------|
| 1 | 打卡照片直传**本地临时路径**(H5 为 `blob:` URL), 落库即失效 | 服务端无照片可审计, 刷单无凭证核验 |
| 2 | 修复途中引入的 `Taro.getFileSystemManager` 在 **H5 端是 Taro 桩**(调用返回 Promise 而非对象) | `fsm.readFile` 直接 TypeError, 电脑端选照片后静默失效 |
| 3 | H5 端 `Taro.chooseImage` 实际渲染 `<input type="file">`, **桌面浏览器忽略 camera 约束** | 弹文件选择框, 相册/网图任意选, 防刷口径被击穿 |
| 4 | `report_site` **先落库后发奖非原子**(钱包未开通时发奖抛错) | 留孤儿点位脏数据; checkin 路径发奖失败会白白消耗当日打卡额度 |

## 二、最终架构(修复后)

```
现场拍照(强制相机)
  ├─ H5 端: getUserMedia 实时取景层(自建 UI, 无文件选择入口)
  │          电脑=摄像头 / 手机浏览器=后置相机, 权限拒绝有引导
  └─ 小程序端: chooseImage sourceType=['camera'](禁相册)
        ↓
本地读取(utils/image-reader.ts 跨端双轨)
  ├─ H5: tempFiles[0].originalFileObj(原生 File) → FileReader.readAsDataURL
  └─ 小程序: tempFilePaths → FSM.readFile(base64)
        ↓
SHA-256 内容指纹(Web Crypto, dataUrlToSha256 → "sha256:"+hex64)
        ↓ 仅提交 72 字符指纹——图片本体永不上传服务器(零存储/隐私友好)
后端校验(pocket_service)
  ├─ 格式校验: _valid_photo_hash(sha256: 前缀 + 64 位 hex, 非法 409)
  ├─ 防刷去重: 同会员指纹全局去重(checkin_photo_exists, 近 500 条)
  ├─ 发奖原子性·第一层: _ensure_wallet_ready 前置校验(落库前快速失败)
  └─ 发奖原子性·第二层: 落库后发奖失败回滚
       ├─ report: delete_site 删点位(零孤儿, 原指纹可重试)
       └─ checkin: 恢复 prev_fields(当日打卡不被消耗)
```

## 七、经验沉淀(可复用)

1. **Taro H5 桩陷阱**: `getFileSystemManager` 在 H5 是
   `temporarilyNotSupport` 桩(返回 Promise)——前端读本地文件一律走
   `utils/image-reader` 双轨, 禁止页面直调
2. **H5 强制拍照**: 桌面浏览器必弹文件框, 须 getUserMedia 自建取景层
3. **指纹代替上传**: 与项目「哈希指纹链代替直接存储」宪法口径一致,
   兼得防刷与隐私(零照片存储)
4. **Node 18 测试坑**: 全局无 webcrypto, 测 `dataUrlToSha256` 需
   `globalThis.crypto = require('crypto').webcrypto` 注入
5. **SSH 验证坑**: PS 单引号经 ssh 到 bash 时内部双引号会丢失
   (`curl -H "X-Role: admin"` 实变空值头)——自定义头验证须写 python 脚本上传执行
