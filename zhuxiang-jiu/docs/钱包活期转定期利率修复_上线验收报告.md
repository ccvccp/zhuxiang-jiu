## 二、缺陷定位与根因分析

### 2.1 缺陷现象

用户报告: 活期转定期 3/6/12/24 个月的年化率 3%→3.3%→3.5%→3.8%
"没有改正过来"。

### 2.2 三层排查(逐层收窄)

| # | 排查层 | 结果 |
|---|---|---|
| 1 | 本地 wallet_service.py DEPOSIT_TIERS | ✅ 正确(0.030/0.033/0.035/0.038) |
| 2 | 生产服务器文件 grep | ✅ 正确(同上) |
| 3 | 公网 GET /api/wallet/interest/rules | ✅ 正确(regular 四档 3%/3.3%/3.5%/3.8%) |
| 4 | 前端 wallet/index.tsx 硬编码文案 | ❌ 发现"3%-5%"旧文案 |
| 5 | **前端 src/api/wallet.ts DEPOSIT_TIERS** | ❌ **根因命中** |

### 2.3 根因

前端 `DEPOSIT_TIERS` 硬编码常量停留在**最初倒挂版**:

| 存期 | 前端显示(错) | 应为(后端终态) |
|---|---|---|
| 3 个月 | 3.0% | 3.0% |
| 6 个月 | **5.0%** | 3.3% |
| 12 个月 | **3.0%** | 3.5% |
| 24 个月 | **3.5%** | 3.8% |

转定期弹层四档利率显示直接消费该本地常量(`{t.rate} 年化`),
与后端完全脱钩。

### 2.4 事故链复盘

后端两轮调息(bc496d9 倒挂微调 / 76be17d 单调递增)均只改后端常量
与设计文档, 验收也止步于容器内常量实证与公网 API 验证——
**前端硬编码常量两轮均漏改**, 且利率验收未覆盖前端展示面,
属纯前端展示漂移(资金计算、实际收益、API 均无影响)。

## 三、修复方案(改正 + 根治双层)

### 3.1 兜底常量改正([wallet.ts](file:///d:/网站架构设计/taro-app/src/api/wallet.ts))

`DEPOSIT_TIERS` 常量修正为 3.0%/3.3%/3.5%/3.8%, 注释标明
"兜底展示; 运行时优先取动态利率"及事故背景。

### 3.2 动态利率根治([wallet/index.tsx](file:///d:/网站架构设计/taro-app/src/pages/wallet/index.tsx))

- 新增 `regularTiers` state(默认常量兜底);
- `loadAll` 非阻塞拉取既有 `WalletAPI.interestRules()`
  (/api/wallet/interest/rules, 公开接口), 成功则以后端
  `regular` 数组映射 `{period, min, rate}` 覆盖, 失败静默回落常量;
- 三处消费点全部切换 `regularTiers`:
  1. 转定期最低存入校验(`handleTransferRegular`);
  2. 弹层四档位渲染(`quickRow`);
  3. 金额输入 placeholder(最低存入提示)。

**效果**: 后端今后调息, 前端弹层自动跟随, 硬编码漂移类事故根治。

### 3.3 顺带修正

空态文案"暂无定期, 转定期享年化 **3%-5%**+奖品"→"**3%-3.8%**"。

## 六、工程沉淀

| 主题 | 记录 |
|---|---|
| 调息验收口径 | 调息类需求须覆盖**前端展示面**——容器常量+公网 API 之外, 须 grep 前端硬编码利率常量同步, 并浏览器实机复核 |

| 事故定位法 | "后端对/前端错"型缺陷按 本地代码→生产文件→公网 API→前端常量 四层收窄, 本次 5 步命中根因 |
