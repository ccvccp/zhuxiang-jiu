## 三、标准部署步骤

> 全程幂等可重跑；中断任意步骤可直接从该步骤重试。

```powershell

git fetch origin; git checkout <目标提交>   # 首上线=0df3b17

docker exec zhuxiang-jiu-backend-1 sh -c "printenv | grep XIAOZHU"
#    预期: XIAOZHU_LLM_MODE=off / XIAOZHU_PROACTIVE_MODE=off
```

## 五、灰度开关开启流程（逐轨独立，均在观察期后）

### 5.1 LLM 意图增强轨（XIAOZHU_LLM_MODE）

**前置检查单**：
- [ ] `LLM_API_KEY` 已配置且 `LLM_ENABLED=on`（35号链路实测可用）
- [ ] 规则轨观察期 ≥2 周：看板②兜底率稳定（无持续异常飙升）
- [ ] LLM 供应商配额/费用确认（意图轨每轮一次调用）

**开启操作**：
```powershell
# .env 追加 XIAOZHU_LLM_MODE=on 后:
docker compose -p zhuxiang-jiu up -d backend   # 容器重建
# 验证: 发一条规则轨未覆盖指令 → 回包 track=llm; 规则轨指令仍 track=rule
```

**红线**：LLM 只选白名单 action 抽参数——数字仍来自执行层 API；轨道异常自动回规则轨（fail-soft）。

### 5.2 主动关怀调度（XIAOZHU_PROACTIVE_MODE）

**前置检查单**：
- [ ] 手动扫描实测 ≥2 周：`POST /api/xiaozhu/proactive/scan` 任务生成与频控正常
- [ ] 关怀文案人工复核（红线：关怀不是营销——只推修复引导不推商品）
- [ ] 47号画像 watched/restricted 档数据质量确认

**开启操作**：同上，`.env` 设 `XIAOZHU_PROACTIVE_MODE=on` 后重建容器。

**频控口径**（代码内置，无需配置）：同一会员同类型 7 天间隔 + 全局日上限。

## 六、回滚预案（三级回退体系）

### 6.1 回退决策矩阵

| 症状 | 级别 | 动作 |
|------|------|------|
| LLM 轨幻觉/延迟/费用异常 | **L1 开关** | 关 XIAOZHU_LLM_MODE |
| 关怀被投诉骚扰/文案不当 | **L1 开关** | 关 XIAOZHU_PROACTIVE_MODE |
| 语音模块局部故障（看板区块降级/ASR 降级） | 不回退 | fail-soft 设计内——按运维手册 §七排查 |
| 兑换/高敏流异常（疑似资损） | **L2 版本** + 冻结 | 立即 L2；同时保留 Redis 数据供审计 |
| 进程级故障（import 错误致启动失败/内存异常） | **L2 版本** | 回退到 bb2577f 重建 |
| 数据污染（测试数据混入/积分误发） | **L3 数据** | 定向清理 voice48 键（见 6.4） |

### 6.2 L1 开关级回退（秒级，最常用）

```powershell
# .env 中对应项改回 off（或删除该行）后:
docker compose -p zhuxiang-jiu up -d backend
# 验证: printenv | grep XIAOZHU → 两项均 off
#       看板⑥/会话数据不丢(仅轨道停用); 规则轨照常服务
```

**特性**：轨道数据全部保留；回退后可随时重新开启。

### 6.3 L2 版本级回退（分钟级）

```powershell
# 1. 回退到 48号前版本(零代码态)
git checkout bb2577f

# 2. 重建镜像与容器
docker compose -p zhuxiang-jiu build backend
docker compose -p zhuxiang-jiu up -d backend

# 3. 冒烟: health 200 + trust45 200 + ai46 sync discovered=28
```

**安全性依据**：48号为纯增量模块（独立路由前缀 /api/xiaozhu/*，既有 55 路由文件零改动）——回退后：
- 会员端浮层如已挂载会出现 API 404 → 前端同步下线 widget 引用（一行 script 删除）
- 管理看板同理删除两文件即可，或保留（页面报"无法连接"无害）
- **Redis voice48 数据可保留**（前向兼容：重新上线时 9 表结构不变）

**分期回退**（保留部分期功能）：回退到对应分期边界提交（如只需 P0-P2 → `c5e47d9`）。注意 P3 积分表/P4 看板表为独立键，旧代码不读不写，残留无害。

### 6.4 L3 数据级清理（定向，谨慎）

```powershell
# ① 会话/轮次（隐私数据，可随时清——会员"一键清除"同款效果）
docker exec zhuxiang-jiu-redis-1 redis-cli --scan --pattern "zhuxiang:voice48:sessions:*"
docker exec zhuxiang-jiu-redis-1 redis-cli --scan --pattern "zhuxiang:voice48:turns:*"
# 确认后批量 DEL

# ② 积分账本（谨慎！删除=会员积分损失）
#    仅限"积分误发"审计结论后执行; 保留 voice48:points_acc 余额键可止血
#    新增发放(止血不追回历史):
docker exec zhuxiang-jiu-redis-1 redis-cli --scan --pattern "zhuxiang:voice48:points*"

# ③ 共创/关怀/失败案例（治理数据，低风险可清）
#    voice48:custom_cmds / proactive / failures

# ④ 46号 side-door 档案与采样（版本回退到 48号前时一并清理）
docker exec zhuxiang-jiu-redis-1 redis-cli --scan --pattern "zhuxiang:ai46:*"
#    → 仅删除 scorerId=xiaozhu_voice 的 govs/samples/reports 相关键
```

**口径**：voice48 键空间与 45/46/47号完全隔离（独立前缀），清理本模块数据**不触碰**其他模块；ai46 侧仅 xiaozhu_voice 档案相关键属于 48号。

### 6.5 不可回退项（无）

本模块无数据库迁移、无既有表结构变更、无不可逆写入——**全部操作可完整回退到 48号前零代码态**。

## 七、应急处理速查

| 现象 | 判断 | 动作 |
|------|------|------|
| 容器反复重启 | 启动期 import 崩溃 | L2 版本回退（bb2577f） |
| 看板 zoneErrors 非空 | 单区块数据源异常 | fail-soft 内——查 Redis 连接；不回退 |
| 兑换重复扣积分投诉 | 幂等/验真疑点 | 冻结入口：看板+浮层下线；L2 回退；保留 points 全量流水审计 |
| 会员反馈"语音没反应" | ASR 降级/无 key | 属预期降级（文本同链可用）；补 LLM_API_KEY |
| 公平性审计 flagged | 等级间直达率差异>20% | 人工复核指令集覆盖（非故障——见运维手册 §三） |
| Redis 内存告警 | voice48 键膨胀 | 会话/轮次可安全清理（隐私短存设计） |
