## 二、配置项清单

### 2.1 必配（已入册 compose，经 `.env` 覆盖）

| 变量 | 默认 | 生产建议 | 说明 |
|------|------|---------|------|
| `II58_MODE` | off | 灰度后 shadow→assist | 决策面三级灰度（见 §五） |
| `II58_LLM_MODE` | off | 按需 on（assist 态） | L2 低置信路由+合成建议——LLM 仅建议不入库 |
| `II58_LEARN_MODE` | off | 观察期后 on | T+1 回流调度 |
| `II58_LEARN_INTERVAL` | 86400 | 86400（可调） | 调度周期秒（下限 300 防忙循环） |

**三级灰度语义**（`II58_MODE`）：

| 值 | 开放面 | 拒绝面 |
|----|--------|--------|
| off（默认） | 仅观测面 9 端点+终审/回流 | 决策/会员面全 409（零影响铁律） |
| shadow | 观测面+评估留痕+采集流水线（挖掘/登记/终审） | 会员面（显式反馈不开放） |
| assist | 全链：含显式反馈（会员面 X-Member-Id） | — |

**不受开关影响的面**（任何模式均可用）：
- 语料终审 `POST /corpus/{id}/review`、标注终审 `POST /labels/{id}/decide`、阈值终审模（calibrate 带 changeId）——**人工铁律**（优化永不自动生效：active 唯一出口）
- 回流 `POST /feedback/collect`（回流管理面）
- 全部观测面（GET 系）

### 2.2 生效方式

改 `.env` 后执行 `docker compose -p zhuxiang-jiu up -d backend`（容器按配置差异自动重建）。

## 五、灰度开启顺序（三开关独立，逐级放量）

```
Step 0  部署完成（全 off）
        └─ 观测面冒烟（§4.1——off 亦可用）
Step 1  II58_MODE=shadow（观察学习期）
        └─ admin 跑 §4.2 shadow 段（evaluate→挖掘→登记→终审→评估命中）
        └─ 观察期 1-3 天：dashboard 度量区任务完成率/澄清率；
           识别记录归因链完整（无归因不计入有效服务）
        └─ 终审通道不受开关影响——可先行演练语料回流链
Step 2  II58_MODE=assist（辅助生产期——会员反馈面开放）
        └─ admin 跑 §4.2 assist 段（feedback→decide→collect）
        └─ 试点会员（X-Member-Id）走"不是这个"反馈全链
        └─ 观察期 3-7 天：labels pending 清队+弱满足/高置信错误信号分布
Step 3  II58_LEARN_MODE=on（T+1 调度开放）
        └─ 可先手动 POST /api/ii58/feedback/collect 即时触发首轮补标
        └─ 观察 events：learn_signal / scheduler_run 留痕
        └─ 高置信错误≥3 自动提交阈值收紧建议（pending——人工终审后生效）
（II58_LLM_MODE=on 按需：assist 态低置信 L2 路由+合成建议——建议最后开启）
```

**放量节奏建议**：内部 admin 演练→试点会员（内部账号）→灰度受众→全量。三铁律保障：优化永不自动生效（语料/标注/阈值全部人工终审唯一出口）；澄清优于错误执行（低置信必 clarify 禁止盲执行）；归因 ID 强制（每次识别携带归因链）。

**回退语义**：任何阶段 `II58_MODE` 回退 off——决策/会员面秒级 409 关闭，已激活语料保留（观测面可查）、终审/回流通道仍可用（人工兜底不关闭）。

## 七、回滚预案（三级）

| 级 | 场景 | 操作 | 生效 |
|----|------|------|------|
| L1 功能回退 | 决策/会员面异常 | `.env` 置 `II58_MODE=off` → `up -d` | 秒级；存量意图链路零影响（off 直通铁律——48/55号并行不替换）；终审/回流通道保留（人工兜底不失效）；调度可独立保留或同步 off |
| L2 配置/内容回退 | 阈值误生效/语料误导 | 阈值：驳回轨（镜像 rejected 基线不变）或重新 calibrate 终审回调；语料：`corpus/{id}/review` 不适用（active 终态）——经标注轨 decide(reject) 或 Redis 直改 retired | 不停机；回流自动记负修正信号 |
| L3 代码回退 | 版本级故障 | `git revert` + rebuild + `up -d` | 分钟级；Redis 数据兼容（五清单只增不改） |

**L2 与 L1 的选择**：阈值/语料问题优先 L2（配置粒度）；链路问题用 L1（面级关闭）。
