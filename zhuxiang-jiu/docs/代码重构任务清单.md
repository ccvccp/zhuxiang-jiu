### B1. Mutex FIFO 推广到其他并发 service

| 字段 | 内容 |
|------|------|
| 任务 ID | B1 |
| 优先级 | P1 |
| 模块 | 所有涉及共享资源读写的 service |
| 背景 | inventory-service 已用 Mutex FIFO,其他 service 可能仍有裸并发隐患 |

| 范围 | 1. order-service(订单号生成防重复)<br>2. coupon-service(优惠券核销防重复使用)<br>3. points-service(积分扣减防超扣)<br>4. wallet-service(钱包余额防超支) |
| 实现要求 | 1. 使用 `window.mutex.withLocks(['key1','key2'], fn)`<br>2. 锁 key 格式统一:`{资源}:{id}`(如 order:next, coupon:C123)<br>3. 多锁按 key 升序获取,反向释放 |
| 验收标准 | 1. 并发 100 次操作无超卖/重复<br>2. 参照 PTC11/PTC12 模式补充并发测试用例<br>3. 吞吐 ≥ 10000 req/s(FIFO 基线) |
| 参考文件 | js/mutex.js / js/inventory-service.js deduct/restock |

| 字段 | 内容 |
|------|------|

| 背景 | checkout submit 已加防重入,其他操作(支付/核销)仍可能连点重复 |
| 任务 | 为以下操作补充 _xxxInFlight 标记 + try/finally: |
| 范围 | 1. pay(支付连点防重复扣款)<br>2. verifyCoupon(核销连点防重复使用)<br>3. exchangePoints(积分兑换连点防超扣)<br>4. walletWithdraw(钱包提现连点防超支) |
| 实现要求 | 1. 模块作用域声明 `let _xxxInFlight = false`<br>2. 入口检查 `if (_xxxInFlight) return {success:false, error:'进行中'}`<br>3. `try { ... } finally { _xxxInFlight = false }` 保证释放<br>4. 不得用 try/catch(会吞异常)或裸 return(异常不释放) |
| 验收标准 | 1. 连点 10 次只有 1 次执行<br>2. 第 2-10 次返回"进行中"错误<br>3. 异常路径后标记正确释放(可继续操作) |
