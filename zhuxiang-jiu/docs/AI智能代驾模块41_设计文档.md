# 41号·AI智能代驾模块 设计文档 v1.0

> 定位：**喝竹香酒，AI 送你回家**——买酒满额 AI 自动发放市内代驾券入券包，酒后一键叫代驾，AI 全自动完成"资格审查 → 券核销 → 智能派单 → 行程跟踪 → 本站支付 → 服务评分回流"全链路零人工。代驾费由本站支付（营销成本），把"酒后最后一公里"做成酒类电商的差异化安全增值服务。
>
> 与物流模块（P1-17）的本质同构：物流送的是**货**（订单→智能选商→承运→签收回执→结算对账），代驾送的是**人**（叫单→智能选司机→行程→完成回执→结算对账）——派单引擎/状态机/回执/对账全套模式平移，猎物从承运商换成三轨运力。
>
> 方法论：对标成熟玩法（滴滴代驾/	e代驾开放平台/酒企"开瓶赠代驾"营销），叠加本项目既有 AI 基建（Mock-first 确定性模拟源 / ai_learning 评分器档案体系 / risk_control 风控 / L5 SVIP 会员体系），并首创**"买酒赠券+本站买单"**的酒类安全营销闭环。

---

## 1. 设计目标与核心概念

### 1.1 一句话模型

**"买竹香酒满 500 → AI 自动发 60 元市内代驾券入券包 → 酒后一键叫代驾 → AI 三轨智能派单（自营/加盟/平台直发）→ 行程安全监控 → 本站 AI 自动支付代驾费 → 双向评分回流让派单越派越准。"**

- 差异化三板斧：**零操作**（叫单后派单/支付/结算全 AI，乘客不碰支付）、**零负担**（券内费用本站买单，超出部分 AI 自动拆分补差）、**零风险**（司机 AI 资格审查 + 行程轨迹留痕 + 安全预警）

### 1.2 三轨运力模型（本模块核心结构）

| 轨道 | 来源 | 资格路径 | 成本 | 优先级 |
|------|------|----------|------|--------|
| **自营代驾员** | 本站超级会员 | L5 SVIP 注册 → AI 资格审查（实名+驾照≥3年+无重大事故）→ 上线接单 | 低（本站直接结算） | 1 |
| **加盟代驾员** | 代驾加盟平台合作会员 | 平台批量入驻登记 + AI 抽查复核 | 中（平台抽佣） | 2 |
| **平台直发** | 外部代驾平台运力 | 订单智能分发到代驾平台（同产品下单的物流分发模式） | 高（平台定价） | 3（兜底/溢出） |

- **自营为骨干、加盟为补充、直发为兜底**：AI 派单引擎按"距离×评分×成本×负载"综合决策，自营池满载或无可用司机时自动溢出直发，永不拒单
- 单乘客行程三轨互斥（一次行程只派一名司机/一个平台），失败可升级改派

### 1.3 与既有模块关系（复用不合并）

| 模块 | 关系 |
|------|------|
| `logistics`（P1-17） | **模式母版**：smart_route_carrier 规则路由 + LogisticsRoutingScorer AI 评分双层结构、承运状态机、三态回执（real/mock/mock_fallback）、日结对账单——四件套全套平移，猎物换司机 |
| `member`（P1-4） | 代驾员资格门槛直接判定 L5 竹海SVIP（`LEVEL_THRESHOLDS[5]=9999`）；乘客侧无门槛（持券即可） |
| `order`/`ai_hooks` | 满额赠券触发点：订单 `pay()` 成功 → `on_payment()` 钩子链新增代驾券发放（实付≥500 且含竹香酒商品）；退款订单 `on_order_outcome()` 冲正扣回未核销券 |
| `payment`（模块05） | 本站支付代驾费走 payout 模式（pending→auditing→approved→paying→paid，重试上限3）；幂等回调口径复用 |
| `ai_learning` | 新增两个评分器（**batch 8，第 22/23 档案**）：`driver_application_gate`（司机资格审查）、`ride_dispatch`（派单决策），决策正确性 Hedge 回流 |
| `risk_control` | 防刷券风控（位置-POI 校验/高频叫单/券异常流转）；司机背景审查信号输入 |
| `compliance`（37号） | 行程轨迹与支付存证（evidenceType 扩展 `ride`） |
| `hub`（35号） | 注册"叫代驾"意图与"代驾员"能力（可选 P2） |
| `ticket` | 行程投诉快通道（代驾专属工单优先级，复用 VIP 升紧急机制） |

## 2. 总体架构：六个子系统

### 2.1 满额赠券引擎（coupon_engine）——补齐全站券体系空白

> 现状：全站无独立券模块（checkout 域仅 2 张种子折扣券 + 工单补偿券记录 + Mock 满减）。本模块**自带完整代驾券引擎**，成为全站券体系的第一块完整落地（发放/过期/核销/冲正闭环），后续商品券可迁移此骨架。

**触发规则**（订单 `PAID` 后 AI 钩子自动执行，用户零操作）：

| 档位 | 订单实付（含竹香酒商品） | 赠券 |
|------|------------------------|------|
| 一档 | 500 ≤ 实付 < 1000 | 1 张 |
| 二档 | 1000 ≤ 实付 < 3000 | 2 张 |
| 三档 | 实付 ≥ 3000 | 3 张 |

- **券规格**：面值 60 元/张；仅限市内代驾（同城行程，起终点同市且里程 ≤ 40km）；有效期 90 天（发放日起）
- **券包**：用户维度聚合容器（`coupon_package`），自动收纳多订单赠券；账户未核销上限 **6 张**（防囤积，达上限不再发放并在券包留痕）
- **冲正**：订单退款 → 未核销券按发放来源逐张作废（`revoked`）；已核销券不追回（服务已消费，计入营销成本）
- **发放幂等**：券码 = `RIDE{orderId}_{seq}`，同一订单重复触发只发一次（锁 `coupon:grant:{orderId}`）

### 2.2 司机资格与审查（driver_gate）

**自营轨道**（超级会员注册，AI 全自动审查）：

1. **申请门槛硬校验**：L5 竹海SVIP（growth_value ≥ 9999 或付费开通）→ 非会员直接拒
2. **材料清单**：身份证号、驾照号、驾龄声明（≥3 年）、无重大交通事故/无酒驾记录声明、紧急联系人
3. **`DriverApplicationScorer` AI 审查**（第 22 档案，五因子）：

| 因子 | 权重 | 判据 |
|------|------|------|
| 材料齐全性 | 0.30 | 必填字段完备、格式校验（驾照位数/校验位） |
| 驾龄与准驾车型 | 0.25 | ≥3 年满分、C1 及以上；<3 年直接拒 |
| 会员信用 | 0.20 | 历史订单风控记录（risk_control 信号）、账户投诉率 |
| 账户健康 | 0.15 | 注册时长、实名等级、支付违约记录 |
| 声明一致性 | 0.10 | 声明内容交叉校验（年龄vs驾龄合理性等） |

4. **审查三档**（沿用阈值范式）：≥70 自动通过（approved）/ 50-70 人工复核队列（manual_review）/ <50 拒绝（rejected，留痕可申诉）
5. **生命周期状态机**：`applied → reviewing → approved/rejected → online（接单中）⇄ offline → suspended（违规暂停）→ revoked（资格吊销）`
6. **持续审查**：接单后每季度 AI 复核（信用信号恶化 → 自动 suspended，人工恢复）

**加盟轨道**：
- 合作平台批量入驻（admin 导入 or 平台 API 同步），资质审查责任在平台，本站 AI **抽查复核**（新司机 100% 抽查驾照格式 + 存量 10% 随机抽查）
- 加盟司机带平台侧评分初始值，服务数据双轨累计

### 2.3 智能派单引擎（ride_dispatch）——物流双层模式平移

**规则层**（对齐 `smart_route_carrier` 纯函数风格）：

1. 乘客定位 → 拉取半径 5km 内在线司机池（自营+加盟）
2. 硬条件过滤：司机评分 ≥ 4.0、驾龄达标、当前未在行程中、非 suspended
3. 轨道优先序：池内有自营 → 自营优先；仅加盟 → 加盟；池空/全忙 → **平台直发**

**`RideDispatchScorer` AI 评分层**（第 23 档案，五因子，高分=优先派）：

| 因子 | 权重 | 判据 |
|------|------|------|
| 接驾距离 | 0.30 | 乘客-司机直线距离分档（≤1km 满分），映射 ETA |
| 服务评分 | 0.25 | 司机累计双向评分（五星制归一） |
| 接单可靠度 | 0.20 | 接单率/完成率/取消率历史 |
| 轨道成本 | 0.15 | 自营 1.0 / 加盟 0.6 / 直发 0.3（成本越低分越高） |
| 负载均衡 | 0.10 | 当日已接单数（防单司机过载，保护体验） |

**决策三档**：≥70 头部司机直接派单（dispatched）/ 50-70 派次优并通知备选/<50 或池空 → 升级平台直发（`escalated`）

**平台直发契约**（复用物流三态回执，P3b 冻结契约风格）：

```
POST {DRIDE_PARTNER_URL}/dispatch
  请求: {rideId, pickup:{lat,lng,address}, dropoff:{...}, couponValue:60, estimatedKm}
  响应: {accepted, partnerOrderId, driver:{name, phone, plateNo, rating}, etaSeconds}
回调: POST /api/ride/partner/callback  {partnerOrderId, event: accepted|started|completed|cancelled, trace}
模式: DRIDE_CHANNEL_MODE = mock | real | mock_fallback（未配置 real 自动回退 mock，Mock-first）
```

### 2.4 行程状态机与安全监控（ride_trip）

**状态机**：

```
requested（已叫单）
  → dispatched（已派单，含司机信息）
  → driver_arriving（司机已出发/到位）
  → trip_started（行程开始，乘客上车）
  → trip_completed（行程结束）
  → settling（AI 结算中）
  → settled（本站已支付，终态）
分支: cancelled（派单后 3 分钟内免责取消，券退回）
      no_driver（全轨无运力 → 券退回 + 工单安抚，罕见留痕）
      exception（安全事件 → 升级人工急线 + 37号存证）
```

**安全监控**（酒后场景底线，全 AI 自动）：

- **行前**：乘客位置 POI 校验（非餐厅/酒吧/酒庄类 POI 的高频叫单 → 风控评分降档）；司机资质行前快照留痕
- **行中**：行程超时预警（市内 > 3h 未结束）、里程异常（超出预估 2 倍）→ 风控介入；轨迹摘要留痕（起终点+里程+时长，不做实时轨迹流，降本）
- **行后**：双向评价（乘客评司机五星制；司机评乘客），AI 审评复用 37号评价审评范式（垃圾评价过滤）

### 2.5 AI 智能支付与结算（ride_settle）

**计价规则**（市内代驾，环境变量可覆盖便于测试）：

```
起步价 35 元（含 5km）+ 超里程 5 元/km + 超时 1 元/分钟（>40min 部分）
夜间（22:00-06:00）加成 20%
```

**AI 自动结算流（trip_completed → settled，全程无人工）**：

1. AI 计价 → 总费用（如 48 元）
2. 券抵扣：一单一券，`min(60, 总费用)` 由本站支付；超出 60 部分乘客自动补差（余额/预授权，复用 payment 扣款口径）
3. 本站支付司机/平台：自营 → payout 直付司机（复用 payment_service payout 状态机）；加盟/直发 → 周期汇总结付合作平台
4. 结算单落库 + 37号存证（evidenceType=`ride`）
5. 双向评价触发 + 派单决策回流

**对账**：日结对账单（对齐物流结算单模式 `pending → reconciling → confirmed → paid`，差异分支 `diff → investigating → resolved`）——本站支付流水 vs 平台账单 vs 券核销记录三方对平。

### 2.6 学习回流（ai_learning，第 22/23 档案闭环）

- **资格审查回流**：司机后续服务数据（投诉率/取消率/评分）回流 `driver_application_gate`——审查通过但服务差的样本修正因子权重
- **派单回流**：行程结果（乘客评分/准时率/取消）回流 `ride_dispatch`——被派单司机的实际表现验证派单决策正确性（Hedge 引擎调因子权重，个体司机权重走可解释规则步进，对齐 40号两层学习范式）
- **营销 ROI 回流**（P2）：赠券订单 → 核销率 → 复购率链路统计，输出"满额赠券档位效果"报表，反哺券包梯度调优

## 3. 数据模型（前缀 ride/driver，双模式内存+Redis）

```
driver_pool            司机池(轨道/平台/资质快照/状态/评分/服务统计/当日负载)
driver_applications    注册审查流水(材料/AI评分/档位/复核记录)
ride_coupon_packages   券包(用户维度, 持有计数/上限)
ride_coupons           代驾券(code/面值/来源订单/发放时间/过期时间/状态)
ride_orders            行程订单(状态机/起终点/司机快照/轨迹摘要/计价明细)
ride_settlements       结算单(本站支付流水/平台账单/差异状态)
ride_reviews           双向评价(评分/AI审评结果)
```

券状态机：`granted → used（核销）/ expired（过期）/ revoked（退款冲正）`

**Mock-first 种子**：8 位种子司机（自营 3/加盟 3/直发模拟 2，对齐 40号 8 博主惯例）、1 个模拟合作代驾平台（`e代驾mock`）。

## 4. API 设计（约 30 端点，前缀 /api/ride）

**乘客端**：
- `GET  /api/ride/coupons` 我的券包（含即将过期提醒）
- `POST /api/ride/call` 叫代驾（起终点；券自动选用最早过期者优先）
- `GET  /api/ride/orders/{id}` 行程详情（司机信息/状态/预计费用）
- `POST /api/ride/orders/{id}/cancel` 取消（免责窗口判定）
- `POST /api/ride/orders/{id}/review` 评价司机

**司机端**：
- `POST /api/ride/driver/apply` 注册申请（自营轨道）
- `GET  /api/ride/driver/application` 审查进度
- `POST /api/ride/driver/online` / `offline` 上下线
- `POST /api/ride/driver/orders/{id}/accept` / `start` / `complete` 行程操作
- `GET  /api/ride/driver/settlements` 我的结算

**平台回调/管理端**：
- `POST /api/ride/partner/callback` 合作平台回执（三态）
- `GET  /api/ride/admin/applications` 审查队列（manual_review 档）
- `POST /api/ride/admin/applications/{id}/decide` 人工复核
- `POST /api/ride/admin/drivers/import` 加盟司机批量导入
- `GET  /api/ride/admin/reconciliations` 对账单列表
- `GET  /api/ride/admin/risk-panel` 风控面板（防刷券信号聚合）
