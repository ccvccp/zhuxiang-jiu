## 二、P5 核心交付

### ① 五类开放 API(§八 8.1 全落地)

| API | 安全控制 | 关键实现 |
|-----|---------|---------|
| 信值查询 | 字段级脱敏 | 证件摘要/因子快照永不开放; 修复建议摘要口径 |
| 兑换核销 | 幂等键 + nonce + 时间窗 | 同 idempotencyKey 重复返回原结果(24h TTL); nonce SET NX EX 原子占位防并发双花; ±300s 防重放 |
| 行为存证 | 敏感词硬拦截 | 证件/病历/指纹(数据最小必要红线); **被拒请求同样留痕**(审计完整性) |
| 信用分转换 | nonce 防重放 | 单向语义; 重放请求 409 |
| 监管审计 | 只读+全留痕 | 四视图(档案/事件/账本/访问日志)脱敏; 自身访问入日志 |

### ② 44号 Key 网关联动(复用而非重建)

开放面端点登记入 44号台账并标 published → ApiKeyMiddleware 自动接管
双头校验/QPS/日配额——45号侧只做业务语义, 传输层治理零重复建设。
实机验证: 无双头 401 → Key 双头 200 全链。

### ③ 治理看板(trust-dashboard)

六区块(§八 8.2): 角色总览(双角色分布/熔断率/分数分层)/AI 雷达态势
(三通道采集量)/修复引擎监控/信值资产(发行/销毁/准备金覆盖率<80% 红色
预警)/自进化面板(申诉/补丁/宪法护栏声明)/审计日志查询。
价值红线常驻: "1 TV = 1 元货品/服务——不可兑现金/不可二级交易"。

### 执行中修复(2 项)

| # | 缺陷 | 修复 |
|---|------|------|
| 1 | 审计日志 Redis LPUSH dict 报错(Invalid input of type: 'dict') | JSON 序列化后入队 |
| 2 | CORS 白名单缺 X-Api-Key/X-App-Code(浏览器直连开放面预检失败) | 补 Key 双头 + X-Nonce/X-Idempotency-Key |

## 九、执行中修复的缺陷(全期 7 项)

| # | 期 | 缺陷 | 修复 |
|---|-----|------|------|
| 1 | P1 | 存证成功轨 depositId 未持久化(状态查询 404) | 显式落库后并档 |
| 2 | P1 | 授权探针被跨源关误拒(未视同权威源) | probe_authorized 入权威源表 |
| 3 | P3 | 账本 Redis 反序列化数值字段返回字符串 | _parse_row 数值还原 |
| 4 | P4 | 申诉 Redis HSET 布尔值报错 | 序列化分支补 bool→0/1 |
| 5 | P4 | 申诉更新时 LPUSH 索引重复入队(decide/collect 轮次翻倍) | 新建/更新分离 |
| 6 | P5 | 审计日志 LPUSH dict 报错 | JSON 序列化 |
| 7 | P5 | CORS 白名单缺 Key 双头(浏览器直连失败) | 补 4 个头 |

**经验**: 双模式(内存/Redis)的序列化边界是缺陷高发区——bool/dict/nested
类型在 Redis 轨需要显式转换; 索引维护(入队/更新)分离是幂等的关键。
