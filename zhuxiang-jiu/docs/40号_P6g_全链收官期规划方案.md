# 40号·AI智能DV博主大模型——P6g 全链收官期规划方案

> 依据:40号 P0-P6f 十阶段交付终态(649+ 断言)+ 66号 P5 收官范式(四区看板/
> 红队七向量/宪法断言/收官三件套)+ 用户指示"开始 P6g 规划"
> 定位:P6f 已完成"生态自治"能力闭环;**P6g 为全链收官期**——不给引擎加新能力,
> 而是把 P5-P6f 的 51+ 新端点从"API 可用"升为"运营可视",把宪法红线从"散布
> 各期断言"收口为"集中攻击验证",把全链从"本地测试"推到"Docker 实机+生产"
> 核心命题:**收官不是停止,而是让十阶段资产可运营、可对抗、可追溯**——
> 看板让自主行为可见,红队让红线可信,实机让交付可用,三册让知识可传

## 一、收官定位:从"功能完备"到"运营就绪"

| 维度 | P6f 现状(功能完备) | P6g 收官后(运营就绪) | 手段 |
|------|------------------|---------------------|------|
| 可视化 | 前端仅 P0-P2 五页签;P5-P6f 51+ 端点无视图 | **自主引擎统一看板**(第 6 页签) | P6g-1 |
| 对抗性 | 红线散布各期断言(被动验证) | **红队七向量主动攻击**(隔离域自清理) | P6g-2 |
| 宪法保障 | 各期专项各自覆盖 | **宪法断言集中收口**(一表全红线) | P6g-3 |
| 交付形态 | 本地内存测试全绿 | **Docker 实机 + 生产部署 + 三册** | P6g-4 |

**现状盘点**(收官必要性):
- 前端 `pages/blogger/index.tsx` 五页签(总览/博主池/侦测/跟随/学习)止步 P2;
  P5 四引擎/P6 音视频五引擎/P6f 生态四引擎——**16 个服务、51+ 端点无任何前端视图**
- 66号先例:红队七向量(RT-01~07)在隔离域 991x 确定性运行——40号尚无红队
- 项目传统:每大模块收官必带 Docker 实机测试 + 运行报告/用户指南/交付总结三册

## 四、P6g-2·红队七向量(隔离域 993x)

### 4.1 攻击向量设计(确定性零 LLM, 对齐 66号范式)

| 向量 | 攻击面 | 防线断言(必拒) |
|------|--------|---------------|
| RT-01 越权租用 | 会员 B 用 A 的 personaId 生成脚本/渲染/上报 | ownerId 命名空间 404 |
| RT-02 租金逃逸 | 直调 P6b render_work 绕租用账本; 篡改 ledger units | 受控写必经 _charge; 账本 append-only |
| RT-03 深审投毒 | "疫?情"拆词/谐音绕风险词; 价值观词混排 | 词表命中即一票否决(去标点归一后匹配) |
| RT-04 授权伪造 | 撤回 auth 后再 deep_review; 过期授权转发; 伪造 evidenceHash | 前置硬门 active+未过期; 撤回秒级下架 |
| RT-05 γ 权重攻击 | compute_emotion_reward 直传 gamma<alpha; set_av_reward_params 越界合并 | 函数级+存储级双 ValueError |
| RT-06 自愈滥用 | heal 耗尽后静默重试; pause 窗口强写 | 耗尽转人工永不丢弃; pause 拒受控写 |
| RT-07 水印剥离 | 构造无 AI_WATERMARK 正文; 伪造 watermarkHash | 生成断言 ValueError; 哈希服务端重算 |

### 4.2 隔离域工程口径

- **隔离域 993x**(personaId/memberId/authId 偏移基址)——避开 64号 98xx、
  65号 9881+、66号 991x;种子数据测试后自清理(66号 Redis 态清理须跳过
  seq/index 非哈希辅助键的教训直接继承)
- 每向量独立 try——单向量异常不中断整轮(66号先例)
- 红队不建新服务:复用各期服务实例, 仅构造恶意输入断言防线

## 五、P6g-3·宪法断言收口

**一张表集中断言 12 条红线**(跨 P5-P6f 全部宪法域):

| # | 断言 | 来源期 |
|---|------|-------|
| 1 | β 传入任何值 → ValueError | P5a |
| 2 | γ<α(函数级+存储级)→ ValueError | P6a |
| 3 | UGC 分成 pending 未 approve → 不入账 | P5b |
| 4 | 高预算推广 → 仅 pending 建议书 | P5c/P6c |
| 5 | pause 后学习/固化/渲染/自愈/受控写全拒 | P5d/P6* |
| 6 | 未授权深审 → KeyError/ValueError | P6b/P6e |
| 7 | BGM 封禁库元素 → 生成拒绝 | P6a/P6b |
| 8 | 无 AI 水印 → 生成失败 | P6b |
| 9 | 授权撤回 → 关联内容全量下架 | P6e |
| 10 | ownerId 越权 → 404 | P6f-1 |
| 11 | 租金/绩效未 approve → 不结算 | P6f-1/2 |
| 12 | 白皮书输出零 PII(piiHits=0) | P6f-3 |

工程形态:`test_blogger_p6g_constitution.py`——单一套件按表逐条断言
(非重复实现, 而是从各期专项提取宪法级子集做**回归哨兵**:

## 九、关键设计决策备忘

1. **收官不加能力**:P6g 不给任何引擎加新端点/新表——看板消费既有端点,
   红队攻击既有防线, 断言收口既有红线;**收官的交付物是"可信度"本身**
2. **看板唯一写口**:前端全只读 + pause/resume 弹窗(理由必填)——
   "观测开放, 干预留痕"的宪法口径在前端的最终落地
3. **红队域 993x 选址**:避开 98xx(64)/9881+(65)/991x(66)——
   模块隔离域不冲突是全站测试基建的隐性约束
4. **宪法哨兵的价值**:12 条断言跨 9 个测试文件散布——任何一期重构
   破坏红线时, 哨兵套件第一个红, 不需要跑全量 649 才发现
5. **实机两轮幂等**:内存/Redis 双模式各一轮(Docker 实机传统口径)——
   Redis 序列化清单遗漏是既有教训(.get() 崩溃先例), 实机是最后防线
6. **三册即传承**:67号三册先例——运行报告给运维、用户指南给 admin、
   交付总结给未来;收官知识不入册等于丢失
