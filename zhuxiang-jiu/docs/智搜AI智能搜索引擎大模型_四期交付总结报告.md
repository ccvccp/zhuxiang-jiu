## 一、项目概览

**一句话定位**：用户说人话，智搜判断「他是谁、他想要什么」，从站内
商品/权益/订单/知识多库中查出正确答案或执行正确动作。

**品牌家族**：智启元(AI财务) × 智法(AI法务) × 智运(AI物流) ×
智图(AI地图) × 智单(AI订单) × 智客(AI会员) × **智搜(AI搜索)**

**复用率**：MVP 复用站内 80% 资产（知识库检索/合规词库/会员模型/
六模型范式），新建面集中在意图层与融合层。

## 二、五层架构与四期演进

```
用户输入（Web search.html / 小竹语音 zs.search）
        ↓
┌─ L1 意图层 ──────────────────────────────────┐
│ 规则锚点得分制(7 意图+强操作词加成+低置信线)    │
│ + P2 LLM 兜底(intentWeight 采纳闸, fail-soft)  │
│ + P3 混合意图拆分(分句→副意图→双路)            │
│ + 槽位 9 类(价格/场景/商品/单号/运单/等级/省份) │
└──────────────┬───────────────────────────────┘
        ↓
┌─ L2 合规前置(硬规则, LLM/拆分均不可绕过) ──────┐
│ 未成年购酒/医疗功效/代理收益承诺 → 命中即拦截   │
└──────────────┬───────────────────────────────┘
        ↓
┌─ L3 多路检索(P1 权益/订单接入, P2 改写) ───────┐
│ R1 商品 | R2 权益(会员模型) | R4 订单(鉴权+智运)│
│ R5 知识(426+条, embedding 检索, LLM 改写问句)  │
└──────────────┬───────────────────────────────┘
        ↓
┌─ L4 融合重排(确定性) ─────────────────────────┐
│ 相关0.5+角色0.2+业务0.2×routeBoost+合规0.1恒定 │
└──────────────┬───────────────────────────────┘
        ↓
┌─ L5 生成与动作(P3 副问摘要合并) ───────────────┐
│ 结构化回答(来源引用)+动作卡片+反馈入口          │
│ → 显式反馈/动作卡点击 → 进化回流               │
└───────────────────────────────────────────────┘
```

## 三、各期交付明细

### MVP（ae5c458 + a84ed50）
- **意图层**：7 意图规则锚点表（独占词 2 分/共享词 1 分得分制）+
  强操作词加成（"竹香酒怎么下单"操作意图优先）+ 低置信 chat 兜底
- **合规前置**：minor/medical/agent_promise 三组硬规则，命中即拦截，
  权重永不参与进化；纯符号/表情零 LLM 调用（有效字符闸）
- **双路检索**：R1 商品（product_service）+ R5 知识
  （knowledge_service 三级检索：2-gram+embedding+rerank）
- **三态灰度**：ZS_MODE off(409)/shadow/assist，生产 assist
- **决策留痕**：意图/槽位/候选 top3/合规/llmAssist/subIntents 全审计
- **前端**：search.html（意图徽章/置信度/结果卡/动作按钮/五快捷场景）

### P1（1402d1b）
- **R2 权益路**：会员模型结构化查询——会员个人化（等级/积分/成长值/
  升级路径/保级进度），游客体系介绍+注册引导（角色×意图二维路由）
- **R4 订单路**：鉴权联动——未登录只给登录引导（不查任何订单数据）；
  登录后 get_my_orders 本人隔离，最近 2 单挂智运最新轨迹摘要；
  三轮起支持订单号/运单号精确查单（非本人单不放行细节）
- **显式反馈进化**：POST feedback（useful/useless）→ routeBoost
  ±0.05 clamp[0.8,1.2]；合规拦截决策永不参与进化（红线）
- query 返回补 decisionId（反馈绑定）；feedbacks 观测面（admin）

### P2（374724a + 8636ea7）
- **LLM 意图兜底**：规则低置信（chat）时单次 LLM 调用同时产出意图+
  改写问句（glm-4-flash，fail-soft 全降级）；采纳受 intentWeight
  进化闸（≥0.6 采纳，<0.6 仅留痕审计）
- **查询改写**：口语→规范问句供知识路 embedding 检索（召回增强）
- **intentWeight 进化**：LLM 兜底决策反馈 ±0.02 clamp[0.4,0.8]
- **隐式转化回流**：POST action-click（动作卡点击 sendBeacon 埋点）
  → routeBoost +0.03 正样本
- **小竹语音接入**：zs.search 指令（"帮我搜/搜一下"句式，置 wine 组
  前防"送礼"截胡）→ 同一意图引擎；ZS_MODE off 播报降级话术
- **智搜看板**：zhisou-dashboard 五区块（模式总览/意图分布条形图/
  进化参数/反馈流/决策留痕），对齐智运看板范式（同源默认+401 汉化）

### P3（b13cdff）
- **混合意图拆分**：一句话多问（"竹奕酒多少钱，顺便看看订单发货了
  吗"）标点分句→独立分类→副意图片段→副路检索标记 subIntent 进融合
- 回答合并：主答+副问摘要；留痕 subIntents
- 护栏：合规整句拦截不绕过；子查询上限 1（总路数 2 防时延放大）

## 七、关键工程决策与教训

1. **Redis 客户端 str 键兼容**（P2 生产 500 事故）：本地内存模式测不到
   decode_responses=True 客户端返回 str——`k.decode()` 三处崩溃；
   修复为 bytes/str 双兼容。教训：双模式存储必须两种模式都测。
2. **Python re 中文边界陷阱**（三轮）：中文也是 `\w`，`\b` 在中文与
   字母间不成立——槽位正则改 lookaround 边界。
3. **NFKC 归一化**（四轮）：全角字母/数字（Ｌ３/ＲＴ１２３）手机输入
   常见，query 入口统一归一。
4. **PowerShell 部署管线**：heredoc 不支持（消息文件化）；嵌套引号
   剥离（验证脚本本地直连生产，不走 ssh 内联 JSON）；git commit
   组合命令首跑静默失败（pre-commit hook stderr 触发 NativeCommandError，
   重跑即成功）。
5. **进化闭环防滥用**：clamp 只防越界不防刷量——同决策同来源只进化
   一次是必要补充。
6. **fail-soft 全链贯彻**：LLM 未配置/节流/超时/返回非法 JSON/纯符号
   输入，全部确定性降级，主链永不因 LLM 故障不可用。
