## 一、运维工具（推荐——service 层直达，无需 token）

### 1.1 命令总表

```bash
# 统计概览（状态分布/在锁金额/累计退还扣除/待结算清单）
docker exec zhuxiang-backend-1 python /app/margin_ops.py stats

# 全量保证金清单（可按状态筛）
docker exec zhuxiang-backend-1 python /app/margin_ops.py list
docker exec zhuxiang-backend-1 python /app/margin_ops.py list locked
docker exec zhuxiang-backend-1 python /app/margin_ops.py list settled

# 查某店保证金（含实时年任务进度 annualPurchasedLive/completionRateLive）
docker exec zhuxiang-backend-1 python /app/margin_ops.py status CS-370102-001

# 到期待结算扫描（dry-run 只查不结算）
docker exec zhuxiang-backend-1 python /app/margin_ops.py due

# 手动结算（幂等——已 settled 直接返回不双退）
docker exec zhuxiang-backend-1 python /app/margin_ops.py settle CS-370102-001 expired
docker exec zhuxiang-backend-1 python /app/margin_ops.py settle CS-370102-001 cancelled
docker exec zhuxiang-backend-1 python /app/margin_ops.py settle CS-370102-001 rejected

# 会员保证金流水（双 type + 汇总对账）
docker exec zhuxiang-backend-1 python /app/margin_ops.py tx 3 10
```

### 1.3 结算 reason 语义

| reason | 场景 | 结算公式 |
|---|---|---|
| expired | 满一年到期（调度器自动/手动补结算） | 退 = 1000 × min(1, 年进货额/50000) |
| cancelled | 中途取消资格（连续3月不达标/管理端取消的漏结算兜底） | 退 = 1000 × min(1, 年进货额/(50000×已运营天数/365)) |
| rejected | 平台驳回（未开业，正常由审核流自动退） | 全额退 1000 |

## 二、HTTP API 速查（需 Bearer JWT；settle 另需 X-Role: admin）

```bash
# 1. 登录取 token（member3=13800000002）
TOKEN=$(curl -s -X POST http://localhost:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"phone":"13800000002","password":"test123456"}' \
  | python3 -c "import json,sys; print(json.load(sys.stdin)['accessToken'])")

# 2. 查店保证金（用户端——店主自查进度）
curl -s -H "Authorization: Bearer $TOKEN" \
  http://localhost:8000/api/citystore/CS-370102-001/margin

# 3. 手动补结算（管理端，幂等）
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H "X-Role: admin" \
  "http://localhost:8000/api/citystore/CS-370102-001/margin/settle?reason=expired"

# 4. 会员钱包流水（含保证金双 type）
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8000/api/wallet/transactions?limit=20"

# 5. 钱包余额（注意字段是 currentBalance）
curl -s -H "Authorization: Bearer $TOKEN" http://localhost:8000/api/wallet/info
```

> 响应结构坑：`wallet/info` 余额字段为 `currentBalance`（非 balance）；`transactions` 列表在响应**顶层** `transactions`（非 data 内）；`auth/login` 的 token 在**顶层** `accessToken`（非 data.accessToken）。

## 四、对账方法（账实核验）

**原则**：margin 记录状态（`margin_ops.py list`）与钱包流水（`margin_ops.py tx`）双向核对。

```bash
# 单会员三步对账:
docker exec zhuxiang-backend-1 python /app/margin_ops.py tx 3 50   # ① 流水: 锁定总额 - 结算总额
docker exec zhuxiang-backend-1 python /app/margin_ops.py list       # ② 在锁记录 amount 总和
# ③ 恒等式: ①(锁定-结算) == ②(在锁总额)——违背则排查流水缺失
```

## 五、异常处置

| 现象 | 排查 | 处置 |
|---|---|---|
| 到期未自动结算 | `due` 查是否在列 → 调度器日志确认运行 | `settle <code> expired` 手动补（幂等安全） |
| 重复结算疑虑 | `tx <uid>` 数 settle 流水笔数 vs margin 状态 | 幂等锁保证不双退；以流水为准 |
| 驳回未退款 | `status <code>` 看 settleReason/settledAt | `settle <code> rejected` 补结算 |
| 取消未结算 | margin 仍 locked 而店已 cancelled | `settle <code> cancelled` 补结算 |
| apply 报余额不足 | `wallet/info`（currentBalance）<1000 | 正确拦截（非故障）；充值后重申 |
| 流水缺 refund | refund=0 属全额扣除（设计行为，无流水） | 看 deductedAmount 留痕 |
