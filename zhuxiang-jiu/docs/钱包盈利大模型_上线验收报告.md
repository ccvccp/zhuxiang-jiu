### 2.3 宪法设计: 全站最宽资金红线豁免面

| 豁免端点 | 权利性质 |

| POST /refund 退款 | 资金权利 |
| POST /deposit/{no}/settle + early-settle | 定期本金取出权 |
| POST /reward/{no}/claim + sign | 奖品领取与签收权 |

  落地路径——单点 AI 提现决策升级为模块级大模型体系

### 5.2 豁免面断言新方法(工程创新)

- 问题: 钱包业务 409(余额不足/状态非法)与门控 409
  状态码相同, 传统 `in (200, 404)` 断言无法区分
- 方案: **门控特征串法**——响应 detail 不含
  "WALLET_MODE" 即未被门控(业务错误可, 模式关闭不可),
  8 豁免端点逐一精确断言
- 价值: 可复用于后续业务错误码与门控码重叠的模块

### 5.3 放行断言适配(测试修正实录)

- shadow/assist 放行断言首版用 POST /open 返回 200+
  walletMode 标记——实际 open 有业务前置(会员档案/
  等级≥L2), 测试虚拟会员返回 404
- 修正: 改用特征串法(无门控特征+非 409)——精确验证
  「未因模式被拒」; walletMode 标记逻辑与小竹同款已实证

## 六、回滚与运维

- **回滚命令**:
  `sed -i 's/^WALLET_MODE=.*/WALLET_MODE=off/' /opt/zhuxiang/.env && docker compose up -d backend`
- **运行时切档**(免容器重建):
  `POST /api/wallet/mode/override {"mode":"shadow"}`
- **护栏暂停恢复**: `POST /api/wallet/mode/resume`(人工留痕)
- **巡检开关**: WALLET_GUARD_AUTO=off 可关(默认 on——
  护栏是保护机制)
- **巡检间隔**: WALLET_GUARD_INTERVAL(默认 3600s, 最小 60s)
- **off 态语义**: 新增盈利入口(开通/充值/消费/转定期/结付/
  发货)409; 资金退出权(提现/取出/退款/领奖/审核链)零影响
