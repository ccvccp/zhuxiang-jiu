## A. 双端一致性(最高优先级)

- [ ] A1 海外与 ECS 的**同名文件**内容标记一致(html 特征串/版本号)
- [ ] A2 海外 Redis 与 ECS 本机 Redis 的**同 key 数据**一致(商品/同盟目录)
      —— 两台是独立库! 改一处不改另一处=必然事故
- [ ] A3 `/api/product/list?page=1&page_size=50` 双端: 商品数一致、无外链图(mchost=0)
- [ ] A4 `images/products/` 文件数双端一致, 抽样图 HTTP 200
- [ ] A5 SPA bundle 字符串补丁双端同改, 且 app.html 引用带新 `?v=`

## B. 缓存与版本

- [ ] B1 改 js/css 后全站 v= 升位(含 45 处无版本号引用的历史教训)
- [ ] B2 图片更新用**新文件名**, 不覆盖同名(无 immutable 但有协商缓存)
- [ ] B3 html 依赖 no-cache 头生效(nginx `location ~ \.html$` 双端都在)

## C. 数据与接口

- [ ] C1 新商品三处齐: 双端 Redis hash(全字段+JSON 嵌套字段合法) + 本地 seed
- [ ] C2 库存独立写 `zhuxiang:inventory:<ID>`, 缺失则前端显示"仅剩 0 瓶"
- [ ] C3 改 Redis 前备份旧值(/tmp 或 C:\tmp8147 下 bak 文件)
- [ ] C4 图片 URL 一律 `/images/` 相对路径(绝对域名在未备案侧必被拦)

## D. 前端渲染

- [ ] D1 SPA 补丁选择器用 `[class*="x"]` 通配(hash 类名会变)
- [ ] D2 覆盖 Taro Image 显示模式: static+transform:none+min-width/height:0+
      width/height:100%+object-fit 整组(仅 object-fit 无效!)
- [ ] D3 MutationObserver 补丁有防重标记(data-hotfix)与 API 失败兜底
- [ ] D4 首页双入口(index/official)功能代码逐行一致(同图/同跳转/同入车)

## E. 部署通道

- [ ] E1 tgz 含目标相对路径前缀, 解压后落位正确(踩过: 图落 dist 根→404)
- [ ] E2 海外脚本走 scp 文件+执行, 不内联 ssh 命令(PS 引号/转义灾难)
- [ ] E3 云助手 InvokeId 用 Send 返回的真实值; 结果只回传 Write-Host
      (python 输出先落文件再回传)
- [ ] E4 AK 走用户级环境变量, 进程未继承时从 User 作用域加载
- [ ] E5 服务器本机 curl 必带 `-H 'Host: <域名>'`(否则默认站点误报 404),
      最终以公网域名为准
