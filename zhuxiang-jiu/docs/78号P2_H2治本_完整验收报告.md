## 一、验收背景与瓶颈定位

### （一）P1 上线后的新瓶颈（[LAT] 四段实测）

P0/P1（TTS 六段治理）收口后，端到端首声账本重算：submit→resp 2231~2837ms 占 ~88% 成为唯一大头，而服务端执行仅 18~85ms——瓶颈在网络非服务端。

### （二）三视角网络分解实证（2026-09-23 16:20）

| 视角 | TCP connect | TLS 增量 | TTFB |
|---|---|---|---|
| 国内客户端 → API POST | **1258ms** | +515ms | **2027ms** |
| 国内客户端 → 静态页 | 253ms | +480ms | 967ms |
| **服务器本机 → API** | 0.2ms | — | **18ms** |

### （三）路径诊断定案

ping 20 次均值 245ms / 丢包 20%；tracert 20 跳实证移动→CMI 国际出口→新加坡普通公网链路。**根因：每次新连接在 20% 丢包链路上 TCP+TLS 握手 ~1.2s 被逐请求重复支付**——语音链一次对话并发多请求（提交 POST + TTS 多块 + 流式 fetch），H1 下各自新开连接，握手成本成倍放大。

## 二、验收项一：站点 HTTP/2 上线

### （一）动作与合规说明

- 生产 nginx 1.30.4 自带 http_v2 模块但站点 `listen 443 ssl` **从未开启**——一行改 `http2 on`（新式指令消除 deprecated 警告），热加载零停机，配置备份 `zxjiu.conf.bak-h2`
- 正式国内 CDN（阿里云 DCDN）强制域名 ICP 备案——未备案态下 H2 是**零成本且免备案合规**的治本路径
- ALPN 协商验证：`h2` ✓（Python ssl 双端 + 浏览器 nextHopProtocol 双确认）

### （二）生产实测对照（[LAT-embed] 真实轮）

| 段 | H1 基线 | H2 实测 | 变化 |
|---|---|---|---|
| vad→submit | 12~26ms | 453~586ms（P50） | 环境波动（非 H2 影响面） |
| **submit→resp** | **2231~2837ms** | **274~393ms** | **-85%** |
| resp→play | 86~104ms | 82~179ms | 持平（缓存/流式路径不变，符合预期） |
| **端到端 total** | 2337~2597ms | **最优 1030ms** | **-56%+，进入 1 秒时代** |
| h2 协议占比 | — | 100% | nextHopProtocol 探测 |

## 三、验收项二：后端→智谱 keep-alive 连接池

### （一）实现要点

- `synthesize`/`synthesize_stream` 每请求新建智谱连接（P1.6 实证 conn_ms 21~103ms 重复支付）——`threading.local` 每池线程复用一条 HTTP/1.1 keep-alive 连接（纯标准库红线内，真 H2 需第三方库不引入，keep-alive 达成同一目标）
- 断连单次重建重试兜底；**正确性红线**：流式生成器半途弃用（前端 abort）→ finally 弃连接（半途连接复用会读残包，`read_done` 标志锁定）
- `conn_ms` 埋点保持"新建才计时"语义

### （二）生产实证

- 同线程 spike 9 连发：`voice78_tts_timing conn_ms=0`（此前 21~103ms 波动）——**握手开销归零**
- 测试 [18] 四用例：同线程两次合成仅建 1 连接 / 断连重建重试成功 / 无 key 零建连 / 流式半途弃用弃连接——78/78 双绿（本地+生产容器），Ruff 零告告警

### （三）部署坑发现与规约升级

`docker compose up -d --build` 出现 COPY 层缓存判定异常（scp 后文件内容已变仍 CACHED，镜像带旧代码启动且无 "Recreated" 输出可辨）——`--no-cache` 重建实证修复。**后端部署规约升级为两步式**：`docker compose build --no-cache backend && docker compose up -d backend`（提交 5596601 留档）。
