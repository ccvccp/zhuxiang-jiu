# 43号·AI智能安全管理模块 P5 展望实施计划 v1.0

> 配套：[43号交付总结 P0-P4 终版](AI智能安全管理模块43_交付总结.md) §八
> 定位：P4 已完成运营成熟化闭环（数据底座/无人值守/外源情报/实况监控）；P5 为**收口与增强**——把"留观的能力"变成"达标的处置"（D5 联动）、把"手动的操作"变成"自动的流程"（情报订阅/告警触达）、把"粗的口径"变成"精的信号"（GeoIP 完整解码）、把"够用的性能"变成"可扩展的性能"（CIDR 二分检索）。
> 调研结论（2026-09-03）：D5 观测端点已具备三条件硬标准输出，只差执行开关；消息模块已有 `CATEGORY_SECURITY` 分类与站内信渠道可直接复用；`security_scheduler` 调度范式可承载情报周度拉取与 Redis 日度体检；`geoip_service.lookup_geo` 当前仅返回命中标记（数据段解码器待建）；`match_threatintel` 线性扫描在 2k 段（firehol_level1）无压力，聚合多源（>10k）需二分检索。

|------|------|---------|------|------|-----------|
| P5-1 | D5 强制联动收口 | 检测能力→处置能力（数据达标后） | P4-1 D5 观测端点（已交付）+ observe 满 2 周数据 | 低（开关+处置联动） | ★★★ 先行（数据达标即启） |

## 二、P5-1：D5 强制联动收口（数据达标后）

### 现状与差距
- D5 跳步检测当前**仅降分不处置**（observe 口径）：命中 → identity_risk 降 20，参与六因子合议但不触发独立处置档。
- P4-1 已交付 `GET /admin/reports/d5` 观测端点，三条件硬标准（观察期 ≥14 天 + D5 相关误报率 <5% + 样本 ≥20）已自动输出"建议"，但**没有执行开关消费这个建议**。

### 实施方案

**① 执行开关（环境变量，默认 off）**：
```
SECURITY_D5_ENFORCE=off        # on = D5 命中参与处置联动
```
- off：行为与当前完全一致（零影响回归保障）
- on：D5 命中且威胁分处于 challenge 边界区间（25-50）→ 升档为 challenge（**不 block**——D5 是行为信号非确定性攻击，封禁过重）

**② 联动口径（保守设计，防误杀）**：
```python
# security_service._do_process 处置决策前:
if d5_hit and SECURITY_D5_ENFORCE == "on":
    if 25 <= threat_score < 50:   # 仅挑战边界区升档
        action = max(action, "challenge")   # 不越过 challenge
```
- 单一 D5 命中**永不单独触发 block**；与硬规则叠加时按硬规则既有口径
- 事件留痕新增因子明细 `d5_enforce`（与降分留痕区分，便于后续单独统计误报）

**③ 达标检查流程（人工决策，不自动开启）**：
- 周度查看 `GET /admin/reports/d5` → 三条件齐备（`recommendation: "ready"`）
- 管理员改环境变量 + docker compose 重启生效
- 开启后 7 天内日报端点复核 D5 相关误报率（回落 >5% 即回退 off）

**④ 日报端点小扩展**：`d5_observation` 增加 `enforceActive` 字段（读环境变量实况），面板⑦区 D5 卡显示当前联动状态（off/达标未启/已启用+天数）。

### 测试与验收
- 专项：off 零影响回归 / on 边界区升档 challenge / 高分区不越级 / 低分区（<25）不因 D5 单独处置 / 与硬规则叠加口径 / 因子留痕区分
- 实机：容器 env 注入 on → 制造 D5 命中 → 事件处置档为 challenge → 回退 off 恢复

### 关键风险
- D5 误报率反弹 → 7 天复核机制 + off 一键回退（与网关总开关同级保险）
- 边界区口径争议（25-50）→ 上线后按日报数据微调（阈值进环境变量 `SECURITY_D5_ENFORCE_BAND`，默认 25-50）

## 三、P5-2：Redis 告警接入消息通道

### 现状与差距
- P4-4 Redis 体检告警（大 key/rate 泄漏/内存水位/碎片率）仅**面板手动体检时可见**——无人主动查看则告警等于不存在。
- 消息模块已具备：`send_message(user_id, channel, title, content, category=CATEGORY_SECURITY)` 站内信渠道、消息模板、订阅管理——**43号尚未接入**。

### 实施方案

**① 告警发送服务**（新建 `services/security_alert_service.py`）：
```python
class SecurityAlertService:
    async def notify_redis_alerts(self) -> dict:
        # 1. 调 RedisHealthService().collect() 取 alerts
        # 2. 无告警直接返回(不骚扰)
        # 3. 有告警 → 逐条 send_message(admin_ids, CHANNEL_INMAIL,
        #    title="[安全运维] Redis 体检告警", content=规则+消息+处置建议,
        #    category=CATEGORY_SECURITY, priority=PRIORITY_P1)
```

**② 管理员触达口径**：
- 接收人：会员表中 `role=admin` 的全部会员（复用 auth 模块角色字段，运行时查询）
- **去重节流**：同规则告警 24h 内不重复发送（Redis SETNX TTL 86400，键 `security43:alert:{rule_hash}`）——防每日体检重复轰炸

**③ 触发时机（双轨）**：
- **定时轨**：挂入 `security_scheduler`（P4-2 范式）——`SECURITY_AUTO_MAINTAIN` 开启时，基线重建后顺带执行日度 Redis 体检+告警发送（**体检结果与告警分离**：体检留痕入统计，仅告警触发时发消息）
- **手动轨**：新增端点 `POST /admin/redis/alert/test`（admin 鉴权）——立即体检并发送一次（用于验证通道与演练）

**④ 面板⑦区联动**：体检按钮渲染告警时，追加"发送站内信"按钮（一键触达，复用手动轨端点）。

### 测试与验收
- 专项：告警触发发送 / 无告警不发送 / 同规则 24h 去重 / 管理员列表查询 / P1 优先级落库 / 调度轨集成
- 实机：制造大 key → 手动轨端点 → 管理员站内信收件箱可见 CATEGORY_SECURITY 消息 → 24h 内重复触发被去重

### 关键风险
- 管理员收件箱轰炸 → 24h 去重 + 仅 P1 告警发送（info 级碎片率提示不发消息，仅面板可见）
- collect() 执行开销（KEYS/SLOWLOG）→ 日度频次足够低，且仅调度器开启时自动跑

## 四、P5-3：威胁情报自动订阅

### 现状与差距
- P4-3 威胁情报导入为 `POST /admin/threatintel/import` **手动上传**——计划文档明确"建议周度手动导入（文件下载也需外网），自动订阅留 P5"。
- 源地址公开稳定：`https://raw.githubusercontent.com/firehol/blocklist/master/firehol_level1.netset`（约 2k 段，CC0）。

### 实施方案

**① 订阅客户端**（新建 `services/threatintel_feed.py`）：
```python

    # httpx.AsyncClient 拉取(项目已有 httpx 依赖)
    # 校验: HTTP 200 + 内容首行含 # 或行数 > 100 + 大小上限 10MB

```

**② 调度集成**（挂入 security_scheduler，P4-2 范式）：
```

SECURITY_THREATINTEL_URL=https://raw.githubusercontent.com/.../firehol_level1.netset
```

### 测试与验收
- 专项：拉取校验（非 200 拒绝/空内容拒绝/超大拒绝）/ 失败不清旧段 / 幂等替换导入 / 调度周期触发 / 统计留痕
- 实机：容器内手动触发单轮拉取（真实 GitHub 源，若外网受限用本地 http.server 模拟源验证全链路）→ 导入成功 → CIDR 命中联动生效

### 关键风险
- GitHub raw 外网可达性（国内环境）→ fail-soft 旧段保留 + 手动端点兜底 + URL 可配（可换镜像源如 ghproxy）
- netset 内容突变（超大/格式变化）→ 大小上限+首行校验+行数下限三重防护

## 五、P5-4：AbuseIPDB 实时查询（单 IP 情报）

### 现状与差距
- P4-3 为**段级静态情报**（Firehol netset）——单个 IP 不在已知恶意段时无实时评分能力。
- AbuseIPDB 免费档：1000 次/天，需注册 API key（`https://api.abuseipdb.com/api/v2/check`，confidenceScore 0-100）。

### 实施方案

**① 客户端（三态，captcha_client 范式平移）**（新建 `services/abuseipdb_client.py`）：
```
SECURITY_ABUSEIPDB_MODE=mock_fallback   # mock / real / mock_fallback
SECURITY_ABUSEIPDB_KEY=                 # real 态必填
```
- mock：确定性分数（IP 末段哈希→0/25/85 三档，可测试）
- real：`GET /api/v2/check?ip={ip}&maxAgeInDays=30`，Bearer key，httpx 重试 2 次
- mock_fallback：real 失败/超配额 → 回退 mock 口径（fail-soft）

**② 配额护栏（免费 1000/天红线）**：
- 本地日计数器（Redis INCR + TTL 到当日 24:00，键 `security43:abuseipdb:quota:{date}`）
- 阈值 900（预留 100 手动余量）→ 超限直接走 fallback，日切重置

**③ 结果缓存（省配额核心）**：
- 查询结果落 Redis：键 `security43:abuseipdb:result:{ip}`，TTL 86400（当日重复 IP 零消耗）
- 命中缓存 → 直接用；未命中且配额足 → 查询+写缓存

**④ 信誉联动（复用 P4-3 降档口径）**：
- confidenceScore ≥75 → 降档至 31（suspicious，不直封——与 Firehol 命中同口径，申诉兜底）
- 25-75 → 轻度扣分 -10（事件留痕 `abuseipdb_low`）
- <25 → 零影响
- 联动挂载点：`apply_to_reputation` 扩展（Firehol 段命中优先，未命中再查 AbuseIPDB——**两级串联，段级免费先行省配额**）

**⑤ 端点（1 个）**：`GET /admin/threatintel/abuseipdb/check?ip=`（实时查询+缓存+配额余量返回，admin 鉴权）

### 测试与验收
- 专项：mock 三档分数 / 配额超限 fallback / 缓存命中不耗配额 / TTL 过期重查 / 降档口径与事件留痕 / real 态无 key 拒启
- 实机：mock 轨全链路（查询→缓存→降档→留痕）；real 轨待 key 后冒烟（与极验同口径：mock 全绿即交付，real 配置即用）

### 关键风险
- 外部 key 获取（注册免费账号）→ 三态设计 mock 轨先行交付
- 配额烧尽 → 900 阈值+缓存+段级前置三重节省（正常流量：段级已过滤大恶意段，单 IP 查询集中于可疑未命中者）

## 六、P5-5：GeoLite2 完整解码（城市/经纬度）

### 现状与差距
- `geoip_service.lookup_geo` 当前仅二分检索到**命中标记**（`{ip, resolved: True}`）——城市名/经纬度需数据段解码器，未实现。
- 异地跳变（geo_velocity_signal）当前口径为"滚动窗口内出现**不同可定位 IP**"——无法区分"换了同城宽带"与"跨国跳变"，精度受限（注释已预留 `_geo_distance_km` 扩展位）。

### 实施方案

**① MMDB 数据段解码器（纯 stdlib，零外部依赖延续）**：
```
数据段类型(control byte + extended type):
  1=pointer / 2=utf8-string / 3=double / 4=bytes
  5=uint16 / 6=uint32 / 11=uint64 / 12=int32
  13=map / 14=array
解码输出: {country_iso, country_name, city_name,
           latitude, longitude}
```
- 解码 `lookup_geo` 返回结构扩展（保持 `resolved` 字段向后兼容）
- 惰性解析：命中检索偏移后再解码（未命中零解码开销）

**② 地理距离信号（替换粗口径）**：
```python
def _geo_distance_km(a: dict, b: dict) -> float | None:
    # haversine 公式(纯数学, 无依赖)
# geo_velocity_signal 升级:
#   窗口内最近一次定位 vs 当前:
#     距离 >500km 且间隔 <2h → 异地跳变信号(原口径保留为退化路径)
#     500km 阈值进环境变量 SECURITY_GEO_VELOCITY_KM
```
- 解码失败/无经纬度 → 回退现"不同 IP"口径（fail-soft，零依赖当前行为的回归保障）

**③ 事件留痕增强**：geo_velocity 命中事件的 factors 明细含 `{from_city} → {to_city} {distance}km`（面板因子展开可读）。

**④ 面板展示**（可选轻量）：管理面板 IP 处置表新增"归属地"列（`lookup_geo` 单次调用，仅列表渲染时取，不进网关热路径）。

### 测试与验收
- 专项：类型解码矩阵（string/double/uint/map/array/pointer 全类型单测）/ 命中返回完整字段 / 未命中零解码 / 距离计算（北京-上海 ~1068km 容差断言）/ 阈值跳变触发 / 无库静默关闭回归
- 实机：`./data/GeoLite2-City.mmdb` 就位后（外部资产待办）→ 公网 IP 查询返回真实城市/经纬度 → 距离跳变 E2E；无库路径零影响

### 关键风险
- mmdb 数据段格式复杂度（指针压缩/变长编码）→ 对照官方 spec 逐类型单测；解码异常全局兜底（try/except 回退命中标记口径）
- GeoLite2 需 MaxMind 账号下载（外部资产待办，与 P0-P3 既有待办合并）→ 解码器先行交付，mmdb 就位即启用

## 七、P5-6：CIDR 二分检索（规模化性能优化）

### 现状与差距
- `match_threatintel` 为线性扫描（ipaddress 库逐段构造网络对象）——2k 段（firehol_level1）单次匹配可接受，但：
  - P5-3 自动订阅稳定后若聚合多源（firehol_level2+ ~20k 段 / aggregated ~180k 段），线性扫描每请求 O(n) 不可接受
  - 计划文档既定："段数少，线性匹配可接受；>10k 段时改前缀树"

### 实施方案

**① 方案选择——区间二分（替代前缀树，更简单可靠）**：
```python
# 导入时预计算: CIDR → (start_int, end_int) 有序区间表
# 查询时: IP → int, bisect_right(starts, ip_int) 取左邻区间
#         判断 start <= ip_int <= end → 命中
# O(n log n) 构建(导入时一次性) + O(log n) 查询
```
- 比前缀树实现简单（标准库 bisect，无自定义节点结构）、内存紧凑（两个 int 列表）、覆盖 v4/v6（v6 用 128 位 int）

**② 缓存构建与失效**：
- 内存缓存：`_range_cache = (version, intervals)` 模块级单例
- 失效口径：import_netset / clear_threatintel 后 version+1（下次查询惰性重建）
- 双模式通用：asyncio 内存模式与 Redis 模式共用同一缓存（缓存是纯计算产物，与存储无关）

**③ 触发阈值（不做无效优化）**：
- 段数 <1000 → 保持线性（省构建成本）
- 段数 ≥1000 → 自动切换二分（对调用方透明，`match_threatintel` 内部分流）

### 测试与验收
- 专项：构建正确性（随机 IP 与线性扫描结果全量对比，1000 组断言）/ v4+v6 混合 / 缓存失效重建 / 阈值分流（999 线性/1000 二分，行为一致）/ 边界（段首/段尾/段外±1）
- 性能基准：20k 段 + 10k 次随机查询 < 200ms（线性对照 >10s，量化收益写交付文档）
- 实机：大 netset 导入（生成 20k 测试段）→ 命中查询正确 + 响应时间可接受

### 关键风险
- 区间表内存（180k 段 × 2×int ≈ 3MB）→ 可接受；超大规模（>1M 段）再评估磁盘 mmap
- 导入并发重建竞态 → asyncio 单线程模型天然免疫；version 戳防陈旧缓存
