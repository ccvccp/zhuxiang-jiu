## 一、模块概览

### 1.1 定位

43号把"攻击面"管完, 44号把"**消费面**"管好——对内 API 资产有台账、接入有钥匙、
用量有规则、健康有评分; 对外消费方有自助门户、有公开目录、有在线调试;
AI 全程建议型(评分/推荐/归因), 处置权留给 43号与人工——**职责边界即安全边界**。

### 1.2 三大理念落法

| 理念 | 落法 |
|------|------|
| 遵循规则 | 一切治理动作有据: 套餐配额/流控阈值/生命周期状态机/审批留痕, 可配置可审计 |
| 方便快捷 | 会员自助申请 Key(默认自动批秒发)/try-out 在线调试/文档即得(自发现) |
| 智能自主 | 异常自检(基线偏离)→ 建议自提(配额推荐)→ 学习自愈(裁决回流调权重) |

### 1.3 平台参照

| 平台 | 借鉴点 |
|------|--------|
| Kong/Apigee | 路由自发现台账 / 开发者门户+套餐+配额 |
| AWS API Gateway | usage plan + throttling 分层, 日配额+QPS 双限, 429 标准语义 |
| Postman AI / Datadog Watchdog | NL 检索 API / 智能异常说明 |
| 本仓创新 | 第27档案 API 健康五因子 + 异常裁决真值 Hedge 回流 + per-API 流量基线 |

## 三、各期交付明细

### P0 · API 资产中心(★★★ 先行)

- **路由自发现**: 扫描 FastAPI `app.routes`(只收 APIRoute, 跳过 Mount/静态//metrics),
  `method|path` 自然键 upsert 幂等; 消失路由标 missing 不删除(零不可逆)
- **module 归属推导**: 路由 tags 首个优先 → 无 tags 文件走静态映射表
  (invoice/ride/main 三文件) → 兜底 uncategorized
- **人工修正**: PATCH module(P1 起 source=manual 不被重扫覆盖)/status(生命周期字段)
- **diff 留痕**: 每次 sync 返回新增/消失/module 修正数(供 P3 变更频率因子与
  P5 弃用预警消费)

### P1 · 开发者凭证(方便快捷核心)

- **Key 模型**: `zk_` 前缀 32 hex 明文仅签发时返回一次, 存储 SHA-256 摘要 +
  前 8 位展示位; `ac_` 前缀 appCode(应用标识, 明文可回显)
- **自助生命周期**: 申请(默认自动批 active 秒发, `API_KEY_AUTO_APPROVE=off`
  转 pending 人工批)/每会员上限 5 把(吊销腾位)/自助吊销/续期(90 天延展)/懒过期
- **双头鉴权网关**: `ApiKeyMiddleware` 纯 ASGI, 默认 `API_MANAGER_MODE=off`
  全直通; 开启后仅拦截 Key 面(台账 published 集 + `{param}` 模板匹配):
  无双头 401 / 校验失败 401 / 通过则移除伪造身份头 + 注入 memberId + 用量留痕
- **安全口径**: Key 校验缓存 60s(吊销秒级失效), fail-open 铁律(基础设施异常放行留痕)

### P2 · 流量治理(遵循规则核心)

- **套餐三档**: free(5 QPS/1000 日)/basic(20/1万)/pro(100/10万);
  per-Key customQps/customDaily 白名单式覆盖(上限 1万 QPS/1000万日)
- **双限执行序**: 套餐/覆盖 → QPS 固定窗口(Redis INCR+EXPIRE 2s 窗) →
  日配额(INCR+EXPIRE 至次日 UTC 零点); QPS 拒绝不消耗日配额(nginx 同口径)
- **429 标准语义**: Retry-After 头 + JSON body 含 retryAfter(秒)
- **管理端**: 套餐视图(各档在用 Key 数)/限值调参(留痕即时生效)

### P3 · 调用观测 + 健康评分(第27档案)

- **观测管道**: 中间件 fire-and-forget 异步留痕(Redis `api44:stat/err/lat`
  按日分桶, 不阻塞响应); `load_usage_window` 单日窗口读取
- **三视图**: per-API(调用量/错误率/avg/max 延迟/消费方数)/
  per-Key Top/配额命中率(贴顶 ⚠ 提示)
- **第27档案 ApiHealthScorer**(五因子, 权重和=1.0):
  成功率 0.30 / P95 延迟达标 0.25 / 流量稳定度 0.15 / 配额健康 0.15 /
  变更频率 0.15 → 0-100 分四档 healthy(≥75)/watch/strained/critical
- **P95 近似口径**: avg/max 累计桶保守折算(sum×0.95+max 上界), 口径明示

### P4 · AI 智能自治

- **基线三检测器**(UEBA 范式平移, per-API 模板近 7 日 μ/σ, ≥3 样本天):
  尖刺(>μ+3σ 且 μ≥5)/骤降(<μ-3σ 且绝对量≥20 防冷启动误报)/
  错误激增(错误率环比×3 且样本≥20 硬阈值)——只记录不处置
- **事件队列**: `template|kind|day` 自然键幂等落库, pending → 人工裁决
- **智能配额推荐**(确定性规则, 非 LLM): 近 7 日 P95×1.3 → 推荐档位,
  贴顶升档/低利用降档建议
- **NL 助手三态**(41/42号范式): mock(确定性模板, 数字永远来自查询层)/
  real(LLM 润色, 失败回退 mock); 意图路由: 延迟/Top/我的用量/搜索/帮助兜底

### P5 · 治理闭环(压轴)

- **裁决真值回流**: `ApiLearningService` 三连(collect/run/status);
  confirmed=检测对(+0.5)/false_positive=误报(-0.5) → Hedge 第27档案权重调优;
  eventFed 幂等防重复回流; 因子合成带 contribution(影响度归一必需)
- **生命周期状态机**(转换人工触发, 台账留痕):
  - 主链 development→published→deprecated→offline + 回退/重启, 非法转换 409
  - deprecated: Key 面响应注入 `X-Api-Deprecated: true` + deprecatedAt 留痕
    + 30 天日落窗口(目录倒计时)
  - offline: Key 面直接 `410 Gone`(响应附目录迁移指引)
  - 下线软护栏: 近 7 日 Key 面调用量>0 阻断 409(可 force=true 强制, 留痕)
- **Key 面语义升级**: published 索引 = published+deprecated+offline
  (development 不拦截), 中间件缓存条目携带 status, 转换即时生效
- **对外目录**: `GET /apis/catalog` 无鉴权——published 自助文档 +
  deprecated 带日落迁移预警; offline/development 不展示
- **try-out 在线调试**: 面板填 Key 双头直调, X-Api-Deprecated/410/
  Retry-After 可实测

## 六、中间件架构

```
请求 ─▶ CORS ─▶ SecurityGateway(43号, 威胁评分全覆盖)
              ─▶ ApiKeyMiddleware(44号, 默认 off)
                    │ off → 直通(零影响铁律)
                    │ on + 非 Key 面 → 直通(JWT/游客流程接管)
                    │ on + Key 面: 双头校验(401) → 双限(429)
                    │   → 身份注入 + 弃用预警头/410 生命周期强制
                    ─▶ JWTAuthMiddleware ─▶ 业务路由
                          └─ 异步留痕(fire-and-forget) → Redis 观测桶
```

关键口径:
- **fail-open 铁律**: 校验/流控基础设施异常 → 放行+留痕(治理不阻断业务)
- **观测不阻塞**: send 包装捕获状态码/延迟, 响应完成后异步留痕
- **缓存**: Key 校验 60s(吊销秒级失效跨 worker 60s 收敛)/Key 面集 60s
  (状态转换主动失效)
- **生命周期强制点**: offline 在观测包装前短路返回 410; deprecated 在
  http.response.start 追加预警头(业务路由零感知)

## 十、执行中发现并修复的缺陷

| # | 阶段 | 缺陷 | 修复 |
|---|------|------|------|
| 1 | P5 | detect() 重复检测把已裁决事件重置回 pending(裁决真值失守, 学习闭环污染隐患) | 落库前存在性检查, 已裁决不覆盖 |
| 2 | P5 | detect() 响应事件缺 eventId(P4 面板裁决按钮渲染失效) | _save_event 回填 eventId |
| 3 | P5 | 前端 decideAnomaly 缺 Content-Type 致 422(存量按钮不可用) | 补请求头(lifecycleAction 同口径) |

**经验教训**: 幂等断言只查条数不查内容是不够的——状态保护需要显式断言;
按钮交互类缺陷唯有实机点击才能暴露。
