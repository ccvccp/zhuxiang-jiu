## 二、升级交付

### 2.1 模式层(credit_mode_service.py)

- **三态**: CREDIT_MODE = off(默认)/shadow(信用观察期)/
  assist(信用辅助期)
- **读取链**: 护栏暂停 > 运行时 override > env > 默认 off
- **状态存储**: `zhuxiang:credit:mode_state` 整档 JSON 单键
- **同步桥接**(62号范式): 进程快照 `_G` +
  `legacy_current_mode()`

### 2.2 护栏三指标(信用业务语义, 恶化>3% 自动 guard_pause)

| 指标 | 基线 | 语义 |
|---|---|---|
| 逾期还款率 overdueRepayRate | 0.10 | overdue/(repaid+overdue) 终态订单(信用履约恶化代理) |
| paylater 拒单率 paylaterRejectRate | 0.10 | rejected/总订单(先用后付风控压力代理) |
| 黑名单占比 blacklistRate | 0.05 | blacklist 账户/总账户(信用恶化面代理) |

### 2.3 路由层(credit_routes.py, 21→25 端点)

- **8 决策端点** `@_decision` 门控(off 409 + creditMode 标记):
  adjust/upgrade/downgrade/blacklist/restore(管理 5)+
  paylater order(下单, strict)+paylater review(审批)+
  quarterly settle(结算)
- **鉴权优先**(小竹/钱包参数化范式零改动复用):
  401/403 优先于 409
- **4 控制面端点**: GET /mode、POST /mode/override、
  POST /mode/guard(缺省仓储实时聚合)、POST /mode/resume

### 2.4 宪法豁免面(履约与兑换权——永不关停)

| 端点 | 权利 |
|---|---|
| POST /paylater/repay | 还款履约权——已生效订单的偿还义务永远可以履行 |
| POST /exchange | 积分兑换权——既得信用积分的权益兑换不可设障 |

观测面 11 GET 永不关停(list/stats/report/quota/score/
level evaluation/exchange recommend+catalog/quarterly/
exchanges/paylater orders)。

红线: 一代 credit_scoring 评分器(batch25)与 enforce 决策门
语义保留; L1-L4 硬规则(L2 才能用 B 额度等)不受 mode 影响。

### 2.5 护栏自动巡检(credit_scheduler.py)

- `run_guard_patrol()` 三指标确定性聚合(list_scores 全量+
  逐户 list_paylater_orders 状态聚合, 上限保护)
- CREDIT_GUARD_AUTO 默认 on, 间隔 3600s; main.py 挂载

## 五、回滚与运维

- **回滚命令**:
  `sed -i 's/^CREDIT_MODE=.*/CREDIT_MODE=off/' /opt/zhuxiang/.env && docker compose up -d backend`
- **运行时切档**: `POST /api/credit/mode/override`
- **护栏恢复**: `POST /api/credit/mode/resume`
- **巡检**: CREDIT_GUARD_AUTO(默认 on)/
  CREDIT_GUARD_INTERVAL(默认 3600s)
- off 态语义: 管理与先用后付入口(调整/升降级/黑名单/恢复/
  下单/审批/结算)409; 还款履约与积分兑换零影响
