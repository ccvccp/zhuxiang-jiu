## 一、模块概览

### 1.1 定位与核心命题

35号 AI Hub 解决的是"能力路由"(哪个模型/工具接哪个
请求), 但会员的真实交互是连续对话: "小竹, 看新品——这个
多少钱——把 100 信用分换成信值"。零散的 API 无法承载
这样的语境。48号的答案: **四层纵向中枢**(感知层听见 →
认知层听懂 → 执行层办成 → 进化层学好)+ **一条铁律**
(语音只是可选入口, 不用语音不受任何损失——反语音霸权)。

### 1.2 三大理念落法

| 理念 | 落法 |
|------|------|
| 遵循规则 | 高敏不可纯语音(confirmToken 屏幕码); 指令白名单三级沙箱; PII 脱敏+一键清除; 积分独立账本入信值走 45号 deposit 验真 |
| 方便快捷 | 唤醒一次 5 分钟免唤醒; 指代消解连续对话; 12 指令直达卡片+jump; 文本/语音同链(键盘兜底/无障碍) |
| 智能自主 | 失败聚类反哺指令集; 共创短语众包上架; 公平性采样防语音层歧视; 主动关怀(默认 off) |

### 1.3 平台参照与本仓创新

| 参照 | 借鉴点 |
|------|--------|
| 35号 AI Hub | ASR 链路与降级、意图规则轨、浮层组件范式 |
| 41/42号 | LLM 三态(增强/降级/关闭)默认 off |
| 45号 | deposit/convert 通道(积分入信值唯一通道) |
| 46号 | 公平性采样维度、看板 fail-soft 分区、审批流 |
| 47号 | 画像 tier(角色感知数据源)、关怀候选名单 |
| 44号 | confirmToken 一次性语义(Key 发放同款) |
| **本仓创新** | **免唤醒窗+指代消解连续对话**、**confirmToken 屏幕码流**(语音念码不算)、**共创指令白名单审核流**(短语众包但不新建执行器)、**失败案例三分类聚类**(兜底/重复/负反馈→指令集缺口清单)、**语音直达率 member_level 公平性桥接**(防语音层歧视) |

### 1.4 一句话内核

> **语音是嘴, 中枢是脑——听见(唤醒)→听懂(认知)→办成
> (执行)→学好(进化), 但永远替会员留着键盘与页面: 嘴快
> 不是特权, 高危必须伸手。**

## 三、各期交付明细

### 3.1 P0 感知层·语音会话中枢

- **会话/轮次仓储**(voice48_sessions/turns, 双模式): 会话
  channelId 归属 memberId; 轮次 seq 正序; 清除级联(隐私红线)
- **唤醒判定**: "小竹"前缀+近似音容错(xiaozhu/小主/小朱);
  5 分钟活跃窗免唤醒(前提: 会话中已发生过至少一次唤醒——
  新会话不因刚开启而免唤醒)
- **指代消解**: "这个多少钱"承接上轮商品语境
- **八指令直达**: 看新品/问价格/查信值/查余额/打开购物车/
  转人工/你能干什么/查优惠(卡片+jump)
- **PII 红线**: 手机号/身份证 mask 落库; 音频即转即删
  (只落 audioMeta 元信息)
- **前端浮层**: js/xiaozhu-widget.js(35号浮层范式, 竹绿主题)

### 3.2 P1 认知层·角色感知大脑

- **绑定表**(voice48_bindings): 会员↔信值档案两套 ID 体系
  衔接; 重复绑定=改绑; 快捷指令"绑定信值档案 N"
- **角色上下文注入**: 等级称号/偏好标签(历史订单类目 top3)/
  47号画像 tier(经 bindings, watched/restricted 推荐降敏)
- **信值指令升级**: "查信值"直读 45号档案;"信值余额"直读
  balance;"能换吗"换算(汇率来自 45号 API, LLM 不产数字)
- **LLM 意图轨**: XIAOZHU_LLM_MODE 显式开关, 默认 off——
  规则轨 track=rule 兜底

### 3.3 P2 执行层·安全业务代理

- **沙箱白名单三级**: 只读(12 action 直达)/一般写
  (cart.submit→45号 checkout)/高敏(trust.convert→
  confirmToken 流); 白名单外 ValueError 拒绝
- **confirmToken 屏幕码流**: 令牌 TTL 120s+4 位数字码;
  codeHint 只泄首位; 码错 3 次作废; **语音念码不算——
  高敏不可纯语音红线**
- **幂等/冷静期**: 同会话同 action+对象 10s 窗去重;
  10 分钟 ≥3 次高敏确认→冷静期提示改页面
- **澄清反问**: 参数槽位缺失追问而非猜测("想把多少信用分
  换成信值?")
- **执行留痕**: "我刚才做了什么"轮次回溯

### 3.4 P3 进化层·交互驱动双优化

- **语音积分账本**(voice48_points/points_acc): 指令完成 +2/
  共创采纳 +100; **独立账本不直改信值**——兑换走 45号
  deposit 验真通道(verified 后扣减; 未绑定/不足额 409)
- **失败案例挖掘**(voice48_failures): fallback/repeat/negative
  三分类; 管理端聚类 topPhrases→建议新增指令 pattern
- **共创指令**(voice48_custom_cmds): 短语→白名单 action 映射;
  pending→approved/rejected 审核流; 上架全局生效(track=
  custom); 贡献者 +100; **不能新建执行器**(安全边界)
- **主动关怀**(voice48_proactive): 47号 watched/restricted 档+
  45号修复窗口×活跃时段; 7 天/人/类型间隔+日上限;
  **默认 off**(XIAOZHU_PROACTIVE_MODE)
- **反语音霸权计分口径**: 只对完成行为计分; 澄清/未唤醒
  轮次零分

### 3.5 P4 语音中枢看板与收官

- **六区块 fail-soft 看板**(GET /api/xiaozhu/dashboard, 单次
  GET 零拼装, 单区块异常不阻断):
  - ①使用总览: 会话量/指令量/直达率/(指令+兜底)/语音 vs
    文本比——意图质量北斗星
  - ②指令命中: action 排行+兜底率(兜底率高=指令集缺覆盖)
  - ③高敏台账: issued/confirmed/wrongCode/expired/cooldown/
    duplicate/通过率(executor 进程级计数, 重启归零)
  - ④积分账本: 发放/兑换/余额/持分/kind 分解
  - ⑤共创队列: pending 待审+失败聚类 topPhrases
  - ⑥治理桥接: member_level 直达率分组预览
- **仓储聚合扫描**: scan_sessions/scan_turns(跨会话全表只读)/
  points_balances_total(双模式合计)
- **executor 台账计数**: 六类事件点埋点+stats() 只读快照
- **公平性桥接**(POST /api/xiaozhu/dashboard/fairness-bridge):
  专属档案 xiaozhu_voice **side-door upsert 治理台账**(不入
  SCORER_REGISTRY——46号 28 档案断言零改动红线; sync 标
  retired 后桥接自愈回 active)→member_level 聚合直达率→
  46号 submit_samples(group=voice_L{N}, 无个人标识字段;
  等级 <5 轮不上报——防小样本误报)→等级间直达率差异>20%
  由 46号 flagged 提示人工复核(**防语音层歧视**)
- **前端看板**: xiaozhu-dashboard.html + js(47号看板范式:
  apiBase localStorage/adminHeaders/zoneErrors 降级提示/
  共创一键上架驳回/桥接按钮)

## 六、五层引擎架构

```
会员(语音/文本同链)
   │
   ▼
[感知层 P0] 唤醒判定(近似音)→免唤醒窗→PII 脱敏落库
   │
   ▼
[认知层 P1] 绑定表→角色上下文(等级/偏好/47号tier)
   │         →指令路由: 绑定快捷→共创短语→规则轨→LLM轨(off)
   ▼
[执行层 P2] 沙箱白名单三级→只读直达/一般写/高敏 confirmToken
   │         幂等 10s 窗+冷静期+澄清反问+执行留痕
   ▼
[进化层 P3] 积分账本(独立)→deposit 验真兑换
   │         失败挖掘→共创审核→指令集自进化
   ▼
[治理层 P4] 六区块看板→高敏台账→公平性桥接(46号)
             防语音层歧视闭环
```
