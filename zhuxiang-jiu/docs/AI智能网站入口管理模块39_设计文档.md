# 39号·AI智能网站入口管理模块 设计文档 v1.0

> 定位：全站的"门面"——把登录从"安全成本"变成"愉悦体验"。以 **AI 自适应认证** 为核心（低风险无感放行 / 中风险轻量二次 / 高风险拦截），叠加**扫码 / 指纹 / 刷脸**三种便捷登录与**角色化爽人落地页**，实现"进得快、留得住、记得牢"。
>
> 方法论：对标成熟平台（微信扫码登录 / Apple ID 生物识别 / 支付宝刷脸 / 阿里风控自适应认证），叠加本项目既有 AI 基建（auth_risk 评分器接入登录决策链 / hub 意图路由 / ai_learning 自学习），全程遵循 **Mock-first 确定性模拟惯例**（真实生物识别硬件/服务商未接入时走确定性模拟轨，产出不中断）。

---

## 1. 设计目标与核心概念

### 1.1 一句话模型

**"AI 识别风险 → 风险决定认证强度 → 强度匹配最爽快的登录方式 → 登录即达角色专属入口。"**

- 设计原则三词诀：**简洁**（一键/一扫/一触，≤2 步完成）、**安全**（AI 风控在后台，用户无感知）、**易操作**（失败有引导、降级有兜底、任何方式不可用都回落密码）
- 驻留飞轮：登录激励（连续登录成长）+ 注册即归因（click_id 三合一埋点）+ 无感续期（可信设备 30 天免登录）→ 降低入口摩擦 = 提升留存

### 1.2 登录方式矩阵（六通道 + AI 决策）

| 通道 | 摸样 | P0 实现 | 真实化预留 |
|------|------|---------|-----------|
| 密码登录 | 手机号+密码 | 已有（30号 auth） | — |
| 短信登录 | 手机号+验证码 | 已有（60s冷却+日限10次） | 换服务商一行 |
| 扫码登录 | PC 展码 / 手机扫确认 | **QR 令牌轮询协议**（本模块新建） | WebSocket 升级（P2 可选） |
| 指纹登录 | 设备指纹传感器一触 | **WebAuthn 式 Mock 轨**（设备端摘要） | 真实 WebAuthn/ctap（P2） |
| 刷脸登录 | 摄像头人脸一瞥 | **vision 识别 Mock 轨**（glm-4v 判照一致性） | 真实人脸 SDK（资质后） |
| OAuth 三方 | 微信/支付宝/QQ | 已有骨架（openid 模拟派生） | 平台接入换真实换取 |

> **生物特征红线（合规）**：指纹/人脸**原始生物数据永不上送、永不落库**——设备端摘要（WebAuthn 公钥式）+ 服务端只存"绑定关系+摘要哈希"；刷脸走设备本地识别后换取一次性票据，云端只做票据核验（对标 Apple FaceID 模式）。Mock 轨同样遵守此口径。

### 1.3 AI 自适应认证（"AI 智能识别角色登录态"的核心）

复用 30号 `auth_risk` 评分器（8 因子 4 级动作，**已建成未接入**——本模块完成接入闭环）：

```
登录请求 → 采集上下文(设备指纹/IP/时段/失败史/账龄/行为)
        → auth_risk 评分(0-100 风险分)
        → 动作映射:
            <25  allow    → 无感放行(可信设备直发令牌, 零交互)
            <50  step_up  → 轻量二次(短信验证码, 一次性)
            <70  challenge→ 强核验(安全问题/刷脸核身)
            ≥70  block    → 拦截(黑名单IP/泄露密码硬约束直拦)
        → 人工裁决回流 ai_learning(误拦/漏放反馈 → 权重自学习)
```

- **设备指纹（新建，评分器 device_match 因子闭环的关键）**：客户端采集 UA+屏幕+语言+时区等弱特征 → 服务端 hash 为 `deviceId`（不采集持久化隐私标识，对标成熟站点的"常用设备"）
- **可信设备清单**：deviceId+memberId 绑定关系，登录即记；`allow` 级设备可开启 30 天免登录（refresh 滑动续期）；"陌生的设备"自动触发 step_up——这正是成熟平台"常用手机一点就进、新手机要验证码"的体验

### 1.4 与既有模块关系（复用不合并）

| 模块 | 关系 |
|------|------|
| `auth`（30号） | **地基**：JWT 双令牌/jti 黑名单/级联吊销/SMS/OAuth 骨架全部复用；新通道统一走 `_login_by_member_id` 签发；本模块不重建会话体系 |
| `auth_risk` 评分器 | 从"观察模式"升级为"决策模式"（接入登录链）；新增第 21 个可学习档案的反馈回流 |
| `hub`（35号） | 登录成功后的**角色落地页**复用 hub ROLE_PANELS（member/cs_staff/admin 各自 chips 面板，登录即达专属入口） |
| `attract`（11号） | 注册/登录入口统一挂 click_id 归并三合一（lead+promotion 绑定+归因表），引流闭环 |
| `member`（02号） | 旧 mock token 双轨退役口径：新入口只走 JWT；登录 bonus/注册积分账本复用 |
| `perm`（权限） | 可信设备管理/生物凭证绑定等管理端点走 perm 授权 |
| `llm_client` | 刷脸 Mock 轨用 vision() 判照一致性（对齐 38号审图降级惯例：失败回落规则轨） |

## 2. 总体架构：六个子系统

### 2.1 统一入口网关（entry_gateway）

全站唯一登录总入口（前端 login.html 升级为"AI 智能入口页"）：

- **AI 预判面板**：页面加载即调 `GET /api/entry/recognize`（带设备指纹）→ 返回该设备的**推荐登录方式排序**（可信设备 → "指纹一键登录"；历史短信用户 → 短信优先；首次访问 → 密码/扫码并列）——"AI 识别登录态"的门面
- **六通道一页切换**：Tab 化（密码/短信/扫码/指纹/刷脸/OAuth），任一通道失败给出**引导式降级**（扫码超时→提示改密码；指纹不可用→回落短信）
- **登录强度自适应**：提交后由 auth_risk 决定是否 step_up（前端弹轻量二次层，不打断上下文）

### 2.2 扫码登录（qr_login，新建）

无 WebSocket 环境下的**轮询协议**（对标微信开放平台扫码登录）：

```
PC:  POST /api/entry/qr/create → {qrId, qrPayload, expiresIn:180s,
      statusUrl}                    # qrPayload 为可渲染文本(前端canvas)
手机: 已登录态 POST /api/entry/qr/{qrId}/confirm   # 扫码确认(带JWT)
     可选 step_up: 高风险手机端也弹二次确认
PC:  GET /api/entry/qr/{qrId}/status?since=seq 轮询(2s)
     status: pending → scanned(已扫待确认) → confirmed(携带一次性
     loginTicket) → PC 用 ticket 换 JWT 双令牌
```

- 一次性 `loginTicket`（60s TTL）隔离"扫码确认"与"令牌签发"两段，防重放
- 三态轮询带 `seq` 增量，确认瞬间返回（体验≈实时）；Mock 轨另提供 `POST /api/entry/qr/{qrId}/mock-scan` 供单端测试/演示
- 超时/取消/已使用三态终局，幂等

### 2.3 生物凭证中心（bio_credential）

指纹/刷脸统一凭证模型（WebAuthn 式两段协议）：

```
绑定(登录态):  POST /api/entry/bio/enroll  {bioType: fingerprint|face,
               deviceChallenge} → 设备端生成凭证对(公钥式摘要) →
               POST /api/entry/bio/bind {bioType, deviceId, credentialId,
               publicKeyHash}   # 服务端只存摘要, 无原始生物数据
登录:          POST /api/entry/bio/challenge {credentialId} → 一次性
               assertionChallenge(60s) → 设备端本地验证(指纹传感器/
               刷脸) → POST /api/entry/bio/verify {challenge,
               assertionHash} → 验签+风险评分 → allow 则直发令牌
```

- **指纹**：设备端传感器完成本地验证（WebAuthn/平台 API），服务端只核 assertion 摘要 —— Mock 轨：`bioType=fingerprint` 时 assertion 由 challenge+deviceId 确定性派生（测试可复现）
- **刷脸**：两条轨——①设备本地识别（同指纹，主轨）②**云端辅助核验轨**（P1）：自拍帧上传 → `vision()` 判"人脸照+活体提示物"一致性（对齐 38号审图降级：失败回落设备轨）；云端**只存判定报告，不存人脸图**
- 凭证管理：设备列表/改名/吊销（吊销即"忘记这台设备的指纹"）；换机迁移=新设备重新 enroll（凭证不跨设备，安全默认）

### 2.4 AI 风控决策引擎（auth_guard）

auth_risk 评分器接入登录决策链（六个通道统一过闸）：

| 因子（8个，权重自学习） | 数据源（本模块补齐） |
|------|------|
| device_match 0.20 | **设备指纹库**（新建，闭环关键） |
| failed_attempts 0.20 | 登录失败计数（IP+账号双维，10min 窗口） |
| geo_velocity 0.15 | 上次登录 IP 地理差/时间差（IP→城市，内置简表） |
| ip_reputation 0.15 | IP 信誉（clean/proxy/vpn/tor/blacklist，内置简表+可扩展） |
| time_pattern 0.05 / account_age 0.05 / password_strength 0.10 / behavior_deviation 0.10 | 登录上下文 + 账号画像 |

- **决策留痕**：每次登录落 `entry:decisions`（因子快照+动作+结果），可观测可审计
- **反馈回流**：管理员在后台对误拦/漏放标记（`POST /api/entry/decisions/{id}/review`）→ ai_learning 反馈（误拦 allow 实为 block → correct=False）→ Hedge 权重自学习——**登录风控越用越准**
- 降级铁律：评分器异常 → 默认 `step_up`（宁可多一次验证，不可裸放）

### 2.5 角色爽人落地（role_landing）

登录成功的"最后一米"——按角色直达专属入口：

- `member`：会员面板（复用 hub ROLE_PANELS chips：查订单/问价格/我的积分/推荐/酒友小聚/转人工）+ 今日签到入口
- `cs_staff`：客服工单台；`admin`：运营全景（跳各模块看板）；`guest→member 注册即引导`：首登引导三步（领新人积分→浏览主推→加购）
- **登录激励（留存钩）**：连续登录天数徽章（1/7/30 天递进积分奖励，复用积分账本）+ 回访问候语（登录时距上次<24h → "欢迎回来"轻提示；>30 天 → 回归礼包码）
- 落地页配置：`entry:landing_config` 可按角色调 chips/横幅（admin 可运营）

### 2.6 驻留埋点闭环（retention_loop）

入口即埋点，引流可归因：

- **注册即归并**：所有注册通道（密码/短信/OAuth bind/刷脸首绑）统一调 attract `attach_registration`（click_id 三合一：lead+promotion 绑定+归因表）
- **登录事件流水**：`entry:events`（通道类型/耗时/成败/风险分/设备）→ 周报看板（通道转化漏斗：访问→尝试→成功→次日回访）
- **渠道维度**：utm/短链码随入口透传（复用 attract 短码体系），"哪个入口带来的人留得住"可量化

## 3. 数据模型（Redis Key，前缀 `entry:`）

| Key | 类型 | 内容 |
|-----|------|------|
| `entry:qr:{qrId}` | Hash | 扫码会话（status/seq/creatorDevice/confirmMember/loginTicket 哈希/expiredAt） |
| `entry:devices:{memberId}` | Hash(field=deviceId) | 可信设备（deviceName/lastLoginAt/lastIp/riskAvg/trustedUntil） |
| `entry:bio:{credentialId}` | Hash | 生物凭证（memberId/bioType/deviceId/publicKeyHash/status/enrolledAt） |
| `entry:fingerprints:{deviceId}` | String | 设备指纹 → 简档（UA 摘要/首次见/次见） |
| `entry:decisions` | Hash(id) | 风控决策留痕（因子快照/动作/结果/反馈态） |
| `entry:events` | Hash(id) | 登录事件流水（通道/耗时/成败/风险分） |
| `entry:login_streak:{memberId}` | String | 连续登录天数 |
| `entry:landing_config` | Hash | 角色落地页配置 |

双模式存储/锁/异常映射遵循项目全局惯例（`lock:entry:qr:{qrId}` / `lock:entry:bio:{memberId}`）。

## 4. API 设计（routes/entry_routes.py，前缀 `/api/entry`，约 22 端点）

**入口与识别（公开）**
- `GET /api/entry/recognize`（带设备指纹头）→ 推荐登录方式排序 + 设备问候（"欢迎回来"）
- `POST /api/entry/login`（统一登录端点：mode=password\|sms + 风险上下文）→ 直发或返回 step_up 要求
- `POST /api/entry/step-up/verify`（step_up 二次验证完成）→ 令牌签发

**扫码（公开+手机端）**
- `POST /api/entry/qr/create` / `GET /api/entry/qr/{qrId}/status` / `POST /api/entry/qr/{qrId}/confirm`（JWT）/ `POST /api/entry/qr/{qrId}/cancel`
- `POST /api/entry/qr/{qrId}/mock-scan`（Mock 轨演示/测试）

**生物凭证（绑定须登录态）**
- `POST /api/entry/bio/enroll` / `POST /api/entry/bio/bind` / `POST /api/entry/bio/challenge` / `POST /api/entry/bio/verify`（公开，凭 challenge）
- `GET /api/entry/bio/credentials` / `DELETE /api/entry/bio/credentials/{credentialId}`

**设备管理（登录态）**
- `GET /api/entry/devices` / `DELETE /api/entry/devices/{deviceId}` / `POST /api/entry/devices/{deviceId}/trust`（开 30 天免登录）

**风控与埋点（管理端 perm）**
- `GET /api/entry/decisions` / `POST /api/entry/decisions/{id}/review`（反馈回流）
- `GET /api/entry/report/overview`（通道漏斗/风险分布/连登榜）

**落地页**
- `GET /api/entry/landing?role=`（角色面板+激励状态）/ `PUT /api/entry/landing`（admin 配置）

鉴权：公开端点入 auth_middleware 白名单；登录态端点走 JWT 注入；管理端点 perm 授权。

| 能力 | 实现 | 降级 |
|------|------|------|

| 登录意图问候 | 规则轨（时段+回访间隔），LLM 可选 | 规则轨确定性 |

## 6. 合规与红线

- **生物特征最小化**：原始指纹/人脸**永不上送不落库**（设备端摘要+绑定关系）；刷脸云端轨只存判定报告
- **设备指纹弱特征口径**：UA/屏幕/语言/时区可拼装摘要，不采 MAC/IMEI 等持久标识；隐私政策声明+设备可删除
- 风控**不裸放**：评分异常默认 step_up；block 决策必须带因子明细（可申诉）
- 酒类年龄门前置：任何新通道首登（OAuth bind/刷脸首绑）复用注册年龄校验口径
- 改密级联吊销全部设备令牌（30号既有能力，本模块凭证同步失效）

- 登录事件流水 + 注册归并挂接
- 专项测试（协议三态/风控四档/设备绑定/幂等/生物红线）

### P1 生物凭证 + 回流
- 指纹/刷脸两段协议（enroll/bind/challenge/verify，Mock 确定性轨）

- 入口运营看板（通道漏斗/留存归因）+ A/B 落地页配置

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 轮询扫码体验差 | 2s 间隔+seq 增量+确认即返；P2 WebSocket 预留协议兼容 |
| 设备指纹被伪造 | 指纹仅作风险因子非身份凭证；allow 直发仅限已 bind 的可信设备 |
| 生物 Mock 轨被绕过 | Mock 凭证标记 `mode=mock`，`ENTRY_BIO_MODE=strict` 时拒绝 mock 轨登录 |
| 风控误拦伤害体验 | block 须因子明细可申诉；反馈回流自纠偏；白名单设备豁免 |
| 新通道绕过年龄门 | 所有首登通道统一走注册校验（bind_phone 模式复用） |
| 与 member 双轨混乱 | 新入口只签 JWT；mock token 仅存量兼容，文档标注退役口径 |
