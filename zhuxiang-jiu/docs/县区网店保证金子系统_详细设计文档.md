# 县（区）网店保证金子系统——详细设计文档

> 文档版本：v1.0 · 2026-09-19

## 一、业务背景与设计目标

### 1.1 业务规则（用户口径）

县（区）网店（分店定位）取消营业执照/食品卫生许可证平台审核，改为「身份证 + 确认签名 + **保证金预存**」三件申请材料。保证金规则：

1. 申请开店时从**钱包活期余额**预存 **¥1000** 作为保证金
2. 锁定期**一年**（自平台确认开业之日起算）
3. **不可提前取现**（区别于钱包普通定期的可提前取出）
4. 到期按**年度进货任务（¥5 万）完成度**退还：完成 80% 扣 200 退 800；完成 ≥100% 全额退还
5. 未完成年度任务从中扣除（按比例）；中途取消经营资格按已运营期折算目标结算
6. 平台驳回申请（未开业）全额退还

### 1.2 设计目标

- **资金安全**：扣款/退款全部走钱包仓储原语，全程锁保护，幂等防双退
- **语义隔离**：不污染钱包既有 deposit（定期）收益/LPR/奖品语义，不占用 frozenAmount（提现在途语义）
- **红线豁免**：保证金退还属于存量资金退出，WALLET_MODE=off 时必须照常可用
- **自动运营**：到期日按各店开业日全年分布，调度器小时级轮询自动结算，管理端手动兜底

### 1.3 方案裁定（为什么不复用现有结构）

| 候选方案 | 裁定 | 理由 |
|---|---|---|
| 复用 wallet deposit（定期） | ❌ 否决 | deposit 承载 DEPOSIT_TIERS 收益率/LPR 合规降档/奖品阶梯语义；`early_settle_deposit` 全局允许提前取（收益清零+1%手续费），与保证金"不可提前取现"直接矛盾；在 deposit 链路分叉业务类型污染面大 |
| 进 frozenAmount（冻结字段） | ❌ 否决 | frozen 是**提现在途**语义（withdraw 申请即冻结/approve 拒绝解冻），会被提现链路的 reduce_frozen 类操作误伤 |
| **独立保证金实体**（采纳） | ✅ | 新实体 `city_store_margins` 沿用 citystore_repository 双模式范式；资金操作只复用 wallet repo 原语（add_balance/save_transaction/next_tx_no）——**wallet 三件（service/repository/routes）零改动** |

## 三、状态机

```
                 ┌──────────────────────────────────────────┐
                 │                apply 成功                  │
                 │  钱包 add_balance(-1000) + margin 记录    │
                 └──────────────────┬───────────────────────┘
                                    ▼
                        ┌─────────────────────┐
                        │  locked (endDate="") │  ← pending 期无锁定期
                        └──┬──────┬──────┬─────┘
           平台驳回 ────────┘      │      └──────── 确认开业(补 startDate/endDate)
        (rejected)               │                  │ =startDate+365天
               ▼                  │                  ▼
        ┌────────────┐    中途取消资格          ┌──────────────────┐
        │  settled   │  (cancelled, 按elapsed) │ locked(有锁定期) │
        │ 全额退1000  │           │             └────────┬────────┘
        └────────────┘           ▼                      │ 满一年
                          ┌────────────┐  expired       │
                          │  settled   │◄───────────────┘
                          │ 按完成度退   │  rate=min(1, 年进货/5万)
                          └────────────┘  refund=round(1000×rate, 2)
```

**状态转换表**：

| 起点 | 触发 | 终点 | 资金动作 | reason |
|---|---|---|---|---|
| apply 成功 | — | locked（无起止） | 钱包 −1000，流水 `citystore_margin_lock`(OUT) | — |
| locked（无起止） | audit approved=False | settled | 钱包 +1000，流水 `citystore_margin_settle`(IN) | rejected |
| locked（无起止） | audit approved=True | locked（补起止） | 无（仅补写日期） | — |
| locked（有起止） | endDate ≤ today | settled | 钱包 +refund，流水 IN | expired |
| locked（任意） | 状态流转至 cancelled / 考核连续3月不达标 | settled | 钱包 +refund，流水 IN | cancelled |

settled 为终态；重复结算被幂等拦截（见 §6）。

## 四、核心流程

### 4.1 锁定（apply 内嵌）

```
apply 校验链（保证金段）:
  5. 前置校验(锁外快速失败——防恶意申请空跑锁):
     wallet_repo.get_account(memberId) → None ⇒ 409 "请先开通钱包账户"
     status != "active"               ⇒ 409 "钱包账户状态异常"
     balance < 1000                   ⇒ 409 "钱包余额不足 ¥1000, 请先充值预存保证金(一年期满按年任务完成度退还, 不可提前取现)"
  ...
  8. 锁定(city:{districtCode} 独占校验通过后):
     margin_no = next_margin_no()
     async with get_lock(f"wallet:{member_id}"):        # 最深一层锁
         new_balance = add_balance(member_id, -1000)     # 不足抛 ValueError(已预检, 竞态兜底)
         save_transaction({type: "citystore_margin_lock", direction: "OUT",
                          amount: 1000, balanceAfter: new_balance, ...})
     store_code = next_store_code(district_code)
     margin.storeCode = store_code → save_margin()
```

### 4.2 确认开业（audit_store approved=True）

```python
margin["startDate"] = today                          # 开业日
margin["endDate"] = (date.fromisoformat(today)
                     + timedelta(days=365)).isoformat()  # 一年期自开业日起算
```

驳回（approved=False）：pending→cancelled + `settle_margin(store_code, "rejected")` 全额退。

### 4.3 结算（settle_margin，幂等核心）

```python
async def settle_margin(store_code, reason) -> dict | None:
    # reason ∈ {expired, cancelled, rejected}，非法 409
    margin = get_margin_by_store(store_code)
    if margin is None: return None
    async with get_lock(f"citystore:margin:{marginNo}"):     # 结算互斥锁
        margin = get_margin(marginNo)                        # 锁内重读(双重检查)
        if margin.status != locked: return margin             # 幂等: 已结算直接返回

        # ---- 完成率计算 ----
        if reason == "rejected" or not startDate:
            rate, annual_purchased = 1.0, 0.0                # 未开业: 全额退
        else:
            end = endDate or today                            # 兜底
            annual_purchased = sum_purchase_between(store_code, startDate, end)
            if reason == "expired":                           # 满一年: 按年任务
                rate = min(1.0, annual_purchased / 50000)
            else:                                             # 中途取消: 按运营期折算
                elapsed = (min(today, end) - startDate).days
                prorated = 50000 * elapsed / 365
                rate = min(1.0, annual_purchased / prorated) if prorated > 0 else 1.0

        refund = round(amount * rate, 2)                      # 1000×rate
        deducted = round(amount - refund, 2)

        # ---- 资金退还(钱包锁内; refund=0 全额扣除不产生流水) ----
        if refund > 0:
            async with get_lock(f"wallet:{user_id}"):
                new_balance = add_balance(user_id, refund)
                save_transaction({type: "citystore_margin_settle",
                                 direction: "IN", amount: refund, ...})

        margin.update(status=settled, settledAt, refundAmount, deductedAmount,
                      completionRate, annualPurchased, settleReason=reason)
        save_margin(margin)
```

### 4.4 联动触发点（三条取消路径全覆盖）

| 路径 | 位置 | 联动 |
|---|---|---|
| 平台驳回 | audit_store approved=False | settle_margin(code, "rejected") |
| 管理端取消 | update_status → CANCELLED | settle_margin(code, "cancelled") |
| 考核取消 | run_assessment 连续3月不达标 → CANCELLED | settle_margin(code, "cancelled") |

### 4.5 实时进度查询（get_margin）

locked 且有 startDate 的保证金附带计算字段（不落库）：

```python
annualPurchasedLive = sum_purchase_between(store, startDate, endDate or "9999-12-31")
completionRateLive = min(1.0, annualPurchasedLive / annualTarget)
```

## 五、结算公式与示例

### 5.1 三种公式

| reason | 公式 | 说明 |
|---|---|---|
| rejected | `refund = 1000` | 未开业，全额退还 |
| expired | `rate = min(1, 年进货额/50000)`；`refund = round(1000×rate, 2)` | 满一年，按年任务完成度 |
| cancelled | `rate = min(1, 年进货额/(50000×elapsed_days/365))`；`refund = round(1000×rate, 2)` | 中途取消，目标按已运营天数折算 |

### 5.2 结算示例（测试实证用例）

| 场景 | 年进货额 | 计算 | 退还 | 扣除 | 验证 |
|---|---|---|---|---|---|
| 驳回（未开业） | 0 | 全额 | ¥1000 | ¥0 | margin 15/15 ✓ |
| 到期完成 80% | ¥40,000 | 40000/50000=0.8 | ¥800 | ¥200 | margin 15/15 ✓ |
| 到期 ≥100% | ¥60,000 | min(1, 1.2)=1.0 | ¥1000 | ¥0 | margin 15/15 ✓ |
| 中途干满进度 | 开业182天进¥25,000 | 25000/(50000×182/365)=25000/24931.5>1 | ¥1000 | ¥0 | margin 15/15 ✓ |
| 中途躺平 | 开业100天进¥5,000 | 5000/13698.6≈0.365 | ≈¥365 | ≈¥635 | margin 15/15 ✓ |
| 到期零进货 | ¥0 | rate=0 | ¥0（不产生流水） | ¥1000 | — |

## 六、并发控制与幂等

### 6.1 锁序（单向嵌套，无死锁）

```
citystore:apply:{memberId}          ← 申请互斥
  → citystore:city:{districtCode}   ← 区县独占
    → wallet:{userId}               ← 锁定扣款（apply 路径最深）
citystore:status:{storeCode}        ← 状态流转/审核
  → citystore:margin:{marginNo}     ← 结算互斥（防双退）
    → wallet:{userId}               ← 退款入账（结算路径最深）
```

所有路径锁序单向（citystore 业务锁 → wallet 资金锁），wallet 锁从不反向获取 citystore 锁——无死锁。

### 6.2 双重检查幂等

调度器自动结算与管理端手动结算可能并发：双方先读到 locked → 均进入 `citystore:margin:{marginNo}` 锁 → **锁内重读 status** → 后到者发现已 settled 直接返回 → 不双退。测试实证：重复结算 `settle_margin(code, "expired")` 两次，refundAmount 不变、钱包余额不变（15/15 用例）。

### 6.3 前置快速失败

钱包余额校验放在**任何 citystore 锁之前**（apply 步骤 5）：恶意/低余额申请不占用锁资源，直接 409。

## 七、调度设计（自动到期结算）

```python
# services/citystore_assessment_scheduler.py
async def run_margin_settlement_round() -> dict:
    result = await CityStoreService().run_margin_settlement()
    # → 扫描 list_due_margins(today): status=locked 且 endDate 非空且 ≤ today
    # → 逐个 settle_margin(store_code, "expired")（单条失败不中断，下轮自然重试）
    return result                                  # {due, settled[], skipped[]}

async def _scheduler_loop():                        # 小时级循环（默认 3600s）
    while True:
        await asyncio.sleep(interval)
        run_monthly_assessment()                    # 既有: 月度考核(1-3日窗口)
        run_margin_settlement_round()               # 新增: 保证金到期结算(每小时)
```

**设计依据**：保证金到期日按各店确认开业日**全年分布**，不能只靠月初窗口——并入小时级循环而非月度考核窗口。幂等保证重复扫描零副作用。

调度统计不入 `_scheduler_stats`（避免与考核统计混淆），仅 logger.info 输出 settled 明细。

## 八、API 设计（2 端点）

### 8.1 用户端：GET /api/citystore/{store_code}/margin

鉴权：X-Member-Id（生产 Bearer JWT）。返回保证金全量字段 + locked 期实时进度：

```json
{"success": true, "data": {
  "marginNo": "CD202609190001", "userId": 9001, "storeCode": "CS-110105-001",
  "amount": 1000.0, "annualTarget": 50000.0,
  "startDate": "2026-09-19", "endDate": "2027-09-19",
  "status": "locked",
  "annualPurchasedLive": 40000.0, "completionRateLive": 0.8
}}
```

### 8.2 管理端：POST /api/citystore/{store_code}/margin/settle?reason={expired|cancelled|rejected}

鉴权：X-Role: admin（生产 Bearer JWT + X-Role）。调度器自动结算的**幂等兜底入口**（手动补结算/对账）。资金红线豁免面：**不受 WALLET_MODE 门控**（citystore_routes 无 @_decision 装饰器，wallet_routes 零改动）——off 档照常退还。

### 8.3 与 WALLET_MODE 的关系（红线论证）

保证金三资金动作在 WALLET_MODE 三档（off/shadow/assist）下行为：

| 动作 | 流水 type | 位置 | off 档行为 |
|---|---|---|---|
| 锁定（apply） | citystore_margin_lock (OUT) | citystore_routes /apply | 可用（apply 非决策端点） |
| 退还/结算 | citystore_margin_settle (IN) | citystore_routes /settle + 调度器 | **可用**（豁免面） |

符合「存量资金退出零影响」铁律：保证金是店主存量资金权益，任何档位下驳回退/到期退/中途退不得被模式关停阻断。

## 十、运维手册

### 10.1 常用查询

```bash
# 生产容器内: 某店保证金状态(含实时进度)
curl -H "Authorization: Bearer <token>" http://localhost:8000/api/citystore/CS-370102-001/margin

```

### 10.2 手动补结算

```bash
# 到期补结算(expired) / 中途取消补结算(cancelled)
curl -X POST -H "Authorization: Bearer <token>" -H "X-Role: admin" \
  "http://localhost:8000/api/citystore/CS-370102-001/margin/settle?reason=expired"
```

幂等：重复调用安全（已 settled 直接返回，不双退）。

### 10.3 异常处置

| 现象 | 排查 | 处置 |
|---|---|---|
| 调度器未自动结算 | docker logs 搜 `citystore_margin_settlement`；确认 endDate≤today 且 status=locked | 管理端手动 settle 兜底 |
| 钱包流水缺 refund | 查 margin.settleReason/refundAmount；refund=0 属全额扣除（无流水为设计行为） | — |
| 重复结算疑虑 | margin 状态与钱包流水核对（type=citystore_margin_settle 计数） | 幂等锁保证不双退，以流水为准 |
| apply 报钱包余额不足 | 钱包余额 <1000 | 充值后重申（409 含规则文案属正确拦截） |

### 10.4 回滚

保证金为新增独立实体，模块回滚（git revert 7736395）不影响钱包余额数据；生产存量 locked 记录可通过管理端 settle（reason=cancelled 或 expired）手动结算退出——资金红线豁免面保证任何档位可退。

## 十一、设计权衡记录

| 决策 | 选择 | 放弃 | 理由 |
|---|---|---|---|
| 实体归属 | citystore_repository 内 | wallet_repository | 保证金生命周期与网店强绑定（驳回/取消/考核联动），钱包侧无业务感知 |
| 不可提前取现 | 无 early 接口（负向设计） | 加拒绝接口 | 不提供入口即不可调用——测试用例覆盖"无 early 接口"负测 |
| 中途取消折算 | 按已运营天数折算目标 | 按全年目标 | 对店主公平（干 6 个月不按 12 个月任务考核）；躺平者仍按比例扣 |
