## 一、P6 四项深化设计

### D1·注册即开通(trustId 同值落地 + 占位建档 + 实名升级)

```
注册链(auth_service.register) fail-soft 挂接:
    ① 条款同意留痕: 注册时 ageConfirmed/agreement 同勾选即
       "信值条款同意"事件落 member 记录(协议已有 AGREEMENT_GUARD
       资产, 复用协议版本号)
    ② 自动建档: trust_id 显式传入 = memberId(同值铁律落地,
       xx64 前端缓存 hack 退役); idNumber 占位 "member:{memberId}"
       (摘要唯一性由 memberId 保证)——证件摘要缺失不挡开通
    ③ 实名升级: auth_realname 链通过后 rebind——占位摘要替换为
       真证件摘要(档案/分数/事件全量保留, 仅唯一键升级;
       升级冲突(该证件已另有档案)走人工申诉队列)
    ④ fail-soft 铁律: 建档异常不阻断注册(补建档入口留前端口)
```

**侵入面**: trust_scoring_service.create_role 增加可选
`trust_id` 参数(同值传入); 新增 `bind_real_digest`(实名升级);
auth_service/auth_realname 两处 hook(同 P2-b login_count 挂接模式)。

### D2·修复通道会员端化(引擎在, 开门)

- taro trust 页增"信值修复"区: 修复计划(违规即列+β 加权最优
  清单+时效窗口——后端 plan 端点已有) + 提交修复证据包 +
  修复明细/进度回放
- 会员端语义: 无违规时显示"信值良好, 无需修复"健康态;
  有违规即列即建议(P2 "立地成佛"算法的会员可视面)
- 修复成本透明化: 天花板(α)/关联度(β)/时效(γ 24h 内≈30 天后
  18-20 倍)三条数学规则前端展示——给改过者清晰可执行的希望路径

## 二、实施路径(四批, 惯例节奏)

1. **D1 注册即开通**(后端: create_role trust_id 参数 + bind_real_
   digest + register/realname 双 hook + 单测)——**其余三项的地基**
   (trustId 同值映射是一切会员端体验与业务挂钩的前提)
2. **D2 修复通道前端**(taro trust 页修复区三入口 + 无违规健康态)
3. **D3 信号自动入分**(事件总线 + 七信号源接入 + 单测; 限制矩阵
   settings 骨架, 默认关)
4. **D4 档位权益**(五权益 settings 化 + 兑换/臻选/修复/语音/推广
   五挂点; 与 D3 限制矩阵同属"约束与收益两端", 一批验收)
5. 生产部署 + 验收(注册新会员即有档/修复入口可见/信号入分实证/
   档位权益灰度开 1-2 项) + 文档回填 + commit

## 三、风险与铁律

- **fail-soft**: 建档/入分/权益挂点任一异常不阻断主流程(注册/
  下单/兑换); 同 P2-b/E2 全项目惯例
- **灰度铁律**: D3 限制矩阵与 D4 权益全量 settings 默认关, 逐项
  转 on; 扣分事件源先 shadow(入分留痕不生效, 观察 1 周误伤面)
- **申诉兜底**: 一切自动扣分可走 P4 申诉(7 日窗口已有), 人工
  复核翻转重算已有——约束力的同时保纠错通道
- **同值映射迁移**: 存量自助建档会员(自增 trustId)不迁移——
  前端 myTrustId 缓存兼容旧档; 新注册走同值。存量映射表留 P7
- **社会行为数据源**(radar 公开域)已有白名单+去标识化铁律,
  本批不动其边界

## 四、验收标准

- 新注册会员: 注册成功即 trustId=memberId 档案在案(grade=watch
  冷启动), 条款同意事件留痕; 建档异常不阻断注册(fail-soft 实证)
- 实名会员: rebind 后真证件摘要生效, 档案历史完整
- trust 页: 修复计划可见(无违规健康态/有违规即列建议), 提交-
  验真-入分链路走通
- 信号源: 制造一次 E3 forfeited → 自动入分事件落库 + 分数变动 +
  申诉可查(shadow 期留痕不生效)
- 档位权益: 兑换上限/臻选 α 按档位实算差异实证(settings 开 1 项)
