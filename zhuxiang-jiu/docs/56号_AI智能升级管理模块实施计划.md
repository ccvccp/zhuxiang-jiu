# 56号·AI智能升级管理模块实施计划

> 定位：本站智能大模型的**受控自进化中枢**——"信值驱动的受控进化"（Value-UEBA 体系收官拼图）
> 范式：Agent GLM 四角色制衡（规划/编码/测试/审计）× 信值沙箱 × 人类终审——从"人工运维"迈向"认知型自洽系统"
> 版本：v1.0（2026-09-06）

---

## 〇、参照方案的本站化优化升级说明

参照方案（用户输入）的五大理念全量继承，工程落地做**六项本站化升级**：

| 参照方案要点 | 本站化升级（落地口径） |
|---|---|
| Agent GLM 四角色协作体 | **规则轨优先+LLM 三态**（48/44/55号范式）：四 Agent 为**确定性编排器**（mock 模板产出），LLM（GLM-4-flash，`LLM_ENABLED`）仅做草稿/润色增强，失败回退 mock——LLM 不进执行决策链；Agent 产出为**版本化变更资产包**（存 aiup56_assets），永不直接落盘生产代码 |
| 信值沙箱（隔离环境动态执行） | **影子评估管线**（55号 shadow_compare 范式）：静态规则校验（敏感 API/PII/国密规范）+ 预算模拟回放 + 价值预估回放——**不执行任意代码**（沙箱执行任意生成代码是本站不可接受的攻击面，列外部待办需 TEE）；预算熔断走 49号 check_and_spend |
| 自动交付生产资产 | **三重门禁+人类终审强制**：功能（测试 Agent）+合规（审计 Agent 一票否决）+信值增益≥阈值（沙箱价值预估）→ 人类审批面板（关键项强制确认+高风险双人复核）为交付终点；**实际部署永远走既有 CI**（pre-commit 钩子）——"交付生产资产"= 交付可直接进入生产流水线的资产包 |
| 语义级回滚 | **回滚预案预生成+资产版本化+45号信值补偿**：每提案编码期即预生成分步回滚预案（含数据清理）；灰度异常触发预案执行留痕+受影响用户 45号 L2 补偿（55号 compensate_tamper_victims 范式）+决策回流负修正 |
| 多源信号融合（用户/系统/合规/模型四侧） | **SIGNAL_REGISTRY 封闭白名单**（52号 registry 范式）：46号三检测器告警+52号五维可用性+55号六指标漂移+44号池 rewardAlignment——**全站既有观测面纯读取**（零侵入），启动自检 RuntimeError 宪法级 |
| 落地路径四期（影子→辅助→受控→可信） | **开关矩阵三级灰度**：`AIUP56_MODE = off / shadow / assist`（默认 off）——shadow=观察学习期（仅决策+提案）、assist=辅助开发期（资产生产+审批交付）；受控自治/可信进化期为远期（**终审人工铁律永不解除**——安全鸿沟） |

**核心原则（继承+强化）**：AI 自主升级的终极目标不是取代人类工程师。若缺乏刚性约束，自主 Agent 极易引发幻觉代码注入、隐私预算失控或合规底线击穿——因此每一次升级决策与代码生成都必须**消耗隐私预算、通过合规校验、接受人类监督**。"如果这个环节出错，我们能否在 5 分钟内恢复用户信任？"——答案必须是肯定的，因为**信任比效率更珍贵**。

## 一、模块定位与架构

```
全站观测面信号(46/52/55号+44号池——纯读取)
        │
        ▼
① 升级决策引擎(SIGNAL_REGISTRY 融合评分——第31档案)
   ├─ 必要性 < 阈值 → defer 观察留痕
   └─ 必要性 ≥ 阈值+预算充足 → 生成《升级提案摘要》
        │
        ▼
② 规划Agent(任务拆解+依赖分析+信值影响预估+回滚预案框架)
        │
        ▼
③ 编码Agent(代码草稿——VALUE_REASON 注释+测试计划草稿;
   mock 确定性模板/LLM real 三态)      ┐
        │                              │ 信值沙箱
        ▼                              │ (预算计量)
④ 测试Agent+信值沙箱(静态规则+预算模拟+价值回放预估;
   超支熔断暂停+告警)                  ┘
        │ 沙箱通过                 沙箱失败 → 回③
        ▼
⑤ 审计Agent(合规三重校验: 代码层/逻辑层/文档层;
   一票否决权; LLM 归因报告)
        │ 合规通过              合规拒绝 → 回②
        ▼
⑥ 人类审批面板(关键项强制确认; escalate 级双人复核)
        │ 批准                   驳回 → 回②
        ▼
⑦ 资产包交付(versioned: 代码草稿+测试计划+回滚预案+审计报告
   ——人工下载后走既有 CI 部署)
        │
        ▼
⑧ 灰度跟踪+语义回滚(预案执行+45号信值补偿)
   └→ 决策回流 → 第31档案 Hedge 学习(44号复用)
```

**三铁律（安全鸿沟工程化）**：
1. **AI 永不落盘生产代码**——产出止于版本化资产包（Redis/内存态），部署动作永远人类+既有 CI；
2. **终审永远人工**——审批面板是唯一交付出口，mock/LLM/沙箱/审计任何"全自动通过"路径在架构上不存在；
3. **预算全程封顶**——提案级预算上限（默认 0.1/提案），每次 Agent 调用（LLM real 轨/沙箱模拟）经 49号 check_and_spend 计量，超支熔断暂停+告警。

**双模型铁律（54/55号范式平移）**：56号评分（第31档案）与各业务模块自有评分轨**并行不替换**——56号仅对"升级决策"打分回流，不侵入任何业务模块。

## 二、升级信号注册表（SIGNAL_REGISTRY——封闭白名单）

52号 registry 范式。每条信号含六字段：

```python
SIGNAL_REGISTRY = {
    "gov46_stagnation": {
        "label": "学习停滞", "source": "ai_governance_health",
        "direction": "positive",   # 命中→推动升级
        "weight": 0.20, "threshold": 1, "status": "active",
    },
    ...
}
```

**首批 10 项信号源**（四侧）：

| 侧 | 信号 | 权重 | 采集口径（纯读取） |
|----|------|------|-------------------|
| 模型侧 | gov46_stagnation 学习停滞 | 0.20 | 46号 live_health 三检测器 |
| 模型侧 | gov46_drift_high 因子漂移高 | 0.15 | 46号 live_health |
| 模型侧 | pool44_alignment 回流对齐下降 | 0.15 | 44号池 rewardAlignment 环比 |
| 用户侧 | us52_usability_drop 可用性下降 | 0.15 | 52号五维指标环比 |
| 用户侧 | qr55_satisfaction_drop 满意度下降 | 0.10 | 55号六指标 satisfactionScore 环比 |
| 系统侧 | qr55_clarify_bloat 澄清效率劣化 | 0.10 | 55号 clarifyEfficiency 环比 |
| 系统侧 | qr55_generation_waste 生成过剩 | 0.05 | 55号 expired_unscanned 信号占比 |
| 合规侧 | gov46_alert_open 合规告警未决 | 0.05 | 46号 alerts status=open |
| 合规侧 | registry_pending 挂起待审批项 | 0.025 | 46号 changes pending 数 |
| 模型侧 | scorer_frozen 档案冻结中 | 0.025 | 46号 is_frozen |

- **启动自检**（52号范式）：10 项数量/四侧覆盖/权重和=1.0/方向合法/来源在册——RuntimeError 宪法级
- **升级必要性评分**：`Upgrade_Necessity_Score = Σ(命中信号×权重)×100` → 与第31档案八因子信任分融合后三级决策

## 三、四 Agent 协作编排（确定性 mock 优先）

| Agent | 职责 | mock 轨（确定性） | LLM real 轨（fail-soft 回退） |
|-------|------|------------------|------------------------------|
| 规划 Agent | 任务拆解/依赖分析/信值影响预估/回滚预案框架 | 按信号类型分发任务模板（46号三检测器信号→治理类任务模板等） | GLM 润色任务描述+依赖补全 |
| 编码 Agent | 代码草稿+测试计划草稿 | 模板库渲染（含 `# VALUE_REASON:` 注释——对信值体系的贡献依据） | GLM 草稿生成（Prompt 含站点代码风格/安全编码/国密调用规范约束） |
| 测试 Agent | 用例生成+沙箱评估执行 | 用例矩阵模板（正常/边界/异常）+影子评估规则 | GLM 补充用例叙述 |
| 审计 Agent | 合规三重校验+归因报告 | 规则库校验（敏感 API/PII/加密强度/文档完整性）+确定性报告 | GLM 润色《升级合规审计报告》+高亮重点项 |

- **Prompt 模板集**：四 Agent 的 system prompt 以常量内置于各服务（`AGENT_PROMPTS`），含"只使用用户提供数据，不编造数字"硬约束（55号归因范式）
- **资产版本化**：每次 Agent 产出以 `assetVersion` 递增留痕（v1→v2 迭代，失败回退重生成不覆盖）
- **调用计量**：mock 轨零成本；real 轨按次计费（默认 0.01/次）经 49号 check_and_spend（预算主体=提案提交人，缺省系统账号）

## 四、信值沙箱（影子评估管线）

三道评估（55号验签三道关范式——全部离线确定性，不执行生成代码）：

| 关 | 评估 | 口径 |
|----|------|------|
| 静态关 | 代码草稿规则扫描 | 敏感 API 白名单比对（DDL/外部请求/eval 类标记）+PII 禁入+国密调用规范比对 |
| 预算关 | 隐私消耗模拟 | 草稿声明的 privacyCost 按 49号 模拟扣减——超提案封顶 → 熔断暂停+告警 |
| 价值关 | 信值增益预估 | 44号池近期反馈回放（目标模块档案）——预估信值增益 < 阈值（默认 0）→ 门禁不通过 |

输出《沙箱评估报告》（verdict: passed/blocked/budget_halted + 三关明细）——测试 Agent 终稿依据。

## 五、数据模型（6 表，前缀 aiup56）

| 表 | 主键 | 用途 |
|----|------|------|
| aiup56_proposals | proposalId | 升级提案（信号快照/必要性分/风险预估/状态机 draft→planned→coded→tested→audited→approved→delivered→rolled_back/archived） |
| aiup56_tasks | taskId | 任务分解（规划 Agent 产出——依赖/预算/信值影响标注） |
| aiup56_assets | assetId | 版本化资产包（代码草稿/测试计划/回滚预案/审计报告，assetVersion 递增） |
| aiup56_sandboxes | sandboxId | 沙箱评估留痕（三关 verdict+预算消耗） |
| aiup56_reviews | reviewId | 人类审批记录（审批人/结论/确认清单勾选/双人复核链） |
| aiup56_events | eventId | 全链事件（signal_scan/plan/code/test/audit/approve/reject/deliver/rollback/compensate/learn） |

复用 44号：ai_learning_profiles（**第31档案 upgrade_orchestration，batch15**）+ ai_learning_feedback；46号：合规告警/冻结态只读；45号：补偿结算；49号：预算计量。

## 六、第31档案：upgrade_orchestration 八因子信任分

| 因子 | 权重 | 口径 |
|------|------|------|
| signal_quality | 0.15 | 信号质量（命中数×来源四侧覆盖度） |
| necessity_score | 0.20 | 升级必要性（信号融合分） |
| budget_sufficiency | 0.15 | 隐私预算余量（49号） |
| risk_posture | 0.15 | 风险态势（46号冻结/告警密度） |
| model_health | 0.10 | 模型健康（44号池对齐度+46号健康分） |
| history_success | 0.10 | 历史升级成功率（回流真值） |
| compliance_posture | 0.10 | 合规态势（46号审计信号） |
| human_load | 0.05 | 人工负载（近期干预率——低负载利于自主） |

输出 0-100 信任分 → 三级决策（`DECISION_THRESHOLDS`）：`defer` 观察（<50）/ `propose` 提案（≥50）/ `escalate` 紧急提案+双人复核（≥80）。

## 七、决策回流管道（七类真值信号）

| 信号源 | reward | 语义 |
|--------|--------|------|
| 提案批准+交付+灰度达标 | +1.0 | 升级决策正确 |
| 提案批准+交付+价值达成率≥90% | +0.8 | 增益预估准确 |
| 提案批准+价值未达预估 | +0.3 | 弱满足（预估偏差修正） |
| 驳回后同类信号复发 | -0.6 | 决策保守（漏判） |
| 交付后灰度异常回滚 | -0.8 | 升级质量缺陷 |
| 审计否决被人工推翻 | -0.5 | 审计误判 |
| 预算熔断频繁 | -0.4 | 预算规划失准 |

44号池双写+T+1 补标（55号 P2 范式全继承：幂等 eventId 1:1/延迟态转正/`_ts_utc` 统一）。

## 九、分期实施计划（P0-P5）

### P0 信号注册表+决策引擎+提案底座
- SIGNAL_REGISTRY 10 项+启动自检（52号范式）
- 升级决策引擎（信号融合评分+第31档案八因子+三级决策）
- 第31档案入册 SCORER_REGISTRY batch15（既有测试 30→31 计数更新——55号 P0 教训预算）
- 提案底座（状态机+《升级提案摘要》生成）
- 测试：专项约 22 断言
- QC：信号白名单封闭（未知源拒绝）；46/52/55号观测面零改动

### P1 规划+编码 Agent（资产生产）
- 规划 Agent（任务模板分发+依赖分析+回滚预案框架——mock/real 三态）
- 编码 Agent（模板库+VALUE_REASON 注释+资产版本化）
- 测试：专项约 26 断言
- QC：AI 产出止于资产包（无落盘生产路径）；LLM 失败回退 mock

### P2 测试 Agent+信值沙箱
- 用例矩阵生成+影子评估三关（静态/预算/价值）
- 预算熔断（49号 check_and_spend 织入——提案级封顶）
- 测试：专项约 22 断言
- QC：超支熔断；价值门禁（预估增益<阈值 blocked）

### P3 审计 Agent+人类审批面板
- 合规三重校验（规则库+一票否决）+LLM 归因报告（三态）
- 审批面板（关键项强制确认清单；escalate 级双人复核）
- 测试：专项约 20 断言
- QC：审计一票否决；无审批不可交付（架构断言）

### P4 交付+语义回滚+信值补偿+回流
- 资产包交付（versioned 出口）+灰度跟踪窗口
- 语义回滚（预案分步执行留痕）+45号 L2 受影响用户补偿
- 七类信号回流+44号池双写+T+1 补标调度器
- 测试：专项约 22 断言
- QC：回滚闭环（预案可执行+补偿落账）；回流幂等 eventId 1:1

### P5 看板+红队+三件套收官
- 看板（提案漏斗/资产产出/审计合规/回滚防御四区）
- 红队：提案投毒/预算耗尽攻击/审批绕过/资产注入（草稿含恶意载荷）/信号伪造/回滚破坏 六向量
- 宪法断言（44/46/49/51号零改动）+三件套文档
- 测试：专项约 24 断言
- QC：投毒防御（护栏+集中度）；全链零回归

**开关矩阵**：`AIUP56_MODE`（默认 **off**——off=决策面关闭零影响；shadow=观察学习期仅决策+提案；assist=辅助开发期资产生产+审批交付）；`AIUP56_LEARN_MODE`（学习调度，默认 off——双开关铁律）。
