# Bug 反馈：Trae CN 索引/缓存重建进程对项目文件反复叠加 UTF-8 BOM

> 提交渠道任选：IDE 内「头像 → 报告问题」/ 社区论坛 Bug 反馈 / 邮件 feedback@mail.trae.cn
> 以下正文可直接粘贴，证据截图/日志可补充。

---

**你的运行环境**：Windows 11 专业版（10.0.26231）｜ Trae CN **1.107.1**（commit 11ec4a1，stable）｜ 飞书账号登录

**问题描述**：

Trae CN 后台的索引/缓存重建进程会**把项目内被索引过的文本文件用带 BOM 的编码写回磁盘**，且每轮重建在首行**再叠加一层 BOM**（`EF BB BF`）。持续观察到的文件已叠加到 2~10 层 BOM。该写入不属于用户编辑（深夜无人时段亦发生），污染的是 Trae 索引缓存清单内的文件（从未被用户/Agent 编辑过的文件也被写坏），而新建文件（不在索引清单内）不被触碰。

**受影响示例**（git 工作区 diff，首字节 `EF BB BF EF BB BF`）：

- `backend/test_*.py`、`verify_*.py` 等约 70 个文件（从未被编辑过）
- `docs/*.md`（曾观察到 10 层 BOM = 历经多轮重建）
- `*.tsx / *.js / *.html / *.ps1` 各类型文本文件均中招

**证据链**（已系统排查定位到 Trae 进程）：

1. **时间衔接**：每日凌晨 02:53:41 起 Trae CN 拉起新进程（含 `--aha-log-session-time=20260923T025341` 的维护会话、tsserver、NodeService），02:54:30 文件写入准时开始——深夜无人操作时段。
2. **写入轮 CPU 取证**：写入进行中对全进程做 2 秒 CPU 双快照，增量 Top5 全部为 Trae CN.exe 进程（renderer 2312ms / tsserver 1343ms / node.mojom.NodeService 1313ms）。
3. **遍历特征**：71 个文件的 mtime 按目录树**字母序逐秒推进**（test_* → verify_* → deploy → docs，02:57:14→03:02:41 连续 5.5 分钟，每秒 1-3 个文件）——典型的索引器全量扫描节奏，而非用户编辑行为。
4. **清单范围验证**：在项目各目录新建 14 个哨兵文件（各种类型）→ 污染轮**零触碰哨兵**，但 Trae 读过的文件（含 Agent 检索过、从未被编辑的）全部被写——写入者遍历的是 Trae 自己的索引缓存清单。
5. **排除项**：已排除 git filter/autocrlf（无 .gitattributes 配置）、Python LSP jedi（重启全量索引实测无写入）、百度网盘、计划任务（LargeFileClean/WXClean 为已卸载孤儿任务）、系统维护任务（Windows 维护窗口任务均不写用户文件内容）。

**影响**：

- 多层 BOM 使 **Python 源文件语法错误**（`SyntaxError`，utf-8-sig 只剥一层）；PowerShell 脚本、md、TS 均存在解析隐患
- git 工作区大面积脏文件（每轮几十个 M），污染提交
- 用户不得不定期批量 `git checkout` 还原 + 编写清理脚本维持仓库卫生

**复现步骤**：

1. 在 Trae CN 中打开一个包含大量文本文件（py/ts/md）的项目，进行正常编辑与 AI 检索（让索引清单覆盖大量文件）
2. 保持 Trae CN 常驻运行至凌晨（或等待其自动维护/更新重启进程）
3. 次日以二进制查看项目文件首字节：`EF BB BF` 重复 ≥2 层；git status 出现大面积非用户修改的 M 文件

**快速验证方法**（供工程师）：

- 监控写入：对项目文件 mtime 高频轮询，写入窗口内对全进程做 CPU 双快照（可用 Restart Manager / ETW），可复现上面证据 1-3
- 定位模块：怀疑点在索引/缓存重建的**文件写回路径**（读入→规范化→`utf-8-sig` 或带 BOM 编码再次写回，且每次运行都会重复叠加），建议审查 workspace 索引器 / 上下文引擎 / aha 维护任务的持久化写回逻辑

**期望**：

1. 索引/缓存重建不写回源文件内容（只读索引），或至少严格保持原字节
2. 已受影响用户提供清理工具或修复版本
3. 希望确认是否有临时开关可关闭相关索引重建功能

**附**：可提供完整取证日志（mtime 秒级分布、CPU 快照、哨兵实验结果）协助定位。
