> 2026-10-01 立项 | 前置: P6 D1 同值铁律已上线(注册即开通,
> trustId=memberId); 本方案收编 P6 之前的存量自助建档档案
> 触发条件(P6 方案 §五): D1 稳定 2 周(约 2026-10-15)

## 〇、生产盘点实证(2026-10-01, 方案规模依据)

| 盘点项 | 实证 | 结论 |
|---|---|---|
| trust45 自增序列水位 | `profiles:seq = 1` | 自增建档仅发生过 **1 次** |
| 存量档案总数 | 10 个 | 见下三分 |
| ├ 真实自助建档 | **1 个**: trustId=1 "彭圭"(真证件摘要 5bbbd3…, score 55.0) | **迁移对象仅此 1 档** |
| ├ 测试残留 | 8 个: trustId 9882-9889 "rt65-xxxx"(digest=name, score 1000.0) | 非会员档案, 列清理候选(§三) |
| └ P6 同值新档 | trustId=38(验收注册, watch/55.0) | 同值铁律生产在轨 |
| 会员水位 | memberId seq=38 | trustId=1 的目标 memberId ∈ 1..37 |

**规模结论**: 真实存量 = 1 档。策略选型按"极小规模"裁剪——
直接**档案搬迁归一**(终态), 不引入查询层映射双体系(为大规模
设计的过渡方案, 1 档不值得留永久技术债)。映射表降级为
**迁移存档记录**(old→new 永久可查, 兼容历史引用), 非运行时依赖。

## 一、迁移设计

### 1.1 映射表(迁移存档, 非运行时依赖)

```
trust45_idmap(Redis hash, key=zhuxiang:trust45:idmap):
    {oldTrustId} → {
        "newTrustId": <memberId>,      # 搬迁目标(同值铁律)
        "memberId":   <memberId>,
        "migratedAt": ISO, "by": "p71_migrate",
        "reason": "存量自助建档收编",
        "profileSnapshot": {...},     # 迁移前档案快照(回滚依据)
    }
用途: ①历史事件/账本中旧 trustId 的可解释归档;
      ②P5 开放面对外旧 ID 查询的 resolve 重定向(兼容期);
      ③审计追溯。运行时业务链路不再读它(全量已归一)。
```

### 1.2 搬迁流程(七步, 工具 migrate_trust45_ids.py)

```
① 身份确认(dry-run): trustId=1 档案 digest 与 auth_realname
   的 idcard_hash 比对 → 定位 memberId(一人一证索引已有);
   无法自动确认 → 人工确认清单(仅 1 档, 管理员裁决)
② 冲突检测: 目标 memberId 须无既有档案
   (P6 前老会员无自动档, 预期无冲突; 有冲突 → 走 P6 实名
   conflict 同款人工申诉裁决, 工具报 conflicts 退出)
③ 快照备份: idmap 存 profileSnapshot + 逐关联表导出
   (events/repairs/风险档案/余额)——回滚依据
④ 档案搬迁(原子逐表):
   profile:     key trust45:profiles:{1} → {memberId}
                (字段不变, 含 TV 余额随档走)
   events:      trustId 字段 1→memberId(历史事件表逐条改写)
   repairs:     归属校验字段同步(_find_event 口径)
   47号风险档案: trustId 关联同步
⑤ 账本特殊处理(宪法口径: ledger 只追加不可篡改):
   历史流水**原样保留旧 trustId**(历史事实不改写)——
   余额展示与后续兑付全部经 idmap/新 ID 归并; 对外开放面
   旧 ID 查询经 idmap resolve 重定向(兼容期 ≥90 天)
⑥ 映射存档: idmap 落档(§1.1)
⑦ 校验: 新档案可查/分数一致/事件数一致/余额一致;
   旧 key 已清; 幂等可重跑(已迁档检测跳过)
```

### 1.3 前端兼容(彭圭设备)

旧设备本地 `trust_id_cache=1` 失效路径: trust 页 loadData
查不到旧档(404)→ 现有逻辑已自动清缓存进建档态——
**误建档风险**: 该会员再点"开通"会以证件摘要重复建档
被 `find_by_digest` 拦截("该证件已建档")→ 提示走档案查询,
人工引导一次即闭环(单档规模, 人工成本可忽略; 若规模化
则前端补"建档冲突→按 digest 反查提示新 trustId"逻辑, 留
本方案 §六 验收观察项)。

## 二、工具规格(migrate_trust45_ids.py)

- 三模式: `--dry-run`(盘点+身份确认+冲突预检, 零写入) /
  `--exec`(七步搬迁, 幂等) / `--verify`(迁移后对账断言)
- 白名单边界: **只处理 idmap 登记档**——不碰同值新档、
  不碰测试残留(§三 单独处理)、不碰无档案老会员
- 输出: 逐档迁移报告(旧/新 ID/关联表计数/余额对账)存
  docs/ 附件 + idmap

## 四、风险与回滚

| 风险 | 缓解 |
|---|---|
| 身份确认错配(1 档) | digest 与实名 idcard_hash 双向比对 + 人工终审(dry-run 报告) |
| 搬迁半程失败 | 逐表原子 + 幂等重跑; idmap profileSnapshot 全量回滚 |
| 账本历史与展示不一致 | 宪法口径: 历史不改写, 展示/兑付经新 ID 归并——对账断言入 verify |
| 前端旧缓存误建档 | digest 查重拦截天然兜底(§1.3); 观察期一人次人工引导 |
| 开放面旧 ID 断查 | idmap resolve 兼容期 ≥90 天, 外部接入方为零(P5 实证) |

## 五、验收标准

- dry-run: 报告 1 迁移档 + 0 冲突(+8 清理候选, 若确认)
- exec 后: 新 memberId 档案可查且分数/事件数/余额与快照
  全等; 旧 ID 开放面查询经 resolve 返回新档案
- verify: 对账断言全绿; 回归 test_trust45_p6 11/11 +
  45号 p0-p5 既有测试全绿
- 前端: 彭圭设备登录后 trust 页正常展示新档(清缓存后)
