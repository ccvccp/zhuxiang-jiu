## SOP-1 首次上线（全新环境）

预计操作：配置 → 构建 → 启动 → 验收 → 开调度。全程约 30 分钟。

### 步骤 1：拉取代码并确认基线（2 分钟）

```powershell
cd d:\网站架构设计\zhuxiang-jiu
git pull origin master
git log --oneline -1
# 确认输出 ≥ 8aa7b05；必须包含 b459c34（attract 修复，缺失会导致归因恒为 0）
git log --oneline | Select-String "b459c34"
```

### 步骤 2：配置 `.env`（5 分钟）

在 `d:\网站架构设计\` 创建/编辑 `.env`（该文件不入 git）。**首次上线最小配置**：

```ini

LLM_API_KEY=<你的智谱API密钥>
LLM_MODEL_PROMO=glm-5.3

# 调度先不开, 验收通过后按 SOP-4 逐个开启
# PROMO_RADAR_AUTO=on
# PROMO_PUBLISH_AUTO=on
```

真实通道/百度推送/真实热点源的凭证**本次不配**（走 mock 轨），资质就绪后按 SOP-5 增补。

### 步骤 3：构建并启动（5 分钟）


### 步骤 4：启动验证（3 分钟）


### 步骤 5：功能验收（10 分钟）

按顺序执行，任一步判据不满足则停，按 §排障 T-xx 处理：

```powershell
$H = @{"X-Role"="admin"}; $B = "http://localhost:8000"

# 5.1 通道状态(五平台 mock)
(Invoke-RestMethod -Headers $H "$B/api/promo/channels/status").data |
  Select-Object platform, effectiveMode
# 判据: 五平台 effectiveMode 均为 mock

# 5.2 雷达扫描
$scan = Invoke-RestMethod -Method Post -Headers $H "$B/api/promo/radar/scan"
"scanned=$($scan.data.scanned) new=$($scan.data.new) discarded=$($scan.data.discarded)"
# 判据: 25 / 20 / 5

# 5.3 种子初始化(画像5平台 + 信源4条)
(Invoke-RestMethod -Headers $H "$B/api/promo/audience/profiles").count   # → 5
(Invoke-RestMethod -Headers $H "$B/api/promo/authority/sources").count  # → 4

# 5.4 生成内容(取第一个已跟进热点)
$hid = (Invoke-RestMethod -Headers $H "$B/api/promo/radar/hotspots?status=engaged").data[0].hotspotId
$gen = Invoke-RestMethod -Method Post -Headers $H -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes('{"hotspotId":' + $hid + ',"platforms":["douyin"]}')) `
  "$B/api/promo/contents/generate"
$cid = $gen.data[0].contentId; $code = $gen.data[0].shortCode
"content=$cid score=$($gen.data[0].complianceScore) code=$code"
# 判据: score=100, code 以 A- 开头

# 5.5 审核 → 发布(过去时间立即出队)
Invoke-RestMethod -Method Post -Headers $H -ContentType "application/json" `
  -Body '{"approved":true}' "$B/api/promo/contents/$cid/review" | Out-Null
$past = (Get-Date).ToUniversalTime().AddMinutes(-1).ToString("o")
Invoke-RestMethod -Method Post -Headers $H -ContentType "application/json" `
  -Body ('{"publishAt":"' + $past + '"}') "$B/api/promo/contents/$cid/publish" | Out-Null
$proc = Invoke-RestMethod -Method Post -Headers $H "$B/api/promo/publish/process"
"receipt: mode=$($proc.data[0].receipt.mode) id=$($proc.data[0].receipt.publishId)"
# 判据: mode=mock, publishId=PUB-douyin-{cid}

# 5.6 归因闭环(短码点击→注册→下单)
$loc = & curl.exe -s -o NUL -w "%{redirect_url}" "$B/r/$code`?utm_source=douyin"
$clickId = ($loc -split "clickId=")[1]
Invoke-RestMethod -Method Post -ContentType "application/json" `
  -Body ('{"clickId":' + $clickId + ',"memberId":99001}') "$B/api/attract/attach" | Out-Null
Invoke-RestMethod -Method Post -ContentType "application/json" `
  -Body ('{"clickId":' + $clickId + ',"orderId":"ORD-ACCEPT-1","orderAmount":299.0,"commission":15.0}') `
  "$B/api/attract/attach-order" | Out-Null

# 5.7 全景报表(归因是否计数)
(Invoke-RestMethod -Headers $H "$B/api/promo/report/overview").data.attribution
# 判据: clicks=1 registered=1 ordered=1 gmv=299
# 若全为 0 → 未包含 b459c34 修复, 回 SOP-1 步骤 1

# 5.8 Hedge 回流
$fb = Invoke-RestMethod -Method Post -Headers $H -ContentType "application/json" `
  -Body ('{"contentId":' + $cid + '}') "$B/api/promo/learning/feedback"
"correct=$($fb.data.correct)"
# 判据: correct=True (有点击 → engage 决策正确)

# 5.9 前端看板(浏览器手动)
# 打开 d:\网站架构设计\zhuxiang-jiu\ai-promo-radar.html 与 ai-promo-studio.html
# 判据: 数据加载正常, 通道/SEO 卡片渲染, 无红色横幅报错
```

**验收全部通过 → 执行 SOP-4 开启调度 → 上线完成。**

## SOP-3 日常运营操作

### 3.1 每日热点处理（雷达大屏 ai-promo-radar.html）

```
打开雷达大屏 → 「立即扫描」 → 检查"待人工裁决"列表(50-70分热点)
→ 逐条「跟进」(进入内容工厂) 或「放弃」 → 记录裁决依据(备注)
```

手动触发（脚本/看板均可）：

```powershell
Invoke-RestMethod -Method Post -Headers $H "$B/api/promo/radar/scan"     # 扫描
(Invoke-RestMethod -Headers $H "$B/api/promo/decisions?pendingOnly=true").data  # 待裁决
# 跟进: POST /api/promo/decisions/{hotspotId}/decide  body {"engage":true,"note":"..."}
```

### 3.2 内容生产与发布（工厂看板 ai-promo-studio.html）

```
选择热点(engaged) → 勾选平台(五选) → 「生成内容」
→ 待审列表逐条「通过/拒绝」(硬违规/溯源违规会 409 拦截, 属正常保护)
→ 通过的内容「入发布队列」(自动排黄金时段)
→ 到期后调度器自动发布; 或「立即处理到期发布」手动出队
```

指定时间发布：`POST /api/promo/contents/{id}/publish` body `{"publishAt":"<ISO时间>"}`。

### 3.3 每周 Hedge 学习

```powershell
# 1. 批量回流本周已发布未回流内容(指标自动从 attract 归因聚合)
Invoke-RestMethod -Method Post -Headers $H "$B/api/promo/learning/collect"

# 2. 触发学习(反馈≥min_feedback=10 才会成功; 不足会 409 提示)
Invoke-RestMethod -Method Post -Headers $H "$B/api/promo/learning/run"

# 3. 查看状态(产出挑战者 challenger)
(Invoke-RestMethod -Headers $H "$B/api/promo/learning/status").data

# 4. 运营确认后晋升挑战者为冠军(雷达评分权重即时切换)
Invoke-RestMethod -Method Post -Headers $H "$B/api/ai-learning/promote/promo_hotspot"
# (具体晋升端点以 routes/ai_learning_routes.py 为准; 也可在 AI 学习看板操作)
```

### 3.4 手动 SEO 推送

```powershell
# 常规(当日已推 URL 自动去重)
Invoke-RestMethod -Method Post -Headers $H "$B/api/promo/seo/push"
# 强制全量重推(慎用)
Invoke-RestMethod -Method Post -Headers $H "$B/api/promo/seo/push?force=true"
# 推送记录
(Invoke-RestMethod -Headers $H "$B/api/promo/seo/pushes").data | Select-Object -First 5
```

## SOP-4 开启自动调度（验收通过后）

```powershell
# 1. 编辑 .env, 追加两行
#    PROMO_RADAR_AUTO=on
#    PROMO_PUBLISH_AUTO=on

docker compose -p zhuxiang-jiu up -d backend

# 3. 确认调度器已启动
docker logs zhuxiang-jiu-backend-1 2>&1 | Select-String "promo_radar_scheduler|promo_publish_scheduler"
# 判据: 两行 "started interval=900s/300s"

# 4. 如需自动学习(攒够10条反馈自动跑 Hedge)
# .env 追加 AI_LEARNING_AUTO=on 后同样重启
```

| 调度器 | 周期 | 行为 |
|--------|------|------|
| promo_radar_scheduler | 15 分钟 | 扫描→评分→自动决策（≥70 自动跟进） |
| promo_publish_scheduler | 5 分钟 | 到期内容出队发布 + 自动 SEO 推送 |
| ai_learning_scheduler | 6 小时 | 反馈≥10 自动 Hedge 学习（影子模式，晋升仍需人工） |

## SOP-6 故障排查速查

| 编号 | 现象 | 处置 |
|------|------|------|
| T-1 | `docker compose` 报 "project name must not be empty" | 命令加 `-p zhuxiang-jiu`（中文目录名所致） |
| T-2 | 容器 unhealthy / 启动失败 | `docker logs zhuxiang-jiu-backend-1`；常见为 Redis 未就绪（等 30s 宽限）或内存不足（检查宿主可用内存） |
| T-3 | 归因报表恒为 0 | 代码未含 b459c34 修复 → 升级代码；或内容短码为空（生成时被拒）→ 检查内容 complianceScore |
| T-4 | 生成 409 "冷却期内" | 同热点 48h 已产 2 条，正常保护；换热点操作 |
| T-5 | 发布 409 "单日上限" | 当日已发布/入队 ≥20（PROMO_DAILY_CAP）；次日恢复或调参 |
| T-6 | 审核 409 "数字无权威信源出处" | 溯源保护触发；在信源库 POST 补充对应条目后重新生成 |
| T-7 | real 模式回执仍 mock_fallback | 查 `receipt.error`：凭证未配（T-5 步骤核对 keyConfigured）或平台 API 失败（端点/版本校准） |
| T-8 | `learning/run` 409 反馈不足 | 先 `learning/collect`；或调低门槛 `PUT /api/ai-learning/config/promo_hotspot` `{"min_feedback":5}` |
| T-9 | Agent 全走规则轨 | `LLM_API_KEY` 未配/失效/配额尽；看板 agentTrace 徽章确认 |
| T-10 | attract clicks/funnel 500 | 旧版本 bug（b459c34 前版本）→ 升级 |

**紧急止血（不回滚）**：`.env` 将 `PROMO_RADAR_AUTO`/`PROMO_PUBLISH_AUTO` 置 off → `docker compose -p zhuxiang-jiu up -d backend`，停止自动调度，人工通道保留。

## 附录：请求速查

```powershell
# 公共请求头(36号全部端点需 admin)
$H = @{"X-Role"="admin"}; $B = "http://localhost:8000"

# 高频端点
# POST /api/promo/radar/scan                                   扫描
# GET  /api/promo/decisions?pendingOnly=true                   待裁决
# POST /api/promo/contents/generate        {"hotspotId":N,"platforms":["douyin"]}
# POST /api/promo/contents/{id}/review    {"approved":true}
# POST /api/promo/contents/{id}/publish   {"publishAt":""}     空=黄金时段
# POST /api/promo/publish/process                              出队发布
# POST /api/promo/learning/collect | /learning/run             回流|学习
# GET  /api/promo/report/overview | /learning/status           报表|状态
# GET  /api/promo/channels/status | /api/promo/seo/pushes      通道|SEO
```

PowerShell 注意事项：JSON body 含中文时用 `-Body ([System.Text.Encoding]::UTF8.GetBytes($json))` + `-ContentType "application/json; charset=utf-8"`（见 SOP-1 步骤 5.4）；日期表达式必须括号 `(Get-Date).ToUniversalTime()`。
