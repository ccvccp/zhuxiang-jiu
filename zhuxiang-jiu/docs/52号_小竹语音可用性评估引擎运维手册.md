# 52号·小竹语音可用性评估引擎 运维手册

> 适用版本：v1（P0-P5 六期全线交付）
> 部署形态：FastAPI 模块（zhuxiang-jiu/backend）+ Redis（容器态）/ 内存（本地态）
> 运维目标：五维指标可观测、告警可处置、开关可回退——评估面永不阻断主链路

---

## 一、开关矩阵

| 开关 | 默认 | 作用域 | off 语义 |
|------|------|--------|---------|
| `US52_MODE` | off | 计算面+测试面 | 409 拒绝（registry/dimensions/快照/报告/告警/看板等**观测面不受影响**） |
| `US52_ALERT_MODE` | off | 告警调度闸 | 调度器不启动；POST /alerts/scan 409（与 US52_MODE 双开关——均须 on） |
| `US52_ALERT_SCAN_INTERVAL` | 86400 | 调度周期秒 | 下限 300（5 分钟）防忙循环 |

**开启告警调度（生产）**：

```bash
# 容器环境变量（docker-compose.yml 或部署平台）
US52_MODE=on
US52_ALERT_MODE=on
US52_ALERT_SCAN_INTERVAL=86400   # 可省略——默认 24h
```

> 双开关设计：先开 US52_MODE（计算面），再开 US52_ALERT_MODE（调度）。任一 off 调度即停——避免半开状态（调度跑空轮）。

## 三、告警处置 SOP

### 3.1 告警分级

| level | 类型 | 处置时限 | 动作 |
|-------|------|---------|------|
| veto | baseline（veto 域） | 立即 | 禁止上线/发布；修复后重跑红队+回归 |
| warn | baseline（其余维） | 限期 | mandatory 决策语义——限期修复并回归 |
| info | drift（动态漂移） | 观察 | 查看趋势（连续 3 日漂移升级为根因排查） |

### 3.2 排查路径

```
GET /dashboard                     → 定位 failing 维度+指标
POST /metrics/{dim}                → 单维详情（detail 统计字段）
GET /alerts?dimension={dim}        → 告警历史（occurrences 频次）
GET /metrics/snapshots             → 快照趋势（恶化拐点定位）
POST /reports/generate             → 生成报告（信值合规影响评估章节给出缓解建议）
```

### 3.3 常见告警根因

| 告警指标 | 常见根因 | 处置 |
|---------|---------|------|
| injection_defense_rate (veto) | 49/51号红队 breached>0 | 查红队报告——注入防线回溯修复 |
| degrade_compliance_rate (veto) | fallback 审计 error 含技术术语（traceback/内部错误等） | 48号降级话术模板修订 |
| budget_exhausted_guide_rate (veto) | 预算 fallback 话术缺"偏好/明日/调整/设置"引导 | 49号 429 语义话术修订 |
| trust_gain_index (warn) | corpus 采纳率/申诉翻转率/授权/礼貌留存四源低迷 | 45号回流处置+50号行为运营 |
| control_sense_rate (warn) | 隐私账户 preference 全默认（无用户行使控制权痕迹） | 会员触点引导（合规话术） |
| intent_parity_gap (warn) | 群体组间命中差>0.05 | 方言/语速适配（50号三场景系数复核） |
| feedback_health_ratio (drift) | 零分反馈占比上升 | 负面反馈根因归类（48号话术修订） |

### 3.4 告警风暴防护

当日同键去重已内建：同指标同类型当日一条（occurrences 累加）——**无需人工去重**。若跨日告警激增，检查：
- 红队测试是否异常高频跑（injection_defense 数据源）
- 48号 fallback 审计是否有异常写入（degrade 数据源）

## 六、故障处置

| 现象 | 诊断 | 处置 |
|------|------|------|
| POST /alerts/scan 409 | 开关未开（响应 detail 说明哪个开关） | US52_MODE+US52_ALERT_MODE 均置 on |
| 看板全空态 | 无快照（评估从未跑过或刚清库） | POST /alerts/scan 或 /metrics/compute 落首快照 |
| 告警去重失效（重复告警激增） | 跨日正常去重边界；或 dedupKey 数据异常 | 查 Redis `us52:alerts:day_index` 键格式 `{metricKey}:{alertType}|{YYYY-MM-DD}` |
| 报告列表空（Redis 态） | P4 前旧版本缺陷（已修复） | 确认部署版本≥56d7a3b |
| 决策=regression | 请求带 sacrificeFlags（负向改进红线触发） | 属预期铁律——检查是否真的牺牲了隐私/可解释性/公平性 |
| 红队跑超时影响 scan 耗时 | resilience 内嵌 49/51号红队真跑（26 用例） | 属预期（每轮 scan 约 5-10s）；高峰期错峰调度 |

## 七、回滚预案

| 层级 | 操作 |
|------|------|
| 一级（关调度） | US52_ALERT_MODE=off → 重启容器（调度停，其余功能不变） |
| 二级（关计算） | US52_MODE=off → 计算面/测试面 409（观测面/看板仍可用——历史数据可查） |
| 三级（整模块下线） | 代码回退至 a35edb4^（52号纯增量——回退不影响 48-51号任何功能） |

> 52号为纯只读聚合模块：**任何层级回滚均不影响主链路业务**（48-51号零依赖 52号）。

## 八、数据保留

| 数据 | 保留 | 清理 |
|------|------|------|
| 指标快照 | 长期（回溯可比） | 无自动清理（量小：每轮 1 条） |

| 阈值告警 | 长期（occurrences 累计） | 人工：DEL zhuxiang:us52:us52_alerts:* |
