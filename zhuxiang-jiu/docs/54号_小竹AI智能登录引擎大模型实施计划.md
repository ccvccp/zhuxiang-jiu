# 54号·"小竹"AI智能登录引擎大模型（自进化闭环）实施计划

> 依据：《"小竹"AI智能登录引擎AI大模型模块规划方案》——"安全底座+信值原生创新"混合架构；将国内头部厂商验证的"工业级能力"转化为"信任交付体验"；**大模型具有自主学习进化和自主升级功能**
> 定位：53号交付了登录引擎的"编排骨架"（五通道+四级响应），54号为其注入**自进化大脑**——登录决策回流 → 在线学习 → 权重演进 → 挑战者晋升 → 版本自主升级 → 漂移监控治理
> 架构原则：**复用 44号学习闭环+46号治理红线+53号事件流水，零重复造轮子**——"大模型"不是新训练一个 LLM，而是把登录决策体系建成一个**持续自我优化的在线学习系统**（Hedge 在线学习+Champion/Challenger 版本管理——成熟 MLOps 范式）

---

## 一、模块定位与架构

### 1.1 自研"大模型"的技术内涵（对照头部厂商范式）

| 国内头部范式 | 本站对应 | 54号落地 |
|-------------|---------|---------|
| 蚂蚁 IFAA 风控大脑（决策回流自优化） | 44号 Hedge 在线学习（已建成） | 登录决策事件回流接入学习闭环 |
| 腾讯天御 Champion/Challenger 灰度 | 44号双轨制+晋升评估（已建成） | 登录模型版本自主升级 |
| 华为 ModelArts 漂移监控+治理 | 46号三检测器+冻结守卫（已建成） | 登录模型健康监测+升级红线 |
| LLM 归因解释（可解释 AI） | 46号 P4 LLM 归因先例 | 登录权重变更自然语言归因 |

### 1.2 自进化闭环架构

```
【53号登录编排(生产)】
  events 六字段审计(riskScore/decision/...)
        │
        ▼ ①决策回流管道(54号新建)
  登录真值标注(成功后行为/申诉/凭证失败/风控拦截
  → 正当/恶意/中性 reward)
        │
        ▼ ②自主学习进化(44号 Hedge 循环)
  因子影响度乘性更新+护栏约束[0.5,2.0]倍+归一化
  → challenger 影子版本
        │
        ▼ ③评估晋升(44号 _challenger_better)
  rewardAlignment+accuracy 双指标
  → auto_apply 晋升 champion(自主升级)
        │
        ▼ ④漂移监控(EMA)+健康检测(46号三检测器)
  偏离基线告警/版本事件溯源
        │
        ▼ ⑤治理红线(46号)
  冻结守卫(暂停学习)+变更审批+人工回滚
```

### 1.3 模型档案设计（44号 SCORER_REGISTRY 新增第 29 档案）

```python
# services/ai_learning_service.py SCORER_REGISTRY 新增:
"login_orchestration": {
    "label": "小竹登录引擎编排评分",
    "module": "54登录大模型", "batch": 13},
```

**八因子权重模型**（登录场景原生——对齐 53号 `_risk_score` 上下文）：

| 因子 | 默认权重 | 口径（数据源全部已在 53号 events 留痕） |
|------|---------|------|
| channel_success | 0.15 | 通道历史成功率（byChannel 聚合） |
| credential_quality | 0.15 | 凭证类型强度（bio>voice>qr） |
| device_match | 0.15 | 基线指纹匹配度档位 |
| budget_sufficiency | 0.10 | 隐私预算余量 |
| member_maturity | 0.10 | 账龄+登录频次 |
| fail_history | 0.15 | 同通道失败计数 |
| voice_confidence | 0.10 | 声纹初筛+活体分 |
| portal_state | 0.10 | 角色四态（new/dormant 加权） |

输出 0-100 风险分 → 四级响应（silent/one_tap/step_up/enhanced——对齐 53号 RISK_TIERS）。

> 红线：`auth_risk`（43号 8 因子）**保持独立零改动**——54号模型与之**并行评分取 max**（双模型互补，不替换不侵入）。

## 二、数据模型（2 表，前缀 login54）

| 表 | 主键 | 用途 |
|----|------|------|
| login54_feedback | feedbackId | 登录决策回流标注（eventId 关联+reward+标注源） |
| login54_model_events | eventId | 模型生命周期事件（学习轮次/晋升/回滚/漂移——版本溯源） |

复用 44号既有：`ai_learning_profiles`（champion/challenger/历史版本）+`ai_learning_feedback`（跨模块反馈池）——54号反馈双写（本表+44号池，走 44号既有 record 接口）。

## 三、决策回流管道（真值标注口径）

| 信号源（53号已有数据） | reward | 说明 |
|----------------------|--------|------|
| 登录成功+后续驻留（retention 领取/导览请求） | +1.0 | 正当（allow 正确） |
| 登录成功+5 分钟内无行为+退出 | +0.3 | 弱正当 |
| 凭证失败 3 次+切换通道成功 | -1.0 | 恶意倾向（挑战正确） |
| 风控拦截后申诉成立（43号 decide_appeal） | -1.0 | 误拦——**负反馈修正模型** |
| 风控拦截后无申诉 | +1.0 | 拦截正确 |
| 令牌重放/跨会员盗用（红队向量） | -1.0 | 对抗样本 |
| 43号 riskFlagged 高危会员登录 | -0.5 | 人工标注兜底 |

**回流时机**：登录事件落库时（同步挂钩）+T+1 批次补标（驻留信号延时可得——调度器 46号 P6 范式）。

## 四、自主升级机制（版本生命周期）

1. **学习轮次**：`min_feedback=10` 待学习反馈 → Hedge 更新 → challenger 产出（44号 run_learning_cycle 复用）
2. **晋升评估**：rewardAlignment 优先+accuracy 兜底（44号 _challenger_better 复用）——`auto_apply=True`（54号档案配置——登录场景样本充足可自主升级；护栏 2.0 倍防失控）
3. **版本快照**：每次晋升落 login54_model_events（versionId/champion 权重快照/评估指标）——审计+回滚依据
4. **自主回滚**：晋升后指标回退（滑动窗口 rewardAlignment 下降>阈值）→ 自动回退上一版本+冻结学习+告警
5. **治理红线**（46号范式全继承）：
   - 冻结守卫：is_frozen(login_orchestration) → 学习跳过
   - 变更审批：人工覆盖权重走审批总线
   - 健康三检测：stagnation（版本停滞）/exhaustion（反馈枯竭）/high drift（漂移）

## 六、分期实施计划（P0-P5）

### P0 模型注册+评分器
- `login_orchestration` 档案注册（SCORER_REGISTRY 第 29 档案+default_weights 八因子+DECISION_THRESHOLDS 四级）
- `Login54Scorer` 评分器（八因子→0-100→四级响应；与 auth_risk 并行取 max）
- 53号 `_risk_score` 接入双模型（max 合成——零侵入可选开关）
- 测试：专项约 18 断言
- QC：因子覆盖 53号 events 全上下文；44号既有档案零改动

### P1 决策回流管道
- `login54_feedback` 表+回流标注引擎（七类信号源→reward）
- 同步挂钩（登录事件落库时）+T+1 补标（调度器）
- 44号反馈池双写（record 接口——学习闭环数据源）
- 测试：专项约 20 断言
- QC：申诉负反馈回流（误拦修正）；红队对抗样本回流

### P2 自主学习进化
- 学习轮次触发（min_feedback=10）+Hedge 更新（44号 run_learning_cycle 复用）
- 护栏验证（[0.5,2.0] 倍）+ 归一化断言
- 影子评分对比（challenger vs champion——模拟决策对比）
- 测试：专项约 18 断言
- QC：权重演进单调收敛；灾难性遗忘防护（replay）

### P3 自主升级+回滚
- auto_apply 晋升+版本快照（login54_model_events）
- 滑动窗口指标回退检测→自动回滚+冻结
- 手动晋升/回滚端点（人工兜底）
- 测试：专项约 20 断言
- QC：晋升-回滚闭环；版本历史可溯

### P4 漂移监控+健康治理
- EMA 漂移监控（DRIFT_ALPHA 0.1 复用）+46号三检测器接入
- 冻结守卫+变更审批联动（46号 is_frozen）
- LLM 归因报告（LLM_ENABLED 依赖+fail-soft）
- 测试：专项约 18 断言
- QC：漂移告警；冻结期间学习跳过

### P5 看板+红队收官
- 引擎大模型看板（版本/因子/回流/漂移四区）
- 红队：权重投毒（伪造反馈操纵权重）防御——护栏+异常标注检测
- 三件套文档+宪法断言（44/46/53号零改动）
- 测试：专项约 20 断言
- QC：投毒防御；全链零回归

**开关矩阵**：`LOGIN54_MODE`（默认 off——off=模型面关闭：53号编排用 auth_risk 原轨，零影响）；`LOGIN54_LEARN_MODE`（学习调度，默认 off——双开关铁律，52/53号范式）。

## 七、风险控制矩阵

| 风险 | 缓解 | 验证 |
|------|------|------|
| 权重投毒（伪造反馈操纵模型） | 护栏 [0.5,2.0] 倍+标注源可信度加权+异常率检测 | P5 红队 |
| 自主升级翻车（新版本劣化） | 滑动窗口回退自动回滚+冻结+人工兜底 | P3 断言 |
| 双模型冲突（54号 vs 43号 auth_risk） | 并行评分取 max（保守合成——不替换不侵入） | P0 断言 |
| 灾难性遗忘 | replay 经验回放（44号 v7.9 机制） | P2 断言 |
| 学习风暴 | min_feedback 门槛+轮次频控+冻结守卫 | P4 断言 |
| 误拦负反馈污染（申诉滥用） | 申诉成立才负反馈（43号 decide_appeal 裁决真值） | P1 断言 |
| 模块侵入既有评分 | login_orchestration 独立档案——44号既有 28 档案零改动 | 全期宪法断言 |

## 八、治理红线（46号范式全继承）

1. **冻结守卫**：is_frozen(login_orchestration) → 学习/晋升全跳过
2. **变更审批**：人工权重覆盖走审批总线（审批翻转+重复索引防护）
3. **版本可溯**：每次晋升落快照（权重+指标+触发源）
4. **一键回滚**：reset_weights+指定版本回滚（两通道）
5. **漂移告警**：EMA>0.25 high 档告警（当日同键去重）
6. **双开关 off 默认**：LOGIN54_MODE/LOGIN54_LEARN_MODE 均默认 off——零影响交付

## 十、结语

原方案价值锚点：**"小竹"智能登录引擎 AI 大模型不是对海外 FIDO 的复刻，而是把国内头部厂商验证过的工业级能力（决策回流/双轨灰度/漂移治理）转化为信任交付体验。** 44号交付了通用学习闭环，53号交付了登录编排骨架，54号让登录引擎拥有**持续自我优化的大脑**——每一次登录都在让下一次登录更懂你，而护栏与治理确保这份进化永远在安全区间内。

> 技术只是骨架，对人的敬畏才是灵魂——模型的每一次自主升级，都必须能向用户解释"为什么"（归因），能被治理叫停（冻结），能回到昨天（回滚）。
