## 二、十三期核心交付

### P0：安全网关中间件 + 威胁评分（第26档案）
- **ASGI 网关**（JWTAuthMiddleware 范式平移）：挂载次序 CORS(外) → **SecurityGateway(中)** → JWT(内)——攻击请求在进入鉴权层之前被评分拦截；白名单快道；BodyPeeker 请求体预读回放
- **ThreatGateScorer 六因子**：IP信誉 0.20 / 请求频次 0.20 / 注入特征 0.25 / 路径异常 0.10 / 身份风险 0.15 / 时空异常 0.10 → 四档处置（≥70 allow / 50-70 throttle 渐进延迟 / 25-50 challenge / <25 block）
- **确定性攻击硬规则**：任一注入特征/探针路径命中 → 至少 challenge；多类特征叠加 → 直通 block（防单信号被加权合议淹没）
- **攻击特征库**：SQLi/XSS/路径遍历/命令注入/扫描器 UA 五类正则 + 探针路径 + query URL 解码（防编码绕过）
- **IP 信誉库三态**：冷启动 80 / 扣分 -10~-60 / 冷却恢复 / 钉住；封禁 TTL 自动解封
- **防误杀三保险**：observe/shadow/enforce 三级灰度 / fail-open / `SECURITY_GATEWAY_MODE=off` 一键回退

### P1：挑战验证 + 申诉双通道 + enforce 四档处置
- **挑战通行证**：应答验证 → IP 通行证 TTL 900s 豁免挑战档（豁免仍留痕 `challenge_exempt` 可申诉）
- **误报申诉双通道**（42号范式平移）：会员申诉（一事件一申诉幂等）→ 管理裁决 `approve` → 事件置 false_positive + **IP 信誉返还 + 自动解封**
- **事件直接裁决**：管理端确认攻击/误报——**学习真值源**

### P2a：UEBA 行为基线（四层流水线）
- **采集层（零侵入）**：网关顺带三维计数直方图（memberId × hour × module）+ 管理端审计日志只读聚合
- **基线层**：双层基线（个人 → 同角色全局兜底 → 双缺完全豁免，新会员零误报）
- **检测层**：D1 时段偏离 / D2 频率偏离（P95×3 防养号）/ D3 敏感功能首次触碰 / D4 试探堆积
- **联动层**：偏离分注入 identity_risk（只降不升）+ behavior_alert 入事件流水复用裁决链

### P2b：态势三态自动升降级 + 学习回流（智能自主升级）
- **三态**（对标 Cloudflare Under Attack Mode）：peace ×1.5 / alert ×1.0 / wartime ×0.3——防线随攻击密度 EMA 自动升降级（滞后防抖：连续 2 窗口越线才转换）；pinned 钉住优先
- **学习回流三连**：collect（裁决真值批量回流，eventFed 幂等）→ run（Hedge 一轮学习）→ 六因子权重自动调优

### 管理面板：七区块前端
- [ai-security-dashboard.html](../ai-security-dashboard.html)：态势卡（手动切换/钉住）/ 攻击事件（一键裁决+因子展开）/ 申诉队列 / IP 处置 / UEBA 基线（直方图可视化）/ 学习回流三连 / **运营成熟化（P4-4：日报序列柱状图+Redis 实况体检）**

### P3-1：网关响应钩子（D4 完整收口）
- **_SendWrapper 响应观测层**：捕获状态码其余透传（响应语义零改写），全部放行路径统一经 `_finish`（fail-open）
- **403/401 加权堆积**（24h 滚动，401 计 0.5）：网关管线实时查询 → D4 完整落地（替换参数化口径）

### P3-2：真实验证码三态通道（极验 v4 / hCaptcha）
- [captcha_client.py](../backend/services/captcha_client.py)：mock/real/mock_fallback 三态（41号范式平移），HMAC 签名头 + httpx 重试
- **票据一次性消费**（SHA256+SETNX 防重放）；**real 态旧口径拒绝**（无票据应答一律 409，堵死脚本绕过）
- 会员挑战页 [challenge.html](../challenge.html)（验证通过自动返回原页面）
- **real 轨待极验凭证**（.env 配置即启用，mock 轨全链路已实机验证）

### P3-3：GeoIP + 设备指纹（geo 精细化）
- [geoip_service.py](../backend/services/geoip_service.py)：GeoLite2 离线库**纯 stdlib** mmdb 二分检索（零外部依赖，缺失静默关闭）
- **设备指纹**（复用 39号信任设备表）：陌生设备打敏感端点降 60 分；信任设备数 ≥3 撞库信号降 40 分
- **异地跳变**：2h 滚动窗口地理历史（mmdb 放入 `./data/` 即启用）；**XFF 反代头**第一跳
- 顺带修复 39号 `entry_repository.save_device` memberId 未落记录体的存量缺陷

### P3-4：登录序列建模（D5 跳步检测）
- **auth_event 留痕钩子**：登录成功/失败入 security_events（火后不管）；**撞库预警**（24h 失败堆积 ≥5 自动生成 behavior_alert）
- **会话序列**：登录标记 `__login__` 起点 + 最近 5 module 环形缓冲（TTL 对齐 JWT 2h）
- **D5 跳步检测器**：真会话 + 登录后 3 请求内直奔敏感端点 + 无常规浏览 → identity_risk 降 20（仅降分不处置，observe 口径）
- 真会话校验（`__login__` 起点防未登录流量误检）

### P4-1：SOC 安全运营日报（D5 联动决策数据底座）
- [soc_report_service.py](../backend/services/soc_report_service.py)：按日聚合事件分布/裁决误报率/申诉/态势时间线；`daily_report` 单日 + `daily_series` 近 N 天序列（汇总+D5 样本）
- **D5 专项观测端点**（联动决策硬标准）：≥14 天观察期 + 误报率 <5% + 样本 ≥20 三条件齐备才建议参与强制联动——用数据说话，不拍脑袋上线
- 2 新端点：`GET /admin/reports/daily`（单日/序列双口径）+ `GET /admin/reports/d5`

### P4-2：UEBA 基线日度调度器（自动化基线维护）
- [security_scheduler.py](../backend/services/security_scheduler.py)：仿 9 类调度器范式——`SECURITY_AUTO_MAINTAIN` 默认 off 主动开启可配，周期间隔可调
- **分批节流**（每批 100 actor，批间 sleep）防事件循环饿死；**姿态空窗评估**（EMA 降级不被饿死）；**基线健康度告警**（覆盖 actor 数/采样天数）；统计留痕
- 容器内单轮手动触发全链路实机验证

### P4-3：威胁情报外源接入（Firehol netset）
- [threatintel_service.py](../backend/services/threatintel_service.py)：Firehol IPList（CC0 许可）netset 解析（注释/IP/CIDR/去重/规范化 /32/上限 2 万段防误传撑爆存储）
- **CIDR 匹配**：ipaddress 标准库线性匹配（<10k 段可接受，>10k 改前缀树留 P5）
- **信誉联动（防误杀核心设计）**：网关 `ensure_reputation` 后置检查——命中情报段 → 信誉降档 **31**（suspicious 区间 30<x≤60，**不直封**，防情报段误伤共享出口 IP）；降档事件留痕可申诉；已降档不重复降
- 3 新端点：`POST /admin/threatintel/import`（幂等全量替换/增量）+ `GET /admin/threatintel/stats` + `GET /admin/threatintel/check`
- 异常不阻断网关（情报服务故障零影响）

### P4-4：Redis 实况监控 + 看板第七区块（运营成熟化收官）
- [redis_health_service.py](../backend/services/redis_health_service.py)：INFO 内存水位（used/max/碎片率/淘汰策略）+ DBSIZE + **键族 12 族计数**（`zhuxiang:security43:` 前缀分类，threatintel 复用 posture 表的嵌套归位）+ SLOWLOG Top10（list/dict 双口径兼容）+ **大 key 抽查**（Hash 族 MEMORY USAGE，封顶 500 防大库扫描）
- **三档阈值告警**：单键 >100KB 建议归档清理 / rate 键 >100k 窗口泄漏检查 / 内存 >80% maxmemory 扩容评估（+碎片率 >1.5 info 级）
- 1 新端点：`GET /admin/redis/health`（admin 鉴权，**手动触发**——KEYS/SLOWLOG 有执行开销，不进 30s 自动刷新）
- **看板⑦区**：近 14 天日报序列纯 CSS 柱状图（hover 误报率，零图表库依赖）+ 汇总 6 卡 + Redis 实况体检按需加载（告警条/内存水位卡/键族表/慢日志）
- 阈值口径写入操作指南 §八

## 五、交付过程中的关键修复（14 项）

| 问题 | 修复 |
|------|------|
| 单次 SQLi 被加权合议淹没（86 分仍放行） | 确定性攻击硬规则：单特征至少 challenge、叠加直通 block |
| URL 编码攻击绕过 | 扫描前 `unquote_plus` |
| 非 /api 探针路径绕过（`/.env`） | 放开快道前缀限制 |
| 通行证豁免后审计断链 | 豁免留痕 `challenge_exempt` 且可申诉 |

| manual 态势模式不生效 | 实时读环境变量（记录值仅留痕） |
| verify_challenge await 缺失 | D2 查询补 await |
| finance 仓储 Redis WRONGTYPE（42号遗留） | seq 键过滤 `":X:seq" not in k`（4 处） |
| 根目录 pytest 18 项假失败 | 根级 pytest.ini（目录陷阱根治） |
| 39号 save_device memberId 未落记录体 | 修复（P3-3 依赖暴露） |
| D5 误检未登录流量 | 真会话校验（`__login__` 起点标记） |
