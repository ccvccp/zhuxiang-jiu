## 一、变更背景

2026-09-17 订单全流程 E2E 测试（下单→签收 17/17 通过）提出"运费规则"观察项。排查发现三层问题：

1. **结算页金额与实付不一致**：checkout 结算页价格明细硬编码 L5 85 折且漏运费——88 元 1 瓶页面显示 74.8，实际实付 80.4（后端 L5 为 8 折 + 运费 10 元）。
2. **用户协议文案与真实链路不符**：协议写"购买两瓶免运费，否则 ¥12 运费"——该口径描述的是前端降级 mock 链（且金额与 checkout 后端实际的 ¥15 也不符），而真实用户链是"满 ¥99 免/¥10"。
3. **三条下单链运费规则不一致**（见下表）。

## 二、规则变更对照

### 变更前（三链并存，口径分裂）

| 链路 | 端点 | 运费规则 | 前端消费 |
|---|---|---|---|
| order | /api/order/* | 折后满 ¥99 免 / ¥10 | **真实用户链**（结算页首选） |
| checkout | /api/checkout/submit | 满 **2 瓶**免 / **¥15**（按数量） | 后端存在、前端不首选（降级 mock 用） |
| xinzhi | /api/xinzhi | 折后满 ¥99 免 / ¥10 | 心智页（此前已对齐） |

### 变更后（三链统一）

> **统一规则：折后金额（会员折扣 + 满减 + 优惠券 + 积分抵扣后）满 ¥99 免运费，未满收取 ¥10 运费。**

三链全部对齐上述口径，计算语义与 `order_service._calc_price` 的 `after_points >= 99` 一致。

## 五、影响面与兼容性

- **真实用户链（order）零行为变化**：统一以 order 为基准，order 链未改动。
- **checkout 端点行为变化**：低折后金额（< ¥99）订单运费从 ¥15 降为 ¥10；单瓶高价（≥ ¥99）从收 ¥15 变为免运费；两瓶免运费规则由金额门槛取代。前端结算页不首选该端点（仅降级 mock 路径），实际影响面为 API 直连调用方。
- **协议文案已同步**，与统一后规则一致。
- 顺带修复：工作区 71 个历史双 BOM 污染文件（PowerShell 重定向遗留，SyntaxError 风险）经 `git diff --numstat` 全量识别后用 Python 二进制层无损去重修复。
