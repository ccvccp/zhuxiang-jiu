# 秒杀首场试运营操作手册（SOP）

> 适用：限时秒杀模块（/api/flash）· 生成于 2026-10-04 检查升级后
> 前提：超时回补调度已开（FLASHSALE_EXPIRE_AUTO=on，60s 心跳）、
> 智法价格审计已真实化（加品自动检测三项价格风险）
> 操作端：taro-app（H5：zxjiu.com 首页 → 我的 → **秒杀管理**）

---

## 〇、前置确认（2 分钟）

| # | 确认项 | 方法 |
|---|---|---|
| 1 | 管理台可达 | H5 登录 zxjiu.com →「我的」页 → 点「秒杀管理」进入工作台（三页签：场次管理/风控参数/运营统计）；非 admin 账号会被拦截 |
| 2 | 调度心跳在转 | 服务器 `docker logs zhuxiang-backend-1 --since 5m | grep flashsale` 应见 `flashsale_expire_scheduler started`（每 60s 自动取消超时未支付订单并回补库存） |
| 3 | 候选商品 | 从主站商品中选 1-2 款（参考锚点：ZX42-2026L07 ¥268 / ZX42-2026B01 ¥88 / ZX45-2026L05 ¥368）；**秒杀价必须低于商品现售价**，否则加品被拒 |

## 一、建场次（场次管理页签 →「创建场次」）

| 字段 | 示例（试运营建议） | 规则 |
|---|---|---|
| 场次名称 | `试运营·竹香首闪` | 非空 |
| 开始时间 | 明晚黄金档如 `2026-10-05T20:00:00+08:00` | ISO8601 **带 +08:00 时区**（工作台已自动转换） |
| 结束时间 | `2026-10-05T21:00:00+08:00` | 必须晚于开始且晚于当前 |

建后为**草稿态**——草稿才可编辑/加品。

## 二、加商品（场次卡 →「添加商品」）

| 字段 | 试运营建议 | 规则 |
|---|---|---|
| 产品 ID | 如 `ZX42-2026B01`（原价 ¥88） | 须为存在商品 |
| 秒杀价 | `69.0`（≈78 折，低于会员价 ¥79.2 更佳） | **必须低于现售价** |
| 秒杀库存 | `10`（小量试水） | ≥1；注意不扣主库存（自包含口径） |
| 每人限购 | `1` | ≥1 |

**加品即自动智法价格审计**（先涨后降/划线价无依据/会员价虚标三检测）：
- 返回 `priceAudit.compliant=true` → 合规，继续
- 返回 findings（如"会员价虚标"=秒杀价高于会员价）→ **人工裁决**：
  调整秒杀价或接受风险，审计只留痕不拦截

## 三、风控参数（风控参数页签；试运营建议保持默认）

| 参数 | 默认 | 建议 | 说明 |
|---|---|---|---|
| 秒杀总开关 enabled | 开 | **开** | 应急时可秒关全场 |
| 注册时长要求 minRegisterHours | 0（不限） | `24`（防新号刷单） | 注册满 N 小时才可抢 |
| 会员等级要求 minMemberLevel | 0（不限） | `0` 保持 | 等级 ≥N 才可抢 |
| 订单超时分钟 orderExpireMinutes | 15 | **15** | 未支付订单自动取消+回补（调度 60s 巡检） |
| 单笔最大数量 maxQuantityPerOrder | 5 | `2` | 配合限购 |

## 四、发布与 C 端验证

1. 场次卡 →「**发布**」（空场次拒绝发布——先加品）
2. C 端验证（另一账号或同一手机）：首页底部 tab「**限时秒杀**」
   → 见场次卡（秒杀价/库存进度/限购/倒计时）→ 到点「马上抢」
3. 我的秒杀订单 → 支付（**当前为模拟支付**，真实网关对接列遗留）
4. 故意不支付一单 → **15 分钟后自动取消+库存回补**（观察调度）

## 五、试运营观察清单（运营统计页签 + 当日回看）

| 观察点 | 预期 | 位置 |
|---|---|---|
| 抢购正确性 | 10 库存 10 人抢恰好 10 单，超拍被拒 | 场次卡进度 + 统计页签 |
| 超时回补 | 未支付订单 15 分钟消失，库存回来 | 统计页签 soldCount 回落 |
| 智法审计留痕 | price_audits 表新增记录 | 法务看板「价格审计留痕」区块 |
| 调度日志 | `flash_expired_orders_cancelled count=N` | 服务器日志 |
| 会员防刷 | 新注册号/低等级按参数被拦（若设了门槛） | 抢购报错文案 |

## 六、应急操作

| 场景 | 操作 | 效果 |
|---|---|---|
| 立即停售 | 风控参数页签 → 总开关关闭 | 全场秒杀暂停（已下单不受影响） |
| 取消整场 | 场次卡 →「取消场次」 | 未支付订单全部取消 + 库存回补（逐商品持锁安全回补） |
| 单笔问题单 | 管理端订单操作/联系技术 | cancel_order 回补 |

## 七、试运营验收口径（收口标准）

- 全链人工走通一单：抢 → 支付（模拟）→ 统计可见
- 超时回补自动触发一次（不支付验证）
- 无审计 findings 或 findings 已人工裁决
- 验收通过后：首场数据存档，纳入次日四观察（秒杀项），并评估
  支付网关对接立项优先级

> 附：API 直连口径（技术侧备份）——建场 `POST /api/flash/admin/sessions`
> {name,startTime,endTime}；加品 `POST .../sessions/{id}/items`
> {productId,flashPrice,flashStock,limitPerMember}；发布
> `POST .../sessions/{id}/publish`；参数 `GET/PUT /api/flash/admin/settings`；
> 统计 `GET /api/flash/admin/stats`（均需 admin 身份）。
