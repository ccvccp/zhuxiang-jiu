# 51号 · 小竹可信知识图谱实施计划

> 定位：信值治理战略闭环**第九面——底座面**（沉默的基础设施）
> 服务对象：47号 UEBA 验真（验证面）/ 45+50号 信值溯源（社会面+确权面）/ 48号 小竹精准问答（交互面）
> 依据：用户提供《Value-UEBA 网站知识图谱构建 SOP》适配本站工程现实
> 铁律继承：off 默认直通 / 零不可逆 / fail-soft / 隐私红线 / 反语音霸权
> 模块编号：51号（全站编号止于 50号，31-34 空缺不复用）

---

## 一、模块定位

知识图谱在信值体系中不是通用百科式语义网络，而是**可信数据资产的结构化底座**——每一个三元组都可溯源（evidence_bundle）、可脱敏（digest-only）、可预算（49号隐私预算感知查询）、可退役（版本快照+retired 态）。

本模块补上代码中两处明确留白：

| 留白声明 | 位置 | 本模块回应 |
|---------|------|-----------|
| "graph 维度以证据内容质量代理……GNN 图谱轨列入外部待办" | `services/trust_verify_v2.py:53-55` | 轻量三元组图谱（非 GNN），供验真 v2 图维度调用（只读） |
| "GNN 图谱轨明确不落地（外部待办）" | `services/trust_risk_collusion_service.py:28-29` | 团伙嫌疑提供邻域查询视图（只读，47号零改动） |

**与既有知识库的区别**：站内 `knowledge_*` 系列是条目+版本表（文档库），51号是三元组+证据链+本体约束（图谱），二者互补不互替。

**与 28号"知识层(图谱)"的关系**：28号是决策筹划的规划愿景（未落地），51号聚焦信值/语音域先行落地，未来可复用本体范式。

## 二、原方案 SOP → 本站适配差异表（核心）

| SOP 通用方案 | 本站落地 | 适配理由 |

| 联邦学习联动更新 | P4 预留 Schema 演进队列（"模型发现→图谱沉淀"飞轮的队列半边） | FL 基础设施在外部待办；50号 record_fl_gradient 行为因子已存在，演进队列可接 |
| LLM 微调抽取 | `KG_EXTRACT_MODE` 三态（off/mock/real，默认 off）+ Prompt 内嵌本体约束 | 与全站 LLM 三态（mock/real/off）一致；mock 态可专项测试 |

| 人工标注员复核 | 复核队列 + admin 裁决端点（46号治理台账范式） | 站内已确立 admin 复核模式（45号申诉/50号 adjudication 180天） |

| Grafana 监控仪表盘 | 自有看板分区 + 46号巡检调度轨模式 | 站内无 Grafana 基础设施；看板即端点 |
| 热点查询 Redis 缓存 TTL | 查询结果缓存 + 写事件失效 | 双模式存储本身即 Redis 态，简化为表级缓存 |

## 三、MVP 范围与边界

### 3.1 实体类型（P0 注册 9 类，分优先级接入）

| 实体 | 对应站内资产 | 敏感度 | 接入期 |
|------|-------------|--------|--------|
| Member（会员） | 48号 voice48_bindings（trustId↔memberId） | L3 高敏——**仅存 digest** | P1 |
| VoiceBehaviorEvent（语音行为事件） | 50号 voice50_events（14 行为 evId） | L2 | P1 |
| Evidence（证据） | 50号 evidence / 47号 ev_sha 指纹 | L2 | P1 |
| TrustFactor（信值因子） | 45号九因子封闭注册表（只读引用） | L1 | P1 |
| PolicyClause（政策条款） | 18号条款协议 | L0 公开 | P2 |
| Product（产品） | 01号产品 | L0 公开 | P2 |
| RepairAction（修复动作） | 45号 submit_repair 通道留痕 | L1 | P3 |
| Institution（合作机构） | 16号代理商 / 21号酒店合作 | L1 | P4（扩展） |
| VoiceAnswer（问答锚定节点） | 48号问答 ground 引用 | L0 | P2 |

### 3.2 关系类型（9 种，含 domain/range 约束）

| 关系 | domain → range | 对应 SOP | 说明 |
|------|--------------|---------|------|
| performed_by | VoiceBehaviorEvent → Member | — | 事件归属（digest） |
| attested_by | VoiceBehaviorEvent → Evidence | issued_by 变体 | **证据链核心** |
| verified_with | Evidence → Evidence | verified_with | 双源互证（47号互证对） |
| contributes_to_credit | VoiceBehaviorEvent → TrustFactor | contributes_to_credit | 50号→45号映射 |
| governed_by | VoiceBehaviorEvent / PolicyClause → PolicyClause | governed_by | 18号条款治理 |
| triggers_repair | VoiceBehaviorEvent → RepairAction | triggers_repair | 45号修复通道 |
| grounds_on | VoiceAnswer → Product / PolicyClause | — | 小竹问答锚定 |
| references | Product → PolicyClause | — | 产品关联条款 |
| operated_by | Evidence → Institution | issued_by | 验证机构（P4 接入） |

### 3.3 排除项（对齐 SOP "小而精"）

- 纯娱乐内容、未经验证的 UGC 评论、非信值关联的商业广告
- 用户原始语音音频（音频即转即删铁律继承，图谱只接转写脱敏文本）
- 跨机构原始数据（PSI 外部待办）

### 3.4 红线原则（SOP 原文继承 + 本站强化）

> 图谱中不存储原始敏感数据，仅存**哈希标识符 + 脱敏属性 + 证据引用指针**。所有节点必须绑定 `source_ref` 字段。**无证据链的三元组标记 unverified，不参与信值计算。**

本站强化：
- 实体标识一律 digest（复用 49号 speaker_proxy_digest 范式），displayName 存 48号 mask_pii 后文本
- unverified 三元组**物理隔离于计分路径**（P1 专项断言 + P5 红队注入验证）
- 图谱查询敏感字段消耗 49号隐私预算，**预算额度与信值等级零挂钩**（公平性红线继承）

## 四、本体设计（P0 交付物形态）

```python
ONTOLOGY_REGISTRY = {
    "entities": {
        "Member": {
            "idPattern": "member:sha256:{digest}",
            "sensitivity": "L3", "privacyCost": 0.02,
            "allowedAttrs": ["digest", "trustTier", "memberSinceDay"],
            "forbiddenAttrs": ["phone", "idCard", "realName"],  # 启动自检断言
        },
        "VoiceBehaviorEvent": {
            "idPattern": "ev:voice50:{evId}",
            "sensitivity": "L2", "privacyCost": 0.01,
            "allowedAttrs": ["behaviorKey", "layer", "value", "status"],
        },
        # ... 9 实体齐备，每属性标注敏感度与隐私预算消耗值
    },
    "relations": {
        "performed_by": {"domain": "VoiceBehaviorEvent", "range": "Member",
                          "minCard": 1, "maxCard": 1},
        "attested_by":   {"domain": "VoiceBehaviorEvent", "range": "Evidence",
                          "minCard": 1},   # 无证据即 unverified —— 强制下限
        # ... 9 关系齐备
    },
}
```

- **QC（对齐 SOP 本体评审会）**：覆盖 ≥90% 信值计算所需字段（50号 14 行为×45号 9 因子映射全覆盖）；无歧义定义；法务合规审查对照全站红线清单
- 本体变更走**审批总线**（`kg51_schema_log` 表，46号 P0 变更审批总线范式）：提交→admin decide→留痕，禁止直改注册表
- 启动自检 `_validate_ontology()`：idPattern 唯一 / domain-range 类型合法 / forbiddenAttrs 与 mask_pii 白名单一致 / 9 实体 9 关系断言

## 六、数据模型

表前缀 `kg51`，Redis key = `zhuxiang:kg51:{table}:{id}`（序列化口径与 voice48 一致：bool→0/1，dict/list→JSON，None→""）：

| 表 | 主键 | 要点 |
|----|------|------|
| kg51_schema_log | changeId | 本体变更审批台账（P0） |
| kg51_entities | entityId | digest 标识 / labelMasked / sourceRef / sensitivity / status |
| kg51_triples | **tripleId（uuid——指纹独立于主键，教训继承）** | subject / predicate / object / evidence(JSON bundle) / sourceType / sourceRef / confidence / status(verified\|unverified\|retired) / version |
| kg51_reviews | reviewId | 复核队列（queueReason: confidence\|conflict\|feedback） |
| kg51_versions | versionId | 周度快照统计（实体数/三元组数/verified 占比） |
| kg51_inspections | inspectionId | 巡检结果（完整性/一致性/时效性三指标+issues） |
| kg51_feedback | feedbackId | 48号纠错→修订队列（fromTurnId → targetTriple） |

## 八、分期实施计划（P0-P5）

### P0 本体奠基（SOP 阶段1）
- 交付：ONTOLOGY_REGISTRY（9 实体/9 关系/属性敏感度+预算消耗值）+ 变更审批总线 + 启动自检
- 复用范式：50号 VOICE_RULES 注册表自检 / 46号变更审批总线
- QC：本体覆盖 ≥90% 信值计算字段；forbiddenAttrs 断言；变更必经审批
- 测试：专项约 24 断言（注册表完整性/domain-range/敏感度分级/审批流/自检）

### P1 证据链采集与抽取（SOP 阶段2+3）
- 交付：三源采集管道（系统源 50号 events 自动入 / 权威源 18号条款+01号产品 / 用户源 48号 turns 脱敏候选）+ evidence_bundle 强制绑定 + 置信度分级 + 复核队列 + 冲突解决（权威>系统>用户）
- QC：核心关系抽取 F1 ≥0.95（mock 已知数据集）；敏感字段零误抽；unverified 物理隔离于计分路径
- 测试：专项约 30 断言（14 行为映射/证据链/unverified 隔离/去重 uuid/复核流/冲突优先级）
- 教训继承：tripleId 用 uuid 唯一化（指纹去重教训）；跨模块种子数据测试后清理

### P2 存储与服务（SOP 阶段5）
- 交付：查询 API（triples/query/grounding）+ 权限过滤矩阵（admin/会员/公开三级）+ 隐私预算织入（49号 check_and_spend）+ 查询缓存 + off 态降级
- QC：P99 <100ms；权限过滤 100% 生效；预算扣减正确；grounding 零成本（L0）
- 测试：专项约 28 断言（查询正确性/权限矩阵/预算扣减/缓存失效/off 直通降级）

### P3 溯源与验真联动（SOP 阶段4 + UEBA 支撑）
- 交付：信值溯源 API（45号 deposit→50号 event→证据链→48号 turn 全路径渲染）+ 47号团伙邻域查询视图（只读）+ verified_with 互证关联 + RepairAction 接入
- QC：溯源完整率 100%（任意 evId 可渲染证据链）；47号代码零改动
- 测试：专项约 26 断言（溯源路径/邻域查询/互证关联/修复关联）

### P4 治理与演进（SOP 阶段6）
- 交付：日度巡检调度（KG_INSPECT_MODE 默认 off，46号调度轨范式）+ 周度版本快照+回溯查询 + 公平桥→46号 + 48号纠错反馈→修订队列 + Schema 演进队列（飞轮预留）+ Institution 实体接入 + 看板
- QC：巡检三指标（完整性/一致性/时效性）；版本可回溯；公平分组覆盖率上报（不足组不上报，50号 MIN_GROUP_SAMPLES 同范式）
- 测试：专项约 24 断言（巡检/版本/公平桥/反馈闭环/调度 off 态）

### P5 红队测试与收官（SOP 风险矩阵验证）
- 交付：红队五类攻击向量跑真网关 + 三件套文档（验收报告/交付总结/运维手册）
- 红队向量：
  - A 虚假三元组注入（无证据链→必须 unverified，无法进入计分路径）
  - B PII 探测（digest-only 强制——原始手机号/身份证/卡号入库即阻断）
  - C 预算绕过（伪造成本字段/直连内表——49号红队 RT-04~06 同思路）
  - D 越权查询（会员面查他人实体/伪造 admin）
  - E 一致性污染（篡改本体注册表绕过审批总线）
- 零改动断言：48号 21 端点 / 49号 17 工具注册表 / 50号 14 行为注册表全量比对
- 测试：专项约 20 断言 + 实机 ×2 轮幂等

**开关矩阵**：`KG_MODE`（总开关，默认 off——off=采集停+查询降级返回空态，fail-soft 直通）/ `KG_EXTRACT_MODE`（off/mock/real，默认 off）/ `KG_INSPECT_MODE`（默认 off）。默认态全站零影响。
