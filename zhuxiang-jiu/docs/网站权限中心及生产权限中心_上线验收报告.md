## 五、缺陷修复实录(生产事故级)

### 5.1 Redis 种子漂移事故

- **现象**: 首轮部署后公网 GET /api/perm/nodes 仅返回 `total 32`,
  centers 只有 production——容器内种子检查全过(读代码内 _SEED_NODES),
  但 API 读的是 Redis 存量表;
- **根因**: 旧版 `_ensure_nodes_seeded_redis` 惰性种子"已有数据即
  跳过"(keys 非空直接 return)——生产 Redis 已存量 32 节点, 新增
  20 网站节点永不落库、存量节点缺 center/centerName 字段;
- **修复**: 重构为**进程级幂等漂移同步**(`_NODES_SYNCED` 模块标记):
  - 按 code 比对追加缺失种子节点(全量字段);
  - 存量节点仅回填 center/centerName 两字段(其余字段不动);
  - 每进程只跑一次, 不影响 get_node_by_code 权限校验热路径;
- **验证链**: fakeredis 本地模拟生产存量(legacy 32 → 52/回填/幂等
  三项)→ 二次部署 → 公网 52 复验 → 固化为 test_perm_center.py
  回归测试。

### 5.2 沉淀教训

种子惰性初始化模块做结构升级时, "表非空即跳过"会导致**存量环境
永不升级**——容器内验证(读代码常量)全过而 API(读存量存储)失败,
**部署后必须公网实证数据面**; 漂移修复须幂等(重复执行零副作用)。

## 六、工程记录

| 主题 | 记录 |
|---|---|
| 断言防腐化 | 存量 `len(nodes)==32` 改下限 `>=32`; 双中心回归同样用动态基线(len(_SEED_NODES))防未来域扩展腐化 |
| fakeredis 惯例 | 生产 Redis 客户端 `decode_responses=True`, fakeredis 模拟须同样配置, 否则 hgetall 返回字节串致反序列化静默丢字段 |
| 部署链 | H5: build:h5 → tar → /var/www/zxjiu/dist 原子替换(旧版备份 dist.bak-permdual); 后端: scp 3 文件 → docker compose up -d --build backend |
| PowerShell 陷阱 | 嵌套引号 python -c 用本地脚本 stdin 管道替代; JSON 体用 `-d "@文件"`; curl 须 curl.exe; 旧版 PS 不支持 `&&` 用 `;` 分步验证退出码 |
| 前端构建 | scss 变量名须与模块既有集对齐($font-size-md 而非 base), 首轮构建 Undefined variable 即时暴露 |
