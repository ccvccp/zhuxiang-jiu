## 一、设计理念与核心命题

### 1.1 一个核心命题

> 平台已有 28 个 AI 评分档案(batch 1-12)深度嵌入业务决策, 但档案各自为政:
> **漂移监控分散**(逐档案查询, 无跨档案视角)、**变更无审批**(权重晋升/
> 伦理补丁直接生效)、**决策不可回放**(快照散落各模块)、**备案靠人工**
> (45号留下的外部待办: 算法备案/伦理审计/监督委员会)。
> 46号的答案: **把"监督委员会"工程化——AI 资产注册中心 + 健康监控 +
> 公平审计 + 决策回放 + 合规材料自动化, 让每一个 AI 决策都可解释、
> 可追溯、可干预、可审计。**

### 1.2 三大理念落法(本仓惯例)

| 理念 | 落法 |
|------|------|
| 遵循规则 | AI 变更(晋升/补丁/冻结)全生命周期审批留痕(不可篡改); 档案可冻结(人工审批后学习暂停); 治理设施 fail-soft(治理异常永不阻断 AI 运行——只有显式冻结才干预) |
| 方便快捷 | 28 档案一屏统览; 算法备案材料一键汇编(数字来自数据层); 健康度自动巡检 |
| 智能自主 | 停滞/枯竭/漂移三类自动检测告警; 公平性偏差自动发现; 决策漂移自动回放比对 |

### 1.3 平台参照与本仓创新

| 参照 | 借鉴点 |
|------|--------|
| 欧盟 AI Act / 生成式 AI 管理办法 | 算法备案材料结构、风险分级、人工监督通道 |
| 43号 P6-2 告警三信号 | 治理告警范式(采集→去重→呈现) |
| 44号 P0 台账 | 注册中心自发现 upsert 幂等范式 |

| **本仓创新** | 28 档案统一治理视图 + 通用决策回放公式(全档案线性结构) + 备案材料自动汇编 |

## 三、P0:AI 资产注册中心

### 3.1 现状与差距

| 维度 | 现状 | 差距 |
|------|------|------|
| 档案清单 | SCORER_REGISTRY 代码常量(28 项) | 治理台账(状态/责任人/冻结位) |
| 变更 | 权重晋升/伦理补丁直接生效 | 审批总线(申请→人工→生效留痕) |
| 冻结 | 无 | 档案级冻结(学习暂停, 审批解锁) |

### 3.2 实施方案

**① 注册中心自发现**(44号台账范式平移):

```python
# services/ai_governance_service.py
async def sync_registry() -> dict:
    """扫描 SCORER_REGISTRY → ai46_registry upsert(幂等)

    - 既有档案: 保留治理状态(frozen/ownerNote), 更新 label/batch
    - 新档案: 入册 status=active
    - 消失档案: 标 retired 不删除(零不可逆)
    - diff 留痕: 新增/退役数
    """
```

**② 变更审批总线**(45号申诉复核范式):

- 表 `ai46_changes`: `{changeId, govId, scorerId, kind:
  promote|patch|config|freeze|unfreeze, payload{before, after},
  reason, requestedBy, status: pending|approved|rejected,
  reviewedBy, reviewNote, requestedAt, reviewedAt}`
- 变更不直接生效——审批通过后才调用对应执行器(晋升走 ai_learning
  promote / 补丁走 45号 patches / 冻结走注册中心)
- 审批留痕不可篡改(只追加语义)

**③ 冻结语义**(唯一干预点, fail-soft 铁律):

```python
# ai_learning_service.run_learning_cycle 顶部(外科手术式守卫):
try:
    from services.ai_governance_service import is_frozen
    if await is_frozen(scorer_id):
        raise ValueError("档案治理冻结中(审批解锁后恢复)")
except ValueError:
    raise
except Exception:
    pass   # 治理设施异常不阻断学习(fail-soft)
```

### 3.3 端点(5)

`GET /ai-gov/registry`(台账+分布)/`POST /ai-gov/registry/sync`(重扫 diff)/
`POST /ai-gov/changes`(提交变更申请)/`GET /ai-gov/changes`(审批队列)/
`POST /ai-gov/changes/{id}/review`(审批: approved 执行 / rejected 留痕)

**测试与验收**: 专项预计 26 项(同步幂等/审批全链/冻结守卫 fail-soft/
重复审批拒绝/参数校验) + 实机 8 项(同步 28 档案→提交冻结→审批→
run_learning 被拒→解冻→恢复 E2E)。

## 四、P1:档案健康度监控

### 4.1 三大检测器(确定性规则, 非评分器)

| 检测器 | 规则 | 数据源 |
|--------|------|--------|
| 学习停滞 | 距最近一次版本晋升 ≥30 天且期间有反馈 | ai_learning history |
| 反馈枯竭 | 近 30 日新增反馈 < min_feedback(学不动) | feedback 计数 |
| 漂移高 | drift.driftLevel == "high"(既有漂移统计) | ai_learning drift |

**群体健康分**(聚合视图指标, 非第29档案——治理健康是确定性聚合,
不入 Hedge): `健康分 = 100 − 停滞40 − 枯竭30 − 漂移30(命中扣满)`。

### 4.2 治理告警(43号 P6-2 三信号范式)

三信号采集 → 去重(同档案同信号当日一条) → 告警呈现;
fail-soft 隔离(单信号采集失败不阻断其余)。

### 4.3 端点(3)

`GET /ai-gov/health`(全档案健康度排行+分层统计)/
`POST /ai-gov/health/scan`(触发一轮巡检落快照)/`GET /ai-gov/alerts`
(告警队列)。

**测试与验收**: 专项预计 26 项(三检测器数学断言/健康分聚合/告警去重/
fail-soft) + 实机 8 项(灌停滞数据→巡检→告警→健康排行 E2E)。

## 五、P2:公平性审计

### 5.1 采样管道

- **自愿上报**: `POST /ai-gov/fairness/samples`——各模块决策点上报
  `{scorerId, group, score, passed}`(group: 自由标签, 如 person/org/
  会员等级)
- **45号事件适配器**: trust45_events 的 person/org 双角色评分天然是
  公平性维度——适配读取聚合入库(只读, 零侵入)
- 采样脱敏: 不含个人标识字段(最小必要)

### 5.2 审计指标与阈值

```
群体 g: n_g / mean_g / passRate_g
指标① 均值差异比 = max|mean_g − mean_all| / max(mean_all, 1)
指标② 通过率差(max-min, 百分点)
告警阈值: ① > 20% 或 ② > 15pp → 该档案 flagged(偏疑)
```

### 5.3 端点(3)

`POST /ai-gov/fairness/samples`(采样上报)/
`POST /ai-gov/fairness/audit`(触发审计→报告落库)/
`GET /ai-gov/fairness/report`(最近报告: 分组统计+flagged 结论+中文归因)。

**测试与验收**: 专项预计 24 项(指标数学断言/阈值边界/空群体跳过/
45号适配器) + 实机 8 项(灌双群体数据→审计→偏差结论 E2E)。

## 六、P3:决策回放与追溯

### 6.1 决策日志总线

表 `ai46_replay_log`: `{replayId, scorerId, subjectRef(脱敏引用),
factors(因子快照), weightVersion, score, action, ts}`——
自愿上报端点 + 45号/43号决策事件适配器(申诉 factorSnapshot 复用)。

### 6.2 通用重算公式(28 档案通用)

```
重算分 = Σ factor.value × 当前冠军权重[factor.name]
(全档案均为 因子×权重 线性结构——一条公式治理 28 档案)
决策漂移 = |重算分 − 原决策分| > 10 分(可配) → 漂移标记
```

回放输出: 原分/重算分/漂移差/权重版本对比/中文归因。

### 6.3 端点(2)

`POST /ai-gov/replay/{replayId}`(重放对比)/`GET /ai-gov/replay`
(日志查询, 支持档案过滤)。

**测试与验收**: 专项预计 22 项(重算数学断言/漂移阈值/版本对比/
脱敏) + 实机 6 项(上报决策→权重变更→回放漂移 E2E)。

## 七、P4:合规材料自动化

### 7.1 算法备案材料(结构化汇编)

从注册中心+健康度+公平性+变更+告警数据自动汇编六节(对齐
《互联网信息服务算法推荐管理规定》备案口径):

```
① 算法基本信息(名称/用途/责任主体占位)
② 数据来源与类型说明
③ 算法逻辑(权重表+因子清单——真实数据, 非编造)
④ 公平性与性能结论(引用 P2/P1 报告)
⑤ 风险防控与应急处置(冻结机制/干预通道/申诉路径)
⑥ 变更记录清单(审批总线留痕)
```

LLM 三态: mock(代码模板, **数字永远来自数据层——LLM 幻觉不进备案**,
42号发票摘要同口径)/real(润色文案)。

### 7.2 治理审计报告

时间窗聚合: 变更数/审批通过率/告警统计/公平性结论/冻结事件——
月度治理报告一键生成。

### 7.3 端点(2)

`GET /ai-gov/compliance/filing`(备案材料, 按 scorerId 或全量)/
`GET /ai-gov/compliance/report?days=30`(审计报告)。

**测试与验收**: 专项预计 20 项(六节完整性/数字来自数据层断言/
时间窗聚合/mock 确定性) + 实机 6 项(建档全链数据→材料汇编→
断言数字与数据源一致 E2E)。

## 九、合规与治理红线(宪法层, 不可逾越)

| # | 红线 | 工程落法 |
|---|------|---------|
| 1 | **治理不阻断** | 治理设施异常 fail-soft 永不阻断 AI 运行; 只有**人工审批的冻结**才干预学习(且仅拦晋升, 不拦评分) |
| 2 | **审批即真值** | 变更审批留痕只追加不可篡改; 重复审批拒绝 |
| 3 | **数字来自数据层** | 备案/报告的每个数字可溯源到注册中心/漂移/审计数据; LLM 仅润色 |
| 4 | **最小采集** | 回放/采样脱敏——不含个人标识/敏感字段 |
| 5 | **监督权分离** | 审批权限独立于业务(X-Role: admin 治理端; 未来可接监督委员会角色) |

## 十、与既有模块的一致性声明

- **零不可逆变更**: 既有路由零改动; ai_learning_service 仅加冻结守卫
  (fail-soft 外科手术式, 与各期档案注册先例同款)
- **不新增评分档案**: 治理健康分是确定性聚合视图(非学习型), 28 档案
  结构不变——46号治理对象是档案而非新增档案
- **范式复用清单**: 台账 upsert(44号 P0)/审批留痕(45号 P4)/三信号告警
  (43号 P6-2)/LLM 三态数字不进数据(41/42/45号)/看板按需加载(43-45号)
- **编号衔接**: 无新档案; 治理视图覆盖 batch 1-12 全部 28 档案
