## 二、三期核心交付

### P6-2：告警通道三信号化（单信号被动可见 → 三信号主动触达）

- [security_alert_service.py](../backend/services/security_alert_service.py)：三信号统一采集 → critical/warn 过滤 → rule 级 24h 去重 → 聚合单封 → 管理员逐一触达
    - **S1 Redis 体检**（P5-2 既有逻辑原样：大 key/rate 泄漏/内存水位/碎片率）
    - **S2 情报订阅降级**（P5-3 已留字段此前无人消费——`consecutiveFailures ≥3` → warn）
    - **S3 调度器基线异常**（`lastErrors` 含 `baseline_anomaly` → warn；自检口径：上轮留痕本轮触达，滞后一轮可接受）
- **单信号 fail-soft 隔离**（采集异常不阻断其余信号与调度）；信号分组渲染（每信号一行摘要，超 10 条截断+计数）
- 新增去重 rule：`threatintel_degraded` / `baseline_anomaly`（与 Redis 体检 rule 各自独立 24h 窗口）
- 第 33 端点 `POST /admin/alerts/collect`（全信号采集+触达，`force` 跳过去重）；`/admin/redis/alert/test` 旧口径保留（仅 Redis 信号，Redis-only 标题兼容）
- 调度器④改调三信号（`lastAlerts` 留痕含 `signals{redis/intel/scheduler}` 分组）；面板⑦区按钮改调新端点

### P6-1：情报源聚合与规模扩展（单源 2k 段 → 多源聚合 180k 段，三道墙拆除）

**三道规模墙**（P6 总计划调研结论）：
1. **全量替换语义** → **按源替换**：`import_netset` 导入 level2 只清 level2 旧段，level1 保留，多源互不干扰；`clear(None)` 全清兼容 P4-3 手动口径
2. **逐键 IO** → **pipeline 批量读写**：导入逐键 hset / 读取逐键 hgetall（180k 次 round-trip 估算 15~20s+）拆 5000/批 + 批间让出事件循环
3. **stats 全量 list** → **计数器化**：源计数 hash 直读毫秒级；计数器缺失**或与区间缓存段数交叉校验不平**（旁路删键/覆写漂移）触发一次全量兜底重建

**核心交付明细**：
- **仓储层**（[security_repository.py](../backend/repositories/security_repository.py)）：`save_many` 批量写 + **覆写检测**（CIDR 跨源键冲突——level1⊂level2 交集段——旧源计数器负抵扣，防漂移）；`clear` 按源负抵扣/全清重置；段元信息 **aux 串键**（`threatintel:meta:{cidr}` = `source|ts`）MGET 批量取（1 命令/5000 键）
- **性能强化三件套**（180k 段实机四项门槛全过，见 §四）：区间构建 scan 分批 + MGET + **v4 纯整数快速解析**（ipaddress ~40µs/段 → ~3µs）；**段记录内联区间项**（命中零 Redis 回填往返）；内存模式同语义
- **服务层**：上限环境变量化（代码默认 20000 兼容，部署 compose 默认 200000——提额为显式运维决策）；`stats()` 三源分布 + `auto.sources` 每源状态 + `degradedSources` 聚合
- **feed 层**（[threatintel_feed.py](../backend/services/threatintel_feed.py)）：`SECURITY_THREATINTEL_URLS` 多源列表解析（name 显式/URL 文件名推导/空 part 容错）；单 URL 变量回退 P5-3 兼容；**状态键模式感知路由**（多源按源键 `threatintel:auto:{name}`，单源 legacy 键 `threatintel:auto` 既有状态连续）
- **调度器**：多源遍历逐源 `maybe_refresh`（每源独立周期判断/失败计数，**单源失败不阻断其余**）+ 失败错误留痕 `lastErrors` 可观测；单源时输出字段语义不变（status/executed:bool/imported 兼容）
- **S2 告警按源触达**（P6-2 通道的既有扩展点自动细化）：多源 rule=`threatintel_degraded:{name}` 站内信含源名可辨识坏源；单源回退 rule 不变
- docker-compose 暴露两变量（URLS 空=单源 P5-3 行为，MAX_CIDRS 部署默认 200000）

### P6-3：enforce 就绪度自动化（纯文字检查单 → 一键评估）

- [enforce_readiness_service.py](../backend/services/enforce_readiness_service.py)：**五检查**（灰度观察期 ≥7 天 / 误报率 <10%（已裁决分母，零裁决保守不判达标）/ 待裁决积压 =0 / 申诉通道动态探活（fail-soft）/ 健康检查白名单）——数据源全部复用既有服务（`daily_series` 单次聚合两检查共享 / `stats()` / `list_appeals()` / `GATEWAY_WHITELIST` 常量），**纯聚合层零新检测**
- **三信号达标汇总**（加分项不进 overall）：D5 criteria 三条件 + d5Enforce 实况 / 威胁情报段数与订阅健康 / GeoIP available / AbuseIPDB mode
- `blockers` 未过项中文摘要（面板灯卡直读）+ `overall: ready|holding`
- **铁律：只评估不切换**——切换仍人工改 `SECURITY_ENFORCE_LEVEL`（note 文案 + 面板 ready 态仍提示人工操作；检查单第 5 条切换后 30 分钟盯盘为人工动作明示不自动化）
- 第 34 端点 `GET /admin/enforce/readiness` + ⑦区**就绪度灯卡**（ready 绿/holding 黄+blockers 首条+五检查表+三信号摘要行，随「刷新日报序列」链式加载——不进 30s 自动刷新，与 D5 状态卡同范式）+ 操作指南 §六补一键评估行

## 三、执行中发现并修复的问题（4 项）

| 期 | 问题 | 根因 | 修复 |
|----|------|------|------|
| P6-1 | **计数器漂移**（全清后统计不归零/异源重复导入虚增） | 计数器维护原在服务层 `import_netset` 主链路——旁路 `clear_threatintel()` 不更新；跨源 CIDR 键覆写不抵扣旧源 | 计数器维护**下沉仓储层**：`save_many` 覆写检测（旧源 -1/新源 +1/同源零变化）+ `clear` 按源负抵扣/全清重置——写入与计数同点，旁路调用不漂移 |
| P6-1 | **调度器破坏 P5-3 单源口径**（p5_3 专项 3 项失败：周期外真执行/异常不阻断/AUTO on 留痕） | 多源遍历无条件写按源键——legacy 单源键状态断档；输出结构改为多源汇总破坏既有断言 | `multi_source_enabled()` 模式感知键路由（未配 URLS 走 source=None legacy 键）+ 单源时结果字段语义不变（`{**单源结果, sources:1}`） |
| P6-1 | **S2 告警未按源细化**（多源降级仍输出单源合并告警） | `_collect_intel_degraded` 只读单源状态键 | 改接 `degraded_sources()` 聚合——多源逐源输出 rule 含源名；单源回退口径文案不变（p6_2 兼容） |
| P6-1 | **两项性能门槛未达**（区间构建 15.9s > 5s；10k 查询 3.73s > 3s） | 剖析定位：hmget 逐命令 redis-py CPU ~40µs × 180k ≈ 7.7s（并发 pipeline 无效——瓶颈非网络）；ipaddress 逐段 ~40µs 解析；命中单键 hgetall 回填往返 | 段元信息 aux 串键 + **MGET 批量取**（1 命令/5000 键，1.4s）；v4 纯整数快速解析（~3µs）；**段记录内联区间项**（命中零回填）→ 构建 4.0s / 10k 查询 0.08s 达标 |

> 两条经验沉淀：①**兼容口径必须由既有专项兜底**（单源回退三个坑——状态键路由/输出形状/告警 rule——正是 P5-3/P6-2/P4-3 存量专项先红后修，防带病上线）；②**性能优化先剖析再动手**（分项计时定位 7.7s hmget 瓶颈后，MGET 单命令批量而非并发 pipeline 才是正解——瓶颈在客户端逐命令 CPU，并发无解）。
