## 一、方案角色 × 全站现状对照矩阵

参照方案："1 中枢调度 + 5 业务专家 + 1 合规守门员 + 1 进化引擎"

| 方案角色 | 全站映射 | 实现度 | 关键缺口 |
|---|---|---|---|
| 🧠 Router Agent | 智搜 L1（意图识别/拆解/分发/融合） | **95%** | 意图拆解已实现(P3 双路)；身份上下文已载入(role/等级) |
| 🛡️ Guardrail Agent | 智搜 L2 合规前置 + 全站词库体系 | **70%** | **输出端校验缺失**（只拦输入，answer 组装后无违禁词二次扫描） |
| 🛒 导购 Agent | 智搜 R1 商品路 | **80%** | 库存状态未展示；比价未做 |
| 🤝 招商 Agent | 智搜 agent 意图 + R3 政策 RAG | **60%** | **区域名额查询未联动**（province 槽位已提取但无消费方）；留资动作卡缺失 |
| 🍽️ 订餐 Agent | ——（全站无餐饮外卖业务） | **0%** | **业务裁剪**：竹香九主营酒类+渠道，不做餐饮下单；改为"餐饮合作导流"（智图 dining POI × 配酒建议） |
| 💎 会员 Agent | 智搜 R2 权益路 | **75%** | 券查询/积分兑换动作卡缺失（等级/积分/升级路径已全） |
| 🎧 客服 Agent | help/order 意图 + chat_service + help_service | **80%** | 售后动作卡为跳转型（可用） |
| 🔄 Evolution Engine | 智搜三参数进化闭环 + 知识库自动保鲜 | **75%** | 知识库自动更新✓(crawl scheduler)；缺坏案例聚类视图、A/B 话术框架 |

**结论**：全站已实现方案约 75-80%——智搜天然就是 Router Agent，七模型
即业务专家层的"重炮"，L2 即 Guardrail 输入端。剩余缺口集中在
**输出端合规、招商区域联动、会员动作闭环、餐饮导流、进化可视化**。

## 二、差距清单（按价值分级）

### GAP-1 合规刚需：Guardrail 输出端校验（方案核心差异化）

**现状**：智搜 L2 只校验用户输入（未成年/医疗/收益承诺命中即拦）；
知识库入库有违禁词扫描（complianceScore），但 **answer 组装输出端
无二次扫描**——商品库/知识库历史内容拼接后仍可能出现极限词组合
（"最好/第一/顶级"），`BANNED_EXTREME` 词表已定义但**零消费**。

**方案**：
- L5 `_compose` 输出前对 answer + snippet 做 `BANNED_EXTREME` ×
  医疗暗示词扫描（确定性规则，LLM 禁入）
- 命中 → 剥离/中性词替换 + 决策留痕 `outputGuard`（命中文/替换动作）
- 观测面：看板护栏区补输出拦截计数；`output_guard_stats`
- 红线：只改话术不改事实数据（价格/单号保留）

### GAP-2 业务闭环：三个 Agent 的"最后一公里"

**2a. 招商 Agent 区域名额联动**（province 槽位已有，零新数据源）
- agent 意图 × province 槽位 → `citystore_service.
  list_available_cities(province_code)` 返回该省可开网店城市数/独占数
- 卡片："山东当前可开区县网店 X 城 / 已独占 Y 城，区域保护先到先得"
- 动作卡：游客→留资引导（attract 留资链路），L4 会员→直达申请

**2b. 会员 Agent 动作卡补全**
- R2 权益卡补"积分兑换"动作（跳兑换页；兑换执行属资金面，仅引导
  不代执行——对齐"建议书永不自动"红线）
- 有将过期积分时提示（points_service.get_expiring_points 已有）

**2c. 导购 Agent 库存展示**
- R1 商品卡 snippet 补库存状态字段（product 库存>0 → "有货"/"紧张"）

### GAP-3 创新体验：餐饮导流 + 进化可视化

**3a. 餐饮合作导流卡**（订餐 Agent 的业务裁剪版）
- 场景词（宴请/请客/商务）× 智图 dining POI → "附近餐饮合作门店 +
  配酒建议"导流卡（复用 xiaozhu_map_service._DINING_POI_TYPES 逻辑）
- **不做下单**（全站无餐饮外卖业务——诚实裁剪，不做空心 Agent）

**3b. Evolution 报表：坏案例聚类视图**
- 看板新增区块：useless 反馈按意图/查询句聚类 top N——运营可见
  "哪些问法总答不好"（数据已有，纯观测面）

**3c. A/B 话术框架（可选远期）**
- ROLE_VARIANTS 角色话术支持 A/B 两版，按 feedbackUsefulRate 自动
  晋升——对齐方案"优胜劣汰"（涉及话术治理，需运营确认参与）

## 三、创新优化（超越参照方案的站内独特资产）

参照方案未覆盖、全站已领先的工程能力，规划中保持并强化：

1. **三态灰度完整语义**（off/shadow 进化冻结/assist）——方案的
   Evolution Engine 无此安全阀
2. **进化三参数闭环**（routeBoost/intentWeight/anchorBoost）+ 防刷分
   闸 + clamp + 留痕可回滚——比方案"更新 Prompt"更工程化可控
3. **67 例边界用例集**（四轮审查沉淀）——方案无质量保障层设计
4. **七模型联动**——方案只设计 5 专家，全站已有智法(法务)/智运
   (物流)/智图(地图)/智单(订单)/智客(会员) 五个重模型可被 Router
   调度（智搜已接智运轨迹/智图 POI/会员模型）
5. **小竹三轨语音接入**（规则/LLM/FC 沙箱）
6. **fail-soft 全链**——LLM 故障永不阻断主链

## 四、实施分期

**GAP-1（建议先行，合规刚需）**：Guardrail 输出端校验
- 工作量小（词表已就位）、风险消除直接

**GAP-2（业务闭环三件套）**：区域名额联动 + 会员动作卡 + 库存展示
- 均为已有数据源的最后一公里，零新存储

**GAP-3（创新体验）**：餐饮导流卡 + 坏案例聚类看板 + A/B 框架
- 体验增强，按需启动（3c 需运营参与）

**裁剪声明**：订餐 Agent 的下单/配送能力**不做**——全站无餐饮外卖
业务，做空心 Agent 违背"懂业务"初衷；以导流卡承接宴请场景。

---

*本规划不新建任何模型——全部缺口在智搜 Router 框架内补齐，
复用站内既有数据源与服务，延续"确定性优先、合规红线、留痕
可审计、进化有闸"四原则。*
