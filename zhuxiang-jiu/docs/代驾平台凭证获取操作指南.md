## 〇、渠道结论（先看）

| 渠道 | 接入方式 | 契合度 | 建议 |
|------|---------|--------|------|
| **滴滴代驾商户开放平台** | 自助开放平台（dop.kuaidadi.com），线上入驻 | ★★★ 自助开户、测试/线上双环境、SDK 齐全 | **首选** |
| e代驾 | 商务对接制（无自助开放平台） | ★★ 覆盖城市广、酒企合作案例多 | 备选/并行询价 |
| 腾讯出行服务开放平台 | 服务商入驻（open.go.qq.com） | ★ 面向小程序出行服务整合 | 不推荐 |

**重要模式说明**：滴滴代驾商户开放平台主推**"代金券模式 / 权益模式"**——即本站向平台采购代驾券/权益，发放给会员，会员用券叫代驾。这与 41号"本站支付代驾费"的业务设计**天然契合**（采购成本即营销成本，平台侧完成计价与支付，本站无需处理司机结算），比"直发订单模式"对接成本更低。若走此模式，41号的对账口径从"订单对账"简化为"券采购对账"。

## 一、滴滴代驾商户开放平台（主路径，7 步）

### 第 1 步：预读接口文档（内部，1 天）

登录 [dop.kuaidadi.com](https://dop.kuaidadi.com/index.html) 阅读"接入指导 + API 列表"：
- 确认平台接口满足 41号需求：下单/派单状态/行程完成/计价/回调
- 注意 API version（部分接口 1.0.0 / 部分 1.0.1，以文档为准）
- **确认泰安在平台服务城市列表**（清单 1.5 项）

### 第 2 步：联系滴滴开通权限（1-3 个工作日）

- 合作邮箱：**dididaijia@didiglobal.com**（滴滴代驾商户开放平台团队）
- 邮件内容：公司介绍（竹香酒业/电商平台）、合作意向（酒类客户代驾权益采购）、**一名开发人员的手机号**
- 平台用该手机号开通商户开放平台权限

### 第 3 步：商户入驻（线上办理，0.5 天）

用该手机号登录 dop.kuaidadi.com → **商户入驻** → 录入商户信息：
- 营业执照、食品经营许可（酒类销售资质）
- 法人/联系人信息、对公结算账户（采购代驾券的扣款账户）
- 完成商户注册

### 第 4 步：申请系统参数（凭证核心步骤，平台审核 1-3 工作日）

商户后台**分别申请测试环境和线上环境**两套参数：

| 平台参数 | 对应本站环境变量 | 用途 |
|---------|----------------|------|
| `appKey` | `DRIDE_PARTNER_APP_ID` | 应用标识 |
| `appSecret` | `DRIDE_PARTNER_APP_SECRET` | HMAC 签名密钥（本站已实现签名头风格） |
| `customerKey` | `DRIDE_PARTNER_TOKEN` | 商户身份（按平台实际鉴权方式映射） |
| API 网关地址 | `DRIDE_PARTNER_URL` | 测试/线上各一个 |
| 回调签名令牌（向平台确认回调鉴权方式后获取） | `DRIDE_PARTNER_CALLBACK_TOKEN` | 回调校验（本站已支持静态令牌/HMAC 双通道） |

同时向平台申请：**测试/线上子渠道 id 和权益 id**（发券类接口必需）、配置**服务器 IP 白名单**和**回调地址**（回调地址填本站公网域名 + `/api/ride/partner/callback`，必须 https）。

### 第 5 步：下载 SDK 与联调（开发 2-5 天）

- 后台"商户接入 → 资源管理"下载 **api 请求 SDK**（https 封装，可直接调用）
- 本站已有 `test_ride_real_channel.py` 本地 mock 平台服务器测试基建；按平台真实签名算法适配 `_partner_auth_headers()`（滴滴为 appKey+appSecret 签名，与本站 HMAC 风格同构）
- 常见报错自查：**999301 = 验签失败**（中文必须 UTF-8 编码，字段逐一对照文档）

### 第 6 步：测试环境全链路验证（1-2 天）

平台提供完整测试工具链：
1. 后台"商户接入 → 资源下载"下载**测试环境司机端 APP**
2. 后台"测试数据" tab **生成测试司机账号**（手机号可虚拟）
   - ⚠️ 必须生成**发单位置对应城市**的司机账号（泰安）
   - ⚠️ 接单时司机须在发单起点附近并处于听单状态，否则报"周围无空闲司机"
3. 发单 → 司机抢单 → 到达 → 开始计费 → 结束 → 支付 → 回调 → 本站 `/api/ride/partner/callback` 接收（本站返回 code=200 才算接收成功，已满足）
4. 对应本站清单 §5.2 灰度（`DRIDE_CHANNEL_MODE=mock_fallback`）

### 第 7 步：线上切换

测试通过后向平台申请线上参数 → `.env` 替换线上凭证 → 按清单 §6.1 三步灰度（mock → mock_fallback ≥48h → real）。

## 三、关键注意事项（来自平台官方文档）

1. **坐标体系**：滴滴代驾接口坐标为**高德系（GCJ-02）**——本站种子司机/起终点为 WGS84 口径，上线前需加坐标转换（高德 SDK 或算法转换，约 ±50-500m 偏差必须消除，否则派单定位错城）
2. **UTF-8 验签**：请求含中文字段必须 UTF-8，否则验签失败（999301）
3. **回调口径**：建议 https；**只有返回 code=200 才认为回调成功**（平台会重试）
4. **审核周期**：滴滴开放平台应用创建需**等待 3 个工作日审核**；测试账号余额不足时先结未结订单/多发小额单/找商务充值
5. **access_token**（若走滴滴用车 API 形态）：client_id/client_secret 换 access_token，有效期 30 分钟，需缓存复用而非每次申请
