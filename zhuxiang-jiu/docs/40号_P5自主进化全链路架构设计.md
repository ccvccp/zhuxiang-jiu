## 二、四维自主化架构

### 2.1 引擎一:自主学习引擎(P5a)

#### 三通道信号模型

| 通道 | 信号种类 | 采集方式 |
|------|---------|---------|
| 正向 positive | clicks / registered / ordered | attract 归因聚合自动采集(滚动采样) |
| 负向 negative | reports / complaints / rate_limit / negative_sentiment | `report_negative` 上报 + 确定性负面词表密度判定(>0.3 触发) |
| 合规 compliance | compliance_score | 三审闸门分数(follow 记录现成字段) |

**信号与反馈分离**(关键设计决策):
- `blogger_signals` 是原始流——可重复采样、不去重(计数指标单调不减,多采样点按 kind 取 max 聚合)
- 44号 feedback 是学习消费端——`run_learning` 按 `consumed` 标记幂等,避免信号重复触发学习

#### 信值对齐复合奖励函数

```
reward = α × 信值转化效率 + β × 合规得分 − γ × 风险损失    clamp [-1, 1]

α = 0.5(转化主目标)   β = 0.3(合规权重,宪法域)   γ = 0.2(风险惩罚)
```

| 分量 | 公式 | 基准 |
|------|------|------|
| 信值转化效率 | `(注册×0.4 + 下单×0.6) / 点击`,按 5% 基准归一 | CONVERSION_REF = 0.05 |
| 合规得分 | 三审 compliance_score / 100 | 现成分数 |
| 风险损失 | `0.5×举报率归一 + 0.3×限流归一 + 0.2×投诉率归一` | RISK_RATE_REF = 2%,RATE_LIMIT_REF = 3 次 |

**双轨平滑过渡**:
- 冷启动(点击 < 3):回退既有 `compute_reward` 流量分量——不破坏现有学习闭环
- 归因充足(点击 ≥ 3):切换信值对齐复合奖励

**β 宪法铁律**:`compute_value_aligned_reward` 中 β 恒取模块常量 `REWARD_BETA`,**不接受调用方传参**;`set_reward_params` 收到任何 beta 值直接 `ValueError` 拒绝;不提供任何调整端点。

#### 学习轮(信号消费闭环)

```
未消费信号 → 按 followId 分组聚合 → 复合奖励计算
→ 44号 submit_feedback(source: blogger_p5a, 附因子快照)
→ 信号标记 consumed → 触发 Hedge 学习轮(fail-soft: 反馈不足返回 deferred)
```

#### 微调研机制(人机共学)

- 仅低置信(< 0.8)可发起——高置信发起直接拒绝(调研成本留给真正不确定的决策)
- 3-5 选项投票,单票即定;投票关闭即生成 `human_feedback` 信号(source: human)
- 人机共学信号 `consumed=True` 仅留痕,不进学习轮聚合(防投票污染奖励计算)

### 2.2 引擎二:自主创作工坊(P5b)

#### 个性化钩子矩阵(确定性生成)

```
5 类人群 × 主钩子+副钩子×2  →  钩子(5) × 结构(2) 组合
  student  → 价格锚点/场景种草/品鉴专业
  mom      → 场景种草/情感陪伴/礼赠体面
  senior   → 情感陪伴/品鉴专业/礼赠体面
  business → 礼赠体面/品鉴专业/价格锚点
  wine_lover → 品鉴专业/场景种草/礼赠体面

版本组合: 主钩子×2结构 + 副钩子×2结构 + 第三钩子×1结构 = 5 版本起
结构库: 痛点-解法-CTA / 故事递进-CTA
```

版本文案 = 钩子开头 × 结构主体 × 合规尾(出处声明 + 免责 + 年龄提示 + **AI 水印**)。

#### 合规内生校验(三层防线)

| 层 | 机制 | 实现 |
|----|------|------|
| 生成时 | 候选词表 = 全量词表 − 禁用词表 | "token 概率置零"的确定性实现 |
| 生成后 | `sanitize_text` 兜底:命中禁用词替换"▇" | FORBIDDEN_WORDS = 四类禁用词表并集去重 |
| 输出时 | **AI 水印断言**:`"AI 创作·内容仅供参考"` 不在正文 → 生成即失败 | 广告法 AI 标识合规 |

三审闸门(`compliance_gate`)原样复用:硬拒或评分 < 60 的版本不入实验。

#### A/B 实验状态机

```
running → promoted(胜出固化)        置信样本: 全版本 clicks ≥ 50
         → (样本不足 → 409 拒绝评估)
```

- 胜出判据:复合 reward 降序,**平局取合规分高者**(β 铁律延伸——合规优先于流量)
- 固化:胜出钩子+结构 → 策略库 `winCount+1`、`avgReward` EMA 平滑(α=0.3)
- 策略排行:`winCount` 降序 → `avgReward` 降序,驱动后续选题默认钩子
- 每版本独立 attract 短码——独立归因追踪

#### UGC 素材库(分成永不自动)

- 授权登记:authorized / cc_by / purchased;分成比例 ∈ [0, 0.5]
- 使用累计 → 生成 `pending` 分成建议书(GMV × 比例)
- **铁律:仅生成建议书留痕,实际给付须人工审批**——同一素材有待审建议时不重复提交

### 2.3 引擎三:自主发布调度器(P5c)

#### 动态时机决策

- `blogger_publish_windows`:平台×小时槽位 → 期望点击 EMA(α=0.3,增量收敛)
- 决策:TOP3 时段中**下一个到来者**(本地时区,当日无则取明日最早槽)
- 冷启动回退:无学习数据 → 既有静态黄金窗(36号 `next_publish_time` 口径)

#### 多账号智能协同

```
选号规则: 钩子偏好标签匹配(优先) → LRU 平局裁决
有效日帽: 新号(累计发布 < 5)帽 1 | 老号帽 3(上限不变)
钩子↔标签映射: 价格锚点→优惠号 / 场景种草→生活号 /
              情感陪伴→陪伴号 / 礼赠体面→商务号 / 品鉴专业→品鉴号
```

#### 发布后 1h 自适应调控(不对称处置)

| 信号(1h 窗) | 动作 | 权限 |
|---------------|------|------|
| 互动低迷(点击 < 10×0.5) | 追加推广建议书(默认预算 50) | 低预算线内自动 / 高预算质押审批 |
| 高频疑问(疑问评论 ≥ 2) | FAQ 置顶回复(模板+合规三件套) | **全自动**(必过合规校验) |
| 负面苗头(负向信号存在或词表密度 > 0.3) | 隐藏候选 + 通知人工 | **仅建议**——AI 永不自动隐藏 |

**不对称原则**:正面动作可自动或半自动;负面处置仅建议——误杀成本远大于漏杀。

### 2.4 引擎四:自治理与进化层(P5d)

#### 进化透明度看板(四区聚合)

| 区 | 内容 | 数据源 |
|----|------|--------|
| 自治开关 | paused/reason/pausedAt | autonomy_state |
| 漏斗归因 | published → withClicks → withRegistered → withOrdered | 全量已发布内容 |

2. **合规闸门**:三审合规分 + 硬拒标记
3. **审计流水**:该内容的决策/生成/发布全量审计 detail 回放

## 三、信值约束机制(宪法域工程化)

### 3.1 约束总览:"自主不等于失控"

P5 的自主性运行在**信值围栏**内。围栏由五类机制构成,全部为确定性工程实现:

```
┌───────────────────────────────────────────────────┐
│              信值围栏(宪法域,永不可校准)              │
├───────────────────────────────────────────────────┤
│ ① β 合规权重     硬编码 [0.1,1.0],传参拒收,无端点    │
│ ② 资金分轨       高预算(>100)永不自动,仅生成建议书    │
│ ③ 惩罚/分成      UGC 分成/质押/处罚全部建议书→人工审批 │
│ ④ pause 仲裁     人工暂停即时冻结全部自主行为          │
│ ⑤ 标识/留痕      AI 水印强制 + 干预哈希上链            │
└───────────────────────────────────────────────────┘
```

### 3.2 β 合规权重:三级防护

1. **函数级**:`compute_value_aligned_reward` 签名接受 alpha/gamma 覆盖,**β 恒取模块常量**——调用方无传参通道
2. **服务级**:`set_reward_params(beta=任何值)` → `ValueError("β 合规权重为宪法域参数…任何调整请求被拒绝")`
3. **端点级**:`/auto/reward/config` 只读(GET);无任何写端点——α/γ 生产调整亦须走 46号审批总线

### 3.3 资金/惩罚/分成分轨

| 场景 | 自动轨 | 人工轨 | 分界 |
|------|--------|--------|------|
| 追加推广 | ≤ 100(BOOST_AUTO_MAX,环境变量可调)mock 轨执行留痕 | > 100 生成 pending 建议书,须人工质押审批 | 预算线 |
| UGC 分成 | 无 | GMV×比例 → pending 建议书 → 人工 approve 后给付 | 永不自动 |
| 负面内容隐藏 | 无 | 仅生成 hide_candidate 建议 + 通知 | 永不自动 |
| FAQ 置顶回复 | 全自动(合规校验通过) | — | 无资金流 |

**推广幂等**:同一内容已有待审或已执行推广时拒绝重复(防重复扣费)。

### 3.4 pause 仲裁优先(最高优先级铁律)

```
pause 指令 → autonomy_state.paused=True(即时生效)
           → 自动抓策略库快照(供 rollback,保留最近 10 个)
           → 干预记录落库 + 哈希留痕

被冻结的自主行为(require_running_async 前置校验):
  ✗ 学习轮 run_learning        ✗ 实验固化 promote_experiment
  ✗ 低预算自动推广 execute_boost ✗ FAQ 自动回复

不受限: 高预算建议书生成(非"行为",给人工审批留通道)、
        干预通道本身、看板观测面
```

- pause 理由**必填**(留痕审计);重复 pause 幂等叠加(理由串联,仍抓新快照)
- **resume 永不自动**——须显式调用;未暂停时 resume 报 409
- rollback 仅可回滚到既有快照——快照缺失或不存在**直接拒绝,不允许编造历史**

### 3.5 规则注入(热更新)

`inject_rule({type, value, scope?})`:type/value 必填,即时生效并留痕。
示例:`{"type": "hook_blacklist", "value": ["hook_price_anchor"], "scope": "create"}`

### 3.6 红线对照表(宪法域,永不可校准)

| 红线 | 工程实现 |
|------|---------|
| β 合规权重永不为零 | 函数级拒传参 + 服务级拒写入 + 无端点 |
| LLM 禁入判定链 | 创作=模板+词表;情绪=词表密度;奖励/归因=确定性公式 |
| 惩罚/质押/分成永不自动 | 建议书 → 46号 submit_change → 人工 approve |
| 高危发布强制审批 | 高预算推广 > 100 → 质押审批 |
| 人工暂停最高优先级 | 仲裁优先于调度器,四类自主行为全拒 |
| AI 标识水印强制 | 生成断言缺失即 ValueError |
| 三审闸门不可绕过 | A/B 版本逐版过审,硬拒不入实验 |
| 干预留痕上链 | SHA256 哈希指纹(40 位截断,best-effort) |

## 四、自愈状态机逻辑

### 4.1 失败分类(确定性词表归因,LLM 禁入)

```
classify_failure(error) → 5 类:

rate_limit         "rate limit" / "too many" / 429 / "频次" / "限流"
content_takedown   "takedown" / "removed" / "deleted" / "下架" / "违规删除"
account_restricted "banned" / "suspend" / "封号" / "受限"
transient          "timeout" / "network" / 502 / 503 / "超时" / "网络"
unknown            兜底
```

### 4.2 状态转移图

```
                      ┌─ rate_limit ──→ 换号(账号矩阵备用号接管,重试)
                      │
发布失败(error) ──→ ─┼─ content_takedown ──→ 人工队列(词表归因完成,
                      │                       修正版重提须人工确认)
                      │
                      ├─ account_restricted ──→ cooling + 备用号接管
                      │                          + 权重降档留痕
                      │
                      ├─ transient/unknown, attempt ≤ 3
                      │        ──→ retry(指数退避, attempt+1)
                      │
                      └─ attempt > 3(重试耗尽)
                               ──→ 人工队列(留痕, 永不静默丢弃)

每次自愈动作 → blogger_audits 留痕(action=auto_heal,
              含 followId/category/attempt/action/error)
```

### 4.3 状态机设计要点

1. **分类优先于重试**:限流/下架/受限三类直接走专项轨道——盲目重试限流只会加重处罚
2. **耗尽兜底铁律**:重试 3 次耗尽**永不静默丢弃**,一律转人工队列留痕
3. **全链留痕**:每次自愈动作写入审计流水(`auto_heal`),看板自愈流水区可回放
4. **纯确定性**:分类=词表匹配,档位=整数比较,无任何模型推理

### 4.4 与既有自愈机制的关系

| 既有机制(P0-P3d) | P5d 增量 |
|------------------|---------|
| 账号矩阵 cooling 触发词(P3c) | 归类为 rate_limit 信号的信号源 |
| failStreak 权重降档 | account_restricted 轨道复用 |
| 学习熔断(fraudShare > 30% 暂停) | 独立保留,与自愈状态机并行 |

## 七、关键设计决策备忘

1. **"大模型"口径**:在线学习系统(Hedge + Champion/Challenger),不是训练 LLM——与 54号"小竹"先例工程统一
2. **信号与反馈分离**:原始流可重复采样,消费端幂等——避免信号重复触发学习
3. **reward 双层结构**:冷启动回退流量分量,样本充足切信值对齐——平滑过渡不破坏既有闭环
4. **A/B 与三限共存**:实验版本共享账号日帽,实验不豁免任何护栏
5. **不对称处置**:正面动作可自动,负面处置仅建议——误杀成本远大于漏杀
6. **pause 下高预算建议书不冻结**:生成建议书非"行为",给人工审批留通道(观测与纠错永不关停的宪法口径)
7. **人机共学信号不进学习轮**:投票留痕(`consumed=True`)防污染奖励聚合
8. **rollback 拒绝编造**:快照仅在 pause 时自动抓取,无快照即拒绝——历史完整性优先于便利性
