# 59号·AI智能服务编排模块 实施计划

> 定位：本站服务交付的统一编排中枢——**58号回答"用户想要什么"，59号回答"如何最优交付"**（服务路由×会话编排×体验分级×风控前置，数据-模型-业务-反馈四位一体闭环）

> 范式：意图识别（58号）→ 服务路由分发 → 会话任务编排 / 搜索推荐交付 / 风控前置分级 → 满意度真值回流第34档案（让服务理解体验边界，让体验反哺编排迭代）

---

## 一、定位与设计理念

### 1.1 模块边界（三面一体）

用户选定三方向统一于"服务编排"骨架：

| 面 | 回答的问题 | 核心机制 |
|----|-----------|---------|
| **客服会话面** | 对话任务如何编排执行 | 多轮会话状态机+任务模板+人工接管 |
| **搜索推荐面** | 内容如何个性化交付 | 语义检索+tier 联动重排+多样性约束 |
| **风控前置面** | 交付前的体验如何分级 | 多维信号聚合+四级处置+申诉回流 |

统一编排骨架：**服务路由**（58号 intentId → 服务通道）×**体验分级**（47号 tier → 流畅度，与 58号阈值联动同思想）×**风控前置**（43/45/47号信号 → 处置档）×**反馈飞轮**（满意度/点击/采纳 → 44号池第34档案 Hedge 学习）。

### 1.2 设计理念（参照方案四大理念+本站化）

| 理念 | 本站落地 |
|------|---------|
| 数据-模型-业务-反馈闭环 | 服务编排注册表（数据）→ 路由决策引擎（模型）→ 三面交付（业务）→ 满意度真值池双写（反馈） |
| 安全合规内生 | 风控前置面（交付前分级处置）；58号"识别即合规"的下游执行层——识别拦截的绝不进入编排 |
| 效果度量 | 四区看板（度量：解决率/采纳率/多样性/增益+服务+内容+防御） |
| 落地路径 | 六期 P0-P5 分期，每期专项+实机+回归三重验证 |

### 1.3 五条工程铁律

1. **默认零影响**：`II59_MODE` 默认 off——存量服务链路（48号语音/既有 chat/search 路由）零影响；59号与既有通道**并行不替换**（双模型铁律平移）
2. **澄清优于错误执行**（上游铁律继承）：58号 clarify/partial 态意图**不进入任务编排**——无确认不执行
3. **识别即合规的下游执行**：58号 boundaryIntercepted 的意图不路由到任何服务面；confirm_required 需确认后才编排
4. **优化永不自动生效**：编排模板变更/处置阈值调整/重排权重全部经人工终审（46号审批总线+共创 pending 范式）
5. **归因 ID 强制**：每次服务交付携带归因链（sessionId+taskId+intentId+riskDecision+track）——无归因不计入有效服务

## 二、服务编排注册表（SERVICE_REGISTRY——52号封闭白名单范式）

三位一体：**服务×通道×SLA**（每服务绑定 plane 服务面/minRole 最小权限/sla 目标+依赖项）。

```
SERVICE_REGISTRY（首批 6 项三面+2 元服务）:
  # 客服会话面
  cs.general_assist     通用客服助手    plane=customer_service  minRole=guest    sla={firstResponse≤3s}
  cs.order_assist       订单售后助手    plane=customer_service  minRole=member   sla={firstResponse≤3s, resolve≤24h}
  # 搜索推荐面
  sr.product_search     商品搜索       plane=search_recommend  minRole=guest    sla={p95≤800ms, top10}
  sr.personal_feed      个性推荐流     plane=search_recommend  minRole=member   sla={p95≤500ms, refresh≤5min}
  # 风控前置面
  rg.experience_gate    体验分级门     plane=risk_gate         minRole=guest    sla={p95≤50ms}
  rg.appeal_channel     申诉通道       plane=risk_gate         minRole=member   sla={response≤48h}
  # 元服务
  meta.help             服务帮助       plane=meta               minRole=guest    sla={}
  meta.unknown          未路由兜底     plane=meta               minRole=guest    sla={}   # clarify 引导
```

启动自检 `_validate_registry()`（RuntimeError 宪法级）：三面覆盖+minRole 合法+SLA 结构合法+依赖项在册+status 合法。

**意图→服务路由表**（ROUTING_TABLE）：58号 12 意图 → 59号服务通道映射（如 product.price_query→sr.product_search；chat.human_transfer→cs.order_assist+escalate；boundary.unauthorized→不路由）。路由表封闭白名单——未映射意图走 meta.unknown 兜底。

## 三、客服会话引擎（P1）

### 3.1 会话状态机

```
opened → serving → resolved → closed
   │         │
   │         └→ escalated（人工接管——43号联动）
   └→ abandoned（超时/客户离开——15 分钟无轮次）
```

会话结构：`sessionId、memberId、channel（text/voice）、intentId（58号消费）、state、turnCount、taskStack（当前编排实例）、escalatedAt、satisfaction、pooledFeedbackId、attribution`。

### 3.2 任务编排（TASK_TEMPLATES）

意图 → 步骤序列模板（确定性 DSL）：

```python
TASK_TEMPLATES = {
  "trust.convert_intent": {
    "steps": ["confirm_amount", "verify_token(48号confirmToken)",
              "execute_convert", "notify_result"],
    "sensitive": True,   # confirm_required 衔接
    "rollback": "notify_rollback"},
  "product.price_query": {
    "steps": ["search_product(sr.product_search)", "render_price_card"],
    ...},
}
```

- 模板版本化（新版入库旧版 retired）；模板变更经 46号审批（人工铁律）
- 步骤执行 fail-soft：单步失败→会话转 escalated 或 resolved(partial)+留痕
- **上游铁律继承**：58号 clarify/partial 不编排（会话 opened 态等待澄清）；boundaryIntercepted 拒绝开话

### 3.3 人工接管流

`escalate`：会话上下文移交（脱敏摘要——PII 不出域）+排队位次+43号安全事件联动（高危会员强制人工）。

## 四、搜索推荐服务面（P2）

### 4.1 语义检索域

- 检索源：57号 published seeds（纯读取）+商品域（既有 product 数据）
- 检索算法：关键词加权打分（58号 _similarity 范式复用——FULL/PARTIAL/AMBIGUOUS）+类目过滤
- 检索日志：query+结果集+采纳标记（回流真值）

### 4.2 个性化重排（tier 联动——只调序不筛除）

| tier | 重排策略 |
|------|---------|
| trusted | 多样性优先（新类目/新商户上浮） |
| standard | 基线（相关性优先） |
| watched | 熟悉度优先（高点击类目上浮——降低探索） |
| restricted | 安全优先（高信誉商户/官方内容上浮） |

**铁律**：重排只调序不筛除（48号偏好重排范式平移）——结果集总数不变。

### 4.3 多样性约束

- 同源上限（单商户 ≤30% 席位）；类目分散（top-N 内 ≥3 类目）
- 推荐解释（explain：rankFactors 留痕——可审计）

## 五、风控决策前置引擎（P3）

### 5.1 多维信号聚合

```
riskScore = w1×threat(43号威胁分) + w2×tier(47号画像) 
          + w3×frequency(会话频次异常) + w4×taskSensitivity(任务敏感级)
```

### 5.2 四级处置

| 档 | 动作 | 语义 |
|----|------|------|
| allow（<25） | 放行 | 正常交付 |
| dampen（25-50） | 减速 | 强制确认页+延迟响应 |
| challenge（50-75） | 挑战 | 二次确认（48号 confirmToken 流复用） |
| block（≥75） | 拦截 | 拒绝服务+43号留痕 |

**fail-soft 铁律**：信号源异常→allow+留痕（风控设施故障不阻断业务——与 43号 fail-open 同思想）。

### 5.3 申诉通道

会员对 challenge/block 处置申诉→人工复核→处置翻转留痕+回流信号（误拦负修正）。

## 六、第34档案：service_orchestration 八因子信任分

44号 ai_learning 入册（batch18——既有测试 33→34 计数更新：预算约 33 处 10 文件，56/57/58号教训预算内消化）。

| 因子 | 权重 | 口径 |
|------|------|------|
| session_resolution | 0.20 | 会话解决率（resolved/总闭话） |
| search_adoption | 0.15 | 搜索采纳率（点击/曝光） |
| recommend_diversity | 0.15 | 推荐多样性（类目熵） |
| risk_accuracy | 0.15 | 风控准确率（处置正确率回流） |
| member_trust | 0.10 | 会员信值（47号 tier 基线） |
| escalation_rate | 0.10 | 人工接管率（过高=编排能力弱） |
| latency_budget | 0.05 | 延迟预算 P95 达标率 |
| coverage_breadth | 0.10 | 服务覆盖度（意图→服务映射覆盖） |

→ 信任分 0-100 → 三级决策：observe（<50 不优化）/optimize（≥50 编排模板+语料回流）/urgent（≥80 复盘会触发）。

## 九、分期实施计划（P0-P5）

### P0 服务编排注册表+会话底座
- SERVICE_REGISTRY 8 项三位一体+启动自检（52号范式）
- 会话状态机底座（opened→closed 六态）
- 第34档案入册 batch18（既有测试 33→34 计数更新）
- 7 表底座+路由表封闭白名单
- 测试：专项约 45 断言；QC：服务白名单封闭；58/48号零改动

### P1 客服会话引擎
- 意图消费（58号 evaluate 结果路由——clarify/partial 拒绝编排铁律）
- TASK_TEMPLATES 任务编排（版本化+46号审批）
- 步骤推进+人工接管（脱敏移交+排队）
- 满意度采集（闭话必采——回流真值源）
- 测试：专项约 40 断言；QC：上游铁律继承；模板人工审批

### P2 搜索推荐服务面
- 语义检索（57号 seeds+商品域纯读取）
- tier 联动个性化重排（只调序不筛除铁律）
- 多样性约束（同源上限+类目分散+explain 留痕）
- 点击/采纳反馈
- 测试：专项约 40 断言；QC：重排零筛除；解释可审计

### P3 风控决策前置
- 四维信号聚合+四级处置（allow/dampen/challenge/block）
- fail-soft 铁律（信号异常 allow+留痕）
- 申诉通道（翻转留痕+误拦负修正）
- 处置阈值配置域（46号审批+人工终审轨——58号阈值域范式复用）
- 测试：专项约 40 断言；QC：fail-soft 不阻断；阈值人工终审

### P4 决策回流+满意度信号+T+1 调度
- 六类真值信号→44号池双写（第34档案；sessionId 1:1 幂等）
- 低满意度预警（满意度<阈值→编排模板复审建议）
- T+1 调度器（II59_LEARN_MODE 默认 off）
- 测试：专项约 40 断言；QC：回流幂等；预警建议人工审批

### P5 看板+红队+三件套收官
- 四区看板（度量：解决率/采纳率/多样性/增益+服务+内容+防御）
- 红队七向量：会话劫持（他人会话推进——属主校验）/结果投毒（伪造采纳）/风控绕过（信号伪造）/推荐操纵（权重注入）/权限逃逸（越面路由）/反馈污染/LLM 越白名单
- 宪法断言（44号 34 档案+58/48号零改动）+收官三件套
- 测试：专项约 35 断言；QC：投毒防御；全链零回归

**开关矩阵**：`II59_MODE`（默认 **off**）；`II59_LLM_MODE`（编排辅助建议，默认 off）；`II59_LEARN_MODE`（调度，默认 off——三开关铁律）。

## 十、风险控制矩阵

| 风险 | 缓解 | 验证 |

## 十一、一致性声明与外部待办

**零改动宪法**（每期断言验证）：44号学习中枢零改动（仅新增第34档案，34 档案口径）；58号意图识别零改动（evaluate 纯消费）；48号语音中枢零改动（turns/confirmToken 纯读取复用）；57号知识库零改动（published seeds 纯读取）；47号画像/43号安全/46号治理零改动（纯读取/审批总线调用）。

**外部待办**：真实 LLM 编排辅助（当前确定性模板轨——LLM 仅建议）；跨会话长期记忆（当前单会话域）；多渠道统一编排（web/app/小程序——当前单通道）；服务网格化（微服务级编排——远期）。

**结语**：59号让服务交付从"硬编码路由"进化为"懂体验的编排中枢"——识别意图之后，它会选择最合适的通道、以最合适的节奏、在最合适的防护等级下交付；当会员信值流动时它让高信值者更流畅、低信值者更安全；每一次满意度都在告诉第34档案"这次编排做对了没有"。**懂路由、知节奏、有分级**——与58号构成"识别→交付"的完整闭环。
