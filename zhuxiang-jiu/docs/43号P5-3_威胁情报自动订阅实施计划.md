# 43号·P5-3 威胁情报自动订阅 实施计划 v1.0

> 配套：[43号P5_收口增强实施计划.md](43号P5_收口增强实施计划.md) §四
> 定位：P4-3 威胁情报导入为 `POST /admin/threatintel/import` **手动上传**——计划明确"建议周度手动导入，自动订阅留 P5"。P5-3 把"周度人工下载上传"变成"调度器无人值守拉取"：情报表从一次性静态快照变成持续更新的活情报。
> 调研结论（2026-09-03）：
> 1. httpx 客户端范式已确认（captcha_client.py 41号范式）：`httpx.AsyncClient(timeout=N)` + `TransportError` 捕获 + 三态容错；
> 2. 调度挂钩点为 `security_scheduler.run_scheduled_security_tasks()` ⑤ 步骤（P4-2 建 ①②③，P5-2 加 ④，本计划加 ⑤）；
> 3. `ThreatIntelService.import_netset(content, source, replace)` 是幂等全量替换入口——**先 parse 成功才 clear 旧段**，天然 fail-soft（拉取失败不触碰旧段，零改造复用）；
> 4. 自动订阅状态（最近拉取/失败计数）存 `security_posture` 表 `threatintel:auto` 记录（`get_scheduler_stats/save_scheduler_stats` 同款双模式存储范式）。

## 二、P5-3a：订阅客户端

### 结构（新建 `services/threatintel_feed.py`）

```python
# 拉取校验参数(计划 §四①)
FETCH_TIMEOUT = 30.0        # 拉取超时(秒)
MAX_NETSET_BYTES = 10 * 1024 * 1024   # 10MB 上限(防误传大文件)
MIN_NETSET_LINES = 100       # 有效行下限(防拉到错误页/空壳)

DEFAULT_FEED_URL = (
    "https://raw.githubusercontent.com/firehol/blocklist/"
    "master/firehol_level1.netset")


async def fetch_netset(url: str = None,
                       timeout: float = FETCH_TIMEOUT) -> str:
    """拉取 netset 文本(三重校验, 失败 raise ValueError)

    校验链(计划 §四① 容错):
        ① HTTP 200(非 200 直接拒绝——429/404/5xx 均为失败)
        ② 大小 ≤10MB(防错误内容撑爆内存/存储)
        ③ 有效行 ≥100(firehol_level1 约 2k 段; 拉到
           HTML 错误页/空壳内容直接拒绝)
    Raises:
        ValueError: 校验任一失败(错误信息含原因)
        httpx.TransportError 由调用方兜底(网络不可达)
    """
    url = url or feed_url()
    async with httpx.AsyncClient(timeout=timeout,
                                 follow_redirects=True) as client:
        resp = await client.get(url)
        if resp.status_code != 200:
            raise ValueError(f"拉取失败 HTTP {resp.status_code}")
        content = resp.text
    if len(content.encode()) > MAX_NETSET_BYTES:
        raise ValueError(f"内容超上限 {MAX_NETSET_BYTES} 字节")
    lines = [ln for ln in content.splitlines()
             if ln.strip() and not ln.startswith("#")]
    if len(lines) < MIN_NETSET_LINES:
        raise ValueError(f"有效行不足({len(lines)} < "
                         f"{MIN_NETSET_LINES})")
    return content
```

### 关键设计决策

| 决策 | 口径 | 理由 |
|------|------|------|
| **校验前置** | parse 前完成三重校验 | 拉到错误页（HTML 404 页/限流提示）不进入导入链路 |
| **follow_redirects** | True | GitHub raw 对部分路径 301 → 目标源，容错一次跳转 |
| **默认源可配** | URL 走环境变量 | 国内环境 GitHub raw 可达性不稳，可换 ghproxy 等镜像 |
| **不含 parse** | feed 只管拉取，解析复用 `parse_netset` | 职责单一；parse 校验（CIDR 格式）仍是 import 的既有防线 |

## 三、P5-3b：调度器 ⑤ 步骤集成

### 挂钩点：`run_scheduled_security_tasks()` 追加 ⑤

```python
    # ⑤ 威胁情报自动订阅(P5-3): 周期到点拉取 netset →
    #    幂等全量替换(import 内部先 parse 成功才 clear——
    #    拉取/校验失败旧段保留, 情报宁旧勿空);
    #    连续失败 ≥3 次 degraded 留痕(可接 P5-2 告警)
    try:
        from services.threatintel_feed import maybe_refresh
        result["threatintel"] = await maybe_refresh()
    except Exception as exc:
        logger.warning("security_scheduler_threatintel_failed: %s",
                       exc)
        result["errors"].append(f"threatintel:{exc}")
```

### 周期判断与容错链（`threatintel_feed.maybe_refresh`）

```python
async def maybe_refresh(force: bool = False) -> dict:
    """周期到点才拉取(force 跳过周期判断, 手动刷新用)

    Returns:
        {executed: bool, reason, imported?, cleared?,
         lastAutoImportAt, consecutiveFailures, status}
    """
    # ① 周期判断: 距上次成功导入 < interval 且非 force → 跳过
    state = await _load_auto_state()
    if not force and _within_interval(state):
        return {"executed": False, "reason": "interval_not_reached", ...}

    # ② 拉取 + 校验(TransportError/ValueError 均走失败链)
    try:
        content = await fetch_netset()
    except Exception as exc:
        state["consecutiveFailures"] += 1
        state["lastAutoStatus"] = "failed"
        state["lastError"] = str(exc)[:200]
        await _save_auto_state(state)   # 旧段不动(fail-soft)
        return {"executed": False, "status": "failed", ...}

    # ③ 导入(幂等全量替换, source=firehol_level1_auto)
    r = await ThreatIntelService().import_netset(
        content, source="firehol_level1_auto", replace=True)

    # ④ 成功: 重置失败计数 + 留痕
    state.update({"lastAutoImportAt": ts(),
                  "lastAutoStatus": "ok",
                  "consecutiveFailures": 0, "lastError": ""})
    await _save_auto_state(state)
    return {"executed": True, "imported": r["imported"], ...}
```

**状态存储**（`security_posture` 表 `threatintel:auto` 记录，双模式）：

```python
{ "lastAutoImportAt": "2026-09-10T00:00:00Z",   # 最近成功导入
  "lastAutoStatus": "ok" | "failed",            # 最近一次拉取结果
  "consecutiveFailures": 0,                      # 连续失败计数
  "lastError": "" }                              # 最近失败原因(截断200)
```

**degraded 口径**：`consecutiveFailures >= 3` → stats() 输出 `degraded: true`（P5-2 告警可后续消费此字段——本计划不改告警服务，避免耦合）。

async def stats(self) -> dict:
    # 既有: totalCidrs / sources / lastImportedAt

    return {...,
        "auto": {
            "enabled": feed_enabled(),          # AUTO 开关实况

            "lastAutoStatus": auto.get("lastAutoStatus"),

### 实机验收（`verify_security_p5_3_live.py`，预计 12 项）

1. 正常业务零影响
2. 容器默认 off（stats.auto.enabled=False）
3. **本地模拟源全链路**：容器内起临时 http.server 挂载 netset 文件 → URL 指向模拟源 → 手动 refresh 端点 → imported≥100 → CIDR 命中联动（命中降档 31）
4. 幂等：同源二次 refresh → imported 一致（全量替换）
5. **失败容错**：URL 指向不存在路径 → status=failed / 旧段保留（命中仍有效）/ consecutiveFailures=1
6. degraded：连续 3 次失败 → stats.auto.degraded=true
7. 恢复：URL 修回 → 成功拉取 → 计数清零 degraded=false
8. 真实 GitHub 源探测（外网可达时 imported≥1000，不可达时降级断言 TransportError 链路，不作为门槛）
9. 调度轨：容器内单轮 `run_scheduled_security_tasks()` → lastThreatintel 留痕
10. 既有手动导入端点回归（双轨并存）
11. 全程业务正常

## 六、关键风险与对策

| 风险 | 对策 |
|------|------|
| GitHub raw 国内可达性不稳 | ①URL 可配（镜像源如 ghproxy）②fail-soft 旧段保留 ③手动上传端点兜底 ④degraded 状态可观测 |
| 拉到错误内容（限流页/HTML 错误页） | 三重校验（200+大小+行数）前置，parse 校验仍是第二道防线 |
| 误配 URL 拉到恶意内容 | ①白名单意识：默认源官方 CC0，自定义 URL 属运维责任 ②行数/大小校验兜底 ③导入后 CIDR 命中只降档不直封（P4-3 防误杀设计天然兜底） |
| 拉取阻塞调度循环 | 30s 超时 + ⑤ 步骤独立 try/except（不阻断基线重建/告警触达） |
| 周期误配（如 60s） | INTERVAL 下限 3600 强制抬升（max(3600, 配置值)） |
