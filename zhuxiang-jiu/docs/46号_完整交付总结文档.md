## 一、模块概览

### 1.1 定位

平台已有 28 个 AI 评分档案(batch 1-12)深度嵌入业务决策,
但档案各自为政: **漂移监控分散**(逐档案查询无跨档案视角)、
**变更无审批**(权重晋升/伦理补丁直接生效)、**决策不可回放**
(快照散落各模块)、**备案靠人工**(45号留下的外部待办)。

46号的答案: **把"监督委员会"工程化**——AI 资产注册中心 +
健康监控 + 公平审计 + 决策回放 + 合规材料自动化, 让每一个
AI 决策都可解释、可追溯、可干预、可审计。

### 1.2 三大理念落法

| 理念 | 落法 |
|------|------|
| 遵循规则 | AI 变更(晋升/补丁/冻结)全生命周期**审批留痕**(只追加不可篡改); 档案可冻结(人工审批后学习暂停); 治理设施 **fail-soft 铁律**(治理异常永不阻断 AI 运行——只有显式冻结才干预) |
| 方便快捷 | 28 档案**一屏统览**; 算法备案材料**一键汇编**(六节结构, 数字来自数据层); 健康度自动巡检三检测器 |
| 智能自主 | 停滞/枯竭/漂移三类自动检测告警; 公平性偏差自动发现(双指标); 决策漂移通用重算公式(一条公式治理 28 档案) |

### 1.3 平台参照与本仓创新

| 参照 | 借鉴点 |
|------|--------|
| 欧盟 AI Act / 生成式 AI 管理办法 | 算法备案材料结构、风险分级、人工监督通道 |
| 43号 P6-2 告警三信号 | 治理告警范式(采集→去重→呈现) |
| 44号 P0 台账 | 注册中心自发现 upsert 幂等范式 |
| 45号 P4 审批留痕 | 变更审批总线(pending→approved/rejected) |
| **本仓创新** | 28 档案统一治理视图 + **通用决策回放公式**(全档案 因子×权重 线性结构, 一条公式治理 28 档案) + 备案材料自动汇编 |

### 1.4 AI 的公信力公式

> **AI 的公信力 = 可解释 × 可追溯 × 可干预 × 可审计**

## 三、各期交付明细

### P0 · AI 资产注册中心(★★★ 治理地基)

- **注册中心自发现**(44号台账范式平移): 扫描
  `ai_learning SCORER_REGISTRY`(28 档案) → `ai46_registry`
  upsert 幂等; 保留治理状态(frozen/ownerNote), 新档案入册
  active, 消失档案标 retired 不删除(零不可逆), diff 留痕。
- **变更审批总线**(45号申诉复核范式): 5 种变更类型
  (promote/patch/config/freeze/unfreeze)——变更不直接生效,
  pending → 人工审批 → approved 执行器分派 / rejected 留痕;
  同档案重复 pending 拒绝; freeze/unfreeze 幂等冲突校验;
  审批留痕只追加不可篡改。
- **冻结语义**(唯一干预点, fail-soft 铁律):
  `run_learning_cycle` 顶部外科手术式守卫——档案被治理
  冻结时拦截学习("档案治理冻结中(审批解锁后恢复学习)");
  治理存储异常**放行**(fail-soft); 仅拦学习不拦评分。
- **执行器分派**: freeze/unfreeze→注册中心状态翻转(即时);
  promote→ai_learning 人工晋升; patch/config→P0 保留人工通道。

### P1 · 档案健康度监控(★★★ 三检测器)

- **三检测器**(确定性规则, 非评分器——治理健康是确定性
  聚合, 不入 Hedge, 不新增第 29 档案):
  - **学习停滞**: 距最近版本事件 ≥30 天且期间有反馈(有数据
    却无版本演进=学不动了); 无版本事件时以最早反馈为观察起点
  - **反馈枯竭**: 近 30 日新增反馈 < min_feedback(学不动);
    从未有过反馈不判(未启动≠枯竭, 防全新部署全员误报)
  - **漂移高**: 既有漂移统计 driftLevel=="high"(43号口径)
- **群体健康分**: `100 − 停滞40 − 枯竭30 − 漂移30`(命中扣满),
  分层 healthy(≥90)/watch(≥60)/risk(<60); 28 档案排行升序
  (最需关注在前)。
- **巡检快照**: `ai46_health_snapshots` 只追加; 实时视图
  (GET /health)与落库快照(POST /health/scan)双轨。
- **治理告警**(43号三信号范式): 采集→去重(同档案同信号
  当日一条——occurrences 累加不新建)→队列呈现; fail-soft
  隔离(单档案采集失败不阻断其余, 单数据源失败仅 errors 留痕)。

### P2 · 公平性审计(★★ 防偏差)

- **采样管道**:
  - 自愿上报: 各模块决策点上报 `{scorerId, group, score,
    passed}`(group 自由标签如 person/org/会员等级)
  - **45号事件适配器**: trust45_profiles 的 person/org 双
    角色评分聚合入库(只读零侵入/幂等跳过/读取异常 fail-soft)
  - **脱敏红线**: 含 id/phone/email/name 等个人标识字段
    直接 409(最小必要红线)
- **审计指标与阈值**(保守阈值防误报):
  - 指标① 均值差异比 = max|mean_g − mean_all| / max(mean_all, 1),
    阈值 **20%**
  - 指标② 通过率差(max−min, 百分点), 阈值 **15pp**
  - **flagged 仅标记不下结论**(人工复核防线)
- **空群体跳过不告警**: 档案采样 <20 出 insufficient 不出
  结论; 单群体 <5 不参与指标(统计意义防线)。
- **审计报告**: 只追加落库, 中文归因结论数字全部来自计算层。

### P3 · 决策回放与追溯(★★ 通用公式)

- **决策日志总线**: `ai46_replay_log` 只追加
  `{replayId, scorerId, subjectRef(脱敏引用), factors(因子快照),
  weightVersion, score, action, ts}`; 脱敏红线(subjectRef 含
  id=/phone= 等直接 409); **45号申诉 factorSnapshot 适配器**
  (已裁决导入/pending 跳过/幂等/读取异常 fail-soft)。
- **通用重算公式**(28 档案通用——全档案均为 因子×权重 线性
  结构, **一条公式治理 28 档案**):
  ```
  重算分 = Σ factor.value × 当前冠军权重[factor.name]
  决策漂移 = |重算分 − 原决策分| > 10 → 漂移标记
  ```
- **回放输出**: 原分/重算分/漂移差/权重版本对比/中文归因
  (主贡献因子 Top3); **只读操作零副作用**(回放不修改档案)。
- **日志查询**: 档案过滤 + 逐条漂移标注 + 漂移计数。

### P4 · 合规材料自动化(★★ 备案一键汇编)

- **算法备案材料**(对齐《互联网信息服务算法推荐管理规定》
  备案口径)六节结构化汇编:
  ① 算法基本信息(名称/用途/责任主体占位)
  ② 数据来源与类型说明(最小采集红线声明)
  ③ 算法逻辑(权重表+因子清单——真实数据)
  ④ 公平性与性能结论(引用 P2/P1 报告)
  ⑤ 风险防控与应急处置(冻结机制/干预通道/申诉路径/fail-soft)
  ⑥ 变更记录清单(审批总线留痕)
- **治理审计报告**(时间窗聚合): 变更数/审批通过率/告警统计/
  公平性结论/冻结事件/健康快照引用 + 中文结论——月度治理
  报告一键生成。
- **LLM 三态**: mock(代码模板, **数字永远来自数据层——LLM
  幻觉不进备案**, 41/42/45号同口径)/real(润色)。

### P5 · 治理看板与干预通道(★★ 压轴)

- **看板聚合**(单端点六区块, fail-soft 分区——单区块异常
  不阻断看板): ①档案总览(状态/batch 分布) ②审批队列(pending
  +一键审批) ③健康排行(Top/Bottom5+三检测器命中) ④公平性
  视图(flagged 列表) ⑤回放轨迹(最近日志+漂移标记) ⑥合规
  入口(备案/报告链接+最近审计引用)。
- **红线常驻**(§九五条): 治理不阻断/审批即真值/数字来自
  数据层/最小采集/监督权分离——看板展示层常驻提示。
- **干预闭环 E2E**: 看板提交冻结申请→审批→注册中心生效→
  run_learning 守卫拦截→解冻→学习恢复(全链实测)。
- **前端面板**: `ai-governance-dashboard.html` +
  `js/ai-governance-dashboard.js`(45号 trust-dashboard 范式
  平移: ES5/localStorage 连接/手动刷新/区块化渲染) +
  干预闭环表单(冻结/解冻申请+一键审批+触发巡检)。

### P6 · 巡检日度调度(调度轨增强, 默认 off)

- **调度器**(security_scheduler 同轨范式——独立模块 +
  start/stop 幂等): 每轮三步——① 健康巡检(scan 内部含
  台账同步→三检测器→告警当日同键去重) ② 新告警管理员
  站内信(仅 alertsNew>0 触发, 聚合单封信号分组渲染+处置
  指引; fail-soft 单人失败不阻断; 不发"一切正常"骚扰信
  ——43号 P5-2 范式) ③ 统计留痕(runs/lastRunAt/巡检摘要/
  触达记录/errors, 存 `ai46:scheduler:stats`)。
- **环境开关**: `AI_GOV_SCHEDULER_MODE=on` 开启(**默认
  off——默认零影响铁律**); `AI_GOV_SCAN_INTERVAL` 可调周期
  (默认 86400s, 下限 300s 防忙循环)。
- **接入**: main.py lifespan startup/shutdown(与既有
  调度器同款幂等接入); 无新端点(手动轨复用
  POST /api/ai-gov/health/scan)。

## 六、治理引擎架构

```
28 个评分档案(ai_learning SCORER_REGISTRY, 自发现同步)
    │
    ▼
AI 资产注册中心(ai46_registry: 状态 active|frozen|retired)
    │ 变更审批总线(ai46_changes: 晋升/补丁/冻结 → 人工审批)
    ▼
治理引擎层
┌──────────────────────────────────────────┐
│ P1 健康度: 停滞/枯竭/漂移高 三检测器        │──▶ 治理告警(43号范式)
│ P2 公平性: 群体分布对比+双偏差指标           │◀── 采样(自愿+45号适配)
│ P3 回放: 通用重算公式(28档案线性结构)       │◀── 决策日志总线
└──────────────────────────────────────────┘
    │
    ▼
P4 合规自动化(备案六节/审计报告——数字来自数据层)
    │
    ▼
P5 治理看板(六区块) + 干预通道(冻结审批闭环)
```

**唯一干预点**(fail-soft 铁律):
```python
# ai_learning_service.run_learning_cycle 顶部
try:
    if await AiGovernanceService().is_frozen(scorer_id):
        raise ValueError("档案治理冻结中(审批解锁后恢复学习)")
except ValueError:
    raise
except Exception:
    pass   # 治理设施异常不阻断学习(fail-soft)
```
——未入册=未治理=不干预; 冻结仅拦学习不拦评分。
