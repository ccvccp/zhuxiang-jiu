# 57号·AI智能知识库模块 上线部署操作手册

> 版本：v1.0（2026-09-06）｜适用代码基线：master ≥ `ed453b8`
> 模块：信值驱动的认知基座与信任源头（趋势感知→三重合规鉴别→认知种子→角色植入×信值回流）
> 部署形态：Docker Compose（backend + redis），Redis 持久态，25 端点

---

## 〇、部署摘要（一页速览）

| 项 | 值 |
|----|-----|
| 功能开关 | `KB57_MODE`（off/shadow/assist 三级灰度，默认 **off**） |

## 二、配置项清单

### 2.1 必配（已入册 compose，经 `.env` 覆盖）

| 变量 | 默认 | 生产建议 | 说明 |
|------|------|---------|------|
| `KB57_MODE` | off | 灰度后 shadow→assist | 决策面三级灰度（见 §五 开启顺序） |
| `KB57_LEARN_MODE` | off | 观察期后 on | T+1 调度 |
| `KB57_LEARN_INTERVAL` | 86400 | 86400（可调） | 调度周期秒（下限 300） |

**三级灰度语义**（`KB57_MODE`）：

| 值 | 开放面 | 拒绝面 |
|----|--------|--------|
| off（默认） | 仅观测面 11 端点 | 决策/会员面全 409（零影响铁律） |
| shadow | 观测面+缺口诊断+采集留痕+鉴别（quarantined 入库） | 会员面（种子不暴露） |
| assist | 全链：鉴别+种子工坊+终审发布+feed/view/反馈/路径/触发 | — |

**不受开关影响的面**（任何模式均可用）：
- 终审 `POST /seeds/{id}/review` 与召回 `POST /seeds/{id}/recall`（**终审人工铁律**——published 唯一出口）
- 回流 `POST /feedback/collect`（回流管理面）
- 全部观测面（GET 系）

### 2.2 生效方式

改 `.env` 后执行 `docker compose -p zhuxiang-jiu up -d backend`（容器按配置差异自动重建）。

## 三、部署步骤（全新环境）

```bash
# ① 拉取代码
git pull origin master

# ② 构建（注意：中文目录名下 compose 项目名推导为空——必须显式 -p）
docker compose -p zhuxiang-jiu build backend

# ③ 启动（backend 依赖 redis healthy；容器启动自动跑 seed_redis.py 幂等种子）

# ④ 健康检查（start_period 30s 后应 healthy）
docker ps --filter "name=zhuxiang-jiu-backend" --format "{{.Names}} {{.Status}}"
curl -sf http://127.0.0.1:8000/api/decision/health
```

**当前既有环境说明**：57号 已随 P0-P5 迭代部署在役（默认 off）；本次入册的 compose 开关项与运行态默认值一致，无需立即重启，随下次容器重建自然生效。

## 五、灰度开启顺序（双开关独立，逐级放量）

```
Step 0  部署完成（全 off）
        └─ 观测面冒烟（§4.1——off 亦可用）
Step 1  KB57_MODE=shadow（观察学习期）
        └─ admin 跑 §4.2 shadow 段（诊断→采集→鉴别）
        └─ 观察期 1-3 天：dashboard 合规区三关拦截分布；
           resources 全部 quarantined/compliant（无泄漏路径）
        └─ 终审/召回不受开关影响——可先行演练发布链
Step 2  KB57_MODE=assist（辅助生产期——种子暴露面开放）
        └─ admin 跑 §4.2 assist 段（craft→review→feed→view）
        └─ 试点会员（X-Member-Id）走 feed→view→feedback 全链
        └─ 观察期 3-7 天：度量区五指标+反馈召回预警
Step 3  KB57_LEARN_MODE=on（T+1 调度开放）
        └─ 可先手动 POST /api/kb57/feedback/collect 即时触发首轮补标
        └─ 观察 events：learn_signal / scheduler_run / seed_expire 留痕
```

**放量节奏建议**：内部 admin 演练→试点会员（内部账号）→灰度受众→全量。三铁律保障：未经鉴别资源永存 quarantined（不因放量暴露）；种子必带合规指纹（无指纹不入库/不出口）；预算超支 halted 熔断不降级（49号双段计量）。

**回退语义**：任何阶段 `KB57_MODE` 回退 off——决策/会员面秒级 409 关闭，已发布种子保留（观测面可查）、终审/召回仍可用（人工下架通道不关闭）。

### 6.2 告警口径

| 信号 | 口径 | 处置 |
|------|------|------|
| 源集中度 | dashboard.sourceConcentration.topRatio > 0.8（alert） | 排查采集源投毒（集中采集单一源嫌疑——人工复核+源白名单复查） |
| 高负反馈 | feedback 响应 suggestRecall=true（≥3 反馈且负≥50%） | 人工确认后 `POST /seeds/{id}/recall`（带 affectedMembers 触发 45号补偿） |
| 预算熔断 | compliance 区 budgetHalts 陡增 / verdict=halted | 人工加额（缺口 budgetCap）或放弃采集；检查 49号系统账户（member 0） |
| 隔离态积压 | resources quarantined 态大量滞留 | 内容安全关中风险/低可信度源待人工——走终审链或放弃 |
| 种子过期 | freshness demoted>0（scheduler_run 事件） | 按缺口重新采集→craft 新版（旧版已自动降权不删除） |
| 护栏异常 | defense.guardrail.healthy=false | 第32档案 champion 权重越 [0.5,2.0] 护栏——44号学习中枢排查 |

## 七、回滚预案（三级）

| 级 | 场景 | 操作 | 生效 |
|----|------|------|------|
| L1 功能回退 | 决策/会员面异常 | `.env` 置 `KB57_MODE=off` → `up -d` | 秒级；存量知识链路零影响（off 直通铁律）；终审/召回通道保留（人工下架不失效）；调度可独立保留或同步 off |
| L2 内容回退 | 单种子误导/过期 | `POST /seeds/{id}/recall`（可带 affectedMembers → 45号 L2 补偿） | 不停机；recalled 终态退出推荐池；回流自动记 -0.8 负修正 |
| L3 代码回退 | 版本级故障 | `git revert` + rebuild + `up -d` | 分钟级；Redis 数据兼容（schema 未破坏性变更；五清单只增不改） |

**L2 与 L1 的选择**：内容问题优先 L2（单种子粒度+自动补偿）；链路问题用 L1（面级关闭）。
