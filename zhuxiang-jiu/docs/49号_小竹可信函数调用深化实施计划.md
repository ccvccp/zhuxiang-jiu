## 一、模块定位与核心命题

### 1.1 为什么需要 49号

48号 P1 的 LLM 意图轨是"最小安全版"：LLM 只能从 12 个白名单
action 里选一个，参数由规则抽取，数字全部来自执行层 API。这守住了
底线，但没有释放 Function Calling 的真正价值——

- **约束是外部硬拦的**：LLM 看不到"这个工具不能做什么"，靠后端
  ValueError 拒绝；模型每次"撞墙"都是一次浪费的推理
- **多步规划无隐私视野**：LLM 无法感知连续调用的隐私代价，用户
  也没有"隐私预算"的知情与控制权
- **结果不可解释**：兑换/修复执行成功后只有数字，没有归因引用，
  用户不知道"为什么恢复这么多"

49号的答案：**可信函数调用四铁律**（显式授权前置 / 输出可解释
绑定 / 隐私预算感知 / 失败安全降级）+ **工具注册表 v2**（约束内嵌
工具描述）+ **FC 网关三重校验**。

### 1.2 三大理念落法

| 理念 | 落法 |
|------|------|
| 遵循规则 | 工具描述内嵌行为禁令（❌）与隐私成本（🔒）——LLM 推理阶段即感知约束；写操作强制 consent_token（双因子）；FC 调用全量审计 |
| 方便快捷 | 只读工具零摩擦直达；预算/授权状态可随时语音查询；失败一键转人工 |
| 智能自主 | 多步调用的隐私成本自动累计；归因报告自然语言播报；红队测试持续防护注入 |

### 1.3 一句话内核

> **Function Calling 的安全性不在于限制模型能力，而在于让约束成为
> 模型认知的一部分——小竹从"能做事的 AI"进化为"懂规矩的信值伙伴"。**

## 三、红线冲突辨析（本规划的工程判断）

### 3.1 冲突点：语音确认 vs 声纹非凭证

**方案原文**：用户语音说"确认预约社区安全宣讲"→ ASR+声纹验证 →
生成 consent_token。

**48号既有红线**（宪法级，不可逾越）：高敏不可纯语音——声纹≠
身份凭证，confirmToken 屏幕码为准。

**裁决：双因子合成，两全其美**——

```
语音确认词（行为意图证据） ──┐
                            ├─→ consent_token（有效期 60s）
屏幕码核销（身份凭证）    ──┘
```

- **语音确认词**：用户须清晰说出预确认短语（ASR 精确匹配），作为
  意图证据记入审计——满足方案"显式授权"语义
- **屏幕码**：4 位数字码核销仍是身份凭证唯一通道（既有 confirmToken
  流不变，仅 TTL 120s→60s）——守住"语音念码不算"红线
- **合成 token**：两因子齐备才签发 consent_token（SHA-256 随机），
  一次性核销，hash 入审计（明文不落库）

### 3.2 冲突点：隐私预算 vs 信值等级

**潜在歧义**：47号画像 watched/restricted 档是否预算更低？

**裁决：预算均等**——隐私是基本权利不是特权，预算只按"用户自主
偏好"分级（默认 1.0/日，用户可调 0.5-2.0），**绝不与信值等级挂钩**
（46号公平性桥接会审计这一点——voice_L* 分组的工具调用成功率仍
须无歧视）。

### 3.3 冲突点：LLM 多步自主 vs LLM 不产数字

**方案语境**：大模型规划多步调用（查窗口→推荐→预约）。

**裁决：规划可以自主，落笔必须留痕**——LLM 可在一次会话内串联
多个只读工具形成推荐（如"查修复窗口→匹配 β 最优项"）；但每步
工具调用的参数与结果全部落 FC 审计流水，且写/高敏操作每步独立走
双因子确认（不因"同一意图链"合并授权）。

## 四、可信函数调用四铁律（工程化定义）

### 铁律① 显式授权前置

- 所有写操作（修复执行/信值兑换/数据提交/共创上架）必须携带
  consent_token
- 签发条件：语音确认词（意图）+ 屏幕码（身份）双因子齐备
- TTL **≤60s**（48号 120s 收紧）；一次性核销；token_hash 审计
- 声纹 speaker 绑定：外部待办前以确定性哈希代理——token 记录
  签发对象的声纹摘要，跨用户复用无效（代理口径，不作身份凭证）

### 铁律② 输出可解释绑定

- 每个写工具响应体**必填** explainability_ref（归因报告引用）
- 归因三源：45号 attribution（修复/兑换数学分解）+ 46号决策回放
  （重算轨迹）+ 49号新增语音归因播报（自然语言转化）
- 缺失 ref 的响应在服务端**自动阻断**（raise，不返回半成品）
- 用户可说"打开修复说明"→ 归因报告卡片（explainability_ref 落地页）

### 铁律③ 隐私预算感知

- 工具描述声明 privacy_cost；FC 网关累计扣减（原子操作）
- 预算账户：会员日预算（默认 1.0，偏好可调 0.5-2.0）+ 会话窗预算
- 超限 → 429 语义 + 标准话术（"隐私预算不足(剩余 X, 需 Y)——
  请在设置中调整隐私偏好或明日再试"）+ 只读工具不受限（零成本
  工具永不降级）
- 预算查询语音直达："我的隐私预算"→ 余额+近 7 日消耗卡片

### 铁律④ 失败安全降级

- 工具调用失败/超时 → LLM **不得编造结果**（"LLM 不产数字"的
  推广红线：不产数字、不编结果）
- 统一安全兜底话术（预定义，不暴露内部细节）+ 人工客服转接选项
  （chat.human 绑定——48号既有指令复用）
- 兜底触发本身落 FC 审计（kind=fallback）→ 看板失败降级计数

## 五、核心架构

### 5.1 工具注册表 v2（Tool Registry）

每个工具的注册结构（OpenAPI 3.1 语义，代码内 manifest）：

```python
TOOL_REGISTRY = {
    "trust.convert": {
        "operationId": "convert_credit_to_trust",
        "summary": "信用分兑换信值",
        "description": "【高敏·写】仅双因子确认后调用。"
                      "❌ 禁止无 consent_token 调用；"
                      "❌ 禁止自动串联多笔。🔒 privacy_cost: 0.08",
        "tier": "sensitive",          # readonly|write|sensitive
        "privacy_cost": 0.08,
        "requires_consent": True,
        "params": {...}, "response": {...},
    },
    ...
}
```

要点：
- **description 内嵌禁令与成本**——注入 LLM System Prompt 后，
  模型在推理阶段即感知约束（方案核心思想：约束成为认知的一部分）
- 三级分级继承 48号沙箱白名单（readonly/write/sensitive 一一对应）
- 只读工具 privacy_cost 0-0.02；写 0.02-0.05；高敏 0.08

工具全集（13 = 48号 12 指令 + 新增修复执行）：

| 工具 | operationId | 分级 | privacy_cost | 说明 |
|------|-------------|------|-------------|------|
| product.new | list_new_products | 只读 | 0.01 | 看新品 |
| product.price | query_product_price | 只读 | 0.01 | 问价格 |
| trust.score | get_trust_score | 只读 | 0.02 | 查信值(含三层明细+趋势) |
| trust.balance | get_trust_balance | 只读 | 0.02 | 查余额 |
| trust.exchange | get_exchange_rate | 只读 | 0.01 | 能换吗换算 |
| promo.query | query_promotions | 只读 | 0.01 | 查优惠 |
| nav.page | navigate_page | 只读 | 0.01 | 打开页面 |
| chat.human | transfer_human_agent | 只读 | 0 | 转人工(兜底出口) |
| xiaozhu.help | describe_capabilities | 只读 | 0 | 你能干什么 |
| repair.plan | get_repair_window | 只读 | 0.02 | **新增**:修复窗口/β匹配推荐 |
| trust.bind | bind_trust_profile | 写 | 0.02 | 绑定档案 |
| cart.submit | submit_checkout | 写 | 0.05 | 结算下单 |
| trust.convert | convert_credit_to_trust | 高敏 | 0.08 | 信用分换信值 |
| repair.execute | execute_repair_action | 高敏 | 0.08 | **新增**:执行修复对冲(方案核心场景) |

### 5.2 FC 网关（三重校验管道）

```
LLM 工具调用请求
   │
   ▼
[校验① consent_token]──写/高敏必须──┐ 无效/过期→403 话术
   │                                │
[校验② 隐私预算]───────────────────┐ 超限→429 话术+偏好引导
   │                                │
[执行] 沙箱白名单执行器(48号 P2 复用) │
   │                                │
[校验③ explainability_ref]─────────┘ 写响应缺失→阻断(500 内部错误)
   │
   ▼
[审计] voice48_fc_audit 流水落库
   │
   ▼
响应(含 ref) → LLM → 自然语言归因播报
```

- 网关是执行器（xiaozhu_executor）的外壳：**沙箱分级/幂等/冷静期
  全部继承**，只加三重校验与审计
- 校验顺序：token（最严）→ 预算 → 执行 → ref（响应侧）

### 5.3 与 48号既有架构的关系

| 48号组件 | 49号处置 |
|---------|---------|
| 指令注册表 COMMANDS | 保留（规则轨不变）；新增 TOOL_REGISTRY 平行映射（action 同名对齐） |
| xiaozhu_executor 沙箱 | FC 网关包裹复用（三级分级/幂等/冷静期不动） |
| confirmToken 流 | 升级为双因子 consent_token（屏幕码流不变，加语音确认词+TTL 60s） |
| _llm_match | 升级为 _llm_tool_call（工具描述注入 System Prompt） |
| LLM 轨开关 | XIAOZHU_LLM_MODE 继续控制（49号全部能力默认 off 零影响） |
| 失败挖掘/共创/看板 | 全保留；看板加 FC 分区（P4） |

## 六、分期计划

### P0 可信工具注册表与 FC 网关骨架

- TOOL_REGISTRY v2（13 工具：描述内嵌禁令/成本/分级）
- FC 网关服务（三重校验管道骨架：token/预算占位校验+审计落库）
- voice48_fc_audit 审计表（fcId/memberId/toolName/tier/
  consentTokenHash/privacyCost/latencyMs/kind(ok|fallback)/ts）
- LLM 轨升级：System Prompt 工具描述注入（_llm_tool_call）
- 失败安全降级话术表（每工具预定义 safe_message+转人工选项）
- 兜底话术与 chat.human 绑定

**测试**: 专项约 22 项（注册表完整性/描述禁令注入/审计落库/
降级话术触发/LLM 注入结构）

### P1 consent_token 双因子流

- 双因子合成：语音确认词（ASR 精确匹配预确认短语）+ 屏幕码核销
- TTL 收紧 120s→60s（CONFIRM_TOKEN_TTL 常量调整+提示语同步）
- token 签发/一次性核销/hash 审计（明文不落库）
- 声纹代理绑定（确定性哈希记录签发对象，跨用户复用无效断言）
- 修复执行新工具走全流（repair.execute——方案核心场景 E2E）

**测试**: 专项约 24 项（双因子缺一不可/TTL 边界/一次性/跨用户
复用拒绝/意图证据留痕）

### P2 隐私预算

- voice48_privacy_budget 表（会员日预算+偏好+当日累计）
- 预算扣减原子操作（Redis 侧 Lua/事务；内存侧锁）
- 超限 429 话术+偏好调整端点（GET/PUT /api/xiaozhu/privacy/
  preferences——用户自主，与信值等级无关）
- "我的隐私预算"语音指令（余额+近 7 日消耗卡片）
- 只读零成本工具永不降级断言

**测试**: 专项约 20 项（预算数学/原子性/超限话术/偏好调整/
只读不受限/日切重置）

### P3 可解释性绑定（explainability_ref）

- 写工具响应强制绑定 ref（缺失自动阻断——服务端 raise）
- 归因三源桥接：45号 attribution（修复/兑换分解）+ 46号决策回放
  + 49号语音归因播报模板（"这次修复之所以高效，是因为它与您的
  逾期类型高度匹配"——参数化，非 LLM 生成）
- "打开修复说明"指令 → 归因报告卡片
- Schema 校验断言（CI 口径：响应缺 ref 的工具调用即测试失败）

**测试**: 专项约 18 项（ref 必填阻断/归因数学一致/播报模板
参数化/卡片直达）

### P4 红队测试与收官

- Prompt 注入红队用例集（工具描述越狱测试：伪造禁令覆盖/成本
  篡改/越权工具诱导——断言全部被拒）
- 看板扩展：FC 分区（调用量/失败降级/预算消耗/token 拒绝分布）
- 上线前安全检查清单七项逐项核验（方案 §五）
- 三件套文档（实施收官/验收报告/运维手册增补）
- 交叉回归：45/46/47/48号全量

**测试**: 专项约 20 项+红队用例集 ×2 轮实机

## 十一、关键风险
