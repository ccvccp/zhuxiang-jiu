# 43号·AI智能安全管理模块 P4 展望实施计划 v1.0

> 配套：[43号交付总结 P0-P3](AI智能安全管理模块43_交付总结.md) §八
> 定位：P0-P3 已交付完整安全免疫系统；P4 为**运营成熟化**——从"功能全"走向"数据驱动的持续运营"：D5 联动决策依据数据而非拍脑袋、基线构建无人值守、威胁情报外源引入、安全运营看板量化。
> 调研结论（2026-09-03）：调度器需新建（现有 9 类调度均为独立模块模式）；D5_stuffing 事件当前被学习回流显式跳过；IP 信誉无外部注入入口；Redis 实况监控无现成数据源。

---

## 一、四个方向总览（按价值/依赖排序）

| 编号 | 方向 | 核心价值 | 依赖 | 建议优先级 |
|------|------|---------|------|-----------|
| P4-1 | 安全运营日报（SOC Daily） | 误报率/D5 联动决策的**数据基础**——一切后续决策的依据 | 无（纯内部统计） | ★★★ 先行 |
| P4-2 | UEBA 基线日度自动重建 | 基线从"手动触发"走向"无人值守" | 调度器新建（仿 9 类既有模式） | ★★★ 高 |
| P4-3 | 威胁情报外源接入（黑名单订阅） | IP 信誉从"自积累"扩展"外源情报"，冷启动即有防护 | 外部源选择 | ★★ 中 |
| P4-4 | Redis 实况监控 + 安全运营看板 | 存储层健康 + 面板量化运营 | 采 Redis SLOWLOG/INFO | ★ 中 |

**实施顺序**：P4-1 → P4-2 → P4-3 → P4-4。P4-1 是纯统计端点零风险先行；P4-2 复用其日报数据判断重建收益；P4-3/P4-4 相互独立可并行。

## 二、P4-1：安全运营日报（SOC Daily）

### 现状与差距
- `stats()` 仅返回当前时刻快照（事件总数/误报率/积压），**无时间维度**——无法回答"D5 上线两周误报率多少""误报率周环比趋势"这类联动决策问题。
- D5 联动的前提（交付文档 §八）是"observe 两周后按误报率数据决定"——当前没有数据支撑。

### 实施方案

**① 日报数据模型**（复用 security43 前缀）：
```
security_daily_reports   按日聚合快照
  key: report:{YYYY-MM-DD}
  { date, eventsByAction{...}, verdicts{confirmed, falsePositive,
    pending}, falsePositiveRate, appeals{...}, blocks,
    d5Jumps, d5Stuffing, verifyPass, captchaMode,
    activeMembers, postureTimeline[{posture, hours}] }
```

**② 日报生成**（`daily_report(day)`）：
- 按日切分 security_events（`createdAt` 前缀过滤）
- D5 专项统计：`factors` 含 D5_stuffing 的预警数、identity_risk 降分请求中 D5 命中占比
- 态势时间线：security_posture.history 按日归并

**③ 端点（2 个新增）**：
- `GET /admin/reports/daily?days=14`：近 N 天日报序列（联动决策数据源）
- `GET /admin/reports/d5`：D5 专项观测（命中数/误报裁决率/建议：是否参与联动）

**④ D5 联动决策口径**（硬标准，写入操作指南）：
```
观察期 ≥14 天 且 D5 相关事件误报率 <5% 且样本 ≥20
  → 建议开启 D5 强制联动(identity_risk 降分参与评分)
否则 → 继续 observe, 日报端点持续输出依据
```

### 测试与验收
- 专项：日报聚合正确性（跨日事件切分）/ D5 专项统计 / 空数据日 / 14 天序列
- 实机：制造事件→次日日报可查

### 关键风险
- 时区口径：`createdAt` 为 UTC ISO，日报按 UTC 切分（与现有 ts() 一致，无需转换）

## 三、P4-2：UEBA 基线日度自动重建

### 现状与差距
- 基线仅手动端点 `POST /admin/behavior/rebuild` 触发——长期运营下基线将停滞，检测精度衰减。

### 实施方案

**① 新建调度器**（`services/security_scheduler.py`，仿 9 类既有模式）：
```python
start_scheduler() / stop_scheduler()
# 后台循环: 每 SECURITY_UEBA_REBUILD_INTERVAL(默认 86400s)执行
#   ① UebaService().rebuild_baselines()
#   ② 顺带触发 PostureService 窗口评估(空窗口降级检测)
# 开关: SECURITY_SCHEDULER_MODE 默认 off(对齐 AI_LEARNING_AUTO 惯例)
```

**② main.py lifespan 挂载**（对齐 ai_learning_scheduler 模式）

**③ 重建收益日志**：每次重建输出 personal/globals 计数与 diff（基线数变化），日报端点可观测重建是否健康（基线数持续下降=采集异常告警）

**④ 环境变量**：`SECURITY_SCHEDULER_MODE=off` / `SECURITY_UEBA_REBUILD_INTERVAL=86400`

### 测试与验收
- 专项：调度器启停幂等 / 重建执行 / 开关 off 零调度
- 实机：容器开调度 → 间隔后基线自动更新

### 关键风险
- 重建耗时随会员数增长——批量重建分批（每批 100 actor，批间 sleep），防事件循环饿死

## 四、P4-3：威胁情报外源接入

### 现状与差距
- IP 信誉完全自积累（冷启动 80 白纸一张），遭遇已知恶意 IP（爬虫农场/僵尸网络）需多次攻击才降分。

### 实施方案

**① 外部源选择**（免费可商用优先）：
- **Firehol IPList**（GitHub 开源，ipset 聚合多源，CC0 许可）：`firehol_level1.netset`（已知恶意段，约 2k 段）
- 备选：AbuseIPDB API（免费 1000 次/天，需 key）
- P4 先做 Firehol 静态文件导入（无 API 依赖、无频控），AbuseIPDB 实时查询留 P5

**② 导入端点与流程**：
- `POST /admin/threatintel/import`：上传/拉取 netset 文件 → 解析 CIDR → 批量写入 IP 段信誉表（`security43:threatintel` Hash，field=CIDR, value=源+导入时间）
- 建议周度手动导入（文件下载也需外网），自动订阅留 P5

**③ 信誉查询扩展**（`ensure_reputation` 前置检查）：
```python
# _do_process ② 处: 命中威胁情报段 → 信誉直通 suspicious(30)
# 不直接 blacklisted(防误杀: 情报段可能含共享出口)
if await self.repo.match_threatintel(ip):
    reputation_score = min(reputation_score, 30.0)
```
- CIDR 匹配：ipaddress 标准库（段数少，线性匹配可接受；>10k 段时改前缀树）

**④ 端点（2 个）**：`POST /admin/threatintel/import` + `GET /admin/threatintel/stats`（导入段数/命中率）

### 测试与验收
- 专项：netset 解析 / CIDR 匹配命中/不命中 / 命中降分不直封 / 导入幂等
- 实机：导入样例段 → 命中 IP 请求 → 信誉降分留痕

### 关键风险
- 情报误伤（共享出口 IP 入段）→ 只降档不直封 + 申诉通道兜底；管理端可对单 IP 加白（pin 已有）

## 五、P4-4：Redis 实况监控 + 安全运营看板

### 现状与差距
- monitor/maintenance 巡检均为模拟数据；安全模块的 rate/behavior/session 等 Redis 键族无实况监控（大 key/过期堆积风险不可见）。

### 实施方案

**① Redis 实况采集端点**（`GET /admin/redis/health`，admin 鉴权）：
- `INFO memory`：used_memory/memory fragmentation
- `DBSIZE` + `security43:*` 键族计数（分前缀：events/baselines/rate/session）
- `SLOWLOG GET 10`：慢命令 Top10
- 大 key 抽查：security_events 键的 MEMORY USAGE 超 100KB 告警

**② 安全运营看板扩展**（ai-security-dashboard.html 新增第七区块）：
- 日报序列图（P4-1 数据：误报率/D5 命中趋势，纯 CSS 柱状图，零图表库依赖——对齐面板 ES5 范式）
- Redis 键族健康卡（events 数/rate 键数/内存水位）

**③ 告警阈值口径**（写入操作指南）：
```
events 单键 >100KB → 建议裁决归档清理
rate:* 键数 >100k → 窗口泄漏检查(过期策略)
used_memory > 80% maxmemory → 扩容评估
```

### 测试与验收
- 专项：INFO 解析 / 键族计数 / 慢日志读取 / 阈值告警
- 实机：容器内真实 Redis 数据可查

### 关键风险
- SLOWLOG/MEMORY USAGE 在大库上的执行开销——仅 admin 手动触发（不进 30s 自动刷新），面板按钮按需加载
