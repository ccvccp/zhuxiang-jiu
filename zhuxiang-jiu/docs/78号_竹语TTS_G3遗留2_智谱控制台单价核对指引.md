# 78号·竹语 TTS G3 遗留 #2：智谱控制台流式单价核对指引

## 一、为什么要核

P1 流式 TTS 已全量上线（`/tts/stream`），代码默认假设**流式与非流式同价、按字符计费**（G3 spike 时流式响应无 usage 字段，无法从 API 侧自证）。第三方转售价参考 0.03 PTC/千字符（302.ai），但权威值须以智谱控制台为准。若流式实际按时长计费或单价更高，P1 成本模型需修正。

## 二、核对步骤（三处交叉）

### 第 1 处：用量明细（计费口径实证——最关键）

1. 登录 **open.bigmodel.cn** → 右上角进入**控制台**
2. 左侧 **财务中心** → **用量明细**（或"资源用量/账单明细"，以实际界面为准）
3. 筛选：**日期=今天**、**模型=cogtts**（本站 TTS_MODEL；若列表另有 glm-tts 也一并看）
4. 记录三个字段：
   - **计费单位**：按"字符/token"还是按"分钟/时长"
   - **单价**（元/千字符 或 元/分钟）
   - **今日用量数值**（与下面第 3 步的本站基准对照）

### 第 2 处：定价公示页（官方单价）

- 打开 **open.bigmodel.cn/pricing** → 搜 **GLM-TTS / cogtts**
- 记录公示单价，并确认是否区分"流式/非流式"两档
- 若定价页无流式区分 → 大概率同价（流式只是响应方式不同）

### 第 3 处：本站今日基准（数量级对账）

今天（09-23）本站已知调用量，可与账单对齐数量级：

| 调用源 | 约定量 |
|---|---|
| nginx `/tts` 整句请求 | 242 次（含验收） |
| `/tts/stream` 流式请求 | 少量（2-10 次） |
| 服务端预合成/容器 spike | 约 20 次 |
| 预估合成字符总量 | 数千～1 万字符级 |

若账单今日用量与上表同数量级 → 计费统计口径无遗漏；偏差一个数量级以上 → 计费单位可能不是"字符"。

## 三、判读标准（对号入座）

| 核对结果 | 结论 | 后续动作 |
|---|---|---|
| 流式=非流式，按字符计费 | **零增量假设成立** | 无动作，D1 门直接过；本指引归档 |
| 流式单列更贵（按字符但单价高） | 成本小幅上浮 | 算账：月增量 = 流式轮次占比 × 差价 × 月字符量 |
| 流式按时长计费（如 0.18 元/分钟档） | 成本模型需修正 | 用下式重算月账单 |
| cogtts 与 glm-tts 分开计价 | 无影响 | 本站用 cogtts，按 cogtts 档核对即可 |

**月账单估算公式**（拿到单价后代入）：
```
月字符量 ≈ 日均 TTS 请求 200~450 次 × 平均 40 字/次 × 30 天 ≈ 24~54 万字符/月
月账单 ≈ 月字符量 × 单价(元/千字符) ÷ 1000
参考: 0.03 元/千字符 → 月账单约 7~16 元(远低于 B 路线 GPU 月租, 自建 ROI 触发器不触发)
```

## 四、顺手核对（顺路 2 分钟）

1. **QPS/并发限制**：定价页或文档 FAQ 看 cogtts 并发上限——填入 B 路线触发器"供应商限流"观察项
2. **免费额度/资源包**：财务中心 → 资源包管理，看有无 TTS 资源包可领
3. **账单告警**：财务中心设置余额告警阈值（建议：月预估 ×3）
