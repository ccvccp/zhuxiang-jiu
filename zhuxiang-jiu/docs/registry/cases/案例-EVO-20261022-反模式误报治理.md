# 案例-EVO-20261022-反模式误报治理

## 一、现象

竹演 B4 反模式 Fast Filter 真实快筛 2651 单元命中 74 处疑似(全 AP-5)。
人工精审(逐处读代码取证)发现: 74 处按端点计数去重后仅 4 处代码位置,
其中 3 处误报+1 处语义豁免, **0 处真反模式**——快筛疑似不能直接当整改清单。

## 二、根因

Fast Filter 块级近似的三重粒度缺陷(v1 口径):
①def 块按行扫描至下一 def 行, 无缩进感知——嵌套/后续同级代码被并入块
(xiaozhu _wake_hot 误报源); ②块级规则"块内任意 for+任意日志即报",
不校验日志是否在循环体内(except 兜底/循环后聚合日志误报源);
③每规则每单元首处取证——首处误报掩盖同文件后续真阳性
(xiaozhu ws_asr_final 观测埋点被 345 行误报掩盖)。

## 三、错误代码/配置

v1 口径(已废弃): `_def_blocks` 按行扫描无缩进判定; 块级命中不校验
循环体内位置; 命中明细 `found[:8]` 仅展示前 8 处——74 处全量明细须
临时脚本导出(精审第一步: 口径还原 74→4)。

## 四、正确写法(只出不施→经确认已施, 提交 06dba25d)

v2 三改进(精审清单三建议全部实装 antipattern.py):
- **def 块缩进感知**: 块止于缩进回落至 def 行及以下的非空行
- **危险调用须在循环体内**: for/while 行(缩进 m)之后缩进>m 的连续行才计
- **文件级豁免通道**: `# zhuyan-exempt: AP-5` 标记跳过对应规则
  (module_guard.py 部署预检报告输出已标记)
配套: B4 回归 5/5+干净零误报不变; v2 复扫 66 处全为 ws_asr_final
观测埋点(v1 掩盖的真阳性浮出)——人工裁量为白名单断言
(`test_v2_real_scan_full_zero`: 白名单外零命中, 新疑似将红)。

## 五、预防规则

快筛规则迭代须配套三件: ①B4 已知答案回放不退化; ②真实全量复扫
新旧对比(误报消除+真阳性不丢); ③已知人工裁量项显式白名单入测试
断言(不静默豁免)。快筛命中在精审前一律"疑似"口径——禁止直接当
整改清单下发(检得出≠改得对)。
