# 案例-EVO-20261022-SEO修复态基准联动

## 一、现象

竹园移交 SEO 23 页 meta description 补齐+P2 8 页 noscript 兜底块补齐后,
竹园 audit 台账 missing 全清零(healthy=25, p0/p1/p2 全 0)——但竹演全量
pytest 出现 1 红: `test_t03_page_seo_evidence` 断言"竹园 audit 已证缺口
(has_description=False)"失败——**修复动作触发了下游基准测试的断言失效**。

## 二、根因

基准测试锚定"真实缺口存在"作为已知答案(B3 低分样本取证)——
`assert act["contract"]["has_description"] is False` 把缺口态写死。
缺口被修复后证据翻转(True), 断言必然红。缺陷不在修复也不在基准本身,
而在**缺口修复与基准断言之间缺联动约定**(与竹园 T3.5 案例计数断言
联动 10→12 同构)。

## 三、错误代码/配置

```python
# 修复前(v1): 永久锚定缺口态——修复即红
assert act["contract"]["has_description"] is False, \
    "竹园 audit 已证缺口——指纹如实呈现(B3 低分样本)"
```

## 四、正确写法(只出不施→经确认已施, 提交 06dba25d)

```python
# 修复后(v2): 翻转为修复态断言+联动说明
assert act["contract"]["has_description"] is True, \
    "23 页 seo_missing 已补齐——指纹应呈现修复态(原低分样本转 True)"
```
配套纪律: 修复真实缺口的提交须同批检查以其为样本的基准断言
(grep 断言文案/样本名), 翻转断言并注明日期+处置提交号; B3 分档回放
不依赖真实缺口页(已知答案回放自带样本)故无联动。

## 五、预防规则

以"真实缺口/真实风险"为已知答案的基准断言, 须在测试注释中标注
样本来源与联动条件(如"缺口样本, 修复后须翻转")——修复对应缺口时
同步翻转断言, 禁止两种反模式: ①为保绿回滚修复(因噎废食);
②删断言了事(丢基准)。家族案例库同类先例: 竹园 T3.5 案例计数联动
(库扩容时计数断言同步+1)。
