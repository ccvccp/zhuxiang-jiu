# 案例-20261021-移动筛选霸屏

## 一、现象

2026-10-21 用户手机（荣耀/QQ 浏览器）点"经典系列/珍藏系列"筛选**无反应、
无商品挂载**的真空壳观感，连续四轮报障。但 nginx 日志铁证显示：
js 拉新成功 + live API 200 + 商品图五张全部 200——**商品实际已渲染**，
问题出在用户"看不见"而非"不存在"。

## 二、根因

移动端 products-layout **单列堆叠**使侧栏筛选面板占满整屏，商品网格被
顶到视口外一屏——用户点筛选后**变化不可见**，误判空壳。叠加用户端云缓存
（QQ 浏览器云加速疑似无视 no-cache）反复喂旧版，v1/v2 修了也触达不了，
掩盖真实交互缺陷，拖成四轮。教训：**"点后无反应"类体感故障要先取证
（日志/截图/UA 实测）分清"没渲染"还是"看不见"，再分清"没修复"还是
"修复没触达"**。

## 三、错误代码/配置

v1 修复前的移动端布局语义（css 单列堆叠 + 常驻侧栏）：

```css
@media (max-width: 768px) {
  .products-layout { /* 侧栏 + 商品单列堆叠, 侧栏霸屏 */ }
}
```

## 四、正确写法

三轮迭代（a166e693 → 2370b4c0 → 5cceb56e）：
v1 折叠面板（默认收起为按钮）→ v2 选定任一项后事件委托自动收起回商品区
（innerWidth<=768 限定）→ **v3 换思路**：干掉侧栏面板概念，系列 chips
横滑条常驻商品区正上方，点选即筛同屏可见——**结构上杜绝"点后看不见"**；
配合缓存三重击破（入口 ver=2 换 URL 强制回源 + nginx html no-store + 页面
no-cache）。线上 QQ 浏览器 UA 终验：13 卡首屏 + 珍藏 1 卡 + 经典 3 卡 +
回全部 13 卡全绿。

## 五、预防规则

移动端交互修复必须线上 UA 实测"点后同屏可见"才算闭环；同页面连续两轮
修复被缓存拦截时，第三轮应换交互形态/换 URL 而非继续打补丁——挂 B1
（缓存面）+ NEW-T1.3（前端调用点审计含交互可见性）。
