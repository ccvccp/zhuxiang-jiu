# 案例-20261021-45度库存事故

## 一、现象

2026-10-19 手机/PC 商城中「竹奕·竹香经典 45° 500ml」（ZX45-2026L05）
商品页显示**"仅剩 0 瓶"**，其余 12 款商品库存显示正常。

## 二、根因

全量盘点 zhuxiang:inventory:* 发现：45° 商品**自身没有库存键**
`zhuxiang:inventory:ZX45-2026L05`——历史库存键被写成了 **ZX42-2026L05**
（42/45 前缀笔误）。该笔误键在 store.py 初始库存中被有意保留（注释：
兼容订单测试），属历史兼容键不可删除。商品查库存按自身 ID 取键 →
键不存在 → InventoryRepository 返回 0 → 前端展示"仅剩 0 瓶"。
上架时"product hash + inventory hash 两键同建"规则（进化清单 C2）在
存量历史数据上失守。

## 三、错误代码/配置

键名错位实况（Redis 取证）：

```
商品ID:      ZX45-2026L05  ──查──>  zhuxiang:inventory:ZX45-2026L05  (不存在 → stock=0)
历史遗留键:   ZX42-2026L05  (stock=300, 兼容键, 保留)
```

## 四、正确写法

三层齐写（提交内含 store.py seed 变更）：① 海外 Redis
`hset zhuxiang:inventory:ZX45-2026L05 stock=300 reserved=0` ② ECS 本地
Redis 同键 ③ seed 源码 store.py `_build_initial_inventory()` 补
`"ZX45-2026L05": {"stock": 300, "reserved": 0}` 带 `[进化 2026-10-19]`
注释——Redis 全量重建（清库重灌）后 45° 也自带库存，防复发。不删除
历史兼容键 ZX42-2026L05（订单测试依赖）。验证：双端+公网 45° stock=300 ✓
+ 全量 13 款零库存复查 NONE ✓。

## 五、预防规则

新商品上架"product hash + inventory hash"**两键必须同建**，键名以
商品 ID 为唯一来源禁止手工拼接（C2 已有，本案例为存量历史数据的
实例印证）；日常巡检零库存复查非 NONE 即报警（overseas-inv-audit.sh
可复用）——挂 C2（已有进化清单）。
