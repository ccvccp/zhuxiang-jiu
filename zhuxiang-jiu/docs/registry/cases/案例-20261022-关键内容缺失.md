# 案例-20261022-关键内容缺失

## 一、现象

竹园盘点(audit T0.3)空正文口径(<200 可见字符)检出 8 页 content_missing
(P2)——以 app.html 为代表(可见正文仅 3 字符, 同类发现共 8 处)。该批页面
为下载/跳转类功能壳页, 静态源码几乎无文本内容。

## 二、根因

功能性壳页(下载引导/客户端跳转)的 UI 依赖少量 JS 动态注入或纯外链按钮,
既未接入共享渲染资产(js/main.js 亦未引用, 无法借共享文本达标), 也无独立
静态内容——对审核器/搜索引擎与禁 JS 环境, 该页近乎空白(核实方式: 源码
可见文本计数, 对照 SPA 壳豁免口径)。

## 三、错误代码/配置

app.html(代表页)——剥离 script/style 与标签后可见文本仅 3 字符:

```text
$ python -c "..._visible_text(open('app.html').read())..."
→ '下载'  (3 字符 < 200 阈值, 且未引用 js/main.js 共享文本)
```

## 四、正确写法

按《资产标准.md》补齐关键内容三选一:
1. 壳页静态化兜底——noscript 块写明用途+主体+资质引用(参照 index
   noscript 资质块写法);
2. 接入共享渲染(引用 js/main.js 借页脚资质/警示语文本达标);
3. 功能说明正文≥200 字符(下载指引+版本说明+联系渠道)。

## 五、预防规则

新壳页/新资产接入时对照《资产标准.md》七项口径自检(空正文阈值 200);
audit 盘点台账按 P0-P2 把关(content_missing 非占位类=P2);
prescribe 按缺口类型出处方(只出不施)。挂 80号-T0.3 盘点口径。
