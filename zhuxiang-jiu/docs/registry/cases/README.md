````markdown
# 案例-20261021-qr白名单死条目

## 一、现象
2026-10-21 扫码登录: scan/exchange/cancel 三步全部被 auth 中间件 401 拦截,
扫码链 100% 断裂（confirm 401 为设计内登录态, 非事故面）。

## 二、根因
PUBLIC_EXACT 白名单 3 条目为无参形态（未对照 L0-端点清单实际路由）。
实际路由为 /qr/{qr_id} 带参形态, EXACT 全等匹配永不命中→死条目。

## 三、错误代码/配置
backend/core/auth_middleware.py PUBLIC_EXACT（e73f6800 修复前）:
    PUBLIC_EXACT = {
        ..., "/qr/scan", "/qr/exchange", "/qr/cancel",  # 死条目: 实际路由为 /qr/{qr_id} 带参形态
    }

## 四、正确写法
删 3 死条目 + 新增 PUBLIC_POST_PATTERNS 正则档放行带参 POST 路由
（提交 e73f6800）; exchange 公开性靠 loginTicket 60s 一次性防重放, 零身份依赖。

## 五、预防规则
白名单新增条目必须与 L0-端点清单实际路由逐条对照（含参数形态）——挂
NEW-T1.2(鉴权可达)与 NEW-T2.3(死条目检测), M1/M2 回放基准。
````

## 入库规则

1. **一案一文件**, 命名 `案例-YYYYMMDD-<短名>.md`——日期为事故发现日期, 短名用中文短语（同日多案按发现顺序编 id 序号）
2. **修复提交当日入库**——复盘完成（现象+根因+修复落库）即写, 不攒批
3. **五段式缺一不可, 元数据必填字段齐全**——缺段/缺字段视为不合格, M0 抽检口径 6/6
4. **证据驱动（铁律 2）**——三、四段必须附文件路径（行号或提交号）, 无出处标"低置信度"
5. **入库后不改写历史**——新发现（如根因修正/复发）追加 `## 附记` 段并注明日期, 五段原文保持事发时快照
6. **预防规则出口（可挂竹盾 rules）**——能映射到竹盾检查清单的标已有编号（B1/C3/C4/E/F1）, 新规则标 `NEW-<竹医任务号>` 待 lead 评审
7. **MD 为源（铁律 3）**——本目录全部入 git, T3.1 检索器直接扫描 MD+front matter, 衍生索引由脚本生成, 禁手工编辑衍生文件
8. **真实事故优先**——虚构/推测型案例不入库; 入库案例须有对应修复提交或工单/报障记录佐证
