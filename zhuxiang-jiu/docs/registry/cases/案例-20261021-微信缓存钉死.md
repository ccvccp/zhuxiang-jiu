# 案例-20261021-微信缓存钉死

## 一、现象

2026-10-21 用户安卓微信打开酒类介绍页商品区**空白**（筛选高亮正常），
07:24 实时复现。但全新环境双 UA 实测 13 卡全部正常——修复代码早已上线，
坏版被"钉死"在用户手机里，强刷前永不更新。

## 二、根因

双层叠加：
1. products.html 的三个 js **裸引用无版本号** + nginx 对 /js/ 目录设置
   **30 天 immutable** 缓存——坏版 T1.1 的 products-live.js 被用户手机
   长期缓存（T1.1 坏版 get() 在 mock 态返回**空数组**，truthy 短路吞掉
   data.js 静态兜底，live 拉取超时/失败页面即永远空白）；
2. ad5c95b0 已修好 get() 返 null，**但未升 v=**——新旧 URL 相同，
   immutable 缓存永不回源，修复无法触达存量缓存。

## 三、错误代码/配置

修复前的引用形态（八页 19 处）：

```html
<script src="js/products-live.js"></script>   <!-- 裸引用, 无 ?v= -->
```

nginx（此为设计内缓存策略，问题在引用侧未配合）：

```nginx
location /js/ { expires 30d; add_header Cache-Control "immutable"; }
```

## 四、正确写法

cart/checkout/module-test/news-detail/news/product-detail/products/service
**八页 19 处**裸引用统一升 v=（提交 3740469e）：

```html
<script src="js/products-live.js?v=20261021"></script>
```

入口链接换代（?ver=2 新 URL）强制回源。此后固化为**B1 铁律：改 js 必升 v=**
（zhudun 预检 B1 项自动告警）。

## 五、预防规则

改任何 js 必须同步升引用处 v=（B1 已入竹盾检查清单）；js 引用一律禁止
裸引用——挂 B1（已有），M0 抽检口径含本案例复述。
