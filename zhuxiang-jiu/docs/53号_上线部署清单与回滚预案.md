## 一、部署架构与范围

### 1.1 部署物清单

| 类型 | 文件 | 说明 |
|------|------|------|
| 服务 | `backend/services/login53_scripts.py` | 话术注册表（17 场景+TTS 四态+黑名单自检） |
| 服务 | `backend/services/login53_registry.py` | 五通道矩阵+四态+六指标注册表（导入即自检） |
| 服务 | `backend/services/login53_service.py` | 编排引擎（~2000 行——态势感知/编排/语音/门户/驻留/指标） |

| 测试 | `test_login53_p0~p5.py` / `verify_login53_p5_live.py` | 专项 220 断言+实机验收脚本 |

### 1.2 依赖关系（全部只读复用，零侵入）

```
53号编排层 ──只读──→ 39号 entry: bio 凭证查询/qr 票据校验/IP 信誉表
            ──只读──→ 43号风控: AuthRiskScorer 8 因子评分
            ──只读──→ 48号语音: detect_wake/open_session/绑定桥/积分余额
            ──调用──→ 49号预算: check_and_spend(通道成本>0 时扣减)
            ──只读──→ 50号声纹: verify/liveness(proxy 标注不作凭证)
            ──调用──→ auth_service: _login_by_member_id(令牌签发)
```

**零侵入铁律**（六期专项宪法断言验证）：39号 24 路由/43号风控/48号唤醒词表/49号 17 工具/50号 14 行为+声纹 proxy 默认态——**全部零改动**。

### 1.3 数据足迹（Redis 键空间，前缀隔离）

| 键 | 用途 |
|----|------|
| `zhuxiang:login53:login53_profiles:{memberId}` | 入口档案（四态+基线+pendingConfirm） |
| `zhuxiang:login53:login53_events:{eventId}` + `events_all` 列 | 登录事件流水（六字段审计） |
| `zhuxiang:login53:login53_retention:{memberId}\|{dayKey}` | 驻留台账（幂等键） |
| `zhuxiang:login53:login53_snapshots:{snapId}` + `snapshots_all` 列 | 指标快照 |
| `zhuxiang:login53:events:seq` / `snapshots:seq` | 自增序列 |

> 键空间与 39-52号完全隔离；写入 50号事件台账（retention claim 时）带 `source=login53_retention` 留痕。

> 53号为纯编排层：开启后会员走 53号多模态编排，off 时直通存量 39号登录。**开/关均可秒级切换，数据全保留。**

**前置检查单**：
- [ ] 冒烟八项全过（§四）
- [ ] 39号 bio 凭证 enroll 流程实测可用（passkey/fingerprint 通道数据源）
- [ ] 43号风控误判率复核（enhanced 档依赖 riskFlagged 标记——误标会导致多因子强制）
- [ ] 运营侧知会：语音口令话术（"小竹，我回来了"三短语）与高危去污名化话术已人工复核
- [ ] 预算口径确认：face 0.05/voice 0.03/fingerprint 0.02 单位每次（49号日预算 1.0 内可支撑 ~20 次高成本通道）

**开启操作**：
```powershell
# .env 追加 LOGIN53_MODE=on 后:
docker compose -p zhuxiang-jiu up -d backend   # 容器重建
# 验证: docker exec zhuxiang-jiu-backend-1 printenv LOGIN53_MODE → on
#       POST /api/login53/prelogin/sense (X-Member-Id) → 200 含 authLevel/intent/budget
```

**开启后 24h 观察项**：

**红线**（代码内置，无需配置）：声纹 proxy 不作凭证（双因子）；预算耗尽不签发（409+降级话术）；令牌一次性（重放拒绝）；退出挽留非拦截（intercepted=False）；高危去污名化（禁红色警告）。

## 六、回滚预案（三级回退体系）

### 6.1 回退决策矩阵

| 症状 | 级别 | 动作 |
|------|------|------|
| 编排登录异常（某通道全失败/响应慢） | **L1 开关** | 关 LOGIN53_MODE → 直通 39号存量登录 |
| 43号风控误标致 enhanced 频发 | 不回退 | 人工复核 43号标记（decide_appeal 申诉通道） |
| 50号台账写入 fail-soft 告警 | 不回退 | 奖励领取不受阻断——查日志 `login53_retention_ledger_failed` |
| 进程级故障（import 崩溃/启动失败） | **L2 版本** | 回退到 `7a1ff40` 重建 |
| 驻留积分误发（资损疑点） | **L2+L3** | 关开关+定向清理 retention 台账（§6.4） |

### 6.2 L1 开关级回退（秒级，最常用）

```powershell
# .env 中 LOGIN53_MODE=off（或删除该行）后:
docker compose -p zhuxiang-jiu up -d backend
# 验证: printenv LOGIN53_MODE → off
#       POST /api/login53/auth/orchestrate → 409（编排停）
#       POST /api/entry/login → 正常（存量登录不受影响）
```

**特性**：档案/事件/驻留数据全部保留；回退后可随时重新开启。

### 6.3 L2 版本级回退（分钟级）

```powershell
# 1. 回退到 53号前零代码态
git checkout 7a1ff40

# 2. 重建镜像与容器
docker compose -p zhuxiang-jiu build backend
docker compose -p zhuxiang-jiu up -d backend

# 3. 冒烟: health 200 + POST /api/entry/login 正常 + hub/panel 200
```

**安全性依据**：53号为纯增量模块（独立路由前缀 `/api/login53/*`，既有 55 路由文件零改动，main.py 仅 +2 行注册）——回退后：
- 前端浮层如已挂载会出现 API 404 → 前端同步下线引用（或保留——"无法连接"提示无害）
- **Redis login53 数据可保留**（前向兼容：4 表结构不变，重新上线直接续用）

**分期回退**（保留部分期功能）：回退到分期边界提交（只需 P0-P3 → `2fd15ea`；P0-P4 → `5f444bb`）。P4 驻留表/P5 快照表为独立键，旧代码不读不写，残留无害。

### 6.4 L3 数据级清理（定向，谨慎）

```powershell
# ① 登录事件流水（审计数据——常规不清；误发排查后可清）
docker exec zhuxiang-jiu-redis-1 redis-cli --scan --pattern "zhuxiang:login53:login53_events:*"

# ② 驻留台账（误发审计结论后执行——删除=会员 streak 重置）
docker exec zhuxiang-jiu-redis-1 redis-cli --scan --pattern "zhuxiang:login53:login53_retention:*"
#    50号侧联查: zhuxiang:voice50:voice50_events 中 source=login53_retention 的事件
#    (仅清 login53 来源; 勿动其他 voice50 事件)

# ③ 入口档案/快照（低风险可清——重建无损）
docker exec zhuxiang-jiu-redis-1 redis-cli --scan --pattern "zhuxiang:login53:login53_profiles:*"
docker exec zhuxiang-jiu-redis-1 redis-cli --scan --pattern "zhuxiang:login53:login53_snapshots:*"
```

**口径**：login53 键空间与 39-52号完全隔离（独立前缀），清理本模块数据**不触碰**其他模块；50号侧仅 `source=login53_retention` 的事件属于 53号。

### 6.5 不可回退项（无）

本模块无数据库迁移、无既有表结构变更、无不可逆写入——**全部操作可完整回退到 53号前零代码态（`7a1ff40`）**。

## 七、应急处理速查

| 现象 | 判断 | 动作 |
|------|------|------|
| 容器反复重启 | 启动期 import 崩溃（login53 模块自检失败会 RuntimeError） | L2 版本回退（`7a1ff40`） |
| 编排面全 409 | LOGIN53_MODE=off | 属预期（默认零影响）；需编排时按 §五 开启 |
| voice 通道持续 dual_factor_required | 用户未说语义口令 | 属预期（声纹 proxy 不作凭证铁律）；检查前端口令提示文案 |
| 预算不足 409 集中出现 | 49号日预算耗尽（高成本通道高频使用） | 属预期降级；引导零成本通道（passkey/qr）或调整偏好 |
| enhanced 档频发投诉 | 43号 riskFlagged 误标 | 43号申诉通道（decide_appeal）+ 人工复核标记 |
| 指标计算全 fail | 事件流水空态或基线口径 | on 态跑 `POST /metrics/compute`；空态满分口径见运维手册 §4.1 |
| 会员反馈"登录变慢" | step_up/one_tap 档位触发（新设备/夜间/失败计数） | 属风控预期；核对 43号评分 factors（explainRef 可查） |
| Redis 内存告警 | login53 键膨胀 | events/snapshots 可安全清理（保留 profiles/retention 保连续性） |
