小竹网站精灵智能模型 大模型设计文档
一、产品概述与定位
1.1 产品定位
小竹网站精灵是一款基于大模型驱动的语音交互智能体，面向网站、小程序、APP等多端场景，支持语音唤醒、语音指令操控、语音咨询、语音购物、语音支付等全链路功能体验，实现"说一句话，完成所有操作"的便捷愉悦交互体验。 1,2
1.2 核心价值
* 用户侧：解放双手，降低操作门槛，实现自然语言直达服务，提升购物与咨询效率
* 商家侧：缩短转化链路，提升用户体验，降低客服人力成本，解锁AI时代流量新入口
* 平台侧：构建AI智能体生态，打通语音交互与真实交易闭环
1.3 适用场景
* 网站端：语音导航、语音搜索、语音下单、语音客服
* 小程序端：语音唤醒小程序、语音点单、语音支付
* APP端：语音操控全功能、语音导购、语音售后
1.4 阶段建设目标
* 第一阶段：实现基础语音唤醒与指令识别，覆盖网站核心功能
* 第二阶段：打通小程序与APP端，实现语音购物与支付闭环
* 第三阶段：融合多模态能力，实现情感化交互与个性化推荐

* 便捷性：语音唤醒即达，无需手动搜索与跳转
* 准确性：意图识别准确率≥98%，响应延迟≤1.5秒

三、系统功能需求
3.1 端侧交互功能
3.1.1 语音采集与唤醒
* 唤醒词配置：支持自定义唤醒词（如"小竹小竹"），支持多唤醒词并行
* 灵敏度调节：用户可调节唤醒灵敏度，适配不同环境噪音
* 误唤醒率指标：误唤醒率≤5%/天，噪音环境下唤醒成功率≥85%
* 唤醒方式：主动唤醒（说出唤醒词）+ 被动唤醒（点击语音按钮）
3.1.2 语音实时识别
* 多语言支持：普通话、英语、日语、韩语
* 多方言支持：东北话、四川话、粤语、上海话等10+种主要方言
* 识别准确率：普通话清晰指令识别准确率≥98%
* 实时字幕展示：语音转文字实时显示，支持编辑修正
* 流式识别：支持边说边识别，降低等待延迟
3.1.3 语音合成输出
* 音色选择：提供多种音色（温柔女声、沉稳男声、活泼童声等）
* 语速音调调节：用户可自定义语速（0.5x-2.0x）和音调
* 自然度指标：MOS评分≥4.0（5分制）
* 情感化合成：根据对话场景自动调整语气（咨询场景亲切、支付场景严谨）
3.1.4 多轮对话交互
* 上下文记忆：支持10轮以上上下文保持
* 智能打断：用户可随时打断语音播报，系统即时响应新指令
* 意图纠错：识别有误时主动追问确认（"您说的是XX对吗？"）
* 话题平滑过渡：话题跳转时通过确认性提问实现自然过渡
3.1.5 异常场景适配
* 音量检测：音量过低时提示"请大声一点"
* 静音检测：持续5秒无语音输入时提示"请问有什么可以帮你？"
* 离线模式：基础导航指令支持离线识别，降低延迟
3.2 云端核心引擎
3.2.1 自动语音识别引擎（ASR）
* 流式识别与批量转写双模式
* 专业词库导入（商品名、品牌名、行业术语）
* 口音自适应学习
3.2.2 自然语言处理引擎（NLP）
* 意图分类：购物意图、咨询意图、导航意图、支付意图等
* 实体抽取：商品名、价格、颜色、尺码、地址等关键信息提取
* 情感识别：内置26种情绪识别，定制个性化应答策略
* 模糊匹配：支持自然语言描述需求（如"帮我点两杯冰美式，一杯加燕麦奶"）
3.2.3 语音合成引擎（TTS）
* 端侧缓存常用话术，降低云端依赖
* 降噪处理，提升嘈杂环境下的播报清晰度
* 多语种混合合成（中英文混读）
3.2.4 声纹认证引擎
* 活体声纹识别，准确率≥99.5%
* 用于支付环节身份核验
* 支持声纹注册与比对
3.3 后台管理功能
3.3.1 用户管理
* 用户列表、管控、筛选、导出
* 用户画像标签体系（200+维度）
* 声纹数据管理
3.3.2 知识库管理

3.3.3 对话数据管理

* 异常统计与筛选导出
* 用户行为分析与A/B测试
3.3.4 内容风控管理
* 违规词库配置与实时更新
* 拦截策略与违规记录查询
* 人工复核流程
3.3.5 权限管理
* 角色配置（超级管理员、运营人员、客服人员）
* 权限分配与子账号管理
* 操作日志审计
3.3.6 数据统计看板
* 用户数据（日活、留存、新增）
* 对话数据（唤醒次数、识别准确率、意图分布）
* 内容数据（热门商品、热门咨询）
* 风控数据（拦截次数、违规类型分布）
3.4 前端用户功能
3.4.1 基础对话
* 文本/语音双模输入
* 多轮上下文记忆
* 流式输出
* 对话清空重置
* 重试反馈
* 点赞点踩评价
3.4.2 智能购物

* 语音筛选（价格、颜色、尺码等）
* 语音查看详情
* 语音加入购物车

* 语音查询物流
3.4.3 智能咨询
* 商品咨询（参数、库存、优惠）
* 售后咨询（退换货、维修）
* 品牌咨询（品牌故事、产品理念）
* 个性化推荐
3.4.4 语音支付
* 语音唤起支付
* 声纹身份核验
* 动态语音指令验证
* 支付结果语音播报
* 免密支付设置（需提前授权）
3.4.5 对话记录管理
* 会话保存、命名、搜索、删除、导出
* 历史记录回溯（"我刚才做了什么？"）

四、交互设计需求
4.1 页面交互规范
* 界面风格：简洁清爽，符合菲茨定律，高频功能触达效率高
* 消息样式：用户消息与系统消息视觉区分明显
* 加载状态：语音识别中显示动态波纹动画
* 空状态处理：无对话时显示引导话术与示例指令
* 操作反馈：微交互设计增强用户操作确认感
4.2 核心交互流程
4.2.1 唤醒→识别→执行→反馈链路
用户说出唤醒词 → 系统响应"我在" → 用户说出指令 → 
ASR转文字 → NLP意图识别 → 执行对应功能 → 
TTS语音反馈 + 视觉反馈 → 等待下一轮指令
4.2.2 语音购物流程
用户："小竹小竹" → 系统："我在" → 
用户："帮我找一款红色的运动鞋，500块以内" → 
系统展示商品列表 → 
用户："第三个详情" → 系统播报商品详情 → 
用户："加入购物车" → 系统确认 → 
用户："去结算" → 系统引导填写地址 → 
用户："用默认地址" → 系统唤起支付 → 
用户声纹验证 → 系统播报"支付成功"
4.2.3 语音咨询流程
用户："小竹小竹" → 系统："我在" → 
用户："这款酒多少度？" → 
系统查询知识库 → 系统："这款竹奕酒是52度竹香酒" → 
用户："有优惠吗？" → 系统："当前满减活动，满299减30" → 
用户："帮我下单两瓶" → 进入购物流程
4.3 多模态协同
* 视觉辅助：语音播报同时展示商品卡片、订单信息
* 触觉反馈：操作确认时震动反馈
* 音效反馈：成功提示音、错误蜂鸣声
4.4 无障碍设计
* 为视障用户提供全语音操作闭环
* 支持屏幕阅读器兼容
* ARIA标签增强动态内容播报
* 全键盘操作兼容

一、设计背景与目标
1.1 行业现状与痛点
当前企业级语音识别（ASR）部署面临三大核心挑战：
"	成本高昂：传统GPU依赖方案硬件采购与运维成本高，云端API按调用量计费在大规模并发场景下费用不可控 1, 5
"	国产化适配难：金融、政务等行业对信创环境有刚性要求，但多数ASR方案仅支持x86架构 1, 3
"	交互体验生硬：半双工模式导致"用户说、机器听；机器说、用户等"的轮次式对话，误打断率高，自然度差 1, 7

借鉴阿里云通义百聆Fun-ASR与科大讯飞VoiceWise的技术路径，为小竹网站精灵设计一套低成本、高性能、国产化适配、自然交互的ASR智能模型方案，核心目标如下：
目标维度	具体指标
成本优化	综合成本较传统GPU方案降低≥48%，较NPU方案降低≥56% 1, 5
性能提升	在线短语音识别并发路数提升≥90%，离线识别吞吐量提升≥150% 1, 5
国产化适配	兼容鲲鹏ARM架构、麒麟Linux系统
交互体验	误打断率下降≥50%，端到端响应延迟≤1.5秒 1, 3
识别精度	普通话清晰指令识别准确率≥98%，方言识别准确率≥90% 11

小竹网站精灵智能模型 -- 支付安全模块设计文档
文档版本：V1.0 编写日期：2026年9月19日
一、设计背景与目标
1.1 模块定位与职责
在小竹网站精灵智能模型的整体架构中，支付安全模块是保障语音交互全链路商业闭环的核心基础设施。根据《产品总体设计文档》中定义的语音交互全链路架构，本模块位于对话管理层与底层支付网关之间，承担着"安全守门人"的关键职责。其核心职责边界涵盖：支付意图的二次确认、用户身份的动态核验、交易行为的实时风控拦截、支付数据的加密传输以及全链路的合规审计。
在模块协作层面，支付安全模块与《声纹认证模块设计文档》中定义的声纹认证模块保持深度协同。为避免重复建设并贯彻"低成本"设计理念，支付安全模块不独立构建声纹采集与比对链路，而是通过内部RPC接口直接复用声纹认证模块的"声纹比对+频谱分析+语音预训练大模型+声学活体检测"四重防御能力。支付安全模块仅负责将声纹认证结果作为核心鉴权因子，结合交易上下文进行综合决策，从而实现安全能力的解耦与资源的高效利用。
1.2 行业现状与痛点
当前，随着语音交互在金融支付领域的渗透，安全威胁呈现出智能化、隐蔽化的趋势。结合行业实践，当前语音支付安全主要面临以下五大核心痛点：
1. 语音劫持与中间人攻击：攻击者利用恶意软件或网络漏洞，在ASR（语音识别）转写后、NLP（自然语言处理）意图解析前，篡改支付指令或替换收款账户信息，导致交易被导向欺诈方。
2. 声纹伪造与深度合成（Deepfake）：随着生成式AI的发展，攻击者可通过少量样本合成高逼真度的目标用户语音，绕过传统的单一声纹比对机制，实施身份冒充。
3. 重放攻击（Replay Attack）：攻击者录制用户的合法支付语音指令，在特定时间窗口内重复播放，试图欺骗系统执行重复扣款或越权交易。
4. 环境噪音与意图误识别：在嘈杂的公共场景下，ASR模型可能将背景噪音误识别为支付确认词（如"支付"、"确认"），或在用户无意识状态下触发支付，导致非授权交易。
5. 合规与审计追溯困难：语音支付具有"过耳即逝"的特性，传统的文本日志难以完整还原语音交互的上下文、用户情绪及环境特征，一旦发生纠纷，难以满足《个人信息保护法》及金融监管的审计要求。
1.3 设计目标
为确保支付安全模块既能抵御高级威胁，又能严格控制运营成本，设定以下量化设计目标：

2.1 总体架构策略：纵深防御+零信任架构
支付安全模块采用"纵深防御（Defense in Depth）"与"零信任（Zero Trust）"相结合的架构策略。
纵深防御体现在构建从端到云、从网络到应用的多层防护体系。在端侧，依托ASR智能模型与TTS智能模型的端云协同架构，实现敏感语音数据的本地预处理与脱敏；在传输层，采用双向TLS加密与动态令牌化技术；在应用层，通过支付身份认证、动态验证、交易风控、防欺诈检测四道关卡层层过滤风险；在数据层，实施严格的字段级加密与隔离存储。
零信任架构则贯彻"永不信任，始终验证"的原则。系统内部各微服务之间的调用均需经过mTLS认证与动态授权，摒弃基于网络边界的隐式信任。即使是来自内网ASR模块的支付意图，也必须经过支付安全模块的独立鉴权与风控校验后方可放行。所有访问请求均被视为潜在威胁，必须通过上下文感知（Context-Aware）的动态评估。

综合考虑"低成本"与"高安全"的双重约束，最终选型为"规则引擎 + 轻量级机器学习 + 大模型兜底"的混合分层方案。
1. L1 规则层（毫秒级）：处理已知的高频、确定性风险（如黑名单、频次限制、金额阈值）。此层消耗极低，可拦截 60% 以上的常规风险。
2. L2 机器学习层（十毫秒级）：采用借鉴《双师训练模型设计文档》中的知识蒸馏框架，将大模型的风控推理能力蒸馏至轻量级XGBoost/LightGBM模型中。此层负责识别复杂行为模式与异常交易，成本仅为大模型的 5%。
3. L3 大模型兜底层（百毫秒级）：仅对L1、L2无法决策的"灰度疑难case"或高价值大额交易触发大模型推理。结合NLP意图识别模块的上下文，进行深度语义分析与欺诈意图研判。
该方案既保证了绝大多数交易的低延迟、低成本处理，又保留了大模型应对高级未知威胁的能力，完美契合项目的成本控制指标。

一、设计背景与目标
1.1 模块定位与职责
在小竹网站精灵智能体的整体架构中，推荐引擎模块是连接用户意图与商品/内容供给的核心枢纽。本模块不仅承担着传统推荐系统的个性化匹配职责，更深度融入了语音交互全链路。其核心职责边界包括：实时解析用户语音交互中的显性指令与隐性偏好，结合用户画像与物品画像进行精准匹配，并将推荐结果转化为适合语音播报的文本格式，无缝衔接至TTS（文本转语音）模块。
在协作关系上，推荐引擎向上承接NLP意图识别模块的语义解析结果与对话管理模块的上下文状态，向下为TTS模块提供结构化的播报文案，同时与后台管理系统进行数据同步，并复用双师训练模型的知识蒸馏框架以实现端云协同的低成本推理。
1.2 行业现状与痛点
当前智能语音场景下的推荐系统普遍面临以下五大痛点：
4. 云端推理成本高昂：纯云端深度学习推荐模型在应对高并发语音请求时，GPU算力消耗巨大，单次推荐成本难以降至商业化可接受范围。
5. 语音交互延迟敏感：传统推荐系统响应时间在200ms以上，叠加ASR与TTS耗时，极易导致语音交互体验卡顿，用户等待耐心流失。
6. 语音场景冷启动困难：新用户缺乏历史点击与购买数据，且语音交互无法像图文界面那样通过视觉引导用户完成冷启动偏好收集。
7. 多模态语义对齐缺失：现有推荐算法多基于文本与行为数据，难以理解语音指令中的情绪、语气及口语化表达，导致推荐结果与用户真实意图错位。
8. 对话流推荐生硬：推荐结果多以列表形式呈现，在语音播报时信息密度过大，缺乏与当前对话上下文的自然融合，用户体验割裂。

2.1 总体架构策略：端云协同+混合推荐架构
本模块采用三层混合推荐架构，核心借鉴双师训练模型的知识蒸馏思路：
* 端侧轻量推荐层：部署经知识蒸馏压缩的轻量级推荐模型（学生模型），参数量控制在50M以内，负责处理高频、低延迟的实时推荐与热门内容召回，完全在设备本地完成推理，零云端成本。
* 云端深度推荐层：部署大参数量的教师模型（基于大语言模型+深度推荐网络），负责处理复杂意图理解、长尾商品推荐、跨域推荐及用户画像的深度更新，按需调用。
* 混合策略路由层：基于请求特征（用户活跃度、意图复杂度、网络状态、设备算力）动态决策推荐请求的路由目标，实现成本与效果的最优平衡。

最终采用"端侧蒸馏模型 + 云端双塔深度模型 + 大模型教师蒸馏"的混合方案。
选型理由： 1. 成本最优：80%以上的日常推荐请求由端侧学生模型处理，云端仅处理20%的复杂请求，综合成本降低65%以上。 2. 延迟达标：端侧推理50ms内完成，满足语音交互实时性要求。 3. 语义对齐：通过大模型教师生成高质量推荐标签与对话式推荐文案，蒸馏至学生模型，使端侧模型具备语义理解能力。 4. 冷启动友好：内容推荐通道与大模型标签体系结合，有效缓解新用户与新商品冷启动问题。
三、核心模块设计
3.1 用户画像引擎
模块功能：构建多维用户画像，包括基础属性、实时行为序列、语音偏好特征、消费能力分层，支持画像的实时更新与端云同步。
技术实现：采用Lambda架构，批处理层每日全量更新离线画像，实时流处理层基于Flink消费用户行为日志与ASR/NLP解析结果，实时更新短期兴趣向量。语音偏好特征通过声纹认证模块与NLP情绪识别结果联合建模，提取用户语速、音调、常用口语化表达等特征。画像数据以KV存储（Redis）+ 向量数据库（Milvus）双写，端侧通过增量同步协议获取画像更新。
性能指标： | 指标 | 目标值 | 说明 | | - | - | - | | 画像更新延迟 | ≤3s | 实时行为到画像更新的端到端延迟 | | 画像查询P99延迟 | ≤10ms | 端侧缓存命中时≤1ms | | 画像覆盖率 | ≥95% | 活跃用户画像完整度 | | 端云同步延迟 | ≤5s | 增量画像同步至端侧的延迟 |
3.2 物品画像引擎
模块功能：构建商品/内容的多维语义画像，包括基础属性、类目体系、标签体系、语音播报友好型描述、关联关系图谱。
技术实现：基于大模型教师模型对全量商品进行离线标签生成与语义向量化，生成包含"适合语音推荐"、"口语化卖点"、"适用人群"等语音场景专属标签。物品画像存储于Elasticsearch + 向量数据库，支持多路召回。通过后台管理系统提供人工审核与标签修正能力，确保大模型生成标签的准确性。
性能指标： | 指标 | 目标值 | 说明 | | - | - | - | | 商品标签生成覆盖率 | 100% | 全量商品均有大模型生成标签 | | 向量检索P99延迟 | ≤20ms | 百万级商品库向量召回延迟 | | 标签准确率 | ≥90% | 人工抽检标签准确率 | | 画像更新频率 | T+1 / 实时 | 基础属性T+1，价格库存实时 |
3.3 混合推荐算法引擎
模块功能：融合多路召回与排序策略，输出最终推荐列表，支持语音场景专属的重排与过滤逻辑。
技术实现：采用多路召回 + 精排 + 重排三阶段架构。召回层包括：端侧协同过滤召回、端侧内容召回、云端双塔向量召回、热门/运营召回。精排层采用端侧轻量GBDT模型与云端DeepFM模型混合，根据路由策略选择。重排层引入语音场景专属规则：过滤不适合语音播报的商品（如纯视觉依赖型）、打散同类目商品、插入对话上下文相关商品、控制推荐数量（语音场景单次推荐≤3个）。融合策略采用加权打分，端侧模型权重0.6，云端模型权重0.4，动态调整。

3.4 实时推荐引擎
模块功能：基于用户当前会话的实时行为与上下文，提供会话级个性化推荐，支持流式处理与即时反馈。
技术实现：采用Flink CEP（复杂事件处理）引擎，实时消费ASR/NLP解析结果、用户点击/加购/支付等行为事件，触发实时推荐计算。会话级推荐模型基于Transformer架构，输入为当前会话的行为序列与对话上下文，输出实时兴趣向量。实时推荐结果写入Redis，端侧通过WebSocket长连接获取更新。支持负反馈实时处理，用户语音打断或明确拒绝后，500ms内更新推荐列表。

3.5 冷启动策略模块
模块功能：解决新用户、新商品、新场景的推荐冷启动问题，快速积累偏好数据并提升推荐效果。
技术实现： - 新用户冷启动：通过声纹认证模块获取用户年龄/性别粗粒度特征，结合NLP意图识别中的显性需求（如"我想买适合跑步的耳机"），触发基于规则的热门+内容混合推荐。首次交互后，通过语音引导式偏好收集（"您平时更喜欢运动风还是休闲风？"）快速构建初始画像。 - 新商品冷启动：利用大模型教师生成的语义标签与向量，通过内容推荐通道直接匹配相似用户，无需等待行为数据积累。设置新商品流量扶持窗口（72小时），给予额外曝光权重。 - 新场景冷启动：基于跨场景迁移学习，将成熟场景的用户画像与推荐策略迁移至新场景，结合小流量A/B测试快速验证。
性能指标： | 指标 | 目标值 | 说明 | | - | - | - | | 新用户首推命中率 | ≥30% | 首次推荐产生有效点击 | | 新商品曝光达标时间 | ≤24h | 新商品获得基础曝光量 | | 冷启动用户画像构建时间 | ≤3次交互 | 3次交互后画像完整度≥60% | | 跨场景迁移准确率 | ≥70% | 迁移策略效果衰减≤30% |
3.6 语音推荐播报模块
模块功能：将推荐结果转化为自然、简洁、适合语音播报的文案，与TTS模块无缝对接，支持对话流中的自然插入。
技术实现：采用大模型教师模型离线生成推荐播报模板库，涵盖商品推荐、内容推荐、促销推荐等场景。在线推理时，根据推荐结果与对话上下文，从模板库中匹配最优模板并填充变量。文案生成遵循语音播报原则：单次推荐≤3个商品、每个商品描述≤15字、突出核心卖点、避免数字与特殊符号、支持追问引导。与对话管理模块协同，在对话锚点处自然插入推荐，避免生硬打断。播报文案同步写入TTS输入队列，支持流式输出。
性能指标： | 指标 | 目标值 | 说明 | | - | - | - | | 播报文案生成延迟 | ≤30ms | 模板匹配+变量填充 | | 文案语音适配率 | 100% | 无不适合播报的内容 | | 用户打断率 | ≤5% | 推荐播报被打断比例 | | 模板覆盖率 | ≥95% | 推荐场景均有对应模板 |

5.2 推荐路由策略
路由决策基于以下特征动态计算： - 用户价值分层：高价值用户（月消费≥500元）优先路由至云端深度推荐，普通用户优先端侧。 - 意图复杂度：NLP识别为复杂意图（多条件、跨类目、咨询型）路由至云端，简单意图（热门、明确品类）路由至端侧。 - 网络状态：弱网/离线状态强制端侧推荐，网络恢复后异步同步云端结果。 - 设备算力：低端设备（内存≤4GB）降级为规则推荐，中端设备运行学生模型，高端设备支持更大模型。 - 时段策略：大促高峰期自动提升端侧路由比例，保障系统稳定性。

一、设计背景与目标
1.1 行业现状与痛点
当前，智能交互系统在消息通知领域普遍面临以下痛点：
* 多通道通知碎片化：短信、邮件、Push、小程序模板消息等通道各自为政，缺乏统一调度，导致运维复杂度高。
* 送达率不稳定：受运营商策略、网络环境、用户设备状态等影响，单一通道送达率波动大，缺乏智能降级机制。
* 成本不可控：高成本通道（如国际短信）滥用，缺乏基于业务优先级的成本优化策略，导致运营成本居高不下。
* 用户骚扰问题：缺乏统一的用户偏好管理和频控机制，高频推送导致用户关闭通知权限，甚至产生投诉。

1.1 行业现状与痛点
小竹网站精灵作为端云协同的语音交互智能体，其微服务架构与高资源消耗特性（ASR/TTS/NLP/大模型推理）对系统可观测性提出了极高要求。当前行业在类似复杂架构中普遍面临以下痛点： - 日志分散难以统一采集：端侧（APP/小程序）、云端弹性层、私有化兜底层日志格式各异，缺乏统一标准，导致跨端故障排查困难。 - 实时监控滞后：传统日志分析依赖定时扫描，告警延迟高，无法应对语音交互对毫秒级响应的要求。 - 故障定位困难：语音交互链路长，涉及声纹认证、意图识别、大模型推理等多个环节，缺乏端到端链路追踪，瓶颈定位耗时。 - 存储成本高昂：全量日志存储导致存储费用随业务增长呈线性甚至指数级上升，缺乏有效的冷热分层机制。 - 合规审计要求：涉及语音支付、用户声纹等敏感数据，需满足严格的数据脱敏与操作审计合规要求。

* 日志分级采集：按业务重要性分级，核心链路全量采集，普通链路采样采集，调试日志仅开发环境开启。

* 索引优化：Loki仅索引标签，不索引日志内容，索引存储成本降低90%。
* 开源替代：Loki/Prometheus/Grafana/SkyWalking均为开源方案，无商业授权费用。
