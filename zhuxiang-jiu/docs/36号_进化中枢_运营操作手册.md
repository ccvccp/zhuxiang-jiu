## 一、进化中枢是什么(30 秒版)

一句话: **你持续回流效果数据, 系统自动学习; 关键决策(风险词)等你批准, 其余自动调但全留痕可审计。**

| 引擎 | 自动/人工 | 你要做的 |
|------|----------|---------|
| 引擎1 热点品类权重 | 自动回归(手动触发按钮) | 每周点一次「运行品类 ROI 回归」+ 看清单 |
| 引擎2 内容风格 A/B | 全自动 | 观察; 冠军产生后无需操作(tone 自动反哺) |
| 引擎3 承接页路由 | 全自动(生成时选臂) | 无需操作; 看三臂数据即可 |
| 引擎4 合规风险词 | **半自动(人工批准)** | 平台拒绝后录入反馈 → 批准/拒绝候选词 |
| 商品拓展 | 全自动(生成时匹配) | 无需操作; 可按热点查询匹配结果 |

**界面入口**: zxjiu.com → 我的(13800000002)→ 站点管理 → 「📈 智能推广」→ 第 6 页签「**进化中枢**」

## 二、日常 SOP-1: 数据回流(每天, 5 分钟)——一切进化的燃料

> 所有进化都依赖效果数据回流。**不回流 = 不进化**。

### 步骤

```powershell
$H = @{"X-Role"="admin"; "X-Member-Id"="2"}; $B = "https://zxjiu.com"

# 1. 批量回流全部已发布未回流内容(指标自动从 attract 归因聚合)
Invoke-RestMethod -Method Post -Headers $H "$B/api/promo/learning/collect"
# 判据: submitted ≥ 0, skipped = 已回流条数(幂等)

# 2. 回流后查看进化样本积累
Invoke-RestMethod -Headers $H "$B/api/promo/evolution/status" |
  Select-Object -ExpandProperty data |
  ConvertTo-Json -Depth 5
```

工作台等价操作: 「总览」页签数据即为回流后报表; 「进化中枢」页签品类卡的「N样本」即时增长。

### 判据与红线

- 每条内容**只会回流一次**(learningFed 幂等标记), 重复调用直接 409——这是正常保护
- 单条手动回流(带外部统计):
  `POST /api/promo/learning/feedback {"contentId":5, "clicks":320, "registrations":12, "orders":3}`
- 回流成功即自动喂给品类统计/风格统计/老虎机三路——**无需任何额外操作**

## 三、日常 SOP-2: 风险词裁决(有平台拒绝时, 10 分钟)——唯一必须人工的环节

### 何时触发
你在抖音/小红书/微博等平台发布的内容出现: 审核拒绝 / 限流 / 被删除。

### 步骤(工作台操作)

1. **录入审核反馈**(该内容在平台被拒时):
   ```powershell
   Invoke-RestMethod -Method Post -Headers $H -ContentType "application/json" `
     -Body '{"contentId":5, "outcome":"rejected", "note":"抖音提示违反社区规范"}' `
     "$B/api/promo/evolution/audit-feedback"
   ```
   - outcome 三选一: `rejected`(拒绝) / `limited`(限流) / `removed`(删除)
   - 判据: 返回 `newCandidates` 列表(系统提取的候选风险词, 2-4 字)

2. **裁决候选**(「进化中枢」页签 → 引擎4 卡片):
   - 每个候选显示: 词 + 拒绝文档数 + 拒绝率
   - 点「**批准**」→ 该词立即生效, 之后雷达扫描与内容生成的**双闸门都会拦截**含该词的热点/文案
   - 点「**拒绝**」→ 标记为误报, 不生效(留痕)

### 裁决判断口径

| 情况 | 动作 |
|------|------|
| 词确实是平台新敏感点(如"沉浸开竹"类新玩法被严打) | **批准** |
| 词只是该条内容偶然携带、平台实际不敏感 | **拒绝**(误报) |
| 拿不准 | 先不动(候选一直挂着, 永不自动生效) |

### 红线(必须知悉)

- **候选词永不自动阻断**——未批准前只观察, 系统绝不会因为你没处理就拦截内容
- 已批准的词想撤销? 当前版本无撤销端点, 需联系开发从 `promo_evo_risk_words` 表删除(下一步迭代可加)
- 强制警示语("过量饮酒有害健康"等)已内置白名单, 不会被提取为候选——放心

## 四、每周 SOP-3: 品类 ROI 回归(每周一次, 2 分钟)

> 引擎1 的心跳。基于一周积累的效果数据重新计算四类热点的实际转化权重。

### 步骤(工作台一键)

「进化中枢」页签 → 引擎1 卡片 → 点「**运行品类 ROI 回归**」按钮。

或 API:
```powershell
Invoke-RestMethod -Method Post -Headers $H "$B/api/promo/evolution/hotspot-weights/run"
# 返回: avgRoi(全站均值) + adjustments(各品类 旧权重→新权重/ROI)
```

### 结果解读

| 看到什么 | 含义 | 动作 |
|---------|------|------|
| `adjustments` 有 2-4 项 | 正常——高 ROI 品类权重升, 低 ROI 降 | 无需操作, 自动生效于高价值清单 |
| `adjustments` 为空 | 样本不足(某品类 <3 条内容) | 正常冷启动期表现, 继续回流 |
| scene 权重 0.48(基线 0.40) | "场景类热点比全站平均跑得好 20%" | 后续生成优先从「高价值清单」选热点 |
| 某品类权重到 0.60 后不动了 | 安全阀生效(基线 1.5× 封顶) | **这是设计行为**, 防止过度优化失控 |

### 高价值热点清单(跟着它选题)

```powershell
Invoke-RestMethod -Headers $H "$B/api/promo/evolution/hotspot-priority"
```
清单 = 品类权重 × 热点评分 排序。**运营选题时直接从这里取 top 热点**去内容工厂生成——这就是进化引擎1 的价值兑现。

## 五、每周 SOP-4: 观察三件事(3 分钟, 无操作)

### 1. 风格冠军(引擎2)
「进化中枢」→ 引擎2 卡片。某风格出现「**冠军**」徽章(样本≥3 且 CTR 最高)后:
- 之后每次生成, 冠军风格自动占首变体, 其余保持 A/B 探索——**全自动, 无需操作**
- SOP 文案可复制到团队知识库: `GET /api/promo/evolution/styles` → `data.sop.sop`

### 2. 老虎机三臂(引擎3)
- 「N次」= 各承接页累计分到的内容数; 「均值」= 该臂平均点击率
- 均值高的臂会自动分到更多内容(UCB1), 均值低的保持探索底线
- **无需任何操作**; 若发现某臂长期均值显著高但次数不涨, 属异常→查 §排障 T-04

### 3. 商品匹配(拓展)
按热点查询本波流量挂哪些商品:
```powershell
Invoke-RestMethod -Headers $H "$B/api/promo/evolution/products/match?hotspotId=16"
```
生成时已自动匹配 top3 并附入内容——这里仅供复盘"这波挂的商品对不对"。

## 六、每月 SOP-5: 进化审计(运营+法务联合, 15 分钟)

> 设计铁律: 进化日志全量留痕, 月度审查确保方向正确。

```powershell
# 全部进化日志(按引擎过滤)
Invoke-RestMethod -Headers $H "$B/api/promo/evolution/log?engine=hotspot_weights"
Invoke-RestMethod -Headers $H "$B/api/promo/evolution/log?engine=compliance"
```

### 审计清单

- [ ] **hotspot_weights 日志**: 本月权重调整是否都在安全阀内(基线 0.5×-1.5×)? 有无某品类被连续单边调整?
- [ ] **compliance 日志**: 批准的风险词逐条复核——是否误伤正常内容题材?(误伤 → 联系开发撤词)
- [ ] 品类权重 vs 品牌调性: 若"综合类"权重持续走高而"文化类"走低——非遗文化产品的调性是否被流量绑架?(运营侧判断, 系统只看 ROI)
- [ ] 风险词总量: activeExtraWords 是否膨胀过快?(正常节奏: 每月个位数)

## 七、四阶段运营节奏(何时期待什么)

| 阶段 | 周期 | 你要做的 | 正常表现 |
|------|------|---------|---------|
| **冷启动期** | 第 1 个月 | 每天 SOP-1 回流; 每周回归一次 | 样本数增长; adjustments 多为空; 无冠军 |
| **快速迭代期** | 第 2-3 月 | 同上 + 开始按高价值清单选题 | 冠军风格产生(tone 反哺生效); 品类权重分化 |
| **稳态优化期** | 第 4 月起 | 维持节奏 + 月度审计 | 老虎机倾斜稳定; 风险词库动态扩充 |
| **生态扩展期** | 按需 | 新平台资质就绪后接入 | 四引擎平台无关设计, 直接复用 |

**冷启动耐心值**: 品类需 3 条已回流内容才参回归; 风格需 3 个变体才有冠军资格。按当前发布节奏(日限 20), 全引擎进入正反馈约需 2-4 周数据积累。

## 九、排障(T-xx)

| 编号 | 现象 | 原因 | 处理 |
|------|------|------|------|
| T-01 | 「进化中枢」页签空白 | evo 接口异常 | 工作台会显示"数据加载失败"; SSH 查 `docker logs zhuxiang-backend-1 \| grep evo` |
| T-02 | collect 回流 submitted=0 | 全部已回流(幂等) | 正常; 新发布内容才会出现 |
| T-03 | audit-feedback 返回 newCandidates=[] | 该词拒绝文档数 <2 或通过内容也含该词 | 多录几条同类拒绝反馈; 或该词本就安全 |
| T-04 | 老虎机某臂次数不涨 | UCB1 均值劣势 | 正常(倾斜设计); 全零臂会保底探索 |
| T-05 | 回归后权重无变化 | 比值在 ±20% 步进内或触 clamp | 正常; 累计多轮才会体现 |
| T-06 | 品类权重显示与清单排序不符 | 清单用**进化后权重**, 基线表未进化品类回落基线 | 以清单为准 |
| T-07 | 生成内容仍含已批准风险词 | 该轮生成早于批准(每轮生成时加载一次) | 下一轮生成即拦截; 当轮内容人工审核时把关 |

## 十、FAQ

**Q1: 我不运行回归, 系统会自己进化吗?**
A: 品类权重不会(需手动触发, 保持人工节奏控制权); 风格冠军、老虎机、风险词观察是全自动的。

**Q2: 进化会让品牌调性跑偏吗?**
A: 双保险——安全阀(权重最多偏离基线 50%) + 月度审计(§SOP-5 专门检查调性漂移)。系统只优化 ROI, 调性判断永远在人。

**Q3: 批准错了风险词怎么办?**
A: 立即停止相关生成; 开发侧从 `promo_evo_risk_words` 表删除该词即回滚(下轮生成生效)。撤销端点在迭代计划中。

**Q4: 引擎4 和三审闸门什么关系?**
A: 三审是**既有闸门**(静态词库+AI 分+人工审), 引擎4 是**动态增量**——批准词只往闸门里"加料", 不改变三审任何逻辑。

**Q5: 多账号/多平台会互相影响吗?**
A: 品类权重与老虎机是全站共享口径; 风险词按平台反馈录入但当前全局生效(平台分维度统计在生态扩展期迭代)。
