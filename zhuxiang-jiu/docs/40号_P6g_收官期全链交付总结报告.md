**bool 反序列化陷阱修复**(实机层发现的真实生产缺陷):
- 症状:resume 返回 200 但 `autonomy_state` 仍 paused=True——治理开关
  在生产 Redis 下"恢复失灵", 全部受控写被空理由 pause 阻断
- 根因:`_serialize` 将 bool 存为 1/0 → Redis hgetall 读回字符串
  `"0"`/`"1"` → `bool("0")` 恒 True——`_deserialize` 无 bool 还原
- 修复:新增 `_deserialize_bools`(指定字段 "0"/"1" 显式还原),
  接入 `get_autonomy_state` Redis 分支
- **本地 687 断言与 P6g-2 红队均未覆盖**(内存模式无此差异)——
  Docker 实机作为最后防线的价值实证

## 四、两个真实缺陷与三层防线方法论(收官核心成果)

| 缺陷 | 发现层 | 为何此前未发现 |
|------|--------|--------------|
| RT-03 拆词绕风险词("疫?情"漏检 100 分) | 红队主动攻击 | 专项测试只测"正例命中", 未构造恶意变形 |
| bool 反序列化陷阱(resume 后 paused 恒 True) | Docker 实机 | 本地全量回归跑内存模式, Redis 序列化差异不可见;红队同跑内存 |

**方法论实证**:

```
被动断言(专项/回归 687) → 主动攻击(红队 24) → 环境差异(实机 30)
        ↓                       ↓                    ↓
   验证"功能正确"         逼出"绕过路径"        暴露"模式差异"
```

三层防线各抓各的, 缺一不可——**收官期不给引擎加任何新能力,
却交付了前十个阶段都无法交付的东西:对整个体系的信心**。
