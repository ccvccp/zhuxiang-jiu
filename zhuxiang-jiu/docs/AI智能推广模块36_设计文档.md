# 36号·AI智能推广模块 设计文档 v1.0

> 模块定位：全网热点智能侦探 → 蹭点决策 → 受众匹配 → GLM-5.3 Agent 内容工厂 → 三审合规 → 适时分发 → 效果回流的**全自动智能推广闭环**。
> 上游基座：attract(AI自动引流) 短链/归因体系、llm_client 统一接入、ai_knowledge RAG、ai_learning Hedge 学习。
> 状态：设计评审稿（P0/P1/P2 分期实施）。

---

## 1. 设计目标与边界

### 1.1 设计目标

| 目标 | 说明 |
|------|------|
| 全网热点侦探 | 适时扫描百度热搜、抖音热榜、微博、知乎、小红书等平台高流量重大事件，评分排序 |
| 智能蹭点 | 自动判定热点与品牌相关性、合规风险，决定跟进/观望/放弃，高风险强制人工确认 |
| 受众匹配 | 平台受众画像 × 产品调性 × 内容角度 三维匹配，为每个热点选对平台和话术 |
| Agent 内容生产 | 调用 GLM-5.3 智能体链（分析→匹配→生成→自查），按各平台规则产出差异化内容 |
| 权威导向 | 内容立意与事实引用以国家标准(GB)、行业协会公开数据等权威信源为准 |
| 适时分发 | 黄金时段调度、单日上限防刷屏、多平台一源多态分发 |
| 效果回流 | 复用 attract 短链归因体系，点击/注册/下单全链路可测，反哺热点评分权重自学习 |

### 1.2 与既有模块关系（对接不合并）

```
                    ┌────────────────────────────────────────────┐
                    │            36号·AI智能推广模块              │
                    │  热点雷达 → 决策器 → 受众匹配 → Agent工厂     │
                    │        → 三审合规 → 发布调度 → 效果回流      │
                    └───────┬──────────┬──────────┬──────────────┘
                            │          │          │
             短链/归因/ROI   │   合规词库 │   RAG信源 │  Hedge权重
                  attract ─┘  ad ───────┘  ai_knowledge ── ai_learning
                  promotion(码绑定)   message(人工审核待办)   hub(能力面板注册)
```

- **attract**：发布内容统一挂 attract 短链（utm_campaign=热点指纹），点击→注册→下单归因全复用，不重复建设
- **ad**：禁用词/警示语口径复用（BANNED_WORDS / REQUIRED_DISCLAIMER / REQUIRED_AGE_TIP）
- **ai_knowledge**：权威信源库 RAG top-k 检索复用
- **ai_learning**：P2 效果回流对接 Hedge 在线学习，调优热点评分权重
- **hub(35号)**：注册"智能推广"能力入面板与意图路由
- **message**：待人工审核/高风险热点预警推送运营

### 1.3 不做什么（边界）

- 不直接对接付费投放 API（ad 模块职责）
- 不做站内分销奖励（promotion/traffic 职责）
- P0/P1 阶段发布走**模拟轨**（生成完整发布包+短链，不真发），真实平台 API 对接放 P2（需平台资质）

## 2. 总体架构：六大子系统

```
 [热点雷达 Radar]      [蹭点决策器 Decision]     [受众匹配 Audience]
  多平台热榜轮询    →    相关性×热度×风险评分   →   平台画像×产品×角度匹配
        ↓                     ↓                        ↓
                   [GLM-5.3 Agent 内容工厂 Studio]
                    分析Agent→匹配Agent→生成Agent→自查Agent（三级降级）
                              ↓
                     [三审合规闸门 Gate]
                    规则审(硬)→AI审(80分线)→人工审(HITL)
                              ↓
                     [发布调度 Scheduler]
                    黄金时段窗口 + 单日上限 + 一源多态分发(attract短链)
                              ↓
                     [效果回流 Impact]
                    归因报表(复用attract) → Hedge权重调优(P2)
```

## 3. 子系统详细设计

### 3.1 热点雷达（promo_radar_service）

**热点源适配器**（Mock-first，同 P1-2/P1-3 模式）：

| 平台 | 环境变量 | 未配置时行为 |
|------|---------|-------------|
| 百度热搜 | `HOTSPOT_BAIDU_API_KEY` | 确定性模拟源（fingerprint 种子） |
| 抖音热榜 | `HOTSPOT_DOUYIN_API_KEY` | 同上 |
| 微博热搜 | `HOTSPOT_WEIBO_API_KEY` | 同上 |
| 知乎热榜 | `HOTSPOT_ZHIHU_API_KEY` | 同上 |
| 小红书热点 | `HOTSPOT_XHS_API_KEY` | 同上 |

模拟源规则：以 `date+slot` 为种子生成确定性热点（标题取自"节庆/宴席/国潮/送礼/酒文化"主题池 + 噪声），保证测试可复现、演示可用；配置真实 KEY 后自动切真实抓取。

**热点评分模型**：

```
score = 0.4*heat_norm(平台热度归一) + 0.2*velocity(上升速度)
      + 0.3*brand_relevance(品牌相关性) + 0.1*persistence(持续时长)
risk_gate: 政治敏感/未成年人饮酒/医疗功效暗示/重大灾害 → 一票否决(discarded)
brand_relevance: 关键词表(酒/宴/礼/婚/庆/节/国潮/文化/聚会)命中
               + embedding-3 与品牌语料余弦相似度（LLM不可用退化为纯关键词）
```

**去重与冷却**：
- `promo:hotspot:dedupe:{fingerprint}`（SHA256(平台+规范化标题)）TTL 48h 防重复入库
- `promo:cooldown:{fingerprint}`：同一热点 48h 内最多生成 N 条内容（默认 2）
- `promo:daily:cap:{yyyymmdd}`：单日全平台发布上限（默认 20），防刷屏触发平台风控

**调度**：`promo_radar_scheduler`，`PROMO_RADAR_AUTO=off` 默认关闭，间隔 15 分钟。

### 3.2 蹭点决策器（promo_service）

```
score ≥ 70 且 risk_gate 通过   → auto_engage(自动进入内容工厂)
50 ≤ score < 70                → manual_queue(人工确认队列, message 通知运营)
score < 50 或 risk_gate 否决    → pass(记录决策留痕, 不生产)
```

- 每条决策记录 `reason`（可解释性：分项得分 + 否决原因）
- 决策结果审计留痕，报表可回溯"为什么跟/为什么不跟"
- 人工队列支持运营一键 `decide(hotspot_id, engage|pass, note)`

### 3.3 受众匹配引擎

**平台受众画像**（初始数据，存 `promo:audience:profile:{platform}`，admin 可改）：

| 平台 | 画像 | 话术基调 | 格式约束 |
|------|------|---------|---------|
| 抖音 | 18-35 大众娱乐 | 快节奏、剧情钩子 | 15-45s 短视频脚本（分镜+口播+字幕） |
| 小红书 | 20-40 女性种草 | 真实体验、生活美学 | 标题≤20字 + 正文≤800字 + 5-8 标签 |
| 百家号/百度 | 全年龄搜索意图 | 客观科普、长尾问答 | ≥1200字 + FAQ 段 |
| 视频号 | 30+ 熟龄 | 信任、情怀 | 图文短句 + 封面文案 |
| 微博 | 话题借势 | 热点话题互动 | #话题# + ≤140字 |

**三维匹配**：`内容角度 × 平台画像 × 产品调性`（婚宴用酒→小红书婚嫁话题；商务礼盒→知乎/百度科普；口粮酒→抖音剧情）。
**站内画像回传**（P1）：取 member/ai_scoring 的站内高价值人群特征，校准平台画像权重。

### 3.4 GLM-5.3 Agent 内容工厂（promo_agent_service）

**Agent 四步链**（每步结构化 JSON 输出，失败即降级）：

```
Step1 热点分析Agent  : 热点(标题/摘要/热度) → {angle, brand_relevance, risk_flags, suggested_products}
Step2 受众匹配Agent  : 角度+平台 → {audience_profile, tone, taboo_words}
Step3 内容生成Agent  : 角度+受众+平台规则模板+权威信源引用池 → {title, body, hashtags, cover_hint, cta, publish_window_hint}
Step4 自查自纠Agent  : 草稿+合规红线清单 → {revised_content, self_check_report}
```

**模型档位与三级降级**：

```
LLM_MODEL_PROMO=glm-5.3 (Agent 专用档位, llm_client.chat 增加 model 参数, 默认值不变向后兼容)
  调用失败 → glm-4-flash 重试一次
  仍失败  → 规则模板轨(复用 attract GEN_TEMPLATES 思路, 保证产出不中断)
降级事件计入 metrics(promo_agent_fallback_total), 看板可见
```

**一源多态**：一次 generate 调用对同一热点生成 N 个平台版本（共享 Step1 分析结果，Step2-4 按平台并行），版本间记录 `content_group_id` 便于横向对比报表。

**权威导向实现（关键设计）**：

- **权威信源库**（`promo:authority:source:{id}`）：只收录**可公开引用**的条目——国标编号（如 GB/T 10781 白香型白酒）、行业协会公开统计数据、权威媒体公开报道链接；每条含"允许引用方式"字段
- **RAG 取材**：Step3 生成时从权威信源库 top-k 检索相关条目，Agent 只能从引用池取材，**禁止编造数据**（Step4 自查含"数字溯源校验"：正文出现的数字/标准编号必须能在引用池或产品库中找到出处）
- **广告法 §9 红线**：不得使用或变相使用国家机关、国家机关工作人员的名义形象作推荐证明；权威引用仅限客观事实陈述（"符合 GB/T 10781 固态法白酒标准"✓ / "XX部门推荐"✗）

### 3.5 三审合规闸门（Gate）

```
一审 规则审(硬, 不过即拒):
  - 广告法极限词(复用 ad BANNED_WORDS)
  - 酒类专项: 不得诱导怂恿无节制饮酒 / 不得出现饮酒动作 / 不得暗示消除紧张焦虑增加体力等功效
  - 强制项: "过量饮酒有害健康"警示语 + 未成年人禁止饮酒提示 + "广告"可识别标识
  - 权威背书红线(§9)
二审 AI审: 合规评分器(复用 ad AI审核思路, 通过线 80 分)
三审 人工审(HITL): 高风险热点 / 新平台首发 / AI审 60-80 分区间 → 强制人工, message 通知运营
```

状态机：`pending → approved | rejected`，拒绝必填 reason，全量审计留痕。

### 3.6 发布调度与效果回流

**发布调度**：
- `promo:publish:queue` ZSet（score=scheduled_at），`promo_publish_scheduler`（`PROMO_PUBLISH_AUTO=off`）每 5 分钟检查黄金时段窗口
- 黄金时段按平台配置（如抖音 12:00-13:00 / 18:00-22:00），Agent Step3 亦给出 `publish_window_hint` 双重确认
- 发布动作（模拟轨）：组装发布包{平台、内容、attract短链(utm_source=平台, utm_campaign=热点指纹), 定时时间} → 状态 `published` + 记录发布回执（模拟回执含 exposure 预估值）
- 真实轨（P2，`PROMO_CHANNEL_MODE=real`）：抖音开放平台/小红书专业号/百家号 API 适配器，需资质就绪后配置 `PROMO_CHANNEL_{PLATFORM}_KEY`

**效果回流**：
- 发布内容统一挂 attract 短链 → 点击/注册/下单归因**全复用 attract 既有链路**，本模块只做 `content_id ↔ attract shortcode` 映射
- 报表：全景 overview（热点数/内容数/发布数/点击/注册/下单/ROI）、平台维度、内容组维度（一源多态横向对比哪个平台版本跑得动）
- P2 对接 ai_learning Hedge：以"单条内容引流量"为反馈信号，在线调优热点评分中 brand_relevance/velocity 权重

## 4. 数据模型（Redis Key 规划）

| Key | 类型 | 说明 |
|-----|------|------|
| `promo:hotspot:{id}` | Hash | 热点事件（platform/title/summary/heat/score/status） |
| `promo:hotspot:active` | ZSet | 活跃热点池（score=评分） |
| `promo:hotspot:dedupe:{fingerprint}` | String | 去重 TTL 48h |
| `promo:cooldown:{fingerprint}` | String | 同热点内容条数冷却 |
| `promo:daily:cap:{yyyymmdd}` | Counter | 单日发布上限计数 |
| `promo:decision:{id}` | Hash | 决策记录（含 reason 审计） |
| `promo:decision:pending` | ZSet | 人工确认队列 |
| `promo:audience:profile:{platform}` | Hash | 平台受众画像（admin 可改） |
| `promo:rule:platform:{platform}` | Hash | 平台规则模板（字数/格式/黄金时段） |
| `promo:authority:source:{id}` | Hash | 权威信源（含允许引用方式） |
| `promo:content:{id}` | Hash | 内容（含 content_group_id/agent_trace 降级轨迹） |
| `promo:publish:queue` | ZSet | 发布队列（score=scheduled_at） |
| `promo:content:link:{content_id}` | String | → attract shortcode 映射 |
| `lock:promo:scan` / `lock:promo:publish` / `lock:promo:generate:{hotspot_id}` | Lock | 分布式锁（遵循 `lock:{key}` 约定） |

## 7. 合规与安全红线（酒类推广专项）

1. **广告法 §23 酒类广告**：不得诱导怂恿饮酒或宣传无节制饮酒；不得出现饮酒动作；不得表现驾驶等活动；不得明示暗示饮酒有消除紧张焦虑、增加体力等功效
2. **强制警示**："过量饮酒有害健康" + 未成年人禁止饮酒提示 + 互联网广告"广告"可识别标识（《互联网广告管理办法》）
3. **权威背书红线（§9）**：不得使用国家机关及其工作人员名义形象作推荐；权威引用仅限国标条文/公开数据的客观事实陈述，且必须溯源可查
4. **未成年人保护**：age_gate 已有体系不放松；热点若涉及未成年人话题直接 risk_gate 否决
5. **热点风险一票否决**：政治敏感/重大灾害/医疗健康暗示类热点永不跟进
6. **平台风控保护**：单日上限+冷却期+发布限流，防止账号被判定营销号
7. **审计留痕**：决策、审核、发布全链路可回溯，模拟轨与真实轨发布均留回执

## 10. 风险与对策

| 风险 | 对策 |
|------|------|
| 平台 API 资质/配额限制 | Mock-first 模拟轨先行，真实轨后置 P2，发布包格式与真实轨一致 |
| LLM 生成内容合规风险 | 三审闸门 + 权威引用池白名单 + 数字溯源校验 + 高风险强制人工 |
| 蹭热点翻车（品牌形象） | 风险一票否决 + 人工确认队列（50-70 分区间）+ 决策留痕可回溯 |
| 账号被平台判定营销号 | 单日上限 + 冷却期 + 黄金时段限流 + 一源多态差异化内容 |
| GLM-5.3 不可用/超时 | 三级降级链（glm-5.3→glm-4-flash→规则轨），metrics 可观测降级率 |
| 未成年人/酒类法规风险 | age_gate 不放松 + §23 硬规则一审即拒 + 未成年人话题热点直接否决 |
