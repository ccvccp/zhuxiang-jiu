## 二、生产缺陷修复明细（9 处，均已部署重建容器）

### P1 级（功能不可用）
1. **traffic seq 通配扫描**: `promoter:*` 命中 `promoter:seq` 计数器（json 解析 int 后 `.get` 崩溃）——生产此前零推广员未触发，E2E 首建即激活；4 端点（list/fission/distribute/admin-stats）500
2. **ad slots 路由遮蔽**: `GET /api/ads/slots` 注册在 `/{ad_id}` 后，"slots" 被当 ad_id 捕获恒 422——端点完全不可用
3. **chat 会话索引毒化**: 旧 fallback 回填存全键，经 `_k()` 二次前缀查询落空——3 存量会话管理端不可见（count 19 vs 22）

### P2 级（护栏/数据完整性）
4. **role 派单 seq 扫描**: `dispatch:*` 命中 seq 致 `.get` 崩溃——9-14 首次真实转人工后，后续转人工的幂等检查+最优客服调度全被 P4 兜底静默吞掉
5. **ad seq 扫描×2**: `ad:ad:*` 与 `ad:placement:*` 各命中计数器
6. **chat 知识索引悬挂**: delete 不清理 knowledge_list
7. **promotion 类型绕过×2**: 自绑拦截与防环校验用 hash 字符串与 int 直接 `==` 恒 False——两道防刷护栏静默失效（自绑返回 200）

### 辅助修复
8. **cooperation B904×2**: except 内 raise 缺 from
9. **chat 派单修复配套**: 生产 session_index 一次性归一（23→22 裸 ID）

## 五、关键沉淀——陷阱分类学（6 类）

| 类别 | 实例 | 规避模式 |
|------|------|---------|
| ① seq 计数器通配扫描 | traffic/role/ad/cooperation | `xxx:*` 扫描必跳 `:seq`；seq 实体命名带前缀避开扫描域 |
| ② 路由静态/动态遮蔽 | ad slots | 单段静态路径必须先于单段动态注册；多段不受影响 |
| ③ 索引毒化 | chat 全键成员 | 索引统一裸 ID+strip 前缀自愈 |
| ④ AI 反馈 note 变体 | 5 种格式 | LREM 双格式匹配（message/ad/application/negotiation/promo） |
| ⑤ hash 字符串 vs int 类型绕过 | promotion 自绑/防环 | 比较前 `str()` 归一 |
| ⑥ 时间依赖 | 静默窗/UTC/本地双基/硬编码 | 测试时间无关化；日期键同基取键 |

**E2E 元规则**: ①清理前先证实键前缀（差集空≠零残留）；②键数增长需分类定性（seq 留痕≠残留）；③422 先查请求模型字段名；④requestBody 不替代鉴权头。
