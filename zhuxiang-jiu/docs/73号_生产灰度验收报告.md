## 三、事故与根因分析

**时间线**（2026-09-30 09:0x 生产时）：

| 时点 | 事件 |
|---|---|
| T+0 | pipeline/run（fast 模板）触发生产首次 ffmpeg 合成 |
| T+~1min | SSH banner 超时失联（sshd 抢不到 CPU）；公网健康检查仍偶发 200 |
| T+300s | `subprocess timeout=300` 保护 kill 掉 ffmpeg；uvicorn 抛 TimeoutExpired 后自愈 |
| T+~5min | SSH 恢复：`load average 49.97 / 75.73 / 43.83`（**2 核小机被压死实证**） |
| 止血 | `.env` `SV73_MODE=off` + 容器重启；load 回落 49.97→17.14→0.30 |

**根因定性**：
- ffmpeg zoompan+xfade+libx264（1080×1440×675 帧）为 CPU 密集型滤镜链——本地开发机 ~15s 完成，生产 2 核 VPS 300s 仍未完成，**算力差距 20x+**
- 功能本身全部正确（剧本/匹配/PNG 全过，PNG 无损渲染不涉及 ffmpeg）——纯资源适配问题，非代码缺陷
- 36号视频号生产线架构自述"渲染+合成在**开发机**跑"——73号 pipeline 首版全链在生产执行违背了该架构假设，事故为该偏差的实证

**保护机制有效性**（事故中按设计生效）：
- `subprocess timeout=300` 硬上限防止无限占机 ✓
- 46+1 鉴权（401）阻断未授权触发 ✓
- shadow 态语义（留痕不占归因）✓

## 六、生产现态与使用范式

**现态**：`SV73_MODE=shadow`（观察期留驻）+ `SV73_RENDER_MODE=off` + `SV73_TTS_MODE=off`——shadow 态零渲染按需动作，无人调用零负载。

**分段使用范式**（正式链路）：

```
① 生产 POST /api/sv73/pipeline/run（热点→匹配→剧本→content 登记, 秒回）
② 开发机取 storyboard → 本地渲染 build（ffmpeg 全链, ~15s）
③ POST /api/sv73/render/attach 挂载产物元数据（mp4 留开发机本地）
④ 36号人工三审 review → approve → publish → rpa_pending
⑤ channels/douyin-bot RPA 拉单发布（开发机本地取 mp4 上传）
```

设计依据：RPA 发布本在开发机执行——mp4 文件无需上生产，生产只持元数据。
