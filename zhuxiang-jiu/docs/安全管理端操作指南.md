# 43号·安全管理端操作指南

> 配套：[43号设计文档](AI智能安全管理模块43_设计文档.md)
> 面板定位：AI 安全网的**人工值守与裁决**工作台——攻击事件复核、误报裁决恢复、申诉处理、IP 处置、灰度切换。
> 现状：P0/P1 已交付 14 端点（管理端 10 个），全部可用；面板页面与学习回流属 P2（本文档含 API 操作口径，P2 面板落地后转为界面操作）。

---

## 一、入口与权限

| 项 | 说明 |
|----|------|
| 访问角色 | `X-Role: admin`（安全/风控岗） |
| 基址 | `http://<host>:8000`（实机 `http://127.0.0.2:8000`） |
| 数据源 | `GET /api/security/admin/dashboard`（态势总览）+ `/admin/events`（事件流水）+ `/admin/appeals`（申诉队列） |
| 刷新建议 | 事件流水 30s 粒度；dashboard 周看（误报率看趋势不看单点） |

## 二、态势总览判读（dashboard）

`GET /api/security/admin/dashboard` 返回：

| 字段 | 判读要点 |
|------|---------|
| `events.byAction` | 四档分布：block/challenge/throttle 占比高 → 正被扫描；challenge_exempt 多 → 验证通道活跃 |
| `events.falsePositiveRate` | **误报率**（false_positive / 已裁决数）。>10% 持续两周 → 反馈给 P2 学习回流，阈值/权重待纠偏 |
| `events.pending` | 待裁决事件数（裁决积压预警，>50 需批量处理） |
| `appeals.pending` | 待裁决申诉数 |
| `blocks` | 当前封禁数（正常 <10；激增 = 攻击进行中或误杀） |
| `enforceLevel` | 当前灰度态（见 §六） |

## 三、攻击事件处置四步法

### 第 1 步：拉取待裁决事件

```bash
GET /api/security/admin/events?verdict=pending        # 待裁决队列
GET /api/security/admin/events?action=block           # 按档位过滤
GET /api/security/admin/events?verdict=pending&action=challenge
```

### 第 2 步：复核事件要素（判断真攻击 vs 误报）

展开事件的 `factors` 六因子明细，按拖分因子分流：

| 拖分因子 | 判读 | 动作方向 |
|---------|------|---------|
| `payload_signature` 低 | 注入特征命中（detail 标"特征分50/0"）——SQLi/XSS/遍历/扫描器，**近零误报** | 确认攻击 |
| `path_anomaly` 低 | 探针路径（`/.env`/`/wp-admin` 等）——扫描器必踩 | 确认攻击 |
| `request_rate` 低 | 窗口频次超限（detail 标"窗口 N/120"）——高频爬虫或 CC | 看频次倍数：2-3 倍=爬虫，10 倍+=CC 攻击 |
| `ip_reputation` 低 | 历史攻击 IP（信誉已扣分）——惯犯 | 确认攻击（配合 §五钉住） |
| `identity_risk` 低 | 未认证打敏感端点（detail 标"风险分20"）——越权试探 | 结合 path 判断：敏感路径+未认证=确认 |
| `geo_time` 低 | 凌晨 0-5 点时段 | 单因子不判定，仅加权参考 |

**组合判读速查**：
- `payload_signature=0` + 多类特征叠加 → **确定性攻击**（硬规则已直通 block），直接确认
- `action=challenge_exempt` → 会员已通过验证的挑战档（**真人信号**），一般无需处理
- `action=verify_pass` → 挑战验证通过记录，非攻击事件

### 第 3 步：裁决（P2 学习真值源）

```bash
POST /api/security/admin/events/{eventId}/decide
{"confirm": true,  "reviewer": "工号", "note": "SQLi扫描确认"}
{"confirm": false, "reviewer": "工号", "note": "正常搜索被拦, 误报"}
```

- **confirm=true（确认攻击）**：事件归档，该真值供 P2 Hedge 学习（AI 拦对了）
- **confirm=false（误报）**：事件置 false_positive，**自动恢复**该事件对 IP 的信誉扣分与封禁——无需手动恢复
- 已裁决事件重复操作返回 409（防误触）

### 第 4 步：误报善后

误报裁决已自动恢复信誉/解封。若误报影响会员体验：
1. 检查同 IP 是否还有其他被牵连事件 → 逐条裁决
2. 频次误杀（如会员聚集出口 IP 共享）→ 调整环境变量 `SECURITY_RATE_LIMIT`（默认 120）
3. 反复误杀的 IP → `POST /admin/ips/{ip}/pin`（钉住高信誉，不受自动降分影响——**慎用**，仅在确认可信时）

## 四、申诉处理（会员误报自救通道）

### 流程

会员端对挑战/封禁事件提交申诉（`POST /api/security/appeals`，仅当事人、一事件一申诉）→ 进入待裁决队列：

```bash
GET /api/security/admin/appeals?status=pending    # 待裁决队列
POST /api/security/admin/appeals/{appealId}/decide
{"approve": true,  "reviewer": "工号", "note": "核实为正常业务"}
{"approve": false, "reviewer": "工号", "note": "维持拦截, 拆分扫描"}
```

### 裁决效果

| 裁决 | 申诉状态 | 联动动作 |
|------|---------|---------|
| `approve: true`（误报） | approved | 事件置 false_positive + **IP 信誉返还扣分 + 自动解封** + 通知会员可重试 |
| `approve: false`（维持） | rejected | 事件置 confirmed 归档（真值：AI 拦对了） |

重复裁决返回 409；申诉不存在返回 404。

### 判定口径速查

| 场景 | 判定 | 依据 |
|------|------|------|
| 申诉理由"搜索含引号被拦" + payload 单特征 | 误报 | 正常搜索词撞注入特征（如英文撇号），approve |
| 申诉理由含糊 + IP 多事件聚集 | 维持 | 扫描器批量试探特征 |
| 共享出口 IP（公司/校园网）频次误杀 | 误报 + 调 RATE_LIMIT | 多会员同 IP 正常聚合 |
| `challenge_exempt` 事件申诉 | 一般误报 | 已通过验证=真人，配合 path 复核 |

## 五、IP 处置

```bash
GET  /api/security/admin/ips                  # 信誉列表(三态)
GET  /api/security/admin/blocks               # 当前封禁(TTL 剩余)
POST /api/security/admin/ips/{ip}/ban         {"reason": "..."}   # 手动封禁
POST /api/security/admin/ips/{ip}/unban                           # 手动解封
POST /api/security/admin/ips/{ip}/pin         {"pinned": true}    # 钉住/解钉
```

**信誉三态**：normal（>60）/ suspicious（30-60，评分降档）/ blacklisted（≤30，直通封禁）

| 操作 | 时机 | 注意 |
|------|------|------|
| 手动封禁 | 确认攻击 IP 需立即隔离 | TTL 默认 900s 自动解封；长期隔离用 pin |
| 手动解封 | 误封紧急恢复 | 误报裁决会自动解封，此操作用于绕过裁决的应急 |
| 钉住 | 确认可信 IP 反复被扣分 | 钉住后不受冷却恢复影响，**攻陷该 IP 则需手动解钉** |
| 解封未封 IP | — | 返回 404（仅封禁表内可解） |

## 六、灰度与开关（安全运维口径）

| 环境变量 | 当前值 | 切换效果 |
|---------|--------|---------|
| `SECURITY_GATEWAY_MODE=on` | 默认 on | **off = 一键回退**（网关全放行，攻击留痕也停止） |
| `SECURITY_ENFORCE_LEVEL=observe` | 默认 | 只留痕不处置（当前态） |
| `=shadow` | 可选 | 同 observe（评分演练） |
| `=enforce` | **上线处置** | 四档真处置：throttle 延迟 / challenge 401+挑战 / block 403+封禁 |
| `SECURITY_RATE_LIMIT=120` | 默认 | 窗口内请求上限（误杀多则上调） |
| `SECURITY_BAN_TTL=900` | 默认 | 自动封禁秒数 |

**enforce 上线检查单**：
1. observe 运行 ≥1 周，`falsePositiveRate` <10%
2. 待裁决事件积压已清零（pending=0）
3. 会员申诉通道畅通（已验证）
4. 健康检查路径在白名单（`/api/decision/health` 永久放行，Docker 探针不受影响）
5. 切换后 30 分钟内盯 `blocks` 数与正常业务 200 率

**故障应急**：网关异常（正常请求大量被拦）→ 立即 `SECURITY_GATEWAY_MODE=off`（fail-open 铁律，网关永远不能锁死网站）。
