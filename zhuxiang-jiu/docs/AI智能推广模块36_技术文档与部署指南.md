## 3. 核心机制

### 3.1 热点雷达与可学习评分

- **热点源**：百度/抖音/微博/知乎/小红书五平台。`HOTSPOT_{PLATFORM}_API_KEY` 未配置走**确定性模拟源**（种子=date+6h槽位+平台，同槽位结果一致可复现；主题池品牌命中档位 3/2/1/0 → 相关度 0.9/0.75/0.55/0.05，评分档位确定）。
- **评分公式**：`score = 100 × Σ(权重ᵢ × 分量ᵢ)`，分量 = heat归一(≥500万满分) / velocity(0-1) / brandRelevance(命中词数分档) / persistence(≥48h满分)。
- **权重可学习（P2）**：四因子权重默认 `heat 0.4 / velocity 0.2 / brandRelevance 0.3 / persistence 0.1`，经 ai_learning Hedge 在线调优；扫描时经 `load_effective_weights`（TTL 30s 缓存）读取 champion，晋升后即时生效。热点落库含 `scoreContributions`（权重×分量，Hedge 反馈的因子快照）。
- **风险一票否决**：政治/未成年人/医疗功效/重大灾害词命中 → 状态直接 `discarded`，永不进入决策。
- **去重与冷却**：指纹 `SHA256(平台+规范化标题)[:32]`，48h 去重；同热点 48h 内最多生成 2 条内容。

### 3.2 蹭点决策三档

| 评分 | 决策 | 热点状态 | 说明 |
|------|------|---------|------|
| ≥70 | auto_engage | engaged | 自动进入内容工厂 |
| 50-69 | manual_queue | active(待定) | 人工确认队列(可解释 reason 留痕) |
| <50 | pass | passed | 留痕放弃 |

每条决策记录含分项 reason（审计可回溯"为什么跟/为什么不跟"）。人工裁决端点 `decide` 支持跟进/放弃，重复裁决 409。

### 3.3 GLM-5.3 Agent 四步链与三级降级

| 步骤 | Agent | 输入 → 输出 |
|------|-------|------------|
| Step1 | 热点分析 | 热点 → {angle, brandRelevance, riskFlags, focus}（同热点共享一次） |
| Step2 | 受众匹配 | 画像库profile + 角度 → {audience, tone, tabooWords} |
| Step3 | 内容生成 | 全上下文 + 权威引用池 → {title, body, hashtags, cta, coverHint} |
| Step4 | 自查自纠 | 草稿 + 合规红线 → {revisedBody, selfCheck}（缺警示语自动补齐） |

**三级降级**：`LLM_MODEL_PROMO`(glm-5.3) → glm-4-flash 重试 → 规则模板轨（五平台模板，必含警示语/年龄提示，产出永不中断）。每步独立降级，`agentTrace` 记录各步走轨。

### 3.4 受众画像库与三维匹配（P1）

- 三平台画像 admin 可配（audience/tone/format/scenes/productTones），种子幂等初始化，Step2 生成时注入。
- 三维匹配 = 角度亲和 50% + 产品调性 30% + 场景命中 20%，通过线 0.6。例：婚宴→小红书(0.95亲和)通过、→抖音(0.4)不通过。
- 站内画像回传：聚合会员等级分布，高价值(Lv3+)占比≥30% 建议"侧重品质礼赠"，否则"侧重性价比日常"。

### 3.5 权威信源 RAG 与数字溯源（P1）

- 信源库仅收录可公开引用条目（国标/协会公开数据/权威媒体），类别白名单 + **背书红线词校验**（"官方推荐"类表述拒绝入库，广告法§9）。
- RAG 检索：2-gram 余弦 top-3（复用 knowledge_repository 的 `tokenize/cosine`，确定性），注入 Step3 prompt（"数字必须出自引用池"）。
- **数字溯源校验**：正则提取正文数字声明（GB/T 标准编号 + 数字×单位），必须能在引用池文本中找到出处；"18周岁以下请勿饮酒"等强制提示白名单豁免。无出处数字 → 内容标记 `provenanceViolations`，**人工审核 approve 被 409 拦截**。

### 3.6 三审合规闸门

```
一审 规则审(硬拒): 饮酒动作(干杯/拼酒…) / 权威背书(国家机关推荐…) /
     功效暗示(消除紧张/助眠…) → 命中即 rejected
二审 AI审: 100 - 极限词×30 - 缺警示×35 - 缺年龄提示×35
     ≥80 待人工 / 60-79 强制人工(requiresManualReview) / <60 rejected
三审 人工审: review 端点(硬性违规与分数不足不可通过; 溯源违规不可通过)
```

### 3.7 发布调度与通道三态（P2）

- 黄金时段窗口（本地时区）：抖音 12-13/18-22，小红书 12-14/20-23，朋友圈 19-22，微博 12-14/21-23，视频号 18-21。发布时间空缺自动取下一窗口。
- 防刷屏三重保护：单日全平台上限 `PROMO_DAILY_CAP=20`（409）+ 同热点冷却 2 条/48h + 黄金时段限流。
- **通道三态回执**：

| mode | 条件 | 行为 |
|------|------|------|
| mock | `PROMO_CHANNEL_MODE≠real` | 确定性回执 `PUB-{platform}-{contentId}`，曝光预估=heat×10000×0.3 |
| real | mode=real 且 `PROMO_CHANNEL_{PLATFORM}_KEY` 配置 | POST 平台开放 API 端点，解析 publish_id |
| mock_fallback | real 模式但凭证缺失 / API 调用失败 | 回退 mock 回执 + error 说明（可观测降级，产出不中断） |

### 3.8 Hedge 效果回流（P2）

- `promo_hotspot` 注册为 ai_learning **第 17 个可学习档案**（batch 4）。
- 反馈语义：已发布内容引流量 >0 → engage 决策正确（reward +1）；零点击 → 失误（-1）。因子快照 = 热点评分四分量 + 贡献值。
- `learningFed` 幂等标记防重复回流；clicks 缺省自动从 attract 归因聚合。
- 学习链完全复用通用 Hedge：影子模式挑战者 → 人工晋升 / 护栏（相对默认 0.5~2 倍）/ 漂移监控 / `AI_LEARNING_AUTO` 调度器自动纳入。
- 晋升即失效权重缓存 → 下次扫描评分即时用 champion 权重。

### 3.9 百度 SEO 自动提交（P2）

- URL 收集：sitemap.xml + 全部已发布内容短链落地页 `{SITE_BASE_URL}/r/{code}`。
- `BAIDU_PUSH_SITE/TOKEN` 配置时 POST `data.zz.baidu.com/urls`（普通收录主动推送）；未配置 mock 全受理（remain=3000-n）。
- **当日幂等**（dateKey 维度同 URL 不重推）+ `force` 强推 + 推送记录落库。
- 发布链路 best-effort 自动推送：`process_publish_queue` 发布成功即推送（仅新 URL）。

## 4. 数据模型

### 4.1 Redis Key（前缀 `promo:`，锁前缀 `lock:promo:`）

| Key | 类型 | 说明 |
|-----|------|------|
| `promo:hotspot:{id}` | String(JSON) | 热点（含 scoreComponents/scoreContributions/riskFlags） |
| `promo:decision:{id}` | String(JSON) | 决策记录（decision/reason/status/note） |
| `promo:content:{id}` | String(JSON) | 内容（含 agentTrace/authorityRefs/provenanceReport/learningFed） |
| `promo:content_link:{contentId}` | String(JSON) | → attract 短码映射 |
| `promo:publish:queue` | ZSet | 发布队列（score=scheduledAt 时间戳） |
| `promo:audience_profile:{platform}` | String(JSON) | 平台画像（admin 可配） |
| `promo:authority_source:{id}` | String(JSON) | 权威信源 |
| `promo:seo_push:{id}` | String(JSON) | SEO 推送记录 |
| `promo:dedupe:{fingerprint}` | String(TTL 48h) | 热点指纹去重 |
| `promo:cooldown:{fingerprint}` | String(TTL 48h) | 同热点内容计数 |
| `promo:daily:{yyyymmdd}` | String(TTL 48h) | 单日发布计数 |
| `promo:{entity}:seq` | String | 自增 ID 序列 |
| `lock:promo:generate:{hotspotId}` / `lock:promo:publish` | Lock | 分布式锁（RMW 保护） |

### 4.2 内存模式表（`LOCK_MODE=asyncio` 时）

`promo_hotspots / promo_decisions / promo_contents / promo_content_links / promo_publish_queue / promo_dedupe / promo_cooldowns / promo_daily_caps / promo_audience_profiles / promo_authority_sources / promo_seo_pushes`（经 `repositories/backend.py` 双模式透明切换）。

### 4.3 内容状态机

```
pending →(review approve)→ approved →(publish 入队)→ queued
       →(process 到期出队+通道回执)→ published
pending →(review reject)→ rejected        生成即预审: 硬违规/低分直接 rejected
```

## 8. 运维手册

### 8.1 日常操作流（推荐节奏）

```
雷达大屏(ai-promo-radar.html) → 扫描 → 处理待人工裁决(50-70分)
→ 工厂看板(ai-promo-studio.html) → 生成(选平台) → 审核待审内容
→ 入发布队列(黄金时段自动) → 看报表/回流 → learning/run 每周一次
```

### 8.2 降级可观测性

| 现象 | 观测点 | 处置 |
|------|--------|------|
| Agent 降级 | 内容详情 `agentTrace`（step1-4 各步 glm-5.3/glm-4-flash/rule） | 检查 LLM_API_KEY/配额 |
| 发布降级 | 内容 `receipt.mode=mock_fallback` + `receipt.error` | 配置对应平台 PROMO_CHANNEL_*_KEY |
| SEO 降级 | 推送记录 `error` 字段 | 核对 BAIDU_PUSH_TOKEN |
| 通道状态 | `GET /api/promo/channels/status` | effectiveMode 一览 |

### 8.3 参数调整

- **调价刷屏上限**：`.env` 改 `PROMO_DAILY_CAP` 重启（或代码层 `promo_service_module.PROMO_DAILY_CAP` 测试内改）。
- **热点冷却**：`PROMO_HOTSPOT_COOLDOWN_HOURS`；同热点条数上限为代码常量 `PROMO_HOTSPOT_COOLDOWN_LIMIT=2`（repo 层）。
- **画像调整**：`PUT /api/promo/audience/profiles/{platform}` 即时生效于下一次生成。
- **Hedge 权重**：ai_learning 通用端点（`/api/ai-learning/weights/promo_hotspot` 查看、`manual_override` 人工覆盖、`promote` 晋升、`config` 调 min_feedback/eta/guardrail）。

### 8.4 常见问题（FAQ）

| 问题 | 原因/处置 |
|------|----------|
| 重复扫描无新增热点 | 正常：同槽位指纹去重（skipped 计数）；跨 6h 槽位或配置真实热点源后才有新数据 |
| 生成 409"冷却期内" | 同热点 48h 已生成 2 条；换热点或调 `PROMO_HOTSPOT_COOLDOWN_HOURS` |
| 发布 409"单日上限" | 当日已发布+已入队 ≥20；次日自动恢复或调 `PROMO_DAILY_CAP` |
| 审核 409"数字无权威信源出处" | 正文数字声明不在引用池（编造数据嫌疑）；修改文案或在信源库补充对应条目后重新生成 |
| `learning/run` 409 | 待学习反馈不足 min_feedback(默认10)；先 `learning/collect` 回流或调低门槛 |
| 回流 409"已回流过" | learningFed 幂等保护，每条内容仅反馈一次（Hedge 数据纯净性） |
| real 模式发布仍为 mock 回执 | 平台 KEY 未配置 → mock_fallback（查 receipt.error 与 channels/status） |

### 8.5 安全与合规红线（运维必读）

1. 全部 29 端点需 `X-Role: admin`；生产配合 JWT 中间件（AUTH_MODE=strict）。
2. 酒类广告 §23 硬闸（饮酒动作/权威背书/功效暗示一审即拒）；"过量饮酒有害健康"+18 周岁提示+"广告"标识强制项。
3. 权威引用仅限客观事实陈述（国标条文/公开数据），数字必须溯源可查。
4. 风险热点一票否决永不跟进；决策/审核/发布全链路审计留痕可回溯。
5. `.env` 不入库；平台凭证与百度 token 均敏感，最小权限分发。
