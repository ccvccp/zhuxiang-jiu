# 79号·竹医 逻辑审查与修正 Agent 创新规划方案

> 版本: v1.0 | 日期: 2026-10-21 | 状态: 待执行
> 家族谱系: 49号图形分析 → 78号竹盾(防) → **79号竹医(审+修)**
> 来源: 借鉴《AI项目逻辑审查与修正Agent开发设计方案》(前沿文档), 结合竹香酒项目实情裁剪创新

## 一、定位与家族分工

竹医 = 开发期工具链(非常驻大模型), 全只读分析+处方只出不施。与竹盾互补:

| | 竹盾 78号 | 竹医 79号 |
|---|---|---|
| 视角 | 空间(改动横向影响面) | 时间(业务链纵向完整性) |
| 子命令 | index / impact / gate | audit / contract / consult |
| 回答 | "这次改动会伤到什么" | "业务链哪里断了+怎么修+怎么验" |
| 底座 | registry(端点/模块/页面/红线) | 复用竹盾 registry + 新增 cases 故障库+链定义 |

## 二、三层校验模型(裁剪自文档 L1/L2/L3)

- **L1 业务链完整性(audit)**: 5 条核心链逐步验证——端点在册/鉴权可达/前端有调用点/数据流衔接。断链即 qr 白名单式事故自动暴露。
- **L2 前后端契约(contract)**: 前端 JS 调用面 vs 后端路由登记表对齐——断契/死条目/未用端点三类报告。
- **L3 修正处方(consult)**: 检索故障复盘库 → 处方报告(Patch diff+回归建议+Blast Radius+P0/P1/P2 分级)。**从简实现: 关键词检索+模板映射, 不上向量库/LLM**。

## 三、数据底座新增

### 1. docs/registry/cases/ 故障复盘库(五段式, 对齐文档 Postmortem 模板)

```
# 案例-YYYYMMDD-<短名>
[现象] [根因] [错误代码/配置] [正确写法] [预防规则→可挂竹盾rules]
元数据: tech_stack / module / severity / related_files
```
首批 6 例(全部真实事故): nginx conf 证书 / qr 白名单死条目 / 微信缓存钉死坏版 JS / 移动筛选霸屏 / 599 满减臆想断言 / 45° 库存事故。

### 2. docs/registry/业务链定义.md(5 条链, 人维护)

每条链 = 有序步骤(端点+前置条件+衔接字段), **AI 起草、用户业务校对**(599 教训: 不臆想业务规则):
- 下单支付链 / 扫码登录链 / 评价双写链 / 分润升级链 / 内容检测链。

### 3. 度量: zhuyi:stats hash(audits_total/broken_chains/consults_total) + zhuyi:index:last_run(复用竹盾 stats 管道模式)。

## 四、架构与技术选型(裁剪决策)

| 文档原方案 | 本项目决策 | 理由 |
|---|---|---|
| 多技术栈 Specialist 路由 | 单栈直查 | 项目仅 FastAPI+原生 JS+Redis |
| Neo4j 代码图谱 | registry.json + 复用 zhudun impact 反向引用 | 已有 T1.4 能力, 不重复建设 |
| 向量库 RAG+LLM 路由 | 关键词+元数据过滤检索+模板处方 | 开发期工具链形态, 故障库规模小(百级) |
| Docker Sandbox | pytest 特性基线(21 断言) | Patch 必须基线全绿才算数, 与"单测绿再提"纪律融合 |
| Opus/o3 模型分层 | 不引入常驻模型 | 家族形态一致 |
| 误报率/采纳率度量 | 保留, M1 口径(≤30%)沿用 | 竹盾 M1 复核方法直接复用 |

## 五、关键铁律

1. **处方只出不施**: consult 生成 Patch 建议, 不写盘不自动应用——人工确认后走竹盾五步 SOP 落地。
2. **证据驱动**: 每条审查结论附行号+registry 条目/案例编号引用, 无出处标"低置信度"(文档反幻觉原则)。
3. **MD 为源**: cases/链定义 MD 为权威源, 衍生索引脚本生成, 对齐竹盾"MD 为源"铁律。
4. **Benchmark 先行**: qr 白名单事故(已知答案)作为 P1/P2 回放基准——检不出即不合格。

## 六、实施路线(详见开发任务列表)

P0 底座(cases+链定义+骨架) → P1 audit(链审查) → P2 contract(契约) → P3 consult(处方) → 四里程碑(M0 抽检/M1 qr 回放/M2 双检出/M3 E2E 处方)。
