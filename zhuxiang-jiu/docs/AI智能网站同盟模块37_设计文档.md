# 37号·AI智能网站同盟模块 设计文档 v1.0

> 模块定位：以**中国酒文化生态**("酒水不分家"——好水·好茶·好酒·好菜·好器·好境)为主线的商户同盟平台。超级会员按内容类目入驻为同盟商，电子地图智能分配服务范围，产品上站交易，**销售价 15% 平台分润**，生产商复用竹香酒溯源体系保真，场景化服务(酒友小聚订餐/定制)实现线上线下互动。
> 上游基座：role(契约+分润总账) / venue(入驻状态机范式) / citystore(地图与订单入口范式) / trace_prod(7工段溯源) / wallet(结算) / compliance(审核合规) / ai_scoring(AI预审) / 36号promo(流量引流)。
> 状态：P0 已交付（2026-09-01：入盟网关状态机+AI预审评分器（第18档案）+商品三道门禁（酒类trace_prod溯源门禁）+15%五方分润（role总账双写+wallet货款入账+T+1结算幂等/冲正）+评价信用+报表，专项52项全绿，全量回归零新增失败）；P1（地图GeoGrid/简化溯源上链/评价AI审评/考核）与 P2（场景服务/流量打通）待实施。

## 1. 设计目标与核心概念

### 1.1 一句话模型

**"超级会员 → 按内容定义角色入盟 → 地图圈定服务范围 → 产品/服务上站 → 交易抽佣 15% 多角色分润 → 溯源保真 + 评价信用 → 场景化酒文化生活"**

服务对象：中高档人群——获得可信(溯源)、可得(地图就近)、可评(信用)的高质量产品与服务。

### 1.2 同盟角色谱系（依据内容定义角色——核心创新）

按"酒水不分家"文化逻辑划分类目，类目即角色，角色即入驻通道：

| 角色代码 | 类目 | 内容范围 | 典型商户 | 溯源要求 |
|---------|------|---------|---------|---------|
| `alliance_water` | 好水 | 泉水/天然水/泡茶水 | 水坊/水企 | 简化溯源(水源地凭证) |
| `alliance_tea` | 好茶 | 茶叶/茶器配套 | 茶庄/茶山 | 简化溯源(批次+产地) |
| `alliance_wine` | 好酒 | 白酒/黄酒/果酒(非本站自营) | 酒厂/酒商 | **全量溯源(复用 trace_prod 7工段)** |
| `alliance_dish` | 好菜 | 菜品/私厨/预制菜 | 私厨/餐厅 | 简化溯源(食材凭证) |
| `alliance_meat` | 肉类 | 火腿/牛羊肉/腊味 | 肉品厂 | 简化溯源(检疫凭证) |
| `alliance_fish` | 鱼类 | 河鲜/海鲜/水产 | 水产商 | 简化溯源(冷链凭证) |
| `alliance_vessel` | 酒具 | 酒器/茶器/杯盏 | 酒具作坊/品牌 | 简化溯源(工艺凭证) |
| `alliance_venue` | 好境 | 酒店/会所/宴饮包场 | 酒店/会所 | 资质准入(消防/食品经营) |

> 类目字典 admin 可配（`alliance:category:{code}`），新类目按"与酒文化关联度"评审后开放——保证生态不泛化成大杂烩。

### 1.3 入盟门槛（"规则同盟商是网站超级会员"）

| 门槛项 | 规则 | 复用 |
|--------|------|------|
| 会员等级 | ≥ Lv4（超级会员线，admin 可配） | member level |
| 实名认证 | 已通过 P1-3 实名 | auth realname |
| 信用分 | role 信用分 ≥ 阈值（默认 80） | role credit_events |
| 冷却期 | 被清退者 90 天内不得再申请（参照 citystore） | citystore 模式 |

### 1.4 与既有模块关系（统筹决策：复用不合并）

```
                 ┌───────────────────────────────────────────────┐
                 │        37号·AI智能网站同盟模块                  │
                 │  入盟审核 → 地图分配 → 商品上站 → 交易分润      │
                 │  → 溯源保真 → 评价信用 → 场景服务(小聚/定制)   │
                 └────┬─────────┬─────────┬─────────┬────────────┘
      契约范式+分润总账 │  入驻状态机 │ 地图/入口 │  溯源    │ 结算/合规/AI
   role ──────────────┘           │          │          │
   venue(范式参考,不合并) ←────────┘          │          │
   citystore(范式参考,不合并) ────────────────┘          │
   trace_prod(7工段全量复用) ───────────────────────────┘
   wallet(货款+佣金) / compliance(审核上报) / ai_scoring(入驻预审) / 36号promo(引流)
```

**明确不合并**：
- venue/citystore 各自服务既有业务（场地铺货/市店考核），同盟仅复用其**范式**；`alliance_venue` 类目商户入驻后，其场所信息可在 P2 与 venue 场地库做引用打通（映射不迁移）。
- trace_prod **直接复用**：酒类生产商入盟后即走既有 7 工段打卡+瓶码绑定，同盟商品详情透出溯源链（`public_trace`），零重复建设。
- 分润一律经 `RoleService.record_external_settlement(source_module="alliance")` 记入 `profit_ledger` 统一总账（venue 已验证的旁路对账模式）。

## 2. 总体架构：七个子系统

```
 [入盟网关 Gateway]        [地图引擎 GeoGrid]         [商品中心 Catalog]
  超级会员申请+类目角色  →   服务范围智能分配       →   上架审核(溯源门禁)
  AI预审→人工审核→签约      geofence+冲突仲裁          站内展示+交易下单
        ↓                       ↓                        ↓
 [交易与分润 TradeShare]    [溯源保真 Provenance]     [评价信用 ReviewCredit]
  订单15%抽佣→多角色分润    trace_prod复用+简化溯源    双向评价+AI语义+信用联动
  T+1结算→wallet入账        批次/凭证上链存证          星级/预警/清退触发
        ↓
 [场景服务 SceneFlow]      ← AI 编排(复用 hub 意图路由)
  酒友小聚订餐(选酒→配菜→订境) / 定制服务 / 线下核销
```

### 2.1 入盟网关（alliance_gateway）

```
申请 → AI预审(ai_scoring) → 人工审核 → 签约(contract) → 试用(90天) → 转正
 ↓拒                          ↓                ↓            ↓
 90天冷却                  补件重报         契约终止       考核不过→清退
```

- 状态机（复用 role 契约范式 + venue 等级）：
  `pending → ai_reviewing → manual_reviewing → signed → probation → active ⇄ suspended → terminated/rejected`
- **AI 预审评分器**（新评分器 `alliance_onboarding`，注册 ai_learning 第 18 档案，Hedge 可学习）：因子 = 会员等级(25)/信用分(20)/实名完整性(15)/类目资质齐备度(25)/区域竞争度(15)，≥80 自动通过进入人工终审快车道，60-79 人工重点审，<60 拒。
- **退出规则**：
  - 主动退出：提前 30 天申请，结清在途订单与分润，状态 `terminated`（90 天冷却后可再申请）
  - 强制清退：连续 2 个考核周期不达标 / 信用分 < 60 / 严重违规（假溯源/刷单/食品安全）→ 即时冻结商品、终止契约、`compliance.raise_risk_warning` 上报
  - 暂停：单周期不达标 / 投诉率超阈 → `suspended`（整改后申请恢复）

### 2.2 地图引擎 GeoGrid（电子地图智能分配服务范围）

**范围模型**（三级，商户申请时勾选，admin 核定）：

```
city(市级) → district(区县级, adcode) → grid(5km×5km 经纬网格)
```

**智能分配与冲突仲裁**（`alliance_geo_service`）：

| 规则 | 说明 |
|------|------|
| 类目密度上限 | 同 grid 同类目商户数 ≤ 上限（默认 3，防内卷；酒类宽松=5） |
| 优质优先 | 竞争时按"信用分+评价星级+考核等级"加权排序，高位者得 |
| 就近推荐 | C 端按定位选 grid → 类目商户推荐（距离+评分排序） |
| 订单入口 | 复用 citystore `decide_order_entry` 五级路径范式：同盟商品下单时定位→grid→商户 |

**数据**：商户范围表 `alliance_coverage(merchantId, category, adcode, gridKey)`；行政区划用 adcode 字典（GB/T 2260），网格 `floor(lat/0.05):floor(lng/0.05)` 编码。

### 2.3 商品中心（alliance_catalog）

- 上架流程：商户提交商品 → 三道门禁 → 站内展示 → 统一交易
  1. **资质门禁**：类目必资质（食品经营许可证/检疫证等，compliance 上报+存证）
  2. **溯源门禁**：酒类商品必须绑定 trace_prod `batch_no`（已 `release_batch` 放行）且瓶码在库；其他类目至少附简化溯源凭证（批次+产地/检疫/冷链凭证哈希上链）
  3. **合规门禁**：复用 36号三审闸门范式（极限词/警示语/食品宣称）
- 商品在**本站统一商品库**展示（`product/list` 加 `source=alliance` 维度），交易走既有 checkout 订单链（库存由商户库存表承扣，锁内原子扣减同 flashsale 范式）
- **价格规则**：商户定价，平台展示价=商户价；成交后 15% 平台抽佣（见 2.4）

### 2.4 交易与 15% 分润（alliance_trade）

```
订单支付成功 → 抽佣 15% → 分润池按角色拆账 → T+1 结算入 wallet
货款 85% → 商户货款账户(T+7 可提现, 冻结期覆盖售后)
```

**15% 分润拆账**（默认比例，admin 参数化，`alliance_share_settings`）：

| 角色 | 份额 | 说明 |
|------|------|------|
| 平台 | 40% (即佣金 6%) | `ROLE_PLATFORM` |
| 所属类目服务商 | 20% | 类目运营角色(如酒类服务商) |
| 推荐人(拉商户入盟者) | 15% | 拉新归因，防刷复用 promotion 防环/唯一绑定 |
| 就近市店 | 15% | 订单入口若来自市店(citystore) |
| 同盟发展基金 | 10% | 活动/补贴池 |

- 记账双写：业务侧结算单 `alliance_settlements` + `RoleService.record_external_settlement(source_module="alliance")` 入 `profit_ledger`；资金经 `WalletService.deposit_reward` 入账
- **结算接口**：`settle_order(order_id)`（T+1 定时调度器 `ALLIANCE_SETTLE_AUTO`，幂等，退款冲正 `reverse_settlement` 参照 role 冲正模式）；商户提现走 wallet 既有三级审批链+大额上报

### 2.5 溯源保真（Provenance）

- **酒类生产商**：全量复用 trace_prod——入盟即开通工段打卡权限（`PermService` 环节授权），商品必须挂 `release_batch` 放行批次，消费者扫码看 7 工段链+瓶码流通
- **其他类目简化溯源**：`alliance_provenance` 表（批次号/产地/检疫证号/凭证哈希），凭证哈希经 compliance `add_blockchain_evidence` 上链存证
- **假溯源红线**：抽检不一致 → 即时清退+风险上报（不可整改类违规）

### 2.6 评价信用（ReviewCredit）

- **双向评价**：消费者↔商户（订单完成+核销后）；评分 1-5 星 + 文字
- **AI 语义审评**（新评分器 `alliance_review` 入 ai_scoring）：恶意差评/刷好评识别（文本语义+行为因子），违规评价折叠
- **信用联动**：评价聚合 → 商户星级 → 周期写入 role `publish_credit_event`（影响入盟门槛信用分与地图竞争排序）
- 考核（参照 citystore 月度考核）：GMV/好评率/履约时效/客诉率 → A/B/C/D 等级 → 影响密度上限配额与暂停/清退

### 2.7 场景服务 SceneFlow（线上线下互动，AI 编排）

**酒友小聚订餐**（王牌场景，"好酒配好菜配好境"一站式）：

```
用户意图("周六6人小聚，喝竹香酒") → hub 意图路由(注册"同盟场景"能力)
  → 场景编排器: 选酒(自营/同盟酒) → 配菜(alliance_dish 私厨按人数配单)
  → 订境(alliance_venue 酒店/会所包间按时段) → 合并下单(一个订单号三子单)
  → 线下到店核销码 → 核销完成 → 三商户分别结算分润 → 三方互评
```

- **定制服务**：酒具刻字/私宴定制/封坛定制——商户发布定制 SKU，用户提交需求单，商户报价→确认→定制生产→交付（状态机 `demand→quoted→confirmed→producing→delivered`）
- **线下核销**：订单生成核销码（一次性，扫码核销幂等），核销触发货款解冻与分润起算

### 2.8 平台流量统筹（行为统筹）

- 同盟商品纳入 36号 promo 引流体系：热点雷达蹭点内容可挂同盟商品短码（utm_campaign 归因）
- 首页"酒文化生活"频道：按用户画像（member_profile 评分器）推荐"水茶酒菜器境"组合内容
- 同盟商户可参与 attract 内容工厂（其产品作为选题产品池），站内分佣内容归因复用 attract 报表

## 4. API 设计（routes/alliance_routes.py，前缀 /api/alliance，约 34 端点）

**入盟（6）**：`POST /apply`（超级会员申请+类目）/ `GET /applications` / `POST /applications/{id}/audit`（人工审核）/ `POST /merchants/{id}/activate`（转正）/ `POST /merchants/{id}/suspend|terminate` / `GET /merchants`
**类目与范围（5）**：`GET/PUT /categories`（类目字典）/ `POST /merchants/{id}/coverage`（申请范围）/ `GET /geo/merchants?lat=&lng=&category=`（就近推荐）/ `GET /geo/coverage`（商户查范围）/ `POST /geo/arbitrate`（冲突仲裁触发）
**商品（6）**：`POST /products`（上架三道门禁）/ `GET /products?merchantId=&category=` / `PUT /products/{id}` / `POST /products/{id}/offline` / `GET /products/{id}/provenance`（溯源透出）/ `GET /products/{id}/trace`（酒类直通 trace_prod 公开链）
**交易与分润（6）**：`POST /orders/{orderId}/settle`（手动结算）/ `POST /orders/{orderId}/reverse`（冲正）/ `GET /settlements` / `GET /settlements/preview`（拆账预览）/ `GET /share/settings` / `PUT /share/settings`
**评价（4）**：`POST /reviews` / `GET /reviews?merchantId=` / `GET /merchants/{id}/rating` / `POST /reviews/{id}/fold`（AI违规折叠）
**场景（5）**：`POST /scenes/gathering`（酒友小聚编排出单）/ `POST /scenes/custom-demand`（定制需求）/ `GET /scenes/custom-demands` / `POST /scenes/custom-demands/{id}/quote|confirm` / `POST /redeem/{code}`（线下核销）
**考核与报表（4）**：`POST /assessment/run`（周期考核）/ `GET /merchants/{id}/assessment` / `GET /report/overview` / `GET /report/category`

鉴权：管理端 X-Role: admin；商户端 X-Merchant-Id（JWT 联动）；公开端（商品/溯源/评价查询）免头。

## 6. 合规与红线

1. 食品类目（菜/肉/鱼/场所餐饮）必须持有效食品经营许可证，资质过期自动下架
2. 酒类：未成年人禁售（复用 age_gate）+ "过量饮酒有害健康"警示 + 同盟酒商须全量溯源
3. 抽佣 15% 与分润比例必须参数化留痕，`profit_ledger` 双轨口径可审计
4. 商户货款 T+7 冻结期覆盖售后，平台不得挪用（分润池与货款账户分账）
5. 评价不得删除只可折叠（留痕），刷好评/恶意差评双向打击
6. 入盟协议/资质/溯源凭证全部上链存证（compliance blockchain_evidence）
7. 假溯源/食品安全事故 = 即时清退不可整改 + 监管报送

## 7. 分期实施计划

### P0 核心闭环（先跑通"入盟→上货→交易→分润"）
- 类目字典 8 角色 + 入盟状态机（AI 预审评分器 + 人工审核 + 契约）
- 商品上架三道门禁 + 站内展示 + checkout 交易（商户库存原子扣减）
