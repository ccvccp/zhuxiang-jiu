# 智运·AI智能物流大模型 升级上线交付总结

> 交付日期: 2026-09-16 | 升级内容: 三态灰度模式层 + 护栏 + 控制面
> 环境生产: 47.236.61.117(zxjiu.com) + 本地开发
> 定位: 物流管理模块(基础 18 端点 + 智运 AI 40 端点)对齐全站
> 大模型标准(68/71/73/74/45号范式)——补齐模式层后正式入列。

---

## 一、背景与目标

物流域两代已全线交付: 基础物流管理(18 端点: 下单/流转/回调/
月结对账/结算) + 智运 AI 一代(P0-P3: 智能路由/轨迹智能/风控
回执/分析进化) + 智酿运通二代(P4-P7: 语义调配/渠道熔断/深度
绑定/角色提醒/进化2.0)。对比全站五大模型缺**三态灰度模式层**
——决策无开关、无护栏、无运行时切档。本次升级补齐该层:

- 决策可控(off 关闭 / shadow 观察 / assist 生产)
- 业务护栏(三指标恶化自动暂停)
- 运行时切档(免容器重建, 人工留痕)
- 基础物流 18 端点零影响铁律(mode 仅作用于 AI 决策面)

## 二、三态与读取链

`ZW_MODE`(智运前缀——避开既有 LOGISTICS_* 命名):

| 态 | 行为 |
|---|---|
| off(默认) | 17 决策端点 409(决策面关闭); 观测面不受影响; 基础物流 18 端点零影响 |
| shadow | 决策放行 + 响应留痕标记 `zwMode` 字段 |
| assist | 决策生效(生产档) |

读取链(优先级): **护栏暂停 > 运行时 override > 环境变量 > 默认 off**。

## 三、端点分类(40 → 44)

| 面 | 数量 | 端点 |
|---|---|---|
| 决策面(门控) | 17 | route/decide、risk/assess、risk/inspect-receipt、risk/claims(POST)、evolution/feedback、semantic/normalize、semantic/register-carrier、semantic/order-profile、semantic/feature-route、circuit/report、binding/tri-code、binding/reverse、alert/scan、alerts/{id}/ack、evolution2/preference、evolution2/suggest、evolution2/suggestions/{sid}/decide |
| 观测面 | 23 | decisions/carrier-scores/route-health、track 三系、claims(GET)、analysis 两系、feedbacks、semantic carriers/feature-routes、circuit status/reports、binding capacity/tri-codes/**verify(公开+脱敏)**/reverses、alerts、evolution2 preferences/anomaly-patterns/carbon/suggestions、status |
| 控制面(新增) | 4 | GET /mode、POST /mode/override、POST /mode/guard、POST /mode/resume |

实现: `routes/zw_routes.py` 统一 `@_decision` 装饰器(门控 off 409 +
shadow/assist 响应标记 zwMode)——17 端点各一行装饰, 语义零变化;
`services/zw_mode_service.py`(蓝本: 45号 trust45_mode_service)。

## 四、护栏三指标(智运语义)

| 指标 | 基线 | 代理语义 |
|---|---|---|
| delayRate 延迟率 | 0.10 | 轨迹延迟占比——时效恶化代理 |
| anomalyRate 轨迹异常率 | 0.05 | 异常轨迹占比——调度质量代理 |
| circuitBreakRate 渠道熔断占比 | 0.10 | 熔断渠道占比——运力健康代理 |

恶化判定: (cur-base)/base > **3%** 自动暂停(基线 0 时 cur>0 即恶化);
paused 留痕 pausedReason/breachTrail(≤50); 恢复须人工 resume(决策留痕)。
护栏是保护机制(功能开关非处罚), 可自动; 全确定性(阈值比较, LLM 禁入)。

## 五、状态存储(45号 P0 教训规避)

状态整档 JSON 单键存储(`zhuxiang:zw:mode_state`, 对齐 _ZwStore
params 范式)——**json.dumps/loads 整体往返, 类型天然保留**,
规避 45号 字段级序列化清单漏注册导致的 Redis 真值误判 P0。

## 七、部署转段 SOP

1. 服务器同步: zw_mode_service.py(新)/zw_routes.py + 测试文件
2. `.env` 写 `ZW_MODE=assist` → `docker compose up -d --build backend`
3. 三层自验: L1 `GET /api/logistics-ai/mode` → assist;
   L2 决策冒烟(route/decide 200+标记); L3 观测(status/
   route/health 200 + binding/verify 公开可达)
4. 回滚: `sed -i 's/^ZW_MODE=.*/ZW_MODE=off/' /opt/zhuxiang/.env
   && docker compose up -d backend`(秒级)

## 八、风险与回滚

- 门控漏插: 17 端点逐一 409 断言覆盖(测试钉死)
- 基础物流误伤: 18 端点零改动(铁律), 基础 3 套回归全绿实证
- 误 off: 生产 .env 钉死 assist; 运行时 override 留痕
- 序列化 P0 复发: 整档 JSON + 专项回归断言双保险
