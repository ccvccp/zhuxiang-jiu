## 一、背景与归因基线

### （一）P0 阶段成果（已收口）

- **P1.5·竹语首声优化**（提交 fc07e31）：服务端响应内并行预合成 + "好的——"恒定首块秒播 + splitSpeech 回退切分。**缓存命中 21ms vs 冷合成 1684ms**（生产冷热对比实证）。
- **P1.6·六段埋点**（提交 5d63ec5）：`voice78_tts_timing` 分段日志（conn/up/acoustic/dl/total）落地，前端 `[LAT-embed]` 采集链修复。

### （二）P1.6 生产归因实测（3 样本）

| 样本 | conn_ms | acoustic_ms | dl_ms | total_ms |
|---|---|---|---|---|
| 4字"好的——" | 26 | 607 | 108 | 742 |
| 13字短句 | 21 | 1097 | 134 | 1253 |
| 44字长句 | 21 | 2709 | 253 | 2984 |

**归因结论**：握手冷启动 ~21-26ms（无可压）、上传 0ms、下载随体积线性（非瓶颈）；**acoustic_ms（服务端合成）占总时 82~91%，与字数近线性——唯一真瓶颈在非流式 API 的"整句合成完才返回"**。P0 文档方案中"预建连/降起播阈值"经实证本站不适用。

### （三）残余瓶颈场景（P1 的靶子）

P1.5 已把热路径（执行轮+默认音色+预合成命中）压至 ~0.1-0.2s，剩余冷路径首声 0.6~3s 波动：

| 场景 | 原因 | P1 预期收益 |
|---|---|---|
| care 轮（识别失败/用户负面，语速 0.92 键不匹配） | mood 系数改缓存键，预合成不覆盖 | 流式首块后 ~0.4s |
| 切音色用户（非 tongtong 档） | 预合成仅写默认音色键 | 同上 |
| 动态新文案首块冷合成 | 从未出现过（无缓存） | 同上 |
| steady 轮（结算确认 0.95 系数） | 同 care | 同上 |

## 二、P1 启动前置门（Gate——过三门再开工）

### （一）G1 真机 AEC 复测基线

在真机微信（X5）与手机浏览器场景采集一周样本：`[LAT-embed]` 四段 + `voice78_tts_timing` 五段，统计：
- **冷/热合成占比**（缓存命中率）——决定 P1 覆盖面
- resp→play 的 P50/P90（冷路径单列）
- 端到端首声 P50/P90

### （二）G2 冷合成占比阈值决策

| 冷合成占比（真机周样本） | 决策 |
|---|---|
| < 10% | **不启动 P1**——P1.5 缓存已覆盖 90%+ 轮次，冷路径偶发可接受，投入产出不成立 |
| 10% ~ 30% | **启动路线 A**（云端流式 API），B 路线挂起观察 |
| > 30% | **A+B 并行评估**——冷路径是常态，自建 ROI 需同步测算 |

### （三）G3 接口与价格查证（A 路线硬前置）

1. **模型名兼容性 spike**：`TTS_MODEL=cogtts` 切 `glm-tts`（或验证 cogtts 是否支持 `stream:true`）——生产容器内跑流式请求实证（智谱文档调用示例已确认 glm-tts 支持 `"stream": true, "response_format": "pcm", "encode_format": "base64"`，SSE `data:` 分块返回）。
2. **流式单价**：查智谱价格页 glm-tts 流式/非流式是否同价（第三方转售价参考 0.03 PTC/千字符）。
3. **音色映射**：glm-tts 官方音色 = tongtong/小陈/锤锤/jam/kazi/douji/luodo——78号 6 档中 **male/female 两档需替代方案**（glm-tts 枚举未列），验证是否仍被接受或换档。
4. **SSE 分块规格**：首块音频时长（决定流式首声下限）、块间隔、pcm 采样率（24kHz/16bit mono 待实证）。

## 三、候选路线评估

### 路线对比矩阵

| 维度 | A：云端流式 API（glm-tts stream） | B：自建 GLM-TTS（开源权重） | C：A 先行 + B 影子 |
|---|---|---|---|
| 首声预期 | conn(26ms)+首块(200~400ms) ≈ **0.3~0.5s** | 同量级，且可调 lookahead 更激进 | 以 A 实测为准 |
| 开发量 | 后端 SSE 代理 + 前端 PCM 流水线（~2-3 天） | 模型部署+音色 LoRA 定制+GPU 运维（数周级） | A + 影子对照开关 |
| 硬件成本 | 零新增 | GPU 服务器（A10/T4 级）月租 + 运维 | 同 A + B 调研费 |
| API 成本 | 与非流式同价则零增量 | 边际成本趋零（电费+折旧） | 同 A |
| 音色 | 7 档官方枚举（male/female 需换档） | **LoRA 定制"小竹"品牌音色**（6 档人格任意复刻） | A 档案为主 |
| 风险 | 供应商依赖/接口变更/SSE 兼容 X5 | 质量对齐验收/峰值容量/运维负担/合规自担 | 双线风险最低 |
| 长期演进 | 受制于云厂商 | 完全自主，文档 P1 三项（流式声学/声码器/常驻量化）全部落地 | 由数据决定 B 是否升级 |

### 决策倾向

**推荐 C：A 先行（快赢），B 影子观察（升级路径）**。理由：
- A 开发量小、零硬件投入，glm-tts 流式接口官方已开放（非自研假设）
- GLM-TTS 权重已开源（HuggingFace/ModelScope，两阶段架构 text2token-AR + token2wav-Diffusion + 2D-Vocos 声码器），B 路线技术可行但需 GPU 投入与音色定制验收——**在 A 的灰度数据（冷占比、月合成量、供应商稳定性）出来前不宜押注**
- B 的启动触发器见 §九

## 四、路线 A 技术方案要点（推荐先行）

### （一）后端：流式 SSE 代理

- 新增 `GET /api/xiaozhu/tts/stream?text=&speed=&voice=`（鉴权/文本限制同 /tts）：
  - 透传智谱 `POST /audio/speech`（`stream:true, response_format:pcm, encode_format:base64`）
  - 以 FastAPI `StreamingResponse` 逐 `data:` 块转发（SSE 兼容 X5 fetch 流式读取需实证；不兼容则降级 chunked 转发）
  - **打点扩展**：`voice78_tts_timing` 增 `first_chunk_ms`（首个 SSE 块到达）——补齐 P1.6 归因缺失的 first_audio_chunk 段
  - 流式完成后**整段拼接落 Redis**（键沿用 `tts_cache_key`，格式加 `:pcm` 后缀隔离）——热句仍秒播走缓存，冷句才流式
- 预合成（P1.5）不动：双通道互补，缓存命中永远优先于流式

### （二）前端：PCM 流式播放管线

- 现有 v3 分句流水线（ttsEnqueue/pumpTts 队列接力）**复用**——把"块=子句"泛化为"块=流式分片"：
  - fetch ReadableStream 逐块读取 → base64 解码 → PCM16 转 Float32（24kHz mono）→ `ctx.createBuffer` 直接构 AudioBuffer（**绕过 decodeAudioData**，pcm 无需解码）
  - 队列接力/序号保序/失败块跳过/打断清理全沿用
- 兜底链：流式失败（SSE 中断/超时）→ 回退整句 `/tts`（P1.5 稳定路径）→ 再回退预取缓存

### （三）音色档案调整

- 78号 JOYVOICE_PROFILES 6 档中 male/female 若 glm-tts 不接受 → 换 `jam/kazi` 角色档或保留 cogtts 非流式兜底（该两档走整句通道）
- `XIAOZHU_TTS_STREAM=off/shadow/assist/full` 四态灰度（对齐全站三态范式）：
  - off：现状（整句+缓存）
  - shadow：流式双发不播，只采 first_chunk_ms 数据
  - assist：流式优先，失败自动回退整句
  - full：流式主用

## 五、成本测算（启动前补数）

| 项 | 取数方式 | 备注 |
|---|---|---|
| 日均语音轮次 × 平均合成字数 | xiaozhu turns 表运营统计 | 算月 API 账单基数 |
| glm-tts 流式单价 | 智谱价格页查证（G3-2） | 若与非流式同价 → A 路线 API 成本零增量 |
| B 路线 GPU 月租 | A10/T4 行情调研 | 与月账单对比得 ROI 转正点 |
| B 路线人力 | 模型部署+LoRA 音色+运维 | 数周级投入 |

## 六、风险与合规

- **A**：供应商接口变更风险（缓存层+回退链已是天然缓冲）；SSE 在 X5 的 fetch 流式兼容性是最大不确定项（G3-4 spike 首验）；流式 pcm 无水印选项需确认合规水印与现 wav 一致
- **B**：自建内容合规自担；峰值容量规划；音色 LoRA 定制需 A/B 听感验收
- **通用**：流式首块前仍有 conn+TN/G2P 时间，P50 收益上限受智谱服务端首块延迟制约（G3-4 实测定预期）

## 七、验收标准（A 路线 full 转段门槛）

1. 冷路径 resp→play：**P50 ≤ 500ms，P90 ≤ 800ms**（[LAT-embed] 真机周样本）
2. 端到端首声（说完→听到）：**P50 ≤ 3.0s**
3. 流式失败回退率 < 2%（assist 态统计），full 态零白屏零静默
4. 音色听感 A/B：6 档与现 cogtts 逐档对照评分不低于基线（male/female 换档单独验收）
5. 回归：test_xiaozhu_joyvoice 全绿 + preheat/预合成/缓存链不回归 + X5 真机白名单验收
6. 78号 P1.5 缓存命中路径（21ms）在流式 full 态仍为首选热路径

## 八、灰度与回滚

- 四态灰度（off→shadow→assist→full），每态真机样本 ≥ 3 天
- 回滚：`XIAOZHU_TTS_STREAM=off` 一键回 P1.5 稳定路径（已生产验证）
- 双 bump 部署规约不变（widget VER + index 引用）

## 九、决策建议与 B 路线触发器

1. **先过 G1~G3 三门**（真机基线周样本 + 冷占比 + 接口/价格查证），门内数据说话
2. 冷占比 ≥ 10% → 启动 A；< 10% → P1 挂起，维持 P1.5（记录归档，季度复评）
3. **B 路线触发器**（满足其一即立项）：
   - 月 TTS 账单 > GPU 月租 × 1.5（ROI 转正）
   - 智谱接口变更/限流/涨价影响可用性
   - 品牌定制音色需求升级（"小竹"专属音色 LoRA 是 78号人格化的终态）
   - A 路线流式首块实测 P90 > 800ms 达不到验收线
