# 60号·AI智能支付管理模块 实施计划

> 定位：本站智能收付管理系统——**从"交易通道"到"信值驱动的价值交换引擎"**（将"资金流"转化为"信任流"与"数据流"的业务价值中枢——连接用户意图、角色权益、合规风控与无形资产估值）

> 范式：意图识别（58号）→ 服务编排（59号）→ **支付履约（60号：让"付钱"变成"履约的自然延伸"）** → 支付行为反哺信值估值与意图优化（信任飞轮）

---

## 一、定位与设计理念

### 1.1 核心差异（传统支付 → 本站智能支付）

| 维度 | 传统支付 | 本站 60号 | 差异 |
|------|---------|----------|------|
| 触发逻辑 | 用户主动+固定金额 | 意图联动+**动态定价** | "人找支付"→"支付适配业务" |
| 风控模式 | 规则引擎+事后拦截 | **信值实时校准+事中自适应验证** | "一刀切拦截"→"分级无感通行" |
| 对账方式 | T+1 人工核对 | **AI 语义对账+异常自动归因** | "滞后纠错"→"实时自愈" |
| 用户体验 | 跳转第三方+重复填写 | 站内闭环+**一键确认** | "中断式支付"→"沉浸式履约" |
| 数据价值 | 仅记录流水 | 支付行为**反哺信值估值+意图优化** | "数据孤岛"→"信任飞轮" |

### 1.2 总铁律

> **"简单"不等于"省略安全步骤"，而是"让合规用户感受不到安全的存在"——支付摩擦感与信任等级成反比。**
> 最好的支付系统，是让用户忘记自己在支付。每一步自问：这个支付步骤是让用户感到被信任，还是被怀疑？

### 1.3 六条工程铁律（本站宪法平移）

1. **默认零影响**：`PAY60_MODE` 默认 off——存量订单/交易链路零影响；60号与既有订单支付路径**并行不替换**（双模型铁律）
2. **渠道三态**：`PAY60_CHANNEL_MODE` mock（默认）/real（fail-hard）/mock_fallback（真实失败回退 mock——41号 DRIDE 范式）；凭证经 .env 注入不落盘
3. **LLM 不进判定链**：对账匹配/风控裁决/分账拆分全部确定性轨；LLM 仅 assist 态生成归因文案与建议（不产数字不产裁决）
4. **优化永不自动生效**：定价规则/风控阈值/分账合约变更全部经 46号审批总线+人工终审
5. **归因 ID 强制**：每笔支付携带归因链（payId+intentId+sessionId+tier+riskTier+定价快照+渠道回执）——无归因不计入有效结算
6. **资金操作保守性**：一切出账（退款/分账/临时额度）默认延迟到账可撤销（T+1 结算域）；异常自动冲正优先于人工

## 三、四维创新架构

### 3.1 智能收银台（P1）

**上下文感知渲染**（CHECKOUT_CONTEXTS）：
- 场景×角色×意图 → 支付方式组合推荐：同盟商上架→"保证金+服务费"合并单；老年用户（49号偏好标记）→"子女代付/语音确认"优先；高信值续费→默认勾选"信用免密续订"（仅生物特征确认语义——屏幕码）
- 渲染留痕 `renderOptions` 可审计

**动态定价引擎**（PRICING_RULES——DSL 封闭注册+版本化+46号审批）：

```
finalPrice = basePrice
  × trustDiscount(tier: trusted 0.95/standard 1.0/watched 1.0/restricted 1.05)
  × contributionDiscount(合规月数: ≥6 月 0.8/≥3 月 0.9/其余 1.0)
  × promoFactor(在期活动——叠加封顶 0.7)
```

**铁律**：优惠归因透明（每项折扣 attribution 展示）；叠加下限封顶 0.7（防击穿）；规则变更人工终审。

**失败智能恢复**（FAIL_RECOVERY）：失败原因分类（余额不足/限额/风控拦截/渠道超时）→恢复建议有序集（拆分支付/换渠道/临时额度申请/稍后重试）——建议性不自动执行。

### 3.2 信值融合风控（P2）

**riskTier 四级验证直通**（信值×金额×行为三轴）：

| 档 | 条件（示例口径） | 验证 |
|----|----------------|------|
| pass（无感） | tier≥trusted 且单笔≤5000 且设备可信 | 直通（confirmToken 轻确认） |
| light（轻量） | tier≥standard 或单笔≤2000 | OTP 语义验证（mock 码） |
| strong（强验证） | tier=watched 或单笔>5000 | 屏幕码+二次确认（48号 confirmToken 流） |
| block（阻断） | tier=restricted 或命中洗钱环路/合规禁令 | 拒绝+整改指引推送 |

- **行为序列校验**：支付前序操作（浏览→下单→改单→支付）纳入特征——跳跃式操作（无浏览直接大额支付）升一档验证
- **合规前置**：角色权限×行业禁令×税务规则校验（不合规直接阻断——58号"识别即合规"支付版）
- **fail-soft**：信值/画像读取异常→light 档+留痕（风控设施故障不阻断业务）

### 3.3 AI 对账与结算（P3）

- **语义级对账**（RECON轨道）：平台订单↔渠道流水↔发票三方匹配（金额+订单号+时间窗）；差异自动分类（渠道超时重复扣款/部分退款/手误金额）→**自动冲正建议**（退款类自动执行 T+1 延迟域+人工终审大额）+LLM assist 归因文案
- **智能分账引擎**（SPLIT_CONTRACTS——合约 DSL+版本化+46号审批）：按合约条款×信值等级×税务规则拆分（如同盟商订单：平台服务费 8%+保证金冻结+商户余额）；实时/T+1/周期三模式
- **现金流预测**（P4）：7 日窗口确定性外推（历史模式+业务日历+信值趋势线性加权）——预警资金缺口

### 3.4 支付数据反哺（P4——信任飞轮）

| 支付事件 | 信值联动 | 档案回流 |
|---------|---------|---------|
| 按时履约+合规开票 | 信值增益输入（45号 platform_conduct 域） | 正样本 +1.0 |
| 支付成功（意图联动单） | 意图模型正样本（58号回流） | intent_positive +0.6 |
| 支付失败/异常 | Bad Case 入库+信值损耗 | payment_anomaly -0.5 |
| 争议/退款 | 纠纷率输入 | refund_dispute -0.8 |
| 洗钱/盗刷确认 | 45号负修正+封禁联动 | fraud_confirmed -1.0 |
| 长期合规记录 | "合规经营证书"生成（外部场景） | compliance_streak +0.3 |

幂等：payId 1:1（pooledFeedbackId 范式）；第35档案 payment_orchestration 池双写。

## 四、第35档案：payment_orchestration 八因子

44号 ai_learning 入册（batch19——既有测试 34→35 计数更新：预算约 34 处 12 文件）。

| 因子 | 权重 | 口径 |
|------|------|------|
| payment_success_rate | 0.20 | 支付成功率（成功/发起） |
| verification_friction | 0.15 | 验证摩擦（直通率——高直通=体验好） |
| recon_accuracy | 0.15 | 对账准确率（自动匹配/总量） |
| fraud_interception | 0.15 | 欺诈拦截率（确认欺诈/拦截总数） |
| member_trust | 0.10 | 会员信值（47号 tier 基线） |
| dispute_rate | 0.10 | 争议率（反向因子） |
| latency_budget | 0.05 | 支付链路 P95 达标率 |
| coverage_breadth | 0.10 | 支付场景覆盖度（意图→支付映射） |

→ 信任分 0-100 → 三级决策：observe（<50）/optimize（≥50 规则与阈值回流）/urgent（≥80 支付复盘会）。

## 五、数据模型（8 表，前缀 pay60）

| 表 | 键 | 语义 |
|----|-----|------|
| pay60_orders | payId | 支付订单（状态机+归因链+定价快照） |
| pay60_checkouts | checkoutId | 收银台渲染（场景组合+renderOptions） |
| pay60_verifications | verifyId | 验证事件（riskTier+验证方式+结果） |
| pay60_flows | flowId | 渠道流水（mock/real 回执+指纹） |
| pay60_recon | reconId | 对账批次（差异分类+归因+冲正态） |
| pay60_splits | splitId | 分账指令（合约版本+拆分明细+结算态） |
| pay60_thresholds | tier | 风控/定价阈值配置域（46号审批联动） |
| pay60_events | eventId | 全链事件（order/checkout/verify/recon/split/appeal/learn_signal/scheduler_run） |

支付订单状态机：
```
created → priced → verified → executing → success → settled
   │          │          │           │
   │          └→ priced_failed(定价失败) │
   └→ cancelled(未支付取消)  └→ failed ─→ recovering(失败恢复)
                                    └→ refunded(退款终态)
```

复用：44号池（第35档案 batch19）；58号 evaluate（意图联动）；59号 route（场景编排）；47号 get_profile（tier 纯读取）；48号 confirmToken（验证流复用）；45号 deposit（信值增益/损耗——platform_conduct 域）；46号审批总线；43号威胁分（风控输入之一）。

## 七、分期实施计划（P0-P5）

### P0 支付注册表+订单状态机+渠道底座
- PRICING_RULES/SPLIT_CONTRACTS/CHECKOUT_CONTEXTS 封闭注册+启动自检（52号范式）
- 支付订单九态状态机+归因链底座
- 渠道适配层（CHANNEL_MODE 三态——41号 DRIDE 范式 mock 优先）
- 第35档案入册 batch19（34→35 计数更新）
- 8 表底座；测试约 45 断言；QC：注册封闭；58/59/48号零改动

### P1 智能收银台
- 动态定价引擎（三因子+叠加封顶+归因透明+46号审批版本化）
- 上下文感知渲染（场景×角色×意图→支付方式组合）
- 意图联动开单（58号 resolved→支付意图；59号 serving 会话关联）
- 失败智能恢复（分类+建议集——不自动执行）
- 测试约 40 断言；QC：定价归因可审计；恢复建议性

### P2 信值融合风控
- riskTier 四级直通（信值×金额×行为三轴）+tier 联动
- 行为序列校验（跳跃升档）+合规前置（权限/禁令/税务）
- 验证流（48号 confirmToken 复用：轻 OTP/强屏幕码）
- 阈值配置域（46号审批+人工终审轨——58/59号阈值域范式复用）
- 测试约 40 断言；QC：fail-soft 不阻断；高信值无感直通

### P3 AI 对账与结算
- 三方语义对账（确定性轨）+差异分类+自动冲正（T+1 延迟域）
- LLM assist 归因文案（仅建议——确定性归因表为真值）
- 智能分账引擎（合约 DSL+三模式结算）
- 测试约 40 断言；QC：资金操作人工终审；冲正留痕

### P4 支付数据反哺+现金流预测+T+1 调度
- 六类支付事件→44号池双写（payId 1:1 幂等）
- 现金流预测（7 日确定性外推+缺口预警）
- T+1 调度器（PAY60_LEARN_MODE 默认 off）
- 测试约 40 断言；QC：回流幂等；预测确定性

### P5 看板+红队+三件套收官
- 四区看板（度量：成功率/直通率/对账准确/欺诈拦截+订单+风控+防御）
- 红队七向量：定价操纵（伪造折扣归因）/风控绕过（tier 伪造）/洗钱环路（资金环注入）/对账投毒（伪造流水）/分账篡改（越权重放）/验证绕过（跳档确认）/退款滥用（重复退款）
- 宪法断言（44号 35 档案+58/59/48号零改动）+收官三件套
- 测试约 35 断言；QC：资金安全全链防御

**开关矩阵**：`PAY60_MODE`（默认 **off**）/`PAY60_CHANNEL_MODE`（默认 **mock**）/`PAY60_LLM_MODE`（默认 off）/`PAY60_LEARN_MODE`（默认 off——四开关铁律）。

## 九、一致性声明与外部待办

**零改动宪法**（每期断言验证）：44号学习中枢零改动（仅新增第35档案，35 档案口径）；58/59号零改动（evaluate/route 纯消费）；48号零改动（confirmToken 流复用）；45号信值（deposit 补偿范式调用）；47号画像/46号治理/43号安全零改动（纯读取/审批总线调用）；既有订单/交易模块零改动（并行不替换）。

**外部待办**：真实渠道接入（微信/支付宝/银联——凭证经 .env 注入，参照 41号直发待办清单）；FIDO 硬件密钥（当前屏幕码语义占位）；跨境实时清算与汇率对冲（real 态远期）；数字货币/稳定币（生态期）；强化学习转化率优化（远期——当前确定性规则轨）。

**结语**：60号让支付从"交易通道"进化为"信值驱动的价值交换引擎"——高信值者享受极简无感（摩擦感与信任等级成反比），低信值者自动增强验证；每一次按时履约都在为信任飞轮加速，每一次异常都在教第35档案识别风险。**复杂留给系统，简单还给用户——让用户忘记自己在支付，但永远记得被信任。**
