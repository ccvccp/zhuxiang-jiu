## 二、六期核心交付

### P5-1：D5 强制联动收口（检测能力 → 处置能力）
- **`SECURITY_D5_ENFORCE` 开关**（默认 off——`/admin/reports/d5` 三条件硬标准达标后人工开启）+ `SECURITY_D5_ENFORCE_BAND` 边界区（默认 25-50，非法配置自动回退）
- on 语义：D5 命中且威胁分 ∈ [lo, hi) → 处置升档为**至少 challenge**；单一 D5 命中**永不单独触发 block**（行为信号非确定性攻击）
- 硬规则叠加不降档；`d5_enforce` 因子独立留痕（单独统计联动误报率）；通行证豁免联动（升档的 challenge 仍可被 TTL 通行证豁免）
- 观测端点新增 `d5Enforce` 实况 + 面板⑦区 D5 状态卡（off/达标未启/已启用三态）

### P5-2：Redis 告警接入消息通道（被动可见 → 主动触达）
- [security_alert_service.py](../backend/services/security_alert_service.py)：采集 → **critical/warn 级别过滤**（info 碎片率仅面板可见防噪声）→ **规则级 24h 去重**（SETNX TTL，大 key 未处理次日不重发）→ **聚合单封**站内信 → 管理员逐一触达（单人失败不阻断）
- `CATEGORY_SECURITY` 强制投递（MANDATORY_CATEGORIES——绕过退订/静默/频率零改造）+ P1 优先级；无告警零发送
- 调度器 ④ 步骤日度自动巡检（`lastAlerts` 留痕）+ 手动轨端点（force 跳过去重）+ 面板一键发送

### P5-3：威胁情报自动订阅（静态快照 → 活情报）
- [threatintel_feed.py](../backend/services/threatintel_feed.py)：httpx 拉取 + **三重校验前置**（HTTP 200 / ≤10MB / 有效行 ≥100——错误页不进导入链路）
- `maybe_refresh` 周期判断（默认 7 天，下限 3600 防误配忙循环）；**fail-soft 旧段宁旧勿空**（import 内部先 parse 成功才 clear）
- 连续 3 次失败 **degraded** 外显（`stats().auto` 可接 P5-2 告警）；调度器 ⑤ 步骤 + 手动 refresh 端点（与上传端点双轨互为降级）

### P5-4：AbuseIPDB 单 IP 实时情报（段级 → 单 IP 精度补刀）
- [abuseipdb_client.py](../backend/services/abuseipdb_client.py)：三态（mock 确定性三档 / real 无 key 拒启 fail-hard / mock_fallback 失败回退 fail-soft）
- **三重配额节省**：Firehol 段级前置（命中不再花配额）+ 24h 结果缓存（同 IP 当日零消耗）+ 900 红线熔断（日切 TTL）
- **两级串联**：Firehol 命中优先返回 → 未命中查 AbuseIPDB；三级强度递进（≥75 降档 31 不直封 / 25-75 轻扣 -10 下限 31 / <25 零影响）
- **mock 态不联动**（执行中修复的设计缺陷——确定性分数不参与信誉联动，未配置零影响）

### P5-5：GeoLite2 完整解码（IP 数量口径 → 真实地理距离）
- **MMDB 数据段解码器**（纯 stdlib 14 类型：pointer 4 级/string/double/uint×4/int32/map/array/boolean/float/bytes）+ metadata 正确解析（map 解码，失败回退固定偏移口径）
- `lookup_geo` 返回城市/经纬度/ISO（中文优先）+ LRU 4096 热路径保护 + 解码异常回退命中标记口径（fail-soft）
- **haversine 距离跳变**：2h 窗口 >500km（可调）降 50，留痕"北京→上海 1068km/2h"；无经纬度回退 P3-3 distinct 粗口径
- **自建最小 mmdb 夹具**（手工编码二进制，编码器↔解码器 round-trip 双向验证）——真实库就位零代码变更
- 面板④区 IP 归属地列

### P5-6：CIDR 区间二分检索（O(n) → O(log n)）
- 有序区间表 + `bisect_right` 左邻判断；**阈值 1000 自动分流**（规模即开关，<1000 线性零改动）
- **版本戳防陈旧**（save/clear 递增——同规模换内容/导入中途/增量导入三陷阱统一防御）；**starts 预计算**（查询零列表重建）
- 命中回填单键取（内存 3MB 而非 50MB dict）；v4/v6 双族独立；`stats().matchMode/matchSegments` 可观测
- 顺带消解隐性瓶颈：查询零 `list_threatintel()` 调用（Redis 模式下逐键 hgetall 网络往返）

## 三、执行中发现并修复的问题（7 项）

| 期 | 问题 | 根因 | 修复 |
|----|------|------|------|
| P5-1 | D5 测试 13 项失败 | P5-4 mock 态确定性分数污染网关联动（D5 测试 IP 被降档） | **联动仅 real/mock_fallback 生效**——mock 是客户端测试口径，未配置零影响 |
| P5-2 | 实机 admins=0 无触达 | 容器 Redis 无 role=admin 会员 | 测试环境提升会员角色（运维口径：管理员经 auth 模块配置） |
| P5-3 | 容器拉取全部失败 | **requirements.txt 缺 httpx**（4 处 lazy import 掩盖——本地全局包可用、容器无） | requirements 补 `httpx>=0.27.0` 根治（存量缺口） |
| P5-3 | 专项"Auto on 执行"误判 | 刚成功导入处于周期内，executed=False 属正常 | 断言改 status=ok 即接通 + 伪造过期状态验真执行 |
| P5-5 | 实机夹具不生效 | 夹具写入 backend/data/，而容器无 `./data` 挂载（非 compose volume 启动） | 改 `docker cp` 注入容器 `/app/data/` |
| P5-6 | **性能 bug**：10k 查询 11 秒 | `_match_bisect` 每次查询重建 2 万元素 starts 列表——O(n) 重建抵消二分收益 | 构建时预计算 starts（修复后达标） |
| P5-6 | **存量缺陷**：clear 只清一半/stats 少算 | `list_threatintel` 默认 limit=10000，但 MAX_IMPORT_CIDRS=20000 允许导入 2 万段——**P4-3 起潜伏，万段内测试从未触发** | 默认 limit 提至 200000 |

> 两条经验沉淀：①**性能优化必须配基准断言**（P5-6 无 10k<200ms 断言则 O(n) 重建 bug 直接带病上线）；②**边界规模测试是存量缺陷的探针**（万段上限的截断缺陷只有 20k 段实机才暴露）。
