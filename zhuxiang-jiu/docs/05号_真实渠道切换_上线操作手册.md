|---|---|---|---|

## 阶段 1 · 凭证注入(不切模式, 业务零影响)

### 1.1 凭证文件落位(推荐文件挂载, 免 .env 转义)

docker-compose 已有 `- ./data:/app/data:ro` 只读挂载, **无需改 compose**:

```bash
# 服务器执行: 建目录 + 落凭证文件(从商户平台下载的原始文件)
mkdir -p /opt/zhuxiang/data/keys && cd /opt/zhuxiang/data/keys
# 微信: apiclient_key.pem(商户API证书私钥)
# 支付宝: app_private_key.pem(应用私钥) / alipay_public_key.pem(支付宝公钥)
chmod 600 /opt/zhuxiang/data/keys/*
```

### 1.2 .env 注入(追加到 /opt/zhuxiang/.env)

```bash
cat >> /opt/zhuxiang/.env <<'EOF'
# --- 05号收款 · 真实渠道凭证(P2-4 后, 切换前先注入但模式仍 mock) ---
PAY60_CHANNEL_MODE=mock
# 主凭证开关(任一非空值, fail-hard 校验项; 建议填 APIv3 密钥)
PAY60_CHANNEL_KEY=<微信APIv3密钥>
# 回调地址(默认值即生产, 可省略)
# PAY60_NOTIFY_URL=https://zxjiu.com/api/payment/callback/pay

# --- 微信支付 V3(下单 P0-1 + 回调验签 P0-2) ---
PAY60_WECHAT_MCHID=<商户号>
PAY60_WECHAT_APPID=<已绑定商户号的AppID>
PAY60_WECHAT_SERIAL_NO=<商户API证书序列号>
PAY60_WECHAT_PRIVATE_KEY=/app/data/keys/apiclient_key.pem
PAY60_WECHAT_APIV3KEY=<32位APIv3密钥>
# 平台证书(回调验签用): 二选一
#   a) 固定证书(从 /v3/certificates 首拉或商户工具导出后固定)
PAY60_WECHAT_PLATFORM_CERT=/app/data/keys/wechat_platform_cert.pem
#   b) 自动拉取(注释掉上面两行, 系统将用商户钥签名请求 /v3/certificates
#      + APIv3 解密, 12h 缓存)——首次回调前需商户凭证齐全
# PAY60_WECHAT_PLATFORM_SERIAL=<固定证书序列号, 选固定模式时建议填>

# --- 支付宝(下单 P0-1 + 回调验签 P0-2) ---
PAY60_ALIPAY_APPID=<开放平台应用ID>
PAY60_ALIPAY_PRIVATE_KEY=/app/data/keys/app_private_key.pem
PAY60_ALIPAY_PUBLIC_KEY=/app/data/keys/alipay_public_key.pem
EOF
chmod 600 /opt/zhuxiang/.env
```

### 1.3 重建生效 + 注入核验(模式仍 mock, 零业务影响)

```bash
cd /opt/zhuxiang && docker compose up -d backend    # env 变更触发重建
docker exec zhuxiang-backend-1 printenv | grep PAY60 | sort
# 期望: 上述全部变量就位, PAY60_CHANNEL_MODE=mock
# 充值回归: 仍走 mock 自动落账(确定性回执, 业务零变化)
```

## 阶段 2 · 灰度切换(mock_fallback, 观察渠道执行器)

### 2.1 切换命令

```bash
sed -i 's/^PAY60_CHANNEL_MODE=.*/PAY60_CHANNEL_MODE=mock_fallback/' /opt/zhuxiang/.env
cd /opt/zhuxiang && docker compose up -d backend
```

### 2.2 灰度语义

- 钱包充值/SVIP 发起支付时**先走真实统一下单**: 成功 → 返回真实
  预支付参数(paying), 等真实回调验签落账;
- 执行失败(网关拒绝/网络/凭证问题)→ **自动回退 mock 自动落账**,
  支付单 callbackContent 留痕 `fallback: true, fallbackReason: <原因>`;
- 业务不中断, 用户无感。

### 2.3 观察与放量判据(观察 ≥ 24h)

```bash
# 灰度期看回退留痕(应逐渐为 0)
docker exec zhuxiang-redis-1 redis-cli --scan --pattern "zhuxiang:payment:order:*" \
  | head -50   # 抽样 hgetall 看 callbackContent 的 fallback 字段
docker logs zhuxiang-backend-1 2>&1 | grep -i "mock_fallback\|gateway_prepay" | tail -20

# 小额实测(¥100 充值): 前端拉起真实支付 → 成功回调 → 余额到账
#   channelTradeNo 应为真实渠道单号(非 MOCK 前缀)
```

**放量判据**: 连续 24h 真实下单成功率稳定(回退留痕趋零)、回调验签
零 401 告警、对账无差异 → 进入阶段 3; 否则排查后重试或回滚。

## 阶段 3 · 全量切换(real)

### 3.1 切换命令

```bash
sed -i 's/^PAY60_CHANNEL_MODE=.*/PAY60_CHANNEL_MODE=real/' /opt/zhuxiang/.env
cd /opt/zhuxiang && docker compose up -d backend
```

### 3.2 三层自验(逐项必过)

```bash
# ① 容器层
docker exec zhuxiang-backend-1 printenv PAY60_CHANNEL_MODE   # real
docker ps | grep zhuxiang-backend-1                          # healthy

# ② 语义层(核心铁律生效)
#    发起支付: mock 自动落账关闭——start 返回 paying + 真实预支付参数
curl -s -X POST https://zxjiu.com/api/wallet/deposit -H "X-Member-Id: <ID>" \
  -H "Content-Type: application/json" -d '{"amount":100,"payChannel":"wechat"}'
# 记 payNo 后:
curl -s -X POST https://zxjiu.com/api/payment/<payNo>/start -H "X-Member-Id: <ID>"
# 期望: status=paying, channelMode=real, payParams 含 h5Url(微信)或 payUrl(支付宝)

# ③ 安全层(伪造回调必须 401)
curl -s -o /dev/null -w "%{http_code}" -X POST https://zxjiu.com/api/payment/callback/pay \
  -H "Content-Type: application/json" \
  -d '{"channelTradeNo":"FORGED","payNo":"PAYXXXX","callbackContent":{}}'
# 期望: 401(无签名归一化载荷在 real 模式被拒)
```

### 3.3 真实小额支付闭环(¥100)

1. 前端(或 curl 走 ②)发起充值 → 拉起微信 H5 / 支付宝跳转;
2. **真实付款** ¥100 → 渠道异步通知 `https://zxjiu.com/api/payment/callback/pay`
   → 验签通过 → 入账;
3. 核验四要素:

```bash
# 支付单: status=paid, channelTradeNo=真实渠道单号(非 MOCK 前缀)
curl -s https://zxjiu.com/api/payment/<payNo> -H "X-Member-Id: <ID>"
# 余额: +100 到账
curl -s https://zxjiu.com/api/wallet/info -H "X-Member-Id: <ID>"
# 回调验签日志: 无 forge_suspect 告警
docker logs zhuxiang-backend-1 2>&1 | grep -i "forge_suspect" | tail -5   # 应为空
```

### 3.4 渠道侧配置(切 real 前在商户平台完成)

| 渠道 | 配置处 | 值 |
|---|---|---|
| 微信 | 商户平台「支付配置」 | 回调 `https://zxjiu.com/api/payment/callback/pay`; H5 支付需在商户平台开通 H5 权限并配置域名 |
| 支付宝 | 开放平台「应用网关」 | 同一回调地址; wap 支付签约 |

## 附录 · 环境变量总表

| 变量 | 用途 | 必填 | 形态 |
|---|---|---|---|
| `PAY60_CHANNEL_MODE` | 渠道三态 mock(默认)/mock_fallback/real | 是 | 枚举 |
| `PAY60_CHANNEL_KEY` | 主凭证 fail-hard 开关 | real 起 | 任一非空 |
| `PAY60_NOTIFY_URL` | 回调地址(默认 zxjiu.com) | 否 | URL |
| `PAY60_WECHAT_MCHID` | 微信商户号 | 微信渠道 | 商户号 |
| `PAY60_WECHAT_APPID` | 绑定商户的 AppID | 微信渠道 | AppID |
| `PAY60_WECHAT_SERIAL_NO` | 商户API证书序列号 | 微信渠道 | 序列号 |
| `PAY60_WECHAT_PRIVATE_KEY` | 商户证书私钥 | 微信渠道 | PEM 路径或内联 |
| `PAY60_WECHAT_APIV3KEY` | APIv3 密钥(回调解密) | 微信回调 | 32 位 |
| `PAY60_WECHAT_PLATFORM_CERT` | 平台证书(回调验签) | 二选一 | PEM 路径或内联 |
| `PAY60_WECHAT_PLATFORM_SERIAL` | 固定证书序列号 | 固定模式建议 | 序列号 |
| `PAY60_ALIPAY_APPID` | 支付宝应用ID | 支付宝渠道 | AppID |
| `PAY60_ALIPAY_PRIVATE_KEY` | 应用私钥(下单签名) | 支付宝渠道 | PEM 路径或内联 |
| `PAY60_ALIPAY_PUBLIC_KEY` | 支付宝公钥(回调验签) | 支付宝回调 | PEM/裸base64/路径 |
| `PAY_EXPIRE_AUTO` | 超时关闭调度开关(默认 on) | 否 | on/off |
| `PAY_EXPIRE_SCAN_INTERVAL` | 超时扫描周期秒(默认 900) | 否 | 整数 |
