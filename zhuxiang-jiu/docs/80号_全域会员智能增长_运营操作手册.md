# 全域会员智能增长(79/80号) 运营操作手册

> 适用对象: 运营团队 | 更新: 2026-10-01(80号上线版)
> 涉及模块: 推广码矩阵(基础) + 79号会员流量智能(引进积分) + 80号全域增长(分享积分/新人礼/落地个性化)
> 权限要求: 管理员账号(X-Role: admin); 以下 API 示例中 `<TOKEN>` 为管理员登录凭证, `<UID>` 为会员数字 ID

---

## 一、积分规则全景(现行有效)

### 1.1 增长激励链(79/80号, 2026-10-01 上线)

| 行为 | 奖励 | 到账方式 | 上限 |
|---|---|---|---|
| 会员分享产品/推广文案 | **20 积分/次** | 即时 | 每日计分 5 次; 同一内容当日只计 1 次 |
| 新会员注册(经推广码) | **100 积分新人礼** | 绑定成功即时 | 一人一生一次 |
| 推荐人引进 1 位注册会员 | **300 积分/人** | 新会员绑定即时 + 站内信通知 | 无上限(逐人发) |
| 观看者点击短码进站 | 无积分(留痕) | — | 用于漏斗统计 |

**每引进一位新注册会员, 系统总发放 400 积分**(新人 100 + 推荐人 300)。

### 1.2 与既有奖励的关系(并行不冲突)

| 既有规则 | 内容 | 与新规则关系 |
|---|---|---|
| 钱包一级奖 | 直推满 10 人 → 20 元购物现金/轮 | 并行, 各算各的 |
| 钱包二级奖(裂变) | 6 个下线各推满 5 人 → 15 元/轮 | 并行 |
| 每日签到 | 10~25 分/天, 周期宝箱最高 200 分 | 独立体系 |
| 领酒资格 | 按奖励规则达标获得 | 独立体系 |

> 说明: 积分可在站内消费抵现; 钱包奖励余额仅可购物不可提现。新会员绑定后 24 小时内计入推荐业绩(老会员绑定不计)。

## 二、防刷机制(系统自动, 无需运营干预)

| # | 闸门 | 机制 | 运营感知场景 |
|---|---|---|---|
| 1 | 同内容当日幂等 | 同一产品/文案当天分享多次只计 1 次 | 会员反馈"分享没到账"——查是否重复内容 |
| 2 | 分享日限 | 每日最多计 5 次(第 6 次起不发) | 会员当日超额——次日恢复 |
| 3 | 24 小时新人原则 | 注册超 24h 的会员绑定推广码不计业绩、不触发奖励 | 老会员绑定"无效"属正常 |
| 4 | 一人一绑 | 每个会员一生只能绑定一个推广码 | 换绑诉求需先作废原关系(见 §3.5) |
| 5 | 防环/自绑 | 不能绑自己的码; 不能互为上下级 | 报错"成环/自绑"属拦截 |
| 6 | 渠道白名单 | 领码渠道仅限七个合法值 | 非法渠道直接拒绝 |
| 7 | 发放幂等 | 每个"新人/引进/分享事件"有唯一标记, 系统重试也不会重复发分 | 无重复发薪风险 |

**刷单特征识别(需人工判断时)**: 短期内同一推荐人绑定数激增、被绑新会员手机号连号、绑定后无任何消费行为——处理见 §4.2。

## 三、后台配置步骤(SOP)

> 所有操作需要管理员身份。示例中的域名按环境替换(生产 zxjiu.com)。

### 3.1 查看当前参数配置

```
curl -H "Authorization: Bearer <TOKEN>" -H "X-Role: admin" \
     https://zxjiu.com/api/promotion/admin/settings
```

返回的 `settings` 中, 与 79/80 号相关的字段:

| 字段 | 含义 | 当前默认 |
|---|---|---|
| pointsPerReferral | 每引进 1 人的推荐积分 | 300 |
| sharePointsPerAction | 每次分享积分 | 20 |
| shareDailyLimit | 分享计分日上限(次) | 5 |
| welcomeNewcomerPoints | 新人礼积分 | 100 |
| enabled | 推广体系总开关 | true |

### 3.2 调整奖励数值(即时生效, 新事件按新值)

```
curl -X PUT -H "Authorization: Bearer <TOKEN>" -H "X-Role: admin" \
     -H "Content-Type: application/json" \
     -d '{"sharePointsPerAction": 30, "shareDailyLimit": 3}' \
     https://zxjiu.com/api/promotion/admin/settings
```

- 只传要改的字段, 未传字段保持不变
- 数值必须 ≥ 0; **设为 0 = 关闭该项奖励**(如 `"welcomeNewcomerPoints": 0` 即停发新人礼)
- 已发放的历史积分不受影响

### 3.3 紧急关停(某项活动出问题时)

按需选择关闭范围:

| 场景 | 操作 |
|---|---|
| 只停分享积分 | `{"sharePointsPerAction": 0}` |
| 只停新人礼 | `{"welcomeNewcomerPoints": 0}` |
| 停推荐引进积分 | `{"pointsPerReferral": 0}` |
| 全部推广体系停摆(含钱包奖励) | `{"enabled": false}`(慎用, 同时停掉既有钱包规则) |

### 3.4 数据查看(效果监控)

| 想看什么 | 操作 |
|---|---|
| 某会员的引流漏斗(点击/注册/积分) | `GET /api/promotion/my/funnel`(带该会员 X-Member-Id; 或让会员自查推广页) |
| 某会员积分流水(含分享/新人/推荐明细) | `GET /api/points/logs/<UID>?source=share80`(source 可换 traffic79/welcome80) |
| 会员积分余额 | `GET /api/points/account/<UID>` |
| 全站绑定关系审计 | `GET /api/promotion/admin/relations?status=valid&limit=200` |
| 奖励发放记录 | `GET /api/promotion/admin/rewards?memberId=<UID>` |
| 领酒待发货 | `GET /api/promotion/admin/wine-claims?status=pending_shipped` |

### 3.5 异常处置: 撤销推广码 / 作废绑定关系

```
# 撤销某推广码(之后不能再被绑定; 已建立的关系不受影响)
curl -X POST -H "Authorization: Bearer <TOKEN>" -H "X-Role: admin" \
     https://zxjiu.com/api/promotion/admin/codes/ZXBJ-XXXXXX/revoke

# 作废某条绑定关系(该会员不再计入上级业绩; 再调用一次 = 恢复)
curl -X POST -H "Authorization: Bearer <TOKEN>" -H "X-Role: admin" \
     https://zxjiu.com/api/promotion/admin/relations/<被绑会员UID>/invalidate
```

### 3.6 手动补发奖励(客诉补偿)

```
curl -X POST -H "Authorization: Bearer <TOKEN>" -H "X-Role: admin" \
     -H "Content-Type: application/json" \
     -d '{"memberId": 123, "rewardType": "wallet", "amount": 20, "detail": "客诉补偿-推广奖励未到账"}' \
     https://zxjiu.com/api/promotion/admin/rewards/grant
```

- rewardType: `wallet`(购物现金) / `wine_qualify`(领酒资格)
- 积分类补偿暂无直发端点——走技术通道或在积分模块处理(联系技术执行)

## 四、常见运营场景处置

### 4.1 会员反馈"我推荐了好友但没到账"

排查顺序:
1. 确认好友是**注册后 24 小时内**绑定的码(超时不计业绩——正常)
2. 查绑定关系: `GET /api/promotion/admin/relations?inviterMemberId=<推荐人UID>` 看该好友 `status` 是否 valid
3. 查推荐人流水: `GET /api/points/logs/<推荐人UID>?source=traffic79` 是否已有 300 分记录
4. 若绑定 valid 且无流水 → 联系技术查日志(系统故障才需要补发, 补发走 §3.6 或积分补偿)

### 4.2 怀疑刷单

1. 查该推荐人绑定列表(§3.4 关系审计), 看新增绑定的时间分布与会员行为
2. 处置组合拳: 撤销其推广码(§3.5) + 作废可疑绑定关系(§3.5)
3. 已发积分追回: 联系技术执行(提供会员 UID 与事件清单)
4. 预防性降闸: 临时下调 `shareDailyLimit` 或相关奖励为 0

### 4.3 临时调整活动力度

大促前调高(如分享 30 分/推荐 400 分) → 大促后回调——都用 §3.2 的 PUT 即可, 即时生效, 无需重启。

## 五、检查清单

**每日(1 分钟)**:
- [ ] `GET /api/promotion/admin/settings` 确认参数未被误改
- [ ] 站内信/客服群无积分未到账集中反馈

**每周**:
- [ ] 关系审计(§3.4)抽查新增绑定, 关注单日暴增的推荐人
- [ ] 看推广页漏斗趋势(点击/注册转化率)评估活动效果
- [ ] 领酒待发货清零(§3.4 最后一条)

## 六、注意事项(红线)

1. **不要**直接改数据库/Redis 里的积分数字——一切走本手册的端点
2. `enabled=false` 会停掉**整个推广体系**(含原有钱包奖励), 关停前确认影响范围
3. 参数修改即时生效且**只影响之后的新事件**——已发的不回追
4. 本手册操作均留管理日志, 勿用他人账号代操作
