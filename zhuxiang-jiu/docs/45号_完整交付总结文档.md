## 一、模块概览

### 1.1 定位

43号把"攻击面"管完, 44号把"消费面"管好, **45号经营"社会面"**——
信值 = 信用的价值化(无形资产), **1 TV 锚定 1 元货品/服务**。

针对现行信用体系三大窄域(只罚不修/只看金融/只归机构)的答案:
**法治 50% + 伦理 30% + 贡献 20% 的三层可解释度量 + 即时修复引擎
+ 行为资产化的价值锚定**。

### 1.2 三大理念落法

| 理念 | 落法 |
|------|------|
| 遵循规则 | 三层权重 50/30/20 为**宪法级常量**(层内归一化——学习漂移数学上动不了层间结构); L1 违法即熔断上层不可覆盖; 全链路留痕可审计 |
| 方便快捷 | 双角色自助建档; 自愿存证通道(先验真再入库); 五类开放 API(走 44号 Key 网关) |

### 1.3 平台参照

## 三、各期交付明细

### P0 · 三层评分内核(★★★ 先行)

- **第28档案 TrustValueScorer**(batch=12): 九因子三层分组
  (L1 法治 50%: legal_record/regulatory/asset_integrity;
  L2 伦理 30%: platform_conduct/community_standing/ethics_evidence;
  L3 贡献 20%: contribution_net/impact_radius/longtail_good)
- **宪法护栏**: 层内归一化——权重任意漂移后层间贡献数学恒定
  (专项篡改权重断言: L1-only 满分恒 50 分)
- **L1 熔断引擎**: general α=1.0 / severe α=0.3 锁 critical(封顶 29.9,
  rawScore 保留)/ criminal α=0 永久; L2/L3 满分不可拯救(硬约束)
- **双角色档案**: person(合同履约)/org(无形资产确权)语义切换;
  证件 SHA-256 摘要存储(明文不落盘)+ idDigest 唯一映射防重复建档
- **冷启动**: L1=80 善意推定 / L2=50 中性 / L3=0 从零 → 初始 55(watch)

### P1 · AI 雷达三通道

- **公开域雷达**: 白名单源(裁判文书/行政处罚/税务公示/权威媒体)
  定向扫描 + 自动去标识化 + mock 确定性发现集(idDigest 哈希派生)
- **授权探针**: 显式授权留痕(probe_auth 事件); 授权读数视同权威源;
  mock 读数 550-950 映射 L2 因子
- **自愿存证**: 验真不过不入分(孤证留痕 rejected 轨可补源重提)
- **验真三道关**: ①多模态真伪(摆拍/刷单/缺可核验要素) ②跨源交叉
  (单源孤证拒绝; ≥2 独立源或 1 权威源) ③意图推理(表演式向善折减,
  real 轨 LLM)——最低置信度 <0.7 即 unverified 宁缺毋滥
- **因果效应估计**: `净贡献 = max(0, 观测 - 群体基线×1.1)`
  (UEBA 群体基线范式——刷量抬不动群体)

### P2 · 即时修复引擎("放下屠刀, 立地成佛")

- **数学模型**: `ΔV = α × Σ(β_i × V_i × γ(t_i)) × AI验真分`
  - α: 熔断分级决定(general 1.0/severe 0.3/criminal 0 通道关闭)
  - β: 关联度映射表(监管整改 1.5/司法履行 1.5/合同履约 1.5/通用捐款 0.3)
  - γ(t)=e^(-0.1t): 24h 内效率≈30 天后 18 倍(高效激励窗口)
- **即时性**: 违规确认即开通道, 修复计划违规即列(时间近优先), 无等待期
- **三重校验防洗白**: ①天花板(单次回分 ≤ 违规扣分×α) ②针对性 β 加权
  ③验真前置(表演式修复拦截)
- **回分折半**: 修复回的是"信用"不是"资产"(防高频小额刷修复)

### P3 · 信值资产与价值兑换(1 TV = 1 元)

- **准备金发行**: 存证 L3 净贡献折半/修复值折半联动发行(验真通过的
  行为资产即准备金); 熔断态冻结发行——**守法是义务不是资产**
- **兑换销毁**(非转移): 申请即锁定 frozen → 商户核销 → TV 销毁 +
  准备金池等额缩减(通货紧缩: 越兑换越稀缺)
- **信用分↔信值单向转换**: 对接本站信用分(bambooScore)100:1,
  同步扣减+等级重算; TV→信用分方向永久禁止(防套利)
- **防挤兑四件套**: 单日(person 500/org 5000)/单月(5000/50000)/
  商户保证金(核销后释放)/熔断联动(冻结不可兑不可转)
- **账本**: 只追加不可篡改, issue/burn/transfer_in 三向
  (**无 transfer_out——价值红线枚举锁死**), balanceAfter 复式连续

### P4 · 自进化闭环

- **申诉复核**: 7 日窗口/重复拒绝/九因子快照留痕 → upheld(计算正确
  +0.5)/overturned(计算错误 -0.5)
- **翻转语义**: 反向事件入库 + **L1 熔断计数回退** + 分数重算——
  "计算错误"意味着该变动从未发生(非补偿叠加); severe 熔断档案
  翻转后恢复 55 且解除熔断
- **学习回流三连**: collect(已裁决未回流→第28档案 Hedge, appealFed
  幂等)/run(层内护栏)/status(申诉统计+宪法护栏声明)
- **归因报告**(可解释强制): 事件 scoreBefore/scoreAfter 口径;
  mock 确定性模板 + real LLM 润色(LLM 幻觉不进数据)
- **伦理补丁**: beta_update 运行时注入 BETA_MAP(β 安全域 [0.1,2.0]/
  幂等 upsert/版本留痕可审计)

### P5 · 对外服务接口平台(压轴)

- **五类开放 API**(业务语义层; 传输层频控走 44号 Key 网关):
  ①信值查询(字段级脱敏+修复建议) ②兑换核销(幂等键+nonce 原子占位
  防双花+时间窗±300s) ③行为存证(敏感词硬拦截+被拒留痕) ④信用分
  转换(nonce 防重放) ⑤监管审计(四视图只读+自身访问留痕)
- **Key 网关联动**: 开放面发布入 44号台账→双头/QPS/日配额自动接管
  (复用而非重建; 实机验证无 Key 401→双头 200)
- **治理看板**: trust-dashboard 六区块 + 价值红线常驻提示

## 九、执行中发现并修复的缺陷(7 项)

| # | 期 | 缺陷 | 修复 |
|---|-----|------|------|
| 1 | P1 | 存证成功轨 depositId 未持久化(状态查询 404) | 显式落库后并档 |
| 2 | P1 | 授权探针被跨源关误拒(未视同权威源) | probe_authorized 入权威源表 |
| 3 | P3 | 账本 Redis 反序列化数值字段返回字符串 | _parse_row 数值还原 |
| 4 | P4 | 申诉 Redis HSET 布尔值报错 | 序列化补 bool→0/1 分支 |
| 5 | P4 | 申诉更新时 LPUSH 索引重复入队(轮次翻倍) | 新建/更新分离 |
| 6 | P5 | 审计日志 LPUSH dict 报错 | JSON 序列化入队 |
| 7 | P5 | CORS 白名单缺 Key 双头(浏览器直连失败) | 补 4 个头 |

**经验教训**: 双模式(内存/Redis)序列化边界是缺陷高发区——bool/dict/
nested 类型需显式转换; 索引维护(入队/更新)分离是幂等关键。
