## 三、当日 Top 坑复盘（按类）

### A. 工具/环境陷阱（Windows + PowerShell + 生产 Docker）
| 坑 | 现象 | 解法 |
|---|---|---|
| PowerShell 无 heredoc | commit 消息/多行脚本无法内联 | 消息文件化（-F file）后即弃 |
| 嵌套引号剥离 | 带引号参数传到远端被剥 | 本地 python 脚本直连公开端点验证 |
| git commit 组合命令首跑静默失败 | pre-commit hook stderr 触发 NativeCommandError | 重跑一次即成功；以 git log 是否前进为准 |
| PDF 无文字层 | 政策扫描件无法提取 | 改取政府网权威网页版 |

### B. 代码缺陷（当日发现并全部清零）
| 缺陷 | 根因 | 修复 |
|---|---|---|
| Redis str 键 `.decode()` 崩（P2 生产 500） | decode_responses=True 客户端返回 str，本地内存模式测不出 | bytes/str 双兼容三处 |
| 中文 `\b` 失效 | 中文也属 `\w`，词边界正则漏匹配 | lookaround 断言（RT 单号等 9 类槽位） |
| 全角字符漏提 | ＲＴ/Ｌ３ 等 NFKC 另一形 | query 入口统一归一化 |
| 看板 apiBase 默认 localhost | https 页面属混合内容被浏览器直接拦截 | 默认改同源空值 |
| 决策留痕二次 reverse | 服务层已按 id 倒序，前端再 reverse 把最新压底 | 实测数据源结构后去掉 |
| 15 处 limit 截断静默漏算 | 超量后无排序无提示地丢任意 N 条 | 全量扫描修复 |
| 进化参数跨段污染 | 测试段间锚点调权链式影响 | 段间 _reset_evo() |
| A/B 参数 float 崩 | ab_active 存 "A"/"B" 字符串 | 新增 get_params_raw |
| zs.search 被 wine.recommend 截胡 | 注册序 first-match，“送礼”先命中酒类 | 调整注册顺序 |
| FC 注册表与执行器不一致 | TOOL_REGISTRY 声明 readonly 但未入白名单 | 同步 SAFE_READONLY |

### C. 测试盲区与用例自身错误
| 类型 | 案例 | 教训 |
|---|---|---|
| 测试环境盲区 | 本地内存 Redis vs 生产 str 返回 | 双态都要有覆盖；生产验证不可省 |

## 四、方法论沉淀（可复用资产）

1. **空转四要素核对法**：模型"有大脑没手脚"的诊断——四要素（灰度开关/调度器/看板/业务挂接）逐一核对 + 全站 import 扫描区分三类消费（自有路由/DAO 复用/决策消费）。智客"底座被业务用了、大脑没有"即由此发现。
2. **升级四件套复制模式**：智启元首个四件套跑通后，智单、智客各半日复制完成。模式一旦验证，边际成本极低。
3. **边界用例集常驻回归**：四轮审查沉淀 67 例，凡改动即复验，防止修 A 坏 B。
4. **生产验证三板斧**：本地脚本直连公开端点 / redis-cli 查留痕 / docker logs 查调度器启动——三层证据缺一不可。
5. **服务层直调测试**：绕过 auth 既有问题的同时测到真实业务逻辑。
6. **业务挂接三铁律**：fail-soft（AI 故障不阻断业务）+ 建议书永不自动 + 挂接点选低频高价值时刻（退款/升级）。
7. **节奏闭环**：每工作块"检查→修复→测试→部署→生产验证→报告存档→commit"一步不缺，报告即资产。
