## 三、当日 Top 坑复盘（按类）

### A. 工具/环境陷阱（Windows + PowerShell + 生产 Docker）
| 坑 | 现象 | 解法 |
|---|---|---|
| PowerShell 无 heredoc | commit 消息/多行脚本无法内联 | 消息文件化（-F file）后即弃 |
| 嵌套引号剥离 | 带引号参数传到远端被剥（grep 管道符/引号两层转义均失败，验证数字 132 不可信） | **base64 内嵌 bash 终解**：本地写好 bash → base64 → `echo {b64} \| base64 -d \| bash`；轻量则本地 python 脚本直连公开端点 |
| **取证连环误报四课**（⑭ 智能引流检查） | ① curl 不加 `--compressed` 误判"v72 未注入"；② nginx UA 分流下无 UA 取证拿到 PC 站页面；③ redis 扫描用下划线键模式误判"13 表全零"（实际冒号式，智能层有数据）；④ docker exec heredoc 不加 `-i` 静默失败 | ①--compressed ②带目标 UA ③扫描模式从 `_k()` 拼接规则推导 ④`-i` 或 `-c` 单行——**"取证的取证"也要复核** |
| **全局参数改动的隐性消费者**（⑮ 语音故障内因） | LLM_TIMEOUT 15→60（为长文生成修）波及共享该全局的 ASR 快调用——"不影响用户侧快调用"的注释承诺被反向遗漏，降级窗口拖 4 倍 | 全局参数调整需扫全部消费方按快慢分档；快调用一律独立超时档（ASR_HTTP_TIMEOUT 范式） |
| git commit 组合命令首跑静默失败 | pre-commit hook stderr 触发 NativeCommandError | 重跑一次即成功；以 git log 是否前进为准 |
| PDF 无文字层 | 政策扫描件无法提取 | 改取政府网权威网页版 |

## 四、方法论沉淀（可复用资产）

1. **空转四要素核对法**：模型"有大脑没手脚"的诊断——四要素（灰度开关/调度器/看板/业务挂接）逐一核对 + 全站 import 扫描区分三类消费（自有路由/DAO 复用/决策消费）。智客"底座被业务用了、大脑没有"即由此发现。
2. **升级四件套复制模式**：智启元首个四件套跑通后，智单、智客各半日复制完成。模式一旦验证，边际成本极低。
3. **边界用例集常驻回归**：四轮审查沉淀 67 例，凡改动即复验，防止修 A 坏 B。
4. **生产验证三板斧**：本地脚本直连公开端点 / redis-cli 查留痕 / docker logs 查调度器启动——三层证据缺一不可。
5. **服务层直调测试**：绕过 auth 既有问题的同时测到真实业务逻辑。
6. **业务挂接三铁律**：fail-soft（AI 故障不阻断业务）+ 建议书永不自动 + 挂接点选低频高价值时刻（退款/升级）。
7. **节奏闭环**：每工作块"检查→修复→测试→部署→生产验证→报告存档→commit"一步不缺，报告即资产。
8. **立项-止血-治本-固化四段节奏**（晚间新增）——遗留问题从"规避"到"根治+制度化"的标准路径：根因定性（conftest 只在 pytest 生效，直跑不经 conftest）→ P0 最小自举复活存量（189 断言）→ P1 与生产同构（mint_token 真 Bearer 轨）→ P2 规范固化防复发。半日一期，纯测试侧零生产风险。

## 六、一句话总结

**上午"检查发现空转 → 四件套复制 → 生产实证活化"，晚间"立项 → 止血 → 治本 → 固化"，夜间"规划 → 执行"双轮闭环，八次检查升级、偏差三连处置，收尾全自动 E2E 实证 + 规划可执行项当日清零 + Bearer 第三批收官 + 用户报障当日闭环**——
当日最重要的不是 93 个 commit，而是沉淀了五条可复用的治理范式：
把"AI 引擎五层完整却无人消费"的全站共性问题变成四件套活化范式（八次检查升级演化出**六类形态**——空转型/语义修正型/外围修复型/运行判定型/数据在积累+断点修复型/调度补齐型——范式成熟的标志是能识别"不需要升级"，也能识别"升级之外的问题"）；
把"规避了事的遗留问题"当日内升级为立项根治并制度化；
把"规划→执行"跑成当日双轮闭环（第二轮把规划的可执行项当日清零——**复盘自身的遗留项也进入当日销项循环**：#6/#12/#14 三条划销）；
偏差处置三形态（运营裁决/工程升级/证据决策）——偏差不必悬置待决，当日按形态归位；
**取证本身也可能误报**（⑭ 连环四课）——生产取证的每个环节（压缩/分流/键格式/容器 IO）都可能是假的"零"，"取证的取证"要复核。
另记五课：**宣称的语义必须被测试锁定**（智码 shadow）；**交付物上线≠可用**（信值双看板）；**"存在"的运行也要实证**（推广留痕 1950 条）；**配置正确≠链路真实**（LLM_TIMEOUT=15 让 LLM 生成形同虚设——配置全对了链路仍可能是坏的，只有 E2E 真跑一遍才暴露）；**"数字残留"≠"问题残留"**（localhost 扫除验证：生产残留 8 文件必须逐行判定——6 纯注释 + 2 正确三元，运行级为 0；同时红线拦截要尊重而非绕过——溯源闸拦『18岁』是机制在正确工作，处置动作改为 rejected 留痕，规则冲突进遗留而不是 bypass）。
