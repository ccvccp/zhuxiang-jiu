## 〇、总览与当前状态

| 机制 | 作用 | 当前状态 | 放量改动 |
|---|---|---|---|
| **E2 设备指纹闸** | 同设备注册 ≥3 个号, 新绑定不计业绩不发分(防批量注册) | 关 | 仅 settings 一个开关, **即时生效** |
| **E3 Escrow 延迟结算** | 引进积分从"注册即发"改"7 天活跃后发"(防僵尸号套分) | 关 | settings 开关 + 调度器环境变量(两步) |
| **E4 阶梯奖励**(已生效) | 月引进 ≥50/≥200 档升 400/500 分 | **默认 50/200 档运行中** | 见 E4 指南 |
| **E4 速率检查项**(已运行) | 24h 绑定速率 >50/>100 三态监测 | **随巡检 shadow 留痕** | 告警开通见 E4 指南 §2.3 |

**放量后行为变化对照**:

| 场景 | 现在(关) | 放量后 |
|---|---|---|
| 同设备第 3 个号绑定 | 照常发 300 分 | 绑定成功但**不发分**(关系标 invalid) |
| 同设备第 6 个号绑定 | 同上 | 不发分 + **管理员收到告警站内信** |

| 新会员 7 天无任何行为 | 已发不追 | **作废不发放**(零成本拦截) |
| 新人礼 100 分/分享 20 分 | 即时 | **不变**(仍即时, 小额拉新体验优先) |
| 推荐人当月达 E4 档位(≥50/≥200) | 该笔按档 400/500 即时发 | 该笔按档 400/500 **进观察期**(escrow 按当月档位定格) |

## 一、E2 设备指纹闸放量

### 1.1 何时放量(触发条件, 任一即启)

- IBMS 巡检出现 `growth_anomalies` WARN/FAIL(24h 绑定速率异常)
- 管理后台关系审计发现: 短期新增绑定的会员手机号连号/昵称规律
- E2 告警站内信送达(同设备 ≥6 号, 系统已自动提示)
- 或: 预防性放量(拉新活动大促前, 提前防批量注册)

### 1.2 前置检查(放量前确认)

```
1. 确认注册映射已在积累: 生产已挂接(2026-10-01 起), 无需操作
2. 看当前设备聚集分布(如有怀疑对象):
   docker exec zhuxiang-backend-1 python -c "..."  # 见 §1.4 观测
3. 评估误杀面: 正常家庭/公司共用设备多账号场景——本闸为"降权
   不封号"(绑定照常), 最坏影响 = 该推荐人少算业绩, 可人工补发
```

### 1.3 放量操作(一步, 即时生效)

```
curl -X PUT -H "Authorization: Bearer <TOKEN>" -H "X-Role: admin" \
     -H "Content-Type: application/json" \
     -d '{"deviceGateEnabled": true}' \
     https://zxjiu.com/api/promotion/admin/settings
```

返回确认 `settings.deviceGateEnabled: true` 即生效——**新绑定立即按新规则**, 已发放的历史不受影响。

### 1.4 放量后验证与观测

| 项 | 操作 | 预期 |
|---|---|---|
| 开关生效 | `GET /api/promotion/admin/settings` | deviceGateEnabled: true |
| 闸门命中(可选实测) | 容器内造同设备第 3 个号绑定 | 日志 `promo_device_gate ... cluster=3 (counted→False)` |
| 告警链路 | 同设备达 6 号时 | 管理员站内信"设备指纹聚集"(同设备 24h 去重) |
| 日常监控 | IBMS 巡检 `growth_anomalies` 项随小时级自动巡检留痕 | PASS/WARN/FAIL 三态可查 `GET /api/ibms/patrol/history` |

### 1.5 回退(一键)

```
curl -X PUT ... -d '{"deviceGateEnabled": false}' ...
```
即时恢复"不拦"状态。**误杀处置**: 被降权的绑定(关系 invalid)可人工恢复——`POST /api/promotion/admin/relations/{invitee_id}/invalidate`(再调一次即恢复 valid), 少发的积分用补发通道。

### 1.6 注意事项

- 指纹口径为浏览器特征摘要(不含个人信息), 换浏览器/清除数据会视为新设备——**宁漏不误**设计, 误杀率低
- 同一 WiFi 不同手机**不受影响**(按设备不按 IP)
- 闸门只影响"新绑定计业绩", 永不封号、不影响登录购物

## 二、E3 Escrow 延迟结算放量

### 2.1 何时放量

- 出现僵尸号迹象: 新注册会员批量绑定后**零回访零订单**(IBMS growth_anomalies 或人工审计发现)
- 引进积分月支出与真实活跃增长明显背离
- 或: 引荐量大增前主动加固(接受 7 天到账延迟的成本)

**成本提示**: 放量后推荐人到账延迟 7 天——头部推荐人可能有反馈, 建议提前站内信/公告告知(系统已自动发"观察期"预期管理站内信)。

### 2.2 放量操作(两步)

**第一步: 业务开关**(即时生效, 可只开这个+手动结算)

```
curl -X PUT -H "Authorization: Bearer <TOKEN>" -H "X-Role: admin" \
     -H "Content-Type: application/json" \
     -d '{"referralEscrowEnabled": true}' \
     https://zxjiu.com/api/promotion/admin/settings
```

**第二步: 调度器开关**(自动结算, 需改环境变量并重启 backend)

```
ssh root@47.236.61.117
printf '\n# 80号 v2-E3 Escrow 自动结算调度器\nGROWTH_ESCROW_AUTO=on\n' >> /opt/zhuxiang/.env
cd /opt/zhuxiang/zhuxiang-jiu && docker compose up -d backend   # 重启加载
```

> 也可调周期(默认每小时): `GROWTH_ESCROW_INTERVAL=3600`(下限 300)
> **只开第一步不开第二步也可行**: 用手动结算端点跑(见 §2.4), 适合先小流量试点

### 2.3 语义边界(放量前必读)

| 项 | 语义 |
|---|---|
| 开启前已发的 300 分 | 不追回, 照旧 |
| 开启后新绑定 | 写 escrow 记录(pending), 不即时发分 |
| **关闭后存量 pending** | **照常被结算**(不弃单)——关闭只停新建 |
| 观察期天数 | 默认 7 天, `escrowDays` 可调(≥1) |
| 达标条件(任一) | 新会员**注册后回访登录过** 或 **下过首笔订单** |
| 熔断 | 近 7 天解冻率 < 90% 连续 3 轮 → **系统自动关闭 escrow** + 管理员告警站内信(回落即时发放, 恢复需人工重开) |

### 2.4 放量后验证与观测

| 项 | 操作 | 预期 |
|---|---|---|
| 开关生效 | `GET /api/promotion/admin/settings` | referralEscrowEnabled: true |
| escrow 建立 | 新测试绑定后 `GET /api/promotion/admin/escrows?state=pending` | 新记录(points=当前档位分, deadline=+7d) |
| 会员可见 | `GET /api/promotion/my/funnel`(该会员) | totals **pendingPoints** 出现观察中额度 |
| 自动结算 | 容器日志 `escrow_settled scanned=... unlocked=... forfeited=...`(每小时) | 双态结算留痕 |
| 手动结算(兜底) | `POST /api/promotion/admin/escrows/settle` | 幂等, 只结算到期 pending |
| 解冻率监控 | `GET /api/promotion/admin/escrows` → stats | unlocked/(unlocked+forfeited) ≥ 90% 为健康 |
| 单条强制解冻(误作废申诉) | `POST /api/promotion/admin/escrows/{id}/force-unlock` | 直接发放(谨慎项) |

### 2.5 回退

| 场景 | 操作 |
|---|---|
| 临时回即时发放 | `PUT settings {"referralEscrowEnabled": false}`——存量 pending 照常结算完 |
| 连调度器也停 | `.env` 删 `GROWTH_ESCROW_AUTO` 行 → 重启 backend |
| 误作废单条 | force-unlock(§2.4) + 必要时积分补发 |

### 2.6 注意事项

- **熔断是自动的**: 若解冻率跌破 90% 连续 3 轮, 系统自己关——收到"Escrow 熔断"告警后先查引进质量再决定是否重开
- 新人礼/分享积分**不受影响**(始终即时)
- 阶梯档位与 escrow 兼容: escrow 记录建立时按当月档位定格分值

## 三、E4 上线后的组合场景(v2 四组件联动)

E4 阶梯(已生效)与速率检查项(已运行)加入后, E2/E3 放量的组合语义:

### 3.1 组合矩阵(同一笔绑定在各开关态下的结果)

| E2 闸 | E3 escrow | E4 档位 | 同一正常新客绑定(推荐人当月第 50 人) |
|---|---|---|---|
| 关 | 关 | 400 档 | 即时发 400 |
| 关 | 开 | 400 档 | 观察期 7 天 → 达标发 **400**(escrow 按档定格) |
| 开(该设备 <3 号) | 开 | 400 档 | 同上(闸门不拦正常设备) |
| 开(该设备 ≥3 号) | 任意 | 任意 | **绑定成功但不计业绩**: 不发分、不建 escrow、**不进当月档位计数**(invalid 关系不计 team) |

> 关键语义: E2 降权的绑定被档位计数排除——刷量号**不会推高推荐人档位** (防"刷 50 个僵尸号把自己刷到精英档"的套利路径)。

### 3.2 速率检查项(E4)与 E2/E3 的联动

```
growth_anomalies 检查项(随巡检 shadow 留痕, 转 on 后触达)
   ├─ WARN(某推荐人 24h 新增 >50) → 排查依据: §1.4 关系审计
   │     └─ 确认批量注册 → 开 E2(拦截后续) + 作废可疑关系 + E1 追回
   └─ FAIL(>100, 团伙嫌疑) → 同上, 处置升级(运营手册 §4.2 组合拳)
```

**联动顺序铁律**: E2 拦截 > E3 延迟 > E4 告警——异常流量先被闸门拦(E2), 漏网的被观察期兜底(E3), 全链路由巡检监测(E4 检查项)。告警开通(§E4 指南 2.3)建议晚于 E2 放量。

### 3.3 三分量叠加的完整防护链(全开后)

```
批量注册团伙: 同设备 ≥3 号 → E2 闸降权(不发分/不建 escrow/不进档位)
僵尸号单点:   新设备注册但 7 天不活跃 → E3 作废(零积分成本)
速率异常:     24h >50/>100 → E4 检查项三态留痕(转 on 后告警)
已发漏网:     E1 追回端点(负流水+同源幂等+欠口)
组合效果:     刷单成本 = 注册手机号成本, 积分收益 ≈ 0
```

## 四、放量节奏建议(四组件版)

```
第 0 天    E2/E3 关, E4 阶梯 50/200 生效, 检查项 shadow 留痕(现状)
  ↓ 触发条件: 速率检查项数据异常 / 设备聚集迹象 / 人工审计
第 1 步    开 E2(低感知) —— 检查项数据开始反映"拦截后"基线
  ↓ 观察 3-7 天
第 2 步    E3 第一步(settings 开关 + 手动结算试点) —— 阶梯高档笔同步进观察期
  ↓ 观察: 解冻率 ≥90%? 推荐人反馈?
第 3 步    E3 第二步(GROWTH_ESCROW_AUTO=on 常态化)
  ↓ 74号 IBMS 观察期满(稳定 4 周 + WARN 闭环率 ≥80%)
第 4 步    IBMS 整体转 on(检查项告警触达, 全自动监控)
```

**回退优先级**: 任何异常先关 settings 开关(E2/E3 即时), 再排查——四组件互不依赖, 可独立开关独立回退。

## 五、应急速查

| 症状 | 判定 | 动作 |
|---|---|---|
| 管理员收到"设备指纹聚集"站内信 | E2 告警(同设备 ≥6 号) | 审计该设备绑定关系, 可疑则作废关系+追回积分 |
| 管理员收到"Escrow 熔断"站内信 | E3 解冻率连续跌破 90% | 系统已自动回落; 查引进质量(哪些渠道来的新客不活跃) |
| 会员反馈"推荐了没到账" | E3 观察期内(7 天)属正常 | 引导看站内信"观察期"通知; 到期自动结算 |
| 会员反馈"到账分比预期少" | E2 降权或档位差异 | 查关系 status + 当月档位; 误杀走恢复+补发 |
| 巡检 growth_anomalies WARN/FAIL | 24h 绑定速率异常 | 按 §3.2 联动路径: 关系审计 → E2 拦截 + 处置组合拳 |
| 会员问"观察期到账是 400 不是 300" | E4 档位 × E3 组合(正常) | escrow 按建档时档位定格, 查当月引进数 |
