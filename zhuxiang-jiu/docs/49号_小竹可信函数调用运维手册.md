## 二、看板⑦FC 分区判读（49号P4 新增）

单次 `GET /api/xiaozhu/dashboard` 聚合（fail-soft：单区块异常只降级不阻断）。

| 指标 | 判读口径 |
|------|---------|
| FC 调用量（calls） | 审计流水总数——与 byTool 分解对照判断工具热度 |
| 失败降级率（fallbackRate） | fallback/总调用。**日常应 <10%**；>30% 红色告警（数据源波动或攻击面异常） |
| 成本合计（privacyCostTotal） | 审计流水 privacyCost 累计（注册表静态值口径） |
| 预算账户/当日累计消耗 | 会员预算账户数与 usedToday 合计——账实对账参考 |
| token 拒绝分布（consentRejects） | **五类计数（进程级，重启归零）**：notFound(伪造)/expired(超时)/used(重放)/crossUser(盗用)/actionMismatch(劫持) |

**预警口径**：
- `used`/`crossUser`/`actionMismatch` 任一**骤升**＝凭证攻击面预警——立即执行 §四 红队复跑核对 breached 是否为 0，并抽查 §三 审计流水 error 字段定位来源会员；
- `expired` 持续偏高＝双因子流程超时体验问题（首次失败自动重新引导已内建，无需干预）；
- `notFound` 偶发＝正常噪声（垃圾 token 输入）；持续高＝批量伪造扫描。

## 三、日常巡检操作

```bash
# 1. 健康与看板快照（每工作日）
curl http://127.0.0.2:8000/api/decision/health
curl -H "X-Role: admin" http://127.0.0.2:8000/api/xiaozhu/dashboard
# 关注: zoneErrors 是否为空; ⑦fallbackRate; consentRejects 分布

# 2. FC 审计流水（每周或事件驱动）
curl -H "X-Role: admin" "http://127.0.0.2:8000/api/xiaozhu/fc/audit?limit=100"
# byKind/byTool 汇总 + records 明细; error 字段=拒绝细节
# (响应话术不泄露拒绝原因——细节只在审计, 管理端可溯)

# 3. 会员预算客诉排查
curl -H "X-Member-Id: <会员号>" http://127.0.0.2:8000/api/xiaozhu/privacy/budget
# 返回余额/偏好/近 7 日消耗; 偏好可自助调整(PUT preferences)
```

## 四、红队复跑（上线检查清单第 5 项·持续防护）

```bash
# 方式一: 端点直调(admin)
curl -X POST -H "X-Role: admin" http://127.0.0.2:8000/api/xiaozhu/fc/redteam

# 方式二: 看板「红队复跑」按钮(结果即时反馈)
```

**执行语义**：四类攻击向量 14 用例**跑真网关**（非 mock——每次拒绝落审计流水，证据可溯）。

**结果判读**：
| 字段 | 含义 |
|------|------|
| breached=0 | 全部阻断 ✅ 正常 |
| breached>0 | **上线阻断**——看板红色告警列 caseId；修复后重跑至 0 方可放过版本 |

**建议频率**：① 每次后端发版后；② consentRejects 分布骤升时；③ 每月例行。

**注意**：红队使用 4901-4915 专用号段（自动建档案+信用分补足 5000+每轮 nonce 载荷差异化）——跨轮复跑幂等，不污染真实会员数据。

## 五、consent_token 生命周期（P1）

```
签发 ──60s──▶ 核销(一次性) ──▶ 直执行窗口内有效
  │                            │
  ├─ 超时 → expired 拒绝       ├─ 重放 → used 拒绝
  ├─ 盗用 → crossUser 拒绝     └─ 劫持 → actionMismatch 拒绝
  └─ 伪造 → notFound 拒绝
```

- 双因子构成：语音确认词（意图证据）+ 屏幕码（身份核销）——**语音念码不算**（48号红线不变）；
- 声纹为确定性哈希代理（`speaker:{memberId}`）——真声纹 KMS 集成前不作身份凭证，仅跨用户复用校验；
- 单容器口径：token 池为进程内存态（重启清空——TTL 60s 天然短窗，影响可忽略）；多副本部署须迁 Redis（外部待办）。

## 六、隐私预算运维（P2）

| 事项 | 口径 |
|------|------|
| 默认限额 | 1.0 × 偏好(0.5-2.0)——**只按会员自主偏好分级，与信值等级无关**（公平性红线） |
| 日切 | UTC 自然日重置（usedToday 清零，历史入史 7 日） |
| 只读工具 | 零成本**永不降级**（cost=0 不检查不扣减——知情权/兜底出口/帮助零成本） |
| 超限表现 | 429 语义话术："隐私预算不足(剩余 X, 需 Y)——请在设置中调整隐私偏好或明日再试" |
| 客诉处理 | 引导自查 GET privacy/budget；偏好调整走 PUT privacy/preferences（区间 0.5-2.0，超界 409） |

## 七、故障排查

| 现象 | 排查路径 |
|------|---------|
| 看板⑦FC 分区显示"区块异常" | fail-soft 已隔离——其余区块照常；查后端日志 `voice48_dashboard_zone_skip fc`；多为 Redis 抖动，刷新即愈 |
| fallbackRate 持续高 | 拉 fc/audit 看 records.error 分布：`隐私预算不足`多→预算策略评估；token 拒绝多→按 §二 预警口径处置 |
| 会员反馈"兑换失败" | ① 查绑定（"绑定信值档案 N"）；② 查信用分余额（45号 credit）；③ 查预算余额；④ 查审计 kind=fallback 的 error 字段定位 |
| 红队端点 403 | 检查 X-Role: admin 头 |
| 红队 breached>0 | 按看板列出的 caseId 对照 [49号_完整交付总结文档.md](49号_完整交付总结文档.md) §三 P4 防御矩阵定位防线；**先修复后重跑，禁止带病上线** |

## 九、运维红线（摘要）

1. 红队 breached>0 不得上线（检查清单第 5 项）；
2. 预算绝不与信值等级挂钩（公平性红线——46号桥接审计口径）；
3. 审计六字段缺一视为审计故障（流水只追加不修改）；
4. 拒绝细节不进用户响应（只落审计 error 字段——防探测）；
5. 双开关 off 是交付默认态（off 直通铁律）。
