## 一、变更总览

| 维度 | 原市级网店 | 新县（区）网店 |
|---|---|---|
| 定位 | 市级城市独占经营 | **本站为总店开设之分店，网站备案即为分店备案** |
| 经营区域 | 地级市地图范围（344 市） | **县（区）级地图范围（3028 区县，一区县一店）** |
| 申请材料 | 营业执照 + 食品卫生许可证（平台材料审核） | **身份证（GB 11643-1999 校验码+出生日期全验）+ 确认签名** |
| 开业流程 | 平台审核后开业 | **轻审核：身份证+签名+保证金预存后平台一键"确认开业"（防恶意注册），可驳回** |
| 保证金 | 无 | **钱包预存 ¥1000，一年期锁定，不可提前取现** |
| 保证金结算 | — | 满一年按年任务完成度退还（80%→退800扣200；≥100% 全退）；中途取消按已运营期折算；驳回全额退 |
| 年度任务 | 月进货 ¥9000（年化 10.8 万） | **年进货额 ¥5 万**（月均 4167） |
| 月度考核线 | 进货 9000 / 销售 5000 | **进货 4167 / 销售 2315**（等比系数 ≈0.463） |
| 进货折扣 | 月销三档 70/80/90 折 | **三档折扣不变**（>4167→70 / 2315-4167→80 / <2315→90） |
| 连续不达标/冷静期 | 3 月取消 / 90 天 | 不变（机制保留） |
| 推广定位 | 城市独占经营 | **店主朋友圈推广 + 口碑销售** |

**已确认口径**（用户四项裁决）：轻审核（保留一键确认）；按比例扣（完成80%扣200退800）；年进货额口径；沿用三档折扣。

## 二、工程化设计

### 2.1 区县数据（新增 services/citystore_districts.py）

- **数据源**：modood/Administrative-divisions-of-China（jsdelivr CDN 拉取 pca-code.json，省→地级(4位码)→区县(6位码)三级树），生成工具 `scripts/gen_citystore_districts.py` 留档
- **结构**：`DISTRICTS: dict[市码, list[(区县码, 区县名)]]` + `ALL_DISTRICTS` 扁平化（省市县四级信息）
- **口径**：直辖市（京津沪渝）所有地级层区县并挂 xx0100 单市条目（含重庆 5002 县层 12 县）；省直辖县级市（济源 419001/仙桃 429004/潜江 429005/天门 429006）自身单条目（码=市码重合白名单）；港澳台三市不收录（apply 409 哨兵）；神农架/海南 4690 系/新疆兵团 6590 系跳过留档（与市级口径一致）
- **自检**（导入即验 5 不变量）：区县码全局唯一 / 挂靠键必在 344 市册 / 前 4 位规则（直辖市+白名单例外）/ 总量 ≥2800 / 挂靠市数=341
- **顺带修正**：regions.py 黑河（231200→**231100**）/绥化（231300→**231200**）区划码笔误——数据对齐时发现，属历史 bug 修复

### 2.2 apply 申请链改造（citystore_service.py）

```
校验链新序: SVIP(L5) → 区县区划册校验(名码规整, 省市区县四级推导)
→ 上级市店拦截(存量市级网店覆盖的地级市, 其下区县不再开放)
→ 身份证校验(18位/出生日期段/MOD 11-2 校验码) + 姓名校验(2-30位)
→ 签名确认(必须 True)
→ 保证金前置(钱包 active 且 balance ≥ 1000, 锁外快速失败)
→ 会员查重 → 90 天冷静期 → 区县独占(一区县一店)
→ 保证金锁定(钱包扣款 1000 → margin 记录) → pending
```

- **锁序单向嵌套**（无死锁）：`citystore:apply:{memberId}` → `citystore:city:{districtCode}` → `wallet:{userId}`
- **storeCode 沿用** `CS-{区县码}-{3位序号}`（与存量 CS-{市码}-{序号} 同构无冲突，序号全局自增）
- **独占索引修复**（实测抓出）：save_store 独占键由 cityCode 改为 **districtCode 优先**——否则区县店误占上级市码，同市其他区县全被误拦
- **移除字段**：businessLicense/foodLicense/taxRegNo（存量店 JSON 多余键不清洗，详情原样返回兼容）

### 2.3 保证金子系统（独立实体，复用钱包资金原语）

**方案裁定**：不复用 wallet deposit（DEPOSIT_TIERS 收益/LPR/奖品语义污染 + early_settle 全局放行与"不可提前取"矛盾）；不进 frozenAmount（提现在途语义）——新建 `city_store_margins` 实体：

```
marginNo=CD+YYYYMMDD+seq / userId / storeCode / amount=1000 / annualTarget=50000
startDate(确认开业补) / endDate(=startDate+365天)
status: locked → settled
settledAt / refundAmount / deductedAmount / completionRate / annualPurchased
settleReason: expired | cancelled | rejected
```

**状态机**：
```
apply 成功 ──锁定──> locked(endDate 空)
    ├─ 平台驳回(未开业) ──> settled(全额 1000, reason=rejected)
    ├─ 确认开业 ──> locked(补 startDate/endDate=+365天)
    ├─ 满一年 ──> settled(按年任务完成度, reason=expired)
    └─ 中途取消(黄牌3月/管理端) ──> settled(按已运营期折算, reason=cancelled)
```

**结算公式**：
- 到期：`rate = min(1, 年进货额/50000)`，`refund = round(1000×rate, 2)`——完成 80% 退 800 扣 200；≥100% 全退
- 中途取消：`rate = min(1, 年进货额 / (50000×已运营天数/365))`——干满进度全退 / 躺平按比例
- 年进货统计源 = city_store_orders（与月度考核同源同口径，`sum_purchase_between` 日期范围方法）

**资金路径**（全走 wallet repo 原语）：锁定 `add_balance(-1000)` 流水 type `citystore_margin_lock`(OUT)；退还/结算 `add_balance(+refund)` 流水 type `citystore_margin_settle`(IN)。**wallet_service/wallet_repository/wallet_routes 三件零改动**——保证金端点全部挂 citystore_routes（无 @_decision 门控），天然落资金红线豁免面（WALLET_MODE=off 照常退还结算，存量资金退出零影响铁律）。

**并发安全**：`citystore:margin:{marginNo}` 锁内双重检查（防调度器与手动结算并发双重退款）。

**调度**：`citystore_assessment_scheduler.py` 小时级循环追加 `run_margin_settlement()`（幂等扫描 locked 且 endDate≤today——到期日按各店开业日全年分布，不能只靠月初窗口）。

### 2.4 轻审核流与联动

- `audit_store` 语义改造：approved=True = **确认开业**（pending→operating + margin 补 startDate/endDate）；approved=False = 驳回（pending→cancelled + 保证金全额退 rejected，未运营不触发冷静期）
- `update_status` 取消路径 + `run_assessment` 连续 3 月不达标取消路径 → 均联动保证金中途结算（cancelled）
- **AI 门同步**：`ai_enforcement_governance.py` 考核快照硬编码 9000/5000 改为 4167/2315（防 enforce 口径漂移）

### 2.5 decide_order_entry 兼容（下单入口）

- adcode（县级码）→ **先精确命中区县店** → miss 后前 4 位+"00"转市级码回退存量市店（原逻辑降级为回退分支）
- cityCode（市级码）→ 存量市店命中（区县店不占市码）
- cityName 匹配增强 districtName 优先比对（前端定位传区县名场景）

## 八、运营机制与回滚

**运营节奏**：申请（身份证+签名+保证金锁 1000）→ 平台确认开业（管理端 POST /{code}/audit approved=true，保证金起算一年）→ 月度考核（4167/2315 双线）→ 年度保证金结算（调度器每小时轮询到期 margin，或管理端 POST /{code}/margin/settle 手动兜底）。

**关键端点**（17 个）：
- 用户端：POST apply / GET districts/available / GET cities/available / GET list / GET {code} / GET+POST {code}/orders / GET {code}/assessment/{month} / GET {code}/assessments / **GET {code}/margin**（保证金+年任务实时进度）
- 管理端：GET pending / GET stats / POST {code}/audit（确认开业/驳回）/ PUT {code}/status / POST {code}/assessment / **POST {code}/margin/settle**（兜底结算，WALLET_MODE 豁免面）
- 公开：POST order-entry/decide

**回滚路径**：
- 后端：`git revert 7736395` 单步 + 重部署
- 前端：恢复 dist.bak-zjcity6 三文件（index.html/app.zjcity6.js/3456.zjcity6.js）
- 保证金存量：locked 记录可通过管理端 settle 手动结算退出（资金红线豁免面）
