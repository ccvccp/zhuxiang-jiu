## 二、看板六区块判读（dashboard）

单次 `GET /api/xiaozhu/dashboard` 聚合（fail-soft：单区块异常
只降级不阻断，`zoneErrors` 列出降级区块）。

| 区块 | 指标 | 判读口径 |
|------|------|---------|
| ①使用总览 | 会话量/指令量/直达率/语音占比 | **直达率=指令命中/(指令+兜底)**——低于 70% 看②；语音占比是渠道分布不是健康指标（文本同链是键盘兜底/无障碍入口） |
| ②指令命中 | action 排行/兜底率 | **兜底率是意图质量北斗星**——高兜底=指令集缺覆盖，配合⑤topPhrases 补 pattern |
| ③高敏台账 | 发放/核销/码错/过期/冷静期/幂等/通过率 | 通过率低→码错高：屏幕码体验问题；冷静期拦截多→疑似异常高频操作，结合 47号画像核对 |
| ④积分账本 | 发放/兑换/余额/持分/kind 分解 | 兑换(redeem)应有 45号 deposit 验真记录一一对应；余额=发放−兑换（守恒校验） |
| ⑤共创队列 | pending 待审/失败聚类 topPhrases | 待审积压→及时审核（会员在等 +100）；topPhrases 高频出现→候选新指令 |
| ⑥治理桥接 | voice_L{N} 等级分组直达率预览 | 等级间差异>20% 属公平性疑点→执行桥接让 46号 flagged 复核 |

## 三、日常巡检操作

```bash
# 1. 健康与看板快照（每工作日）
curl http://127.0.0.2:8000/api/decision/health
curl -H "X-Role: admin" http://127.0.0.2:8000/api/xiaozhu/dashboard
# 关注: zoneErrors 是否为空; ①直达率; ②兜底率; ③冷静期计数

# 2. 失败聚类（每周——指令集进化依据）
curl -H "X-Role: admin" http://127.0.0.2:8000/api/xiaozhu/failures
# topPhrases 反复出现的短语 → 评估新增指令 pattern(走开发流程)
# 注意: rawText 已 PII 脱敏, 可安全查阅

# 3. 共创队列（每日——会员在等审核）
curl -H "X-Role: admin" http://127.0.0.2:8000/api/xiaozhu/commands/custom
# 看板⑤一键上架/驳回, 或:
curl -X POST -H "X-Role: admin" -H "Content-Type: application/json" \
  -d '{"approve": true, "note": "高频短语"}' \
  http://127.0.0.2:8000/api/xiaozhu/commands/custom/{cmdId}/review
# 上架: 贡献者 +100 积分; 短语全局生效(track=custom)
# 审核红线: action 只能是白名单(提交时已校验)——共创映射不新建执行器

# 4. 公平性桥接（每月——防语音层歧视）
curl -X POST -H "X-Role: admin" \
  http://127.0.0.2:8000/api/xiaozhu/dashboard/fairness-bridge
# 回包 groups=voice_L1... → 46号侧审计:
curl -X POST -H "X-Role: admin" -H "Content-Type: application/json" \
  -d '{"scorerId": "xiaozhu_voice"}' \
  http://127.0.0.2:8000/api/ai-gov/fairness/audit
# flagged=true → 人工复核(等级间直达率差异>20%——查指令 pattern
# 是否对低等级会员常用语覆盖不足; flagged 仅标记不下结论)
```

## 四、主动关怀调度（默认 off）

```bash
# 默认零影响态: XIAOZHU_PROACTIVE_MODE 未设或 off
# 手动触发(容器内同链路):
curl -X POST -H "X-Role: admin" \
  http://127.0.0.2:8000/api/xiaozhu/proactive/scan
# 回包 skipped=true 即默认态(正常)

# 开启日度自动(docker-compose.yml):
#   XIAOZHU_PROACTIVE_MODE=${XIAOZHU_PROACTIVE_MODE:-off}
# → .env 设 on → docker compose up -d backend
# 频控口径: 同一会员同类型关怀 7 天间隔; 全局日上限;
# 候选=47号 watched/restricted 档 + 45号修复窗口 × 活跃时段
# 红线: 关怀不是营销——只推修复引导不推商品
```

## 五、会员侧常见问题处置

| 症状 | 原因 | 处置 |
|------|------|------|
| "请以「小竹」开头唤我" | 新会话首轮未唤醒 | 正常（防误触发红线）；唤醒一次后 5 分钟免唤醒 |
| "10 秒内同指令已受理" | 幂等去重 | 正常（防重复执行）；10s 后可重发 |
| "短时间内多次高风险操作已触发冷静期" | 10 分钟 ≥3 次高敏确认 | 正常（安全红线）；引导改用页面操作 |
| "确认码错误(剩余 N 次机会)" | 屏幕码输错 | 3 次作废须重新发起（防爆破） |
| "尚未绑定居值档案" | 兑换/信值指令无绑定 | 引导说"绑定信值档案 N"或 POST /bindings |
| "积分不足(需 100 起兑)" | 兑换门槛 | 100 积分=1 兑换单位；走 deposit 验真后到账 |
| 兑换未到账 | deposit 验真未过 | 查 45号 deposit 记录与 47号风控命中(未过验真不扣积分) |

## 七、故障排查

| 现象 | 排查 |
|------|------|
| 看板某区块 error | fail-soft 设计——看 zoneErrors; 该区块数据源异常不阻断其他区块; 常见于 Redis 连接抖动, 先查容器健康 |
| 台账③计数清零 | 正常——executor 进程级计数, 容器重启归零(与令牌同口径); 需持久化属多副本迁移待办 |
| 兑换 409 积分不足 | 查 GET /points 余额; 兑换单位 100 分 |
| 令牌核销 404 | TTL 120s 过期或已作废/已核销（一次性）——重新发起指令 |
| LLM 轨未生效 | 默认 off 属预期；XIAOZHU_LLM_MODE=on 需 LLM_API_KEY |
| ASR 转写失败 | 35号链路无 key 时结构化兜底属预期降级 |
| 桥接 404 档案未入册 | 首次桥接自动 side-door 入册; 若报错查 ai46 治理台账 Redis 连接 |

## 八、运维节奏与红线速查

| 节奏 | 动作 |
|------|------|
| 每工作日 | 看板快照(zoneErrors/直达率/兜底率)+共创审核 |
| 每周 | 失败聚类 topPhrases→指令集进化评估 |
| 每月 | 公平性桥接+46号审计 flagged 复核 |

**六条红线速查**：语音仅可选入口（不用不扣分）｜高敏必须
屏幕码（念码不算）｜音频即转即删+PII mask+一键清除｜LLM
不产数字｜积分独立账本入信值走 deposit 验真｜默认零影响
（LLM 轨/关怀 off, 46号 28 档案口径不变）。
