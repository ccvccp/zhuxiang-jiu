# 57号·AI智能知识库模块实施计划

> 定位：本站智能大模型的**认知基座与信任源头**——"合规为盾，种子为核，信值为尺，进化为魂"
> 范式：趋势感知 → 三重合规鉴别 → 认知种子工坊 → 角色植入学习 × 信值回流闭环（Value-UEBA 体系下知识从"被动存储"升级为"主动认知引擎"）
> 版本：v1.0（2026-09-06）

---

## 〇、参照方案的本站化优化升级说明

参照方案（用户输入）的四大需求（自动获取/合规鉴别/种子植入/多模态支持）全量继承，工程落地做**六项本站化升级**：

| 参照方案要点 | 本站化升级（落地口径） |
|---|---|
| 趋势感知+主动捕获（多维信号融合+缺口诊断） | **缺口信号封闭注册表 GAP_SIGNAL_REGISTRY**（52号 registry 范式）：业务侧（既有 knowledge_* 缺口队列+搜索无结果埋点）+技术侧（46号三检测器+44号池对齐）+用户侧（52号五维+55号六指标）——**全站既有观测面纯读取**（零侵入），启动自检 RuntimeError 宪法级；缺口诊断=信号×权重→《知识补全优先级清单》（高优先级定向采集/低优先级观察队列） |
| 三重合规鉴别中心（版权+隐私+内容安全） | **确定性规则轨三关**（56号信值沙箱范式）：①版权关（采集源白名单+内容哈希指纹去重+授权协议标注）②隐私关（PII 模式扫描+自动脱敏/合成替换+49号预算计量——预算不足暂停采集）③内容安全关（敏感模式黑名单+风险分级——高风险转人工复审）；合规指纹=sha256(内容+来源+时间戳)+状态码；**未经鉴别的原始资源仅存沙箱隔离态（kb57_resources.quarantined），严禁暴露终端用户**；LLM real 轨仅 assist 润色鉴别报告，不进判定链 |
| 种子化植入（可插拔/可验证/带信值属性的认知种子） | **种子结构规范+KNOWLEDGE_REASON 注释即证据**（56号 VALUE_REASON 范式）：`SEED_TYPES` 封闭枚举（text/image/video/qa_pair/workflow）——首期 text+qa_pair 全落地，image/video 带 mediaRef 引用（/media 静态资源）+多模态对齐元数据（摘要/关键帧标记/转写稿）；版本化共存+A/B 旧版降权不删除；每颗种子强制携带合规指纹+信值标签（无指纹不入库铁律） |
| 智能提醒与种子入口（角色画像+情境触发+播放器+路径编排） | **确定性角色匹配+API 层情境触发**（54号规则轨范式）：角色（群众/社工/开发者）×场景（办事/学习/故障）×学习记录三元组映射推送策略——mock 确定性模板，LLM 润色仅 assist 态；情境触发先落 API 埋点（搜索无结果/操作卡点上报端点）而非前端弹窗；统一种子入口=会员面三端点（feed 推荐/view 内容带合规指纹校验/feedback 反馈）；学习路径=微课程序列+完成信值积分（45号联动） |
| 运营效果度量（五指标） | **四区看板+第32档案回流**：知识覆盖率/合规通过率/种子有效率/学习转化率/信值增益总量五指标进看板"度量区"；种子真值反馈六类信号回流44号第32档案（knowledge_orchestration，batch16）Hedge 学习 |
| 落地路径四期（基础→智能→全域→生态） | **开关矩阵三级灰度**：`KB57_MODE = off / shadow / assist`（默认 off）——shadow=观察学习期（仅缺口诊断+采集留痕）、assist=辅助生产期（鉴别+种子工坊+植入开放）；生态开放期（第三方种子 API+贡献者激励）列远期外部待办 |

**核心原则（继承+强化）**：知识库的成功不在于收录了多少数据，而在于是否让**正确的知识在正确的时刻以正确的方式抵达正确的人**。若缺乏刚性约束，自动采集极易引发版权侵权、隐私泄露、AI 幻觉污染——因此每一颗种子都必须**通过三重合规鉴别、携带合规指纹、接受信值度量**。"如果这颗种子被误解，我们能否在 30 秒内澄清并修复信任？"——答案必须是肯定的，因为**知识的价值永远建立在信任之上**。

## 一、模块定位与架构

```
全站观测面信号(46/52/55号+44号池+knowledge_*缺口——纯读取)
        │
        ▼
① 趋势感知引擎(GAP_SIGNAL_REGISTRY 融合诊断——第32档案评分)
   ├─ 必要性 < 阈值 → 观察队列留痕
   └─ 必要性 ≥ 阈值 → 《知识补全优先级清单》→ 定向采集(源白名单)
        │
        ▼
② 三重合规鉴别中心(确定性规则轨)
   ├─ 版权关: 源白名单+内容指纹去重+授权标注
   ├─ 隐私关: PII 扫描+脱敏/合成替换+49号预算计量(不足即停)
   └─ 内容安全关: 敏感模式黑名单+风险分级(高危转人工)
   ├─ 全过 → 合规指纹生成 → 种子工坊        不通过 → 隔离/脱敏/告警留痕
        │
        ▼
③ 知识种子工坊(结构化+多模态对齐+KNOWLEDGE_REASON+版本化)
   └─ sandbox 态种子 → 人类终审(发布审批) → published
        │
        ▼
④ 角色植入与种子入口(确定性匹配+情境触发+学习路径)
   └─ 用户反馈 → 信值评估器
   ├─ 正反馈 → 权重提升+扩散(推荐位提升)
   └─ 负反馈 → 降权/修正/紧急下架(+45号受影响用户补偿)
        └→ 决策回流 → 第32档案 Hedge 学习(44号复用)
```

**三铁律（安全鸿沟工程化）**：
1. **未经合规鉴别的原始资源永不暴露终端用户**——原始资源仅存沙箱隔离态（quarantined），唯一出口是"通过三关→生成合规指纹→封装种子→人类终审发布"；
2. **种子必带合规指纹与信值标签**——无指纹不入库、无信值标签不入推荐池（可断言、可追溯、可召回）；
3. **隐私预算全程封顶**——采集（PII 扫描）+处理（多模态对齐）+展示（植入推送）三段计量，统一经 49号 check_and_spend，超支熔断暂停+告警（不抛错留痕——人工加额或放弃）。

**双模型铁律（54/55/56号范式平移）**：57号评分（第32档案）与既有 knowledge_* 知识库训练模块**并行不替换**——57号仅对"缺口诊断与种子价值"打分回流，纯读取既有 knowledge_* 的缺口队列与统计，零改动既有知识库路由/服务/仓储。

## 二、缺口信号注册表（GAP_SIGNAL_REGISTRY——封闭白名单）

52号 registry 范式。每条信号含六字段（signalId/label/side/source/direction/weight/threshold/status）。

**首批 10 项信号源**（四侧）：

| 侧 | 信号 | 权重 | 采集口径（纯读取） |
|----|------|------|-------------------|
| 业务侧 | kb_gap_open 既有缺口未决 | 0.20 | knowledge_* 缺口队列 open 数（跨模块读取，不写入） |
| 业务侧 | kb_search_miss 搜索无结果高频 | 0.15 | knowledge_* ask 无答案埋点聚合 |
| 用户侧 | us52_inclusion_drop 包容性下降 | 0.15 | 52号五维 inclusion 环比（老年/无障碍场景知识缺口代理） |
| 用户侧 | qr55_satisfaction_drop 满意度下降 | 0.10 | 55号六指标 satisfactionScore 环比 |
| 系统侧 | gov46_stagnation 学习停滞 | 0.10 | 46号 live_health 停滞检测器 |
| 系统侧 | xz48_failure_high 小竹失败挖掘高频 | 0.10 | 48号失败挖掘队列量（语音场景知识缺口代理） |
| 合规侧 | gov46_alert_open 合规告警未决 | 0.075 | 46号 alerts status=open（政策更新知识缺口代理） |
| 合规侧 | gov46_drift_high 因子漂移高 | 0.075 | 46号 live_health 漂移检测器 |
| 模型侧 | pool44_alignment 回流对齐下降 | 0.075 | 44号池 rewardAlignment 环比 |
| 模型侧 | kb_freshness_stale 知识新鲜度过期 | 0.075 | 既有 knowledge_* retired/过期占比（知识过时代理） |

- **启动自检**（52号范式）：10 项数量/四侧覆盖/权重和=1.0/方向合法/来源在册——RuntimeError 宪法级
- **知识必要性评分**：`Knowledge_Necessity_Score = Σ(命中信号×权重)×100`（negative 信号抑制）→ 与第32档案八因子信任分融合后三级决策（defer 观察/collect 采集/urgent 紧急采集）

## 三、采集源注册表（SOURCE_REGISTRY——可信源封闭白名单）

**三侧来源**（首批 6 源，封闭可扩展——新增源须 admin 注册+46号变更审批口径）：

| 源 | 类型 | 可信度 | 授权协议 | 采集口径 |
|----|------|--------|---------|---------|
| gov_policy_official | authority | 0.95 | 公开政务（署名标注） | 政策原文/解读（mock 轨：运营注入） |
| authority_clauses_18 | authority | 0.95 | 站内自有（18号条款） | 条款知识（站内纯读取） |
| academic_open | authority | 0.90 | CC-BY 开放学术 | 适老化/无障碍研究摘要 |
| partner_authorized | partner | 0.85 | 授权合作方 | 合作方供数（mock 轨） |
| ops_manual | internal | 0.90 | 站内自有 | 运营手册/SOP 文档 |
| media_whitelist | media | 0.70 | 白名单媒体（标注转载） | 权威媒体热点（低可信度——需人工复审） |

**铁律**：白名单外来源（UGC/crawl 未知源）采集即拒——版权关第一道阻断；`sourceCredibility < 0.75` 强制人工复审（内容安全关高危路径）。

## 四、三重合规鉴别中心（确定性规则轨）

三关串行（56号信值沙箱范式——全部离线确定性，LLM 不进判定链）：

| 关 | 评估 | 口径 | verdict |
|----|------|------|---------|
| ① 版权关 | 来源合法性+指纹去重 | 源∈SOURCE_REGISTRY（白名单外即拒）+content_hash 指纹库比对（重复即拒——防换皮重采）+授权协议标注（CC 协议自动带署名要求） | clean / violation |
| ② 隐私关 | PII 扫描+预算计量 | PII_PATTERNS 三模式（身份证 17 位/手机号/银行卡 16-19 位——56号静态关同款）+自动脱敏（掩码替换）+敏感字段合成数据替换；每次扫描经 49号 check_and_spend 计量（预算不足→采集暂停 not 降级放行） | clean / masked / halted |
| ③ 内容安全关 | 敏感模式+风险分级 | SENSITIVE_CONTENT_PATTERNS 黑名单（政治敏感/暴恐/色情/虚假信息代理模式）+风险分级（high 转人工复审/middle 标注置信度供下游/low 直通） | safe / high_risk / middle_risk |

**合规指纹**：`complianceFingerprint = sha256(content_hash + sourceId + timestamp + verdict)`——后续追溯/审计/召回的唯一定位符。

**输出**：《合规鉴别报告》（verdict: passed/blocked/quarantined + 三关明细+脱敏留痕+预算消耗）。

## 五、知识种子工坊（结构规范+多模态+版本化）

### 5.1 种子结构规范（JSON Schema 完整版）

```python
SEED_TYPES = ("text", "image", "video", "qa_pair", "workflow")

seed = {
    "seedId": 1024,                        # 自增主键
    "seedVersion": 2,                      # 版本化（同知识点新旧共存）
    "type": "text",                        # SEED_TYPES 封闭枚举
    "title": "老年人补贴申请要点",
    "content": {                           # 按类型分形态
        "text": "……正文（已脱敏）",
        "mediaRef": None,                  # image/video: /media 路径
        "transcript": None,                # video: 转写稿（多模态对齐）
        "keyframes": None,                 # video: 关键帧时间戳标记
        "alt": None,                       # image: 无障碍替代文本
    },
    "contentHash": "sha256:...",           # 内容指纹（版权关去重锚点）
    "complianceFingerprint": "sha256:...", # 合规指纹（三关全过后生成）
    "valueTags": ["elderly_service", "policy_2026", "high_trust"],  # 信值标签
    "sourceId": "gov_policy_official",
    "sourceCredibility": 0.95,
    "privacyCost": 0.002,                  # 展示消耗预算（49号计量）
    "knowledgeReason": "覆盖 us52_inclusion_drop 缺口……",  # 入库依据（注释即证据）
    "humanVerified": True,                 # 人类终审标记
    "validUntil": "2027-09-06",            # 有效期（过期自动降权+触发更新）
    "abTest": {"active": False, "variantOf": None},
    "status": "published",                 # 状态机
    "createdAt": "...", "updatedAt": "...",
}
```

### 5.2 种子状态机（八态）

```
sandbox（工坊产出，隔离态）
  → review（待人工终审）
    → published（发布——入推荐池）
      → boosted（高正反馈——权重提升+扩散）
      → downgraded（负反馈降权/A-B 旧版）
      → retired（退役/过期——保留可追溯不删除）
    → rejected（驳回——回工坊重制）
```

**KNOWLEDGE_REASON 注释即证据**：每颗种子强制携带入库依据（缺口信号引用+预期用途）——人类审核与 AI 推理时引用（56号 VALUE_REASON 范式）。

**版本化+A/B**：同知识点新版发布旧版不删除、自动降权（`abTest.variantOf` 关联对照）；有效期元数据驱动定期健康检查（过期标记+触发更新流程——及时更新奖励/滞后更新扣分进回流）。

## 六、第32档案：knowledge_orchestration 八因子信任分

44号 ai_learning 入册（batch16——既有测试 31→32 计数更新预算：约 33 处 10 文件，56号 P0 同型教训预算内消化）。

| 因子 | 权重 | 口径 |
|------|------|------|
| signal_quality | 0.15 | 缺口信号质量（命中数×四侧覆盖度） |
| necessity_score | 0.20 | 知识必要性（信号融合分） |
| budget_sufficiency | 0.15 | 隐私预算余量（49号） |
| risk_posture | 0.15 | 风险态势（46号冻结/告警密度） |
| source_health | 0.10 | 来源健康（近期采集源可信度均值） |
| history_success | 0.10 | 历史种子有效率（回流真值） |
| compliance_posture | 0.10 | 合规态势（鉴别通过率） |
| human_load | 0.05 | 人工负载（复审队列深度——低负载利于自主） |

输出 0-100 信任分 → 三级决策（`DECISION_THRESHOLDS`）：`defer` 观察（<50）/ `collect` 定向采集（≥50）/ `urgent` 紧急采集+人工加急复审（≥80）。

## 八、角色植入与情境触发（P3 设计）

### 8.1 角色画像匹配（确定性推荐算法）

```
推荐优先级 = 基础分(角色×种子受众标签匹配)
           + 场景加成(当前任务/最近搜索词×种子 valueTags)
           - 学习记录折减(已学/已忽略同知识点)
           - 预算成本(privacyCost 49号可余量校验)
角色映射(封闭枚举):
  citizen 群众 → 受众标签 elderly_service/policy(大字版+语音入口标记)
  staff 社工/工作人员 → SOP/workflow/政策要点
  developer 开发者 → API/技术文档
```
