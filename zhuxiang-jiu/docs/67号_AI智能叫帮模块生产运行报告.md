## 一、模块定位回顾

AI智能叫帮模块是"信值驱动的互助网络"（非劳务交易中介）：

- **公益模式**：求助免费互助，完成后按"类别基准 × 时长(h)"** 100% 记录公益信值**
- **有偿模式**：双方协商价格、平台确认，**零佣金**，信值按公益标准的 **10%** 记录（`paidRatio=0.1`，比例不可篡改）
- **信值约束**：接单门槛（公益 0 / 有偿 20 信值）、违约扣减、差评扣减，双向约束发单方与接单方
- **LBS 大厅**：按紧急度 > 距离 > 时效排序，支持模式/分类/半径筛选（radius_km ≤ 200 强校验）
- **确定性原则**：需求解析、类别识别、信值结算全部为规则代码，**LLM 禁入判定链**

### 3.6 P1 智能调度层规则（生产实测）

**三维匹配引擎**（GET /orders/{id}/match，信值 40% + 同类经验 30% + 地理 30%）：
- 候选池 = 历史完成单帮助者（排除发布者），Top3 输出含可解释理由（信值/经验/评分/距离）
- 本地实测：Top1 = m3（累计信值 77 · 同类经验 2 单 · 评分 5.0 · 常活动区距求助点 3.8km，score=0.763）

**偏好推荐排序**（大厅个性化）：
- 规则：历史完成频次 ≥ 总数 1/3 的类别视为偏好类，命中单置前并显示 ✨ 徽章
- 紧急优先级最高（不可被偏好覆盖）；偏好优先级高于距离（本地实测：偏好类 3.48km 排在非偏好类 0km 前）

**信值捐赠**（POST /orders/{id}/donate）：
- 资格门槛：累计信值 ≥ 50（高信值用户）；额度 1-10；仅公益单；每单每人一次（幂等拒重）
- 结算闭环：捐赠即时扣减捐赠者信值入单捐赠池 → 完成时全额奖励帮助者（本地实测：基础 12 + 捐赠 5 = 17）

**荣誉体系**（数字功德碑口径，按公益信值晋级）：
- 阶梯：🌱见习(0) → 🥉铜心(10) → 🥈银心(50) → 🥇金心(100) → 🏆白金守护者(300) → 🌳功德圆满(1000)

**互助故事卡**（GET /orders/{id}/story，仅 completed 单）：
- 确定性模板：类别文案 + 双方评价摘录 + 分享文案（含社区捐赠标注）

**安全护航**（GET /orders/{id}/guard，观测不干预）：

### 3.7 P2 生态深化层规则（生产实测 · 2026-09-10 上线）

**信值传承**（数字功德碑，POST /heritage/apply + /heritage/{id}/accept）：
- 仅**公益信值**可传承（有偿信值不可——宪法口径）；发起人公益净值 ≥10
- 双方确认：发起 → 受让人确认 → 即时划转（按确认时点实际公益净值封顶，双边流水留痕）
- 幂等：每人同时仅一笔待确认；受让人不可是自己
- 生产实测：m1（公益 20）传承 10 给 m2 → m1 10 / m2 +10，非受让人确认 409 拒绝 ✓

**企业 CSR 信值包**（POST /csr/packages + /csr/packages/{id}/donate）：
- 企业包额度 10-10000 认捐留痕（平台零资金流）；定向捐给**待接单公益单**入捐赠池
- 每包每单限一次；单笔 1-100 且 ≤ 包余额；**不动用个人信值**（包池独立）
- 生产实测：m2 创建包 50 → 捐 20（包余 30，单池 +20，大厅卡片显示"社区已捐 20 信值"）✓

**互助接力**（POST /orders 带 relay=true + legs 2-5）：
- 偏远地区多人分段：各段独立接单/开始/完成；总信值按段均分（末段补差，**总和恒等**）
- 段完成 → 下一段自动回大厅待接；全段完成才整单收口（末段结算发布者感谢+捐赠池归末段帮助者）
- 已完成段的接力单**不可取消**（已履约的善行不可撤）
- 段历史帮助者经 relayHelpers 保留可见性
- 生产实测：2 段 8 信值接力"送老年机到乡镇"——段1 m3 +4 回大厅、末段 m1 +4 整单收口，发布者感谢 +1 ✓
- 浏览器实测：大厅"接力 x/N段"徽章、当前段地址、我的互助段进度圆点（●● 2/2）✓

**生产浏览器验证（6/6 全过，console 零错误）**：CSR 捐赠展示、信值流水（传承-10/接力+4）、传承入口与弹层（发起表单+已划转记录）、发布接力开关（2-5 段选择器）、接力进度圆点。
