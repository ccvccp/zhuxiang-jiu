# 38号·AI智能产品管理模块 设计文档 v1.0

> 定位：自营商品的"写半边"——现有 `product` 模块只有面向消费者的读路径（列表/搜索/详情），本模块补齐**后台管理链路**：权限角色 × 审核制度 × 商品上下架 × 展示图片设计更换 × AI 智能。
>
> 方法论：对标成熟电商平台（淘宝千牛/京东商家后台）的"草稿→审核→上架"运营范式，叠加本项目已有的 AI 基建（评分器档案体系 / LLM 降级链 / 多模态识图 / 权限 RBAC）。

---

## 1. 设计目标与核心概念

### 1.1 一句话模型

**"谁有权改、改了必须过审、过审才能上架、图片更换走 AI 审图，全程留痕可回滚。"**

- 商品状态机（37号式显式转移表）保证"未过审的商品消费者永远看不见"
- 权限来自 perm 模块（28权限点体系）新增的产品域权限点，**编辑与审核职责分离（SoD）**
- 图片更换不是简单替换 URL：**AI 识图审图 + 版本历史 + 一键回滚**

### 1.2 权限角色谱系（复用 perm 模块 RBAC，不另造轮子）

| 角色模板 | 产品域权限点 | 能做什么 | 不能做什么 |
|---------|-------------|---------|-----------|
| 商品运营（operator） | `product.edit` / `product.image` / `product.submit` | 创建/编辑草稿、更换图片、提交审核 | 直接上架、审核他人商品 |
| 商品审核员（auditor） | `product.review` | 人工终审（通过/驳回） | 审核自己编辑过的商品（**SoD 硬约束**） |
| 管理员（admin） | `product.admin` | 直通上下架、紧急下架、权限授予/吊销 | — |

**接入方式**：perm 模块的 `perm_nodes` 表新增 `product` 域 4 权限点（edit/image/submit/review，admin 为超集），沿用其"逐级审批链 + 限时授权 + 责任书 + 权责信用分"制度——即**权限本身也要走审核**（谁可以当审核员，由上级审批授予）。运营/审核员的授权、审批、吊销全部复用 perm 模块既有 15 端点，本模块零新增权限管理端点。

**降级兼容**：无 perm 授权数据时，按 JWT 角色回退——`admin` 拥有全部产品域权限，`member` 无产品权限（403）。权限判定顺序：perm_grants 有效授权 > JWT 角色 > 拒绝。

### 1.3 商品状态机（显式转移表，酒类电商合规口径）

```
draft ──提交──▶ ai_reviewing ──AI≥80──▶ manual_reviewing ──人工通过──▶ on_sale
  ▲                │                                            ▲      │
  │                │AI 60-79(强制人工) ─────────────────────────┘      │
  │                │AI <60 ──▶ rejected                              │
  │                └─AI异常(服务不可用)──▶ manual_reviewing(降级保产出)  │
  │                                                                     │
  ├─被驳回后可编辑再提（rejected ─编辑─▶ draft）                          │
  └────────────────── 管理员直通: draft/任意态 ──▶ on_sale ────────────┘

on_sale ⇄ off_sale（运营/管理员按权限操作，双向均留痕+可配审核）
off_sale/on_sale ──编辑( substantive )──▶ draft（重大改动重新过审）
```

| 状态 | 消费端可见 | 谁能进 | 谁能出 |
|------|-----------|--------|--------|
| draft 草稿 | 否 | operator 创建 | operator 提交 / admin 直通 |
| ai_reviewing AI预审中 | 否 | 提交自动进入 | AI 评分自动流转 |
| manual_reviewing 待人工审 | 否 | AI≥60 自动进入 | auditor 终审 / admin 直通 |
| rejected 已驳回 | 否 | AI<60 / auditor 驳回 | operator 编辑回 draft |
| on_sale 在售 | **是**（接入现有 `product` 读路径过滤） | auditor 通过 / admin 直通 | 下架操作 |
| off_sale 已下架 | 否 | 下架操作 | 重新上架 |

**关键联动**：现有 `product_repository._apply_filters()` 强制只返回 `on_sale`——本模块不改消费端一行代码，只把管理态商品从 `status="on_sale"` 中排除即可（见 §7 P0 联动项）。

**紧急下架**（合规红线）：admin 可从**任意状态**直达 `off_sale`（酒类负面舆情/资质过期场景），跳过全部审批，操作入 perm_audit_logs 留痕。

### 1.4 与既有模块关系（统筹决策：复用不合并）

| 模块 | 关系 |
|------|------|
| `product`（消费端读） | 共享商品数据结构；本模块写管理态字段（status/编辑版本），`on_sale` 商品自动被现有读端点展示 |
| `perm`（权限RBAC） | 权限点/角色模板/审批链/审计日志全部复用，新增 product 域 4 权限点种子 |
| `ai_scoring` + `ai_learning` | 新增 `product_gate` 评分器（**第 20 个可学习档案**），复用 champion/challenger/Hedge 全链 |
| `llm_client` | `vision()`（glm-4v-flash）做 AI 审图；`chat()` 走 36号式三级降级链做文案优化 |
| `hub media`（35号） | 图片上传管线整套复用（base64 → 本地卷 `/media/image/` → 静态 URL） |
| `compliance`（词库） | 商品名/描述禁用词口径复用 36号/37号共享词表 |
| 37号 `alliance` | **边界清晰不越界**：38号管自营商品，37号管同盟商户商品，两套状态机互不干扰 |

## 2. 总体架构：五个子系统

### 2.1 商品管理网关（catalog_admin）

商品 CRUD + 状态机流转 + 版本快照。

- **创建**：operator 建 draft（名称/描述/价格/库存/类目/图片，字段对齐现有 `_build_product` 结构，缺图用占位生成）
- **编辑双轨**：
  - **cosmetic 微调**（描述文案/标签/排序权重）→ 不改状态，直接生效但留版本快照
  - **substantive 实质变更**（价格/名称/规格/主图）→ on_sale 商品回落 `draft` 重新过审（防"过审后偷换内容"漏洞，成熟平台同款设计）
- **版本快照**：每次保存落 `pdm:product_versions:{id}`（内容 JSON + 操作人 + 时间 + 变更类型），支持任意版本一键回滚（回滚 = 一次 substantive 编辑，同样要过审）

### 2.2 权限与审核（governance）

- 权限判定器 `require_product_permission(node, member_id)`：perm_grants 查有效授权 → JWT 角色回退 → 403
- **SoD 硬约束**：auditor 提交终审时校验"最近一次 substantive 编辑人 ≠ 审核人"，违反 → 409
- 全部上下架/审核/图片更换操作写 `perm_audit_logs`（复用 perm 模块审计表，module="pdm"）

### 2.3 图片中心（image_studio）——"设计更换"核心

**图片资产管理**（复用 hub media 管线 + 扩展）：

```
上传(base64 ≤5MB jpg/png/webp) → 校验 → 落盘 /media/image/{date}-{uuid}.ext
  → 入图库 pdm:images:{imgId}(url/大小/尺寸/上传人/商品绑定)
  → AI 审图(见下) → usable/flagged
```

**AI 审图（vision 多模态，三级降级）**：

1. `vision()`（glm-4v-flash）识图，输出结构化判定：**饮酒动作 / 未成年人出镜 / 低俗暴露 / 水印遮挡 / 模糊低清 / 图文一致性**（图内物与商品标题类目是否相符——防"挂羊头卖狗肉"）
2. vision 服务异常 → 降级规则轨：仅做扩展名/大小/尺寸下限校验，标记 `aiSkipped=true` 转人工抽查
3. 判定违规项 → 图片置 `flagged`，禁止设为主图；轻缺陷（如模糊）提示运营重传

**图片设计更换流程**（本模块亮点）：

```
运营选择商品 → 上传新图 或 AI 生成设计图(见 2.4) → AI 审图通过
  → 写入图片版本组(pdm:product:{id}:images 历史, main+gallery)
  → on_sale 商品的图片更换默认走 substantive(回落 draft 过审)
  → 管理员可配"纯图片替换白名单"(免审, 仅 cosmetic 级差异)
  → 任意历史图片版本一键回滚
```

**图文一致性校验**同样用于人工审核辅助：审核员界面直接展示 AI 审图报告（违规项+置信度+识图描述），人工只做终审裁决。

### 2.4 AI 设计工坊（design_studio，P2）

- **AI 生成商品主图**：按商品类目/卖点多模态生成——复用项目既有 `text_to_image` 生成管线（SDXL），prompt 由 LLM 按商品信息自动构造（"酱香型白酒·礼盒装·国风静物·暖光"式），产出直接入图库走 AI 审图
- **AI 文案优化**：商品标题/详情页文案，36号式三级降级链（glm-5.3 → glm-4-flash → 规则模板），输出经 36号共享禁用词表硬校验后仅作建议，运营采纳后按编辑轨落库
- **AI 主图 A/B 建议**：同商品多版本主图存于图片版本组，AI 按历史转化数据（复用 attract 归因/商品销量）建议主图选择（P2 尾项，依赖数据积累）

### 2.5 智能上下架引擎（listing_advisor）

- **上架预审评分器 `product_gate`**（ai_scoring 第 20 档案，五因子）：

| 因子 | 权重 | 判据 |
|------|------|------|
| 合规词命中 | 0.25 | 商品名/描述/图片 OCR 违禁词（酒类广告法§23 口径） |
| 信息完备度 | 0.20 | 必填字段（价格/库存/规格/主图/类目）缺项数 |
| 图片质量 | 0.25 | AI 审图报告（主图清晰度/违规项/图文一致性） |
| 价格合理性 | 0.15 | 同类目历史价格分位数离群度（防虚高/倾销） |
| 品类风险 | 0.15 | 酒精度数/类目敏感度（高度酒加权） |

  分数线沿用 37号口径：**≥80 快车道（仍需人工点确认）/ 60-79 强制人工重点审 / <60 直接拒**；评分因子快照落库，接入 ai_learning Hedge 学习（审核员的人工裁决自动回流训练权重）
- **智能下架建议**（P1）：连续 N 天零销量 + 低评分 + 长库存龄 → 建议下架（只建议不自动执行，运营确认）；临期/资质过期 → 强制建议
- **上下架操作幂等**：重复上架请求返回当前态（锁 `lock:pdm:product:{id}`，Redis/asyncio 双模式）

## 3. 数据模型（Redis Key，前缀 `pdm:`）

| Key | 类型 | 内容 |
|-----|------|------|
| `pdm:product:{id}` | Hash | 管理态字段覆盖层（status/当前版本号/编辑人/提交人/审核人/驳回理由/AI 预审快照）——商品主数据仍在 `product:{id}`，两表以 productId 关联 |
| `pdm:product_versions:{id}:{ver}` | String(JSON) | 版本快照（全量字段+变更类型 cosmetic/substantive+操作人） |
| `pdm:images:{imgId}` | Hash | 图片资产（url/尺寸/大小/上传人/aiReview JSON/绑定商品） |
| `pdm:audit:{id}` | String(JSON) | 模块内操作流水（权限判定路径/操作/前后状态；同步写 perm_audit_logs） |
| `pdm:seq:{entity}` | String | 自增 ID（product_version/image/audit） |
| perm 模块表 | — | `perm_nodes` 追加 product 域 4 权限点种子 |

**双模式存储**遵循项目惯例：内存 dict / Redis Hash 自动切换（`STORE_MODE`），锁走 `get_lock()`（`LOCK_MODE` 动态读）。

## 4. API 设计（routes/pdm_routes.py，前缀 `/api/pdm`，约 26 端点）

**商品管理（operator）**
- `POST /api/pdm/products` 创建草稿
- `PUT /api/pdm/products/{id}` 编辑（cosmetic/substantive 自动判定，body 可 force 声明）
- `POST /api/pdm/products/{id}/submit` 提交审核（→ ai_reviewing）
- `GET /api/pdm/products/{id}/versions` 版本列表
- `POST /api/pdm/products/{id}/versions/{ver}/rollback` 版本回滚

**审核（auditor）**
- `GET /api/pdm/reviews/pending` 待审队列（含 AI 预审报告+审图报告）
- `POST /api/pdm/products/{id}/review` 终审（approve→manual_reviewing 商品可上架 / reject→rejected+理由）
- `POST /api/pdm/products/{id}/ai-precheck` 手动触发 AI 预审（排障/复评）

**上下架（operator/admin 按权限）**
- `POST /api/pdm/products/{id}/list` 上架（须 on_sale 前置态 approved；幂等）
- `POST /api/pdm/products/{id}/delist` 下架（reason 必填；幂等）
- `POST /api/pdm/products/{id}/force-delist` 紧急下架（admin only，任意态直达）
- `GET /api/pdm/listing-advice` 智能上下架建议列表（P1）

**图片中心（operator）**
- `POST /api/pdm/images` 上传图片（base64，AI 审图自动触发）
- `GET /api/pdm/images/{imgId}` 图片详情（含 AI 审图报告）
- `PUT /api/pdm/products/{id}/images` 更换商品图片组（main/gallery，on_sale 商品默认回落 draft）
- `POST /api/pdm/products/{id}/images/rollback` 图片组回滚历史版本
- `GET /api/pdm/images/flagged` 被标记图片列表（重传/销毁）

**AI 工坊（operator，P2）**
- `POST /api/pdm/design/generate-main-image` AI 生成主图（商品信息→prompt→生成→自动入图库+审图）
- `POST /api/pdm/design/copy-optimize` 文案优化建议（不入库，仅建议）

**看板（admin）**
- `GET /api/pdm/report/overview` 全景（各状态商品数/待审队列长度/AI 预审通过率/审图违规率/今日上下架流水）

鉴权：全部端点走 JWT 中间件（`X-Member-Id`+`X-Role` 注入）+ 本模块 `require_product_permission()` 双门禁；无产品权限 → 403。

## 5. AI 能力落位

| 能力 | 实现 | 降级 |
|------|------|------|
| 上架预审 | `ProductGateScorer`（20 档案，五因子） | 纯规则因子，LLM 缺席不中断 |
| AI 审图 | `vision()`（glm-4v-flash）结构化判定 | 规则轨（扩展名/大小/尺寸），标记转人工 |
| 图文一致性 | vision 识图 + 类目词表比对 | 关闭该项，仅提示 |
| 文案优化 | `chat()` 三级降级链 | 规则模板轨 |
| 主图生成 | `text_to_image`（SDXL 管线） | 不可用时返回占位图建议 |
| 权重学习 | ai_learning Hedge（20 档案） | —（复用既有机制） |

## 6. 合规与红线

- 酒类商品图片**饮酒动作/劝酒场景**硬拒（一审规则，AI 审图 + 人工终审双闸）
- 未成年人出镜图片硬拒；权威背书/功效暗示词沿用 36号共享词表
- SoD：编辑≠审核，审核自己编辑的商品 → 409
- 全部管理操作双写审计（模块流水 + perm_audit_logs）
- substantive 变更必须重过审——杜绝"低价过审后改高价"

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| vision 误判（酒瓶静物误判饮酒动作） | AI 仅作预审/标记，终审权永远在人工；flagged 可申诉重审 |
| 权限数据缺失导致全员裸奔 | 判定顺序 perm_grants > JWT 角色 > 拒绝；admin 兜底唯一 |
| 图片存储膨胀 | 单商品图片版本组上限（默认 10 版，超限淘汰最旧 cosmetic 版） |
| 状态机被并发操作击穿 | 全部流转 `lock:pdm:product:{id}` 锁内 + 显式转移表校验（非法转移 409） |
| 与 37号同盟商品边界混淆 | 端点前缀隔离（/api/pdm vs /api/alliance），文档+代码头注释双标注 |
