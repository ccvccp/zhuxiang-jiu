# 51号 · 小竹可信知识图谱 · 运维手册

> 适用：运维/管理端日常操作
> 前置：Docker 容器运行中（backend+redis healthy）
> 鉴权：管理端 `X-Role: admin`；会员面 `X-Member-Id`；公开面无鉴权

---

## 一、开关矩阵

| 环境变量 | 默认 | 语义 | 变更时机 |
|---------|------|------|---------|
| `KG_MODE` | off | on=数据面全开（采集+查询）；off=采集停 409/查询空态 200/溯源与治理面不受影响 | 需要图谱服务时 |
| `KG_EXTRACT_MODE` | off | LLM 抽取轨（未接入——预留） | 外部 LLM 就绪后 |
| `KG_INSPECT_MODE` | off | 日度巡检调度轨 | 长期运营开启 |
| `KG_INSPECT_INTERVAL` | 86400 | 巡检间隔秒（下限 300） | 按需 |

**开启顺序建议**：`KG_MODE=on` → 手动触发一次采集（见下）→ 观测无误 → 可选开启巡检调度。

## 二、日常操作 SOP

### 2.1 采集（数据面）

```bash
# 手动触发三源采集（admin）
curl -X POST http://127.0.0.2:8000/api/kg51/ingest/run \
  -H "X-Role: admin" -H "Content-Type: application/json" -d '{}'

# 采集状态观测
curl http://127.0.0.2:8000/api/kg51/ingest/status -H "X-Role: admin"
```

采集统计口径：`sources.system/authority/user/trace/institution` 各含 `scanned/entities/triples/skipped/updated/reviews`。

**重复采集幂等**：实体 entityId 自然键首次为准；三元组指纹去重；pending→settled 事件重采走置信升级（0.85→0.98）。

### 2.2 复核裁决（质量闭环）

```bash
# 队列（confidence=低置信 / conflict=冲突 / feedback=纠错）
curl "http://127.0.0.2:8000/api/kg51/reviews?status=pending" -H "X-Role: admin"

# 裁决（approve→目标转 verified/active；reject→retired 留痕）
curl -X POST http://127.0.0.2:8000/api/kg51/reviews/1/decide \
  -H "X-Role: admin" -H "Content-Type: application/json" \
  -d '{"approve": true, "decisionNote": "人工采信"}'
```

### 2.3 巡检与版本（治理面）

```bash
# 巡检触发（三指标快照——不受 KG_MODE 影响）
curl -X POST http://127.0.0.2:8000/api/kg51/inspect/run -H "X-Role: admin"
curl http://127.0.0.2:8000/api/kg51/inspect/latest -H "X-Role: admin"

# 版本快照+回溯
curl -X POST http://127.0.0.2:8000/api/kg51/versions/snapshot \
  -H "X-Role: admin" -H "Content-Type: application/json" -d '{"label": "v1.0"}'
curl http://127.0.0.2:8000/api/kg51/versions -H "X-Role: admin"

# 公平桥上报 46号
curl -X POST http://127.0.0.2:8000/api/kg51/fairness-bridge -H "X-Role: admin"
```

巡检三指标判读：
- **completeness**（完整性）<1 → 有事件缺证据链或实体悬挂——检查采集是否覆盖
- **consistency**（一致性）<1 → 冲突复核积压——处理 `/reviews?status=pending&reason=conflict`
- **freshness**（时效性）<1 → 采集时龄 >48h 或 unverified 占比 >50%——重跑采集/复核

### 2.4 看板判读

```bash
curl http://127.0.0.2:8000/api/kg51/dashboard -H "X-Role: admin"
```

| 分区 | 关注点 |
|------|--------|
| scale | 实体/三元组规模趋势 |
| verified.verifiedRatio | <0.5 → 复核积压或采集质量下降 |
| reviewBacklog.byReason | conflict 高 → 数据源打架；feedback 高 → 用户纠错活跃 |
| budget.exhaustedToday | 预算耗尽账户数（正常现象——日切重置） |
| lastInspection | 三指标最近快照 |
| cache | 查询缓存命中容量 |

### 2.5 红队自检

```bash
curl -X POST http://127.0.0.2:8000/api/kg51/redteam -H "X-Role: admin"
```

**breached>0 即上线阻断**——须修复后重跑。报告含 `immutability` 零改动断言（17 工具/14 行为/9 因子）。

## 三、故障处置

### 3.1 常见问题

| 现象 | 原因 | 处置 |
|------|------|------|
| ingest/run 409 | KG_MODE=off（采集停铁律） | 确认开启意图后置 KG_MODE=on |
| query 200 空态 | KG_MODE=off（fail-soft 直通） | 非故障——设计行为 |
| query 409 "隐私预算不足" | 49号预算当日耗尽 | 次日自动重置；紧急可调隐私偏好（49号运维手册） |
| query 409 "越权" | 会员查他人主体/无身份 | 非故障——权限矩阵 |
| 巡检 freshness 持续低 | 采集未跑/unverified 积压 | 手动 ingest/run + 复核裁决 |
| 互证三元组缺失 | 47号互证窗（90天）内无双向引用 | 检查 45号 deposit sources 是否含 trust: 引用 |

### 3.2 fail-soft 边界

以下异常**不阻断主链路**（降级留痕）：互证计算异常（kg51_mutual_skip）、预算分区异常（看板降级文案）、16/21号机构扫描异常（跳过该源）、缓存读写异常（穿透）。日志关键字：`kg51_`。

## 四、数据治理

### 4.1 存储布局（Redis key 前缀 `zhuxiang:kg51:`）

| 表 | 内容 | 清理口径 |
|----|------|---------|
| kg51_schema_log | 本体变更审批台账 | 永久保留（审计） |
| kg51_entities | 实体（digest-only） | retired 态保留（溯源） |
| kg51_triples | 三元组（含 evidence_bundle） | retired 态保留 |
| kg51_fp_index | 指纹索引 | 随三元组 |
| kg51_reviews | 复核台账 | 永久保留 |
| kg51_versions / kg51_inspections | 版本/巡检快照 | 只追加（回溯） |
| kg51_feedback | 纠错反馈台账 | 永久保留 |
| kg51_scheduler_stats | 调度留痕 | 最近一份 |

### 4.2 红队痕迹处置

红队注入的三元组（subject 含 `fake:`/`probe-`）落 unverified——不影响计分路径；治理口径：置 retired（管理端复核裁决 reject）或直接清理 `zhuxiang:kg51:*`（验收脚本每轮自动清理）。

### 4.3 回滚预案

1. **代码回滚**：回退至上一提交 → 容器重建（`docker compose up -d --build backend`）→ KG_MODE 保持 off（默认零影响）
2. **数据回滚**：kg51 表全部为增量——删除 `zhuxiang:kg51:*` 即回到空图（45/46/48/49/50号数据不受影响）
3. **本体回滚**：注册表为代码态——回退提交即回滚本体；审批总线留痕不删（可溯）
