## 一、模块定位

知识图谱在信值体系中不是通用百科式语义网络，而是**可信数据资产的结构化底座**——每一个三元组都可溯源（evidence_bundle）、可脱敏（digest-only）、可预算（49号隐私预算感知查询）、可退役（版本快照+retired 态）。

本模块补上代码中两处明确留白：

| 留白声明 | 位置 | 本模块回应 |
|---------|------|-----------|
| "graph 维度以证据内容质量代理……GNN 图谱轨列入外部待办" | trust_verify_v2.py | 轻量三元组图谱（非 GNN），溯源面供验真调用 |
| "GNN 图谱轨明确不落地（外部待办）" | trust_risk_collusion_service.py | verified_with 互证邻域（47号纯函数复用） |

**三块预制件焊接**（不是从零建图）：49号隐私预算 = SOP 隐私预算感知查询；47号 ev_sha 指纹 = SOP 证据链绑定；50号 14 行为台账 = BehaviorEvent 实体源。

## 三、架构关键设计

### 3.1 与 SOP 通用方案的适配差异

| SOP | 本站落地 |
|-----|---------|
| NebulaGraph 图数据库 | 三元组关系表 + 双模式存储（零新中间件） |
| OWL/RDF-S 本体 | Python 注册表 + 启动自检（49/50号范式） |
| PSI 跨域对齐 | 不落地（外部待办——无跨机构场景） |
| LLM 微调抽取 | KG_EXTRACT_MODE 三态预留（默认 off） |
| RESTful+GraphQL | 纯 RESTful（注入面最小化） |
| 人工标注员 | 复核队列 + admin 裁决（46号范式） |
| 月度公平报告 | 公平桥 side-door → 46号 |
| Grafana | 自有看板端点 |

### 3.2 开关矩阵

| 开关 | 默认 | off 行为 |
|------|------|---------|
| KG_MODE | off | 采集停（409）；查询面空态 200 fail-soft；溯源/治理/观测面不受影响 |
| KG_EXTRACT_MODE | off | LLM 抽取轨预留（未接入） |
| KG_INSPECT_MODE | off | 调度零 task（46号P6范式） |

### 3.3 红线体系

- **digest-only**：PII 禁入基线（phone/idCard/bankCard/realName）全实体强制 + 审批总线提交侧拦截 + 红队三重验证
- **证据链**：attested_by minCard=1；无证据链即 unverified 物理隔离于计分路径
- **置信度源上限**：user≤0.6 / system≤0.98 / authority≤1.0（P5 红队加固的注入护栏）
- **预算均等**：查询成本按实体敏感度静态值，与信值等级零挂钩
- **零不可逆**：45/46/49/50号注册表/档案/端点零改动（宪法断言每期三重验证）

## 四、一致性声明

本模块对既有模块的全部改动均为**只读复用或纯增量**：

- 45/47/50号代码零改动（trace 跨表只读渲染；互证纯函数调用）
- 46号仅 side-door 档案入册（28 档案断言零改动）
- 48号仅新增 feedback 入口（零既有端点改动）
- main.py 纯增量（路由注册 3 行 + 调度器启动/停止）

**零不可逆操作，零宪法断言破坏，默认 off 全站零影响。**

## 六、结语

51号交付的不是一个功能，而是一把**可信数据资产的标尺**——信值闭环八面（43-50号）到此拥有了沉默的底座。SOP 战略提醒全盘继承：**图谱的价值不在于节点数量，而在于每个节点都能经得起质疑、追溯与验证。**
