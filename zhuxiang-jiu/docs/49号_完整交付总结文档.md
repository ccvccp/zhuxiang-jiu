## 一、模块概览

49号解决的核心问题：LLM 时代的函数调用（FC）天然带三类风险——**工具滥用**（该确认的不确认）、**成本黑箱**（调用一次消耗多少隐私说不清）、**凭证伪造**（token 被偷/重放/冒用）。49号以"约束的最高形态是常识"为设计哲学，让禁令写进工具的自我介绍、成本成为规划红绿灯、每次落笔都有归因出处：

| 铁律 | 工程落法 |
|------|---------|
| ① 显式授权（consent） | 高敏工具必须双因子（语音确认词+屏幕码）→ consent_token 60s 一次性核销 |
| ② 可解释绑定（ref） | 写工具响应强制 explainability_ref，缺失业务标识即阻断（不返半成品） |
| ③ 隐私预算感知 | 注册表声明 privacy_cost，网关原子扣减，超限 429 话术，只读零成本永不降级 |
| ④ 失败安全降级 | 每工具预定义 safe_message（不编结果）+ 人工转接选项 |

**默认零影响**：`XIAOZHU_LLM_MODE=off` 时 FC 网关不激活（规则轨照常）；48号 21 端点零改动；45/46/47号只 import 复用。

## 三、各期交付明细

### P0 可信工具注册表与 FC 网关

- **Tool Registry v2**：16 工具（只读 12/写 2/高敏 2），每个 description 内嵌行为禁令（❌）与隐私成本（🔒）——注入 LLM System Prompt 后模型推理阶段即感知约束（约束内化铁律）；
- **FC 网关**：executor 的可信外壳——[校验① consent_token]→[校验② 隐私预算]→[执行 沙箱]→[校验③ ref 必填]→[审计]；只读零摩擦直达（日常 90% 无感）；
- **审计六字段铁律**：memberId/toolName/consentTokenHash/privacyCost/ts/kind（ok|duplicate|fallback）——漏一即测试失败；
- **一致性自检**：启动期校验注册表三级分级 ⊆ 48号沙箱白名单（认知边界不得宽于执行边界）。

### P1 consent_token 双因子

- **签发**：语音确认词（意图证据，ASR 精确匹配+哈希留痕）+ 屏幕码（身份核销）双因子齐备 → 签发 60s 一次性 token；
- **核验**：TTL≤60s / 一次性 / action 匹配 / 声纹代理绑定（跨用户复用无效）；
- **直执行**：有效 token 绕过 confirmToken 再发（双因子已齐备）；
- **TTL 收紧**：confirm_token 120→60s（计划铁律①）。

### P2 隐私预算

- **账本**：voice48_privacy_budget（dailyBudget 1.0 × preference 0.5-2.0）；
- **原子扣减**：check_and_spend 检查+扣减一体（超限 raise→429 语义话术+偏好引导+转人工）；
- **日切重置**：dayKey 滚动清零，历史入史 7 日；
- **预算均等红线**：只按用户自主偏好分级，绝不与信值等级挂钩；
- **只读零成本永不降级**：cost=0 不检查不扣减。

### P3 可解释性绑定

- **ref 三段式**：`exp-{action}-{业务id}-{8位哈希}`（动作+业务 id+确定性 seed）；
- **绑定强制**：写/高敏响应必含 ref（trust.convert/repair.execute/cart.submit/trust.bind），缺失业务标识 raise 阻断；
- **归因三源**：45号 attribution 全文 + 46号决策回放 + 49号参数化播报模板（非 LLM 生成——数字来自数据层）；
- **"打开修复说明"**：explanation.report 指令（注册于 nav.page 之前——指令优先级防冲突）。

### P4 红队测试与收官

- **红队用例集**（[xiaozhu_fc_redteam.py](../backend/services/xiaozhu_fc_redteam.py)）：

| 向量 | 用例 | 防御机制 |
|------|------|---------|
| A 工具描述越狱（3） | 伪造 requiresConsent/tier/description | 注册表静态值是唯一事实源——挑战流照常 |
| B 成本篡改（3） | 伪造 privacyCost=0/-1、预算耗尽绕过 | 审计与扣减均读注册表；预算检查在扣减前 |
| C 伪造 token（5） | 随机/格式伪冒/重放/跨用户/动作劫持 | 五类拒绝全计数（consent_rejects） |
| D 越权诱导（3） | 未注册工具/注入指令串/只读垃圾 token | 白名单 ValueError；防御不在模型层终止 |

- **看板第 7 区块 FC 分区**：调用量/失败降级率/预算消耗（流水成本+账户聚合）/token 拒绝分布（notFound/expired/used/crossUser/actionMismatch——骤升即凭证攻击面预警）；
- **红队端点**：`POST /api/xiaozhu/fc/redteam`（admin）——breached>0 即上线阻断；
- **前端**：看板⑦FC 分区展示+红队复跑按钮（突破时红色告警并列出 caseId）；
- **上线检查清单七项**：全部工程化为断言（专项 04 组）。
