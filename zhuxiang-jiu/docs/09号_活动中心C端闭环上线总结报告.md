- **类型化扩展区块**：

## 六、后端加固与修复

### 6.1 游客公开面扩展（auth_middleware.py）
- `PUBLIC_GET_PREFIXES` 增加 `/api/activity/lottery/`（奖品池概率公示，合规要求；POST /draw 不受 GET 前缀影响）
- 新增 `PUBLIC_GET_PATTERNS` 正则 `^/api/activity/\d+$`（活动详情 GET）
- **安全边界**：不能放宽为前缀 `/api/activity/`——那会把 `my-registrations`/`prizes/mine` 变为中间件层公开（路由层仅校验头存在性，存在伪造 X-Member-Id 越权风险）。测试 3 用例锁死该边界。

### 6.2 报名/取消本人校验（activity_routes.py）
- register/cancel 增加 `header X-Member-Id 与 body.userId 一致`校验（403），对齐 draw_lottery 既有「仅本人可抽奖」先例
- 测试：冒名报名/取消/抽奖均 403

### 6.3 两处既有缺陷修复
| 缺陷 | 根因 | 修复 |
|---|---|---|
| my-registrations 内存态恒返回空 | 路由把头字符串直接传 service，`reg_map.get("1")`（str）查不到 int 键；prizes/mine 均有 `int()` 唯独此接口漏 | `user_id = int(_require_member_id(...))`（Redis/内存双模式均正确） |
| 列表 registrationCount 恒为创建时快照 0 | 报名/取消不回写活动文档，get_activity 实时重算而 list 返回存储值，两处口径不一致 | service `list_activities`/`list_admin_activities` 逐条实时重算（对齐 get_activity 口径） |

### 6.4 前端错误体字段兼容
全局异常处理器返回 `{success:false, error}`，FastAPI HTTPException 返回 `{detail}`，旧版 `{message}`——前端 errMsg() 三字段兼容读取。
