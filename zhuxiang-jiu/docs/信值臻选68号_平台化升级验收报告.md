## 四、验收发现

### 4.1 交付期缺陷（本次升级引入/暴露，全部闭环）

| # | 缺陷 | 根因 | 修复 | 复验 |
|---|------|------|------|------|
| 1 | Redis 态开通钱包触发 WRONGTYPE（该用户钱包永久不可用；生产 member3 实证——`wallet/info` 与 `transactions` 均 500） | `SETNX` 先建 string 占位键再 `HSET` 覆盖——中途异常遗留 string 脏键 | 类型预检+单条 HSET 原子写入（无占位中间态、无崩溃窗口）；旧版脏键（值恒为 `"{}"`）读侧视为未开通、开通自动清除重建；其余异常类型诚实拒绝 | E2E **96/96** + Redis 场景 **12/12** |
| 2 | 占位字段判重方案（HSETNX `_placeholder`）在真实账户上误判为新开通，零余额初始数据重置真实账户 | HSETNX 的 NX 语义为**字段级**而非键级——真实账户无占位字段时返回 1 绕过 409 检查；服务层 `open` 无预检（仓储层唯一防线），且 E2E 重复开通用例仅内存态覆盖 | 加固阶段实证发现，弃用占位方案，改为"键上已有真实字段即已开通"预检判重；重复开通 409 且余额不被重置 | Redis 场景 **12/12**（S2 余额 100.25 保持） |
| 3 | 钱包 5 个读端点（info/transactions/daily-interest/deposits/rewards）对 ValueError 未映射——异常键场景 500 而非设计的 409（写端点均有该映射，读端点遗漏） | live 脚本首跑 S4 场景发现（读侧 500）；junk 键经 `_redis_get_account` 抛 ValueError 时路由只捕 KeyError | 补齐 5 读端点 `except ValueError → 409`（与写端点对齐） | 生产实机 live **14/14** |

修复位置：`zhuxiang-jiu/backend/repositories/wallet_repository.py` `_redis_open_account`/`_redis_get_account`（已随本验收报告一并提交入库）。

**教训沉淀**：双模式契约必须 Redis 态实机验证——内存态 E2E 96/96 全绿曾掩蔽字段级 NX 语义缺陷（重复开通即重置账户）；S1-S5 容器内实机场景补齐该防线后闭环。
