## 二、业务规则与口径确认

| 规则 | 口径 | 落地 |
|---|---|---|
| 金额/期限 | ¥1000 × 一年 | MARGIN_AMOUNT=1000 / MARGIN_TERM_DAYS=365（自确认开业日起算） |
| 不可提前取现 | 无 early 接口（负向设计） | 不提供入口即不可调用（测试含负测） |
| 到期结算 | 按年任务完成度 | rate=min(1, 年进货额/50000)，refund=round(1000×rate,2) |
| 比例扣除 | 完成 80% 扣 200 退 800 | 实证用例（15/15 之一） |
| 中途取消 | 按已运营期折算目标 | rate=min(1, 进货/(50000×elapsed/365)) |
| 驳回 | 未开业全额退 | reason=rejected，refund=1000 |
| 年任务基准 | 年进货额 ¥5 万 | ANNUAL_PURCHASE_TARGET=50000，与月度考核同源同口径 |

## 三、方案裁定（为什么是独立实体）

| 候选 | 裁定 | 理由 |
|---|---|---|
| 复用 wallet deposit（定期） | ❌ | DEPOSIT_TIERS 收益/LPR/奖品语义污染；early_settle 全局放行与"不可提前取"直接矛盾 |
| 进 frozenAmount | ❌ | 提现在途语义，会被提现链路误伤 |
| **独立 margin 实体** | ✅ | 沿用 citystore 双模式范式；资金只借 wallet repo 原语——wallet 三件零改动 |

**红线豁免面论证**：保证金端点全部挂 citystore_routes（无 @_decision 门控），WALLET_MODE=off 时驳回退/到期退/中途退照常可用——符合"存量资金退出零影响"铁律（设计文档 §8.3 三档行为表）。

## 十、运维工具与速查（v1.1 新增 · 提交 b16c030）

### 10.1 运维工具 backend/margin_ops.py（容器内直达 service 层，免登录 token）

```bash

docker exec zhuxiang-backend-1 python /app/margin_ops.py due 30                        # 剩余 30 天内到期预警(运营视角, 本版新增)
docker exec zhuxiang-backend-1 python /app/margin_ops.py settle CS-370102-001 expired  # 手动结算(幂等)
docker exec zhuxiang-backend-1 python /app/margin_ops.py tx 3 10                       # 会员双type流水+汇总对账
docker exec zhuxiang-backend-1 python /app/margin_ops.py remind                       # 手动补跑一轮到期提醒(aa607bf, 档位幂等)
```

- 配套 repo 只读方法 `list_all_margins`（双模式，margin 回归 15/15 不受影响）
- 部署：宿主机 /opt 持久源 + docker cp 容器即时生效（repositories/ 子目录铁律）
