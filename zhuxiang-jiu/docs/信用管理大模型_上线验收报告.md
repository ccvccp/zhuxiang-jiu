## 五、验收中发现并解决的问题(工程记录)

### 5.1 paylater 造数键结构(测试修正实录)

- 首版巡检造数用 `save_paylater_order`——只写主表
  **不建 user 索引**(`credit_paylater_orders_by_user`),
  巡检逐户聚合读不到订单, 恶化指标未触发
- 修正: 改用 `add_paylater_order`(新建语义, 维护索引)
- 沉淀: 造数须区分**新建**(add, 建索引)与**状态变更**
  (save, 仅覆写主表)两类仓储方法

### 5.2 Pydantic 参数校验先于装饰器(载荷修正实录)

- 首版决策面测试载荷 `{"amount": 100, "type": "goods"}`
  返回 422——PaylaterOrderRequest 必填 `userId`, 且
  FastAPI 参数解析在装饰器之前
- 修正: 载荷改为 `{"userId": 9002, "amount": 100}`
- 沉淀: 决策面测试载荷须先过 Pydantic 参数校验
  (422 不是门控语义)

## 六、回滚与运维

- **回滚命令**:
  `sed -i 's/^CREDIT_MODE=.*/CREDIT_MODE=off/' /opt/zhuxiang/.env && docker compose up -d backend`
- **运行时切档**(免容器重建):
  `POST /api/credit/mode/override {"mode":"shadow"}`
- **护栏暂停恢复**: `POST /api/credit/mode/resume`(人工留痕)
- **巡检开关**: CREDIT_GUARD_AUTO=off 可关(默认 on——
  护栏是保护机制)
- **巡检间隔**: CREDIT_GUARD_INTERVAL(默认 3600s, 最小 60s)
- **off 态语义**: 管理与先用后付入口(调整/升降级/黑名单/
  恢复/下单/审批/结算)409; 还款履约与积分兑换零影响
