# 小竹对话延迟优化交付报告（全链路拆解落地）

> 日期：2026-10-04 | 依据：用户五维优化方案（模型分层/RAG/工程架构/Guardrail/监控）
> 优化对象：48号小竹语音对话 LLM 轨

---

## 一、架构校准（方案假设 vs 实际现状）

| 方案假设 | 实际现状 | 处置 |
|---|---|---|
| Multi-Agent（Router/导购/招商/Guardrail 四 Agent） | **单体瀑布**：本地规则瀑布 + 单函数 LLM 意图分类（规则轨实测 18-63ms） | 方案按现状映射落地 |
| DashScope qwen 重模型做对话 | 文本 LLM 为智谱 glm-4-flash；qwen 仅 ASR | 模型分层照做（见②） |
| Guardrail 是串行 LLM | **已是本地正则+沙箱+FC 网关**（方案④"正确做法"天然满足） | 零改动确认 |
| RAG 检索慢 | **无 RAG 层**，上下文注入仅几百字（产品行+5轮摘要） | 无需优化 |
| 回复需 SSE 流式 | 前端已分句流水线+TTS 预合成（v3 验收 <2.0s）；TTS 流式轨 v5 哪嘟剥离进行中 | 维持现状 |

**真实瓶颈定位**（生产实测）：
1. LLM 轨存在 `_llm_match → _llm_dialog_intent` **双串行 LLM 往返**
2. glm-4-flash 分类**中位 1761ms**（波动 1.3~3.1s；v89 历史实证 2.95~3.27s）
3. `_llm_match` 为同步裸调（无 to_thread）——**阻塞整个事件循环**（与上午 API 20s 超时同源）

## 二、落地优化（四项）

### ① 双串行 LLM 合并为单次（对应方案①「减少串行调用」）

- 删除前置 `_llm_match` 独立路由调用；`classify_dialog_intent` 的
  `command:<action>` 白名单扩全量（`COMMAND_ACTIONS` 动态注入）
- `_exec_smart_intent` 原生支持 command 分发（800ms 熔断）——零适配
- **附带消灭同步裸调阻塞点**（事件循环不再被 LLM 卡死）

### ② 模型分层路由（对应方案①「用对模型」——实测数据拍板）

生产容器 bench（3 次中位，同 prompt）：

| 模型 | 延迟 | 意图判定（"有什么新品酒"） |
|---|---|---|
| glm-4-flash（原） | 1761ms（波动大） | next ✗ |
| qwen-turbo | 808ms | **affirm ✗（误判有加购风险，弃用）** |
| **qwen-plus（启用）** | **919ms** | **command:product.new ✓ 正确** |

- `chat()` 新增 `profile="xiaozhu"` 独立档：`XIAOZHU_LLM_BASE_URL/MODEL/API_KEY`
  （已配置 DashScope compatible-mode + qwen-plus，key 复用 DASHSCOPE）
- turbo 误判 affirm 印证方案原话"用对模型比用贵模型更重要"——**快而错不可接受**

### ③ 意图缓存（对应方案②「缓存热点」）

- `_llm_dialog_intent` 结果 Redis 缓存（键 `zhuxiang:xiaozhu:intent:{sha256}`，TTL 300s）
- 仅缓存上下文无关意图（command/chat/unknown）；affirm/negate/next/setqty
  依赖对话状态不缓存——高频 FAQ 同文本 300s 内跳过整段 LLM 往返

### ④ 监控开启（对应方案⑤「数据驱动」）

- `XIAOZHU_LAT_REPORT=on`（客户端四段延迟 s1/s2/s3/tt 上报 + P50/P90 统计端点）
- 服务端分段埋点已有：`voice48_timing`（asr/llm_dialog/total）、`voice78_tts_timing`

## 三、优化效果（生产实测对比）

| 场景 | 优化前 | 优化后 | 降幅 |
|---|---|---|---|
| LLM 轨最坏（双串行 glm） | ~4-6s（1.3-3.1s + 2.95-3.27s） | **单次 ~1.5s**（llm_dialog_ms=1479/1523 实测） | **≈65%** |
| 单次分类 bench | 1761ms（glm 波动大） | 919ms（qwen-plus 稳定） | 48% |
| 规则轨（大多数流量） | 18-63ms | 不变 | — |
| FAQ 复问（缓存命中） | 重复 LLM 往返 | Redis 毫秒级 | ~100% |
| 事件循环健康 | _llm_match 裸调可阻塞全站 API | 已消灭 | 根治 |
