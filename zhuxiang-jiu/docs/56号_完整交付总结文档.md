# 56号·AI智能升级管理模块 完整交付总结文档

> 版本：v1.0（2026-09-06）
> 定位：信值驱动的受控进化（Value-UEBA 收官拼图）——从人工运维迈向认知型自洽系统
> 状态：P0-P5 六期全线交付完毕（含收官三件套）

## 一、模块概览

**56号·AI智能升级管理模块**实现"AI 智能升级管理"的生产级 Agent 闭环：在 Value-UEBA 信值体系约束下，让 AI 自主完成"信号感知→升级提案→任务规划→代码草稿→沙箱测试→合规审计→人类终审→资产交付→灰度回滚→决策回流"全生命周期，而每一次升级的代码**永不直接落盘生产**——交付的永远是版本化资产包，部署永远走既有 CI。

**战略位形**（Value-UEBA 四面收官）：

| 模块 | 守护面 |
|------|--------|
| 43号安全管理 | 攻击面 |
| 44号API智能管理 | 消费面 |
| 45号信值 | 社会面 |
| 55号二维码AI智能管理 | 交互面 |
| **56号AI智能升级管理** | **智能本身的进化方向** |

**三铁律**（安全鸿沟工程化，贯穿六期）：
1. **AI 永不落盘生产代码**——资产包 versioned 出口，人工下载走既有 CI（pre-commit 钩子链）
2. **终审永远人工**——强制确认清单+escalate 双人复核+审批留痕追责（永不解除）
3. **预算全程封顶**——提案级 0.1+每次 LLM 调用计量+超支熔断（49号口径）

**四 Agent GLM 协作模型**（规则轨优先+LLM 三态）：规划 Agent→编码 Agent→测试 Agent→审计 Agent 为确定性编排器，mock 模板产出（可测可断言），LLM 仅 shadow/assist 态草稿润色增强（fail-soft 回退），不进执行决策链。

## 三、各期交付明细

### 3.1 P0 信号注册表+决策引擎+提案底座（df7cdda）

- **SIGNAL_REGISTRY**：10 项四侧封闭白名单（模型侧 0.525：gov46_stagnation 0.20/gov46_drift_high 0.15/pool44_alignment 0.15/scorer_frozen 0.025；用户侧 0.25：us52_usability_drop 0.15/qr55_satisfaction_drop 0.10；系统侧 0.15：qr55_clarify_bloat 0.10/qr55_generation_waste 0.05；合规侧 0.075：gov46_alert_open 0.05/registry_pending 0.025），权重和=1.0，启动自检 `_validate_registry` 六类断言（RuntimeError 宪法级——52号范式）
- **八因子评分器**（第31档案 upgrade_orchestration，batch15 入册）：signal_quality 0.15/necessity_score 0.20/budget_sufficiency 0.15/risk_posture 0.15/model_health 0.10/history_success 0.10/compliance_posture 0.10/human_load 0.05 → 信任分 0-100 → 三级决策（defer<50/propose≥50/escalate≥80）
- **决策引擎**：scan_signals 十源纯读取 fail-soft（46号三检测器/44号池对齐环比/55号六指标两帧环比/52号五维环比/46号告警与挂起）→ 命中×权重→必要性→NECESSITY_GATE 20 分前置门槛（环境因子不构成升级理由）→ 提案落库（九态状态机+《升级提案摘要》+预算封顶 0.1）
- 既有测试 30→31 计数更新 33 处 10 文件（55号 P0 同型教训预算内消化）

### 3.2 P1 规划+编码 Agent（f338513）

- **规划 Agent**：SIGNAL_TASK_KINDS 信号→任务类别确定性映射（governance 4 信号/usability 4/compliance 2）+TASK_TEMPLATES 三类六模板（title/objective/dependencies/depType 四型/privacyCost/estimatedGain/experienceNote/rollback 三件套 strategy+steps+dataCleanup）；real 轨 LLM 润色仅 assist 态 fail-soft+PLAN_LLM_COST 0.01 计量（49号封顶内）
- **编码 Agent**：CODE_TEMPLATES 四类模板（governance 护栏校验/usability 指标归因两帧环比/compliance 告警闭环/default 占位）+VALUE_REASON 注释即证据（对信值体系贡献依据）+testPlan 用例矩阵三型（normal/boundary/exception）；资产版本化落库 assetVersion 递增（失败重生成不覆盖）；real 轨 LLM 补充草稿不替换模板（保 VALUE_REASON 完整性）

### 3.3 P2 测试 Agent+信值沙箱（bad72cd）

- **用例矩阵**：normal 草稿非空/boundary 函数结构完整（def+长度）/exception 容错分支（try-except-None-KeyError-if 命中）——离线确定性执行
- **静态关**：SENSITIVE_PATTERNS 十模式黑名单（eval/exec/__import__/文件系统直读/外部 HTTP/os.system/subprocess/DDL 删改表/数据删除）+PII_PATTERNS 三模式（身份证 17 位/手机号/银行卡 16-19 位）violation 阻断+CRYPTO_HOME_MADE 自造加密告警不阻断（走站内规范建议）
- **预算关**：提案级封顶比对（projected=spent+SANDBOX_COST>cap → halted 熔断不抛错留痕——人工加额或放弃）
- **价值关**：estimatedGain>VALUE_GATE 门禁（生成过剩风险防御）
- verdict 三态：budget_halted 优先/全过 passed/否则 blocked；状态 coded→tested/blocked

### 3.4 P3 审计 Agent+人类审批面板（9098903）

- **审计三重校验**：①代码层（沙箱静态关结论复核+资产完整性草稿非空/数量齐+弱加密告警复核）②逻辑层（budgetCap 超支 critical+stateMachine 沙箱未过不应进审计 critical+rollbackPlan 缺失 warning）③文档层（summary 摘要完整性+valueReasons VALUE_REASON 缺失即证据断档 critical+testPlans 缺失 warning）
- **一票否决**：任一层 critical → verdict rejected，状态 audited 回 planned 重规划
- **LLM 归因报告**：mock 确定性模板（三层结论+发现计数+沙箱 verdict+否决重规划指引/通过待人类终审）+real 润色 assist 态 fail-soft；数字来自数据层；highlightItems 人工重点关注项高亮（一键追问入口前五）
- **审批面板**：REQUIRED_CONFIRMATIONS 四关键项强制确认清单（readAuditReport/reviewedSandbox/acknowledgedRollback/acknowledgedBudget——缺勾选拒绝受理防形式化）+escalate 双人复核（第二审批人必填且不可同人）+审批留痕 reviews 表+驳回回 planned

### 3.5 P4 交付+语义回滚+决策回流（5b88e6f）

- **资产包交付**：approved 状态机校验（无审批不可交付铁律）→ 完整资产包（drafts/testPlans/VALUE_REASONs/rollbackPlans 任务对齐/auditReport/sandboxVerdict/approval 四要素/budget 口径/deploymentNote AI 永不落盘声明）→ approved→delivered+灰度跟踪窗口+deliver 事件
- **语义回滚**：预案分步执行留痕（每任务 step/strategy/steps/dataCleanup/executed）+45号 L2 受影响用户信值补偿（submit_deposit platform_conduct 正向抚慰，fail-soft 档案不存在跳过计数）+delivered→rolled_back 三重留痕
- **决策回流**：七类真值信号（deliver_success +1.0/value_achieved ≥90% +0.8/value_missed +0.3/reject_recurrence -0.6/rollback_after_deliver -0.8/veto_overturned -0.5/budget_halt_frequent -0.4）+44号池双写（第31档案，上下文重构+八因子快照+reward 连续奖励——54/55号 P2 范式）+幂等 pooledFeedbackId 1:1
- **T+1 调度器**：AIUP56_LEARN_MODE=on 开启（默认 off 零影响），周期可调默认 24h 下限 5 分钟，scheduler_run 事件留痕

### 3.6 P5 看板+红队+三件套收官（26a822b）

- **四区看板**（52/55号范式纯数据层聚合）：①funnel 提案漏斗（九态分布+曾抵达转化+三级决策分布）②assets 资产产出（资产/版本/草稿/VALUE_REASON/llmCalls+沙箱 verdict 分布）③compliance 审计合规（审计结论+一票否决+审批结果+强制确认完整率）④defense 回滚防御（回滚/补偿落账/预算熔断/七类信号分布+集中度+第31档案护栏健康 [0.5,2.0]×基线）
- **红队六向量**（确定性离线可复现）：RT-01 提案投毒/RT-02 预算耗尽/RT-03 审批绕过三路/RT-04 资产注入三型/RT-05 信号伪造三路/RT-06 回滚破坏三路——全防御
- **收官三件套**：实施计划（已有）+收官报告+完整交付总结文档（本文）

## 十、配置运维手册

**开关矩阵**：

| 开关 | 默认 | 取值 | 语义 |
|------|------|------|------|
| AIUP56_MODE | off | off/shadow/assist | 决策面三级灰度（off=零影响；shadow=观察学习期；assist=辅助开发期） |
| AIUP56_LEARN_MODE | off | on/off | T+1 回流补标调度 |
| AIUP56_LEARN_INTERVAL | 86400 | ≥300 秒 | 调度周期 |

**部署**：镜像 `zhuxiang-jiu-backend`（容器 healthy）；观测面 off 可达；`POST /api/aiup56/redteam` 需 shadow/assist 态执行红队演练；`POST /api/aiup56/feedback/collect` 可手动触发回流。

**日常运维**：
1. 开启 shadow 观察信号与提案质量（GET /dashboard 漏斗区）
2. 提案链路演练：plan→code→test→audit→review（全勾选确认）
3. 开启 assist 走完整资产生产；审批后 deliver 导出资产包走 CI
4. AIUP56_LEARN_MODE=on 启动 T+1 回流（回流统计 GET /feedback/stats）
