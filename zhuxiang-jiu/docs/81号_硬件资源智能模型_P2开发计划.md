## 〇、P1 基线与 P2 解决的两个真问题

P1 现状: 闸门只接 3 个试点调度器(全站 45 个调度入口的 7%), 压力
场景下 42 个入口照常抢资源; 水位阈值为静态 v1(内存 450/250MB、
磁盘 20/10%、load 核数×2)——不识"这台机器的正常态", 高基线时期
(如日常闲时 700MB)跌到 500MB 静态线不告警, 错过错峰最佳时机。

| 真问题 | P2 对策 |
|---|---|
| 批任务让路面太窄 | 接入面 3→27(分层放量, 见 §一) |
| 静态阈值不识基线, 偏离正常态不预警 | 分时 EMA 基线 + **只紧不松**双轨判定(见 §二) |

## 二、增量 B: 阈值 EMA 化(只紧不松双轨)

### 2.1 数据层: 水位小时采样序列

- 采样点: run_hrm_decision 每轮已 refresh 直采——按**小时去重**落
  一条样本(同小时多轮只记首条), Redis list `zhuxiang:hrm81:
  water_samples` 封顶 **720 条**(30 天×24, ~100KB, 小机无压力),
  内存模式降级同款(测试)
- 样本结构: `{ts, memMB, diskRatio, load1}`

### 2.2 基线层: 分时 EMA(黄金时段 EMA 同范式, 40号/44号先例)

- 24 个小时桶各自维护 EMA(α=0.1, 新样本当日增量更新)
- **冷启动门槛**: 桶内样本覆盖 **≥7 个不同日**才判基线有效;
  <7 天一律静态轨兜底(P1 行为不变)——满足"数据积累"触发器的
  渐进语义: 7 天起部分小时桶陆续生效, 30 天全桶覆盖
- EMA 与静态的关系铁律——**只紧不松**(核心设计决策):

```
mem_amber_threshold = max(静态 450MB, 基线小时 EMA × 0.65)
mem_red_threshold   = max(静态 250MB, 基线小时 EMA × 0.45)
load_amber_threshold = max(核数×2, 基线小时 EMA × 3)   # load 只进 amber
```

只紧不松的消解作用: ① 高基线时期(闲时 700MB)跌至 500MB——静态
不响, 动态轨收紧(700×0.65=455)提前 amber, 批任务提前错峰;
② 低基线时期(慢性紧张 300MB)动态算出 195MB 也**永远不会放松**
——max 取静态 450, 防"EMA 自适应慢性泄漏陷阱"(基线随泄漏下漂
而阈值跟跌)。**动态轨是静态轨的增强, 不是替代**。

### 2.3 磁盘特殊处理(不做 EMA, 做趋势外推)

磁盘水位单调递增, 分时基线无意义——静态阈值保留; 增量改做
**填充率趋势外推**: 近 7 日样本线性回归 → 按/日填充速度算
"距 amber 线剩余天数", 注入 capacity_proposal 建议书(升配/清理
的量化依据)与 status 观测面。

### 2.4 开关与可观测

- **HRM81_EMA=off(默认)/on**——独立 kill switch, 任一时刻回退
  纯静态零行为差异(灰度铁律: EMA 化先 shadow 双记观察)
- decision 留痕新增 `tracks` 字段: 本轮各指标命中的轨道
  (`static`/`ema`/`both`)——shadow 期双轨对比数据即验收材料
- GET /api/hrm81/status 增加 `ema` 段: 基线覆盖天数/当前小时桶
  基线值/动态阈值实际值/磁盘剩余天数
