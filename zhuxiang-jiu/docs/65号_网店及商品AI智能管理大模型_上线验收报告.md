## 五、验收中发现并修复的缺陷(重要工程记录)

### 5.1 缺陷一: 护栏巡检红队污染(实机暴露, 已修复)

- **现象**: 生产红队跑后巡检触发 guard_pause, 决策面被锁
- **根因**: 红队七向量攻击仿真的 rejected 草稿留在生产 Redis,
  被巡检计入 S1 合规拦截率(分母含攻击数据)——admin 每跑一轮
  红队即自 DoS 决策面, 本地单进程测试不可见
- **修复**: `run_guard_patrol` 按 ownerId ≥ 9881(RT_OWNER_FLOOR,
  对齐 RT_OWNER_BASE)排除红队隔离域; 软删 closed 红队店铺保留
  在表足以识别孤儿草稿; 本地补 2 断言(红队草稿不计入分母/
  红队店铺不计入违规率)
- **验证**: 修复后红队→模式仍 assist(实机 18/18 内含)

### 5.2 缺陷二: 撤销并发竞态(RT-07 失守, 已修复)

- **现象**: 生产红队 RT-07「撤销重放」失守,
  evidence `concurrentSuccesses: 2` 违反 exactly-one 原子性
- **根因**: `revoke_campaign` 读-检查-写无锁——Redis 生产模式
  双并发均读到 active 致双写 revoked; 单进程 asyncio 序列化
  掩盖该缺陷, 本地测试全绿
- **修复**: `get_lock` 活动级互斥锁(core.locks 双模式:
  asyncio/redis)包裹读-检查-写全段
- **验证**: 修复后生产红队 **7/7 全防住**; 本地 65号全套回归全绿

### 5.3 事件: 工作区 BOM 批量污染(已恢复)

- 69 个 py/ps1/md 文件被批量叠加 BOM(单→双 `EF BB BF`),
  Python SyntaxError U+FEFF(test_xx64_p0~p5/batch3-6/dm61/ii58/
	kb57/av62/xx64 服务与 verify 系列等)
- **处置**: `git diff --numstat` 区分 1+/1- 纯 BOM 污染与真实改动
  (75 文件中 6 个真实+69 个 BOM-only)→ BOM-only 批量
  `git checkout` 恢复 HEAD 零 BOM 状态
- **教训沉淀**: 工作区异常先 git numstat 审计再处置, 避免
  手工修复引入二次偏差

### 5.4 前端字段对齐(浏览器验证发现)

- 红队结果卡 passed 显示 `--`: 后端返回 `defended/allDefended`,
  前端读 `passed/seedCleaned`——mock 与真实结构漂移
- **修复**: 前端改读 `defended/allDefended`, 单测 mock 同步对齐
  真实结构, 重建 H5(`app.23e48095.js`)后浏览器复验渲染正确
