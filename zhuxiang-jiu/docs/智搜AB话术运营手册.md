## 一、A/B 实验是什么（30 秒版）

用户在搜索页提问时，智搜回答的**开头引导话术**目前有两个版本
（A 版 / B 版），系统自动把流量对半分给两版，然后追踪用户反馈：

- 用户点 **👍 有用 / 👎 没用** → 计入"有用率"
- 用户点**回答里的动作按钮**（如"逛商城选酒"）→ 计入"点击率"

哪一版的数据更好，看板会给出**晋升建议**，由您手动确认后，
该意图今后全部使用优胜版本。

**一句话**：让数据替您选话术，不再靠拍脑袋。

## 二、文案修订指南

### 2.1 当前占位文案（可直接替换的模板）

> 现行文案为工程占位版。您可按下方模板逐条修订，修订后交工程
> 更新 `VARIANT_LIB`（约 5 分钟生效，无需停机）。

**① 招商意图（agent）**

| 版本 | 游客看到 | 会员看到 |
|---|---|---|
| A（供应链强调） | 为您找到招商政策摘要——源头酒厂直供供应链，意向合作可提交留资 | 为您找到招商政策——供应链直供+区域保护，认证代理可在会员中心查看专属政策 |
| B（营销赋能强调） | 为您找到招商政策摘要——全域营销赋能扶持，意向合作可提交留资 | 为您找到招商政策——营销赋能+培训体系，认证代理可在会员中心查看专属政策 |

**② 会员权益意图（equity）**

| 版本 | 游客看到 | 会员看到 |
|---|---|---|
| A（体系介绍型） | 注册成为会员即可享受积分、会员价与生日礼等权益 | 为您查询当前会员等级对应的权益与升级路径 |
| B（利益点驱动型） | 加入竹香会员——消费攒竹叶当钱花，新人注册立得 100 竹叶 | 您的会员权益已就绪——等级越高会员价越优，查看升级路径 |

**③ 商品意图（product）**

| 版本 | 游客/会员看到 |
|---|---|
| A | 为您找到商品购买信息 |
| B | 为您挑选了以下好酒 |

### 2.2 修订五原则

1. **两版差异要"看得出来"**：核心卖点不同（如 A 讲供应链、B 讲
   营销赋能）——若两版几乎一样，实验结果没有意义。
2. **长度建议 15~40 字**：太短没有说服力，太长在手机上被截断。
3. **合规红线（不可触碰）**：
   - ❌ 极限词：最好 / 最佳 / 第一 / 顶级 / 极品 / 百分百 /
     全网最低（系统输出端会自动替换为中性词，但源头别写）
   - ❌ 医疗暗示：治病 / 疗效 / 保健功效 / 解酒
   - ❌ 收益承诺：保底 / 稳赚 / 保证收益 / 躺赚
4. **一版一个主张**：A/B 实验测的是"哪个主张更打动人"，不要在
   同一版里堆三个卖点。
5. **改文案 = 开新一轮实验**：修订生效后建议同步**清零指标重开**
   （见 SOP §3.4），避免新旧文案数据混在一起。

### 2.3 修订交接流程

```
运营：按模板修订文案（表格形式即可）
  ↓
工程：更新 VARIANT_LIB 常量（backend/services/zs_search_service.py）
  ↓
工程：重置实验（SOP §3.4），指标从零开始
  ↓
运营：在看板观察新一轮数据
```

## 三、晋升操作 SOP

### 3.1 日常查看（建议每周一次）

1. 打开 `/zhisou-dashboard.html`（admin 登录）
2. 滚动到 **⑦ A/B 话术实验** 区块
3. 每个实验意图一行，看三个数字：

| 数字 | 含义 | 怎么读 |
|---|---|---|
| **样本** | 该版收到的有用/没用反馈总数 | 每版 ≥30 才够下结论 |
| **有用率** | 有用 ÷ (有用+没用) | 主要指标，越高越好 |
| **点击率** | 动作卡点击 ÷ 曝光次数 | 辅助指标（转化意向） |

### 3.2 晋升建议出现时（怎么办）

当**两版样本都 ≥30** 且**一版有用率优出另一版 ≥20%**，该意图
下方会出现绿色横幅：

> **建议晋升 → 版本 X（优出 NN%）** ［确认晋升］

**操作步骤**：
1. 点击 **［确认晋升］** 按钮
2. 弹出确认框 → 核对意图名与版本号 → 点 **确定**
3. 立即生效：该意图今后全部使用优胜版本，状态变为
   `promoted:X`（绿色徽标）

### 3.3 晋升前的三个自查（建议但不强制）

- [ ] 两版**曝光次数**（served）大体均衡（55:45 以内）——分流是
      自动对半的，若严重倾斜请反馈工程排查
- [ ] 优胜版的**点击率**没有明显更差（有用率高但点击率反而低，
      可再观察一轮）
- [ ] 想好下一轮：晋升后是否立即换新文案重开实验（推荐——持续
      迭代优于一次定终身）

### 3.4 重置实验（开新一轮）

**场景**：修订了新文案 / 想重新收集数据

- **方法 A（看板）**：暂无按钮——联系工程执行（一条命令）
- **方法 B（工程执行）**：
  ```
  重置回实验态：POST /api/search-ai/ab/promote?intent=意图名&to_variant=
  清零指标：redis-cli del zhuxiang:zs:ab_stats
  ```
- **效果**：恢复 A/B 对半分流，指标从零累计

### 3.5 不要做的事

| ❌ 不要 | 原因 |
|---|---|
| 样本不足就晋升 | 30 以下波动大，容易选错 |
| 同时晋升 + 立刻改文案但不清零 | 新旧文案数据混淆，结论失真 |
| 让工程"直接改成某一版，别实验了" | 失去持续进化能力；正确做法是晋升（效果相同且留痕） |
| 在 shadow（影子）模式下等数据 | shadow 是观测档，**A/B 计数冻结不计入**——数据只在 assist 生产档积累 |

## 四、常见问题 FAQ

**Q1：为什么我改了文案，看板数据没变化？**
文案修订需要工程更新代码并重置实验。若未重置，旧数据仍在累计。

**Q2：两版数据几乎一样（优出 <20%）怎么办？**
说明当前两版主张差异对用户无感。建议：修订出差异更大的两版
（参见 §2.2 原则 1），重置后重测。

**Q3：晋升后能反悔吗？**
能。执行"重置实验"（SOP §3.4）即回到分流态；或反向晋升到另一版。
所有操作在看板留痕（ab-decisions 可查）。

**Q4：什么时候能扩大到其他意图（品牌/帮助/订单…）？**
当前试点 equity/agent/product 三意图。数据跑通 1-2 轮后，可提
需求让工程把更多意图加入实验池（AB_POOL 配置项）。

**Q5：合规拦截话术（如未成年拦截提示）也会做 A/B 吗？**
**不会**。合规话术是硬规则，永不参与实验——这是系统红线。
