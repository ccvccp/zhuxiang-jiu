## 二、设计核心(三个不能照抄的坑与解)

**坑① 零分污染**: not_woken 普通文本轮(海量 0.0 分)若进 EMA 链,
链值恒≈0 → 双过判定永远拦截 → 唤醒全灭。
**解**: **仅 raw ≥ 0.55 的轮进 EMA 链**(近似音带下界——u 韵与表内
变体才有平滑意义), 低于 0.55 视为无唤醒意象, 不更新不参与。

**坑② 对称平滑误杀真唤醒**: 用户合法说"小竹"(1.0)但历史低分会把
ema 拉低 → 真唤醒被拦。
**解·高置信直通带**: `raw ≥ 0.9`(精确+强近似: 小竹/小竹竹/晓竹)
**绕过 EMA 直接唤醒**——真唤醒主路径零伤害, EMA 只管辖 0.7-0.89
的临界带(弱近似/同韵段), 恰是误触画像的分布区(P3-1 判定的 0.55-0.74
集中段的判定区上沿)。

**坑③ 判定语义**: 平滑是"只紧不松"的信号版——EMA 只增加约束,
永不放宽:
```
on 态判定(SCORE_MODE=on 且 WAKE_EMA=on 且链 warm):
  raw < 0.7            → 不唤醒(原判定不变)
  raw ≥ 0.9            → 唤醒(直通带, ema 不参与)
  0.7 ≤ raw < 0.9      → score_ema = 0.1×raw + 0.9×链值
                          唤醒 = raw ≥ 0.7 且 score_ema ≥ 0.7 (双过)
链冷启动(count < 10)   → EMA 不参与(= raw 单过, 与 off 零差异)
```
连续偶发 0.7(历史低链拉低 ema)被双过拦截; 持续近似音场景链值
自然爬升, 正常唤醒不累积误伤——**收敛方向单向**(拦截→放行可,
放行→拦截仅由 raw 自身决定), 满足只紧不松铁律。

## 三、实施面(P1 单层, 预计 1+1+2 文件)

1. **services/xiaozhu_service.py**:
   - `_WAKE_EMA_ALPHA=0.1 / _WAKE_EMA_WARM_ROUNDS=10 /
     _WAKE_EMA_DIRECT=0.9 / _WAKE_EMA_FLOOR=0.55` 四常量
   - `wake_ema_mode()`(env 三态)+`_get_wake_ema(member_id)`(repo 读
     链, fail-soft None)+`_update_wake_ema(member_id, raw)`(≥0.55 才进链)
   - `detect_wake_v2` 保持纯函数零改动; **平滑挂在调用侧**
     `_handle_text_internal` 唤醒段: on+on+warm 时对 0.7≤raw<0.9 轮
     双过判定, 拦截轮走 not_woken 轨(reply/wakeHint 不变)
2. **repositories/xiaozhu_repository.py**:
   - 新键族 `voice48_wake_ema`(TABLE 常量, 单 hash 无 seq/index——
     **不触混型铁律**), `get_wake_ema/set_wake_ema` 两方法
     (fields: value/count/updatedAt, float 归一)
3. **留痕**: turn 增 `wakeEma`(本轮 ema 值, 直通/冷启动轮空)+
   `wakeTrack`("rule"默认/"emaPass"双过/"emaBlock"拦截/
   "emaDirect"直通)——81号 tracks 同款观测口径, hash 自由字段
   无 schema 迁移

## 四、灰度矩阵与回滚

| XIAOZHU_WAKE_SCORE_MODE | XIAOZHU_WAKE_EMA | 行为 |
|---|---|---|
| off(默认) | 任意 | 旧轨零差异(EMA 不参与, 链仍静默更新) |
| on | off(默认) | P1 分值判定原样 |
| on | on | 本方案双过+直通(实施后灰度观察 7 日) |

**回滚**: `sed -i 's/^XIAOZHU_WAKE_EMA=.*/XIAOZHU_WAKE_EMA=off/' /opt/zhuxiang/.env && docker compose up -d backend`
——任一时刻回 P1 分值判定零差异(拦截面清零)。
