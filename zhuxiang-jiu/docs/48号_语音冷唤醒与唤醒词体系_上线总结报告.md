## 一、背景

小竹语音精灵此前以**右下角常驻悬浮球**为全站入口（点击 → iframe 浮层面板）。本次按需求改造为业界语音助手形态：**常态无浮球，呼唤唤醒词「小竹、小竹」唤出面板**，并逐步演进为完整唤醒词配置体系（设置入口 → 同音容错 → 品牌前缀补全）。

## 三、唤醒引擎设计（js/voice-wake-widget.js，483 行）

### 3.1 检测主轨：云端流式 ASR
- 复用 48号 P1 流式识别轨同协议（`/api/xiaozhu/ws/asr`：auth → ready → 16k Int16 PCM 分帧 → partial/final）
- **partial 实时匹配**（不等 final，唤醒更快）；WS 首条 JWT 鉴权——游客不启动监听（球保留为入口）
- 选型依据：国内网络浏览器识别（Chrome→Google 服务）普遍不可达，语音页生产主轨即云端——唤醒引擎与生产现实一致

### 3.2 成本与稳健护栏
| 护栏 | 设计 |
|---|---|
| VAD 音量门限 | 静默期不建流不推流（起 0.012 / 止 0.006 RMS，3 帧起 / 1.2s 静默收段） |
| 环形缓存 | 1.5s@16k 回补——人声起判时回补唤醒词开头音频，分帧发送守百炼 16KB/帧约束 |
| 段级熔断 | 单段 6s 封顶 + 每分钟最多 6 段（噪音环境防刷 ASR 额度） |
| 面板互斥 | 面板打开即暂停唤醒监听（防自触发），关闭自动恢复 |

### 3.3 唤醒词匹配体系（三轮演进终态）
| 模式 | 匹配逻辑 |
|---|---|
| 默认「小竹、小竹」 | 两声（中间 ≤4 字符），9 形态同音容错集（小主/小朱/晓竹等） |
| 预设「你好小竹」 | 单声短语，「小竹」段复用同音容错 |
| **自定义 2-8 字** | **双轨**：精确文本（正则转义）OR **拼音序列包含**——GB2312 一级字库 3755 字 → 396 无声调音节表（15KB 内嵌，[gen_pinyin_table.py](../backend/gen_pinyin_table.py) 生成源 + [embed_pinyin_widget.py](../backend/embed_pinyin_widget.py) 幂等嵌入）；`-` 音节分隔符防跨界误拼（xia≠xiang），标点原样保留作自然断界 |

### 3.4 「小竹」前缀自动补全
- 自定义词保存时自动补全品牌前缀（输入「精灵」→ 唤醒词「小竹精灵」），已带前缀不重复
- 输入实时预览（绿色「保存后呼唤：小竹精灵」/ 红色超长提示），核心词 6 字封顶（前缀+核心 ≤8 字）
- 清空保存 = 恢复默认（原语义保留）

## 四、语音面板配套（backend/xiaozhu-voice.html → 生产 dist）

1. **唤醒开关**：「📣 唤醒开/关」（modes 行）——写 `localStorage 'xiaozhu.wake'` + postMessage `xz-wake-on/off` 即时启停父页引擎
2. **唤醒词设置**：「⚙️ 唤醒词」弹层——当前值 + 预设按钮 + 自定义输入（实时预览）+ 说明；保存写 `localStorage 'xiaozhu.wakeword'` + postMessage `xz-wake-word` 即时重建匹配器
3. **商城登录态兜底**（顺手修复既有断点）：getAuth 增加 `auth_session` 兜底——商城用户打开面板**不再要求二次登录**
4. **安全设计**：匹配器只信同源 localStorage 词值，第三方伪造 postMessage 无法注入任意正则/拼音序列

## 五、状态与消息协议

| 存储 | 含义 |
|---|---|
| `xiaozhu.wake` = on/off | 唤醒引擎开关 |
| `xiaozhu.wakeword` | 唤醒词（空=默认双声 / 你好小竹 / 自定义词） |

| postMessage（语音页 → 父页 widget） | 动作 |
|---|---|
| `xz-wake-on` / `xz-wake-off` | 引擎启停（含麦克风获取/释放） |
| `xz-wake-word` | 匹配器实时重建 |
| `xz-panel-show/hide`（原协议） | 面板开合/免提恢复（关闭面板恢复唤醒监听） |
