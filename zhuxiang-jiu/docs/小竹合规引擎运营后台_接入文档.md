# 小竹合规引擎运营后台 · 接入文档

> 版本：v1.0（2026-10-04 上线，commit `41be1f9`）
> 适用：运营/法务人员、后台前端开发、运维

---

## 一、概述

合规引擎运营后台是小竹智能助手 Guardrail 的规则管理面，提供**规则配置、白名单豁免、命中审计、发布热更新、测试沙箱**五大能力。

```
运营后台 API ──发布──> 快照(Redis) ──广播──> 小竹引擎(DFA 重建)
     ↑                                          │
     └──────── 命中日志(gr_hit_log) ◄── 拦截/替换留痕 ┘
```

核心链路：
- **规则流**：草稿（status=0）→ 发布（POST /publish）→ 引擎即时重建 DFA（Pub/Sub）→ 线上生效（≤1s，丢消息时 60s 轮询兜底）
- **数据流**：线上拦截/替换 → `gr_hit_log` 留痕 → 人工打标（确认违规/误杀）→ 误杀加白名单 → 再发布 → 豁免生效

**运行时基线**（seed 自带，开箱即用）：
- 5 个分类：未成年人保护 / 招商红线承诺 / 酒类功效虚假宣传 / 诱导过量饮酒 / 通用合规底线
- 41 个拦截词（BLOCK，命中即拦+分类话术）+ 15 个替换词（REPLACE，输出端不阻断替换）

## 二、鉴权与基础信息

| 项 | 说明 |
|---|---|
| Base URL | `https://zxjiu.com/api/guardrail/admin` |
| 生产鉴权 | `Authorization: Bearer <token>`（登录 `/api/auth/login` 获取，admin 角色） |
| 开发/测试鉴权 | `X-Role: admin`（需环境 `AUTH_COMPAT_TRUST_HEADERS=1`，生产默认剥离该头） |
| 响应格式 | 成功 `{"code": 0, "data": ...}`；失败 FastAPI 标准 `{"detail": "..."}` |
| 字符编码 | UTF-8；规则词支持中文/英文/数字 |

> 下文示例统一省略鉴权头，用 `BASE` 代指 Base URL。

## 三、API 端点详解（13 个）

### 3.1 规则大盘

```
GET {BASE}/overview
```

响应 `data` 字段：

| 字段 | 含义 |
|---|---|
| todayHits / totalHits | 今日 / 累计命中数 |
| topWords | 命中 Top10 词 `[{word, count}]` |
| reviewed / falsePositive / falsePositiveRate | 已复核数 / 误杀数 / 误杀率(%) |
| pendingReview | 待复核数 |
| published | 当前生效版本快照（version/ruleCount/blockWords 等） |
| ruleStats | 规则统计 `{total, published, draft}` |

> 建议误杀率 > 2% 时人工介入（对应您方案中的告警阈值）。

### 3.2 规则列表

```
GET {BASE}/rules?categoryId=&status=&ruleType=
```

筛选参数均可选：`categoryId`（分类 ID）、`status`（0 草稿 / 1 已发布，-1 全部）、`ruleType`（BLOCK / REPLACE）。

### 3.3 新增规则（草稿）

```
POST {BASE}/rules
Content-Type: application/json

{
  "categoryId": 1,              // 分类 ID（见 3.13 分类说明）
  "ruleType": "BLOCK",          // BLOCK=拦截 / REPLACE=替换
  "patternType": "EXACT",       // EXACT=精确词(DFA) / REGEX=正则(字段预留)
  "patternValue": "假一赔十",    // 敏感词本体
  "replaceValue": "",           // 仅 REPLACE 必填：替换后的合规话术
  "customBlockResponse": "",    // 可选：自定义拦截话术(优先于分类默认)
  "riskLevel": 2,               // 1 低 / 2 中 / 3 高
  "priority": 100,              // 执行优先级(小者先)
  "status": 0,                  // 0=草稿(默认, 线上不生效) / 1=直接发布态
  "updatedBy": "张运营"
}
```

约束：`ruleType=REPLACE` 时必须提供 `replaceValue`，否则 409。

### 3.4 修改规则

```
PUT {BASE}/rules/{id}
{ "riskLevel": 3, "status": 1, "updatedBy": "张运营" }
```

字段均可选，仅传要改的。**注意：修改已发布规则后需再次 POST /publish 才对引擎生效。**

### 3.5 删除规则

```
DELETE {BASE}/rules/{id}
```

级联删除该规则关联的白名单。删除后同样需发布生效。

### 3.6 批量导入

```
POST {BASE}/rules/batch
{
  "categoryId": 1,
  "ruleType": "BLOCK",
  "words": "假一赔十,\n晒单返现,买酒报销",   // 逗号/换行分隔
  "riskLevel": 2,
  "updatedBy": "张运营"
}
```

自动去重：与库内已有词重复的跳过并回显。响应：`{"created": 2, "skippedDuplicates": ["晒单返现"]}`。**导入后为草稿态，需发布生效。**

### 3.7 白名单列表

```
GET {BASE}/allowlist?ruleId=123
```

### 3.8 新增豁免（误杀治理核心）

```
POST {BASE}/allowlist
{
  "ruleId": 123,                 // 关联的敏感词规则 ID
  "allowPattern": "第一家店",     // 豁免模式
  "matchType": "CONTAINS"        // CONTAINS=包含 / REGEX=正则(预留)
}
```

**豁免语义**：命中敏感词时，若**原文或清洗文本包含豁免模式**，该次命中放行（豁免模式支持变体穿透：`"第 一 家 店"` 与 `"第一家店"` 等价）。典型用法：敏感词 `"第一"` + 豁免 `"第一家店"`。

### 3.9 删除豁免

```
DELETE {BASE}/allowlist/{id}
```

### 3.10 命中日志

```
GET {BASE}/hits?feedbackStatus=&direction=&limit=100
```

- `feedbackStatus`：0 待复核 / 1 确认违规 / 2 误杀（-1 全部）
- `direction`：INPUT（输入拦截）/ OUTPUT（输出替换）
- `limit`：默认 100，上限 500

记录字段：`traceId/sessionId/memberId/direction/ruleWord/category/ruleType/originalText(手机号已脱敏)/processedText/hitTime/feedbackStatus`。

### 3.11 人工打标（Evolution Engine 数据源）

```
POST {BASE}/hits/{hit_id}/feedback
{ "feedbackStatus": 2, "feedbackBy": "李法务" }   // 1=确认违规 / 2=误杀
```

误杀（2）时响应自动附白名单建议：

```json
{
  "code": 0,
  "data": {
    "hit": { ... },
    "suggestAllowlist": {
      "ruleWord": "第一",
      "originalExcerpt": "我们是本地第一家店…",
      "hint": "建议评估为该词添加白名单豁免后 POST /publish 生效"
    }
  }
}
```

运营确认后：`POST /allowlist`（用建议的 ruleWord 反查规则 ID）→ `POST /publish`。

### 3.12 发布（热更新）

```
POST {BASE}/publish
{ "by": "张运营" }
```

动作链：`status=1` 规则+白名单 → 组装快照 → 写引擎热更新键 → Pub/Sub 广播 → 所有引擎节点即时重建 DFA。

响应：`{"version": 3, "publishedBy": "张运营", "ruleCount": 58, "blockWords": 42, "replaceWords": 16, "allowPatterns": 1, "publishedAt": "..."}`

**幂等可重复发布**；发布本身零停机（引擎原子替换引用，不阻塞请求）。

### 3.13 测试沙箱（发布前必用）

```
POST {BASE}/sandbox
{ "text": "这个酒能治高血压吗" }
```

响应：

```json
{
  "code": 0,
  "data": {
    "input": "这个酒能治高血压吗",
    "blocked": true,
    "category": "alcohol_claims",
    "word": "治",
    "response": "抱歉，酒类属于饮品，不能代替药物……",
    "finalOutput": "……",        // 输出端替换后的文本
    "highlights": [{ "word": "治", "span": [4, 5] }],
    "engineVersion": "builtin"
  }
}
```

沙箱使用**引擎当前内存态词库**（含最近一次发布），span 为原文定位（变体穿透场景定位不到时为 `[-1,-1]`，前端按词渲染兜底）。

## 四、分类（categoryId）对照

分类为 seed 内置（首次启动灌入），经 `GET /rules` 的记录可反查；运营新增分类需直接操作 `gr_category` 表（当前版本未开放分类 CRUD 端点）。

| categoryId（seed 顺序） | categoryCode | 名称 | 默认话术要点 |
|---|---|---|---|
| 1 | minor_protection | 未成年人保护 | 禁止向未成年人售酒 |
| 2 | franchise_redline | 招商红线承诺 | 不做违规收益承诺 |
| 3 | alcohol_claims | 酒类功效虚假宣传 | 酒类无治疗保健功效 |
| 4 | excessive_drinking | 诱导过量饮酒 | 倡导适量饮酒 |
| 5 | general_compliance | 通用合规底线 | 内容不适宜提示 |

> REPLACE 类规则的 `categoryId` 可填 0（不参与拦截分类归因）。

## 五、典型运营流程

### 场景 A：新增一批拦截词并上线

```
1. POST /rules/batch        批量导入(草稿)
2. POST /sandbox            用典型违规句模拟 → 确认命中符合预期
3. POST /publish            发布生效
4. GET  /overview           次日观察 topWords 是否出现新词
```

### 场景 B：误杀处理闭环（核心价值流）

```
1. GET  /hits?feedbackStatus=0        查看待复核
2. POST /hits/{id}/feedback {"feedbackStatus": 2}   打标误杀
   → 响应附 suggestAllowlist 建议
3. POST /allowlist {"ruleId": X, "allowPattern": "建议豁免词"}
4. POST /sandbox {"text": "原误杀句"}  验证仍拦截或已豁免*
5. POST /publish                       发布生效
```

> *沙箱验证的是引擎内存态，第 4 步需在第 5 步发布后再验（或直接发布后观察线上）。

### 场景 C：周度合规巡检

```
GET /overview → 关注:
  - falsePositiveRate > 2%  → 逐条复核待复核队列
  - topWords 异常飙升      → 判断是否新违规话题, 补词
  - pendingReview 积压     → 安排法务打标(数据喂给后续 SFT/DPO 微调)
```

## 六、错误码

| 状态码 | 场景 |
|---|---|
| 401 | 缺失/无效鉴权头 |
| 404 | 资源不存在（规则 ID、命中 ID、豁免 ID 无效） |
| 409 | 业务冲突（REPLACE 缺 replaceValue / 打标值非 1|2 / 豁免关联规则不存在*） |
| 500 | 服务异常（日志关键字 `guardrail_admin_500`） |

> *豁免关联不存在的规则当前返回 404。

## 七、注意事项与最佳实践

1. **先沙箱后发布**：新增/修改规则务必先 `POST /sandbox` 模拟验证，防止配置错误导致大面积误拦（您方案中的"配置防错闸"）。
2. **草稿/发布分离**：所有新增默认草稿态，`publish` 是唯一生效入口——批量试词不影响线上。
3. **词长建议 ≥2 字**：单词如"治""药"极易误杀；优先用组合词（"药酒疗效"优于"药"），误杀用白名单治理而非删词。
4. **变体穿透是双向的**：词库匹配会忽略空格/标点/大小写（"未 成 年"命中"未成年"）；豁免模式同样穿透。
5. **热更新时延**：正常 ≤1s（Pub/Sub）；极端丢消息场景 ≤60s（轮询兜底）。验证发布是否生效看 `GET /overview` 的 `published.version` 与沙箱的 `engineVersion`。
6. **替换与拦截的区别**：BLOCK 命中即拦返回话术（用户输入端）；REPLACE 仅输出端替换不阻断。广告法绝对化用语走 REPLACE，红线违法走 BLOCK。
7. **命中日志脱敏**：`originalText` 落库前已对手机号脱敏；完整 PII 脱敏在会话层（mask_pii）完成。
8. **数据闭环出口**：`feedbackStatus=1/2` 的日志即微调数据源——每周提取 `originalText` 转 SFT/DPO 训练集（规划项，待数据积累后立项）。
9. **命中日志高性能写入（AsyncHitLogger）**：主链路命中后 `put_nowait` 入内存队列（<1ms 非阻塞），后台 Worker 每 **2s 或满 200 条**批量落库（Redis pipeline 一次提交）；队列上限 10000，命中风暴时**丢弃背压**保主业务；优雅停机自动刷残留。测试/巡检可调 `flush_hits()` 即时落库。
10. **白名单 REGEX 型豁免**：`POST /allowlist` 的 `matchType=REGEX` 时豁免模式按**预编译正则（忽略大小写）search 原文**——适合一族上下文一次配齐（如 `第[一二三]家店` 豁免"第一"）。`CONTAINS` 型保持变体穿透语义。两类可对同一敏感词并存，任一命中即豁免。
