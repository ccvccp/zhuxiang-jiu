# 42号·管理端拦截面板操作指南

> 配套：[42号设计文档](AI无感开票模块42_设计文档.md) §2.5
> 面板定位：AI 无感开票的**拦截观察与人工兜底**工作台——reject 档（金额异常/高频拆分/风控信号）的复核、误拦截恢复、申诉处理。
> 现状：决策流水与统计端点已上线（P0）；面板页面与处置动作属 P1 待建项，本文档同时作为 P1 的实施需求规格。

---

## 一、面板入口与权限

| 项 | 说明 |
|----|------|
| 访问角色 | `X-Role: admin`（财务/风控岗） |
| 数据源 | `GET /api/invoice/admin/decisions?action=reject`（拦截流水）+ `GET /api/invoice/admin/stats`（四档分布） |
| 刷新建议 | 手动刷新为主（拦截为低频事件）；P1 前端页可挂 30s 自动刷新 |

## 二、面板信息结构（P1 实施规格）

**顶部统计卡**（数据源 `admin/stats`）：
- 决策总数 / 自动开具数 / 待确认数 / **拦截数** / 引导收集数 / 自动化率
- 阈值参考：自动 ≥70 / 待确认 50-70 / 拦截 <50

**拦截列表**（数据源 `admin/decisions?action=reject`）：

| 列 | 字段 | 判读要点 |
|----|------|---------|
| 订单号 | orderId | 与业务后台订单详情关联跳转 |
| 会员 | memberId | 高频拆分常集中同一会员 |
| 评分 | score + factors | 四因子明细展开看哪项拖分 |
| 拦截原因 | detail | "金额低于下限" / 因子降档 |
| 拦截时间 | decidedAt | 申诉时效参考 |
| 操作 | — | 见 §三 |

## 三、拦截处置四步法（核心操作流程）

### 第 1 步：复核拦截原因（判断误拦 vs 正确拦截）

展开决策流水的 `scoreSnapshot.factors`，按拖分因子分流：

| 拖分因子 | 判读 | 动作方向 |
|---------|------|---------|
| `order_risk` = block/review | **先查订单风控**（订单模块风控面板），风控误判则发票可恢复 | 转订单风控复核，确认后走第 3 步恢复 |
| `frequency` 低分 | 该会员 24h 开票 ≥5 张，查是否拆分开票（多笔小单同日报销） | 正确拦截（拆分开票违规）→ 保持拦截 |
| `amount_reasonable` 低分 | 金额相对该会员历史异常（首单巨额定酒类发票） | 联系会员核实 → 真实采购走第 3 步 |
| `title_confidence` 低分 | 新抬头首次使用 | 正常谨慎，非误拦 → 无需处理 |

### 第 2 步：查申诉（P1 待建：申诉入口）

会员端"我的发票"页对拦截决策可见"我要申诉"入口（P1 范围）。当前无申诉通道前，客服工单渠道收集申诉，管理员凭工单号处理。

### 第 3 步：误拦恢复——人工补开

复核确认误拦后，两条路径（**均已可用**）：

**路径 A（推荐）**：通知会员在"我的发票"页手动触发
```
POST /api/invoice/orders/{orderId}/request   （会员端, X-Member-Id）
```
决策流水自动升级（reject → auto_issue，detail 记"用户手动补开"）。

**路径 B**：管理员直接开票（19号手动通道，需注意抬头信息由会员提供）
```
POST /api/finance/invoice/issue   （member 端点, 用会员 ID 与抬头）
```

### 第 4 步：正确拦截——归档观察

拆分开票等正确拦截**保持不动**（发票不开即无税影响）；面板按月导出 reject 流水给财务备查（P1 前用 `GET /api/invoice/admin/decisions?action=reject` 导出）。

## 四、判定口径速查（什么该拦、什么该放）

| 场景 | 判定 | 依据 |
|------|------|------|
| 同会员 24h 第 5 张票 | 拦 | 频次因子归零，疑似拆分开票规避发票限额 |
| 订单被风控 block | 拦 | 风控信号直通，先解风控再谈发票 |
| 首单 ¥5 万大额 | 拦后核实 | 金额合理性降档，防虚开 |
| 新抬头首次 | 不拦（分数够则自动开） | 置信度低但其余因子正常仍可过 70 线 |
| 零元/极小订单 | 拦（硬规则） | 低于 `INVOICE_MIN_AMOUNT`，无需人工 |
| 企业抬头无税号 | 不会到面板 | 抬头簿录入时已 409 拒绝 |

## 六、相关端点速查（当前已可用）

| 端点 | 方法 | 用途 |
|------|------|------|
| `/api/invoice/admin/decisions?action=reject` | GET | 拦截流水（含 factors 明细） |
| `/api/invoice/admin/decisions` | GET | 全量决策流水 |
