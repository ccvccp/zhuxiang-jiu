## 〇、本手册与叫帮手册的关键差异(先读)

| 维度 | 叫帮(67号) | 本例(62号中文化) |
|---|---|---|
| 决策面 | 7 端点门控 | **无**——不碰 AV62_MODE |
| 模式回退 | HELP_MODE=off(一级) | **不存在**——中文化与三态灰度无关 |
| Redis 残留 | mode_state 键 | **无任何键**——domainNames 是代码常量非存储 |
| 数据影响 | 需清测试单 | **零**——登记/评估/信值数据全保留 |
| 最轻回退 | 改 env | **后端撤字典**(前端 domainCn 自带回落) |

**核心解耦特性**: 前端 `domainCn(d) = regDomainNames[d] || d`——
后端撤掉 domainNames 键后, 前端**自动回落英文码显示**, 前端代码无需回退。
两侧可独立回滚互不阻塞。

**生产现状基线(2026-09-17 实测)**:
- 容器 zhuxiang-backend-1 Up (healthy); AV62_MODE=assist(.env 第 89 行, 回滚**不动**);
- 公网 registry meta.domainNames 9 域中文名在线;
- dist 引用 `app.fd14c636.js`(中文化版);
- 备份链: `dist.bak-av62credit` 为**叫帮版快照**(app.dcd2d25d.js)——
  中文化版与信值引擎版(app.83701710.js)**均无生产快照**(见第四节警示)。

## 一、回滚决策矩阵(先判断回滚级别)

| 触发场景 | 回滚级别 | 预计耗时 |
|---|---|---|
| 中文文案有误(错字/误解/业务方要求改回) | **一级: 后端字典回退**(单文件 scp+重建) | ~3 分钟 |
| 前端渲染异常(domainCn 白屏/chips 错乱) | **二级: H5 回退**(应急快照式或精确重建式) | 2~15 分钟 |
| 后端容器崩溃(自检强化误杀启动失败) | **三级: 完全代码回滚**(git revert 0dba076) | ~15 分钟 |

> 一级回退后: 前端自动回落英文码(behavior/compliance/knowledge...),
> 登记功能/表单联动/证据字段渲染/信值引擎**全部正常**——仅展示文案变化。

## 二、一级回滚: 后端字典回退(推荐主路径)

适用: 中文显示内容有误, 需恢复英文码显示。**前端零改动**。

### 2.0 前置(可选但推荐): 补建中文化前端快照

中文化部署时未建 dist 备份——回滚前先补, 让回滚本身可逆:

```bash
ssh root@47.236.61.117 "cd /var/www/zxjiu && cp -r dist dist.bak-av62domaincn && grep -o 'app\.[a-z0-9]*\.js' dist.bak-av62domaincn/index.html | head -1"
```

预期输出 `app.fd14c636.js`——快照成功。

### 2.1 本地取旧版文件(两种方式二选一)

**方式 A·revert 提交式(推荐, git 历史干净)**:

```powershell
cd d:\网站架构设计
git revert --no-edit 0dba076     # 反向提交: 3 文件回滚(后端1+前端2+测试1)
git log --oneline -1             # 确认 revert 提交生成
```

> revert 后工作区即旧版, 直接进入 2.2。
> 注意: 同时回滚了前端 2 文件——**仅 scp 后端文件**, 前端不动(见 2.2);
> 前端文件的回滚留待三级或将来重构建时自然生效。

**方式 B·止血式(不动 git, 最轻)**:

```powershell
cd d:\网站架构设计
# PowerShell 的 > 会写 UTF-16 BOM 毁掉 .py 文件——必须用 cmd 包裹字节直传:
cmd /c "git show 0dba076^^:zhuxiang-jiu/backend/services/av62_registry.py > %TEMP%\av62_registry_old.py"
```

> ⚠️ 编码红线: PowerShell `>` 重定向输出 .py 必为 UTF-16 双字节,
> Python 只接受单 BOM——**双 BOM 直接 SyntaxError 启动崩溃**。务必 cmd /c。

### 2.2 上传旧版并重建容器

```bash
# 方式 A(revert 后工作区已是旧版):
scp zhuxiang-jiu/backend/services/av62_registry.py root@47.236.61.117:/opt/zhuxiang/zhuxiang-jiu/backend/services/av62_registry.py

# 方式 B(止血文件):
scp %TEMP%\av62_registry_old.py root@47.236.61.117:/opt/zhuxiang/zhuxiang-jiu/backend/services/av62_registry.py

# 容器重建(观察启动自检三件套通过):
ssh root@47.236.61.117 "cd /opt/zhuxiang && docker compose up -d --build backend 2>&1 | tail -2"
```

> scp+ssh 长命令在 PowerShell 下有静默吞命令先例——**上传后必须在容器内实证**
> (见 2.3), 不可只看退出码。

### 2.3 回退验证(三项)

```bash
# ① 容器健康:
ssh root@47.236.61.117 "docker ps --filter name=zhuxiang-backend-1 --format '{{.Status}}'"
# 预期: Up xx seconds (healthy)

# ② 公网 registry 撤键确认(domainNames 应消失):
curl -s https://zxjiu.com/api/av62/registry -H "X-Role: admin"
# 预期: meta 中无 domainNames 键(其余 meta.byRole/elementDetails/creditRules 正常)

# ③ 容器内常量确认(方式 A/B 均适用):
ssh root@47.236.61.117 "docker logs zhuxiang-backend-1 2>&1 | grep av62 | tail -3"
# 预期: av62_registry_validated roles=3 elements=13 risk=3(启动自检过)
```

### 2.4 前端回落验证(浏览器)

访问 https://zxjiu.com → 62号页 → 登记页签(强制刷新 Ctrl+F5):

## 三、二级回滚: 前端 H5 回退

适用: 前端渲染异常(domainCn 逻辑本身出错导致 chips 错乱/白屏)。
后端 domainNames 键**保留无害**(旧前端不读)。

### 3.1 应急快照式(~2 分钟, 有功能代价)

```bash
ssh root@47.236.61.117 "cd /var/www/zxjiu && rm -rf dist && cp -r dist.bak-av62credit dist && grep -o 'app\.[a-z0-9]*\.js' dist/index.html | head -1"
```

预期输出 `app.dcd2d25d.js`。

> ⚠️ **代价警示**: dist.bak-av62credit 是叫帮版快照——恢复它将
> **连带丢失信值引擎前端**(评估页签"信值评估(V_credit)"按钮与信值报告卡)。
> 后端 31 端点仍在, 仅前端无入口。仅当前端彻底不可用时应急,
> 稳定后应按 3.2 精确重建恢复信值引擎前端。

### 3.2 精确重建式(~15 分钟, 只撤中文化保留信值引擎)

```powershell
# ① 本地恢复信值引擎版前端(0dba076^ 即 f4a09d8):
cd d:\网站架构设计
git checkout 0dba076^ -- taro-app/src/pages/av62/index.tsx taro-app/test/test-av62.js

# ② 构建(npm 不在系统 PATH, 须前置 nodejs 目录):
cd taro-app
$env:PATH = "d:\网站架构设计\nodejs\node-v20.18.2-win-x64;" + $env:PATH
npm run build:h5

# ③ 打包上传(先备份当前 dist, 再解压):
tar -czf $env:TEMP\dist_av62_en.tar.gz -C dist .
scp $env:TEMP\dist_av62_en.tar.gz root@47.236.61.117:/tmp/
ssh root@47.236.61.117 "cd /var/www/zxjiu && cp -r dist dist.bak-av62domaincn 2>/dev/null; tar -xzf /tmp/dist_av62_en.tar.gz -C dist && grep -o 'app\.[a-z0-9]*\.js' dist/index.html | head -1"
```

验证: 浏览器 Ctrl+F5——登记页英文码 + 评估页签**信值评估按钮在**(与 3.1 的区别)。

## 四、三级回滚: 完全代码回滚(git revert + 双端)

适用: 后端服务异常(容器崩溃/自检误杀)或需彻底回到 f4a09d8 态。


revert 后工作区已是旧版, 可跳过 ① 直接构建。

### 4.4 本地回归(回滚提交前的质量门)

### 4.5 残留清单(回滚后全部无害)

| 残留物 | 位置 | 影响 | 处置 |
|---|---|---|---|
| domainNames 键 | 已随 2.2 撤除 | — | — |
