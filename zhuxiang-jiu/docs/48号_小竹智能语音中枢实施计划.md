# 48号·小竹智能语音中枢实施计划 v1.0
## ——全感知语音业务代理 · 意图直达 · 信值价值闭环 · 主动智能

> 状态: 规划设计稿 · 2026-09-04
> 定位: **网站的新操作系统入口**——不是"指令翻译器",
> 而是"懂业务、识角色、有记忆的智能业务代理"; 同时是
> 信值体系的**数据采集端**与**价值交付端**
> 前序: 35号(Hub 能力路由/ASR 链路) → 45号(信值) →
> 47号(验真风控) → **48号把三者串成"所说即所得"**

---

## 一、设计理念与核心命题

### 1.1 一个核心命题

> 传统语音助手 = 关键词匹配 + 通用回复 + 单向指令 +
> 与业务割裂。本站已有的 35号 Hub 解决了"能力路由",
> 但它仍是**被动文本意图分类器**——用户必须先知道
> 网站有什么功能、再自己找入口。
>
> "小竹"的答案: **唤醒即直达(意图→action→页面/卡片)、
> 角色千人千面(会员等级+信值+偏好注入)、语音即价值
> (交互行为可积累信用、操作中嵌入信值查询/修复/兑换)、
> 从被动响应到主动关怀(修复窗口临近主动提醒)。**

### 1.2 传统助手 vs 小竹(工程对照)

| 维度 | 传统语音助手 | 小竹(本模块) |
|------|-------------|-------------|
| 理解 | 关键词→搜索框 | 语义意图→结构化 action(Function Calling)→直达页面/卡片 |
| 响应 | 所有人相同 | 会员等级+信值等级+偏好标签动态调整 |
| 价值 | 执行完即结束 | 操作中嵌入信值查询/修复引导/兑换路径 |
| 主动性 | 等唤醒词 | UEBA 修复窗口+活跃时段驱动主动提醒 |
| 集成 | 独立模块 | 直接调用 45号信值/47号画像/产品/订单既有 API |

### 1.3 三大理念落法(本仓惯例)

| 理念 | 落法 |
|------|------|
| 遵循规则 | 语音仅是**可选交互方式**绝不替代传统路径(反语音霸权); 高敏操作强制屏幕二次确认; 音频即转即删仅存脱敏文本 |
| 方便快捷 | 唤醒即直达(免学页面结构); 免唤醒连续对话; "所说即所得"全链 mock 可测 |
| 智能自主 | 意图规则轨→LLM 轨自动升级; 失败案例自动挖掘; 用户共创指令经审核入全局库 |

### 1.4 设计红线(继承 43-47号 宪法层)

- **反语音霸权**: 语音仅为可选入口; 传统页面路径零改动;
  **不因用不用语音影响信值**(只对有效交互行为计分)
- **高敏操作不可纯语音完成**: 兑换/支付/信息变更必须
  屏幕确认码二次验证(声纹/语音确认不算)
- **隐私最小采集**: 音频转写后立即删除, 仅存脱敏文本;
  身份证/手机号/卡号等 PII 在落库前 mask(47号敏感词
  同款红线); 一键清除语音历史
- **默认零影响**: 新模块纯增量; 主动关怀调度器默认 off
  (46号 P6 范式); LLM 轨默认 off 规则轨兜底(35号范式)
- **不直接改信值**: 语音交互产生的"贡献"走独立积分账
  本(voice_points), 经 45号既有 deposit 验真通道自愿
  申报入分——不绕过宪法 50/30/20 与 47号验真风控

## 四、P0:感知层·语音会话中枢

### 4.1 差距

35号已有"音频→文本"但没有"文本→业务直达": 转写结果
只进 chat 闲聊; 无会话概念(多轮"这个多少钱"指代前文);
无唤醒词语义。

### 4.2 方案

**① 小竹会话模型**(voice48_sessions / voice48_turns):

```
session: {sessionId, memberId, channel(voice|text),
  startedAt, lastActiveAt, status(open|closed)}
turn: {turnId, sessionId, seq, audioMeta(时长/大小——
  音频本体不落库), rawText(脱敏后), intent, action,
  result{reply, card, jump}, latencyMs, ts}
```

**② 唤醒与免唤醒**:
- 首句唤醒: 转写文本以"小竹"开头(去标点空格前缀匹配,
  容错"小猪/小竹竹"近似音映射)→ 唤醒成功, 剥离前缀后
  进意图解析
- 免唤醒连续对话: 会话 5 分钟窗内后续语句直接解析;
  指代消解(mock: "这个/它"→上一轮 jump/card 的对象)
- 未唤醒语音→返回 `wakeHint`(不执行, 防误触发)

**③ 八个高频指令直达**(规则轨, 每条=意图+action+反馈):

| 指令示例 | action | 数据源 | 反馈 |
|---------|--------|--------|------|
| "看新上线产品/新品" | product.new | /api/products/list?sort=new | 卡片列表+jump |
| "XX 多少钱" | product.price | /api/products/search | 单品卡片 |
| "查我的信值/信用" | trust.score | 45号(经绑定表) | 信值卡片 |
| "我的信值余额" | trust.balance | 45号 ledger | 余额卡片 |
| "打开购物车/订单/个人中心" | nav.page | 前端路由 | jump |
| "今天有什么优惠" | promo.query | 既有优惠端点 | 卡片 |
| "转人工客服" | chat.human | 35号既有 | 转接卡片 |
| "帮助/你能干什么" | xiaozhu.help | 指令集自描述 | 能力卡片 |

**④ 隐私基线**: 转写后临时音频立即删除(hub 现状补
强); 文本落库前 PII mask(身份证/手机号/卡号正则→*);
一键清除会话(级联轮次)。

**⑤ 前端**: 小竹浮层(语音条+对话流+卡片渲染+跳转),
ai-hub-widget 按住说话范式平移; 全站页面可挂载。

**⑥ 端点(6)**: POST /xiaozhu/sessions(开)、
POST /xiaozhu/sessions/{id}/voice(音频全链)、
POST /xiaozhu/sessions/{id}/text(文本同链)、
GET /xiaozhu/sessions/{id}(历史)、
DELETE /xiaozhu/sessions/{id}(清除)、
GET /xiaozhu/commands(指令集)。

**测试与验收**: 专项预计 22 项(唤醒判定/近似音/免唤醒
窗口/指代/PII mask/级联清除/8 指令路由)+实机 8 项
(音频上传→直达卡片 E2E ×2 幂等)。

## 五、P1:认知层·角色感知大脑

### 5.1 差距

P0 回复千人一面; 意图只有规则轨(14 枚举不够业务直达);
问"能换吗"不知信值几何。

### 5.2 方案

**① 指令集注册表升级**(xiaozhu_commands):
每条指令 `{intent, patterns, action, params 提取器,
角色过滤, 反馈模板}`——意图从"分类"升级为"结构化
action 生成"(mock 确定性: 规则→参数槽位填充)。

**② LLM 意图增强轨**(XIAOZHU_LLM_MODE, 默认 off):
- 规则轨不中(兜底 general)且开关 on → LLM 从指令集
  中选择 action+抽取参数(JSON 输出, 41/42号范式)
- LLM 失败/未配 key/开关 off → 一律回退规则轨
  (35号 HUB_INTENT_LLM 预留空位的落地)
- **LLM 只产 action 不产内容**——数字永远来自执行层
  API(防幻觉红线, 46号备案同款)

**③ 角色画像注入**(千人千面的数据基座):
```
role_context = {
  memberLevel: member_service.get_level(memberId),   # L1-L5
  trustTier:   47号画像 tier(经 bindings, watched/     # 推荐降敏
               restricted 档新品推荐过滤高风险标签)
  trustBalance/creditPoints: 45号(经 bindings),
  preferenceTags: 会员历史订单类目 top3(既有订单聚合)
}
```
- 注入反馈模板: 等级→话术敬语变体; 偏好→"看新品"结果
  重排序(偏好类目加权); **推荐公平性**: 重排序不排除
  其他类目(只调序不筛除, 防信息茧房)
- 未绑定信值档案→信值类指令返回引导绑定卡片(不报错)

**④ 信值上下文感知**:
- "这个能换吗/能用信值换吗"→ 自动取当前卡片商品价+
  会员信值余额→回"当前信值 X, 该商品需 Y, 差 Z"+
  获取路径卡片(做任务/捐公益/修复)
- "我上次违章怎么修复"→ 45号修复计划(剩余窗口/γ(t)
  时效系数实时计算)→"窗口还剩 N 天, 现在完成可获
  1.5 倍修复值"+一键 jump 修复页

**⑤ 情感急缓标记(mock 确定性)**: 语速(词数/时长)+叹词/
 重复标点启发式→ urgent 标记→ 播报模板简化+优先给
  jump 少啰嗦(真情感识别列外部待办)。

**⑥ 端点(2)**: POST /xiaozhu/bindings(绑定信值档案)、
GET /xiaozhu/context(角色上下文调试视图)。

**测试与验收**: 专项预计 26 项(参数槽位/LLM 三态回退/
角色注入变体/未绑定引导/换算数学/修复窗口 γ(t)/情感
启发式)+实机 8 项。

## 六、P2:执行层·安全业务代理

### 6.1 巙距

P1 只"读"; 高敏写操作(兑换/支付/信息变更)若无防线,
语音误识别即真金白银损失。

### 6.2 方案

**① 执行沙箱**(xiaozhu executor):
- action 白名单注册(每个执行器显式声明: 只读/写/高敏)
- 写操作幂等: 同 session 同 action+同对象 10s 窗去重
  ("小竹买……说两遍"只执行一次)
- 高敏分级:
  - **只读**(查/导航/推荐)→ 直接执行
  - **一般写**(加购物车/收藏)→ 执行+结果播报
  - **高敏**(信值兑换/信用分转换/大额下单/信息变更)
    → **confirmToken 流**

**② 二次确认令牌流**(高敏操作唯一通道):
```
语音"把 100 信用分换成信值"
→ 沙箱识别高敏 → 不执行, 返回:
  {confirmRequired: true, confirmToken, summary:
   "将扣除100信用分, 获得1信值", expiresIn: 120s}
→ 前端弹屏幕确认层(显示 summary+4 位数字码, 用户念/
  输入——输入为准, 语音念码不算防声纹伪造)
→ POST /xiaozhu/confirm/{token} {code}
→ 核销执行(调 45号 convert 既有通道)或过期作废
```
- 冷静期: 同会话 10 分钟内 ≥3 次高敏确认→ 暂停高敏
  通道, 提示改用页面(防冲动/诱导)
- 模糊指令澄清反问: 参数槽位缺失→ 追问而非猜测
  ("您是想看'新产品'还是'新上线的服务'?")

**③ 多模态反馈卡片**(card 类型注册):
product_list/product_detail/trust_score/trust_balance/
repair_plan/confirm/promo/guide/nav/help——前端统一
渲染器; 渐进披露(列表→点开详情, 不长篇播报)。

**④ 事务与回滚**: 执行器只调既有业务 API(复用其
事务语义); 小竹层记录执行留痕(turn.result)支持
"我刚才做了什么"回溯查询。

**⑤ 端点(2)**: POST /xiaozhu/confirm/{token}、
GET /xiaozhu/sessions/{id}/actions(执行留痕回溯)。

**测试与验收**: 专项预计 30 项(白名单越权拒绝/幂等
去重/令牌过期/码错重试上限/冷静期触发/澄清反问/
高敏全链)+实机 10 项(兑换 confirmToken E2E ×2)。

## 七、P3:进化层·交互驱动双优化

### 7.1 差距

交互数据用完即弃; 系统永远被动; 用户教不会助手。

### 7.2 方案

**① 语音交互积分**(voice_points 独立账本):
- 计分事件(仅有效行为, 反语音霸权红线——不因"用语音"
  本身计分): 完成一次指令直达+2; 提交指令纠错反馈被
  采纳+20; 共创指令上架+100
- **不直接改信值**: 积分达阈值可经"积分→45号 deposit
  自愿申报"通道换取信值(走既有验真管线, 47号风控
  照常审查——语音刷分同样逃不过画像)
- 账本只追加, 可查询可导出

**② 主动关怀调度器**(XIAOZHU_PROACTIVE_MODE=off 默认,
46号 P6 调度器范式):
- 日度扫描: 47号画像 watched/restricted 档+45号修复
  窗口临期(≤3 天)×会员活跃时段(历史会话时间分布)
  → 生成关怀任务(站内信+小竹首页问候条)
- 内容: "修复窗口还剩 3 天, 现在完成线上宣讲可获 1.5
  倍修复值"——数字来自 45号 γ(t) 实时计算
- 频控: 单会员单类提醒 7 天一次; 总量日上限(防骚扰)

**③ 失败案例自动挖掘**:
- 轮次标记: 兜底 general / 连续重复同指令(≥2 次)/
  主动负反馈("不对/不是这个")→ 归类 failure_cases
- 管理端聚类视图(P4 看板呈现): top 未命中语句→
  建议新增指令 pattern(人工审核后入注册表——46号
  审批总线范式, 不自动生效)

**④ 用户共创指令**(POST /xiaozhu/commands/custom):
- 高频用户可提交"自定义短语→既有 action"映射
- pending→管理审核→上架(全局可见)或驳回; 贡献者积分
  +100; 上架指令带 contributor 留痕
- 安全边界: 共创只映射**白名单 action**, 不能新建执行器

**⑤ 端点(4)**: GET /xiaozhu/points、
POST /xiaozhu/points/redeem(积分→信值 deposit 通道)、
POST /xiaozhu/commands/custom、
POST /xiaozhu/proactive/scan(管理端手动触发)。
