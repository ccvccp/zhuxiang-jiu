# 55号·二维码AI智能管理模块 上线部署清单

> 版本：v1.0（2026-09-06）｜适用代码基线：master ≥ `f204412`
> 模块：全站智能应用统一交互总线（意图即码、码即服务、全域贯通）
> 部署形态：Docker Compose（backend + redis），Redis 持久态，20 端点

## 〇、部署摘要（一页速览）

| 项 | 值 |
|----|-----|
| 功能开关 | `QR55_MODE`（生成/核销面，默认 **off**） |
| 调度开关 | `QR55_LEARN_MODE`（T+1 学习调度，默认 **off**） |

| 回滚 | 一级：开关回退（秒级）；二级：权重回滚（不停机）；三级：代码回退 |

## 二、配置项清单

### 2.1 必配（compose 已入册，经 `.env` 覆盖）

| 变量 | 默认 | 生产建议 | 说明 |
|------|------|---------|------|
| `QR55_MODE` | off | 上线灰度后 on | 生成/核销/完成标记总开关 |
| `QR55_SECRET` | **dev** | **强随机值（必改）** | HMAC 签名密钥；轮换使存量未核销码失效（默认 TTL 300s → 影响窗口 ≤5 分钟） |

### 2.2 可调

| 变量 | 默认 | 说明 |
|------|------|------|
| `QR55_LEARN_MODE` | off | T+1 调度（清扫+补标+快照+学习+回归检测） |
| `QR55_LEARN_INTERVAL` | 86400 | 调度周期秒（下限 300）；**首轮在 interval 之后**——可先手动 `POST /api/qr55/feedback/collect` |
| `QR55_REGRESSION_THRESHOLD` | 0.3 | 滑动窗口回退阈值（超值自动回滚+46号冻结） |
| `LLM_ENABLED` + `LLM_API_KEY` | off | 澄清/归因 real 轨（可选，最后开） |

### 2.3 生效方式

改 `.env` 后执行 `docker compose -p zhuxiang-jiu up -d backend`（容器按配置差异自动重建）。

## 三、部署步骤（全新环境）

```bash
# ① 拉取代码
git pull origin master

# ② 构建（注意：中文目录名下 compose 项目名推导为空——必须显式 -p）
docker compose -p zhuxiang-jiu build backend

# ③ 启动（backend 依赖 redis healthy；容器启动自动跑 seed_redis.py 幂等种子）
docker compose -p zhuxiang-jiu up -d

# ④ 健康检查（start_period 30s 后应 healthy）
docker ps --filter "name=zhuxiang-jiu-backend" --format "{{.Names}} {{.Status}}"
curl -sf http://127.0.0.1:8000/api/decision/health
```

**当前既有环境说明**：55号 已随 P0-P5 迭代部署在役（默认 off）；本次入册的 compose 开关项与运行态默认值一致，无需立即重启，随下次容器重建自然生效。

## 四、上线验收清单

### 4.1 生产冒烟（只读安全，≤2 分钟）

- [ ] `GET /api/decision/health` → 200
- [ ] `GET /api/qr55/registry`（X-Role: admin）→ 200（12 项服务+四类模板）
- [ ] `GET /api/qr55/model/status` → 200（champion + readiness 字段）
- [ ] `GET /api/qr55/stats` → 200（六指标键齐备）
- [ ] `GET /api/qr55/dashboard` → 200（四区齐备：volume/services/funnel/defense）
- [ ] `GET /api/qr55/governance/health` → 200（freezeGuard.frozen=false）
- [ ] 鉴权抽查：无 X-Role 访问任一管理端点 → 403

### 4.2 功能验收（QR55_MODE=on 后）

- [ ] `POST /api/qr55/generate`（试点会员，精确意图）→ `generated` + 五段码 `ZXBJ-QR55:...`
- [ ] `POST /api/qr55/scan` → `redeemed` + 落地页；同码二次扫 → `replayed`
- [ ] 改尾码扫 → `tampered`（阻断+留痕）
- [ ] 儿童模式 apply 类 → `child_confirm_required`；confirmed 回传 → `generated`

### 4.3 全量回归（**仅限预生产/演练环境**）

五个实机验收脚本（各 ×2 轮幂等，基线合计 220 项次全过）：

```bash
python verify_qr55_p1_live.py   # 52 项次：生码三态/千面/核销四态/预算
python verify_qr55_p2_live.py   # 50 项次：七类信号/池双写/结算/六指标
python verify_qr55_p3_live.py   # 42 项次：学习/晋升/回滚/自动回滚+冻结
python verify_qr55_p4_live.py   # 40 项次：治理冻结/拨测/补偿/儿童/归因

```

> ⚠️ **生产禁跑**：P3/P4/P5 脚本含 Redis 清理逻辑（`zhuxiang:ai_learning:*`、`zhuxiang:ai46:*`），会**清空 44号学习池与 46号治理台账**；P5 红队还会向池内注入 30 条 `attacker_flood` 反馈。生产如需红队复验，执行后须按脚本内 `redis_del_keys` 键清单清理还原。

## 五、灰度开启顺序（双开关独立，逐级放量）

```
Step 0  部署完成（全 off）
        └─ 观测面冒烟（§4.1——off 亦可用）
Step 1  QR55_MODE=on（生成/核销面开放）
        └─ admin 试点会员跑 §4.2 全链（generate→scan→complete）
        └─ 观察期 1-3 天：dashboard 四区 + stats 六指标无异常
Step 2  QR55_LEARN_MODE=on（T+1 调度开放）
        └─ 可先手动 POST /api/qr55/feedback/collect 即时触发首轮补标
        └─ 观察 model_events：feedback_collect / metrics_snapshot / scheduler_run 留痕
Step 3  （可选）LLM_ENABLED=on（澄清/归因 real 轨）
        └─ 失败自动回退 mock，不影响业务
```

**放量节奏建议**：试点会员（内部账号）→ 灰度受众（elderly/general 白名单内）→ 全量。49号预算（默认日限 1.0）与 45号信值档案为个性化数据源，未建档会员走中性口径不阻断。

## 六、监控与运维

### 6.1 日常巡检端点（admin）

| 频率 | 端点 | 关注点 |
|------|------|--------|
| 日 | `GET /dashboard` | 四区：码量趋势 / 漏斗转化 / 防御区护栏+集中度 |
| 日 | `GET /stats` | 六指标环比（意图满足率/渗透率/预算健康度/拦截有效率/满意度/澄清效率） |
| 周 | `GET /governance/health` | 三检测器信号 / 冻结态 / 域内事件 |
| 周 | `GET /attribution` | 权重变更归因（LLM 三态） |
| 按需 | `POST /probe` | 白名单 route 可达性拨测（12 项，失败不计预算） |

### 6.2 告警口径

| 信号 | 口径 | 处置 |
|------|------|------|
| 防御区集中度 | topRatio > 0.8（dashboard.sourceConcentration.alert） | 排查标注源投毒（46号复核） |
| 自动回滚 | regression_rollback 事件（drop>阈值） | 已自动回滚+冻结——人工复核后 46号 unfreeze |
| 篡改激增 | tamper 事件计数陡增 | 排查码渠道泄露；跑 `POST /probe/compensate` 补偿受害者 |
| 冻结中 | learn 返回 409"冻结" | 46号审批队列处理 |
| 拨测失败 | probe.failed > 0 | route 白名单复核（转人工阈值见看板） |

### 6.3 数据留存

qr55 四表（codes/events/feedback/model_events）Redis 持久化（appendonly）；44号池/45号档案随既有模块备份策略。

## 七、回滚预案（三级）

| 级 | 场景 | 操作 | 生效 |
|----|------|------|------|
| L1 功能回退 | 生码/核销异常 | `.env` 置 `QR55_MODE=off` → `up -d` | 秒级；存量二维码链路零影响（off 直通铁律）；调度可独立保留或同步 off |
| L2 模型回退 | 权重劣化（未触发自动回滚） | `POST /api/qr55/model/rollback`（可指定 versionId） | 不停机；44号版本历史可溯 |
| L3 代码回退 | 版本级故障 | `git revert` + rebuild + `up -d` | 分钟级；Redis 数据兼容（schema 未破坏性变更） |

**冻结态恢复**：46号审批总线提交 `unfreeze` 变更并批准（review_change）。

## 九、常见问题（FAQ）

| 现象 | 原因/处置 |
|------|-----------|
| `docker compose` 报 "project name must not be empty" | 中文目录名——必须 `-p zhuxiang-jiu` |
| `POST /generate` 返回 409 | QR55_MODE=off（铁律非故障）；观测面不受影响 |
| `POST /redteam` 返回 409 | 红队需 on 态（off 无攻击面） |
| `GET /attribution` 返回 409 | 无权重变更事件——先触发 `POST /model/learn` |
| `POST /model/learn` 返回 409 | 反馈不足（min_feedback=10）或 46号冻结中 |
| 调度首日无补标 | 首轮在 interval（默认 24h）之后——手动 collect 先行 |
| 扫码"预算不足降级" | 49号日预算耗尽（UTC 日切重置）；L0 服务永不降级 |
| 改 QR55_SECRET 后存量码全 tampered | 预期行为（HMAC 失配）——TTL 300s 自然过期消散 |
